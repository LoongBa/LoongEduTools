## 2. 目标与原则

- **目标**：落地「隐性数对模式识别标注」——练习中提示在 `findLogicStep` 卡住时**退化**为「观察标注」：识别出「某单元里数字 {a,b} 只藏身同两格」，高亮该两格 + 教学文案，不替孩子填数、让孩子自己推。同时 `analyzeTechniques` 识别隐性数对 → 错题画像正确归组（「需综合」缩小、关联 hiddenPair 教学关）。
- **版本定性**：**V1.5.0（minor）**——新增用户可感知的提示行为形态（观察标注）+ 引擎新识别器。属「用户可感知的新形态/里程碑级能力」边界，按 2026-09-27 规则 minor 须经用户同意（本方案评审后、实施前单独确认）。
- **原则**：
  - **纯模式、不落子**：隐性数对识别器只标注模式（藏身两格 + 数字对），不产出落子——绕开 V1.4.0 裁剪根因（明确标注与单步落子的语义分界）。
  - **显隐区分**：识别器必须排除「显性数对」误报（两格候选恰为 {a,b} 是显性数对，不是隐性数对；隐性数对的独特价值在藏身格候选 ≥3）。
  - **教学语系 + 去游戏化**：观察文案「数字 x、y 只藏在这两个格子里」教学口径，不出现竞技表述。
  - **最小修改**：引擎新增独立纯函数 `findHiddenPairPattern`（findLogicStep 不动，仅 useHint 退化时调用）；Board 新增一类模式高亮 prop；analyzeTechniques 增强保留缓存语义（B2/I1 修订：**不猜测推进**，命中即 add+break 保持「诚实子集」语义）。
  - **测试 fixture（B2 修订）**：**手工构造极小盘**作 engine fixture（确定性命中 + findLogicStep 先返回 null）——撤销 v0.1「LESSON_DATA.hiddenPair 教学盘可作 fixture」主张（oracle 手算验证该盘无解且 col2 数字 2 为隐性唯一非数对，教学盘重蹈 V1.4.0 B1 覆辙）。教学盘仅作文案/视觉回归参考，不作引擎断言。

## 3. 变更设计

### 3.1 引擎：`findHiddenPairPattern`（P0/P1，新增独立纯函数）

`sudoku.ts` 新增：

```ts
/** 隐性数对模式标注（V1.5.0）：某单元内数字对 {a,b} 的候选位置集全集落于同 2 格（藏身格）。
 *  纯模式识别，不产出落子——与 findLogicStep 单步落子语义分离（V1.4.0 裁剪根因）。
 *  排除显性数对误报：藏身格候选集任一格 ≥3 候选（{a,b} 恰为候选的是显性数对，不在此列；N1 此判据与「候选集≠恰{a,b}」数学等价）。
 *  前置条件（I5）：调用方应确保 findLogicStep(grid) 返回 null（即无隐性唯一/宫排除/行列排除可推进）——否则对某些 pair 结构（如 x 唯一位=1 的格子组合），交集判定不会命中，属预期行为（该结构已被 ②③ 覆盖）。
 *  返回 null = 无隐性数对模式。 */
export interface HiddenPairPattern {
  /** 藏身两格 (locked cells) */
  cells: [number, number];
  /** 被藏的两个数字 */
  values: [number, number];
  /** 所在单元（row/col/box） */
  unitKind: "row" | "col" | "box";
  unitIdx: number;
}
export function findHiddenPairPattern(grid: Grid, size: Size): HiddenPairPattern | null;
```

实现要点：
- 遍历 row/col/box 全部单元（`unitCells` + `unitCount`，与 findLogicStep 同构）。
- 单元内空格候选矩阵：数字对的候选位置集。对每个数字对 {x,y}（1..size 两两组合），收集「候选位包含 x」与「包含 y」的两集合，若**交集 = 同一 2 格且并集也恰 = 这 2 格**（即 x、y 的候选位全集都落在这 2 格）→ 候选模式（I5 前置条件下，此判定等价于标准隐性数对定义）。
- **显性数对排除**：该 2 格中**至少一格**的候选数 ≥3（否则两格候选恰 {x,y}，是显性数对，findLogicStep ④ 已覆盖）——「至少一格」而非「两格均」，允许非对称隐性数对（一格恰 {a,b}、另一格 {a,b,c}，I6-1）。
- 候选矩阵复用 `candidatesFor`（每次格候选计算轻量，9×9 可接受；不引入跨调用缓存，与 findLogicStep 的 candCache 隔离）。
- 多单元命中时按 row → col → box 顺序、pair 遍历顺序返回第一个（稳定且确定，I6-3）。

### 3.2 Board 模式高亮（P2，新增 prop + token）

`Board.tsx` 新增 `pattern?: { cells: number[]; tone: "hidden-pair" }`；渲染一类新高亮（I4 定调新增 token）：

```tsx
// 单元格内（现有 button className 追加；优先级见下）
isPattern && "bg-hl-pattern/30 ring-1 ring-inset ring-hl-pattern/60 hl-shape-pattern",
```

- **token（I4 定稿）**：`styles.css` **8 组主题块各新增 `--hl-pattern`**（柔紫/青系，与 hl-peer/hl-selected/hl-same 色相区分），机械追加 8 行一次成本。**不用** hl-selected 加透明度派生（会像「淡化选中态」，教学语义不清）。
- **优先级链（I3 定稿）**：`isPattern` 排在 `isPeer` 之后、errMark 与 transparent 之前（sel > wrong > same > peer > pattern > errMark > transparent）；`isPattern` 仅在空格（`!val`）时生效（藏身格必为空）；fallback 条件 `!isSel && !isWrong && !isSame && !isPeer && !isErrMark && !isPattern`（追加 `!isPattern`）。

### 3.3 useHint 退化观察标注（P0/P2，核心 UX）

`Practice.tsx` `useHint`（329-351）在 `findLogicStep` 返回 null 之后、`setMsg("需要更长的推理链")` 之前插入：

```ts
const pattern = findHiddenPairPattern(board, size);
if (pattern) {
  setWarn(false);
  const label = pattern.unitKind === "row" ? `第 ${pattern.unitIdx + 1} 行` : pattern.unitKind === "col" ? `第 ${pattern.unitIdx + 1} 列` : `第 ${pattern.unitIdx + 1} 宫`;
  setPattern({ cells: pattern.cells, tone: "hidden-pair" });   // I2：新 pattern prop，不走 setHintCells/peerGuide
  setMsg(`💡 ${label}里，数字 ${pattern.values[0]} 和 ${pattern.values[1]} 只藏在这两个格子里——这两个格子把 ${pattern.values[0]}、${pattern.values[1]} 悄悄锁住了。想想这对数字应该怎么放？`);   // N3：代词指明「这两个格子」
  playSound("tap");
  window.clearTimeout(hintTimer.current);
  hintTimer.current = window.setTimeout(() => { setPattern(null); }, 3200);
  return;
}
```

- **关键语义**：hint 不再「替孩子填」，而是「指出模式让 TA 自己推」——与 hiddenPair 教学关第 1 步引导文案同构（content.ts 234）。N3：文案「这两个格子把 a、b 悄悄锁住了」指明藏身格，避免 v0.1「它们」指代含糊。
- **I2 路径定稿**：退化提示用**新 `pattern` prop**（Practice 持有 `pattern` state，经 Board 的 `pattern` prop 渲染 `hl-pattern` 视觉）；`hintCells`/peerGuide 保留给常规提示（高亮「已填排除源格」）。两语义不同（藏身空格 vs 排除源格）强制视觉区分。
- 提示消失机制沿用（3200ms）。
- 若未命中模式 → 保持现状「需要更长的推理链」。

### 3.4 analyzeTechniques + content.ts 增强（P1，画像归组联动）

`sudoku.ts` `analyzeTechniques`（526-542）：每轮 `findLogicStep` 返回 null 时，先调用 `findHiddenPairPattern`：
- 命中 → `set.add("隐性数对")` → **break**（I1 修订：**不猜测、不推进**——V1.4.0「诚实子集」B2 语义边界保持；least-constrained 猜测会引入「伪阳性标签」（猜测后涌现的技巧非题面固有），收益不明且耦合 replay.ts 语义。least-constrained 推进推迟到「需发现多重进阶技巧」的真需求出现）。
- 未命中 → break（现状）。

`content.ts`（B1 修订，**v0.1 误判为无需改动，实为缺失**）：
- `TECHNIQUE_LESSON_MAP`（109-116）增 `隐性数对: "hiddenPair"`——v0.1 以为 V1.4.0 已写，实考只有 `显性数对: "nakedPair"` 与 `"X-Wing": "xwing"`；

`content.ts`：

- `TECHNIQUE_GROUPS` adv 组 `techniques` 已含 `隐性数对`（137）→ 无需改动。**画像归组自动生效**（groupOfTechniques 命中 adv 组 + 关联 hiddenPair 教学关）。
