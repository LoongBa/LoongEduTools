## 三、变更摘要

- **零打扰提醒**：仅设置页「本机数据」卡内联展示「上次备份：今天 / N 天前 / 从未备份」状态行；仅超期（≥14 天）或从未备份且有数据时显示建议行。无弹窗、无首页干扰（红线：符合 V1.2.0 遗留「避免打扰，保持手动最简」）。
- **单独键设计**：`redtools.shudu.backupAt` 独立于 store——不随备份文件导出（防自指）、不随恢复导入（恢复后按备份文件 `createdAt` 诚实重置）。
- **写点完整**：备份成功 → 清零提醒；恢复成功 → 取文件 `createdAt`；清除进度 → 清除键。
- **文案**：教学与训练语系，无游戏化（「建议先备份一份」「换设备或清除浏览器数据时进度不丢」）。

## 四、自审意见处置

| 意见 | 结论 | 处置 |
|---|---|---|
| 备份时间戳放 store 更统一？ | 否决（自审） | 放 store 会随备份文件导出形成自指闭环、跨设备恢复后误同步；单独键 + `createdAt` 重置语义更诚实 |
| 恢复后是否应视为「已备份」？ | 采纳（自审） | 恢复的数据 = 备份文件快照，其备份时刻 = 文件 `createdAt`；用户看到「上次备份：N 天前」与数据实际时点一致，不误导 |
| 从未备份且无数据 → 提示吗？ | 不提示（自审） | `hasData` 守卫：空档不提示，避免新用户首屏被打扰 |
| 阈值 14 天是否合理？ | 保留（自审） | 两周一次备份提醒，与「建议定期备份」的惯例一致；零打扰设计下即使阈值偏短也无打扰成本 |
