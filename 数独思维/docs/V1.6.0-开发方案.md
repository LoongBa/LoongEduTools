## 1. 背景与现状问题

| 编号 | 优先级 | 问题 | 代码位置 |
|---|---|---|---|

## 2. 目标与原则

- **目标**：结算层新增「🧠 这道题用到的技巧」个人化建议区块——基于 `analyzeTechniques` 画像，展示本局涉及的推理技巧 chips；**与教学关关联的技巧提供「去复习」入口**（直达 openSkill 教学关）；按「已点亮/未点亮」差异化提示（P2）。复用 V1.3.0 分组 / V1.5.0 画像全链路，补上结算层这个学习闭环出口。
- **版本定性**：**V1.6.0（minor，自主判断）**——新增用户可感知的结算层形态（技巧复盘 + 教学复习入口），跨文件接口（Practice 新 prop `onLesson`）。符合 2026-09-28 规则「新增用户可感知形态 / 跨文件接口变更 → minor 自主」。
- **原则**：
  - **复用画像，不重算**：直接调 `analyzeTechniques(start.puzzle, size)`（内部 techniqueCache 兜底），不发明第二套识别。
  - **画像诚实语义保持**：画像 =「题面推理链可推进部分的技巧近似标签」（V1.5.0 oracle B2 语义），非「孩子填错的技巧」。渲染文案避免「你错在这」误导，用「这道题会用到」口径。
  - **教学语系 + 去游戏化**：chips 复用 StepReview 技巧色带（toneClass 同款 base/adv/ach）；文案「复习一下更稳」教学口径，无竞技表述。
- **最小修改**：Practice 新增 `onLessonKey?: (key: string) => void` prop（index.tsx 传 `openSkill` 兼容签名）；不动结算层主布局（区块插在 ResultSummary 后、suggestion 前）；不动 StepReview/分组/画像。
- **定位差异（N2）**：SkillSuggestions 是结算主 Overlay 上**即时可见**的技巧提炼 + 教学闭环入口；StepReview 是子浮层的深入整盘回放（无教学入口）。两处 chips 视觉相似但用途不同——SkillSuggestions 让用户在结算层就能看到入口，不必先进 StepReview。非冗余。
- **入口闭环**：未点亮技巧 → 按钮「🎓 去学一下」；已点亮 → 「✅ 已会，再练一组」→ 跳教学关（SkillLesson 完成即点亮，教学关内已完成态自然出现）。简化：统一跳教学关，按钮文案仅区分是否已点亮（行为同 openSkill）。

## 3. 变更设计

### 3.1 Practice 新增 `onLessonKey` 回调（P1）

`Practice.tsx` Props 增：

```ts
interface Props {
  params: StartParams;
  onExit: () => void;
  onFinish: () => void;
  /** V1.6.0：结算层「去复习技巧」→ 打开教学关（index.tsx openSkill 复用；N1：与 HomeView onLesson(s) 区分，此回调收 lessonKey 字符串） */
  onLessonKey?: (lessonKey: string) => void;
}
```

- 解构取值；结算层技巧区块点击时 `onLessonKey?.(lessonKey)`（空安全，未传则区块仅展示 chips 无跳转）。
- `index.tsx`（L179-180 渲染处）传：`<Practice ... onLessonKey={openSkill} />`——openSkill 签名 `(key: string)` 兼容（lessonKey 即 skill key，`TECHNIQUE_LESSON_MAP` 值域 ⊂ ALL_SKILLS keys，`skillByKey` 内置 undefined 防护 N4/openSkill 内 `if (!s) return`）。
- **换轨语义（N3）**：点入口 → `openSkill(lessonKey)` → `setView("lesson")`，Practice 卸载；教学关学完 `onExit` 回首页，**不返回结算 Overlay**（合理「换轨学习」，方案明示）。

### 3.2 结算层技巧建议区块（P0/P1/P2，核心 UX）

`Practice.tsx` 结算 Overlay 内 `ResultSummary`（679-687）之后、`suggestion`（688-692）之前插入：

```tsx
{/* V1.6.0：这道题用到的技巧（复用 V1.3.0 画像 + V1.5.0 增强；教学关复习入口） */}
<SkillSuggestions
  techniques={settlementTech}   // useMemo(analyzeTechniques(start.puzzle, size))
  lit={store.skills}
  advLit={store.advSkills}
  onLesson={onLesson}
/>
```

`SkillSuggestions` 组件（Practice.tsx 内联，同文件紧耦合范式）：
- 入参：`techniques: string[]`、`lit: Record<string, string>`（基础）、`advLit: Record<string, string>`（进阶）、`onLessonKey?: (key: string) => void`。
- 渲染逻辑：
  - `techniques.length === 0` → 返回 null（纯观察盘的题不给建议，与 StepReview「没有可拆解」口径一致）。
  - 「🧠 这道题会用到这些推理技巧」标题（`text-[11.5px] font-semibold`）。
  - chips 行（`flex flex-wrap gap-1.5`）：**I1：SkillSuggestions 内联扩展色带表** `TECH_TONE_V2 = { ...TECH_TONE, 隐性数对: "adv", 显性数对: "adv", "X-Wing": "adv" }`（防 StepReview TECH_TONE 缺「隐性数对」+ 防御兜底），`toneClass(TECH_TONE_V2[t])` 复用色带样式（base=badge-base / adv=badge-adv）。
  - **I3 正交说明**：色带走 `TECH_TONE_V2`（中文名→色，`唯一候选`→base 是已有设计——对孩子是基础思维，与 `Technique.tier=="adv"` 不一致）；点亮判定走 store 双查（`uniqueElim`/`nakedPair`/`hiddenPair`/`xwing` 均写 `advSkills`，`boxElim`/`rowColElim` 写 `skills`）——两系统正交，维护时勿混。
  - **复习入口**：遍历 `TECHNIQUE_LESSON_MAP[technique]`——若能映射（实测 analyzeTechniques 产出 ⊂ {唯一候选,宫内排除,行排除,列排除,隐性数对} 全部可映射，I2；`显性数对`/`X-Wing` 当前画像不产出，映射仍在防御未来识别器扩展），且 `onLessonKey` 可用，渲染「🎓 去学一下」（未点亮）或「✅ 已会 · 复习」（已点亮）小按钮（`Btn variant="quiet" size="sm"`）。**冗余防户**：`TECHNIQUE_LESSON_MAP[technique]` undefined 时只显示 chip 无入口（I2，当前不触发，保留防 findLogicStep 将来识别 triple 等）。
  - **I4 诚实限定**：区块底部一行小字 `text-[10.5px] text-muted-foreground`：「按标准推理链整理，未必和你当时的思路完全一致。」（对齐 StepReview L138 口径）

> 布局细化（实施时定）：
> - 方案 A（推荐，pairs 卡片）：一行一个技巧 → `[技巧chip] [🎓去学一下 / ✅已会]`，垂直堆叠 1-3 行（画像通常 ≤3 技巧；9×9 可能 4-5，滚动不担心，Overlay 内 width 受限）。
> - 方案 B（chips 群 + 底部一个总入口）：技巧 chips 平铺一行，底部「🎓 去复习第一个未点亮技巧」单一入口。更省空间但「哪个技巧→哪个教程」映射弱。
> 选 A：每个技巧与其教学关入口成对，学习关联直白。

- 空 safe：`onLesson` 未传时渲染 chips 但不渲染按钮（或整个区块降级为只读 chips）。
