## 附录：A2 对比度自动化目视预检（2026-10-01）

> 依用户确认「同意自动化目视预检」执行。预检脚本：`src/tests/contrast-precheck.mjs`（`pnpm test:contrast`）。
> 截图产物：`docs/对比度预检/<scheme>-<mode>.png`（8 张，同 commit 存档，图文同源）。
> 方法：读 8 组主题生效 CSS 变量 → OKLCH→sRGB 精确换算 → 半透明前景按 **sRGB src-over** 合成（与浏览器渲染管道一致）→ WCAG 对比度。

### 预检结论（供真机复核）

1. **primary/10 徽章文字：浅色 sky/mint 两主题低于 AA（3.37 / 3.69）→ 首个疑似项**
   - 现象与 V1.4.2 方案预判方向**相反**（原预判「深色 primary 偏亮 /10 偏淡」——实测深色全队达标 5.81-6.41 ✅；问题反而在**浅色 sky/mint**：浅色 primary 偏深、/10 透明底叠浅 background 后更淡，白底浅 tint 上 12px 粗体深 text = 低对比）。
   - 影响面：「第 x/n 题」连做进度徽章（Practice.tsx L569）。字号 12px bold，属小字，AA 需 4.5。
   - 建议：真机目视确认后，若确认偏淡，patch 方向 = 该徽章文字换 `text-secondary-foreground`（深浅色对比均 >8）或 bg 加厚至 `bg-primary/15`。**列为可修待真机项**。
2. **hl-pattern 填充/描边：全主题 1.07-1.11 / 1.16-1.24 → 第二疑似项（设计本意即 subtle，需判读）**
   - 该色带是 V1.5.0「隐性数对观察标注」的视觉载体（Board.tsx L101 `bg-hl-pattern/30 ring-hl-pattern/60`），`/30` 填充本来**刻意极淡**（不抢格子数字可读性），ring `/60` 是实际视觉线索。
   - 判定：数字可读性无忧（数字不会落在 pattern 格上——`isPattern` 限定空格，9.63+ 为理论最坏值）。需真机确认的是**观察标注触达率**：若真机目视发现 kids 注意不到藏身格，可微调 `--hl-pattern` 亮度或 ring 提到 `/70`。
   - 不构成阻断；V1.5.0 遗留「观察标注触达率」本就有后续观察项。
3. **对照验证**：secondary 徽章（计时）8.6-9.9 ✅，证明换算与合成链路正确。
