# D04 内容包生产管线方案（P2）

> 状态：**方案 v1.0，供 P2 实施**。本文档定义教师客户端**内容包生产管线**：从仓库既有产物（教材点读/词卡/RedTools 工具/点读陪练内容）→ 加密内容包 → 服务端发布 的全流程与工具规范。
> 上游：`S01-内容包与口令包Schema_v1.0.md`（格式）、`A01-教师客户端服务端API契约_v1.0.md`（发布接口）、`R01-教育工具-教师客户端需求分析与设计方案.md`（§4.4/§9 P2）。
> 范围：打包脚本体系 + 各类型内容包生产流程 + 服务端发布/上新包 SOP + QA 验证。
> 更新：2026-09-23 ｜ 决策记录见 §7

## 1. 背景与目标

### 1.1 背景

- P0 预装包（教材点读/词卡）由 `scripts/pack_content.py` 手工打包验证；
- P2 需**规模化**内容包生产：新增内容包 = 打包 + 发布到服务端 + 教师下载，全程免人工重发版；
- 输入源分散：教材点读（RedTools zip）、PEP 词卡（PEP词库+LoongMediaTools 资产）、RedTools 40+ 工具（可选应用）、点读陪练原创内容包（各册 data 型）。

### 1.2 目标

1. **一条命令**从任意输入源产出 Schema v1.0 合规内容包（zip：manifest 签名 + data/ 加密 + package.json 预检）；
2. 支持全部包类型：`app`（教材点读/工具应用）/ `data`（词卡/复习/代课/节日内容包）/ `roster`（名单包，在线版生成）；
3. 服务端"上新包免发版"：上传 R2 + 更新 manifest → 教师客户端 manifest 感知即下载；
4. QA 闭环：打包自检（解包验证/签名校验/冒烟）+ 可追溯记录。

### 1.3 非目标

- 内容包市场（搜索/评分/创作者上传）→ P4；
- 名单包生成在线版（抽卡配置）→ 在线版项目（R3 前）；
- 壳内 AI（生产/生成）→ 壳内零 AI 红线不变（LLM 生成属在线版备课端 R4/R5）。

## 3. 打包脚本体系

### 3.1 脚本布局（`教师客户端/scripts/`）

```
scripts/
├── pack_content.py         # ① 主入口：输入源 → Schema v1.0 内容包 zip
├── pack_app.py             #    app 型：HTML/JS/资源目录 → 包
├── pack_data.py            #    data 型：JSON/词库/素材目录 → 包
├── crypto_out.py           # ② 加密/签名模块（AES-256-GCM + ed25519，复用打包机/发布 key）
├── gen_manifest.py         # ③ 生成 manifest.json（含签名）
├── gen_package_json.py     # ④ 生成 package.json（预检清单）
├── verify_pack.py          # ⑤ QA：解包自检（hash 比对/签名校验/解密冒烟）
├── publish_pack.py         # ⑥ 发布：上传 R2 + 更新 manifest（对接 API 契约 §4.3/§4.1）
└── config.example.json     #    打包参数（输入源/输出/密钥引用位）
```

### 3.2 打包流程（pack_content.py 端到端）

```
pack_content.py --source <input> --package-id <id> --version <ver> [--type app|data] [--out dist/]

1. 收集：读输入源（zip 解包 / 目录 / JSON+素材）
2. 规范化为 data/ 结构：
   - app 型：data/app/index.html + data/app/assets/**（保持相对路径）
   - data 型：data/data/**（JSON/词库/图片/音频）
3. gen_package_json：遍历文件 → 相对路径 + SHA-256 → package.json（未加密，预检用）
4. gen_manifest：拢 package_id/version/type/name/min_shell_version/required_license_level/
   size/content_hash/download_url 等（Schema §2.2）
5. crypto_out：data/ 区逐文件 AES-256-GCM 加密（HKDF 派生密钥）
   → 输出 加密后的 data/ 文件（iv|ct|tag）+ 记录解密前置信息
6. 签 manifest：ed25519（打包机开发 key 或发布 key，见 §3.4）→ 写入 signature
7. 组装 zip：manifest.json + package.json + data/（加密后）→ content-pack-<id>-<ver>.zip
8. verify_pack 自检（见 §5）
```

### 3.3 命令行参数（约定）

| 参数 | 说明 | 示例 |
|---|---|---|
| `--source` | 输入源路径 | `RedTools/publish/学科/新英语四上点读1单元.zip` |
| `--package-id` | 包唯一 id | `pep-reader` / `pep-vocab-g4s` / `substitute-kit` |
| `--version` | 包版本（独立递增） | `1.3.3` |
| `--type` | 包类型 app/data | `app` |
| `--min-shell` | 所需最低壳版本 | `0.1.0` |
| `--lvl` | 所需口令级别 1/2 | `2`（教材敏感） |
| `--name/--desc/--icon` | 展示元数据 | `教材点读` |
| `--out` | 输出目录 | `dist/` |
| `--key` | 签名密钥文件 | `keys/dev-sign.pem`（默认开发 key） |

### 3.4 密钥管理

| 阶段 | 密钥 | 说明 |
|---|---|---|
| 开发（本地打包验证） | `keys/dev-sign.key`（本地生成，不入库） | P0-P2 开发期打包自检用 |
| 发布（服务端/运营） | `PKG_SIGN_KEY`（Workers Secret，与 API 契约 §4.3 上传接口配套） | P2 正式发布用；签名包含 `key_id` 供客户端校验公钥 |
| 客户端公钥 | 内嵌壳配置（随壳分发，P1 换真实公钥） | Schema §2.2 `signature.key_id` 对应 |

> 原则：打包机只持有**开发签名 key**；正式发布签名在 Workers 侧通过上传接口（§4.3）完成或发布机持有受保护发布 key（不入库、不随包分发）。

## 4. 各类型内容包生产流程

### 4.1 app 型（教材点读 / RedTools 工具）

```
教材点读：RedTools/publish/学科/新英语四上点读1单元.zip（HTML base64 内联）
  → 解包→ data/app/**（index.html + audio/*.js 等，Chrome 61 兼容）
  → min_shell="0.1.0" lvl=2 → pack_content.py --type app

RedTools 工具（数学口算/24点/成语接龙…）：
  → 取 series/<系列>/<工具>/src/ 构建产物（dist 或 src 静态资源）
  → 常规 lvl=1（非教材敏感）→ app 型
  → 注意：工具若依赖外部数据（词库/素材）须一并纳入 data/app/assets/
```

### 4.2 data 型（词卡 / 复习 / 代课 / 节日）

```
PEP 词卡包：PEP词库 976 词 → 按册/单元切片 → 词卡 HTML 静态页（认词闪卡样式）
  → data/data/cards/*.json + 音频/图片 → lvl=1

代课应急教案包（R2）：每单元 1 包
  → 5 分钟流程脚本（markdown/HTML）+ 素材索引 + 板书 PDF + 备用活动
  → data/data/** → lvl=1

复习包（R3）/ 节日包（R15）：LLM 辅助生成内容（生产管线）+ 人工审 → data 型
  → 与"壳内零 AI"红线兼容：生成发生在生产端，出包即静态数据
```

### 4.3 roster 型（名单包）

- 不在打包机产出：由**在线版**配置端生成（AES 加密 + 口令派生），走 API 契约外的在线版流程；
- 本管线的 roster 支持仅用于 QA 测试（mock 名单包生成）。

## 5. QA 验证（verify_pack.py）

| 检查项 | 方法 | 失败行为 |
|---|---|---|
| 结构完整性 | zip 含 manifest/package.json/data/ 且路径合法 | 报错退出 |
| 签名校验 | manifest.signature 用公钥验证 | 报错退出 |
| hash 比对 | package.json file_index → 解密后逐文件 SHA-256 比对 | 报错退出 |
| 解密冒烟 | 用开发口令密钥解密 data/ 抽样 3 文件 → 可读 | 失败退出 |
| 包体积 | 体积 ≤ 门禁（教材点读 ≤ 10 MiB；工具/数据按红线） | WARN |
| 依赖完整 | app 型 index.html 引用的 assets 均在包内 | 报错退出 |
| 版本记录 | package_id+version 不重复（本地 registry.json） | WARN/覆盖提示 |

**QA 输出**：`dist/<id>-<ver>-qa.json`（检查结果 + 时间戳 + 打包器版本），归档追溯。

## 6. 服务端发布 SOP（上新包免发版）

### 6.1 发布流程（publish_pack.py）

```
publish_pack.py --package-id <id> --version <ver> --prod
  → 1. 上传 zip 到 R2（POST /api/edu/packages，X-Api-Key: PKG_ADMIN_KEY）
          → key: content/<id>/<ver>.zip + 返回 checksum
  → 2. 更新 manifest：
          - R2 静态方案：更新 manifest/latest.json（新增/替换该包条目，is_latest=1）
          - （P4 迁 D1 packages 表）
  → 3. 校验：GET manifest → 确认该包条目在列；GET 下载 URL → 头 200
  → 4. 记录：dist/<id>-<ver>-published.json（发布人/时间/URL）
```

### 6.2 上新包 checklist（运营侧人工）

1. 打包（§3）→ QA 全过；
2. `publish_pack.py --prod` → 上传成功 + manifest 更新；
3. 教师客户端（有网）→ 拉 manifest → 出现新包 → 下载 → 校验 → 可用；
4. 验证：开发机壳内下载冒烟（可选自动化）。

### 6.3 更新策略

| 场景 | 做法 |
|---|---|
| 内容修正（同一个包） | 升 `package_version`（patch）→ 重新发布 → 客户端感知更新覆盖 |
| 新内容包（新 id） | manifest 加条目 → 客户端应用列表出现新入口 |
| 下架 | manifest 移除条目（客户端保留本地已装，不强制删除） |
| 敏感内容（教材） | `required_license_level=2` → 口令级别不足教师不可下载 |
