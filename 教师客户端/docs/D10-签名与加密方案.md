> 状态：v2.0（2026-09-27；由《D10 服务端签名壳配置方案》**改名扩编**为全平台签名/加密统一方案——内容包签名/加密问题并入 §8–§10，原壳配置内容为 Part A 不变。v1.0 = `df0bc16` 实现 + `79ece6c` dev 公钥预置）
> 前序：D01 §2（config.json 字段）、A01 §4.5（签名凭证签发契约）、S01 §2.2/§2.5（信封与加密字段冻结）、D09（防扩散威胁模型 + 母密钥链 + 凭证生命周期）、D04 §3（管线密钥管理）、R03 §4（下载扩展/工具箱）

## 1. 定位与威胁模型

### 1.1 背景（决策点4 演进）

| 阶段 | 方案 | 状态 |
|---|---|---|
| 一 | `config.json` 明文 `api_base`（可改，换服务器只改一个字段） | ✅ `d0506fe` |
| 二 | **服务端签名配置 + 本地加密缓存**（防篡改升级） | ✅ `df0bc16` |

用户关键洞察：**这些工具/内容包「数据来自服务器更新的插件、内容清单」——服务器地址是唯一需事先明确的配置**。但明文 `config.json` 可被任何人改写指向恶意服务器。二阶段引入「平台私有配置不可伪造」：配置内容受 ed25519 签名保护，`api_base` 仅作引导入口。

### 1.2 威胁分层与对策

| 威胁 | 场景 | 对策层 |
|---|---|---|
| 本地篡改 | 老师/运维改 `config.json` 的 api_base 指向恶意服务器 | ed25519 验签（壳内硬编码公钥）：拉到的配置无私钥必验签失败 → 拒绝 |
| 配置窥探 | 别人查看机房配置内容（服务器地址拓扑） | AES-256-GCM 加密缓存 `config.enc`（随机 nonce + GCM tag） |
| 配置伪造 | 恶意服务器下发假配置诱导降级 | 签名私钥仅管理员持有（`scripts/gen_shell_config.py --key keys/prod.key`） |
| 配置回放 | 抓包重放旧版本配置 | 缓存加密层随机 nonce；签名已覆盖内容本身 |

**语义澄清（防混淆）**：防篡改靠 **ed25519 签名**（改一个字节 → 验签失败）；加密层（AES-GCM）防本地静态窥探 + 完整性（GCM tag）。两者职责不同、互补。

### 1.3 已否决/短路的方案（决策记录）

| 方案 | 结论 |
|---|---|
| 服务端独立端点（`/api/edu/shell/config`） | **不需要**。静态托管即可服务 `GET {api_base}/shell/config.signed.json`，无 API 依赖 → 契约先行，服务端立项后再实现 |
| 纯静态明文配置 | 可被改 → 无法防篡改（本方案即其升级） |
| 公钥部署时再注入（留空 TODO） | 违背 `package.rs::SIGN_PUBKEYS` 先例（开发期预置 dev 钥、生产轮换追加）；留空会导致运行时必失败死角 → 预置 dev 公钥 |

### 1.4 四信任域总览（v2.0 扩编）

| # | 域 | 密钥 | 保护对象 | 详节 |
|---|---|---|---|---|
| 1 | 壳配置签名 | ed25519 `shell-config-2026` | 平台配置 `config.signed.json` | Part A（§2–§7） |
| 2 | 内容包签名 | ed25519 `dev-sign-2026`（公钥表 `SIGN_PUBKEYS`） | 内容包 `manifest.json` | §8 |
| 3 | 内容包加密 | AES-256 母密钥 `content-master.key` | 包内 `data/` 逐文件密文 | §9 |
| 4 | 凭证签名 | ed25519 `credential-sign-2026`（服务端独立密钥对） | `credential.enc` 签名凭证 | A01 §4.5（契约）+ D09 §2.2（结构） |

域 1/2/4 同为 ed25519 签名但**信任域分离**——不同 key_id、不同公钥表、不同私钥保管地，**禁止跨域复用密钥**；域 3 为对称加密，不进签名体系。四域的保管/轮换/泄露处置见 §10。

## 2. 信任链与数据流

```
config.json（明文引导，api_base 可改——改坏最多连不上）
  └→ GET {api_base}/shell/config.signed.json      ← 静态托管即可，无需服务端端点
        └→ 壳端 ed25519 验签（key_id=shell-config-2026，公钥硬编码 SHELL_CONFIG_PUBKEYS）
              ├─ 通过 → 采信 + AES-256-GCM 加密落盘 config.enc（离线解密重验）
              └─ 失败 → 拒绝（回退离线缓存，若有）
```

**信任根**：ed25519 公钥硬编码于壳二进制（`shell_config.rs::SHELL_CONFIG_PUBKEYS`），私钥仅管理员持有。这是与内容包验签（`package.rs::SIGN_PUBKEYS`）完全对称的信任模型。

> **内容包支路**（v2.0）：同一条「签名 → 验签 → 采信」链的另一半见 §8（内容包签名）与 §9（内容包加密与解锁）——两支共用 `verify_signed_envelope` 同一验签函数。

## 3. 配置包格式（信封对齐 S01 §2.2）

```json
{
  "schema_version": "1.0",
  "api_base": "https://api.loongba.education",
  "signature": {
    "alg": "ed25519",
    "key_id": "shell-config-2026",
    "nonce": "985ad4c4c2abbf08",
    "signed_payload_hash": "sha256:<canonical_json 的 sha256>",
    "sig": "<ed25519 签名 hex>"
  }
}
```

| 字段 | 说明 |
|---|---|
| `config.*` | 任意平台配置键值（未来扩展：内容包默认源、策略开关等） |
| `signature.alg` | 恒 `ed25519` |
| `signature.key_id` | 公钥表索引（支持多 key 轮换） |
| `signature.signed_payload_hash` | `sha256:` + canonical JSON（剔除 signature/checksum，sort_keys + `(",",":")` + ensure_ascii=False） |
| `signature.sig` | ed25519 签名（128 hex） |

**canonical 规则**与内容包 manifest 完全一致（共用 `package::canonical_json_sign_view`）——Python 工具与 Rust 校验互操作已验证（`python_generated_package_verifies` 测试）。

## 4. 壳端实现（Rust）

### 4.1 命令（`src-tauri/src/commands/shell_config.rs`）

| 命令 | 职责 |
|---|---|
| `shell_config_fetch` | async：GET `{api_base}/shell/config.signed.json` → 验签 → AES-GCM 加密落盘 `config.enc` → 返回签名包 |
| `shell_config_cached` | 读离线缓存：解密 → 重验签 → 返回；缓存无/解密失败/验签失败 → Err（需重新拉取） |
| `shell_config_key_status` | 当前缓存 key_id + 壳内可接受 key_id 表（前端展示/轮换提示） |

### 4.2 验签复用（`package.rs` 泛化）

```rust
// 原：verify_manifest_signature(v) —— manifest 专用
// 现：verify_signed_envelope(v, pubkeys) —— 参数化公钥表，manifest 与 shell_config 共用
pub fn verify_signed_envelope(v: &serde_json::Value, pubkeys: &[(&str, &str)]) -> Result<(), String>
```

- 校验链：signature 块存在 → alg=ed25519 → key_id 在表 → signed_payload_hash 复核 → 验签
- manifest 与壳配置从此共享同一规则，未来新增签名对象（如口令包）同法扩展

### 4.3 加密缓存（AES-256-GCM）

| 项 | 值 |
|---|---|
| 文件 | exe 同目录 `config.enc` |
| 密钥 | HKDF-SHA256 固定派生（passphrase 壳内常量，非跨机传输） |
| 布局 | `[iv:12B][ciphertext+tag]`（随机 nonce 每次写入不同密文） |
| 离线 | 解密 + 重验签后才采信（防静态篡改双保险） |

## 5. 部署与轮换

### 5.1 首次部署（开发/测试）

```powershell
# 1. 生成 dev 密钥（gitignored，自动创建）
python scripts/gen_shell_config.py --config config.dev.json --out dist/shell/config.signed.json
# 2. 脚本输出公钥 hex → 已预置在 shell_config.rs::SHELL_CONFIG_PUBKEYS（dev 公钥 431390d5...）
# 3. 将 config.signed.json 放任意静态托管，config.json api_base 指向该托管根
```

### 5.2 生产上线（换钥轮换）

```powershell
# 1. 生成生产专用密钥（独立文件，勿用 dev 钥！）
python scripts/gen_shell_config.py --config config.prod.json --key keys/prod.key --out dist/shell/config.signed.json
# 2. 把输出的公钥 hex **追加**进 SHELL_CONFIG_PUBKEYS（新条目，旧钥仍可验 = 双轨兼容）
# 3. 重新编译壳 + 发布签名包到生产托管
```

**轮换原则**：公钥表是数组——追加新 key_id 条目即可，旧配置旧钥可验、新配置新钥可验（对齐 `SIGN_PUBKEYS` 的双轨模式）。**删除旧公钥**意味着旧配置全部失效，只在主动作废时做。

### 5.3 安全操作

| 项 | 要求 |
|---|---|
| 私钥保管 | `scripts/keys/*.key` 已 gitignored；生产私钥离线保管（U 盘/密码管理器） |
| 私钥泄露 | 立即生成新 key 对、轮换公钥表、重新签发全部配置、重新编译壳 |
| 配置更新 | 只重签配置包放托管，壳端 `api_base` 不变即可感知（签名已覆盖新内容） |

## 8. 内容包签名（机制）

> 字段级冻结规范见 S01 §2.2；本节叙述机制与信任链，操作步骤见 D12（打包/发布指南）。

### 8.1 签名信封（与 §3 同构）

`manifest.json` 内嵌 `signature` 块，字段与壳配置信封完全一致：`alg`（恒 `ed25519`）、`key_id`（现役 `dev-sign-2026`）、`nonce`、`signed_payload_hash`、`sig`。

- **canonical 规则**（Python `scripts/gen_manifest.py:60-75` ↔ Rust `package.rs::canonical_json_sign_view`）：剔除 `signature` + `checksum` → `sort_keys=True, separators=(",",":"), ensure_ascii=False` → `signed_payload_hash = "sha256:" + sha256(canon)`。
- **`checksum` 不入签名**：它是 zip 本体 hash，而签名单在 zip 封口前生成——先有 manifest 后有 checksum，进签名即循环依赖（`gen_manifest.py:4-5`）。签名覆盖除 `signature`/`checksum` 外的全部字段；zip 本体完整性由分发通道的 checksum 比对 + staging 验签双重兜底（§8.3）。

### 8.2 公钥表与轮换

| 项 | 值 |
|---|---|
| 公钥表 | `package.rs::SIGN_PUBKEYS`（`package.rs:14-17`），现役条目 `dev-sign-2026` |
| 私钥 | `scripts/keys/dev-sign.key`（ed25519 PEM，gitignored；`crypto_out.py:21`） |
| 轮换 | **追加**条目即双轨（旧包旧钥可验、新包新钥可验；`package.rs:13`）——与 §5.2 壳配置同规则；移出旧钥 = 作废该钥全部签名对象，仅主动驱逐时做 |

### 8.3 壳端验签链（`package.rs:190-246` `read_manifest`）

五步校验，任一步失败 → `Err`（不入索引 = 不可见不可载）：

1. `signature` 块存在 → 2. `alg == "ed25519"` → 3. `key_id` 在 `SIGN_PUBKEYS` → 4. `signed_payload_hash` 复核 canonical → 5. ed25519 验签。

- `min_shell_version` 门（`version_lt`，`package.rs:250-267`）：壳版本不满足 → 跳过不入索引。
- 实现 = `verify_signed_envelope`（§4.2）——manifest 与壳配置**同一函数、同一校验链**；Python 打包侧与 Rust 的互操作由 §11 `canonical_json_matches_python`（canonical 一致）与 `interop_decrypt_real_embedded_with_master_key`（python 加密包 → Rust 全量解密）证明。
- 分发通道的验签时点（下载 staged / U盘先验签后解压）见 §9.4 与 D09 §7。

### 8.4 生产侧 QA

`scripts/verify_pack.py` 七项自检（structure / signature / hash / decrypt_smoke / size / app_deps / registry），signature 项独立验签，任一 FAIL → exit 1。可照做的完整步骤见 D12。

## 9. 内容包加密与运行时解锁

> 字段级冻结规范见 S01 §2.5；威胁模型与母密钥 ADR 见 D09 §2。

### 9.1 算法与布局

| 项 | 值 |
|---|---|
| 算法 | 逐文件 AES-256-GCM，无 AAD（`crypto_out.py:35-39`；Rust 解密 `protocol.rs:295-304`） |
| 布局 | `iv(16B) | ciphertext | tag(16B)`，IV 每文件随机前置 |
| `content_hash`（入 manifest，受签名覆盖） | `sha256(b"".join(sorted blobs))` = **密文**存储区整体 hash 按存储序（`pack_content.py:153-156`） |
| `package.json::file_index[].sha256` | **明文**逐文件 hash，裸 hex 无前缀（`gen_package_json.py:19`）——供 QA/预检比对；`package.json` 整体不签 |

### 9.2 母密钥链（打包侧）

- 内容主密钥 `scripts/keys/content-master.key`：64 位小写 hex（32B），gitignored，缺失自动生成 + chmod 0600（`pack_content.py:54-74`）；`--content-key-file` 可覆盖默认路径（多钥场景）。
- **打包直供，不走 HKDF**：v1.0「口令 → HKDF → 内容密钥」对内容包已弃用（`pack_content.py:17-18`；`crypto_out.py:24-32 derive_key` 残留但不再调用）。内容包密钥链只保留两段：打包侧母密钥（本节）+ 运行时 credential 解锁（§9.3）。
- 保管、轮换与泄露后果是**四域中最重的一条**，见 §10 域 3。

### 9.3 运行时解锁链（PIN + 口令 → 内容密钥，仅内存）

`credential.rs:423-469 credential_unlock`：

1. PIN（≥6 位）+ 课堂口令；
2. 重跑认证步骤 1-4 校验（防绕过，`:437-438`）；
3. `credential.enc.key_material`（base64）= `[salt:16][nonce:12][内容密钥:32][tag:16]`（`:357-359`）；
4. `KEK = Argon2id(PIN+口令, salt)`，m=48MiB、t=2、p=1（`:345-353`）；
5. AES-256-GCM 解出 32B 内容密钥 → `contentkey::set_content_key` **仅进程内存**（`:452-454`），不落盘；
6. KEK 用完即清（`:455`）；
7. 推进 `last_verified_at`（时钟回拨锚点，`:457-461`）。

**包内只有密文、没有密钥**——密钥来自 U 盘 `credential.enc` → PIN+口令解锁。换设备或口令超期，即使拿到全部包也解不开（防扩散核心，威胁模型见 D09）。PIN/导入 UI 接线后置（D09 §9.2-5），未解锁时内容请求 403 为预期行为。

### 9.4 明文包三点拒收（D09 §7 步骤 2 落点）

| 落点 | 位置 | 语义 |
|---|---|---|
| U 盘导入预检 | `store.rs:437-444` | `encrypted != true` → **零磁盘写入**即拒 |
| 云端下载 staged | `store.rs:312-314` | 解包暂存后复核 `encrypted`，明文 → 拒收 |
| 加载入口 | `package.rs:60-66,144-150` | `pack_encrypted` 读 `package.json.encrypted` 标志，明文 → `Err` |

打包侧 `--plain` 已从管线删除（`pack_content.py:19-20`）——明文包在产物链上不再可能生成。

### 9.5 内存供给（`protocol.rs`）

- 协议 `edu-content`（`:35`；Windows 实际请求 `http://edu-content.localhost/<path>`，`:3-6`；注册 `lib.rs:105-107`）。
- **不落盘**：整文件内存解密后响应（`:8-10`）；每响应 `Cache-Control: no-store`（`:11-12`）。
- GCM 无随机访问 → 先整文件解密（认证标签整体校验）再切片（`:14-15`）；Range 单区间 206/416，多区间/非法域按 RFC 9110 回退 200（`eval_range`，`:196-246`）。
- 路径穿越拒绝（`resolve_under`，`:277-291`）。
- 卸载四连（`package.rs:125-136`）：`hide_watermark` → 内容窗 `destroy()` → `clear_serve_root()` → `clear_content_key()`。

## 10. 密钥总表（保管 · 轮换 · 泄露处置）

> 四信任域（§1.4）各自独立，**禁止跨域复用密钥**。域 1/2/4 共用换钥总原则：公钥表是数组——**追加即双轨、删除即作废**；泄露三步走 = 生成新 key 对 → 追加公钥表 → 重新签发既有对象。

| # | 域 | 密钥 | 保管地 | 轮换 | 泄露/丢失处置 |
|---|---|---|---|---|---|
| 1 | 壳配置签名 | ed25519 `shell-config-2026` | `scripts/keys/*.key`（prod 私钥离线保管） | 公钥表追加双轨（§5.2） | 新钥对 + 追加 `SHELL_CONFIG_PUBKEYS` + 重签配置 + 重编壳（§5.3） |
| 2 | 内容包签名 | ed25519 `dev-sign-2026` | `scripts/keys/dev-sign.key`（gitignored） | `SIGN_PUBKEYS` 追加双轨（§8.2） | 新钥签新包；移出旧钥 = 旧包全部验签失败（仅主动作废时） |
| 3 | 内容主密钥 | AES-256 32B `content-master.key` | `scripts/keys/content-master.key`（gitignored；办公室/密码库保管 **⚠ 必须备份，单机丢失无法找回**） | **不可在线轮换**——换钥 = 全量重打包重发（现役 4 包，D09 ADR-3） | 丢失 = 既有加密包**永久不可解**；泄露 = 全部包可解 → 换钥 + 重打全部包 + 追发 |
| 4 | 凭证签名 | ed25519 `credential-sign-2026` | 服务端 `CREDENTIAL_SIGN_PRIVATE_KEY`（A01 §4.5） | 服务端独立轮换 | 与域 1/2/3 不同信任根——泄露**不**危及内容包；处置按 A01 §4.5 |

本地辅助密钥（非信任域，随载体/口令走）：

| 项 | 派生/存放 | 性质 |
|---|---|---|
| `config.enc` 缓存钥 | HKDF-SHA256（壳内常量 passphrase） | 非跨机传输；防本地静态窥探（§4.3） |
| `credential.enc` KEK | Argon2id(PIN+口令, salt) | 每机每师不同；换 PIN/口令即换（旧 PIN 失效） |
| 内容密钥（32B） | 由 `credential.enc` 解出 → 进程内存单例 | 不落盘；unload 即清（§9.3/§9.5） |
| 口令包/名单包密钥 | 见 S01 §3（冻结格式） | 独立于本表四域说明 |
