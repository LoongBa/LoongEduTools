## 0. 术语与命名决策（先读）

1. **全界面、全文档禁用「商店」二字**（易被误会为收费）。原侧栏「内容商店」改名为 **「下载扩展」**。
2. **「下载扩展」页内部只分两区**：**内容**（教材点读、词库包等内容包）与 **扩展**（工具类/增强类包）。不要出现「市场 / 商城 / 应用商店」等任何消费向词汇。
3. **「工具箱」**：老师自选的**免费工具集合页**，含分组、搜索、「我的工具」（收藏）、「最近使用」，并可**打包成随身工具包**（见 §4）。
4. 「内容商店」是壳内 UI 自创名，docs 全文 0 引用（R01/D05/S01/A01 均无）——改名**无文档阻力**；实现时需在 A01/D05 补一条命名决策记录（实现阶段处理，本设计稿不改上游文档）。
5. 关联词既有事实：仓库内「工具箱 / toolbox / extension」字样 **0 命中**；空态文案已有「内容包和扩展」表述（App.tsx:331/343/357/382）——「扩展」一词已有共识基础。
6. **工具箱数据架构（v1.1 定稿）**：**工具清单（分类/推荐/下载地址）由服务器端维护并提供下载；本地只管理本地快捷方式**（我的工具/最近使用本质是快捷方式视图）。本地不自建清单副本作为权威源，只存缓存与快捷方式。

## 2. 需求 1：侧栏二级导航

### 2.1 现状（事实基线）

- 侧栏 9 项**单层平铺**：应用、内容商店、一键开课、抽卡分组、班级看板、打卡单、复盘本、计时器、纪律（App.tsx L197–226；`View` 联合类型 12 值，L16–28）。
- 登录/个人信息/设置已收进**右上角头像菜单**（v0.2 落地，App.tsx L225 注释、L514–570）——本需求**不再动头像菜单**。
- 侧栏固定 `width:200px`（App.css L200–208），`nav { gap:4px }`、`.nav-item { padding:9px 12px; font-size:14px }`（L242–266）。
- **全仓库无折叠/手风琴组件**（collapse/accordion/expand 0 命中）；无搜索框（见 §4）。
- 分组有文档背书：**D05 §1.1 `/tools 课堂工具集（抽卡/分组/纪律/计时器）`**、**D05 §2.2 「── 课堂工具 ──」分节**。

### 2.2 分组方案（推荐，UI Agent 可在此结构上做视觉方案）

```
侧栏（200px，自上而下）
├─ 品牌区（桃李助手 · 龙爸乐学，不动）
├─ ▾ 内容            ← 一级分组头（可折叠）
│   ├─ 应用
│   ├─ 一键开课
│   └─ 下载扩展        ← 需求 2 改名后
├─ ▾ 课堂工具          ← 一级分组头（可折叠；D05 §1.1 /tools 先例）
│   ├─ 抽卡分组
│   ├─ 班级看板
│   ├─ 打卡单
│   ├─ 复盘本
│   ├─ 计时器
│   └─ 纪律
├─ 工具箱              ← 一级入口（单项不成组；需求 3）
└─ 侧栏底（全屏 F11 按钮，不动）
```

- 分组依据：**内容获取与使用**（内容组） vs **课堂现场操作**（课堂工具组，与 D05 §1.1/§2.2 完全对齐）。
- 「工具箱」是单一新页，作为**平级一级项**（不塞进任何组，不制造只有 1 个子项的组）。
- 头像菜单承载的 profile/login/settings **不回流侧栏**。

### 2.3 交互需求

| 点 | 要求 |
|---|---|
| 折叠/展开 | 点分组头切换；chevron（▶/▾）指示；动画 ≤200ms（D05 无障碍约定） |
| 默认态 | 首装**全部展开**；折叠态持久化（localStorage，刷新不丢） |
| 当前页高亮 | 子项 active 时该组**强制展开**且组头带轻标识（避免「当前页在收起的组里」的迷失） |
| 点击子项 | 切视图；**不再**收起所在组（避免误收起） |
| 键盘可达 | 分组头/子项均可 Tab 聚焦，`focus-visible` 有焦点环（沿用既有惯例 App.css L1038–1044） |
| 无障碍 | 子项保持 ≥40px 点击高度；`aria-expanded` / `aria-current` 语义补齐 |

### 2.4 视觉与改造约束（给 UI Agent 的硬边界）

1. 侧栏 200px **不加宽**；子项缩进 12–16px；组头字号可小于子项，用 `--sidebar-muted`，子项沿用 `.nav-item` 语义色。
2. 深浅主题都要成立：只用现有令牌（`--sidebar-bg/-text/-nav/-muted/-border/-hover`、`--primary`、`--on-primary`），**不引入新色值**。
3. **禁止重命名 `.sidebar`**——打印规则依赖它（App.css L2270–2273、L2387–2390：checkin/reflection 视图打印时隐藏侧栏）。
4. 净新增样式（现仓库无先例）：`.nav-group` / `.nav-group-head` / `.nav-subnav` / `.nav-chevron`；「点外关闭」模式可参考 `.user-menu-panel`（App.css L325–371），但侧栏分组常开，**不需要**点外关闭。
5. 同步改文案的既有位置：App.tsx L202（nav「内容商店」）、L257（更新提示 banner）、StoreView.tsx L85（`<h2>`）。
6. `apps`/`quickstart`/`settings` 是 App.tsx 内联 section、其余 9 个是独立组件文件——导航改造**只动 nav 结构与 View 分发**，不重排视图组件。

## 3. 需求 2：下载扩展（原内容商店 + 内容/扩展分区）

### 3.1 现状（事实基线）

- 页主体：`StoreView.tsx`（177 行）——toolbar 仅「刷新 / 从 U 盘导入…」，**扁平 `card-grid` 全量渲染，无 tab、无 filter、无分区**（L123–168）；`package_type` 仅作文本展示（L137）。
- 数据模型：`store.rs RemotePkg`（9 字段）→ `StoreItem`（12 字段，加 installed 差集）；**无任何分类字段**（L21–75）；TS 侧 `api.ts` L61–95 镜像。
- **关键事实：分类字段全链路只差壳端和服务端两段**：

| 层 | 状态 |
|---|---|
| S01 §2.2（Schema） | ✅ 已定义 `categories: ["教材","英语"]` + `description`（L55–56，标注「内容包市场演进预留」） |
| A01 §4.1（契约） | ✅ L235 白纸黑字：「manifest 结构预留 `categories`/`description` 字段」 |
| 生产管线 | ✅ `gen_manifest.py`（L23,32-33,50-51）、`pack_content.py`（`--categories/--description` L118-119,195-196）已实装 |
| 服务端 | ❌ D1 packages 表 11 列无 categories；`packages.ts` manifest entry 只写 9 字段（L154–164） |
| 壳端 Rust/TS/UI | ❌ RemotePkg/StoreItem/StoreView 均不解析、不消费 |

- `package_type: app|data` 是**运行时形态**（解压后 app/ 目录 vs data/ 目录，S01 §2.2 L46 + §2.5 加密区判定绑定），**不是**产品维度——**不可**用它做内容/扩展分区（会污染加密判定与 `verify_pack.py:93` 分支）。
- 架构现状注释：「内容包/扩展两分区**由服务端承载**」（App.tsx L98–99、window.rs L99、空态按钮 L343「打开内容服务器页面（内容包 · 扩展）」）——本需求把分区**搬进壳内** StoreView，属**架构方向变更**，实现时须同步清理这 5 处注释/文案，否则文档与实现长期矛盾（并需在 D05 补决策记录）。

### 3.2 分区方案（推荐：方案 A，复用已预留的 `categories`）

**「内容 / 扩展」两分区 = 按 `categories` 标签分流**（含 `"扩展"` 标签 → 扩展区；缺省/不含 → 内容区，向后兼容已有全部包）。

改造清单（实现阶段，供设计理解数据流）：

| 段 | 文件 | 动作 |
|---|---|---|
| 契约 | A01 §4.1 示例 | 响应示例加 `"categories": ["扩展"]` |
| 服务端 | `server/src/handers/packages.ts` L122、L154–164 | 接收 categories（CSV→数组）写入 manifest entry；categories 缺省 = 空数组（向后兼容） |
| 壳 Rust | `store.rs` L22–43 | `RemotePkg` / `StoreItem` 加 `categories: Vec<String>`（缺省空） |
| 壳 TS | `api.ts` L61–95 | 两 interface 同步 `categories: string[]` |
| 壳 UI | `StoreView.tsx` L123–168 | 按 `categories.includes("扩展")` 拆两区 |

否决项（记录在案）：
- **方案 B**（新增 `section: content|extension` 枚举）——与 A01 已预留的 categories 重复造轮子，需 S01 升级 + 全链路新字段，不划算。
- **方案 C**（`package_type` 加第三值 `extension`）——**不可取**，污染 S01 运行时形态语义与加密区判定。

### 3.3 UI 需求

1. 页面标题「**下载扩展**」；**禁**「商店」字样（含 tooltip、空态、banner）。
2. 两分区呈现：推荐**页内 tab 或分段切换**（可复用 `.tab-row/.tab` L584–606 或 `.rost-tab` L1010–1036 模式，但注意它们是浅色语义，放进深色头部需走令牌）；也可用「分节小节头 + 两个 card-grid」（D05 §2.2 「── 内容 ── / ── 扩展 ──」分节先例）。**UI Agent 二选一出方案**。
3. 保留既有能力不动：刷新、U 盘导入、下载/更新/已安装按钮、`已装/可更新` badge、未登录去登录 banner、加载中/空态三分支。
4. 分区切换**不丢加载态/错误态**；空分区给独立空文案（「该分区暂无内容」类，不复用整页空态）。
5. 可选加分项（设计可含、实现可后置）：分区旁数量徽标；`categories` 多标签时在卡片 `.store-tags` 追加标签。

## 4. 需求 3：工具箱

### 4.1 定位

> **老师自选的免费工具集合，沉淀成自己的随身工具包。**
> 收录各类**免费/开源常用工具**（截屏、屏幕标注、按键显示等），每类推荐 1–若干个；老师按喜好**收藏固定**，并**打包到本软件的工具箱目录**，带走即用。

- 与既有边界：
  - **内置课堂工具**（抽卡分组/看板/打卡/复盘/计时/纪律）归 §2「课堂工具」组，**不进工具箱页**（工具箱收**外部桌面工具**）。
  - **RedTools HTML5 小工具**（43 个，4 系列）经内容包分发，走「应用/下载扩展」，**不进工具箱**（避免三套清单打架）；工具箱**可留一个跳转入口**「更多课堂小工具 → 应用」（可选项，见 §8 待确认）。

### 4.2 页面结构（需求骨架，布局交给 UI Agent）

```
工具箱
├─ [搜索框] 按名称/标签/描述实时过滤
├─ 最近使用（横向或紧凑列表，最多 10 条，置顶区；空则隐藏该节）
├─ 我的工具（收藏的工具，置顶区；空则给引导文案「点工具卡上的 ★ 收藏」）
└─ 全部工具（按类别分组）
    ├─ ▾ 截屏录屏     [工具卡 × n]
    ├─ ▾ 屏幕标注
    ├─ ▾ 按键显示
    ├─ ▾ 虚拟键盘
    └─ （类别可扩展，数据驱动）
```

### 4.3 交互需求

| 能力 | 要求 |
|---|---|
| 清单获取 | 进入工具箱页拉取**服务端清单**（§4.4）；失败时用本地缓存清单继续浏览并提示可重试（沿用既有 serverProbe 的可达/不可达文案习惯） |
| 分组 | 类别分组展示；组头可折叠（与侧栏同一套折叠组件/样式语言） |
| 搜索 | 即输即筛（无需回车）；匹配 name/aliases/tags/description；有命中时**自动展开命中组**；无命中给空态 + 清空按钮 |
| 下载状态 | 卡片区分**未下载 / 已下载**：未下载 → 「下载」（按清单 `download_url` 落盘到工具箱目录，完成后自动生成本地快捷方式）；已下载 → 直接启动 |
| 我的工具 | 工具卡上 ★ 收藏/取消；收藏态是**本地快捷方式的一部分**（§4.4，持久化）；收藏项在「我的工具」节出现（同一工具两处出现属正常） |
| 最近使用 | 每次成功启动工具记一条（去重置顶，LRU 上限 10）；「最近使用」与「我的工具」均提供**一键启动** |
| 启动工具 | 已下载（有本地快捷方式）→ 用系统命令直接启动 `path`（沿用壳既有 shell/open 能力），**不注入、不监控第三方工具进程**；未下载 → 先走下载 |
| 收藏打包 | 一键「导出随身工具包」：把**本地快捷方式清单 + 已下载工具目录**打包为 zip（或同步到可移动目录）；换电脑「导入随身工具包」恢复快捷方式与工具本体 |

### 4.4 数据分层（v1.1 定稿）：服务端清单 + 本地快捷方式

> **原则：清单在服务端（权威源），本地只存「缓存 + 快捷方式」。**

#### ① 服务端清单（权威数据源，服务端维护）

- 新端点 **`GET /api/edu/toolbox/manifest`**，仿 A01 §4.1 packages manifest 模式（MVP 静态 JSON + R2 手工维护，不走数据库实时逻辑）；**A01 需补此端点契约**（实现阶段）。
- 服务端维护内容：分类、工具条目、**下载地址**、许可/平台/推荐标记。增删改工具**只改服务端清单**，壳端无须发版。

```jsonc
// 服务端 toolbox/manifest（示意，字段以 A01 契约为准）
{
  "version": "1.0",
  "updated_at": "2026-09-25T00:00:00Z",
  "categories": [
    { "id": "capture", "name": "截屏录屏" },
    { "id": "annotate", "name": "屏幕标注" },
    { "id": "keys", "name": "按键显示" },
    { "id": "keyboard", "name": "虚拟键盘" }
  ],
  "tools": [{
    "id": "keyviz",
    "name": "Keyviz 按键显示",
    "category": "keys",
    "tags": ["按键", "快捷键", "演示"],
    "description": "实时显示按键/鼠标操作，教学演示用",
    "license": "MIT",
    "homepage": "https://github.com/mulaRahul/keyviz",
    "download_url": "https://…/keyviz-win.zip",
    "size_bytes": 1234567,
    "checksum": "sha256:…",
    "portable": true,
    "win7_ok": false,
    "recommend": true,
    "entry": "keyviz.exe"      // 落盘后的相对启动文件
  }]
}
```

#### ② 本地快捷方式（唯一的本地业务状态，仅此一份）

- 存储：客户端数据目录下 `toolbox.json`（与 `packages/` 同级的运行目录模式）；工具本体落盘 `toolbox/<id>/`。
- 「我的工具」「最近使用」都是这份快捷方式数据的**视图**（pinned / last_used）。

```jsonc
// 本地 toolbox.json（示意：只管快捷方式，不复制清单）
{
  "shortcuts": [{
    "tool_id": "keyviz",                     // 关联服务端清单条目
    "path": "toolbox/keyviz/keyviz.exe",     // 相对数据目录（或绝对路径，手动添加时）
    "pinned": true,                          // → 我的工具
    "last_used": "2026-09-25T08:00:00Z",     // → 最近使用（LRU 上限 10）
    "source": "download"                     // download=按清单下载 | manual=手动添加本地已有程序
  }]
}
```

- **降级**：服务端清单不可达 → 展示本地缓存清单（只读）+「清单更新失败，可重试」提示；已下载工具的启动**不依赖网络**。
- **（可选）手动添加**：老师把本地已装的同类工具登记为快捷方式（`source: "manual"`），不经过服务端清单。

#### ③ 随身工具包

导出 = `toolbox.json` 快捷方式清单 + `toolbox/<id>/` 已下载工具目录 → zip（或可移动目录）；导入 = 反向恢复，快捷方式按 `tool_id` 对齐（清单可达时自动补全展示信息）。

#### ④ 收录合规红线

## 5. 全局设计约束（三个需求共同遵守）

1. **主题**：只用既有令牌，深/浅主题等价支持；禁止新增裸色值。
2. **Win7 兼容**：壳 UI 不用 Win11-only 特性（如依赖新 WebView 才有的 CSS）；动效轻量、≤200ms，尊重 `prefers-reduced-motion`（D05 §3）。
3. **打印**：不得破坏既有打印隐藏规则（勿改 `.sidebar`/`.banner` 选择器名）。
4. **无障碍**：可点击目标 ≥40px（工具卡/导航），焦点可见，`aria-*` 语义补齐。
5. **红线**：运行时零 AI；儿童数据零采集；禁 `as any`/`@ts-ignore`/空 catch；不引入新依赖（确需引入先在实现评审提出）。
6. **数据契约**：S01 冻结字段不动（`categories`/`description` 是已预留字段，非破坏性启用）。
