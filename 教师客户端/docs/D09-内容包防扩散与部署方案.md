## 1. 定位与威胁模型

### 1.1 版权边界（本方案的立足点）

- **人教社允许教学使用，不允许商业分发。** 技术措施的唯一职责：在客户端内实现"教学使用 vs 商业分发"这条边界。
- 面向家长的点读陪练线（配图自绘/TTS 重读）不适用本方案——本方案针对教师客户端内的**原版教材点读内容包**（PEP 扫描页 + 原音，法律敏感层）。
- 不追求"绝对不可复制"（不存在），追求：**随手拷贝即失效（挡 99%）+ 授权滥用可追溯（水印/台账）+ 有组织扩散靠合同与法律**。

### 1.2 威胁分层与对策

| 威胁 | 场景 | 对策层 |
|---|---|---|
| 随手拷贝 | 老师/学生把内容包文件夹拷到自己电脑 | 签名凭证（机器绑定+过期）+ PIN + 口令，拷走即废 |
| 跨机转存 | 老师在多台教室电脑各留一份、或拷回家 | 签名凭证绑定机器指纹，异机无效（同口令也无效） |
| 授权滥用 | 授权教师把内容拿去二次分发 | 渲染层水印 + 签发台账 + 机器配额（A01），可追溯 |
| 恶意导入 | 伪造/篡改内容包经 U 盘导入 | ed25519 验签（S01，既有）+ 导入器 RCE 加固（新增） |

### 1.3 已否决方案（决策记录）

| 方案 | 否决原因 |
|---|---|
| DPAPI 机器绑定（CryptProtectData） | **还原卡环境必死**：DPAPI 主密钥在 `%APPDATA%\Microsoft\Protect\`（profile 内），重启回滚后主密钥文件消失，桌面持久区里的 blob 成为孤儿，`CryptUnprotectData` 失败且口令无法补救（主密钥文件必须在盘上）。补救需管理员用 Data Igloo 重定向 Protect 目录，脆弱、非默认、依赖管理员懂 DPAPI 内部机制。 |
| 消灭 Tier S（口令明文层） | 用户否决（口令是教师日常使用的主路径，不可移除）。 |
| 纯 USB 运行（程序+内容全在 U 盘） | WebView2 Fixed Version 从可移动盘运行 MS 明确不支持（WebView2Feedback #2334 backlog）；UDF/缓存写 U 盘慢且损耗；忘带 U 盘 = 停课。 |
| 强制桌面副本下课即删 | 与"内容包常驻教室机以稳定授课"冲突，收益低（副本本身是密文）。 |

## 2. 认证与密钥设计（核心）

> **分工**：签名与加密的统一机制叙述、四域密钥总表（保管/轮换/泄露处置）已并入 **D10-签名与加密方案** §8–§10；本节保留决策记录、威胁上下文与凭证生命周期原文。

### 2.1 三因子与文件分工（C1 定稿）

| 因子 | 载体（exe 同目录） | 防什么 |
|---|---|---|
| **签名凭证**（Ed25519） | `credential.enc` **新格式**（含 `format_ver` 与旧格式区分） | 跨机拷贝（指纹绑定）+ 过期失效（≤14 天）——**不可本地伪造/续期** |
| **PIN**（教师个人，≥6 位） | 教师记忆 | 拿到文件夹但不知 PIN 的人（学生/同事随手拷） |
| **口令**（课堂口令，S01 既有） | 教师记忆 | 保留 S01 口令体系，作为 KDF 第二因子 |

**文件三分工（与既有代码对齐）**：

| 文件 | 内容 | 来源 |
|---|---|---|
| `credential.enc` | Ed25519 签名凭证（新格式，`format_ver` 标识） | 本方案新增（替代原同名文件） |
| `session.enc` | JWT 缓存（原 `credential.enc` 的 AES-GCM JWT 结构**改名迁移**） | auth.rs 既有结构，仅改名 |
| `license.json` | 学期口令包（ed25519 签名 JSON） | license.rs 既有，不动 |

- **auth.rs 的 `cred_key = SHA256(fingerprint + 固定盐)` 机制整体废弃**——它无任何秘密（fingerprint 本机可算、盐硬编码），任何人拿到文件+机器即可解密。新体系中 JWT 缓存（`session.enc`）与签名凭证的加密密钥均来自 Argon2id KEK。

### 2.2 签名凭证结构

服务端（登录/续期时）签发：

```
credential = Ed25519_Sign_server({
  format_ver,        // 格式版本（与旧 credential.enc 的 AES-GCM JWT 区分）
  machine_fp,        // fingerprint.rs：HKLM MachineGuid + 计算机名 → SHA256 前32 hex
  issued_at,         // unix epoch 秒（i64）
  expires_at,        // unix epoch 秒 = issued_at + 14 天；整数比较，绕开 parse_iso_secs 近似误差（H4）
  seq,               // 递增序号（防旧凭证覆盖新凭证，导入时拒绝 seq ≤ 当前）
  key_material,      // 包裹的内容密钥（AES-256-GCM，与 S01 §2.1 算法一致）
  quota_ref          // 关联 A01 机器配额
})
```

- 验签公钥**硬编码进壳**，但用**独立密钥对** `credential-sign-2026`（壳内新增 `CREDENTIAL_SIGN_PUBKEYS`，与 `package.rs` 的内容包 `SIGN_PUBKEYS` 分离——两个信任域，私钥不共用）。
- 过期时间、序号与机器指纹**都在签名保护内** → 拿到文件夹的人改不了过期、改不了指纹（改了签名即废）；续期必须回服务端重新签发。
- **完全离线可验**（公钥在壳里），教室断网可正常开课。

### 2.3 验证顺序（关键，防离线攻击）

```
1. Ed25519 验签           （公开数据，无需任何秘密）
2. machine_fp 匹配当前机器 （fingerprint.rs）
3. expires_at 未过期（unix 秒整数比较）+ 时钟回拨检测（见下）
4. seq > 已安装凭证的 seq  （防旧凭证覆盖新凭证）
   —— 任一失败：直接拒绝，不进入 PIN 环节
5. KEK = Argon2id(结构化(PIN, 口令), salt) → 解开 key_material → 内容密钥
6. 协议处理器内存解密内容文件（AES-256-GCM，S01 §2.1 既有）
```

**顺序的意义**：跨设备攻击者（步骤 2 失败）**连可离线穷举的目标都拿不到**——PIN 环节只在合法机器上到达。

**工程细节（H3/M6/M7）**：
- **时钟回拨防护**：每次验证成功后把 `last_verified_at`（unix 秒）写入豁免区；启动时若 `now < last_verified_at` → 拒绝并提示"系统时间异常"。防止把系统时钟往回拨给过期凭证续命（完美防不了，但挡"随手改时间"）。
- **PIN‖口令 拼接**：**结构化拼接**（如 `[pin_len:u16][pin_bytes][pass_bytes]`），杜绝 `PIN="123456"+口令="78"` 与 `PIN="1234"+口令="5678"` 产生相同输入的碰撞。
- **Argon2id 参数**：推荐 `m=48MiB, t=2, p=1, output=32B`（教室机 <8GB + WebView2 已占 400-600MB 下的平衡点，单次 ~200ms on Win7 i3；上线前在目标机实测定稿）。

### 2.4 内容密钥与密钥文件（C2 定稿：S01 升 v1.1 + 全量重打包）

- 内容密钥解开后存内存（不落盘）；包裹状态的密钥文件与内容包同目录存放（Argon2id + AES-256-GCM）。
- **与 S01 v1.0 的差异声明（H2/C2）**：S01 v1.0 冻结的密钥派生是"口令 → HKDF → 内容密钥"；本方案改为"Argon2id(PIN‖口令) → KEK → 解 key_material → 内容密钥"，新增 key_material 包裹层与 PIN 因子。**决策（已定）：S01 升版 v1.1 + 补 ADR；已交付的 11 个英语点读 zip 按新格式全量重打包 + 重 QA（内容可随时重新生成）；不做双轨兼容解密器。**
- **"不落盘"边界澄清**：指协议处理器走内存解密路径 + `Cache-Control: no-store`（需实测 Tauri 自定义协议响应头可设置性，见 §8 R4）。§5.2 M4 的"解密到临时文件"备选与本承诺**互斥，二选一**——如选临时文件路径，须声明为例外并附清理时序（窗口 destroy 即 `remove_dir_all`）。`package.rs` 的 `TEMP_PREFIX` 预留视为该例外的落点。
- **一切密钥材料都是文件**（落 exe 同目录或桌面豁免区）→ 天然免疫还原卡回滚，与仓库"所有数据落 exe 同目录"硬约束一致。
- P0 的 `pack_content.py --plain` 明文路径**删除**（明文包绕过全部防线）；删前先完成 11 个 zip 重打包（否则 P0 预装包无法启动）。

### 2.5 残余风险（R2 已定：接受）

- **本地 PIN 防君子不防拖库**：验证数据在本地 → 持有文件夹 + 时间的定向攻击者可离线穷举短 PIN（Argon2id 拖慢但不能阻止）。缓解：PIN ≥6 位、Argon2id 高成本参数、先验签再进 PIN 的顺序、**水印+台账兜底追溯**。此定位与"挡 99%"目标一致，不追求物理不可能。
- 同机器上的文件夹盗取（有物理接触）：靠水印追溯，接受。

### 2.6 过期与续期策略（R1 已定）

- 有效期 **14 天**（`expires_at` 在签名内不可篡改）；到期**硬断**：口令失效、无法登录开课。
- **续期 = U 盘复制，零教室网络**（教师动线本就经过办公室，R02 U 盘刚需）：
  1. 到期前 3 天起 UI 预警（复用 license `expiring_soon`/`days_left` 模式）；
  2. 教师带 U 盘到办公室 → 服务端按**教师 + 机器 fp** 签发新凭证写入 U 盘（私钥不出服务端；可一次预签 2-3 份，教师批量带走、按周期覆盖，稀释"每两周跑一趟"的频率）；
  3. 教室机恢复：app 内"**从 U 盘导入凭证**"——**先验签 → 验 machine_fp → 验有效期 → 才落位覆盖**（与 §2.3 同序），兜底为手动覆盖 exe 同级 `credential.enc`；若学期口令 `license.json` 同时到期，U 盘一并覆盖。
- 机器绑定是前提：U 盘上的凭证是"为特定机器签的"（签名含 machine_fp）；机器 fp 由 app 展示（`license_status.machine_fp`），办公室据此签发。
- **预签多份防回滚（M1）**：凭证含递增 `seq`（§2.2），导入命令拒绝 `seq ≤` 当前已装凭证——教师误导入旧份不会把长有效期覆盖回短有效期。
- **运维风险登记**：U 盘丢失（§8 R8）→ 报失后服务端拒签该机后续批次（软吊销，离线无 CRL）；办公室签发机故障（§8 R9）→ 应急预案。
- 运维成本如实记录：14 天窗口 ≈ 教师每两周走一次办公室（预签多份可稀释）；如放宽 30 天，被复制凭证的可用期同步变长——与 R1 原始约束（复制件最多活 1-2 周）直接取舍。
- 备选（本期不做）：到期降级只读。

### 2.7 三个过期窗口的联动（H6 补充）

既有体系存在三个独立时间窗口，D09 签名凭证是第四个（也是唯一"硬断"的），联动矩阵如下：

| 窗口 | 载体 | 时长 | 来源 | 过期效果 |
|---|---|---|---|---|
| JWT | `session.enc`（原 credential.enc 改名） | 7 天 | A01 §1.3（既有） | 在线功能（下载/上报）需重登；**不阻断离线开课** |
| **签名凭证** | `credential.enc` | **14 天** | D09 §2.2（新增） | **硬断：内容解密不可用 = 无法开课** |
| 学期口令 | `license.json` | 一学期 | S01/A01（既有） | 到期只读旧、锁新（D01 既有口径）；U 盘可一并更新（§2.6） |
| last_verified_at | 豁免区状态文件 | 滚动 | D09 §2.3（新增） | 时钟回拨检测，非过期窗口 |

**联动规则**：四者独立判断；**只有签名凭证过期才硬断开课**——JWT 过期只影响联网、学期口令过期按 D01 既有降级策略。"到期口令失效无法登录"（R1）特指签名凭证过期态。

## 3. 部署形态（方案 C）

### 3.1 形态定义

| 组件 | 位置 | 说明 |
|---|---|---|
| 程序（绿色 exe，D01 既有） | 教室机桌面/指定位置（还原卡豁免区），或 U 盘 | 不用安装包 |
| 内容包（密文） | exe 同目录 `packages/`（既有） | 允许在多台教室机常驻——副本是密文，异机打不开 |
| credential.enc（签名凭证） | exe 同目录（**跟 exe**，用户决策） | 复制者最多用到过期（≤14 天）+ 需 PIN |
| 密钥文件（口令/PIN 包裹态） | 与内容包同目录 | file-based，免疫回滚 |
| U 盘（R02 刚需） | **钥匙与搬运**：导入内容包、随身工具包（R02 既有） | 不作为运行介质（WebView2 限制） |
| WebView2 运行时 | ① 系统已装 evergreen（优先）② exe 旁 `webview2-runtime/`（兜底） | 见 §4 |

### 3.2 关键取舍

- **多台教室机各留一份 = 接受**：每份都是"锁着的箱子"（签名凭证绑原机指纹），拷贝行为不产生新可用副本。
- **凭证跟 exe（而非 U 盘）**：复制整个文件夹者获得 ≤14 天窗口 + 必须同时知 PIN/口令；换机器立即失效。这比"凭证跟 U 盘"少了每机重认证的摩擦，用过期时间换取窗口上限。
- **教室数据无痕（R02）范围澄清**：指课堂临时缓存下课即走；内容包/程序常驻属部署资产，不在"无痕"约束内。

## 4. WebView2 部署（修订：任意目录，不必须入 baseline）

### 4.1 机制（已核实）

- **Fixed Version 模式**：cab 解压即用的文件夹（MS 官方三种分发之一），不写注册表、无需安装权限、支持相对 exe 路径、**免费再分发**（保留 MS 声明、cab 从 MS 来源获取、不随源码开源）。
- 接线：`WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 环境变量（wry 0.55.1 对 `browserExecutableFolder` 参数写死 `null`，源码 `webview2/mod.rs:343` 已核实 → null 时环境变量生效）。**在 `main()` 最早期设置**，不改 wry、不升 Tauri。
- **设了即权威、不回退**：指向目录缺失 → 创建失败，不自动回落系统版本。→ 检测逻辑必须自己写。
- 环境变量是**进程级**的（不是机器级）——共享教室机上**严禁**设机器级环境变量（会影响机器上所有 WebView2 应用，且是已知攻击面）。

### 4.2 启动检测流程（扩展 `webview2.rs`，复用既有 MIN_MAJOR=108）

```
1. 读注册表检测系统 evergreen：HKLM(HOW6432)/HKCU → EdgeUpdate\Clients\{F3017226-…}\pv   （只读，不受还原卡影响）
2. pv 存在且 ≥108.0.x  → 不设环境变量 → 用系统 evergreen（Win10/11 教室机拿到持续安全更新）
3. 否则：exe 旁 webview2-runtime/ 存在 → 设 WEBVIEW2_BROWSER_EXECUTABLE_FOLDER=<exe_dir>\webview2-runtime\
4. 否则 → 走既有 bootstrapper 兜底（webview2.rs 现逻辑）
⚠️ 检测必须直接读注册表，不用 GetAvailableBrowserVersionString（若未来引入 Tauri fixedRuntime 配置会污染该探测）
⚠️ 不使用 Tauri webviewInstallMode:fixedRuntime 配置（无条件设环境变量，会丢弃系统较新 evergreen）
```

### 4.3 Win7 固定版 109 获取与约束

| 项 | 事实 |
|---|---|
| 包 | x64 197.5MB / x86 177.8MB（cab）；x64 runtime 同时服务 x86+x64 进程，**建议 bundle x64 + x64 exe** |
| 来源 | 官方下载页已下架 → Microsoft Update Catalog 或 WebView2RuntimeArchive（109.0.1518.78），留存哈希记录（许可要求"从 MS 来源获取"） |
| 许可 | 免费再分发；保留声明、不开放源码、cab 内 license 文本出货前核对 |
| 版本锁 | **WebView2 SDK ≤1.0.1518.46**（Win7 支持的最后一版）→ 核对 wry 0.55.1/webview2-com 绑定版本 |
| 冻结 | 109 自 2023-10 无安全更新 → **evergreen 优先是安全必需**（Win10 机器绝不强制用 109）；109 仅渲染第一方内容 |
| 豁免 | 109 免 Win10 Fixed≥120 的 icacls AppContainer 授权步骤 |

### 4.4 硬限制

- ❌ 网络路径/UNC（MS 明确）❌ **可移动 U 盘**（MS backlog，未支持，不赌）
- ❌ 路径含 `\Edge\Application\`（ERROR_NOT_SUPPORTED）
- ⚠️ 机器级 GPO `BrowserExecutableFolder` 策略可覆盖一切 → preflight 检测并告警（学校 IT 政策场景）

### 4.5 UDF（用户数据目录）

- Win32 默认 UDF 在 exe 旁；Tauri/wry 会传自己的 data_directory（需核实实际落点）。
- 还原卡回滚区内的 UDF → 每次开机重置（cookies/localStorage/IndexedDB）。**影响**：WebH5 的 `content-cache.ts`（IndexedDB 单元缓存）每次开机需重建——可接受（重缓存），但若希望缓存跨重启存活，用 `WEBVIEW2_USER_DATA_FOLDER` 挪到豁免区。
- **落地前核实项**：跑一次确认 Tauri 2.11.6 默认 UDF 位置。

### 4.6 部署前提（从硬前提降级为建议）

教室机"先装 WebView2 再刷新还原卡 baseline"**不再是硬前提**（exe 旁固定版兜底），仍建议批量装好以让教室机走 evergreen 安全更新路径。

## 5. 内存约束（<8GB 教室机）

### 5.1 实测量级

- 内容包单文件最大 494KB（词卡包）→ **逐请求解密缓冲峰值 <0.5MB，不构成压力**；H5 单单元 0.7–5MB 按 group 惰性加载。
- 头号内存源（与解密无关）：
  1. **`dist/ip/` 6 张未压缩 PNG = 23.35MB**（解码后位图膨胀 3–4×）——同目录已有 6–11KB 的 .webp 替代版未被使用；
  2. 三窗口 hide 不 destroy → renderer 常驻（shell 基线估 ~400–600MB，活跃内容窗口可达 ~1GB）；
  3. WebH5 `bufferCache`（AudioBuffer）无上限无淘汰；
  4. WebView2 协议响应 IPC 有 3–8× 拷贝放大（WebView2Feedback #4294）。

### 5.2 动作项

| # | 动作 | 改动点 |
|---|---|---|
| M1 | `dist/ip/` PNG → 现成 webp | WebH5 引用替换（收益最大） |
| M2 | 内容窗口 unload：hide → destroy 或 hide+`TrySuspendAsync`（runtime 109 可用，92+ 引入） | `package.rs` L87-94；destroy 需实测 Tauri 时序（已知 issue #9199/#9353 已修但需验证） |
| M3 | `bufferCache` 加 LRU 上限（如最近 20 组） | WebH5 `audio.ts` |
| M4 | 协议响应支持 HTTP Range → 206 分片（Tauri 官方 streaming 示例模式，每次只解密 ~1MB 片段）——**首选，不落盘**。⚠️ "解密到临时文件 + SetVirtualHostNameToFolderMapping" 与 §2.4 "不落盘"承诺互斥，仅当 Range 不可行时启用，且须声明例外+清理时序 | 自定义协议处理器 |

### 5.3 红线（109 环境）

- ❌ 不挂 `WebResourceResponseReceived` 监听（#5138 已知泄漏，109 未修）
- ❌ 不用 `MemoryUsageTargetLevel`（需 runtime 114，Win7 无）→ 用 `TrySuspend` 替代
- ❌ 不用 `--single-process` / `--disable-gpu`（MS 反对，后者把 GPU 内存转嫁 renderer）
- ⚠️ Tauri `hide()` 是否传播到 `Controller.IsVisible` 存疑（PR #9246 落了又 revert）→ 显式控制或实测；hide 保留 renderer，真正释放靠 destroy/TrySuspend
- ✅ 官方替代手段：对内容窗口定期 `Reload()` 回干净基线

## 6. Win7/Win10 单版本策略（结论：单二进制，零条件编译）

- Rust target 无法区分 Win7/Win10（同一 `x86_64-pc-windows-msvc`）→ **不引入任何条件编译**；差异全部收敛在依赖锁与运行时检测（§4.2 即运行时分流先例）。
- **版本锁链（写入依赖策略）**：

| 项 | 锁 | 现状 |
|---|---|---|
| Rust | =1.77.2（1.78+ 弃 Win7） | ⚠️ **`rust-toolchain.toml` 缺失，必须补** |

### 9.2 偏差登记（实施与方案原文不一致处，均已判定接受）

1. **M4 "~1MB 分片" → 整文件内存解密后按 Range 切片**（`protocol.rs`）：最大单资产 506KB < 1MB 分片阈值，整文件解密一次、响应从内存切片，无中间明文落盘——语义等价、实现更简。
2. **附A M1 归属与实况偏差**：`ip/*.png` 23.3MB 只存在于 `点读陪练/WebH5`（且 webp=0，§5.2 "已有 webp 替代"与实况不符），4 个包源均无 `ip/`。守卫实现为"**仅当同名 .webp 姊妹存在才排除 ip/*.png**"（对当前 4 包为 no-op）；WebH5 引用替换归点读陪练线，不在本方案执行。
3. **"11 个 zip 全量重打包" → 4 包**（2026-09-26 用户裁定，S01 ADR-3）：实际消费 = 预装 `pep-reader-u01` + `pep-vocab-cards` + 四上 1/2 单元可下载 zip（本地仅存 1/2 单元 2 个，其余 9 个随发布清理/仅存分发渠道）；`RedTools/publish` 内 6 个 `点读陪练_*` 属原创线，不碰。D04/README 中"11 zip"表述待同步（见 9.2-7）。
4. **步骤2 "明文包被拒"落点定案**：U 盘导入预检（验签/解压前、零磁盘写入）+ 下载 staged 校验（失败清理暂存）+ `package.load` 服务前，三点拒收 `encrypted ≠ true`；协议层保留明文直通原语仅限单测可达，生产路径已被 load 断开。
5. **3a 决策补记**：session.enc 兼容读旧 cred_key 字段、PIN 格式为本实现定义、seq 双模式（旧覆盖/新拒绝）、**解锁/导入 UI 后置**——4 包重打包后 embedded `encrypted=true`，未解锁时协议 403 属预期，待 UI 落地后闭环运行期验收。
6. **运行期实测项**（不阻塞交付）：R4 no-store 被 WebView2 遵守、R6 destroy 窗口时序、透明水印窗口 Win7 真机表现（Win7 无 DWM 时 transparent 可能退化为黑底不透明——功能可降级接受）。
