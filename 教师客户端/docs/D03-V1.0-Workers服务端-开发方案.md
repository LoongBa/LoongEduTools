# D03 教师客户端 Workers 服务端开发方案（V1.0 · P1）

> 状态：**方案 v1.0，供 P1 实施**。本文档为教师客户端配套 Cloudflare Workers 服务端实现方案。
> 上游：`A01-教师客户端服务端API契约_v1.0.md`（接口契约）、`R01-教育工具-教师客户端需求分析与设计方案.md`（§2.3/§7）、`D01-教育工具-教师版RUST外壳开发方案.md`（§6）。
> 范围：Cloudflare Workers + D1（账号/激活码/口令/内容包元数据）+ R2（内容包/口令包文件）+ 短信/微信登录 + JWT + 限频。
> 更新：2026-09-23 ｜ 决策记录见 §8

---

## 1. 背景与目标

### 1.1 现状

- 教师客户端 P0 离线可用（Tauri 壳 + 预装内容包），P1 需引入在线认证（微信/短信/密码）与课堂口令周期性授权；
- 无任何服务端实现：仓库有 Cloudflare 先例（RedTools 教师客户端方案曾评估 Workers+D1，未实施）；
- 在线版设计要求（`docs/教育工具/教育工具在线版设计要求.md`）已定义 `/api/edu/*` 命名空间对齐约定。

### 1.2 目标（P1）

1. 落地三方式登录 + 7 天 JWT + 凭证刷新/找回；
2. 激活码 ⇄ 微信绑定（防转卖）、机器绑定 ≤3；
3. 课堂口令签发/续期/下载（服务端签名口令包）——与内容包 Schema §3 一致；
4. 内容包清单 manifest + 下载鉴权（口令级别达标）+ 服务端发新包（管理接口）；
5. 白名单数据上报 + 强制字段过滤 + 限频；
6. 全部跑在 Cloudflare 免费额度内（Workers + D1 + R2），零运维。

### 1.3 非目标（P1 不做）

- 内容包市场（搜索/分类/评分/创作者）→ P4；
- 在线版家长端/学习小组/报表 → 在线版项目，非本服务端；
- 文件批量上传/审核工作流 → P4。

## 2. 总体架构

```
┌─ Cloudflare Workers（教师客户端 API）──────────────────┐
│  /api/edu/* 路由                                        │
│  ├─ AuthService:  微信扫码/短信/密码/refresh/profile     │
│  ├─ LicenseService: 口令签发/续期/机器绑定               │
│  ├─ PackageService: manifest/下载/上传(管理)             │
│  ├─ ReportService: 白名单 ingest                       │
│  ├─ 中间件: JWT 校验 / 限频 / 字段白名单过滤             │
│  └─ 依赖: D1（数据）+ R2（文件）+ KV（限频计数/二维码会话）│
└───────────────────────────────────────────────────────┘
         │
         ├─ 短信：腾讯云短信 API（短信验证码）
         ├─ 微信：微信开放平台 OAuth（扫码登录）
         └─ 存储：Cloudflare D1（SQLite）+ R2（对象存储）
```

### 2.1 资源与命名

| 资源 | 用途 | 命名 |
|---|---|---|
| Worker | API 入口 | `edu-teacher-api` |
| D1 数据库 | 结构化数据 | `edu-teacher-db` |
| R2 bucket | 内容包/口令包文件 | `edu-teacher-pack` |
| KV | 限频计数 + 二维码会话 + refresh token | `edu-teacher-cache` |
| 域名 | 生产绑定 | `api.loongba.education`（自定义域） |

### 2.2 技术栈

- Cloudflare Workers（ES Modules，TypeScript）；
- `wrangler.toml` 配置 bindings（D1/R2/KV/Secret）；
- 依赖：`@cloudflare/workers-types`、`hono`（轻量路由，仓库有 Cloudflare 技能先例可选）或原生 `router`（接口少，原生即可，推荐原生减少依赖）；
- 密码哈希：`bcryptjs`（D1 校验 + Worker 环境可跑）；
- JWT：`@tsndr/cloudflare-worker-jwt` 或自实现 HS256（轻量）。

## 3. 数据模型（D1）

### 3.1 数据表

```sql
-- 教师账号
CREATE TABLE teachers (
  id            TEXT PRIMARY KEY,           -- 't_' + nanoid(12)
  openid        TEXT UNIQUE,                -- 微信 openid（可空，密码/短信登录无）
  phone         TEXT UNIQUE,                -- 手机号（登录主键）
  password_hash TEXT,                       -- bcrypt（密码登录）
  name          TEXT,
  grade         TEXT,                       -- 任教年级（必填）
  subject       TEXT,                       -- 任教科目（必填）
  agree_terms   INTEGER DEFAULT 0,          -- 同意条款
  license_level INTEGER DEFAULT 1,          -- 授权口令级别（激活后升 2）
  status        TEXT DEFAULT 'active',      -- active/disabled（违规封禁）
  created_at    TEXT,
  updated_at    TEXT
);

-- 激活码
CREATE TABLE licenses (
  license_key   TEXT PRIMARY KEY,           -- 'ABC-1234-...'（激活码）
  teacher_id    TEXT,                       -- 绑定教师（激活后写）
  license_level INTEGER,                    -- 1-2
  machine_quota INTEGER DEFAULT 3,
  status        TEXT DEFAULT 'unused',      -- unused/bound/revoked
  bound_at      TEXT,
  created_at    TEXT
);

-- 课堂口令
CREATE TABLE classroom_licenses (
  id            TEXT PRIMARY KEY,           -- 'lcs_' + nanoid
  teacher_id    TEXT,
  semester      TEXT,                       -- '2026S' / '2026A'
  license_level INTEGER,
  expires_at    TEXT,                       -- 一学期到期日
  machine_count INTEGER DEFAULT 0,
  machines      TEXT,                       -- JSON: ['fp1','fp2']
  status        TEXT DEFAULT 'valid',       -- valid/expired
  created_at    TEXT,
  UNIQUE(teacher_id, semester)
);

-- 内容包元数据（manifest 从 R2 静态 JSON 读取；本表为 P4 市场演进预留/版本审计）
CREATE TABLE packages (
  package_id    TEXT PRIMARY KEY,
  version       TEXT,
  package_type  TEXT,                       -- app/data
  name          TEXT,
  required_license_level INTEGER,
  min_shell_version TEXT,
  size_bytes    INTEGER,
  checksum      TEXT,
  r2_key        TEXT,
  is_latest     INTEGER DEFAULT 1,
  released_at   TEXT
);

-- 上报记录（聚合白名单，不含儿童数据）
CREATE TABLE reports (
  id            TEXT PRIMARY KEY,
  teacher_id    TEXT,
  day           TEXT,                       -- '2026-09-23'
  data          TEXT,                       -- JSON（白名单字段）
  created_at    TEXT
);
```

### 3.2 索引

```sql
CREATE INDEX idx_licenses_teacher ON licenses(teacher_id);
CREATE INDEX idx_classroom_teacher_sem ON classroom_licenses(teacher_id, semester);
CREATE INDEX idx_reports_teacher_day ON reports(teacher_id, day);
```

## 4. 认证实现

### 4.1 微信扫码登录

```
流程：
1. POST /auth/wechat/qr → Workers 生成 qr_id + 二维码 URL（微信开放平台网页授权链接）
   → 存 KV（qr_id → {state, status:'waiting', device_id}，TTL 120s）
2. 客户端展示二维码；轮询 GET /auth/wechat/status（每 2s）
3. 用户微信扫码 → 授权回调到 Workers /auth/wechat/callback?code=
   → 用 code 换 openid（微信 API）
   → 查 teachers.openid：
      存在 → 更新 KV status='confirmed'，生成 JWT
      不存在 → 状态 'need_bind'（前端引导补任教信息 → POST /auth/profile → 完成注册）
4. 客户端轮询到 confirmed → 拿到 JWT → 存本地（7 天凭证缓存）
```

**微信 OAuth 前置**：需微信开放平台账号（`docs/教育工具/教育工具在线版设计要求.md` 已评估预留）；P1 若微信审核未过 → **先以短信/密码为主，微信扫码接口留桩（返回 501 占位）**，不阻塞 P1 认证闭环。

### 4.2 短信验证码

```
1. POST /auth/sms/send：
   → 限频检查（KV 计数：phone 分钟/小时/天）
   → 生成 6 位码，存 KV（sms:{phone} → code+exp，TTL 300s）
   → 调腾讯云短信 API 发送
2. POST /auth/sms/verify：
   → 校验 code → 查 phone 建账号（无则注册）→ 返回 JWT
```

**腾讯云短信**：需短信签名/模板审核（仓库评估过 100 条试用）；P1 若审核未过 → 开发环境可打日志兜底（`SMS_MOCK=true` 环境变量）。

### 4.3 密码登录 / 找回

- `POST /auth/password`：bcrypt 校验 → JWT；
- 找回：短信验证码（复用 4.2 流程）→ `POST /auth/password/reset` → 更新 password_hash。

### 4.4 JWT 与凭证

- 签发：HS256，`JWT_SECRET` 环境变量；payload `{ sub, lvl, exp (7d), iat, jti }`；
- refresh token：UUID 存 KV（`rt:{jti}` → teacher_id，TTL 7d）；
- 中间件 `requireAuth`：验签 + 查 status（disabled → 401 FORBIDDEN）。

### 4.5 激活码绑定

```
POST /auth/activate：
  → 校验 license_key 存在 && status='unused'
  → 绑定 teacher_id（license_key→teacher_id, status='bound', bound_at）
  → 教师 license_level 升级（1→2）
  → 返回 machine_quota（默认 3）
```

## 5. 课堂口令实现

### 5.1 签发/续期（POST /license/renew）

```
→ requireAuth
→ 校验教师 license_level ≥ 1（未绑激活码 → 403）
→ 读取 classroom_licenses(teacher_id, semester)：
    无 → 创建：expires_at = 学期末（规则：2026S → 2027-01-31；2026A → 2026-08-31，
          每年 2 期：A=春(2-8月) S=秋(9-次年1月)，规则集中管理）
    有且 valid → 续期：expires_at 顺延一学期
→ 生成口令包 JSON（Schema §3.2 结构）→ 用服务端私钥 ed25519 签名（Secret: LICENSE_SIGN_KEY）
→ 存 R2（key: license/<teacher_id>/<semester>.json）+ 返回给客户端
```

### 5.2 机器绑定（POST /license/bind）

```
→ requireAuth + 口令有效
→ 读 classroom_licenses.machines（JSON 数组）：
    若 machine_fp 已存在 → 返回当前（幂等）
    若 len ≥ machine_quota → 403
    否则追加 → 更新 count/machines → 重签口令包（含新 machines）→ 存 R2
```

### 5.3 签名实现

- 密钥：`LICENSE_SIGN_KEY`（ed25519 私钥，Workers Secret）；
- 签名包结构 = Schema §3.2 `license.json`（含 signature）；
- 客户端（Rust）用内置公钥校验（P0 自签 → P1 换真实公钥，公钥随壳分发，config 内嵌）。

## 6. 内容包实现

### 6.1 manifest（GET /packages/manifest）

- 来源：**R2 静态文件** `manifest/latest.json`（运营侧手工更新，简单配置起步）或 D1 查询；
- 方案：R2 静态 JSON 为 MVP（上新包 = 传文件 + 更新 JSON，免代码发布），P4 迁 D1 动态化；
- 响应结构见 API 契约 §4.1。

### 6.2 下载（GET /packages/<id>/<ver>）

```
→ requireAuth
→ 读口令 classroom_licenses(teacher, 当前学期)：
    valid && level ≥ package.required_license_level → 放行
    否则 → 403（口令过期/级别不足）
→ 从 R2 读文件（key: content/<id>/<ver>.zip）→ 流式返回（+校验 checksum 头）
```

### 6.3 上传（POST /packages，管理）

```
→ X-Api-Key 校验（Secret: PKG_ADMIN_KEY）
→ multipart 收文件 → 存 R2（content/<id>/<ver>.zip）
→ 计算 checksum → 写 D1 packages 表（is_latest=1，旧版清除标志）
→ 更新 R2 manifest JSON（如用静态方案）
```

## 7. 安全与运维

| 项 | 方案 |
|---|---|
| Secret 管理 | Workers 环境变量（`JWT_SECRET`/`LICENSE_SIGN_KEY`/`PKG_ADMIN_KEY`/`SMS_*`/`WX_*`），不入库不入代码仓 |
| 限频 | KV 计数（memcache 语义）：见 API 契约 §6 表 |
| 上报过滤 | 请求体 JSON 白名单 schema 校验（只取白名单字段，未知字段丢弃），≥64KB 拒绝 |
| 短信防刷 | 限频 + 图片验证码（P1 可先不做验证码，靠限频兜底） |
| CORS | 限定域名（在线版 + 壳内 WebView fetch 用 IP/Domain 白名单） |
| 部署 | `wrangler deploy`；环境：dev（worker.dev）/ prod（自定义域）；CI 可接 GitHub Actions（可选） |
| 数据保留 | 儿童数据零存储（上报已白名单过滤）；教师账号数据保留期按合规要求（P1 记默认保留 3 年） |
| 日志 | Workers 内置日志（无第三方）；敏感字段脱敏 |

## 附录 A · 轻量机（Node/SQLite）移植方案

> 状态：**附录 A v1.0，随 P2 后实施**（2026-09-24 决策）。
> 背景：实际生产环境为**腾讯云轻量应用服务器 Ubuntu**（已购），非 Cloudflare。用户决策：**CF 免费档仅作测试/前期过渡，生产落轻量机**；云函数（SCF）不采用——已有现成服务器，SCF 需另开通且拆成"函数+网关+数据库+对象存储"四件套，比守一台机更复杂。
> 目标：同一份业务代码，**双入口**——`wrangler dev/deploy`（Workers，测试过渡）与 `node`（轻量机，生产）——handler 零改动。

### A.1 移植面盘点（已核实，2026-09-24）

Workers 专属 API 面**恰好只有三类绑定 + 6 个配置串**，无 `waitUntil`/`caches`/`cf`/`WebSocket`/Queues 等任何其他 CF API；`_ctx` 参数收到但未使用。

| 绑定/配置 | 用法（file:line 依据） | 移植去向 |
|---|---|---|
| `env.DB`（D1） | **27 处**，全部 `.prepare().bind().first()` 或 `.run()`（**无** `.all()/.raw()/.execute()/.batch()`） | `node:sqlite`（DatabaseSync）自写 2 方法 shim |
| `env.KV` | 5 个 key 族（`rt:`/`rtoken:`/`sms:`/`rl:`/`rl:authfail:`），全字符串值，仅 TTL 淘汰 | SQLite 单表 `kv_store(k,v,expires_at)` + 懒删除 |
| `env.R2_PACK`（注意：**不是** `R2`） | `.get()` 6 处 / `.put()` 4 处，**无** delete/list/head；键：`manifest/latest.json`、`content/<id>/<ver>.zip`、`license/<uid>/<sem>.json` | 本地文件系统目录（key 即相对路径） |
| `JWT_SECRET` | ratelimit.ts:58 校验必配 | `process.env` |
| `LICENSE_SIGN_KEY` / `LICENSE_SIGN_KEY_ID` | sign.ts:56/94（缺省临时自签仅限本地） | `process.env` |
| `PKG_ADMIN_KEY` | packages.ts:109 上传管理密钥 | `process.env` |
| `SMS_MOCK` / `LICENSE_SIGN_KEY_ID`（vars） | auth.ts:138 字符串比较 `"true"` | `process.env`（保持字符串，勿转 bool） |
| `SMS_SECRET` | types.ts:15 声明但**从未读取**（死配置） | 移除引用，不移植 |

**零新运行时依赖**：项目本无任何 runtime deps（hashing=PBKDF2 WebCrypto、JWT=手写 HS256、签名=WebCrypto Ed25519），Node ≥18.4 原生支持全部 WebCrypto 能力（Ed25519 自 v20.19.3/v22.13 起稳定；本机 Node v26 已验证）。现有 PBKDF2 密文**移植后直接有效，无需重哈希**。

### A.2 架构：适配层双入口

```
server/
├── src/
│   ├── index.ts            # Workers 入口（export default { fetch }）—— 不改
│   ├── handlers/ lib/ types.ts              # 业务层 —— 不改
│   └── node/
│       ├── main.ts         # ★ Node 入口：node:http → Request → worker.fetch(req, env, {})
│       ├── env.ts          # ★ 读 .dev.vars / process.env 组装 Env
│       └── adapters.ts     # ★ D1/KV/R2 三个 shim，满足 types.ts 的 Env 接口
├── migrations/0001_init.sql # 原样复用（纯 SQLite DDL）
└── data/                    # gitignore：app.db + r2/ 目录
```

- **D1 shim**：`prepare(sql) → bind(...) → { first(), run() }`；`first()` 须返回 `null`（非 better-sqlite3 的 `undefined`）以保持 `T | null` 类型契约；SQL 已全为 SQLite 方言（含 `ON CONFLICT ... DO UPDATE SET ... = excluded.*`，packages.ts:133），原样执行。
- **KV shim**：单表 + 懒淘汰（读时查 `expires_at`）；限频 key 本身含时间窗索引，TTL 是双保险，无需 cron。
- **R2 shim**：文件目录；返回对象只需 `.body`（WHATWG ReadableStream）/`.size`/`.json()`；所有 put 调用点已是 try/catch 尽力而为（R2 是软依赖），无原子性要求。
- **HTTP bridge**：缓冲 `IncomingMessage` → `new Request(...)` → 调用现有 `worker.fetch` → 写回 `ServerResponse`。路由是手写 if-chain，**不需要任何框架**（无 express/fastify）。
- **构建**：`tsx` 直跑 TS（dev 依赖），或后续可选 esbuild 单文件打包；`tsconfig` 需加 `@types/node` 并保持 wrangler 路径可用。

### A.3 配置与密钥（对应正文 §7）

| 名 | Workers 注入 | 轻量机注入 |
|---|---|---|
| `JWT_SECRET` | `wrangler secret put` | systemd `Environment=` / `.env`（≥32 字节随机） |
| `LICENSE_SIGN_KEY` | `wrangler secret put`（PKCS8 PEM） | 同上；与壳端预置公钥配对，**不可随机器丢失** |
| `PKG_ADMIN_KEY` | `wrangler secret put` | 同上（`publish_pack.py --api-key`） |
| `SMS_MOCK` | wrangler.toml var | 环境变量，生产接真短信后置 `"false"` |

**激活码种子**：`licenses` 表业务代码只读不写（auth.ts:249/259），上线前须向 SQLite 手工 seed 激活码——Workers 与轻量机同样适用（运维项，非代码项）。

### A.4 运行与部署（轻量机 Ubuntu）
