## 2. 短信真接入（腾讯云）

### 2.1 ⚠️ 前置阻塞项（必须先办）

1. **账号主体 = 企业认证**：2025-09-18 起个人账号无法创建个人自用签名（发不出国内短信）；教师客户端是教育产品，**必须腾讯云企业实名认证**（营业执照 + 法人/经办人证件 + 承诺函），周期约 7–10 个工作日（运营商报备）。
2. **教育行业硬限制**：房地产/教育行业**只允许发送验证码模板**——通知/营销类一律驳回。教师客户端登录验证码场景合规，**不要申请通知类模板**。
3. **申请顺序**：企业认证 → 资质报备 → 创建签名（~2h 审核 + 运营商报备 7–10 工作日）→ 创建验证码模板（~2h）→ 创建应用取 `SdkAppId`。

### 2.2 依赖与配置

```
dotnet add package TencentCloudSDK.Sms --version 3.0.1499   # 传递依赖 TencentCloudSDK.Common + Newtonsoft.Json
```

`appsettings.json`（或环境变量覆盖）新增节：

```json
"TencentSms": {
  "Mode": "Mock",                    // Mock | Real（生产必 Real）
  "Region": "ap-guangzhou",
  "Endpoint": "sms.tencentcloudapi.com",
  "SdkAppId": "1400xxxxxx",
  "SignName": "你的签名内容",         // 不含【】
  "TemplateId": "xxxxxxxx",
  "SecretId": "${TENCENTCLOUD_SECRET_ID}",   // 环境变量注入
  "SecretKey": "${TENCENTCLOUD_SECRET_KEY}"
}
```

### 2.3 代码改造（替换 SendSms 的 mock 段）

- 新增 `SmsService.cs`（`ISmsService` + `TencentCloudSmsService` 实现）：`SendVerificationCodeAsync(phone, code)`，内部构造 `SendSmsRequest`（`SmsSdkAppId/SignName/TemplateId/TemplateParamSet=[code]/PhoneNumberSet=["+86"+phone]`），校验 `SendStatusSet[].Code == "Ok"`，失败抛异常。
- `SmsClient` 注册 Singleton（线程安全）；密钥从配置/环境变量读，禁止硬编码。
- `Program.cs`：`Sms:Mock` → `TencentSms:Mode` 判定——`Mock` 走现有打印 + dev_code；`Real` 调 `ISmsService`。
- 错误处理：区分平台拒绝（参数/资质/频控，4xx 语义）与送达失败（运营商返回，记录日志 + 可选回执）；验证码散列存储/一次性消费逻辑**不动**（Storage.cs 已有）。

### 2.4 频控与配额（对齐 A01 §6，I1）

> **Oracle 评审 I1**：A01 §6 要求「1 条/分钟；5 条/小时；10 条/天」，当前仅 60s 重发间隔。补小时/天级滚动窗口计数。

| 项 | 值 | 设计配合 |
|---|---|---|
| 单号 60 秒 | 1 条（现有 ResendGap，保留） | `TOO_FREQUENT` 429 逻辑保留 |
| 单号自然日 | **2 条**（应用默认，可调） / 运营商非营销硬顶 **10 条/天** | 连续失败锁定账号而非狂发；验证码过期重发计入配额 |
| **单号小时级（I1）** | **5 条/小时**（A01 §6） | Storage `SmsRecord` 增 `HourCount/DayCount/WindowStart` 滚动窗口（D13 实施清单同步） |
| **IP 级（I1）** | 认证失败 5 次/小时/IP → 429（A01 §6） | 简易 IP 计数（或 Caddy rate_limit 兜底，D13 §3.3） |
| 单次请求 | ≤200 号 | 验证码单号发送，无此边界 |
| 价格 | 0.041–0.050 元/条（10 万条档 0.045） | 首购 1000–10000 条，成本可忽略 |

### 2.5 失败降级 + 错误码映射（I7）

- `Real` 模式短信 API 不可达/频控命中 → 返回现有 `Error` 结构（A01 语义），**不得回退 Mock 发码**（生产泄露验证码 = 安全事件）。
- 日志记录腾讯云错误码，便于告警。

**腾讯云错误码 → A01 code 映射表（Oracle I7）**：

| 腾讯云错误码 | A01 code | HTTP |
|---|---|---|
| `Ok` | — | 200 |
| `LimitExceeded.PhoneNumber*` / `DeliveryFrequencyLimit` | `RATE_LIMITED` | 429 |
| `UnauthorizedOperation.SmsSdkAppIdVerifyFail` | `UNAUTHORIZED` | 401 |
| `InvalidParameter.*`（参数错） | `BAD_REQUEST` | 400 |
| `FailedOperation.SignatureIncorrectOrUnapproved` / `TemplateIncorrectOrUnapproved` | `SERVICE_UNAVAILABLE`（资质未过审） | 503 |
| `FailedOperation.*`（运营商送达失败） | `SMS_SEND_FAILED` | 502 |
| 网络/超时 | `SERVICE_UNAVAILABLE` | 503 |

## 3. 微信 OAuth 真接入（微信开放平台 · 网站应用）

### 3.1 ⚠️ 前置阻塞项（必须先办）

1. **开放平台账号 + 开发者资质认证**：注册 `open.weixin.qq.com`，完成开发者资质认证（**300 元/年**，仅微信支付）；网站应用通常需**企业/组织类主体**（个人主体功能受限）。
2. **创建网站应用并审核**：审核 1–7 个工作日；通过后再**申请开通「微信登录」能力**（单独审核项）。
3. **授权回调域名**：域名需 **ICP 备案**（新备案域名 24h 后才可配置）、仅 https、无 `/` 后缀；配置后回调只能到该域名。**选 `api.taoli.loongba.cn`**（与 D13 同域）。

### 3.2 授权流程（OAuth2.0 authorization_code）

```
壳（已登录，持 JWT）── GET /api/edu/auth/wechat/authorize ──▶ 服务端
   服务端：生成 bind_token（TTL 30min，关联用户）+ state → 返回授权 URL
壳 WebView ── 打开 https://open.weixin.qq.com/connect/qrconnect?appid&redirect_uri&response_type=code&scope=snsapi_login&state#wechat_redirect ──▶ 用户扫码
微信 ── 302 ──▶ https://api.taoli.loongba.cn/api/edu/auth/wechat/callback?code=CODE&state=STATE
   服务端：校验 state → code 换 openid（AppSecret 服务端持有）→ 按 bind_token 关联用户 → 绑定 wechat_openid
   ── 返回「绑定成功/失败」HTML（壳 WebView 展示；失败含原因文案）
壳 ── GET /api/edu/auth/wechat/bind/status?token=bind_token ──▶ 服务端：bound → 壳刷新用户态
```

**设计要点**：
- **redirect_uri 必须 = 开放平台已配置域名下的 https 地址**（壳本地页面/`tauri://` 无法作回调域）→ 用服务端中转 callback 页面；壳只负责打开授权 URL + 展示回调结果。
- **state 防 CSRF**：32 字节随机 hex（≥128 bit）+ 服务端一次性校验（TTL 30min，校验后即删）；`bind_token` 为服务端签发的短期票据（32 字节随机 hex，关联已登录用户），避免 JWT 出现在 URL。
- **code 换 openid**：`GET https://api.weixin.qq.com/sns/oauth2/access_token?appid&secret&code&grant_type=authorization_code` → 响应含 `access_token(2h)/refresh_token(30d)/openid/unionid`（网站应用直接返回 unionid）。code 仅能换一次（重复 → `40029 invalid code`），超时 10 分钟。
- **绑定策略**：openid 查绑定表 → 已有（幂等返回已绑定）；无 → 写入 `users.wechat_openid`；**unionid 落库（可空）**为未来跨端打通预留。
- **用户信息（I6 简化）**：当前仅取 openid + unionid；`/sns/userinfo` 拉昵称/头像 **列为后续迭代可选**（A01 `teacher` 对象无这些字段，引入文件存储属范围蔓延）。
- **Token 生命周期（I6 简化）**：绑定是一次性操作（code → openid → 绑定即完事）——**不缓存 access_token、不持久化 refresh_token**（避免引入加密密钥管理复杂度）；微信侧后续如需拉用户信息再临时换取。

### 3.2b bind_token 状态机（Oracle B5，必须定义）

| 项 | 设计 |
|---|---|
| 存储 | 新增 `data/wechat_binds.json`（Storage.cs 加 `WechatBindRecord(bind_token, state, user_id, status, created_at, bound_at)`），**落盘持久化**（进程重启后 pending 态可恢复） |
| 状态 | `pending → bound / expired / failed`；`callback` 成功写 `bound`，code 换 token 失败写 `failed`，TTL 30min 写 `expired` |
| 轮询 | `bind/status` 每 2s、上限 = TTL 30min；命中终态即返回（bound/failed/expired）；轮询不改变状态 |
| 安全 | bind_token/state 均 32 字节随机 hex；state 一次性校验（callback 消费后即删）；bind_token 防枚举（高熵 + TTL） |
| 并发 | 同一用户同时发起多次绑定 → 前序 bind_token 置 expired（只保留最新） |

**安全边界记录**：当前仅「绑定」不「登录」——若将来实现微信扫码**登录**（A01 §2.1 的 `qr_id` 轮询），需防「绑定劫持」（攻击者用自己 bind_token+state 诱导受害者扫码，绑受害者 openid 到攻击者账号）；届时登录流程须用独立 session 而非绑定票据。

### 3.3 配置项（环境变量注入，D13 env 模板同步）

| 配置 | 说明 |
|---|---|
| `WECHAT_APPID` | 网站应用 AppID |
| `WECHAT_APPSECRET` | **仅服务端持有**，严禁下发前端/进代码库 |
| `WECHAT_CALLBACK_BASE` | `https://api.taoli.loongba.cn`（授权回调域名，ICP 备案） |
| `WECHAT_USE_MOCK` | `true`（本地/CI 用 mock 派生 openid）/ `false`（生产） |

### 3.4 接口适配（B1：路径不与 A01 §2.1 冲突 + 回写 A01）

- `POST /api/edu/auth/bind/wechat { code }`（需 JWT）：保留——**真实实现** = 用 code 换 openid 后绑定（网页端直接回调场景）；壳内改为走 §3.2 中转流程。
- 新增 **`GET /api/edu/auth/wechat/authorize`**（需 JWT → 返回授权 URL）+ **`GET /api/edu/auth/wechat/bind/status`**（轮询绑定结果，**不与 A01 §2.1 登录轮询 `/wechat/status?qr_id=` 冲突**）+ **`GET /api/edu/auth/wechat/callback`**（中转回调页，无 JWT）。
- **回写 A01 §2**：新增三端点契约入档（authorize/bind-status/callback 路径、参数、错误码）；既有端点签名不变。
- Mock 模式：authorize 返回假 URL，code → `wechat_mock_<code>`（现状逻辑保留为 Mock 分支）。

### 3.5 安全要点（官方规范）

- HTTPS 强制；`redirect_uri` 参数顺序严格按文档（appid→redirect_uri→response_type→scope→state→#wechat_redirect）
- AppSecret **严禁下发前端/进日志**，仅服务端持有；access_token/refresh_token 不落库（I6 简化，绑定一次性）
- 频率：code 换 token 1 万/分钟；高频调用注意限流

## 4. 验收标准

1. `Sms:Mode=Mock`：现有冒烟闭环不变（send → dev_code → verify）
2. **生产过渡（B2）**：Production + Mock → send 503 无 dev_code；Production + Real → 正常
3. 微信 Mock：authorize → 假扫码 → bind 幂等（现状回归）
4. 微信 Real（开放平台应用）：扫码 → 中转回调 → 绑定真实 openid；重复绑定幂等；state 过期/错配拒绝；错 code（40029）错误提示；bind_token expired 轮询终态
5. 壳端真机：config.json api_base 指向生产 → 手机号登录 / 微信扫码绑定全链路
6. `dotnet build` 0 警告；单测覆盖（N3 用例清单）：SendSmsRequest 参数构造 / Mock·Real 分支 / 频控小时·天级 / 腾讯云错误码映射 / bind_token 状态机（过期、枚举拒绝、幂等）/ state 一次性校验

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 腾讯云企业认证未办/被拒（阻塞） | **生产过渡策略（D13 §3.4）**：认证端点 503 禁用，配置下发不受影响；S6 真接入待认证 |
| 教育行业模板限制 | 仅申请验证码模板（合规场景），模板文案已符合规范 |
| 短信成本/配额耗尽（测试误发） | Mock/Real 严格分流；测试环境恒 Mock；小时/天级频控（I1） |
| 微信开放平台审核 + ICP 备案（阻塞，周期长） | 测试号先行联调；正式应用审核周期预留；备案域名 24h 生效 |
| 微信 AppSecret 泄漏 | 仅服务端持有；环境变量注入；严禁前端/日志 |
| 绑定劫持（未来微信登录场景） | 当前仅绑定不登录，风险低；已记录安全边界（§3.2b） |
