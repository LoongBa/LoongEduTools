# D11 下载目录监控与课件素材自动归档方案

> 状态：v1.0（2026-09-26 落盘；设计评审版，待实现）
> 前序：D01 §2（config.json 字段/壳目录结构）、D04（内容包管线）、D09（防扩散红线）、D10（签名配置/信任链）、R03 §4（下载扩展/工具箱）
> 本方案回答：监控教师浏览器下载目录，发现课件素材（PDF/图片/音频/视频）时如何确认归类、自动归档进客户端管理目录、合并通知提示、分类插件/内容/教材，最终支持整体打包导出。
> 关联代码：`src-tauri/src/commands/`（textbook.rs/store.rs/recents.rs）、`src/ui/lib/store.ts`（useNotifications/useDownloadTasks）、`src/ui/components/`（TopBar/DownloadExtView/ToolboxPanel）

---

## 1. 定位与边界

### 1.1 解决的问题

| 现状痛点 | 本方案 |
|---|---|
| 教师用浏览器扩展抓取教材/课件 → 文件散落浏览器下载目录 | 客户端监控下载目录 → 自动发现 → 提示确认归类 |
| 教材扫描需手动「选目录 → 扫」（TextbookSection 现状） | 发现即提示，确认后自动归档，无需手动扫描 |
| 名师课堂音频/视频等课件资料无法统一管理打包 | 归档进客户端 `archives/`，随随身工具包走 |
| 通知列表平铺无分类（Notification 无业务通道） | 通知加 `channel`：插件/内容/教材 + 合并相近通知 |

### 1.2 版权红线（延续 D09·README 硬约束）

> **只供教师个人教学与学习使用**，不对外分发。归档的教材/课件资料仍受版权保护——客户端**只做整理与打包（随 U 盘跟教师走），不提供任何形式的分发/分享能力**。UI 文案必须明确提示「仅供个人教学和学习使用」。

### 1.3 已否决方案（决策记录）

| 方案 | 否决原因 |
|---|---|
| 客户端 CDP 驱动浏览器"执行扩展 JS" | 第三方扩展无法被 CDP 注入（扩展沙箱持有 chrome.* 权限）；需逆向复刻抓取逻辑 + 批量抓取原版教材超出合理使用形态，版权边界变灰（见前轮分析） |
| 安装扩展 + 客户端通讯 | 第三方扩展无 native messaging / 本地 socket / 自定义协议，**无法通讯**；正确做法是监视其落盘 |
| 强制浏览器改下载目录到客户端目录 | 不现实：Preferences 只在浏览器未运行时可写、Chrome 有危险路径保护、多 Profile 复杂；改为**监视真实下载目录** |
| `notify` crate 实时监视 | 项目硬约束「零新增 crate」（Cargo.toml L38-44 两次声明 + MSRV 1.77.2）；`notify` 不存在于 Cargo.lock；`tauri-plugin-fs-watch` 非官方插件。**改用 std 轮询**（详见 §4.2） |
| 归档目录放 AppData | U 盘绿色形态下 AppData 换机即失，违背「随身」；只能 `<exe>/archives/` |

## 2. 数据流与信任链

```
教师浏览器（Edge/Chrome）下载 → 下载目录（Known Folder / 浏览器 Preferences）
        │
        ▼
客户端 archives 监控（std 轮询线程，spawn 于 setup）
        │ 发现新文件（非 baseline）→ 判定下载完成（:crdownload 移除 / 大小稳定）
        ▼
确认卡片（UI · Notification 带 action/meta）
   ├─ 自动识别：学科/版本/年级/册次（文件名关键词）→ 预填可编辑
   ├─ ☑ 下次同类自动整理（记住偏好 → 存规则）
   ├─ 取消（留在下载目录，通知里可回看） / 确认归档
        ▼
Rust archive::confirm_archive（移动文件）
   └→ <exe>/archives/<学科>/<版本>/<年级><册次>/<文件>
        ▼
通知（channel=archive，group_key 合并）+ 打包索引更新
```

**信任链与 D10 的关系**：归档规则（自动整理偏好、分类映射）属于**平台配置**，可纳入 D10 签名配置包的 `config` 字段下发；但本方案 MVP 先做本地规则（`taoli.archive.rules` localStorage），D10 配置包字段扩展留后。

## 3. 下载目录定位（Win7 兼容）

### 3.1 定位优先级

| 优先级 | 来源 | 方式 | 坑 |
|---|---|---|---|
| 1 | 浏览器 Preferences `download.default_directory` | 读 `%LOCALAPPDATA%\Microsoft\Edge(User Data)\Default\Preferences` / Chrome 同构 | 文件被浏览器 mmap 锁，只读不写；多 Profile 需扫 `Profile N` |
| 2 | 组策略 `HKLM\SOFTWARE\Policies\Microsoft\Edge\DownloadDirectory` | winreg 读 | 仅 Edge；Chrome 无强制策略 |
| 3 | **Windows Known Folder** `FOLDERID_Downloads` | `SHGetKnownFolderPath` | **Win7 完全支持**（Vista 引入）；返回值需 `CoTaskMemFree`；注册表缺失时降级 `%USERPROFILE%\Downloads` |

**实现**：Rust `known_folders` crate（仅 Windows，薄封装 `SHGetKnownFolderPath`）或 projects 已有的 `windows` crate（Tauri 2 已依赖，零新增）。**推荐直接走 `SHGetKnownFolderPath` 的 `windows` crate 路径**——零新增依赖。

### 3.2 位置可视化

设置页显示当前检测到的下载目录 + 「修改」按钮（`open({directory:true})` 手动指定，存 `config.json`）。**网络盘/映射盘检测到 → 提示"实时监控不可靠，已切换 500ms 轮询"**（ReadDirectoryChangesW 对 SMB 旧版返回 `ERROR_INVALID_FUNCTION`；轮询方案天然规避，见下）。

## 4. 目录监视（Rust · 零新增 crate）

### 4.1 关键技术：为什么用轮询

| 方案 | 结论 |
|---|---|
| `notify` crate（RecommendedWatcher=ReadDirectoryChangesW） | 不存在于 Cargo.lock；违反「零新增 download」约束；网络盘/映射盘不可靠（SMB 限制）；Win7 需实测 |
| `tauri-plugin-fs-watch` | 非官方插件（仓库 READ ONLY），v2 已并入 `tauri-plugin-fs` 但 Downloads 不在 BaseDirectory 白名单 |
| **std 轮询**（推荐） | 零依赖、天然兼容网络盘、实现简单、教室低配机单目录 read_dir 开销极小 |

**落地**：新建 `commands/archive.rs`，`std::thread::spawn` 后台线程：

```rust
// 伪代码：2s 间隔轮询下载目录
loop {
    let now = snapshot(dir);                          // 文件名+大小+修改时间的 HashMap
    for (name, meta) in now.diff(baseline) {          // 新增或变化的文件
        if is_temp_suffix(name) { continue; }         // :crdownload / .part
        if !size_stable(&path, name) { continue; }    // 两次采样间隔 500ms 大小一致
        emit_pending(&path, name);                    // app.emit("archive:new", ...)
    }
    baseline = now;
    sleep(2s);
}
```

- **baseline 快照**：监视启动瞬间记录目录清单，避免把旧文件当新下载（参照下载管理库的两段判定）
- **下载完成判定**：`:crdownload` 后缀（Chrome/Edge）/ `.part`（Firefox）移除 + 文件大小两次采样一致（间隔按文件大小分档：<10MB 200ms、10-200MB 500ms、>200MB 1s）
- **事件合并**：Chrome 单个下载会产生多次 Modify 事件 → 轮询天然合并（每 2s 一次快照）
- **残留清理**：启动时清除 >24h 的 `:crdownload` 残留
- **挂载**：`lib.rs setup()`（L109 后）spawn；`app.emit("archive:new")` 推前端（`core:event:allow-emit` 已在 capabilities 授权，`package.rs:422` emit 是先例）

### 4.2 事件驱动 vs 轮询并存的说明

轮询线程**只负责发现**；前端收到 `archive:new` 事件后弹确认卡片（交互在 UI 层）。发现与确认解耦——用户不在场时新文件进入「待确认」队列（`taoli.archive.pending` 持久化），下次打开客户端仍可处理。

## 5. 确认卡片（UX · 按用户需求规格）

### 5.1 卡片内容（发现新文件时）

```
┌─────────────────────────────────────────────┐
│ 📄 检测到新下载                             │
│ U01_Greetings.mp4（12.5 MB · 视频）         │ ← 文件名 + 类型 + 大小
│                                             │
│ 课件内容仅供个人教学和学习使用              │ ← 版权提示（必显，D09 红线）
│                                             │
│ 学科 [英语 ▾]  版本 [人教版 ▾]              │ ← 自动识别预填，可编辑
│ 年级 [四年级 ▾]  册次 [上册 ▾]              │
│                                             │
│ ☑ 下次同类文件自动整理（不再询问）          │ ← 记忆偏好
│                                             │
│ [取消/忽略]  [确认归档]                      │
└─────────────────────────────────────────────┘
```

### 5.2 自动识别规则（文件名关键词 → 元数据，预填不锁定）

```typescript
// 参考 auto_file_organizer 的 pattern 配置 + Google Photos「建议→确认」模式
const DETECTION_RULES = [
  { pattern: /四[上下]|Grade.?4|U0[1-4]/i, subject:"英语", version:"人教版", grade:"四年级", volume:"上册" },
  { pattern: /U0[5-8]|四[上下].*英语/i, ... volume:"下册" },
  { pattern: /部编版|语文/i, ... },
  // 用户纠正持久化：用户改过字段 → 记忆 → 下次识别优先用户纠正
];
```

**识别置信度**：高（文件名含 `四年级英语上册` 明确词）→ 绿框 +「自动识别」；中（只匹配 `U01`）→ 黄框「部分识别请确认」；低 → 不预填全手动。

### 5.3 级联选择（学科 → 版本 → 年级 → 册次）

- 父未选 → 子禁用（placeholder「请先选学科」）
- 父变更 → 子 dataSource 重过滤 + 子值清空（参考 Syncfusion/Zag 级联模式）
- 册次（上/下）用 **segmented/radio** 而非 dropdown（仅 2 选项，dropdown 低效）
- **反模式禁止**：识别结果锁定不可编辑、级联不清空子级、没有「重新识别」入口

### 5.4 记忆偏好

「下次同类自动整理」勾选 → 存规则 `{pattern, subject, version, grade, volume}` 到 `taoli.archive.rules`（localStorage）。规则匹配成功 → 后续同模式下载**静默归档 + 通知追加**，不再弹卡片。规则匹配失败 → 通知追加「未匹配」条目，仍可手动处理。

**与 D10 配置包的关系**：规则属于平台配置，D10 签名包可下发全局默认规则；本机用户自定义规则覆盖（优先级：签名包默认 < 用户自定义）。

## 6. 归档（Rust · 移动文件）

### 6.1 目录结构（随 U 盘走）

```
<exe>/archives/
├── 英语/人教版/四年级上册/U01_Greetings.mp4
├── 英语/人教版/四年级上册/U02_Words.mp3
├── 音乐/人音版/三年级上册/...
└── archives.json   ← 归档索引（同 toolbox.json 模式：uuid → {file, subject, ...}）
```

沿用 `exe_dir()`（recents.rs:14）+ 与 `packages/`/`toolbox/` 同级。教师点「打开运行目录」（`window::open_run_dir` 先例）即能看到。

### 6.2 移动实现（复用 staging→rename 双先例）

```rust
#[tauri::command]
pub fn archive_confirm(app, path: String, meta: ArchiveMeta) -> Result<ArchiveEntry, String> {
    // meta = { subject, version, grade, volume }
    let dest_dir = exe_dir(app)?.join("archives")
        .join(&meta.subject).join(&meta.version).join(format!("{}{}", meta.grade, meta.volume));
    fs::create_dir_all(&dest_dir)?;
    let dest = dest_dir.join(file_name);           // 重名加 (1) (2)
    let staging = dest_dir.join(format!(".{}.staging", file_name));
    fs::copy(&path, &staging)?;                     // 拷贝而非移动：下载目录是用户资产，保留原文件
    if verify_copy(&staging)? { fs::rename(&staging, &dest)?; }   // staging→rename 原子落盘
    else { fs::remove_file(&staging)?; return Err(...); }
    let entry = write_archives_index(app, ...)?;    // 读改写 archives.json（recents 模式）
    Ok(entry)
}
```

- **拷贝而非移动**：下载目录是用户浏览器资产，归档是"收编副本"而非"搬走原件"——用户删浏览器记录仍可追溯
- **原子落盘**：staging → `rename`（复用 `store.rs:325,521` 先例）
- **索引写**：`archives.json` 必须**读改写保留未知字段**（复用 `recents.rs::save_recents` 的 Value 合并模式，防冲 `api_base` 同类坑）
- **撤销**（必做，参考 FilePipe/FilesDesk「Preview + Undo」）：通知里带 "撤销归档" → 删除 archives 副本 + 回写索引（源文件在下载目录天然可恢复）

### 6.3 支持的文件类型（新常量，勿复用 textbook.rs IMAGE_EXT）

| 类 | 扩展名 |
|---|---|
| 教材 PDF | pdf |
| 课堂图片 | jpg jpeg png gif webp bmp |
| **音频**（新） | mp3 m4a wav ogg flac aac |
| **视频**（新） | mp4 mkv avi mov wmv webm flv |

`textbook.rs::IMAGE_EXT` 无音视频——新功能需独立常量 `ARCHIVE_EXT`（D11 专属，不改 textbook 扫描口径）。

## 7. 通知系统扩展（插件/内容/教材 + 合并）

### 7.1 类型扩展（不破坏现有 kind 语义）

```typescript
// types.ts —— Notification 增加独立业务通道字段（勿扩展 kind 严重度）
export interface Notification {
  id: string;
  kind: "success" | "info" | "warn";          // 保留：严重度（TopBar KIND_ICON 索引保持）
  /** 新增：业务通道（插件/内容/教材/归档） */
  channel?: "plugin" | "content" | "textbook" | "archive";
  title: string;
  body?: string;
  /** 新增：携带 payload（文件路径/归档结果）供 action 按钮使用 */
  meta?: { path?: string; subject?: string; count?: number; groupKey?: string };
  /** 新增：可执行动作（确认/撤销/去归类） */
  action?: "confirm-archive" | "undo-archive" | "go-classify";
  at: string;
  read: boolean;
}
```

**为什么独立 `channel` 而非扩展 `kind`**：`TopBar.tsx:37-38` 用 `KIND_ICON[n.kind]` 字面量索引（exhaustive），扩 `kind` 联合会编译失败；`kind` 是严重度（success/info/warn），`channel` 是业务线（插件/内容/教材）——职责分离。

### 7.2 下载任务分类（DownloadKind 扩 "textbook"？——不，保持二元 + channel 补全）

| 现状 | 目标映射 |
|---|---|
| `DownloadKind = "pkg" \| "tool"` | 插件 ≈ tool；内容 ≈ pkg；教材 ≈ **channel="textbook"**（新，DownloadKind 保持二元避免动历史） |
| 下载中心分区 categories 含「工具」→ tool 区 | 与 DownloadKind 双口径（探索发现的不一致） |
| **存量 bug**：`LaunchpadView.tsx:97` startDownload prop 缺 info 参数 → 工具下载标成 "pkg" | **实现前必修**（补 `{name, kind}` 参数），否则插件/内容判定建在脏数据上 |
| `taoli.settings.notifyLaunch` 死开关（只写不读） | 实现时补读取闭环（可复用为「自动整理」偏好入口） |

### 7.3 通知合并（group_key + count + 时间窗）

**数据模型变更**（`useNotifications.push` 内，仿 store.ts:431 历史按 id 去重先例）：

```
push(n, opts?: { groupKey?: string })
  if groupKey && 存在同 key 未过期条目:
    count++  / last_at = now / title 更新为 "3 个文件已归档" / items 追加 filename
  else:
    新建条目（count=1）
```

**group_key 设计**（参考 worldmonitor coalesceKey + LLD group_key + Outlook 时间窗聚合）：

| 通知类型 | group_key | 窗口 |
|---|---|---|
| 归档成功 | `archived:{subject}:{version}:{grade}{volume}` | 15 min（同批次合并） |
| 未匹配规则 | `unmatched:{extension}` | 24h（同类累积） |
| 下载完成（插件/内容） | 沿用现有 id 去重（短任务） | — |
| 下载失败（新增 warn 通道） | `error:{itemId}` | 1h |

**前端展示**（参考 Outlook batching + Windows Action Center）：
- `count > 1` → 标题 "3 个文件已归档：英语·人教版·四年级上册" + chevron 展开明细（items_json：文件名列表）
- 合并条目支持「全部已读」/「撤销全部」
- **反模式禁止**：按 title 精确匹配（含时间戳会退化成不合并）、合并过宽（全堆一起）、合并后丢 items 明细、merge 规则变更重算历史（只作用于新事件）

### 7.4 Toast 约束（关键）

**Tauri 2 `@tauri-apps/plugin-notification` 的 Actions API 是 Mobile Only**——Windows 上 toast **无操作按钮**。所以：
- 系统 toast 仅做「检测到新下载，点击查看确认卡片」**提示**（无按钮）
- 确认/归档/撤销交互**全部在应用内**（Notification 带 `action` 字段，点击通知 → 定位到确认卡片）
- 若未来要 toast 真按钮（"自动整理"/"忽略"）→ 需原生 WinRT AppNotification + COM activator（超出 MVP，记入决策记录）

> ⚠ 此为设计阶段必须确认的技术约束：**不做 toast 按钮**，交互收敛在应用内。

## 8. 打包与导出（随身工具包扩展）

### 8.1 现状落差（探索确认）

- 随身工具包导出**在前端**（`ToolboxPanel.tsx:168` exportPack → `toolbox-pack.json` **纯 JSON 索引**），**不含任何二进制**（工具 zip 本体/教材文件都不打包）
- Rust 侧**无 zip 写入能力**（只有自写 central directory 读取器 + flate2 解包）
- R03 §4.3 要求"zip 打包工具目录"与实际 JSON 实现有落差

### 8.2 本方案（两阶段）

**MVP（本轮）**：归档索引进包
```
toolbox-pack.json 增加 media_archive?: {
  entries: [{ rel: "英语/人教版/四年级上册/U01.mp4", size, subject, at }],
  exported_at
}
```
归档文件本体**不打包**——与既有 `downloaded_tools.path` 相对路径引用的落差保持一致。教师 U 盘拷贝时 `archives/` 目录随 exe 一起走，索引帮助换机后重新挂载/核对。**标注「随包走 = 拷贝 U 盘目录，非工具内打包」**。

**二期（需新依赖）**：若必须把音视频实体打进 zip → 新增 `zip` crate（写）。触发点：教师换机且不愿拷整个目录时。**记入决策记录，MVP 不做**（新增依赖需再过 MSRV 1.77.2 / Win7 验证）。

### 8.3 归档内容版权提示

打包/导出时 UI 固定显示「内含教材/课件资料，仅供个人教学和学习使用，请勿对外分发」——延续 D09 §1.1 红线。

|---|---|
| `archive_watch_dir(app, dir)` | 设置/更新监视目录（存 config.json `archive` 子对象，读改写保留未知字段）+ 重启轮询线程 |
| `archive_confirm(app, path, meta)` | 归档：拷贝 → staging→rename → 写索引（§6.2） |
| `archive_undo(app, entry_id)` | 撤销：删副本 + 回写索引 |
| `archive_rules(app)` | 读写本地自动整理规则（确认卡片的「下次自动」落这里） |
| `archive_list(app)` | 归档索引清单（前端浏览/打包用） |
| `archive_pack_index(app)` | 生成 `media_archive` 索引段（供前端 exportPack 嵌入） |

事件：`archive:new`（发现新文件）→ 前端弹卡片；`archive:done`（归档完成）→ 通知。

**注册**：`mod.rs` 声明 + `lib.rs` use 列表 + invoke_handler（照 `shell_config` 先例）；spawn 线程在 `setup()`（照 `credential::startup_check` 位置）。

## 12. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 轮询监视（std 线程）而非 notify crate | 零新增依赖（项目硬约束）+ 网络盘兼容 + 实现简单；轮询天然合并事件 |
| 2 | 归档 = 拷贝而非移动 | 下载目录是用户浏览器资产；保留原件可追溯，撤销天然可恢复 |
| 3 | Notification 加独立 `channel` 而非扩展 `kind` | kind=严重度（KIND_ICON 索引）、channel=业务线，职责分离防编译断裂 |
| 4 | 不做 toast 操作按钮 | Tauri 通知插件 Actions 是 Mobile Only；确认交互收敛应用内（应用内按钮） |
| 5 | MVP 只打包索引，不打包音视频实体 | Rust 无 zip 写入能力，新增依赖需再过 MSRV/Win7 验证；U 盘拷目录即可带走实体 |
| 6 | 自动识别预填不锁定 + 纠正持久化 | Google Photos/auto-fill 模式：自动是起点，用户可改，改完被学习 |
| 7 | 归档规则优先级：签名包默认 < 用户自定义 | 与 D10 配置链衔接：全局规则签名下发，本地覆盖 |
| 8 | 先修 LaunchpadView startDownload 脏数据 | 插件/内容分类建立前必须先干净（当前工具被标 pkg） |

## 13. 实施顺序（建议）

1. **P1 观测**：`archive.rs` 轮询 + `archive:new` 事件 + 下载目录定位（含 Win7）——纯 Rust，不依赖 UI
2. **P2 确认**：确认卡片 + 自动识别 + 级联 + 记忆偏好（`useArchiveRules`）
3. **P3 归档**：拷贝移动 + 索引 + 撤销
4. **P4 通知**：channel/meta/action 扩展 + groupKey 合并 + 下载分类三分（先修 LaunchpadView）
5. **P5 打包**：media_archive 索引进包 + 「仅个人使用」文案全覆盖
