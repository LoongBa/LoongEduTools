## 1. 项目背景与目标

### 1.1 背景

- 起点：龙爸易教系列 H5 小工具（首个「新英语四上点读1单元」）以 **zip + index.html** 分发。
- 痛点（旧壳方案背景）：
  1. 老师需在**教室电脑**上播放，zip 解压 + 双击 index.html 对非技术用户不友好；
  2. 资源（音频 base64 js / 图片 webp）全部**明文可解压**，任何人解压即得全部素材；
  3. 无身份验证，谁拿到 zip 谁就能用；无升级通道，修复/新增单元需重新分发 zip。
- 定位升级（2026-09-23）：从「RedTools 小工具的桌面壳」→「**教师课堂专用工具**」——U 盘拷贝即用、教材点读为主应用、合同规认证与内容包体系、数据零采集。

### 1.2 两条合规路径的产品线分工

| 产品线 | 内容 | 分发对象 | 版权依据 |
|---|---|---|---|
| **点读陪练**（对外） | 原创句子/图/音，只同步教材知识点骨架 | 家长/家庭 | 全原创，合规分发 |
| **教师客户端点读**（对内） | **人教教材素材**（原版点读） | 仅已认证教师课堂 | 课堂教学 = 合理使用范围 |

- 教师客户端吃「英语点读」v1.3.3 现成资产（已交付、已 QA、11 个 zip），零新增内容生产；
- 点读陪练继续走原创线，两条线互不污染。

### 1.3 产品定位

| 项 | 说明 |
|---|---|
| 产品名 | 桃李助手 · 龙爸易教·教师端 |
| 目标用户 | 小学英语老师（教室电脑 / 智慧屏，Win7 + Win10/11） |
| 核心价值 | 弥补教室电脑/电子白板不足：素材即取即用、课堂互动工具、备课便利；授权可控；版本可升级 |
| 形态 | Tauri 绿色 exe（免安装、U 盘拷贝部署，WebView2 承载 H5） |

## 2. 合规设计（核心）

### 2.1 版权依据

- 人教教材电子版授权条款：「**仅供个人教学和学习使用**」；
- 课堂教学（老师教室使用）属合理使用范围；**商用/对外分发需正式授权**；
- 素材使用合法性的前提 = 使用者是「教学者」→ 产品必须以技术手段控制分发对象。

### 2.2 微信实名认证（合规护栏）

工具 U 盘拷走即用、可无限复制，必须锁定使用者身份：

| 手段 | 作用 |
|---|---|
| **微信实名注册**（免费） | 可追溯性：每个激活/下载/使用有真实归属，违规可追责 |
| **注册声明**（任教年级/科目 **必填** + 同意《仅供个人教学使用》条款） | 使用者自我声明承担违规责任；产品方有声明存档 |
| **激活码 + 微信绑定** | 一码一微信，机器绑定（建议 2-3 台/码：教室智慧屏+教室电脑+备课电脑） |

> 认证粒度判断：**免教师资格证/学校邮箱强验证**。免费注册不是放弃认证，而是「低摩擦进门 + 高可追溯约束」——门槛放行，闸门常闭（违规可封禁激活码/吊销资格）。

### 2.3 课堂口令（周期性授权）

**授权模型：一次激活 → 周期性认证（有期限口令）。** 防止工具被拷走后被第三方长期乱用：

```
【获取】老师微信登录在线版 → 申请课堂口令（一学期）→ 服务端签发
        → 口令包 = {口令hash, 到期日, 服务端签名, 机器范围}
        → 下载/同步到教师客户端（或 U 盘导入）
【使用】口令有效期内：全部内容/应用/名单包离线可用，零网络
【到期前】本地提示「口令将于 X 天到期，请在线续期」（提前 15 天）
【到期后】按过期策略执行（默认 B，见下）
【续期】在线版一键续期（免费）→ 新口令包覆盖旧包 → 本地内容不动
```

| 决策点 | 方案 |
|---|---|
| 有效期 | **一学期**（与教学节奏对齐；教师身份有效性随学期确认；教材授权条款"持续用于教学"的证明周期） |
| 到期行为 | **默认 B：只读旧、锁新**——已下载内容可继续用，不能下载新内容/配置新名单；新版内容包要求口令版本 ≥ X，乱用者旧包自然淘汰。（备选 A 全锁 / C 宽限期 30 天，评审可调） |
| 防伪造 | 口令包服务端私钥签名 + 到期日 + 机器范围 |
| 简单保护边界 | 本地时间校验可被改时钟绕过——**接受**（对齐"不强防专业破解"既有判断）；服务端每次签发新口令包时顺带校准时间 |

**认证三方式 + 凭证缓存（与口令分层）：**

- 登录支持 **微信扫码 / 短信验证码 / 账号密码** 三方式，服务端签发凭证；
- 凭证本地加密缓存，默认 **7 天** 有效期 → 有效期内离线运行全部功能，到期需联网重新认证；
- **认证层与口令层独立**：凭证证明"使用者是活跃教师"（7 天）；口令证明"授权周期内可解锁内容"（一学期）。内容包运行时鉴权 = 凭证有效 × 口令级别达标 × 范围匹配。

### 2.4 数据原则：零采集

- 教师客户端软件本体**不采集儿童数据**：不记录学习行为、不上传进度、无埋点；
- 个性化数据（学生名单等）默认**云端不留**（传输中加密、落本地）；
- **教室连网时数据上报仅限授权/使用状态白名单**：教师账号标识（哈希）、客户端版本、已安装内容包清单、口令状态、内容包聚合使用统计——**不上报学生名单/学习行为/练习成绩**，儿童数据零采集红线不变（技术细则见 RUST 外壳开发方案 §5.3）；
- 在线报表 → 老师登录**在线版**查看，与本软件无关；
- 与点读陪练「儿童数据最小化、不做班级排名」红线天然兼容——教师客户端从根上不碰儿童数据。

## 3. 部署形态

### 3.1 方案 A（首选）：U 盘拷贝到教室电脑/智慧屏

- 学校采购的智慧屏基本为 **Win7/10 + Android 双系统，默认 Windows** → **单一绿色 exe 通吃**，无需 APK、无需 H5 浏览器适配；
- 部署：U 盘拷贝 → 插教室电脑/智慧屏 → 双击即开；
- 免安装（绿色 exe）绕开教室电脑「受管控不能装软件」；离线运行绕开「网络白名单」；
- **U 盘同时是更新介质**：内容包 zip 放 U 盘 → 软件启动检测 → 校验 hash → 自动并入本地内容库。

### 3.2 方案 B（备选）：手机投屏

- 不推荐：教室大屏投屏协议碎片化（AirPlay/Miracast/DLNA/Cast+ 各品牌不互通）、手机系统分叉、依赖同网与稳定性——40 分钟课堂经不起"投不上/掉线"折腾；
- 仅作为老师个人手机演示的补充场景，不做主路径。

## 4. 功能设计

### 4.1 基础功能需求（继承旧壳 F1-F7）

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 双击运行即打开点读工具 | P0 | 无需安装、无需命令行、无需浏览器操作 |
| F2 | 支持全屏/窗口播放 | P1 | 教室投影场景常用 |
| F3 | 资源嵌入 + 加密，不可解压获取 | P0 | 普通用户无法从安装目录拿到原始素材 |
| F4 | 在线验证身份（微信/短信/密码 → 凭证缓存） | P1 | 详见 §2.2/§2.3；离线兜底见 §2.3 凭证缓存 |
| F5 | 自动升级（检测新版本→下载→替换） | P1 | 修复与新单元发布免人工分发 |
| F6 | 多工具支持（同一壳加载不同内容包） | P1 | 一套壳服务全部教师工具 |
| F7 | 教室无网可用（离线运行） | P0 | 凭证 7 天缓存 + 口令一学期兜底，断网可用 |

### 4.2 壳层（多工具平台，Tauri 绿色 exe）

| 能力 | 说明 |
|---|---|
| 双击即开 + 全屏（教室投影） | 继承 F1/F2 |
| 资源加密（zip 加密 + 口令） | 继承 F3，防随手拷贝传播 |
| 微信认证 + 课堂口令 | §2.2/§2.3 |
| 多工具/内容包管理 | 预装 + 可下载应用与内容包 |
| 更新 | 云端下载（登录态）+ U 盘导入，统一落地为「压缩+加密+口令」本地包 |

**双版本体系（核心架构）**：客户端（壳 X.Y.Z，`tauri-plugin-updater` 低频更新）与内容包（manifest 独立版本 + content_hash，下载/U 盘导入）为**两个版本体系**，独立演进、互不强绑：壳更新不迁移内容包；内容包声明最低壳版本（`min_shell_version`）达标才加载。技术方案详见《D01-教育工具-教师版RUST外壳开发方案.md》。

### 4.3 主应用：教材点读（第一个应用，预装）

- 内容源：原 RedTools「英语点读」v1.3.3（11 个 zip，已交付已 QA）；
- 功能：**播放、点读、听写、歌曲歌词与伴唱等**；
- 第一版范围待定（见 §10 待确认 ①）：(a) 旧点读原样（播放/点读）先出，听写/伴唱排后续；(b) 第一版移植听写/点唱台能力（从点读陪练）。

### 4.4 可下载应用/内容包

- 从 RedTools 40+ 工具中选课堂适用的（数学口算/24点/成语接龙等）逐步开放为**可下载应用**（可执行包）；
- 各册单元内容包（点读陪练原创内容/后续册次）作为**可下载数据包**；
- 统一保护：**压缩 + 加密/口令简单保护**（挡住 99% 随手拷贝，不做强 DRM）；
- 下载渠道：云端（登录态）+ U 盘（离线兜底）。

### 4.5 特定应用：上课抽卡（在线配置 → 加密下载 → 本地用）

```
【在线版】（老师手机/电脑，有网）
  导入/录入学生名单 → 生成名单包（AES 加密 + 课堂口令）→ 下载
        │ 传输中加密
【教师客户端】（教室电脑，离线）
  本地解密（口令）→ 名单存本地 → 上课抽卡（随机点名/分组）→ 全程离线
```

- **云端不留**：名单在云端只流经不留存（下载后即删），默认数据最小化；
- **本地解密即用**：运行期零网络，教室断网照常点名；
- 课堂口令由老师在线配置时设定，口令有期限（与 §2.3 同一体系）。

> **模式可推广**：「在线配置 → 加密下载 → 本地离线用」是教师客户端所有个性化数据的标准模板：
> 上课抽卡（名单）/ 老师自建词表练习（选模板+词表）/ 分组（名单分组）——统一走同一条通道。

| 声音克隆教师 | ❌ **不做** | 预生成 TTS 已覆盖；增量价值≈0 | 不做 |
| 实时翻译/释义 | ❌ **不做** | 教师懂英语；学生喊词上云=儿童数据 | 不做 |
| 情感/注意力识别 | ❌ **不做** | 儿童人脸=伦理+数据双红线 | 不做 |

| **R17** | F4 | **课前展示素材包**（Daily Report 话题卡 + 示范音频，生产期 TTS） | P1 | 内容包 |
| **R18** | F5 | **朗读打卡单**（生成朗读清单打印/大屏展示，教师课堂用，不采集） | P2 | 内容包 |

> **F2 集体备课 / F3 学情分析会 归在线版（教师客户端不做）**：前者需云端协作（与离线/零采集冲突）；后者需儿童学习数据（教师客户端零采集红线）——均由在线版/家庭端数据回流承载，不进入课堂壳。

### 5.4 三个高杠杆新功能

1. **代课应急教案包体系**（R2）｜Effort: Short——痛点极真实（代课是每个老师遇过的混乱），技术零风险（就是内容包），首发即验证内容包分发链路双重价值；
2. **在线版 AI 备课助手 → 内容包**（R4/R5）｜Effort: Medium——备课期云端 LLM 生成分层练习/听写卷，三关全过（处理教材非儿童/云端非 Win7/教师时间净省）。**这是教师客户端"AI 赋能"的唯一干净出口：AI 不进壳，AI 喂壳**；
3. **壳内课堂工具集**（R1/R6/R12）｜Effort: Quick–Short——多班进度看板+一键开课+抽卡分组，非 AI、高频、低投入，补齐文档缺失的"课堂日常工具"层（RedTools 计时器/转盘/骰子移植即用）。

## 6. 技术方案

### 6.1 打包技术选型（2026-09 评估，沿用）

| 方案 | 打包体积 | 目标电脑依赖 | 前置条件 | 结论 |
|---|---|---|---|---|
| **Tauri**（Rust） | **~3-10 MB** | **零依赖**（静态编译 + 系统 WebView2） | 需装 Rust 工具链（~500 MB） | **首选**（P0/P1 全满足） |
| .NET 单文件 self-contained | 60-150 MB | 零依赖 | 已有 dotnet 10 + C# 经验 | 备选（体积大） |
| .NET framework-dependent | ~5 MB | 需装 .NET 运行时 | 同左 | 教室电脑可能没有运行时 |
| Electron | 100 MB+ | 零依赖 | — | 体积劝退 |

**结论（2026-09-23 定稿）**：**Tauri 2.x**。Win7 为硬目标（.NET 10 不支持 Win7——.NET 8 起最低 Win10 1607），Tauri 是唯一覆盖 Win7+Win11 的选项；不捆绑 Chromium（系统 WebView2）、官方升级插件、资源可编译进二进制。

### 6.2 技术选型明细

| 层 | 选型 | 依据 |
|---|---|---|
| 壳 | **Tauri 2.x 定稿**（Rust，绿色 exe） | Win7+Win11 全覆盖；~3-10MB、零运行时依赖、官方 updater |
| 前端 | **教材点读 HTML 直接复用**（零重写，Chrome 61 兼容）+ 壳 UI 用 **React 19 + Vite + TanStack Router**（与点读陪练 WebH5 实际技术栈一致） | 旧点读单 HTML + base64 内联 = Tauri 静态资源即插即用；React 团队已有在线版先例 |
| 认证 API | Cloudflare Workers + D1 | 微信 openid 绑定、激活码表、口令签发；成本≈0、已有 Cloudflare 技能 |
| 内容托管 | Cloudflare R2 + CDN | 应用/内容包/口令包分发 |
| 更新 | `tauri-plugin-updater`（应用）+ 内容包 hash 校验（数据） | 应用走官方升级；内容包 U 盘/云端双通道 |
| 加密 | 包体 AES + 口令；口令包服务端签名 | 简单保护定位 |
| 数据 | 名单包本地存储（云端不留） | 数据最小化 |

### 6.3 Win7 兼容基线（硬约束）

- Win7 上 WebView2 **停更于 2023-01**（Chromium ~108 版，已安装继续可用）；
- 教师客户端 H5 内容以 **Chromium 108 为兼容基线**：不引入超出该内核的新特性；
- 现状满足：教材点读（Chrome 61 兼容）零压力；点读陪练原创内容（要求 Chrome 90+）108 也满足；
- Win7 上 WebView2 需手动安装（非预装）→ 部署时随包提供引导安装说明。

### 6.4 Rust 命令层清单（壳层全部 Rust 代码，<500 行）

| 命令 | 能力 | 说明 |
|---|---|---|
| 内容包解密/导入 | 解密加密包 → 并入本地内容库 | U 盘检测 + 云端下载共用 |
| 名单包本地存储 | AES 名单包读写 | 抽卡数据落本地 |
| 窗口控制 | 全屏/退出/快捷键 | 教室投影场景 |
| 口令校验 | 本地校验签名 + 到期日 | 服务端签发时顺带校准时间 |

> 前端不能直接读本地文件（WebView2 浏览器安全限制），内容包/名单包的一切文件操作必须走 Rust 命令层或 fs 插件——这是壳层最核心的 Rust 代码；旧点读 base64 内联设计规避"运行时读文件"，加载零阻力。

### 6.5 总体架构

```
┌─ 教师客户端（Tauri 绿色 exe，U 盘拷贝部署）─────────────┐
│  启动 → 微信/口令校验（缓存授权，离线可用）           │
│  ├─ 预装：教材点读（第一个主应用）                    │
│  ├─ 可下载：应用/内容包（zip 加密+口令）              │
│  ├─ 特定应用：上课抽卡（名单包本地解密）              │
│  └─ 更新：云端拉取（登录态） + U 盘导入（离线）       │
└─────────────────────────────────────────────────────┘
        │ HTTPS（仅注册/签发/下载时）
        ▼
  Cloudflare Workers（认证/激活码/口令签发）+ D1 + R2
```

### 6.6 数据流

1. **开发侧**：`RedTools/build.py` 产出 dist（数据+音频+图片）→ Tauri 构建脚本嵌入为资源。
2. **启动**：壳检查本地凭证缓存 → 未过期直接进工具；过期/无凭证 → 弹登录页 → 调 Workers API 验证。
3. **升级**：壳带当前版本号请求服务器 → 有新版则提示下载 → 下载签名安装包 → 校验签名 → 替换重启（内容包走 manifest 独立更新）。
4. **多工具**：壳内置内容包清单（id/名称/数据 key），按凭证+口令授权展示可用工具列表。

## 8. 关键流程

| 流程 | 步骤 |
|---|---|
| **注册** | 微信扫码 → 填任教年级/科目（必填）→ 同意《仅供个人教学使用》→ 生成教师账号（openid）→ 绑定激活码 |
| **激活** | 首启扫码/已绑定机器自动通过 → 本地标记激活 → 此后离线 |
| **口令** | 在线申请（一学期）→ 签名口令包下载/导入 → 本地校验到期日 |
| **下载** | 登录态 → 云端拉应用/内容包 → 落本地加密包（或 U 盘导入） |
| **抽卡** | 在线版配置名单 → 加密名单包下载 → 本地口令解密 → 离线抽卡 |
| **违规处置** | 发现传播 → 后台吊销该微信激活码 → 名下机器下次联网失效 |
