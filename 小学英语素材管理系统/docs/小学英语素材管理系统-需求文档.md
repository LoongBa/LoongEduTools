# 小学英语素材管理系统 · 需求文档（v1.0 草案）

> 版本：v1.0 ｜ 日期：2026-09-21 ｜ 状态：**草案（待评审）**
> 定位：**自用**的小学英语（人教版 PEP）素材管理系统——服务本仓库三个消费方，
> 不做商业分发，不追求通用化。先专后通：先做透 PEP 小学英语这一个域，其它视频生产
> 模式启动时再逐个评估是否提炼通用层（每种模式有自己的流程/素材来源/特点）。
> 文档位置：`小学英语素材管理系统/docs/`（本系统独立根目录，与 `点读陪练/`、`PEP词库/` 并列）。

## 1. 背景与问题

### 1.1 现状盘点（2026-09-21 实测）

素材根目录 `F:\_教材素材\人教版（PEP）（主编：吴欣）`（11 册，六下未出版）：

| 素材 | 数量 | 说明 |
|------|------|------|

| 单句音频 `P{页}_{序号}_{文字}.mp3` | **11289 条** | 含单句/页音频/单元音频（递归统计） |
| 字幕 `*.srt / *_cn.srt / *_en_cn.txt` | **369 个** | 英/中/双语 |
| 点读数据 `PEP词库/data/diandu/*.json` | 11 册 | book.json（页面+热区+音频直链，**不入 git，book_data.zip 分发**） |

| 重绘 QA 报告 `qa_reports/` | 10 册 HTML | **内嵌结构化 `const DATA={pages:[{page,has_redr,ssim}]}`**（正则可提取）；`qa_reviews.json` 当前**为空 `{}`** |

| **合计（素材根）** | **13,548 文件 / 7.63 GB** | |

> Oracle 评审盘点结论（2026-09-22）：重绘已覆盖多册（非"四上示例"）；`qa_reviews.json` 为空（QA 结论性状态待定策略）；TTS 重读仅四上产出。

### 1.2 现状问题（痛点）

| # | 问题 | 现状 | 后果 |
|---|------|------|------|
| P1 | **素材清单靠人工维护** | `素材清单.md` 是一张手工表格 | 统计数字易失真，新增/删除素材后不同步 |
| P2 | **素材状态散落多处** | 音频/图片在素材库、重绘状态在 `tasks/`+`qa_reports/`、TTS 状态在 `_重读音频素材/`、制作状态在 `素材清单.md` | "四上哪些页没重绘？哪单元缺 TTS？QA 过没过？"要翻 4+ 处 |
| P3 | **完整性无法自动校验** | book.json 页码/热区 vs 实际素材 vs 重绘产物 无对账 | 构建/制作时才发现缺素材，返工 |
| P4 | **三个消费方素材需求各自为政** | 单元视频 / 点读陪练小程序 / 点读陪练教辅 各按需取用 | 无统一"某单元对某消费方是否就绪"的视图 |
| P5 | **词库/点读数据/教材素材归属分散** | `PEP词库/` 与 `F:\_教材素材\` 两处 | 缺少一张"册→单元→素材→产物"的全局索引 |
| P6 | **agent/脚本无结构化状态可查** | 批量生图/TTS/重绘工具各自为政 | 无法用一句查询回答"下一批该做什么" |

### 1.3 一句话目标

**建立一个以「册→单元」为纲、以「素材清单 JSON」为单源真值（SSOT）的自用素材管理系统**：
自动盘点素材、对账完整性、追踪生产状态（重绘/TTS/QA/制作）、输出三个消费方（单元视频 / 点读陪练小程序 / 点读陪练教辅）的就绪度视图——让"下一批该做什么"一次查询可得。

## 2. 范围与边界

### 2.1 范围内（本期）

- **域**：人教版（PEP）小学英语 1–6 年级（当前 11 册，六下出版后自动扩展）
- **消费方**：
  1. **单元视频制作**（CapCutTool + 重绘 + TTS → 视频草稿）
  2. **点读陪练小程序**（content.json + audio + images → 离线/在线双模式）
  3. **点读陪练教辅**（打印版五件套，复用内容包上游）
- **能力**：素材盘点、完整性对账、生产状态追踪、消费方就绪度视图、缺失清单输出、agent 可查询

### 2.2 范围外（明确不做）

| 项 | 说明 |
|----|------|
| **通用 MAM** | 不做语义搜索/人脸/说话人分离/镜头检测/视觉相似度（open-post-production 那套）——我们没有长视频素材，**重富化层全部用不上** |
| **跨学科抽象** | 不做数学/语文等其它学科的通用素材模型；先专后通，本期只做 PEP 英语 |
| **NLE 往返** | 不做 Premiere/Resolve/FCP 互操作（我们无长视频剪辑环节） |
| **素材去重/归档** | 不管理素材的移动/清理/生命周期（素材只增不减，路径约定不变） |
| **版权素材入库** | 教材原图/原音/原句仅作**索引**（不入系统内容层），消费方遵守版权红线（点读陪练原创自产） |
| **在线服务化** | 不做 Web 服务/多用户/权限；纯本地脚本 + JSON + agent 查询 |

### 2.3 先专后通原则

- 本期数据结构**以 PEP 英语的「册→单元→页→track」为纲**，不抽象到通用"任意教材"
- 当第二个视频生产模式（如数学口算视频/科普视频）启动时，**逐个对比其流程/素材来源/特点**，
  再决定哪些可提炼为共享层（如"文件清单校验""状态机"），避免为想象的需求设计
- 系统内部预留"模式（mode）"维度（如 `video/peidian/print`），但本期只有 PEP 英语一个域

## 4. 功能需求

### FR1 素材盘点（自动扫描）

- FR1.1 扫描素材根目录，按「册→单元→页→track」生成结构化清单 JSON（SSOT）
- FR1.2 支持增量盘点（文件 mtime/hash 变化才更新条目）
- FR1.3 输出每册统计：页面图/单句音频/页音频/单元音频/字幕/封面/PDF 数量与大小
- FR1.4 六下未出版（目录不存在）时清单中明确标记"未出版"，不报错

### FR2 完整性对账

- FR2.1 以 book.json（`PEP词库/data/diandu/*.json`）为基准，校验每页素材：
  页面图存在 / 每 track 单句音频存在 / 页音频存在 / 字幕存在
- FR2.2 输出差异清单：缺图页、缺音 track、无音页（数据源特性，如六上 P9/P21 等 7 页）、页码不对齐
- FR2.3 对账结果纳入状态字段（`integrity: ok | missing_xxx | no_audio_page`）

### FR3 生产状态追踪

- FR3.1 追踪四类生产状态（每单元/每页）：
  | 状态 | 来源 | 值域 |
  |------|------|------|
  | 重绘 | `重绘工具/tasks/*/output/` + `qa_reports/` | 未开始 / 进行中 / QA待检 / 通过 / 返工 |
  | TTS重读 | `_重读音频素材/单句音频/` | 未生成 / 部分 / 完整 |
  | 制作（视频草稿） | `素材清单.md` 制作状态 + CapCutTool 产物 | 未制作 / 已生成 / 手调保留 |
  | 内容包（点读陪练） | `点读陪练/` content 相关产物 | 未生产 / 草稿 / 已审校 / 已发布 |
- FR3.2 状态自动推导为主，人工覆盖为辅（状态表允许人工标注原因，如"手调保留"）

### FR4 消费方就绪度视图

- FR4.1 对每个单元输出三视图（一个 JSON 查询即得）：
  - **视频就绪**：页面图+重绘通过+音频齐全（点读视频）
  - **小程序就绪**：内容包已审校 + 音频/图片已产（点读陪练）
  - **教辅就绪**：内容包已审校 + 打印版字段已填（打印五件套）
- FR4.2 输出"单元×消费方"矩阵（就绪/缺什么/阻塞原因）

### FR5 缺失清单与下一步建议

- FR5.1 输出「每册待办」：未重绘页列表 / 缺 TTS 单元 / QA 待检 / 内容包未产单元
- FR5.2 按消费方优先级排序（如"四上视频全就绪，下一步补五上重绘"）

### FR6 Agent/脚本可查询

- FR6.1 清单 JSON 以稳定 schema 存放，agent（批量生图/TTS/重绘）通过读文件或 MCP 查询
- FR6.2 提供 CLI：`list/status/missing/report` 四类查询（输出 JSON 或 markdown）

### FR7 与既有系统的衔接（不重复造轮子）

- FR7.1 读取 `PEP词库/data/vocab/pep_vocab.json`（词库 SSOT）
- FR7.2 读取 `PEP词库/data/diandu/*.json`（点读数据 SSOT，对账基准）
- FR7.3 读取 `RedTools/重绘工具/qa_reviews.json` 与 `qa_reports/`（重绘状态）
- FR7.4 视频模板信息以 `LoongMediaTools/CapCutTool/` 为准（只引用，不复制）
- FR7.5 点读陪练内容状态读取 `点读陪练/`（骨架/内容包/构建产物）

## 5. 非功能需求

| # | 项 | 要求 |
|---|----|------|
| N1 | **轻量** | 纯 Python 3.9+（stdlib + 可选 PIL/json5），不引入重型依赖；单脚本可跑 |
| N2 | **可重建** | 清单 JSON 全部由脚本生成（源真相=文件系统+book.json），删除 JSON 可一键重建 |
| N3 | **快** | 全量盘点 ≤ 30 秒（11 册 / 1.3 万文件）；增量盘点 ≤ 5 秒 |
| N4 | **稳定 schema** | 清单 JSON 带 `schema_version`，变更走版本迁移，不破坏消费方 |
| N5 | **不碰素材** | 只读素材库与产物目录，绝不移动/重命名/修改素材文件 |
| N6 | **UTF-8/中文友好** | 全中文路径与内容，Windows 兼容（路径带空格/中文） |
| N7 | **幂等** | 重复运行结果一致（同一输入 → 同一清单） |

## 6. 验收标准

1. `python inventory.py scan` 输出 11 册清单 JSON，与实测统计（1685 图 / 11289 音频 / 369 字幕）一致
2. `python inventory.py check --grade 四年级 --term 上册` 能指出"四上 86 页全对账"或列出具体缺项
3. 对"四上 Unit 1"能回答：视频就绪？小程序就绪？教辅就绪？缺什么？（对照现状推演）
4. 删除清单 JSON 后重跑 `scan` 5 分钟内还原
5. 三个消费方任一 agent 能通过 CLI 读到"下一批该做什么"的 JSON 结果
6. 运行期间素材库文件 0 修改（`git status` / 素材目录 mtime 无变化）
