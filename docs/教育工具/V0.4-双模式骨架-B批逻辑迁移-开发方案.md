## 0. 接口事实核对（v0.4.1 修订核心：LX_SHARED 真实接口语义）

> 以下为本方案迁移模板的唯一事实依据（oracle 一审 R1-R6 后整理），实施时以 `_shared/js/src/*.js` 源码为准。

**storage 模块接口**（`_shared/js/src/storage.js`）：
- `LX_SHARED.storage.configure({ toolName })`：注入工具拼音名（如 `'math'`），**必须先于任何 get/set 调用**（否则前缀退化为 `redtools.app.v1`，localStorage 键名漂移，已发布数据读不到）；
- `LX_SHARED.storage.get(key)` / `set(key, val)`：`key` 是**版本后缀**（如 `'v1'`），非完整 STORE_KEY；内部拼 `'redtools.' + toolName + '.' + (key || 'v1')`；
- `get` 无默认值参数，**读空返回 `null`** → 各工具 loadStore 必须自带 DEFAULT_STORE 兜底；
- 语义：`LX_SHARED.storage.mode === 'online'` 时转 getCloud/setCloud（当前在线桩与 localStorage 同构，非真在线）。

**progress 模块接口**（`_shared/js/src/progress.js`）：
- 对外暴露 **`LX_SHARED.progress.streak(dates)`**（非 `.calcStreak`）；签名 `calcStreak(dates): number`（dates 数组）；
- 华容道为**无参变体** `calcStreak()`（内部读 `store.checkin.dates`），迁移需单独处理。

## 2. 目标与原则

- **目标**：38 款 static 工具 main.js 的存储/打卡/进度逻辑迁移到 `LX_SHARED.storage/progress`；为需内容切分的工具建 content.js（free_units 生效）；清除 P3/P4/P5 遗留。
- **原则**（继承 V0.2 改造红线）：
  1. **不改动核心玩法逻辑与判定规则**——只做「内容加载、存储、认证」三层适配；
  2. **最小化侵入**：迁移 = 将 `loadStore/saveStore/calcStreak` 函数**体**替换为对 `LX_SHARED` 的转发，调用点不动（saveStore/calcStreak 保持原签名形态，见 §3.1 双型模板）；
  3. **数据零迁移**：迁移前必须 `LX_SHARED.storage.configure({ toolName })` 注入工具拼音，使 localStorage 键名保持 `redtools.<tool>.v1` 不变；
  4. **默认值不丢**：`loadStore` 用 `LX_SHARED.storage.get('v1') || DEFAULT_STORE`，DEFAULT_STORE 从原 loadStore 函数体原样搬移（不做"优化"）；
  5. Chrome 61 兼容（ES2017，无 `?.`/`??`/class fields），无模块语法。

## 3. 变更设计

### 3.1 P1：38 款 main.js 存储/打卡迁移（主体工作，v0.4.1 重写）

**迁移前置（每款 main.js 顶部，`var store = loadStore()` 之前）**：
```js
LX_SHARED.storage.configure({ toolName: 'math' });   // 拼音从 STORE_KEY 提取：redtools.math.v1 → 'math'
```

**A 型——标准三件套款（35 款含 loadStore/saveStore/calcStreak，saveStore 无参/calcStreak 有参为主）**：
```js
var DEFAULT_STORE = { /* 原 loadStore 返回的默认对象原样搬移，照抄不优化 */ };

// 原签名 loadStore() 无参 → 保持无参
function loadStore() {
  var s = LX_SHARED.storage.get('v1');
  return s || DEFAULT_STORE;
}
// 原签名 saveStore() 无参（直接读闭包 store 变量）→ 保持无参
function saveStore() {
  LX_SHARED.storage.set('v1', window.store || store);
}
// 原签名 calcStreak(dates) → 保持有参（35 款标准型）
function calcStreak(dates) {
  return LX_SHARED.progress.streak(dates);
}
```
> 说明：saveStore 无参款占绝大多数（38/39），闭包内 `store` 变量名各工具一致（抽查确认）；若个别工具 store 变量不在闭包可达范围（如挂 `window.` 或模块命名空间），按该工具现状直接引用同名变量，**不改调用点**。
> 例外 1：**蜡笔物理** `saveStore(s)` 有参（唯一），模板为 `function saveStore(s) { LX_SHARED.storage.set('v1', s); }`。
> 例外 2：**华容道** `calcStreak()` 无参（L60-69，内部读 `store.checkin.dates`），见下方「华容道特例」。

**A 型变体——七巧板（函数名 loadRec/saveRec，非 loadStore/saveStore）**：
```js
// 七巧板：LS_KEY='redtools.tangram.v1' → configure toolName='tangram'；DEFAULT 从 loadRec 原实现搬移
function loadRec() { var r = LX_SHARED.storage.get('v1'); return r || DEFAULT_REC; }
function saveRec(rec) { LX_SHARED.storage.set('v1', rec); }   // 原签名 saveRec(rec) 有参
function calcStreak(dates) { return LX_SHARED.progress.streak(dates); }
```

**B 型——calcStreak-only 款（24点/打字背单词 2 款，无 loadStore/saveStore/loadRec/saveRec 定义，自有键抽象保留不动）**：
- **24点**：自定义 storage 抽象（三键 CHECKIN_KEY=`math24_checkin`/RECORDS_KEY=`math24_records`/PREF_KEY=`math24_prefs` + 三 normalize 函数）**保留不动**（schema-agnostic 透传无优势，强行迁移会三键互相覆盖）；仅迁移 calcStreak（有参）：`function calcStreak(dates) { return LX_SHARED.progress.streak(dates); }`；
- **打字背单词**：自有键抽象（CHECKIN_KEY=`dazi_checkin`/RECORDS_KEY=`dazi_records`）保留不动；仅迁移 calcStreak（有参）：同上。

**华容道特例（calcStreak 无参）**：
```js
// 原签名 calcStreak() 无参（内部读 store.checkin.dates）
function calcStreak() {
  return LX_SHARED.progress.streak(store.checkin.dates);
}
```

**逐工具验收**：
- A 型款（35）+ A 型变体（七巧板）：`grep -cE "function loadStore|function saveStore|function loadRec|function saveRec|function calcStreak" <main.js>` == 0（迁移后无自有实现，只有转发）；
- B 型款（2）：`grep -c "function calcStreak" <main.js>` == 0；
- 全款（38）：`grep -c "LX_SHARED.storage.configure" <main.js>` >= 1（捕获 configure 缺失）；且 configure 行号 < `var store = loadStore()` 行号（无键名漂移）；
- **键名契约（运行时）**：Playwright 打开每款后读 localStorage 键名，断言不含 `redtools.app.`（configure 注入成功、无退化前缀），且键名与 V0.3 发布版一致（`redtools.<tool>.v1`）。

### 3.2 P2：content.js 结构化（free_units 生效）

现状：38 款无 content.js，`write_static_data_js` content=[]（确认路径 `cfg.src_dir / "content.js"` = `src/content.js`；`build_framework.py` L547 正则只认 `window.CONTENT_DATA = [...]` JSON 数组字面量，**不执行 JS 表达式**）。
方案：仅对 **已登记 free_units 且内容可数组化** 的工具建 `src/content.js`（JSON 数组字面量，offline 截前 free_units 条 / online 全量，`write_static_data_js` L550 已有实现）：
- **A 档（必做 3 款）**：
  - **数学口算（free_units=3）**：content.js 手写/脚本生成一次 **JSON 数组字面量**（24 条，Chrome Schema 兼容无对象展开）：
    ```js
    window.CONTENT_DATA = [
      { "id": "g1_10addsub", "name": "10以内加减法", "grade": 1 },
      { "id": "g1_20add", "name": "20以内加法", "grade": 1 },
      ...
    ];
    ```
    **顺序必须与 main.js POINTS 定义顺序一致**（POINTS 是对象，`Object.keys` 顺序 = 插入顺序 = 一年级在前）；main.js 数据流改为读 `APP_DATA.content`（替换内嵌 POINTS 常量或按需映射）。**默认切分语义：前 3 个一年级知识点**（g1_10addsub/g1_20add/g1_20sub），符合"低年级启蒙免费"；
  - **单词闪卡（free_units=200）**：content.js = 词库 JSON 数组（构建期读 PEP词库 `data/vocab/` 已解析 JSON 生成）；
  - **打字背单词（free_units=200）**：同上（词库管线复用）。
- **B 档（选做，评估后另立 V0.5）**：益智款数组化（七巧板图案/数独 grid/舒尔特档位等）+ 关卡制（推箱子 155 关/蜡笔物理 10 关/华容道 4 关提为 content.js）。

**风险**：content.js 化需保证 main.js 数据流从「内嵌常量」改为「读 APP_DATA.content」，涉及数据源重构，比 P1 侵入大 → 本轮只做 A 档 3 款，B 档另立迭代。
