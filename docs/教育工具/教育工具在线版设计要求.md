# 教育工具在线版设计要求（v0.2）

> 适用范围：LoongEduTools「教育工具」产品线全部工具（口算/专注力/闪卡/七巧板/数独/点读陪练等）
> 上位文档：《教育工具产品指导原则》（同目录）、《教育工具产品矩阵规划》（同目录）
> 关联：《教育工具-教师客户端需求分析与设计方案》（`教师客户端/docs/`，激活码/在线验证机制可复用）
> **文档目的（本轮）**：作为 **Agent 改造任务书**——把已编写上线的 26+ 款小红书工具改造为
> **离线/在线双模式**，并尽可能在**通用模块共用代码**，方便后续扩展与升级。
> 版本：v0.2（2026-09-21）｜ 状态：待评审

---

## 一、文档目的与改造目标

**一句话目的**：让 Agent 把 RedTools 下已交付的离线小工具，统一改造为「离线免费试用 + 在线完整使用」双模式，**核心逻辑一套代码，双模式共用；通用能力抽成公共模块，新工具直接复用**。

**本轮改造目标**：
1. **双模式支持**：每个工具产出 `离线包`（前 N 章/阶段，无认证）与 `在线包`（全量，认证解锁）；
2. **代码共用**：练习核心逻辑（出题/判定/交互）与 UI 双模式共用一套，不复制两份；
3. **通用模块化**：认证、存储、打卡、家长报告等横向能力抽为公共模块，一处维护、全工具生效；
4. **可扩展可升级**：新增工具/新单元只需接入通用模块；认证从口令平滑演进到微信 OAuth。

**设计红线**（沿用指导原则，不因在线化突破）：
- 工具仍为「有标准答案的练习」，不做游戏（无版号风险）；
- 孩子端无社交、无注册墙；数据最小化（只存完成状态/打卡天数）；
- 核心功能永久免费 → 「前 N 章/阶段」免费，完整版经授权解锁，付费只解锁内容范围。

## 二、现状与技术基线（改造起点）

**现有代码组织**（已实机核验）：

```
RedTools/
├── build_framework.py      # 构建框架：src → dist → zip（音频 base64、图片 webp、1024 图标）
├── build_all.py            # 批量构建入口（--tool / --units / --pages / --bump）
├── tools.py                # 工具注册表
├── series/<系列>/<工具>/
│   ├── src/
│   │   ├── index.html      # 单页壳（header/main/footer + data.js + assets/*.js）
│   │   └── assets/         # main.js（主逻辑）+ generators.js（出题器）+ style.css + icon
│   └── README.md / 设计文档.md
└── dist/                   # 构建产物 zip（小红书离线包）
```

**技术基线**（现状约束，改造必须兼容）：
- ES2017 经典脚本：**无 import/export、无 `type="module"`**，IIFE + `window.*` 全局注入；
- 数据经 `data.js` 注入 `window.APP_DATA`（含 meta）；出题器挂在 `window.KOU_GENERATORS` 等全局；
- 平台沙箱：**离线包不得外网、不得全局排行榜/云存档/多人/AI/登录**；音频 base64 内嵌 JS；
- 包体上限 10MB（小红书 H5 沙箱硬上限）。

> 改造红线：**不改动核心玩法逻辑与判定规则**；只做「内容加载、存储、认证」三层的模式适配。

## 三、双模式产品要求（业务需求）

### 3.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    教育工具（每个工具双模式）                    │
├──────────────────────────┬──────────────────────────────────┤
│  离线包（体验钩子）        │  在线包（留存沉淀）                  │
├──────────────────────────┼──────────────────────────────────┤
│ 内容：前 N 章/阶段        │ 内容：全部章节/全部难度档             │
│ 认证：无，打开即用        │ 认证：手机号+授权口令（前期）          │
│ 数据：仅本地存储          │       → 微信认证（企业认证后）         │
│ 形态：纯静态 H5/zip      │ 数据：云端，家庭码绑定               │
│ 合规：天然符合离线沙箱    │ 能力：完整练习+历史+家长报告          │
└──────────────────────────┴──────────────────────────────────┘
         ↑ 页脚引导「完整版在在线版练习」 ↑
```

### 3.2 离线包要求

1. **内容范围**：每个工具只内置**前 N 章/阶段**（示例：口算前 3 个难度档、点读陪练 Unit 1、闪卡前 200 词、数独入门档、七巧板前 4 图案）——N 值表见 §六；
2. **形态**：纯静态 HTML、纯前端、无后端、无账号、本地存储；
3. **合规**：不设排行榜/云存档/多人实时/内购/广告；
4. **引流**：页脚固定引导「完整版 · 在线练习」，跳转在线版入口（二维码/口令页）；
5. **不设墙**：离线包内不弹付费窗、不锁功能，边界只到「内容范围」。

### 3.3 在线包要求

1. **内容**：全量章节/难度档，与离线包共用同一套练习引擎与数据格式；
2. **能力**：练习 + 即时判定 + 打卡 + 历史记录 + 家长报告（家长端）；
3. **孩子端**：仍**无账号**，以**家庭码**进入（沿用指导原则 §3.2/§4.3）；
4. **家长端**：手机号账号承载授权管理与家长报告；
5. **数据**：云端存储，家庭码维度隔离，仅家庭内可见；数据最小化；
6. **部署**：H5 挂已备案个人网站 + 公众号基础菜单入口；不依赖微信 openid（个人订阅号阶段）。

### 3.4 认证体系（业务要求）

| 阶段 | 主体状态 | 认证方式 | 能力边界 |
|---|---|---|---|
| 前期 | 个人订阅号 + 个人网站（非经营性） | **手机号 + 产品授权口令**（自建） | 完整版解锁、数据留存；无微信登录 |
| 后期 | 个体工商户 → 备案转企业 → 服务号认证 | **微信认证**（OAuth）等 | 微信一键登录、微信支付、短信服务 |

**前期流程**：
- 首次开通：输入手机号 + 产品授权口令 → 校验（产品范围/有效期/绑定状态）→ 绑定手机号 → 设置密码（≥6 位）→ 进入完整版；
- 日常登录：手机号 + 密码；
- 密码找回：手机号 → 短信验证码 → 重置密码（依赖短信服务，见 §七待确认）。

**口令规则**：
- **来源**：在**公众号或其它途径购买获得**（公众号菜单/文章引导 → 小报童订阅、材料包、教师授权等渠道均可售卖；与教师客户端激活码同一套生成与校验逻辑）；
- **属性**：`产品范围`（解锁哪些工具）× `有效期`（如 1 年）× `绑定手机号`；
- **防共享**：一口令绑定手机号后可绑定有限设备数，换绑需验证；
- **换号不丢数据**：手机号为主键，数据挂手机号下，换设备登录即恢复。

### 3.5 账号模型（与既有约定衔接）

| 角色 | 账号 | 用途 |
|---|---|---|
| 孩子端 | 无账号，家庭码进入 | 练习、打卡（沿用指导原则，不新增注册墙） |
| 家长端 | 手机号（+后期微信） | 授权管理、密码找回、家长报告 |
| 家庭维度 | 家庭码（主键不变） | 数据隔离、换号不丢、组内统计防反推 |

> 本设计在指导原则「账号主键 = 家庭码/口令」之上**新增家长手机号账号层**，家庭码仍是孩子端与数据隔离的主键；手机号用于家长侧认证与授权，两者绑定。

## 四、技术改造要求（Agent 执行规范 · 核心）

### 4.1 总体原则：一套核心 + 双模式适配层

```
series/<工具>/src/
├── index.html              # 外壳（模式无关，仅按构建模式注入不同 data/adapters）
├── core/                   # 核心逻辑 —— 双模式共用，本轮基本不动
│   ├── main.js             # 主逻辑（练习流程/判定/反馈/打卡入口）
│   └── generators.js       # 出题器（随机出题 + 反推校验）
└── adapters/               # 适配层 —— 新模式新增，按构建模式注入
    ├── content.js          # 内容加载：离线=内置子集 / 在线=全量（或增量拉取）
    ├── storage.js          # 存储：离线=localStorage / 在线=云端（家庭码维度）
    └── auth.js             # 认证：离线=跳过 / 在线=调服务器验证接口（本期只预留契约）
```

**构建时注入，运行时无感**：同一份 `core/` 源码，`build_framework.py` 按 `--mode offline|online` 注入
对应 `data.js`（内容子集/全量）与 `adapters/`，产出两个包。**杜绝两份 main.js 分叉**。

> **在线验证实现策略（本轮确认）**：在线版验证走**服务器端已有接口**——客户端不做本地自校验，
> 只调用服务器验证接口换取授权状态；本期文档**只规划预留接口契约**（见 §4.6），
> `auth.js` 等公共模块的**代码实现后续更新**（待服务器接口就绪后接入），不阻塞 A 批试点。

### 4.2 通用模块（横向能力，抽到 `RedTools/_shared/js/`）

> 目标：一处实现、全部工具复用；新工具零重复开发。

| 模块 | 职责 | 复用范围 |
|---|---|---|
| `auth.js` | 认证客户端：调服务器验证接口（口令/登录/找回），微信 OAuth 预留；**本期只定契约，实现待服务器接口就绪后更新** | 全部在线包 |
| `storage.js` | 存储适配：localStorage / 云端（家庭码维度、防反推聚合） | 全部工具 |
| `progress.js` | 打卡、连胜天数、历史曲线（个人纵向激励） | 全部工具 |
| `feedback.js` | 即时正反馈（打勾/鼓励音效/进度条）、判定结果 UI | 全部工具 |
| `report.js` | 家长报告（家长端可见，数据最小化） | 在线包 |
| `guard.js` | 防沉迷/自控力通用能力（沿用 `docs/通用需求-防沉迷自控力.md`） | 全部工具 |
| `ui-kit.js` | 通用组件：按钮/进度条/徽章/卡片，统一风格 | 全部工具 |

**模块化约束**（兼容现有 ES2017 基线）：
- 仍**不引入** import/export / bundler；以「IIFE + 固定全局命名空间」如 `window.LX_SHARED.auth` 注入；
- 各模块零依赖或仅依赖 `LX_SHARED` 内部，可单独构建合并；
- 构建时把用到的 `_shared/js/*.js` 合并进产物（离线包只合入离线必需子集，控制包体）。

### 4.3 数据层抽象（内容与配置分离）

现状 `window.APP_DATA` 混合内容与 meta，改造为：

```js
window.APP_DATA = {
  meta: { tool, version, mode: 'offline'|'online', unit_count },
  content: [ /* 章节/难度档条目：离线=前 N 条；在线=全量 */ ]
};
```

- **离线包**：构建时按 `tools.py` 注册的 `free_units`（前 N 章）截取 content；
- **在线包**：content 全量打包，或仅首屏 + 后续增量拉取（初期先全量，简单可靠）；
- 各工具 `content` 结构随工具而异（词汇表/题档/单元卡），**仅需保证 `meta` 字段统一**，通用模块只读 meta。

### 4.4 构建管线扩展（build_framework.py）

| 能力 | 现状 | 改造后 |
|---|---|---|
| 构建模式 | 仅离线 zip | `--mode offline\|online`，双产物：`dist/<tool>/offline.zip` + `online/` |
| 内容切分 | 全量打包 | offline 按 `free_units` 截取；online 全量 |
| 适配层注入 | — | 按模式合并对应 `adapters/` 与 `_shared/js/` 子集 |
| 版本 | 单版本 | offline/online 可同版本号（共享 version），在线包另带 API 版本 |

`tools.py` 工具注册表增加字段：
```python
TOOLS = { "数学口算": { "series": "学科", "free_units": 3, "modes": ["offline", "online"], ... } }
```

### 4.6 在线验证接口契约（预留 · 服务器端提供）

> 原则：**验证全部在服务器端完成**（已有服务器），客户端只提交凭证、接收授权状态，
> 不做本地自校验；本期仅**定义契约并预留**，服务器接口与 `auth.js` 实现后续更新。

**基础约定**：
- 传输：HTTPS；请求/响应 JSON；`Content-Type: application/json`；
- 凭证：服务器签发 `token`（短期）+ 本地缓存授权状态（离线兜底 N 天）；refresh 语义后续补充；
- 命名空间：与教师客户端方案对齐（Cloudflare Workers 风格），路径建议 `/api/edu/...`。

**预留接口清单**（契约先行，实现后置）：

| 接口 | 方法 | 请求要点 | 响应要点 | 说明 |
|---|---|---|---|---|
| `POST /api/edu/auth/activate` | JSON | 手机号、产品授权口令、设备标识 | 成功/失败+原因（口令错/已绑定/过期）；成功后返回临时凭证 | 首次开通：绑定手机号↔口令 |
| `POST /api/edu/auth/login` | JSON | 手机号、密码 | token + 授权范围（解锁工具清单/有效期） | 日常登录 |
| `POST /api/edu/auth/reset` | JSON | 手机号、短信验证码、新密码 | 成功/失败 | 密码找回（依赖短信服务） |
| `GET /api/edu/auth/status` | 凭证 | — | 授权状态、剩余有效期、可解锁工具 | 断网重连/换设备校验 |
| `POST /api/edu/data/sync` | JSON | 家庭码维度完成状态/打卡 | 服务端确认 | 在线数据留存（数据最小化） |
| `POST /api/edu/report/query` | 凭证 | 家庭码、时间范围 | 家长报告数据（仅完成状态/打卡聚合） | 家长端 |

**预留即不阻塞**：A 批试点阶段，在线包可用「契约 + 假实现」（本地桩返回授权成功）先行开发
双模式与通用模块；服务器接口就绪后，仅替换 `auth.js`/`storage.js` 内部实现，不改 `core/`。

## 五、数据与合规（技术落点）

1. **手机号 = 个人信息**：收集需告知并取得同意（《个人信息保护法》），仅用于认证与找回；
2. **未成年人保护**：不满 14 周岁信息处理须监护人同意（PIPL 第 31 条）→ 孩子端无账号、家长手机号操作授权；数据仅家庭内可见；
3. **数据最小化**：只存完成状态/打卡天数，不存错题、正确率、能力评估；`storage.js` 从数据模型上约束；
4. **组内统计防反推**：小组 <10 人只显示不可反推的汇总量（`storage.js` 聚合层实现）；
5. **版号红线**：在线包不引入计分对抗/排行/多人实时/抽奖；
6. **密码安全**：密码加盐哈希；短信验证码限频、防爆破；令牌不过度暴露。
