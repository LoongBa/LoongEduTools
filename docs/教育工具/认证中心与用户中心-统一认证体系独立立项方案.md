# 认证中心与用户中心 · 统一认证体系独立立项方案（教育小程序 + 桃李助手）

> 状态：v0.2（2026-09-30，Oracle 外审 1B/6I/4N 全采纳后修订）
> 定位：**独立新服务 `auth.loongba.cn`（.NET 10）**，统一承载所有在线教育小程序 + 桃李助手的认证需求——认证中心 + 用户中心（档案）+ 统一口令兑换体系。
> 上游：`教育工具在线版设计要求.md`（§3.5 账号模型 / §4.6 预留契约）、`公共服务端接口与生产部署方案-教育小程序与桃李助手.md` v0.3（部署/S6/fail-fast 复用）、`D14-S6-微信短信真接入方案.md`、`S01/A01`（离线激活码并存）。
> 技术路线：.NET 10；独立域名 `auth.loongba.cn`；与 `api.taoli.loongba.cn`（server-dotnet 业务端）分工并存。

## 1. 立项背景与目标

### 1.1 背景（现状问题）

| # | 问题 | 现状 |
|---|---|---|
| P1 | **认证割裂** | 在线小程序的 `auth.js`/`storage.js` 是**桩**（`lx.auth.v1` stub-token，TODO 待接服务器）；桃李助手在线认证在 server-dotnet（`sms/send`+`verify`/`bind/wechat`）；两套不相通 |
| P2 | **授权方式分散** | 部分工具点读陪练已提「产品授权口令」（公众号购买），数学巧算等提「付费解锁」，桃李助手有「激活码」——无统一兑换码体系、无兑换记录、用户无法查看自己买了什么 |
| P3 | **免费但需微信认证无法落地** | 设计要求 §3.5「家长手机号 + 家庭码」；个别工具规划「免费需微信认证」——但个人订阅号无网页授权（指导原则 §3.3），无认证中心无从实现 |
| P4 | **教师免费通道无审核流** | 桃李助手「针对教师免费」但需证明教师身份——需「公众号填表提交资料 → 人工/自动审核 → 发口令」的完整链路 |
| P5 | **用户看不到自己的授权/兑换历史** | 应用内只显示个人基础信息；兑换历史、各小程序授权与使用情况无处可查——需独立用户中心 |
| P6 | **微信认证形态不统一** | 微信内打开（公众号网页授权）与浏览器打开（扫码）形态不同；壳 WebView 无法作 redirect_uri（D14 绑定票据中转）——需统一双形态 |

### 1.2 目标

1. **认证中心**：所有在线应用（教育小程序 ×44 + 桃李助手）统一认证入口——微信（公众号网页授权 + 开放平台扫码双形态）+ 手机号短信登录 + 口令兑换；纯接口验证为主、页面跳转用于微信授权。
2. **用户中心（档案）**：应用内可查个人信息；**口令兑换历史、各小程序授权与使用情况** → 独立用户中心页面（统一 URL，各应用可跳转）。
3. **统一口令兑换体系**：直购 / 公众号领取 / 教师资质审核发放 → 统一兑换码 → 兑换到具体小程序（app_id）× 授权范围 → 记录历史。
4. **全产品接入**：44 款教育小程序（auth.js/storage.js 契约不变、内部替换）+ 桃李助手（在线认证委托认证中心，离线激活码并存）分批接入。

### 1.3 范围与边界

| 项 | 范围 |
|---|---|
| 核心 | 认证中心 + 用户中心 + 口令兑换体系 + 各小程序/桃李助手接入改造 |
| **离线版不变** | 离线包（小红书 zip）纯静态无账号红线不变；`auth.js` offline 分支恒授权保留 |
| **离线激活码并存** | 桃李助手离线开课（A01 activate / S01 口令包 / D09 凭证）**不动**；新口令体系只管在线认证（用户裁定 2026-09-30） |
| 不做 | 支付收单（口令来源的购买在公众号/第三方渠道，本方案只消费「已生成的口令」）；内容包生产管线；在线商店 |

## 2. 总体架构

### 2.1 组件拓扑

```
用户（微信内 / 浏览器 / 桃李助手壳）
   │
   ├──▶ lexue.loongba.cn  （CF Pages 静态：44 款在线小程序本体）
   ├──▶ taoli.loongba.cn  （CF Pages 静态：桃李助手官网/内容包）
   └──▶ 桃李助手壳（Tauri，教室机）
          │
          ▼
   ┌────────────────────────────────┐
   │  auth.loongba.cn（.NET 10 自包含单文件）        │
   │  ├─ 认证中心：微信双形态 / 短信 / 口令兑换 / JWT │
   │  └─ 用户中心：档案 / 兑换历史 / 我的应用        │
   └───────────────┬────────────────┘
                   │ JWT 验签 / 授权查询
                   ▼
   api.taoli.loongba.cn（server-dotnet，桃李助手业务：激活码/口令包/内容包/上报）
```

- **auth.loongba.cn = 统一身份源**：账号（微信 openid/unionid + 手机号）唯一表；签发 JWT 供**所有**在线应用验证。
- **api.taoli.loongba.cn（server-dotnet）**：桃李助手**业务**服务端不动（激活码/口令包/内容包/凭证/上报）；其在线认证委托 auth 中心验签（共享 JWT key 或内网自调用）。
- **静态面**：lexue/taoli 仍在 CF Pages；认证/口令/档案全部走 auth 中心，不引入新静态依赖。

### 2.2 与既有体系关系

| 体系 | 关系 |
|---|---|
| `公共服务端方案 v0.3`（教育小程序+桃李助手共用 server-dotnet） | **认证部分由本方案接管**：v0.3 的「统一账号 + roles 分域 + family 域」演进为独立 auth 中心（本方案权威）；v0.3 保留部分 = 部署工件模式/fail-fast/S6/错误码映射（**基础设施复用**）+ server-dotnet 桃李助手业务（api.taoli.loongba.cn 保留，认证验签委托 auth 或共享 JWT key） |
| `D13 部署` | auth 中心复用同款部署工件模式（publish.sh/systemd/Caddy/备份/回滚/fail-fast），服务名 `edu-auth-api`，独立 `/opt/edu-auth-api/` |
| `D14 S6 微信/短信` | 短信 `ISmsService` 复用（手机号登录走 auth）；微信从「绑定票据中转」扩展出「标准 OAuth 双形态」（认证中心）；壳内绑定场景**保留绑定票据中转** |
| `A01 激活码 / S01 口令包 / D09 凭证` | **不变，离线开课场景专用**；教师在线认证 = auth 中心口令兑换，离线 = 激活码，两者通过统一账号关联 |
**v0.3 family 域端点迁移映射（Oracle I1——auth 中心接管认证后，v0.3 已定义的 family 域端点路径/角色演进）**：

| v0.3 family 域端点 | auth 中心新端点 | 处置 |
|---|---|---|
| `family/auth/activate`（family JWT） | `auth/redeem`（parent JWT） | 迁移（路径域 `family/auth/*` → `auth/*`） |
| `family/auth/status`（family JWT） | `auth/grants` | 迁移 |
| `family/data/sync`（家庭码弱凭证） | `auth/data/sync` | 迁移（家庭码弱凭证语义不变） |
| `family/report/query`（family JWT） | `auth/report/query` | 迁移 |
| `family/auth/status` 轮询 | — | 废弃（由 `auth/grants` 取代） |

- **角色命名演进**：v0.3 用 `["family"]` → auth 中心用 `["parent"]`（语义对齐「家长账号」）。**兼容策略（Oracle I1）**：auth 中心只签发 `["parent"]`；consumer（server-dotnet 等）读取层做 `family→parent` 兼容映射（参照 v0.3 I7 读取默认模式：无 roles → 默认 `["teacher"]` 的既有逻辑保留，遇 `family` 视为 `parent`）。

### 2.3 主体模型

| 主体 | 账号 | 认证方式 | 授权 |
|---|---|---|---|
| **家长/普通用户** | 微信免密账号（openid/unionid）或手机号账号 | 微信双形态 / 短信验证码 | 免费应用微信认证即可用；付费关卡口令兑换 |
| **教师** | 微信/手机号账号 + 教师身份（审核） | 微信 / 短信 / 教师口令 | 教学关卡通吃；桃李助手在线授权口令 |
| **孩子** | **无账号**（家庭码，沿用设计要求 §3.5） | 家庭码弱凭证 | 家庭码维度数据隔离（不纳入本认证中心的账号表） |

> **家庭码不纳入认证中心账号体系**：孩子端无账号红线不变；认证中心只服务「有账号主体」（家长/教师）。家庭码由各小程序 + auth 中心按既有设计要求管理（备选：auth 中心未来提供家庭码托管 API，本期不做）。

### 2.4 认证形态

| 形态 | 适用 | 流程 |
|---|---|---|
| **页面跳转（微信授权）** | 微信内打开小程序 / 浏览器扫码 / 壳内 WebView | 应用跳 auth 中心 → 用户微信授权 → auth 回调 → 302 带一次性 code 回应用 → 应用用 code 换 JWT |
| **纯接口验证** | 各应用已持 token 后的日常调用；auth.js 内部 | Bearer JWT → auth 中心 `/api/edu/auth/verify` 验签 + 返回授权快照；应用侧也可本地验签（共享公钥/对称密钥） |

## 3. 认证中心（Auth Center）

### 3.1 统一身份源（Account）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `u-{unixMs}-{rand}`（与 v0.3 同风格） |
| `phone` | string? | 手机号（唯一，可空——微信免密账号可无手机号） |
| `phone_password_hash` | string? | 密码散列（若启用密码登录；本期可跳过，登录主走微信/短信） |
| `wechat_mp_openid` | string? | 公众号网页授权 openid（微信内） |
| `wechat_web_openid` | string? | 开放平台网站应用 openid（扫码） |
| `unionid` | string? | 微信开放平台 unionid（双形态同一用户关联，D14 I5 复用） |
| `nickname` / `avatar` | string? | 可选（SNS userinfo 拉取，用户认同授） |
| `roles` | string[] | `["parent"]` 默认；教师审核通过后增 `["teacher"]` |
| `teacher_profile` | object? | 教师档案（姓名/学校/任教年级科目/审核状态，P4 审核流产物） |
| `created_at` / `updated_at` | DateTimeOffset | |

**账号合并规则**：
- 微信双形态同 unionid → 同一账号（openid 双字段归并）。
- **⚠️ snsapi_base 前提（Oracle I3）**：公众号网页授权 `scope=snsapi_base` **只返回 openid、不返回 unionid**（需 `snsapi_userinfo` 或用户已关注服务号）。因此微信内首登可能建「仅 mp_openid」账号，扫码首登建「仅 web_openid」账号——两账号在获取 unionid **之前**无法自动合并。
- **合并触发机制（Oracle I3）**：① 任一登录态获得 unionid（后续 `snsapi_userinfo` 授权 / 开放平台扫码）→ 回查该 unionid 既有账号 → **自动归并**（转移授权记录）；② **手机号绑定触发合并**——用户用手机号登录/绑定（短信验证码验证）时，检测到该手机号已有账号 → 双微信 openid 字段 + 授权记录**合并迁移**，需短信验证码 + 原登录态双重确认（防劫持）。两个触发点均在 §8 安全设计覆盖。
- 微信免密账号 + 手机号 → 绑定合并（同一人，微信先行注册后补手机号；手机号登录时若命中同一手机号且微信已绑 → 合并，需短信/微信双重验证防劫持——见 §8 安全）。
- 手机号唯一索引；微信 openid 唯一索引。

### 3.2 微信认证双形态（用户裁定 2026-09-30）

> 前置：**公众号升级为认证服务号**（个人订阅号无网页授权，指导原则 §3.3 现状）或使用已认证服务号；开放平台网站应用（D14 已规划，300 元/年）。

| 形态 | 触发 | OAuth 流程 | 前提 |
|---|---|---|---|
| **公众号网页授权** | 微信内打开 lexue 小程序 | `connect/oauth2/authorize?appid&redirect_uri=auth.loongba.cn/oauth/wechat/mp/callback&response_type=code&scope=snsapi_base&state` → 静默拿 openid（`scope=snsapi_base`；**仅返回 openid，不返回 unionid**——需 `snsapi_userinfo` 或关注服务号，见 §3.1 合并触发）；需昵称/头像时 `snsapi_userinfo` | 认证服务号 + 网页授权域名 = `auth.loongba.cn`（ICP 备案） |
| **开放平台扫码** | 浏览器打开 / 壳 WebView | `connect/qrconnect?appid&redirect_uri=auth.loongba.cn/oauth/wechat/web/callback&response_type=code&scope=snsapi_login&state#wechat_redirect`（D14 §3.2 同款） | 开放平台网站应用 + 授权回调域名 `auth.loongba.cn` |

**回调处理（auth 中心）**：
1. `code` 换 token 微信侧（AppSecret 服务端持有，不落前端）；**access_token 不缓存、refresh 落库（I6 简化 → 不持久化）**。
2. 按 `unionid`/`openid` 查/建账号：有 → 登录；无 → 建微信免密账号（默认 `roles=["parent"]`）。
3. 签发一次性 `oauth_code`（TTL 5min，单次消费），302 回 `redirect_uri?oauth_code=xxx&state=xxx`。
4. 应用（小程序/桃李助手壳）用 `oauth_code` 调 `/api/edu/auth/oauth/exchange` 换 JWT。

**壳内绑定场景（桃李助手）**：保留 D14 绑定票据中转（`bind/status` 轮询）不动——认证中心为壳内微信登录新增等价中转流程（authorize 返回授权 URL → 扫码 → callback 落微信账号 → 壳轮询 bound）。

**⚠️ 微信登录 vs 绑定 session 隔离（Oracle I6）**：D14 §3.4 安全边界明确记录——「当前仅绑定不登录；若将来实现微信扫码**登录**，需防绑定劫持（攻击者用自己 bind_token+state 诱导受害者扫码，绑受害者 openid 到攻击者账号）；届时登录流程须用**独立 session** 而非绑定票据」。本方案把微信从「绑定」扩展到「登录」（建/认账号 → 签发 oauth_code → JWT），**必须显式声明**：登录流程的 `state`/`oauth_code` 与绑定流程的 `bind_token`/`state` **完全独立、不复用、不混用**——登录用独立的 5min 单次 oauth_code 建立新会话，绝不在登录流程复用绑定票据。

### 3.3 手机号短信登录（复用 S6）

| 端点 | 说明 |
|---|---|
| `POST /api/edu/auth/sms/send` | 手机号验证码（复用 TencentCloudSDK.Sms + 频控 60s/小时/天/IP；生产 Mock → 503 防 dev_code 泄露，v0.3 fail-fast 同款） |
| `POST /api/edu/auth/sms/verify` | 验证码登录/绑定：有账号 → 登录；无账号 → 建手机号账号（`roles=["parent"]`）→ 若微信免密账号已存在同 unionid → 合并（需验证） |

> 手机号登录与微信登录统一 JWT（同一账号体系），登录后各应用看到同一用户中心档案。

### 3.4 统一口令兑换体系（Redemption Code）

**口令 = 授权兑换券**（区别于桃李助手离线「激活码」——激活码绑机器离线开课，口令在线兑换授权）：

| 字段 | 说明 |
|---|---|
| `code` | 兑换码（**高熵定稿，Oracle N1**：`LOONG-XXXX-XXXX-XXXX`，每段 4 位 36 进制去易混字符，总熵 ≥ 72bit，防爆破） |
| `channel` | 来源渠道：`shop`（公众号/小报童等直购）/ `offcial`（公众号领取）/ `teacher-review`（教师资质审核发放，P4） |
| `target_app_id` | 可兑换的小程序/产品 id（`*` = 全产品） |
| `scope` | 授权范围（如 `all` / `unit:N` 关卡解锁 / `pro`） |
| `expires_at` | 口令本身有效期（未兑换前过期作废） |
| `valid_until` | 兑换后授权有效期（如 1 学期/1 年/永久） |
| `single_use` | 是否单次兑换（默认 true；`offcial` 领取可多批） |
| `bound_wechat` / `bound_phone` | 绑定限定（教师审核口令绑定 openid，防转售） |
| `status` | `available / redeemed / expired / revoked` |
| `batch_id` | 批次（后台生成/导入用） |

**生成**：`scripts/gen_codes.py`（复用 D13 激活码生成思路）→ 种子/CSV → 导入 auth 数据（BatchRecord + CodeRecord），**生产 demo seed 清空 + 拒绝启动发现 demo 散列（fail-fast 同款）**。

**兑换流**（应用内，登录态）：
```
应用（已登录，持 JWT）── POST /api/edu/auth/redeem { code } ─▶ 认证中心
    校验：登录态 → code 存在/未用/未过期/未吊销 → target 匹配 → 绑定限定通过
    → 创建 GrantRecord（account_id, app_id, scope, valid_until, source=redemption, code_id）
    → 记录 RedemptionRecord（兑换历史）→ code.status=redeemed（single_use）
── 响应 200 { grant: {...} }  → 应用刷新授权状态
```

**授权查询（应用侧日常）**：`GET /api/edu/auth/grants?app_id=xxx`（JWT）→ 返回该应用全部有效授权（免费微信认证 / 口令授权 / 教师授权 + 到期时间）→ 应用据此解锁关卡。

### 3.5 教师资质审核流（P4，公众号填表）

```
教师（微信内）── 公众号表单（姓名/学校/任教年级科目/微信号）──▶ 审核后台
    表单采集 openid（网页授权 snsapi_base，静默绑定）
    ── 人工/自动审核（自动：任教信息完整性 + 重复提交防护；人工兜底）──▶ 通过/驳回
    通过 → 生成 teacher-review 口令（绑定 openid，single_use，target=taoli-teacher，scope=pro）
    → 公众号/短信通知教师「口令已发放」
教师 ── 桃李助手在线端登录（微信）── 输入口令兑换 ──▶ roles 增 ["teacher"] + teacher_profile 审核通过
── 桃李助手在线功能解锁；离线开课仍走激活码（并存）
```

- 自动审核门槛放低 + 人工复核抽样（先自动快速通过完整信息的教师，异常人工兜底）。
- 兑换后 `teacher_profile.status=approved`，JWT 带 `roles:["teacher"]`。

### 3.6 Token / 会话

| 项 | 设计 |
|---|---|
| JWT | HS256（对称密钥 `AUTH_JWT_SECRET`，≥32 字节随机），payload `{ sub, roles, exp, iat, jti }`；TTL **2h 会话级**（在线场景短会话）+ **7d 长效**（桃李助手壳/低敏应用，沿用 v0.3 约定）双档 |
| 验签 | auth 中心 `/api/edu/auth/verify`（Bearer JWT → 查账号状态 + 返回授权快照）；server-dotnet 可共享 `AUTH_JWT_SECRET` 内网自验签（不额外调 auth） |
| 刷新 | `POST /api/edu/auth/refresh`（过期 JWT 直换，v0.3 I5 简化模型）：2h 短会话过期后凭 7d JWT 续；7d 过期重新登录 |
| 一次性 `oauth_code` | TTL 5min 单次消费（3.2 步骤 3 → 4 换 JWT） |

| auth.js 方法（对外） | 内部实现（替换） |
|---|---|
| `A.status()` | 携本地 JWT → auth `/verify` → 返回 `{ authorized, scope, expireAt, roles }`（失败回退本地缓存） |

### 5.5 错误码与限频

- 错误结构/七码复用 A01 §1.2 + v0.3 新增 `SERVICE_UNAVAILABLE`(503)/`SMS_SEND_FAILED`(502)。
- **新增端点特有错误码**（Oracle N2）：

| code | HTTP | 场景 |
|---|---|---|
| `OAUTH_CODE_EXPIRED` | 400 | oauth_code 已过期（>5min） |
| `OAUTH_CODE_CONSUMED` | 400 | oauth_code 已被消费（单次） |
| `OAUTH_STATE_MISMATCH` | 400 | state 校验失败（CSRF） |
| `CODE_NOT_FOUND` | 404 | 口令不存在 |
| `CODE_REDEEMED` | 400 | 口令已兑换（single_use） |
| `CODE_EXPIRED` | 400 | 口令已过期（未兑换前超时） |
| `CODE_REVOKED` | 403 | 口令已吊销 |
| `CODE_BOUND_MISMATCH` | 403 | 绑定限定不匹配（教师口令绑定 openid，非本人兑换） |
| `CODE_TARGET_MISMATCH` | 400 | 口令 target_app_id 与应用不符 |
| `FAMILY_CODE_INVALID` | 400 | 家庭码不存在/错误 |

- 频控（Oracle N3 补全）：短信 60s/小时/天/IP（v0.3 §2.4）；**口令兑换失败 5 次/小时/账号 → 429**（防爆破）；**oauth/authorize 10 次/分钟/IP**（防刷授权跳转）；oauth/exchange 每 oauth_code 单次消费（天然限频）。

| server-dotnet 端点 | 处置 |
|---|---|
| `sms/send`、`sms/verify` | **废弃**（迁移 auth 中心 `/sms/send`+`/sms/verify`；壳端 auth.js 指向 auth 中心） |

| `codes/activate`、`license/renew`、`credential/sign`、`packages/*`、`report/ingest` | **保留**（桃李助手业务端点，离线开课/内容/上报专用） |

> 最终分工：**server-dotnet 只保留桃李助手业务端点 + JWT 验签**；smss/微信/refresh 全部收归 auth 中心（Oracle I5）。

## 8. 安全设计

| 项 | 设计 |
|---|---|
| fail-fast 三件套 | `AUTH_JWT_SECRET` 缺失/默认 → 拒绝启动；Production + `TencentSms:Mode=Mock` → 认证端点 503；demo 口令 seed 清空 + 库中 demo 散列 → 拒绝启动（v0.3 同款） |
| 口令防爆破 | 高熵 code + 散列存储 + 兑换失败 5 次/小时/账号 429 + single_use |
| 微信双形态安全 | AppSecret 仅服务端；oauth_code 单次消费 TTL 5min；state 防 CSRF；绑定限定口令防转售 |
| 微信登录 vs 绑定 session 隔离（Oracle I6） | 登录 `state`/`oauth_code` 与绑定 `bind_token`/`state` 独立不复用（§3.2 声明），防绑定劫持（引用 D14 §3.4 安全边界） |
| 账号合并防劫持 | 微信免密账号 + 手机号合并需双向验证（微信登录态 + 短信验证码），防他人手机号抢绑；unionid 归并仅发生在微信侧凭证验证后（Oracle I3） |
| 用户中心防护 | 个人档案/兑换历史仅本人 JWT 可读；使用情况聚合不含学习明细（儿童数据红线） |
| 浏览器态 | JWT 存 localStorage 有 XSS 面 → 短会话 + 敏感操作二次验证；桃李助手壳（WebView）低敏可 7d |
| 域名/IPC | `auth.loongba.cn` ICP 备案 + DNS 灰云直连 + Caddy 自动 HTTPS + 限频（复用 D13 §5/I9） |

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 公众号服务号主体/认证（前置阻塞，个人订阅号无网页授权） | 立项即启动服务号认证（或复用可用的认证服务号）；过渡期先上线开放平台扫码 + 短信双路径；网页授权后置 |

| 微信 openid 双形态账号合并复杂度 | unionid 为主键合并；早期未获 unionid 的账号用 openid 双字段 + 手机号绑定兜底 |
| 设备 XSS 盗 JWT（localStorage） | 短会话（2h）+ 敏感操作二次验证；桃李助手壳 long-session 例外 |
| 44 款接入工作量大 | 统一 auth.js 一次改造全部受益；分批接入（主力 4 → 学科 6 → 其余）；缓存/降级（离线可用回退） |
| 与 server-dotnet v0.3 duplicate | 明确分工：auth=认证/档案/口令；server-dotnet=桃李助手业务；共享 JWT key 不重复造账号 |
| 口令经济（转售/恶意兑换） | 高熵 + single_use + bound + 兑换频控 + 渠道留痕 |
