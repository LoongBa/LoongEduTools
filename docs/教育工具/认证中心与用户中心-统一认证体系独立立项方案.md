# 认证中心与用户中心 · 统一认证体系独立立项方案（TKWF.Extension · 教育小程序 + 桃李助手）

> 状态：v0.6（2026-09-30——Oracle 外审 GO 有条件 + 1B/5I/4N 全采纳后修订；v0.5 = TKWF.Extension 定位升级）
> 定位：**认证中心 + 用户（档案）中心 = TKWF.Extension 通用组件**（吸收 DMP-Lite AuthCenter 经验：MemberUId 内部 id / 头像 URL / RefreshToken rotation / 跨商户映射），独立装配、部署为认证中心实例；**各业务系统/子系统只消费令牌 + 公共档案，业务角色本地映射、业务信息本地按需增强**（用户裁定 2026-09-30）。
> 上游：`DMP-Lite`（会员卡 AuthCenter / 平台管理全局用户映射 R04）、`TKWF` 框架（DomainUser&lt;T&gt; / AuthorityFilter&lt;T&gt;）、`教育工具在线版设计要求.md`、`公共服务端方案 v0.3`（部署/fail-fast 复用）、`D14`。
> 技术路线：TKWF 生态（.NET + PostgreSQL，装配实例 `auth.loongba.cn`）；与 `api.taoli.loongba.cn`（server-dotnet 业务端）分工并存。

## 1. 立项背景与目标

### 1.1 背景（现状问题）

| # | 问题 | 现状 |
|---|---|---|
| P1 | **认证割裂** | 在线小程序的 `auth.js`/`storage.js` 是**桩**（`lx.auth.v1` stub-token）；桃李助手在线认证在 server-dotnet；DMP-Lite 已有 AuthCenter（会员卡在用）但未覆盖教育线；各业务系统各自为政 |
| P2 | **授权方式分散** | 点读陪练「产品授权口令」、数学巧算「付费解锁」、桃李助手「激活码」——无统一兑换码体系、无兑换记录、用户无法查看自己买了什么 |
| P3 | **免费但需认证无法落地** | 个别工具规划「免费需认证」——个人订阅号无网页授权，无统一认证中心无从实现 |
| P4 | **教师免费通道无审核流** | 桃李助手「针对教师免费」但需证明教师身份——需「公众号填表 → 审核 → 发口令」完整链路 |
| P5 | **用户看不到授权/兑换历史** | 应用内只显示个人基础信息；兑换历史、各小程序授权与使用情况无处可查——需独立用户中心 |
| P6 | **令牌/ID 契约未统一** | 各系统返回手机号/openid 各异；无「平台内部 id + 应用本地映射」统一规范（DMP-Lite 已有 MemberUId 实践未推广） |
| P7 | **认证能力重复建设** | DMP-Lite AuthCenter、LoongEduTools 规划、未来新系统各建一套——应抽象为 TKWF.Extension 通用组件，一次建设多系统复用（用户裁定 2026-09-30） |

### 1.2 目标

1. **TKWF.Extension 通用组件**：认证面（Token 签发/刷新/撤销 + 微信/短信/口令）+ 档案面（公共 Profile API + 用户中心页面）——独立装配部署为认证中心实例，多业务系统消费。
2. **令牌契约统一**：JWT 只带 `sub`（平台内部 id）+ 标准声明，**不含业务角色**（「你是谁」）；业务角色由各应用按 `sub` **本地映射**（「你能干什么」，小书童 student/owner/parent 等）。
3. **用户中心（档案）**：公共信息（认证中心：手机号/微信绑定/昵称/头像 URL/兑换历史/我的应用）+ 业务信息（子系统本地按需保存，不适合集中、需特化的留在本地）；用户看更多 → 跳转用户中心页面。
4. **口令兑换体系**：统一兑换码（商品载体/电商上架/分销/公众号领取/教师审核）+ campaign 免费体验 → 兑换到具体应用（app_id）× scope → 记录历史。
5. **全业务系统接入**：44 款教育小程序 + 桃李助手（本仓库）+ 小书童等并行业务系统（各自接续），auth.js/storage.js 契约不变、内部替换。

### 1.3 范围与边界

| 项 | 范围 |
|---|---|
| 核心 | TKWF.Extension（认证面 + 档案面 + 身份适配层）+ 装配实例 + 各业务系统接入改造 |
| **离线版不变** | 离线包（小红书 zip）纯静态无账号红线不变；`auth.js` offline 分支恒授权保留 |
| **离线激活码并存** | 桃李助手离线开课（A01 activate / S01 口令包 / D09 凭证）**不动**；新口令体系只管在线认证 |
| **认证降级路径** | ① 个人订阅号阶段：手机号短信 = 唯一在线认证，微信 openid 仅菜单/聊天事件被动采集，口令经「菜单/聊天交互」被动回复下发（无需网页授权）；② 认证就绪后（服务号/开放平台/个体户企业/代认证）：微信网页授权 = 便捷登录，「认证只是便捷，不必每次验证手机号」 |
| 不做 | 支付收单（口令购买在公众号/第三方渠道，本方案只消费已生成口令）；内容包生产管线；在线商店 |

## 2. 总体架构

### 2.1 组件拓扑（TKWF.Extension · 认证中心定位）

```
                    ┌──────────────────────────────────────────────┐
                    │  TKWF.Extension（通用组件，多系统复用）          │
                    │  ├─ 认证面：微信双形态/短信/口令兑换/令牌签发      │
                    │  ├─ 档案面：公共 Profile API + 用户中心页面       │
                    │  └─ 身份适配层：JwtDomainUserParser（令牌→DomainUser）│
                    └──────────────┬───────────────────────────────┘
                                   │ 装配部署
                                   ▼
                  auth.loongba.cn（认证中心实例，.NET + PG）
                                   │
          ┌────────────────────────┼──────────────────────────┐
          │ 票据 URL + 接口换取     │ sub=平台内部 id（MemberUId 风格）│
          ▼                        ▼                          ▼
   教育小程序（44款/lexue）     桃李助手（壳）                 并行业务（小书童等）
   auth.js/storage.js 替换    在线认证委托                     本地角色映射
   本地业务档案按需             离线激活码并存                   student/owner/parent
```

- **认证中心（装配实例）** = TKWF.Extension 组件装配：签发**统一 JWT**（`sub` = 平台内部 id），各业务系统凭令牌消费认证/档案/授权快照。
- **各业务系统**：只存「本地业务映射 + 本地业务档案」，不持有认证中心账号库；角色/业务信息本地映射（§3.2/§5）。
- **api.taoli.loongba.cn（server-dotnet）**：桃李助手**业务**服务端保留（激活码/口令包/内容包/上报），在线认证验签委托认证中心（共享 JWT key 或内网调 `/verify`）。
- **静态面**：lexue/taoli 仍在 CF Pages；认证/口令/档案走认证中心。

| `TKWF 框架`（DomainUser&lt;T&gt; / AuthorityFilter&lt;T&gt;） | **身份适配层关键**：JwtDomainUserParser 把令牌（sub=内部 id）填进 `DomainUser&lt;TUserInfo&gt;` → **AuthorityFilter 零改动**（它只消费 DomainUser）——唯一框架侧新增 = Ext.Identity 适配层（§2.5） |

| `D13 部署` | 认证中心实例复用部署工件模式（systemd/Caddy/备份/回滚/fail-fast） |
| `A01 激活码 / S01 口令包 / D09 凭证` | **不变，离线开课场景专用**；教师在线认证 = 认证中心口令兑换，离线 = 激活码，统一账号关联 |
| `教育工具在线版设计要求 §4.6` | 6 端点被认证中心 API 吸收升级，`auth.js` 契约对外保持兼容 |

### 2.3 主体模型与 ID 契约

> **平台内部 id = 唯一跨系统身份引用（用户裁定 2026-09-30）**——不返回手机号、不返回 openid；JWT `sub` + 档案 `userId` 均用平台内部 id（MemberUId 风格 string(32)）。

| 主体 | 令牌身份（认证中心） | 业务角色（本地映射） | 业务档案（本地按需） |
|---|---|---|---|
| **家长/普通用户** | 平台内部 id（`u-{unixMs}-{rand}`，手机号主键注册） | 各应用自行定义（如小书童 parent/owner） | 各应用本地（进度/设置/家庭码关联） |
| **教师** | 平台内部 id + 教师审核标记（认证中心仅标 `teacher_verified`，**不判业务权限**） | 桃李助手等本地（课堂口令/内容范围） | 本地（任课班级/机器绑定） |
| **孩子** | **无账号**（家庭码，沿用设计要求 §3.5；不纳入认证中心账号表） | 家庭码维度数据隔离 | 各应用本地（家庭码关联） |

- **业务角色不进令牌**：令牌 = 「你是谁」（sub/认证方式/教师审核标记）；「你能干什么」（角色/权限）由各业务系统按 sub + 本地映射计算——与 DMP 全局用户映射（平台 id ↔ 商户局部 id）同构。
- **游客态**：纯免费小程序可不登录直接玩（localStorage）；需云存档/跨设备/口令兑换/家长报告 → 手机号验证登录。

### 2.4 认证形态与回调承载（票据 URL + 接口换取，用户裁定）

| 形态 | 适用 | 流程 |
|---|---|---|
| **页面跳转（微信授权）** | 微信内 / 浏览器扫码 / 壳 WebView | 应用跳认证中心 → 微信授权 → 认证中心回调 → **302 带一次性票据回应用** → 应用用票据调内部接口换令牌 |
| **纯接口验证** | 应用已持令牌后的日常调用 | Bearer JWT → `/verify` 验签 + 授权快照；应用侧也可共享密钥本地验签 |
| **公众号衔接链接** | 个人订阅号欢迎语/菜单回复带链接 | 关注自动回复/菜单回复文字带**一次性票据链接** → 用户点开认证中心 H5 → 补手机号/领口令/绑账号 |

**回调令牌承载（票据 URL + 接口换取）**：
1. URL 只带**一次性票据**（`ticket`，TTL 5min，单次消费）+ 回跳地址 `redirect_uri`；**绝不带明文令牌/手机号/openid 等敏感信息**（用户可能复制链接外扩散——§8 铁律）。
2. **换令牌路径按子应用形态区分（Oracle B1 修订）**：
   - **有服务端子应用**（桃李助手 server-dotnet / 平台服务端）：子应用服务端调认证中心**内网/trust 域接口**换取令牌（`POST /oauth/exchange`，认证中心与子应用内网互通）——令牌不经 URL、不经浏览器。
   - **纯前端静态站**（教育小程序 44 款，CF Pages 无服务端）：`/oauth/exchange` **公网可达** + **票据绑定 `app_id` + `redirect_uri` 白名单 + PKCE 式 `code_verifier`**（前端生成，换令牌时校验）——等价 OAuth2 Authorization Code + PKCE for SPA，防票据拦截/抢先消费（Oracle B1：静态站无法走内网，必须公网换令牌并加客户端绑定防劫持）。
3. 令牌失效/泄露 = 应用可随时向认证中心能力收权，无需依赖曾扩散的 URL 内容。

### 2.5 框架对接（TKWF DomainUser&lt;T&gt; / AuthorityFilter&lt;T&gt;）

> 并行业务系统 Q4 的结论（用户裁定 + 已核实框架事实）：**能对接，需 TKWF.Extension.Identity 新增适配层**；AuthorityFilter **零改动**（Oracle N3 已核实：`AuthorityFilterAttribute<TUserInfo>.PreProceedAsync` 只消费 `context.DomainUser.IsAuthenticated` 与 `user.IsInRole(r)`，不关心 DomainUser 来源）。

```
JWT(sub=平台内部id) ─▶ [TKWF.Extension.Identity: JwtDomainUserParser]
     ─▶ ParseAndVerify（Parse 内部强制 Verify——Oracle I5：杜绝「只 Parse 不验签」的遗漏漏洞）
     ─▶ 验证签名/过期（共享公钥/JWKS 或内网 /verify introspection）
     ─▶ 构建 IDomainUser(DomainUser<TUserInfo>, UserIdString=sub, claims)
     ─▶ DomainUserAccessor（standalone/web/api 三种装配）
     ─▶ 业务代码 DomainUser.UserId / Use<T>() / [AuthorityFilter<TUserInfo>(Roles=...)]
         └─ IsInRole 由业务系统 TUserInfo/IAuthorizationMapper 实现（Oracle I4）
```

**新增组件（本方案产出，命名统一为 `TKWF.Extension.Identity`，Oracle I1）**：
- `JwtDomainUserParser.ParseAndVerify(token)`：**验签 + 令牌 → DomainUser**（合并接口，内部强制验签，杜绝漏验签——Oracle I5）；子应用服务端走内网换令牌后本地解析，静态站走公网换令牌 + PKCE 校验后本地解析
- `ITokenVerifier`：共享公钥本地验签 / 远程认证中心 introspection（`/verify`）
- `IAuthorizationMapper<TUserInfo>.MapRoles(sub, claims)`：sub + 认证声明（含 teacher_verified，Oracle I4）→ 本地业务角色，供 `IsInRole`；**约束：业务角色不进令牌，认证中心不感知角色模型**
- 装配一次，多业务系统复用；AuthorityFilter/DomainUserAccessor 框架侧无改动（Oracle N3 确认）。

> **teacher_verified 边界（Oracle I4）**：`teacher_verified` 是认证中心核实的**身份声明**（类比 OIDC `email_verified`），**本身不参与 AuthorityFilter 的 IsInRole 角色判定**；业务系统如需教师角色，在本地 `MapRoles(sub, claims)` 中映射（如 sub + teacher_verified → 本地 "teacher" 角色）。认证中心只核实「你是教师」，不决定「教师能干什么」。

## 3. 认证中心（认证面）

### 3.1 统一身份源（Account，认证中心实例数据）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string(32) | **平台内部 id（MemberUId 风格）**——JWT `sub` / 跨系统唯一引用 |
| `phone` | string | **手机号 = 身份主键（必填，唯一）**——关键身份识别（用户裁定） |
| `phone_password_hash` | string? | 密码散列（本期跳过，登录主走短信/微信便捷） |
| `wechat_mp_openid` | string? | 公众号 openid（网页授权或菜单/聊天事件被动采集） |
| `wechat_web_openid` | string? | 开放平台网站应用 openid（扫码） |
| `unionid` | string? | 微信开放平台 unionid（双形态同一用户关联） |
| `nickname` | string? | 昵称（微信授权拉取） |
| `avatar` | string? | **头像 URL**（string，非二进制——DMP-Lite 实践确认） |
| `teacher_verified` | bool | 教师审核标记（认证中心仅标「已核实教师」，**不含** 业务权限/级别） |
| `auth_level` | int | 认证强度（1=手机号 / 2=微信便捷 / 3=教师核实） |
| `created_at` / `updated_at` | | |

**账号模型（手机号主键 + 微信便捷）**：
- 账号必有手机号（`phone` 必填）；微信 openid 仅**便捷登录绑定**，不是账号本体；微信登录未绑手机号 → 引导补手机号（短信验证）——不建无手机号孤儿账号。
- **个人订阅号阶段**：微信 openid 靠公众号菜单/聊天事件被动采集（§3.4b），用于口令绑定/防转售；在线认证走手机号短信。
- **账号合并**：微信双形态同 unionid 归并；手机号绑定触发 openid/授权记录合并（短信 + 原登录态双重验证防劫持）。snsapi_base 前提（Oracle I3）：仅返回 openid 不返回 unionid，早期账号以 openid 双字段 + 手机号兜底。

### 3.2 微信认证双形态（认证后就绪 · 便捷路径）

> 前置（非阻塞）：微信网页授权/扫码需认证服务号 + 开放平台网站应用；个人订阅号阶段微信不做登录凭证，口令经菜单/聊天下发（§3.4b）；将来个体工商户/企业/代认证后再启网页授权便捷登录。

- **公众号网页授权**：`connect/oauth2/authorize?...redirect_uri=auth.loongba.cn/oauth/wechat/mp/callback&scope=snsapi_base`（snsapi_base 仅 openid，需 userinfo 或关注服务号才 unionid）。
- **开放平台扫码**：`connect/qrconnect?...redirect_uri=auth.loongba.cn/oauth/wechat/web/callback&scope=snsapi_login`。
- **回调处理**：code 换 openid（AppSecret 服务端持有，access_token 不缓存、refresh 不持久化）→ 查账号（已绑手机号 → 便捷登录；未绑 → 引导补手机号）→ 签发**一次性票据**回应用。
- **壳内绑定场景**：保留 D14 绑定票据中转（`bind/status` 轮询）；认证中心新增等价登录中转（票据 + 接口换取）。
- **⚠️ 微信登录 vs 绑定 session 隔离（Oracle I6）**：登录 `state`/票据与绑定 `bind_token`/`state` 独立不复用，防绑定劫持（D14 §3.4 安全边界）。

### 3.3 手机号短信登录

- `POST /api/edu/auth/sms/send` + `/sms/verify`（复用 TencentCloudSDK.Sms + 频控 60s/小时/天/IP；生产 Mock → 503 防 dev_code 泄露）。
- 验证码登录/绑定：有账号 → 登录；无账号 → 建手机号账号；微信 openid 命中未绑账号 → 绑定归并（短信验证）。

### 3.4 统一口令兑换体系（口令 = 商品载体 + 授权兑换券）

| 字段 | 说明 |
|---|---|
| `code` | 高熵（`LOONG-XXXX-XXXX-XXXX`，每段 4 位 36 进制去易混字符，总熵 ≥ 72bit） |
| `channel` | `shop`（直购）/ `offcial`（公众号领取）/ `campaign`（免费体验/拉新）/ `teacher-review`（教师审核）/ `distributor`（渠道分销） |
| `marketplace` | 电商上架来源（douyin/xiaohongshu/wechat/pdd/direct） |
| `distributor_id` | 分销商 id（distributor 渠道必填；后台追踪发放/兑换/分成） |
| `sku_ref` | 商品 SKU 引用（电商商品 → 口令批次映射） |
| `target_app_id` | 可兑换的应用/产品 id（`*` = 全产品） |
| `scope` | 授权范围（all / unit:N / pro） |
| `expires_at` | 口令本身有效期（未兑换前过期作废） |
| `valid_until` | 兑换后授权有效期 |
| `single_use` | 是否单次兑换（默认 true） |
| `bound_wechat` / `bound_phone` | 绑定限定（教师口令绑 openid 防转售） |
| `status` | available / redeemed / expired / revoked |
| `batch_id` | 批次 |

**生成与上架**：`gen_codes.py` + **管理端**（§5.2b）：按 SKU 批量生成 → 导出 CSV → 电商平台订单获口令（商家后台/自动化发货回调兑入口令）。分销渠道绑定分销商（batch 维度跟踪）。生产 demo seed 清空 + 拒绝启动发现 demo 散列（fail-fast）。

### 3.4b 公众号口令下发通道（个人订阅号阶段可用的降级实现）

- 个人订阅号**无需网页授权**：自定义菜单 + 服务器配置 + 被动回复即可下发口令；事件 `FromUserName` = 用户 openid（无网页授权也能采集绑定）。
- 链路：菜单点击领口令 / 聊天关键词领口令 / 教师审核口令「查收口令」菜单 / 欢迎语·菜单回复带**一次性票据链接**引导（补手机号/领口令/绑账号）。
- 防刷：按 openid 日限频 + 高熵 + 兑换频控；无客服消息主动推送 → 一律「用户主动来取」，文案引导。

### 3.5 教师资质审核流（P4）

`公众号填表（姓名/学校/任教/微信号，采集 openid）→ 人工/自动审核 → 生成 teacher-review 口令（绑 openid）→ 引导回公众号「查收口令」菜单取口令 → 桃李助手在线端登录（手机号）→ 兑换 → 认证中心标记 teacher_verified + 本地教师档案授予 → 在线功能解锁；离线激活码并存`

### 3.6 令牌与会话

| 项 | 设计 |
|---|---|
| JWT | HS256/RS256（`AUTH_JWT_SECRET`/`AUTH_JWT_PUBLIC_KEY`），payload **`{ sub: 平台内部id, auth_level, teacher_verified, exp, iat, jti }`——不含业务角色**；TTL 2h 会话 + 7d 长效双档 |
| 验签 | 认证中心 `/verify`（introspection）；业务系统可共享公钥本地验签 |
| 刷新 | `/refresh`（refresh token rotation，DMP-Lite 实践；2h 会话凭 7d/refresh 续） |
| 回调票据 | `ticket`（TTL 5min 单次）→ 内部接口换令牌（§2.4 铁律） |

## 5. 授权模型与接口契约

### 5.1 授权分层 + 集中授权边界

| 档 | 授权模式 | 认证要求 |
|---|---|---|
| **A · 免费需登录** | 全量免费，登录即用；游客态可免登录 | 手机号验证（主）；微信便捷（认证后） |
| **B · 免费关卡 + 口令关卡** | 免费部分登录即用；收费关卡需口令 | 手机号 + 口令兑换（shop/offcial/campaign） |
| **C · 教师授权** | 课堂向免费但需教师口令 | 手机号 + teacher-review 口令 → teacher_verified |

**集中授权边界**：
```
口令（商品/上架/分销）→ 认证中心（认证+授权中枢）→ /grants·/verify 授权快照 → 各应用
```
- 认证中心 = 唯一授权权威：口令/兑换/授权计算/分发管理（admin）全在认证中心闭环。
- **各应用只接受授权快照**（`/grants`、`/verify`）——不接触口令明文、不理解兑换逻辑、不解析 URL 票据。
- **业务角色 ≠ 授权快照**：授权快照是「对某应用兑了什么（scope/有效期）」；**业务角色（student/owner/parent 等）由应用按 sub 本地映射**（§2.3/§2.5）——两者正交。

### 5.2 认证中心 API（前缀 `/api/edu/auth/`）

| 方法 | 路径 | 用途 | 认证 |
|---|---|---|---|
| GET | `/oauth/wechat/mp/callback`、`/oauth/wechat/web/callback` | 微信授权回调（→ 302 带一次性票据） | — |
| GET | `/oauth/authorize?app_id&redirect_uri` | 应用授权跳转入口（含壳 WebView 中转） | 无 |
| POST | `/oauth/exchange` | **一次性票据换 JWT**（内部/trust 域接口换取） | ticket |
| POST | `/sms/send`、`/sms/verify` | 手机验证码登录/注册/绑定 | 无 |
| POST | `/redeem` | 口令兑换（登录态） | JWT |
| GET | `/grants?app_id` | 应用授权状态查询 | JWT |
| GET | `/verify` | 令牌验签 + 授权快照（introspection） | JWT |
| POST | `/refresh`、`/logout` | 刷新 / 注销 | 过期 JWT |
| POST | `/data/sync` | 孩子端完成状态/打卡轻量信封（家庭码弱凭证） | 家庭码 |
| GET | `/report/query` | 家长报告查询（家庭码 + 时间范围） | parent JWT + familyCode |
| POST/GET | `/family/code` | 家庭码签发/绑定/查询 | parent JWT |

**§4.6 六端点全吸收对照**：login→oauth/exchange+sms/verify、reset→sms/send+sms/verify、activate→redeem、status→grants、data/sync→data/sync、report/query→report/query。**密码登录本期不做**。

### 5.2b 管理端 API（前缀 `/api/edu/admin/`，API Key 保护）

`POST /codes`（批量生成）/ `GET /codes`（批次查询）/ `POST /codes/{id}/revoke`（吊销）/ `GET /distributors/{id}/codes`（分销统计）/ `POST /import`（电商订单→口令：CSV/回调兑入）。

### 5.3 框架适配 API（TKWF.Extension.Identity）

| 方法 | 用途 | 消费方 |
|---|---|---|
| `JwtDomainUserParser.ParseAndVerify(token)` | **合体验签 + 令牌 → DomainUser&lt;TUserInfo&gt;**（sub→UserIdString；内部强制 Verify，杜绝漏验签——Oracle I5） | 业务系统装配 |
| `ITokenVerifier.Verify(token)` | 共享公钥本地验签 or 远程 introspection（`/verify`） | 业务系统 |
| `IAuthorizationMapper<TUserInfo>.MapRoles(sub, claims)` | sub + 认证声明（含 teacher_verified）→ 本地业务角色（student/owner/parent…）供 IsInRole（Oracle I4） | 各业务系统实现 |

> **调用约束（Oracle I5）**：业务系统**只调用 `ParseAndVerify`**（合并接口），不得只 `Parse` 不 `Verify`——未验签令牌不得进入 DomainUser。`IsInRole` 接管方式（构造预填角色 vs 重写委托 Mapper）在 M3 试点明确（Oracle I5）。

### 5.4 错误码与限频

- 错误结构/七码复用 A01 §1.2 + v0.3 新增 `SERVICE_UNAVAILABLE`(503)/`SMS_SEND_FAILED`(502)（Oracle B1/N2）。
- **新增端点特有错误码**（Oracle N2）：

| code | HTTP | 场景 |
|---|---|---|
| `TICKET_EXPIRED` | 400 | 一次性票据已过期（>5min） |
| `TICKET_CONSUMED` | 400 | 票据已被消费（单次换取） |
| `TICKET_STATE_MISMATCH` | 400 | state 校验失败（CSRF） |
| `CODE_NOT_FOUND` | 404 | 口令不存在 |
| `CODE_REDEEMED` | 400 | 口令已兑换（single_use） |
| `CODE_EXPIRED` | 400 | 口令已过期（未兑换前超时） |
| `CODE_REVOKED` | 403 | 口令已吊销 |
| `CODE_BOUND_MISMATCH` | 403 | 绑定限定不匹配（教师口令绑 openid，非本人兑换） |
| `CODE_TARGET_MISMATCH` | 400 | 口令 target_app_id 与应用不符 |
| `FAMILY_CODE_INVALID` | 400 | 家庭码不存在/错误 |

- **限频**（Oracle N3 补全）：短信 60s/小时/天/IP；口令兑换失败 5 次/小时/账号 429；`/oauth/authorize` 10 次/分钟/IP；`/oauth/exchange` 每票据单次消费（天然限频）；公众号口令下发按 openid 日限频（§3.4b）。

## 8. 安全设计

| 项 | 设计 |
|---|---|
| fail-fast 三件套 | `AUTH_JWT_SECRET` 缺失/默认 → 拒绝启动；Production + Mock → 认证端点 503；demo 口令 seed 清空 |
| **回调票据铁律（用户裁定 + 强化）** | URL 任何 token/code/票据 **必须一次性（TTL + 单次消费）+ 不携带敏感信息**；**换令牌路径**：有服务端子应用走内网/trust 域接口换取；**纯前端静态站（教育小程序）走公网接口 + PKCE code_verifier + 票据绑 app_id/redirect_uri 白名单**（Oracle B1）——令牌不经 URL/浏览器，复制扩散无风险 |
| **认证中心故障降级（Oracle I3）** | 在线业务：令牌本地验签兜底（`ITokenVerifier` 共享公钥验签不依赖认证中心在线）+ 授权快照短时缓存（`/grants` 不可达时用缓存，过期强制重取）；离线开课不受影响（激活码并存） |
| **管理端数据隔离（Oracle I3）** | §5.2b 管理端点按 `app_id` 权限隔离：某业务系统的运营/分销商仅能操作本 `app_id` 的口令/兑换/吊销，不能波及其它业务系统的授权数据（GrantRecord 靠 app_id 域隔离 + 管理端鉴权双重约束） |
| 令牌最小化 | JWT 只含 `sub` + 认证声明 + 过期，**不含业务角色/业务数据**（降低令牌泄露连带面） |
| 口令防爆破 | 高熵 + 散列 + 兑换频控 + single_use；campaign 限 scope/期限 + openid 日限频 |
| 微信安全 | AppSecret 仅服务端；登录 state/票据 vs 绑定 bind_token 隔离（防劫持）；access_token 不缓存 |
| 账号合并防劫持 | 手机号主键；合并需短信 + 原登录态双验证；unionid 归并仅微信侧凭证验证后 |
| 用户中心防护 | 公共档案仅本人令牌可读；使用情况聚合不含学习明细（儿童数据红线） |
| 浏览器态 | JWT localStorage XSS 面 → 短会话 + 敏感操作二次验证；桃李助手壳 7d 例外 |
| 域名/IPC | auth.loongba.cn ICP 备案 + DNS 灰云直连 + Caddy 自动 HTTPS + 限频 |

| TKWF.Extension 通用化跨仓库协作（TKWF 生态 vs 本仓库） | 明确分工：Ext 组件在 TKWF 生态立项（含 DMP-Lite AuthCenter 经验吸收）；认证中心实例 + 教育接入在本仓库；令牌契约（sub 内部 id）为两方共同冻结的接口 |
| AuthorityFilter 消费令牌的不确定性（唯一框架侧风险） | Ext.Identity 适配层（JwtDomainUserParser）把令牌变成 DomainUser——AuthorityFilter 零改动；M3 前置验证（接一个业务系统试点） |
| 公众号服务号/认证未就绪 | 认证降级路径：个人订阅号阶段手机号 + 菜单/聊天口令先行；网页授权后置 |
| 业务角色模型多样（小书童 parent/owner/student vs 教育应用） | 令牌不带业务角色；各业务系统 IAuthorizationMapper 本地映射——认证中心不感知角色模型 |
| 统一身份源单一故障点 | 认证中心高可用 + 数据备份 + 部署脚本可迁移；离线场景不受影响（激活码并存） |
| 44 款接入工作量大 | 统一 auth.js 一次改造全部受益；分批接入；离线可用回退 |
| 口令经济（转售/恶意兑换） | 高熵 + single_use + bound + 频控 + 渠道留痕 + campaign 限 scope/期限 |

- **2026-09-30（用户 3 问 + 并行系统 4 问 → v0.5，定位升级 + Oracle 外审修订 v0.6）**：
  - **令牌**：JWT 只带 `sub`（**平台内部 id**，MemberUId 风格）+ 认证声明，**不含业务角色**——「你是谁」由认证中心，「你能干什么」（student/owner/parent 等）由**各应用按 sub 本地映射**（DMP R04 全局映射同构）。

  - **用户中心能力边界**：一个库两个逻辑面（认证面 Token Issuer + 档案面 Profile API/页面），完整 OIDC 非必需；头像 **URL**（string，非二进制，DMP-Lite 实践）；业务角色不进令牌、档案不集中业务特化数据（各系统本地按需增强）。
  - **框架对接（Q4，Oracle 外审确认）**：AuthorityFilter 零改动（已核实源码只消费 DomainUser）——需 `TKWF.Extension.Identity` 适配层（`ParseAndVerify` 合并接口 / `ITokenVerifier` / `IAuthorizationMapper.MapRoles(sub, claims)`，Oracle I1/I4/I5），M3 试点验证。
  - **认证中心定位 = TKWF.Extension 通用化**（吸收 DMP-Lite AuthCenter 经验，用户裁定）：独立装配部署为认证中心实例，各业务系统（教育线/桃李助手/小书童等）消费；LoongEduTools 侧产出 = 认证中心实例 + 教育接入，Ext 通用层在 TKWF 生态立项。
  - **Oracle 外审 v0.5 处置（1B/5I/4N 全采纳）**：B1 静态站换令牌 PKCE；I1 命名统一 `TKWF.Extension.Identity`；I2 DMP-Lite 关系=参考重写不复用代码（会员卡保留原址，未来按需迁移）；I3 故障降级（本地验签兜底 + 授权快照缓存）+ 管理端 app_id 权限隔离；I4 teacher_verified 为身份声明不参与 IsInRole、本地 MapRoles 映射；I5 ParseAndVerify 合并 + M3 验证 IsInRole 接管；N1-N4 确认（令牌最小化/授权快照与业务角色正交/AuthorityFilter 零改动/CSRF·重放防护完备）。
