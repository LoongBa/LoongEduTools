# 双模式骨架 — 开发方案（V0.2）

> 系列/范围：RedTools 教育工具 · 双模式（离线/在线）改造 **A 批试点骨架**
> 依据：`docs/教育工具/教育工具在线版设计要求.md`（v0.2，§4 技术改造要求）
> 状态：**V0.2 已按 oracle 审核意见修订**（2026-09-21；V0.1 → V0.2 修订见 §9 变更记录）
> 定位：本轮**只搭骨架 + 契约**，不做全量工具迁移（B/C 批后续）；试点 = 点读陪练（新结构）+ 数学口算（渐进接入）

## 1. 背景与现状问题

### 1.1 现状

| # | 问题 | 代码位置 |
|---|---|---|
| 1 | 26+ 工具全部平铺 `src/index.html + assets/main.js`，main.js 内含全部逻辑，无分层 | `series/<系列>/<工具>/src/assets/main.js` |
| 2 | 存储/打卡代码**每工具复制一份**（loadStore/saveStore/checkin 各写各的） | 各工具 main.js |
| 3 | 构建仅产出离线 zip，无 `--mode offline|online`，无内容切分（free_units） | `build_framework.py` |
| 4 | `RedTools/_shared/` 未建，无公共模块承载位 | — |
| 5 | 在线认证/云端存储无代码预留（设计要求书 §4.6 契约未落地） | — |

### 1.2 同构性实测（progress.js 抽取前提，已核验）

- **`calcStreak(dates)` 签名在 40+ 工具中完全同构**（数学口算/24点/乘法口诀/舒尔特/数独/成语/益智全系/经典游戏系……）；
- **checkin 模式同构**：`store.checkin = { dates: [], streak: 0 }` + 完成即点亮今日 + FIFO 截断 365；
- **store 顶层字段同构**：`{ version: 1, checkin, ...(工具特有) }`，STORE_KEY = `redtools.<tool>.v1`；
- → **progress.js/storage.js 抽取可行**，且 STORE_KEY 兼容已发布工具的本地数据。

### 1.3 目标（本轮 A 批骨架）

1. 建 `RedTools/_shared/js/` 公共模块（`window.LX_SHARED` 命名空间），**先定契约 + 离线实现**；
2. 建 `build_framework.py` 双模式构建：`--mode offline|online`，注入内容子集/全量 + 适配层；
3. 点读陪练按新 `src/core/ + src/adapters/` 结构落地（试点新结构）；
4. 数学口算**最小侵入**接入 `_shared/js`（只替换 loadStore/saveStore/checkin 为公共模块调用，不改核心玩法）；
5. 在线验证接口契约（设计要求书 §4.6）以 `_shared/js/auth.js` 桩形式预留。

### 1.4 非目标（红线）

- 不改动任何工具的核心玩法/判定规则（设计要求书 §二红线）；
- 不迁移全部工具（B/C 批）；
- 不接入真实服务器（认证桩 + localStorage 云端模拟）。

## 2. 目标架构

### 2.1 目录总览（新增/变更）

```
RedTools/
├── _shared/js/                    # ★ 新增：公共模块（IIFE + window.LX_SHARED 命名空间）
│   └── lx-shared.js               #   ★ 单文件合并产物（构建时把 auth/storage/progress/guard/ui-kit 合并进此文件）
│   └── src/                       #   模块源（构建合并 → lx-shared.js）
│       ├── auth.js                #     认证客户端契约（桩）
│       ├── storage.js             #     存储适配（schema-agnostic 透传）
│       ├── progress.js            #     打卡/连胜/历史
│       ├── guard.js               #     防沉迷/自控力
│       └── ui-kit.js              #     通用组件
├── build_framework.py             # ★ 变更：--mode offline|online + free_units 切分 + 适配层注入 + core/adapters 复制
├── tools.py                       # ★ 变更：ToolConfig 增 modes/free_units/shared_js 字段
└── series/<工具>/src/
    ├── index.html                 #   外壳（模式无关，脚本注入由构建决定）
    ├── core/                      #   ★ 新工具：核心逻辑（双模式共用）
    │   ├── main.js
    │   └── generators.js
    └── adapters/                  #   ★ 新工具：适配层（构建按模式注入）
        ├── content.js
        ├── storage.js
        └── auth.js
```

**存量工具接入形态（最小侵入，不搬 core）**：
- 存量工具**不引入 `core/` 目录**；只在 `assets/` 旁加 `adapters/storage.js`（可选）+ `index.html` 加一行 `<script src="./_shared/lx-shared.js">`；
- main.js 内部 loadStore/saveStore/checkin 改为调用 `LX_SHARED.storage/progress`；
- 数学口算即此形态（§5.2）。

### 2.2 运行时脚本注入顺序（oracle B 项修订）

```
data.js（构建注入 APP_DATA，含 meta.mode）→ lx-shared.js（读 APP_DATA.meta.mode 设 LX_SHARED.mode）
→ adapters/*.js（可 register 覆盖默认实现）→ core/main.js（消费 APP_DATA + LX_SHARED）
```

- **data.js 必须先于 lx-shared.js**：`LX_SHARED` 的 IIFE 顶层同步读 `APP_DATA.meta.mode` 设置 `LX_SHARED.mode`（data.js 在后会读到 undefined）；
- **core 访问约束（写入契约）**：`core` 必须用 `LX_SHARED.storage.get()` **属性查找**，禁止 `var s = LX_SHARED.storage` 捕获引用（adapters 在 core 前 register 覆盖，捕获会拿到旧引用）；
- `window.LX_SHARED.version = '0.1'`（oracle E 项：运行时调试 + B 批兼容判断）。

### 2.3 APP_DATA 契约（设计要求书 §4.3）

```js
window.APP_DATA = {
  meta: { tool, series, version, mode: 'offline'|'online', free_units, api_version },
  content: [ /* 章节/难度档：offline=前 N 条；online=全量 */ ]
};
```

- 公共模块只读 `APP_DATA.meta`；`content` 结构随工具而异，core 各自消费。

## 3. 公共模块设计（_shared/js/src/ + 合并 lx-shared.js）

> 全部 IIFE + `window.LX_SHARED` 命名空间（ES2017，无 import/export，Chrome 61 兼容）。

### 3.1 命名空间

```js
window.LX_SHARED = {
  version: '0.1',
  mode: 'offline' | 'online',       // 由 data.js（APP_DATA.meta.mode）驱动
  auth: { status(), login(), activate() },
  storage: { get(), set(), remove() },
  progress: { checkin(), streak(), best(), history() },
  guard: { check(), remind() },
  uikit: { btn(), badge(), overlay(), toast() },
  register(name, impl)              // 适配层覆盖默认实现
};
```

### 3.2 storage.js —— **schema-agnostic 透传（oracle C 项阻塞修订）**

```js
// 离线（localStorage）：仅做「前缀 + JSON 透传」，不校验字段、不拒绝任何键
//   get(key)  -> localStorage.getItem('redtools.<tool>.' + key) 解析 JSON
//   set(key)  -> JSON.stringify 写入；remove(key)
//   key 默认 'v1'（兼容现有 STORE_KEY='redtools.<tool>.v1' 的已发布数据）
// 在线（云端桩）：localStorage 同构（接口留 TODO 待接 POST /api/edu/data/sync）
// 数据最小化白名单（设计要求书 §5）只约束【在线 sync 上行路径】：
//   sync 时仅提取 { completedUnits, checkin }，错题/成绩/历史【不】上行云端
//   —— 离线 localStorage 完整保留工具自有字段（wrongBook/history/best 等）
```

> **关键修订**：数据最小化是**云端合规**要求，不下沉到离线 localStorage。数学口算现有 store（profile/wrongBook/history）离线照常存取，仅在线 sync 时过滤上行。

### 3.3 progress.js —— 从 40+ 工具同构逻辑抽取

```js
// checkin(store)   -> 当日去重 + streak（calcStreak 同构签名，见 §1.2 实测）
// streak(dates)    -> calcStreak(dates) 完全同构（40+ 工具一致）
// best(store, key, stars, ms) -> 更高星级或同星级更快则更新
// history(store, item)        -> push + ≤30 FIFO
// 键名：redtools.<tool>.v1 保留（向后兼容）
```

### 3.4 auth.js —— 契约 + 离线/在线桩（设计要求书 §4.6 预留）

```js
// 契约注释：activate/login/reset/status/dataSync/reportQuery 6 接口（设计要求书 §4.6 表）
// 离线：status() 恒 { authorized: true, scope: 'offline', expireAt: null }
// 在线桩：localStorage 存授权状态（模拟服务器响应）；实现 TODO 待接 POST /api/edu/auth/*
```

### 3.5 guard.js —— 防沉迷（沿用 通用需求-防沉迷自控力.md）

```js
// 从 24点/扫雷/贪吃蛇 已实现逻辑抽取：session 累计/到点提醒（延迟×2/自律锁）
// check() -> { limited, minutes, remaining }；remind() -> 弹提醒层（复用 uikit.overlay）
```

### 3.6 ui-kit.js —— 通用组件（首版精简）

```js
// btn(text, cls)/badge(text)/overlay({title, sub, stars, btns})/toast(msg)
// 视觉对齐指导原则 §4.1：打勾/进度条/徽章；无排行榜 UI
// feedback（即时正反馈）内联于各工具 main.js，B 批再抽，A 批不动
```

### 3.7 register() 覆盖机制（oracle B 项约束）

```js
// 构建注入顺序：data.js → lx-shared.js（含默认实现）→ adapters/*.js（在线覆盖）→ core
// adapters/storage.js（在线版）调用 LX_SHARED.register('storage', cloudImpl) 替换默认
// 约束：core 访问 LX_SHARED.* 用属性查找（每次 .get()/.set() 实时取），禁止捕获引用
```

## 4. 构建管线扩展（build_framework.py）

### 4.1 ToolConfig 新增字段（oracle A 项）

```python
@dataclass
class ToolConfig:
    ...
    modes: list[str] = field(default_factory=lambda: ["offline"])  # ["offline","online"]
    free_units: int | None = None   # 离线免费章节数（None=全部）
    shared_js: bool = True          # 是否合并 _shared/js 公共模块
```

- 全部新字段带默认值 → **向后兼容**（现有 26 工具登记不变）。

### 4.2 copy_static 扩展（oracle A 项修订）

```python
def copy_static(cfg, out_dir, mode='offline'):
    # 1) 复制 src/index.html → out_dir/index.html
    # 2) 复制 src/assets/  → out_dir/assets/  （现有）
    # 3) 新：复制 src/core/  → out_dir/core/   （若存在）
    # 4) 新：复制 src/adapters/ → out_dir/adapters/（若存在）
    # 5) 新：若 cfg.shared_js：合并 _shared/js/src/*.js → out_dir/_shared/lx-shared.js
```

### 4.3 build_tool 扩展（--mode）

```python
# build_all.py --tool 点读陪练 --mode online
# 1) copy_static(cfg, out_dir, mode)
# 2) 按模式写 data.js：
#      offline: content = 截取前 free_units 条；meta.mode='offline'
#      online:  content = 全量；meta.mode='online'
# 3) 按模式合并 adapters：
#      offline: adapters/{content,storage,auth}.js 用 src/adapters/offline/ 版
#      online:  用 src/adapters/online/ 版（auth 桩）
# 4) 产物：dist/<tool>/offline/ + dist/<tool>/online/（双目录）
```

### 4.4 产物命名与发布约束（oracle D 项显式化）

```
dist/<工具>/offline/  → <工具>_离线版.zip → publish/<系列>/   # 小红书发布（唯一对外）
dist/<工具>/online/   → 部署目录（不入 zip、不入 publish、不入小红书）
```

> **合规红线（显式）**：在线包产物仅存 dist/ 部署目录，**不发布小红书**（小红书只发离线 zip）。在线包含全量内容 + auth 桩，若外传 zip 可被绕过——桩阶段接受，真实部署走服务器校验（设计要求书 §4.6）。
