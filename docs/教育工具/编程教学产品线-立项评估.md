## 1. 转型依据

- **版号红线**：无标准答案、只有分数/生存时长 = 游戏（指导原则 §二）；国内运营网络游戏须办版号。
- **转型原则**：把「表现性挑战」改为「有标准答案的编程练习」——指令序列有唯一正确解（或程序可判定的最优解），
  从「玩」变为「学编程逻辑」。

## 2. 推迟款 → 编程教学映射表

| 推迟款 | 原玩法（无标准答案） | 编程教学转型（有标准答案） | 判定机制 | 难度 |
|---|---|---|---|---|
| **推箱子** | 推动箱子到目标点（Microban 155 关） | **机器人路径编程**：积木指令（↑↓←→ + 推箱动作）编排序列，执行后箱子到目标（✅ D1 已交付，v1.4） | 求解器验证（已内嵌 BFS 最优解）——指令序列是否使箱子到目标 = 对/错 | 关卡制（155 关即 155 道编程题） |
| 俄罗斯方块 | 下落方块排列消除（无判定点） | **方块排列指令**：给定目标布局，用旋转/移动指令拼出（✅ D3 已交付，v1.0） | 布局比对（程序判定目标布局达成） | 关卡制（目标布局 = 关卡） |
| 反应测速（点击/手速） | 测毫秒/CPS（纯分数） | **循环指令编程**：用「重复 N 次」指令完成点击序列任务 | 任务结果判定（如：用循环让角色走 N 步到终点） | 概念关卡（顺序/循环/条件） |
| 2048 | 合并数字（生存式分数） | **合并策略编程**：指令序列（方向键）使合并达成目标值 | 最终盘面判定（达到目标数字 = 对） | 关卡制 |
| 贪吃蛇/蜡笔物理 | 生存/物理模拟 | （转型价值低，不推荐——指令语义不天然） | — | — |

> **首选推箱子**（路径指令语义最天然 + 关卡/求解器资产已内嵌，转型成本最低）。

## 3. 原型设计：「机器人走迷宫」路径编程练习

**定位**：编程教学线第一款（对标 Scratch 启蒙的「指令序列」阶段，但纯离线 zip + 有标准答案）。

### 3.1 玩法

- 盘面：网格迷宫（复用推箱子关卡数据格式，'#'墙 / 'o'空 / '$'箱子 / '.'目标 / '@'机器人）；
- 指令区：积木指令条（↑ 前进 / ← 左转 / → 右转 / 🧲 推箱）+ 「▶ 执行」按钮 + 「↺ 清空」；
- 目标：编排指令序列 → 执行 → 机器人按序列移动/推箱 → 箱子全部到目标点 = 答对；
- 判定：**复用推箱子 BFS 求解器**——执行结果盘面与目标盘面对比（对/错）；或比较「我的指令数 vs 最优解步数」给星级。

### 3.2 有标准答案论证（合规关键）

| 判定维度 | 机制 |
|---|---|
| 对/错 | 指令序列执行后的盘面 = 目标盘面（可程序判定，非表现性分数） |
| 星级 | 指令长度 vs 最优解步数（≤1.5× 最优 = 3★，程序可算） |
| 学习反馈 | 执行失败显示「第 N 步撞墙/箱子卡住」定位错误指令（像调试器） |

> 无生存/分数/时间竞争——纯「编排-执行-验证」循环，是编程练习不是游戏。

### 3.3 资产复用

- **关卡数据**：`推箱子/src/assets/levels.js`（Microban 155 关，155 道编程题）；
- **求解器**：`推箱子/src/assets/main.js` 内嵌 BFS（最优解步数 = 星级基准）；
- **渲染**：复用推箱子网格渲染（SVG/Canvas）；
- **双模式**：`LX_SHARED.storage`（free_units 语义 = 前 N 关免费）+ offline/online 双包；
- **合规**：UI「练习/指令/执行」用语，无「游戏/关卡胜负」。

### 3.4 原型范围（MVP）

- 前 10 关（Microban 前 10 关，难度平缓）；
- 指令：前进/左转/右转/推箱 + 执行/清空/撤销；
- 判定：目标盘面对比 + 最优解星级；
- 三档难度 = 关卡区段（简单 1-5 / 普通 6-10 / 挑战全 155 开放）。

## 4. 版号合规验证（对照 §五 自查清单）

| 自查项 | 结果 |
|---|---|
| 有标准答案？ | ✅ 目标盘面判定 |
| 无排行榜/名次？ | ✅ 个人纵向（最优解星级） |

| 无内购/广告/抽奖？ | ✅ |
| 数据最小化？ | ✅ 仅关卡进度/星级 |
| 离线纯静态？ | ✅ |

> **结论**：原型满足全部自查项，可安全立项。
