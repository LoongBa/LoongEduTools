## 2. 玩法设计

### 2.1 规则

- 经典数独：盘面 N×N（数字 1~N），目标让**每行 / 每列 / 每宫（粗线框）都只出现一次 1~N**。
- 每局盘面由算法**运行时随机生成**（回溯终盘 + 挖洞保证唯一解），孩子不会背答案、不会背题面。
- 交互：**点空格 → 底部数字条点数字填入**（一排按钮，非屏幕九宫格，低龄友好）。
- 全部填满且无冲突即过关；填错不意味着游戏失败，可随时擦掉或撤销重来。

### 2.2 操作

| 输入 | 说明 |
|---|---|
| 点空格 | 选中该格（橙色描边 + 同行/列/宫浅蓝 tint + 同数字浅橙 tint 教具高亮）；点同一格取消选中 |
| 数字条 1~N | 有选中**用户格** → 填数判定；无选中 → 提示「先点一个空格子，再选数字哦」；选中**已知格** → 提示「这是题目给的格子，不用填」；**铅笔模式**下 → 切换候选笔记 |
| ✏ 笔记（v1.1） | 切换铅笔/落子模式；铅笔下点数字在空格记/取消候选，行/列/宫已有该数拒绝并温和提示 |
| 橡皮 | 清空选中格（值 + 候选笔记；仅用户格可擦；已知格提示"不能擦"）；入撤销栈 |
| 撤销 | 恢复上一步（数字/橡皮/提示/笔记均入栈，可连续撤销） |
| 提示 | 自动找候选最少的空格、填上正确解 + 同步自动铅笔清理；入撤销栈；**用提示星级封顶 2★** |
| 实体键盘 | 游戏页响应：1-9 填数/记笔记（≤N 生效）、Backspace/Delete 擦除选中格 |
| 底栏按钮 | 「返回难度」回难度页；「重新开始」同难度重抽一局 |

### 2.3 反馈

- **合法落子**：绿色确认（`okFlash 300ms`，`color #12b76a`）+ 轻音效；**答错不惩罚**——填入的数字只要当前行/列/宫不冲突即接受（即使与终盘解不同也不计错、不提示）。
- **冲突（行/列/宫已有该数）**：红闪（`wrongFlash 400ms`，`#fff1ef → #ffc2ba → 白`）+ 错误计数 +1 + 温和提示「行 / 列 / 宫里已经有这个数啦，换一个试试」（橙色 warn）；**不改变盘面**。
- **教具高亮**（选中态同时呈现三种信息，帮孩子"看懂"数独约束）：
  - 选中格：`#fff3e0` 浅橙底 + `outline 3px #ff9f43` 橙色描边；
  - 同行/列/宫格（peer）：`#ecf5ff` 浅蓝 tint；
  - 同数字格（same）：`#ffedd1` 浅橙 tint。
- **已知格**：浅灰底 `#f2f6fa` + 深色字（不可编辑）；用户格：天蓝字 `#4aa8ff`。
- **音效**（Web Audio `OscillatorNode` 合成，零音频文件）：点选（520Hz 0.05s triangle）/ 填对（660→990 双音）/ 冲突（165Hz 0.16s square 低沉）/ 胜利（523/659/784/1047 上行琶音，同分类整理/迷宫寻路）。首次用户手势创建 `AudioContext`，播放异常静默降级。

### 2.4 规则教学（v1.3）

**设计来源**：《数独小侦探_开发方案》§5 教学体系第一层（规则教学三步）+ 数独侦探简化落地原则（无语音、纯数字、零素材）。

- **入口**：难度选择页「📖 规则教学」按钮（虚线描边卡片，副标题「3 步看懂：行 · 列 · 宫不重复」），点击打开教学弹窗。
- **演示盘**：固定 4×4 盘面 `TEACH_BOARD = [1,0,3,4, 3,4,0,2, 2,1,4,3, 4,3,2,1]`（唯一解验证通过：空格 (0,1)=2、(1,2)=1，宫界 2×2 与三档难度同色 `#9db4c8`）。
- **三步讲解 `TEACH_STEPS`**（文案面向儿童，去语音改文字+音效）：

| 步 | 标题 | 讲解要点 | 高亮格 |
|---|---|---|---|
| 1 | 每一行 | 每行里数字 1-4 只能出现一次，看这一行缺哪个 | 首行 [0,1,2,3] |
| 2 | 每一列 | 每列里也只能出现一次 | 第 2 列 [1,5,9,13] |
| 3 | 每个宫 | 每个粗线小方格（宫）里也只能出现一次 | 左上宫 [0,1,4,5] |
| 4 | 开动小脑瓜 | 找到缺的数字填进去，全部填对就过关；「开始挑战」 | 无 |

- **交互**：上一步/下一步/跳过；末步按钮变「开始挑战」（关闭弹窗回难度页）；空格显示 `?` 提示「缺谁」，高亮格浅蓝底 `#ecf5ff` + 主色 inset 描边 `2px #4aa8ff`；翻页播放点选音效。
- **实现**：复用结算浮层 `.overlay`/`.overlay-card` 机制（openTeach 构造 overlay 挂 `overlayEl`，关闭走 `hideOverlay`）；纯 DOM 动态渲染（无模板字符串）；solver.js 零改动。

### 2.5 技巧教学关（v1.4/v1.5）

**设计来源**：《数独小侦探_开发方案》§5 教学体系第二层（技巧教学关）落地——v1.4 单宫排除 → v1.5 行列排除 + 区块排除 → **v1.8 交叉排除**（L4 收尾，四技巧全齐，对齐「每技巧 1 个教学关 + 技巧徽章」；v1.5 曾以锁定占位卡存在）。

- **技巧数据 `SKILLS`**（内嵌 main.js，独立于普通局生成）：
  - **单宫排除（v1.4）**：盘面 4×4 `[1,0,3,4, 3,4,0,2, 2,1,4,3, 4,3,2,1]`（唯一解已验证：空格 (0,1)=2、宫0 已有 1,3,4 缺 2；(1,2)=1、宫1 已有 3,4,2 缺 1）+ 两步引导 `steps`（讲解文字 + 目标格 `cell` + 目标数字 `num` + 高亮约束组 `hl`）+ 完成语 `done`。
  - **行列排除（v1.5）**：盘面 `[1,2,0,4, 3,4,1,0, 2,1,4,3, 4,3,2,1]`——第一步行排除（第 1 行有 1,2,4 缺 3，`hl` 整行 4 格）、第二步列排除（第 4 列有 1,3,4 缺 2，`hl` 整列 4 格）；唯一解已验证。
  - **区块排除（v1.5）**：盘面 `[2,3,0,1, 4,1,2,0, 1,4,3,2, 3,2,1,4]`——第一步「宫缺 3、4，右边格的竖列已有 4 → 4 只能放这格」、第二步「宫只剩 3」；唯一解已验证。
  - **交叉排除（v1.8，L4）**：盘面 `[0,2,3,0, 3,4,0,0, 2,1,4,3, 0,0,2,1]`——**行/列/宫三源交集**判定（对齐开发方案 §3.3「候选数唯一且由行/列/宫联合约束」）：(0,3)=4（行缺{1,4}∩列缺{2,4}∩宫缺{1,2,4}={4}）、(1,3)=2（{1,2}∩{2,4}∩{1,2,4}={2}）；`hl` = 行+列交叉 7 格（重叠 1 格）；唯一解已验证（全部 6 空均被单元交集唯一确定）。
- **入口**：难度页技巧教学卡循环渲染 `SKILLS`（四技巧全渲染，无锁定卡），未点亮 `🎯 <技巧名>技巧`、已点亮 `✅ <技巧名>技巧 · 已点亮徽章 · 可再练一次`；另设「🏆 技巧徽章墙」入口卡。
- **教学关视图**：独立渲染（`renderSkillView`）——顶栏「← 返回 + 🎯 技巧名 + 教学关·不计入进度」、棋盘（复用 `.cell`/`.board-card`/宫线 box-t/box-l）、引导文字行 `#skill-msg`、数字条 1..N；**不渲染**普通局工具条/计时/错误计数（教学关零压力）。
- **高亮渲染（v1.5 修复 v1.4 遗留）**：`refreshSkillCells` 改为**两层分离**（与普通局同构）——宫界线 box-t/box-l 与目标格 `target` 蓝色描边画在外层 `.cell`，已知格 `given` 浅灰底 / 高亮 `peer` 浅蓝底 / 选中 `selected` 橙框画在内层 `.cell-inner`；v1.4 曾把状态类全设在外层 `.cell` 导致 peer/given/selected 样式落空（宫高亮不可见），已修复并补计算样式验证。目标格选中时不叠加 `selected`（避免橙蓝双框）。
- **引导交互**：
  - 目标宫格 `peer` 浅蓝高亮（行/列/宫均可表达，由 `steps[].hl` 指定）；选中目标格时 `target` 加强（inset 3px 主色描边）；
  - 点目标格 + 点正确数字 → 落子（天蓝 `skill-num`）+ **先推进步进再刷新高亮**（v1.5 修复：v1.4 刷新在高亮停留在上一步约束组，行→列切换时可见）+ 完成时点亮徽章 `store.skills[key] = true` + 结算浮层「🎉 学会啦！徽章已点亮」+ 胜利音效；
  - 点错/点非目标格 → 温和提示「看高亮的地方：已经有哪几个数？缺的就是答案哦」（v1.5 起通用表述，不再写死"这个宫"），**不计错误、不改变盘面**；
  - 已知格点击提示「题目给的格子，不用填」。
- **独立标记**：教学关不写 `store.best/recent/history/checkin/cur`（不计普通进度、不影响星级、不打卡）；可随时返回（← 返回）跳过；完成后可重练。
- **返回路由**：`openSkill(k, from)` 记录 `badgeFrom`（'difficulty'/'badgewall'），`exitSkill` 按来源返回难度页或徽章墙。
- **持久化**：`store.skills`（defaultStore 新增 + loadStore 补全），结构 `{ boxElim: true, rowColElim: true, blockElim: true, ... }`——新增 key 零迁移成本。
- **实现**：纯 DOM 渲染（复用 colPct/cellFont/宫线逻辑），`state.playing=false` 保证实体键盘不误触发；solver.js 零改动。

### 2.7 错题本 / 收藏本（v1.6）

- **错题定义**：冲突填数（错误计数 +1）与使用提示（没独立看出）均为"错题"——对局内分别收集 `state.errLog`（错格 `{idx, wrong}`）与 `state.hintIdx`；教学关永不记录。
- **记录时机**：通关（`onWin` → `commitMistake('win')`）或中途退出（`backToDifficulty`，仅已有错时）提交 `store.mistakes`；无原始盘面（v1.6 前旧断局快照）不追踪（`state.origPuzzle` 缺失即跳过）。
- **数据**（上限 50 条 FIFO，同盘面去重保留最新）：`{ id, ts, level, board(原题), solution, errors:[{idx,wrong}], hintIdx:[], result:'win'|'quit', stars }`；通关 0 错 0 提示的重练（掌握）→ 自动消除同盘面旧记录（掌握即清）。
- **收藏本**：结算浮层「⭐ 收藏这局」toggle（`store.favorites`，同构去重）；手动加入/移除/清空。
- **视图**：难度页「📕 错题本」（有记录才显示 + 条数）/「⭐ 收藏本」（常驻）；列表卡（迷你盘缩略 + 难度 + 错/提示计数 + 时间 + ▶重练 / 🗑移除 / 清空二次确认）；错题重练（`replayRecord`）用原盘面/原难度开局，错格以浅红 `replay-mark` 标注 + 提示行「本局来自错题本」；重练与普通局同等计成绩/打卡。
- **持久化**：`defaultStore` 新增 `mistakes: []`、`favorites: []` + `loadStore` 守卫补全；`saveCur` 快照补 `origPuzzle`（旧快照缺失不追踪）；store.version 不 bump。

### 2.8 提示带讲解（v1.6）

- **升级动机**（对齐开发方案 §5 题面引导 v2）：原提示只给答案不讲理由；现先说明约束来源再落子。
- **判因**（纯函数 `explainHint(N, puzzle, solution, r, c)`）：按行 → 列 → 宫顺序，找「单元内已填 N-1 个不同数且恰缺该格解」的一处 → 返回 `{kind, i, hl(单元格数组), have(已有数), miss(缺的数)}`；找不到（盘面中期）退化旧文案 `提示：第 r 行第 c 列 填数字 v`。
- **交互**：点击「提示」→ 同步落子 + 讲解文案 `提示：看第 X 行/第 X 列/这个宫：已经有 a、b、c，缺 d——这格只能填 d` + 约束来源单元高亮（`state.hintExpl.hl` → 复用 `.cell-inner.peer` 浅蓝，3s 后自动清除，下次用户操作亦清除）+ `state.hintIdx` 记录 + 自动铅笔同步。
- **限流**（按难度档）：4×4 不限 / 6×6 每局 ≤3 / 9×9 每局 ≤2；`checkHintBtn` 到限置灰，文案「提示次数用完了」。
- **实现**：纯函数 + 高亮复用教具 class；solver.js 零改动。

### 2.9 分享题 / 导入（v1.7）

对齐《数独侦探_迭代设计_v1.6》§6.1/6.2（二维码 §6.3 延期，随微信版评估）。

- **导出文本**（结算浮层「📤 分享这题」→ 弹层段 A）：`数独侦探 · {N}×{N} · 已知 {n} 格\nSD{N}:{board 用 , 连接（空格=0）}\n（空格填 0；复制后在数独侦探「📥 导入题目」粘贴）`；「复制题目」= 隐藏选中 textarea + `execCommand('copy')` + toast 兜底（复用贪吃蛇 share 模式）。

### 3.2 出题引擎（solver.js，`window.SUDOKU`）

纯算法模块（无 DOM），**运行时程序化出题，零题库**；与学科 24 点同思路（24 点=表达式穷举；数独=回溯终盘+挖洞唯一解）：

```
genPuzzle(N, givens):
  fillBoard(N)                    # 随机回溯完整终盘（每格 1..N 洗牌后尝试）
  loop 最多 4 轮迭代挖洞：
    positions = 全部格下标洗牌
    while 当前已知格数 filled > givens:
      逐格尝试 puzzle[pos]=0
      solveCount(puzzle, N, 2) === 1  → 接受该洞（filled--）
      否则 → 回填恢复
      一轮无进展 → break，换一张新终盘重试
    filled <= givens+4 → 返回 { puzzle, solution, givensCount }
  兜底：最后一次终盘单轮挖洞直接返回（仍保证唯一解）
```

| 方法 | 职责 |
|---|---|
| `boxDims(N)` | 宫尺寸：4→[2,2]、6→[2,3]、9→[3,3] |
| `cellValid(board,N,r,c,v)` | 行/列/宫冲突判定 |
| `fillBoard(N)` | **随机回溯完整终盘**（每格候选 1..N 洗牌，保证每次布局不同） |
| `solveCount(board,N,limit)` | 解计数（数到 limit 即止）；**唯一解校验用 limit=2** |
| `genPuzzle(N,givens)` | **挖洞唯一解生成**：多轮逼近目标已知格 + 兜底，返回 `{puzzle, solution, givensCount}` |
| `getCandidates` | 当前盘面某格可合法填写的数字列表（升序） |
| `findHintCell` | 找候选最少的空格（提示选格） |

- **唯一解保证**：每次挖洞都用 `solveCount(...,2) === 1` 校验，挖出来的每局都是"只有一个正确答案"的完整题目。
- **性能实测**（node `test_sudoku.js`，门槛 9×9 genPuzzle <1.5s）：**9×9 genPuzzle 平均约 5ms、fillBoard 单次约 0ms**，出题瞬间完成，无等待感。
- **移植来源**：`数独小侦探原型/logic_test.js`（原型自身已断言唯一解/已知格范围/解合法性）；语法降级为 **ES2017**（var + function，去除解构 / spread / `Array.prototype.fill` / 箭头函数）。
- 前端模块加载顺序：`data.js`（构建生成 meta）→ `solver.js` → `main.js`（运行期引用 `window.SUDOKU`；缺失时显示「算法模块缺失，请检查 solver.js」）。

## 4. 交互与判定

- **选中态**：`selected` 记住当前格下标（-1 = 无）；`innerClass(i)` 依次叠加 `given`（已知格）/ `user`（用户格）/ `selected` / `peer`（同行列宫）/ `same`（同数字）五个 class。
- **填数判定 `onNumTap(v)`**：取胜状态忽略 → 无选中提示 → 已知格拦截 → 与当前值相同静默返回 → **先清空自身再判冲突**（`cellValid` 含自身所在行/列/宫，必须先置 0）：
  - **合法** → 接受新值（答错不惩罚）+ 撤销栈记录原值 + 绿闪 + `checkWin()`；
  - **冲突** → 恢复原值不动盘面 + 错误 +1 + 红闪 400ms + 温和提示。
- **撤销栈**：`undoStack` push `{i, val, pen}`（填数记录原值+原笔记、橡皮记录原值+原笔记、提示记录 0+原笔记、铅笔记笔记记录全量笔记快照），**上限 200 条**（超出 shift 最旧）；撤销恢复该格原值与笔记。
- **候选笔记（铅笔模式，v1.1 新增）**：工具条「✏ 笔记」按钮切换铅笔/落子模式（启用时按钮高亮，提示行说明）。
  - 铅笔模式下点数字 → 在选中空格**切换候选笔记**（`state.pencils[i]` 升序数组，每个数字一个 `.note-slot.on` 小格渲染）；
  - 手动笔记**冲突校验**：若该数字在行/列/宫已存在 → 拒绝并温和提示（红闪），任何情况下不允许保留错误候选；
  - **自动铅笔同步**：普通模式或提示落定某数后，`erasePenInUnit(i,v)` 自动清除同行/列/宫其余格的该候选数；橡皮同时清值与笔记。
  - 笔记不计入提示次数与错误计数，不影响星级；`solver.js` 的 `getCandidates` 为数据基础，无需改动。
- **断局恢复（v1.2 新增）**：对局快照 `store.cur` 在**每步操作后自动保存**（填数/橡皮/撤销/提示/笔记切换/铅笔模式切换；`saveCur()` 冻结累计 `state.ms` + `startStamp` 落盘）。
  - 难度选择页有快照时显示「▶ 继续上次」入口（含已玩秒/已填格数/错/提示统计）；
  - `restoreCur()` 回填全部 state（盘面/候选笔记/撤销栈/提示/错误/选中格/铅笔模式），`startTimer` 以累计值为基线**续算计时**；
  - 通关（`onWin`）/重开（`newRound`）清除快照；`saveCur` 带 `won` 守卫防止通关瞬间回写快照覆盖清除。
- **智能提示 `pickHintCell`**：遍历所有空格，候选越少越优先，填该格**正确解**（`solution[i]`，保证提示内容绝对正确）；但**跳过「正确解当前不可放」的被堵格**（格子的正确解不在当前候选里 = 该格被填错的数堵死）；全部被堵则建议「有格子被填错了，先用橡皮擦掉，再试试提示」。提示消息：「提示：第 r 行第 c 列 填数字 v」；提示落定后同步触发自动铅笔清理。
- **通关 `checkWin`**：全部填满后做**防御性校验**（逐格剔除自身再验 `cellValid`，合法落子规则下必然成立）才结算；提示按钮在盘面无空格时禁用。

## 5. 星级与最佳成绩判定

- **星级 `calcStars(hints, errors)`**（双指标，提示与错误均影响）：

| 条件 | 星级 |
|---|---|
| 提示 0 次 **且** 错误 0 次 | ★★★ |
| 提示 ≤1 次 **且** 错误 ≤3 次 | ★★ |
| 其余（过关即有） | ★ |

  - 用过提示星级**封顶 2★**；错误 >3 次封顶 1★。
- **最佳判定 `betterThan(A, B)`**：**星级高优先，同星级比用时短**；仅当严格更优才覆盖 `store.best[key]`。
- **最近**：`store.recent[key]` 无条件覆盖为本局用时；**历史**：`history` 无条件 push 后滚动保留最近 30 条。
- 结算浮层展示：星级 + 「用时 X 秒 · 错误 N 次 · 提示 N 次」+ 新纪录徽标 + 打卡 + 三按钮（再来一局 / 选难度 / 打卡日历）。
