## 3. 错题本（v1.6 · P0）

### 3.1 数据模型

```jsonc
store.mistakes = [            // 上限 50 条，FIFO 滚动；同盘面去重（保留最新）
  {
    "id": "m_<ts>",           // 唯一 id（时间戳）
    "ts": 1760000000000,      // 记录时间（ms）
    "level": "4",             // 难度档（4/6/9）
    "board": [1,0,3,...],     // 盘面（题目，0=空）——重练用
    "solution": [1,2,3,...],  // 终盘（重练判分 + 讲解用）
    "errors": [               // 错格记录（一次冲突填数记一条）
      { "idx": 5, "wrong": 7, "ts": ... }   // 格子下标 / 填错的值 / 时间
    ],
    "hintIdx": [3, 12],       // 使用提示的格子（提示=没独立看出，视为弱错）
    "result": "win" | "quit", // 该局最终：通关 / 中途退出
    "stars": 2                // 通关时的星级（quit 为 -1）
  }
]
```

### 3.2 触发规则（什么算"错题"）

| 事件 | 是否记 | 说明 |
|---|---|---|
| 冲突填数（错误计数 +1） | ✅ 记 | 核心错题：填错的位置 + 正确值 |
| 使用提示（自动填正确值） | ✅ 记 | 提示 = 没独立看出来，属"待复习"格（`hintIdx` 单独标注，可在列表筛选"提示过的格"） |
| 通关 0 错 0 提示 | ❌ 不记 | 无错题 |
| 中途退出 | 若已有错题 ✅ / 全对退出 ❌ | 有错题且未通关 → 保留（重练入口） |
| 教学关 | ❌ 永不记 | 教学关独立标记不计进度（沿用 v1.4 约定） |

### 3.3 去重与上限

- **去重**：同盘面（`board` 序列相等）只保留最新一条——避免连败刷屏；重练后若仍错，更新时间戳。
- **上限**：50 条 FIFO（超限移除最旧）；`loadStore` 守卫补 `mistakes: []`。
- **重练闭环**：点错题 → 以原难度/原盘面进入对局（复用 startGame 的指定盘面路径）→ 通关后若 0 错 0 提示 → 弹「🎉 这道题你已经掌握啦」并从错题本移除（掌握即清，保持列表"未掌握"语义）。

### 3.4 UI 与入口

- 难度页新增「📕 错题本」（`teach-btn` 家族，带角标显示条数，0 条时不显示入口）。
- 列表视图（仿徽章墙 `showBadgeWallView` 模式）：盘面缩略（小棋盘复用渲染）+ 难度 + 错格数/提示数 + 时间；操作：点卡片重练 / 条目内「🗑 移除」/ 底部「清空错题本」（二次确认浮层）。
- 重练对局内：**错题回看提示**——顶部小字「这格上次填错过」标注错格（浅红标记，非错误状态，不计错）。

## 4. 收藏本（v1.6 · P0）

### 4.1 数据模型

```jsonc
store.favorites = [           // 上限 50 条；手动管理
  { "id": "f_<ts>", "ts": ..., "level": "9", "board": [...], "solution": [...] }
]
```

### 4.2 交互

- **加入**：结算浮层新增「⭐ 收藏这局」（通关后；未通关也可收——收藏"想再练的难题"）。已收藏 → 文案变「⭐ 已收藏」。
- **列表**：难度页「⭐ 收藏本」入口 → 列表（缩略 + 难度 + 时间）；点卡片重练；条目「🗑 移除」；底部「清空收藏本」二次确认。
- 与错题本关系：**两本独立**（收藏=主动、错题=被动），同一盘面可同时存在两条；共享 `board` 序列去重互不干扰。

## 5. 提示带讲解（v1.6 · P0）

### 5.1 现状

提示 = `findHintCell` 找候选最少格 → 自动填正确值 + 文案「第 r 行第 c 列只能填 X」——只给答案，不讲理由。

### 5.2 升级机制（对齐开发方案 §5「题面引导 v2」：先高亮约束来源，再落子）

1. **选格**：沿用 `findHintCell`（候选最少）。
2. **判因**：新增纯函数 `explainHint(N, board, solution, idx)` → 对 hint 格，检查行/列/宫三组：各自已有数字集 ∪ 该格候选 → 判定 X 唯一性的**约束来源**：
   - 行缺失集含 X 且 X 不在该行 → 来源 = 行；
   - 列 / 宫同理；
   - 多来源 → 取最先命中的主来源（文案：「看第 r 行 / 第 c 列 / 这个宫」）+ 可列完整缺失集。
3. **交互（实施版：同步落子 + 讲解高亮，非两步动画）**：点击「提示」→ **同步落子** + 讲解文案「提示：看第 r 行/第 c 列/这个宫：已经有 a、b、c，缺 d——这格只能填 d」+ 约束来源单元高亮（`.cell-inner.peer` 浅蓝，**3s 后自动清除，下一次用户操作亦清除**）。实施时评估过"先高亮再落子"的两步动画，为避免 350ms 延迟落子与用户操作/断局快照的竞态，改为同步落子 + 讲解高亮（讲解价值 = 文案 + 高亮同时呈现）；后续若需纯两步引导可再评估。
4. **落子时机**：与教学关一致——讲解后再填，避免"提示即答案"的无效性。
5. **限流**：按难度档限提示次数（对齐开发方案 §2 input 演进）：4×4 不限制 / 6×6 每局 ≤3 / 9×9 每局 ≤2（超限提示按钮置灰 + 文案「先试试自己找」）。

### 5.3 与教学体系呼应

- 提示讲解的文案口径与技巧教学关一致（"缺哪个就填哪个"）；讲解命中的约束来源若对应已学技巧（单宫/行列/区块排除），文案可点技巧名（如「这步用到了你学过的『行列排除』」）——联动徽章墙（v1.5 已存 `store.skills`）。

## 6. 分享题（v1.7 · P1 / 二维码 P2）

### 6.1 题目文本（先行）

- **导出格式**（复制文本）：
  ```
  数独侦探 · 4×4 · 已知 10 格
  SD4:1,0,3,4,3,4,0,2,2,1,4,3,4,3,2,1
  （空格填 0；复制后在数独侦探「📥 导入题目」粘贴）
  ```
- **导入入口**：难度页「📥 导入题目」→ 粘贴文本框 → 校验（长度=N²、值域 0..N、唯一解可解）→ 进入对局（标记「他人分享」）。
- 校验失败温和提示（对齐现有提示文案风格）；导入盘不计入最佳成绩（防刷榜，本地工具则防误记）。

### 6.2 题目图片（打印友好，P1）

- Canvas 绘制：黑白 + 大格（A4 打印友好）+ 标题「数独侦探 · 第 N 题」+ 题面（空答案）；**不渲染答案**（学生版）。
- 可选「答案版」切换（家长判分用）。
- 弹层「长按保存图片 / 打印」，复用贪吃蛇 share 弹层模式。

### 6.3 二维码（P2 · 需决策）

- **现状约束**：零依赖、Chrome 61、离线——仓库无现成 QR 实现；需内嵌纯 JS QR 编码器（约 4–8KB，ES2017 可用）。
- **决策点**：① 内嵌编码器（内容=6.1 紧凑格式，扫码→微信识别→文本→导入）；② 或暂缓，先文本+图片。
- **建议**：v1.7 先文本+图片交付；二维码随「微信版增强」一期评估（二维码的消费场景在微信生态，离线 zip 场景价值低）。

- 弹层「📸 长按保存图片 · 分享到小红书/朋友圈」。

### 7.2 文字分享（先图片+文字，微信版增强二期）

```
🎉 我在「数独侦探」挑战 9×9 困难成功！
⭐⭐⭐ 3 星 · 用时 8分32秒 · 0 错 0 提示
```

## 10. 约束与风险

| 风险 | 等级 | 对策 |
|---|---|---|
| QR 编码器依赖/体积 | 中 | 分期：v1.7 文本+图片；二维码随微信版评估（§6.3） |
| localStorage 体积（图片不走库） | 低 | 只存 JSON 记录；canvas 即时生成不落库；上限 50 条 |
| execCommand('copy') 兼容 | 低 | 已有兜底路径（贪吃蛇验证过 Chrome 61） |
| 错题记录隐私（儿童数据最小化） | 低 | 纯本地不联网；无账号无上报 |
| 提示讲解与"自己思考"矛盾 | 中 | 限流 + 讲解先行（先看到原因，再落子），不直接给答案前先引导 |
| 导入盘刷最佳成绩 | 低 | 导入盘不计入 best/checkin（标记来源） |
| 无竞技原则 | 低 | 分享只写自身成绩，无对比无排行（§7.2 红线） |
