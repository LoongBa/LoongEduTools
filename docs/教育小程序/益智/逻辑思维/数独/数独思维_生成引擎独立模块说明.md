| 项 | 事实 |

## §2 API 契约

**盘面约定**：扁平 `number[N*N]` 数组、行优先 `index = r*N + c`、`0` = 空格。

| 方法 | 签名 | 返回 | 源码行 |
|---|---|---|---|
| boxDims | (N) | [宫行,宫列]：4→[2,2]、6→[2,3]、其余→[3,3]（静默默认，无校验） | L30 |
| cellValid | (board,N,r,c,v) | boolean 行/列/宫冲突判定 | L37 |
| fillBoard | (N) | number[N*N] 随机回溯完整终盘 | L58 |
| solveCount | (board,N,limit) | number：0 无解/1 唯一解/≥limit 至少 limit 个解 | L85 |
| genPuzzle | (N,givens) | {puzzle, solution, givensCount} | L109 |
| getCandidates | (board,N,r,c) | number[] 升序合法候选 | L161 |
| findHintCell | (board,N) | {r,c,cands} 或 null（盘满） | L171 |

**行为契约（必须写明）**：

| 契约 | 说明 |
|------|------|
| `cellValid` 假定目标格为空 | main.js L1799 注释原话；main.js L1036-1037 调用前先置 0（`b[idx] = 0` 再判）。**传入已有值会得到错误结果** |
| `genPuzzle` 已知格范围 | 实际已知格 ∈ **[givens, givens+4]**（非精确）；4 轮尝试 + 兜底单趟 |
| `genPuzzle` 唯一解保证 | **始终保证唯一解**——每洞 `solveCount(_, N, 2) === 1` 校验 |
| `solveCount` limit 早退 | 有 limit 早退上限；**唯一解判定传 `limit=2`**（main.js L1866 即此用法） |
| `findHintCell` 短路 | cands.length===1 时短路返回（L183）；盘满返回 null |
| 随机不可控性 | **无种子/PRNG 参数**——全部随机经 `Math.random`；确定性生成靠外部种子注入（见 §3） |
| 内部未导出 | `randInt`、`shuffle`（IIFE 内部，不暴露） |

### 3.2 一次性捕获 + 缺失兜底

- main.js L50：`var SUDOKU = window.SUDOKU || null;`（IIFE 初始化**一次性捕获**）。
- 缺失兜底：main.js **L2467-2469**（`startGame`）/ **L2500-2502**（`resumeGame`）→ `viewEl.textContent = '算法模块缺失，请检查 solver.js'`。

### 3.3 调用点 15 处

| 方法 | 次数 | 调用点（main.js） |
|------|:---:|-------------------|
| boxDims | ×8 | L434 同宫判定 / L659 宫边框 / L912 提示讲解 / L1916 分享卡网格 / L2318 渲染 / L2780-2781 教学关 / L2824 教学盘 |
| cellValid | ×3 | L825 落子合法 / L1038 通关防御校验 / L1811 导入题解算 |
| genPuzzle | ×2 | L2429 / L2432 `newRound` 有/无种子 |
| solveCount | ×1 | L1866 导入唯一解校验 |
| getCandidates | ×1 | L895 `pickHintCell` |
| **fillBoard** | **×0** | 仅 `genPuzzle` 内部用 |
| **findHintCell** | **×0** | 被 main.js 自研 `pickHintCell`（L887）取代——因需额外过滤「正确解当前仍可放」（L897 `cands.indexOf(sv) === -1` continue），`findHintCell` 缺此过滤 |

### 3.4 种子注入模式（同题机制核心）

代码级引用 main.js **L2424-2433**：

```js
var origRandom = Math.random;
Math.random = mulberry32(seed);
try { g = SUDOKU.genPuzzle(lv.N, lv.givens); }
finally { Math.random = origRandom; }
```

这就是 **v1.12 每日挑战（当日 YYYYMMDD 种子同题）** 与 **v1.13 闯关地图（每关固定 seedBase 同题）** 在 solver.js 零改动下实现的机制。**任何消费方要确定性出题必须采用此模式**：

1. 保存 `Math.random` 原引用
2. 替换为种子 PRNG（`mulberry32(seed)`）
3. `try ... finally` 包裹 `SUDOKU.genPuzzle` 调用，保证复原（防异常泄漏污染全局）

### 3.5 唯一重复点说明

main.js L1798-1821 本地 `solveBoard(board, N)` 重实现回溯（因 `solveCount` 只返回计数不返回解），但**合法性仍委托 `SUDOKU.cellValid`（L1811）**——是**借用原语而非复制逻辑**；解路径复用 solver 的尝试顺序（先 `cellValid` 后落子，L1799 注释）。

## §6 迁移指南（三路径 + 步骤）

### 6.1 三条路径（按摩擦递增）

| 路径 | 操作 | 适用 | 摩擦 |
|------|------|------|:---:|
| **1 原地标记可复用（现态，推荐）** | solver.js 留在工具内，本文档声明独立契约；未来同类逻辑游戏（华容道/推箱子等）直接复制引用 | 当前 | 低 |
| **2 系列级共享** | 迁至 `series/益智/逻辑思维/_shared/solver.js`（对齐 `_shared/成语词库/` 先例），需 build_framework.py 扩展接线 | 逻辑思维子系列出现第 2 个消费方时 | 中 |
| **3 仓库级共享** | 进 `RedTools/_shared/js/src/` + 扩展 `merge_shared_js` 顺序列表（build_framework.py **L810**） | 跨 ≥2 工具系列消费 | 高 |

> 路径 1 先例表述模板（对齐打字背单词-设计文档风格）：**「独立可复用，未来其他 XX 类工具可直接引用」**。

### 6.2 复制迁移步骤（任一路径通用）

1. **复制文件**：`solver.js` → 目标共享位置
2. **引入**：index.html 在业务脚本前加 `<script src>`
3. **捕获 + 守卫**：`var SUDOKU = window.SUDOKU || null;` 一次性捕获 + null 守卫兜底（缺失时提示「算法模块缺失」，勿裸调）
4. **确定性**：需求确定同题 → `mulberry32` 包裹 `Math.random`（见 §3.4）
5. **验证四步**：
   - **唯一解**：`solveCount(puzzle, N, 2) === 1`
   - **已知格范围**：`givensCount ∈ [givens, givens+4]`
   - **解合法性**：终盘行/列/宫无冲突（`cellValid` 逐格）
   - **性能**：9×9 `genPuzzle` <1.5s 门槛（实测平均 ~5ms）

### 6.3 命名冲突警示

**`solver.js` 文件名已被 24点（`window.Game24`，完全不同的引擎）占用**；共享位置**必须改名**（如 **`lx-sudoku.js`** 对齐 `_shared/lx-shared.js` 命名模式），**勿裸用 solver.js**——同目录同名不同引擎会互相覆盖。
