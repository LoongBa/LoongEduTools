## 2. 玩法设计

### 2.1 规则

- 经典数独：盘面 N×N（数字 1~N），目标让**每行 / 每列 / 每宫（粗线框）都只出现一次 1~N**。
- 每局盘面由算法**运行时随机生成**（回溯终盘 + 挖洞保证唯一解），孩子不会背答案、不会背题面。
- 交互：**点空格 → 底部数字条点数字填入**（一排按钮，非屏幕九宫格，低龄友好）。
- 全部填满且无冲突即过关；填错不意味着游戏失败，可随时擦掉或撤销重来。

### 2.2 操作

| 输入 | 说明 |
|---|---|
| 点空格 | 选中该格（橙色描边 + 同行/列/宫浅蓝 tint + 同数字浅橙 tint 教具高亮）；点同一格取消选中 |
| 数字条 1~N | 有选中**用户格** → 填数判定；无选中 → 提示「先点一个空格子，再选数字哦」；选中**已知格** → 提示「这是题目给的格子，不用填」；**铅笔模式**下 → 切换候选笔记 |
| ✏ 笔记（v1.1） | 切换铅笔/落子模式；铅笔下点数字在空格记/取消候选，行/列/宫已有该数拒绝并温和提示 |
| 橡皮 | 清空选中格（值 + 候选笔记；仅用户格可擦；已知格提示"不能擦"）；入撤销栈 |
| 撤销 | 恢复上一步（数字/橡皮/提示/笔记均入栈，可连续撤销） |
| 提示 | 自动找候选最少的空格、填上正确解 + 同步自动铅笔清理；入撤销栈；**用提示星级封顶 2★** |
| 实体键盘 | 游戏页响应：1-9 填数/记笔记（≤N 生效）、Backspace/Delete 擦除选中格 |
| 底栏按钮 | 「返回难度」回难度页；「重新开始」同难度重抽一局 |

### 2.3 反馈

- **合法落子**：绿色确认（`okFlash 300ms`，`color #12b76a`）+ 轻音效；**答错不惩罚**——填入的数字只要当前行/列/宫不冲突即接受（即使与终盘解不同也不计错、不提示）。
- **冲突（行/列/宫已有该数）**：红闪（`wrongFlash 400ms`，`#fff1ef → #ffc2ba → 白`）+ 错误计数 +1 + 温和提示「行 / 列 / 宫里已经有这个数啦，换一个试试」（橙色 warn）；**不改变盘面**。
- **教具高亮**（选中态同时呈现三种信息，帮孩子"看懂"数独约束）：
  - 选中格：`#fff3e0` 浅橙底 + `outline 3px #ff9f43` 橙色描边；
  - 同行/列/宫格（peer）：`#ecf5ff` 浅蓝 tint；
  - 同数字格（same）：`#ffedd1` 浅橙 tint。
- **已知格**：浅灰底 `#f2f6fa` + 深色字（不可编辑）；用户格：天蓝字 `#4aa8ff`。
- **音效**（Web Audio `OscillatorNode` 合成，零音频文件）：点选（520Hz 0.05s triangle）/ 填对（660→990 双音）/ 冲突（165Hz 0.16s square 低沉）/ 胜利（523/659/784/1047 上行琶音，同分类整理/迷宫寻路）。首次用户手势创建 `AudioContext`，播放异常静默降级。

## 3. 难度与出题引擎

### 3.1 三档难度（双参数：盘面尺寸 N × 目标已知格 givens）

| key | 难度 | 盘面 | 目标已知格 | 约挖空 | 格内字号 |
|-----|------|------|-----------|--------|---------|
| '4' | 简单 | 4×4 | 10 | ~6 | 30px |
| '6' | 普通 | 6×6 | 21 | ~15 | 22px |
| '9' | 困难 | 9×9 | 33 | ~48 | 16px（≥14px 保持可读） |

- 生成器实际已知格落在 **[目标, 目标+4]**（挖洞受唯一解约束，无法精确到目标值时取近似）；顶栏显示**本局实际已知格数**「4×4 · 已知 10 格」。
- 格列宽按盘面：4→25%、6→16.6667%、9→11.1111%（方形格 `width` + `padding-bottom` 同百分比）。

### 3.2 出题引擎（solver.js，`window.SUDOKU`）

纯算法模块（无 DOM），**运行时程序化出题，零题库**；与学科 24 点同思路（24 点=表达式穷举；数独=回溯终盘+挖洞唯一解）：

```
genPuzzle(N, givens):
  fillBoard(N)                    # 随机回溯完整终盘（每格 1..N 洗牌后尝试）
  loop 最多 4 轮迭代挖洞：
    positions = 全部格下标洗牌
    while 当前已知格数 filled > givens:
      逐格尝试 puzzle[pos]=0
      solveCount(puzzle, N, 2) === 1  → 接受该洞（filled--）
      否则 → 回填恢复
      一轮无进展 → break，换一张新终盘重试
    filled <= givens+4 → 返回 { puzzle, solution, givensCount }
  兜底：最后一次终盘单轮挖洞直接返回（仍保证唯一解）
```

| 方法 | 职责 |
|---|---|
| `boxDims(N)` | 宫尺寸：4→[2,2]、6→[2,3]、9→[3,3] |
| `cellValid(board,N,r,c,v)` | 行/列/宫冲突判定 |
| `fillBoard(N)` | **随机回溯完整终盘**（每格候选 1..N 洗牌，保证每次布局不同） |
| `solveCount(board,N,limit)` | 解计数（数到 limit 即止）；**唯一解校验用 limit=2** |
| `genPuzzle(N,givens)` | **挖洞唯一解生成**：多轮逼近目标已知格 + 兜底，返回 `{puzzle, solution, givensCount}` |
| `getCandidates` | 当前盘面某格可合法填写的数字列表（升序） |
| `findHintCell` | 找候选最少的空格（提示选格） |

- **唯一解保证**：每次挖洞都用 `solveCount(...,2) === 1` 校验，挖出来的每局都是"只有一个正确答案"的完整题目。
- **性能实测**（node `test_sudoku.js`，门槛 9×9 genPuzzle <1.5s）：**9×9 genPuzzle 平均约 5ms、fillBoard 单次约 0ms**，出题瞬间完成，无等待感。
- **移植来源**：`数独小侦探原型/logic_test.js`（原型自身已断言唯一解/已知格范围/解合法性）；语法降级为 **ES2017**（var + function，去除解构 / spread / `Array.prototype.fill` / 箭头函数）。
- 前端模块加载顺序：`data.js`（构建生成 meta）→ `solver.js` → `main.js`（运行期引用 `window.SUDOKU`；缺失时显示「算法模块缺失，请检查 solver.js」）。

## 4. 交互与判定

- **选中态**：`selected` 记住当前格下标（-1 = 无）；`innerClass(i)` 依次叠加 `given`（已知格）/ `user`（用户格）/ `selected` / `peer`（同行列宫）/ `same`（同数字）五个 class。
- **填数判定 `onNumTap(v)`**：取胜状态忽略 → 无选中提示 → 已知格拦截 → 与当前值相同静默返回 → **先清空自身再判冲突**（`cellValid` 含自身所在行/列/宫，必须先置 0）：
  - **合法** → 接受新值（答错不惩罚）+ 撤销栈记录原值 + 绿闪 + `checkWin()`；
  - **冲突** → 恢复原值不动盘面 + 错误 +1 + 红闪 400ms + 温和提示。
- **撤销栈**：`undoStack` push `{i, val, pen}`（填数记录原值+原笔记、橡皮记录原值+原笔记、提示记录 0+原笔记、铅笔记笔记记录全量笔记快照），**上限 200 条**（超出 shift 最旧）；撤销恢复该格原值与笔记。
- **候选笔记（铅笔模式，v1.1 新增）**：工具条「✏ 笔记」按钮切换铅笔/落子模式（启用时按钮高亮，提示行说明）。
  - 铅笔模式下点数字 → 在选中空格**切换候选笔记**（`state.pencils[i]` 升序数组，每个数字一个 `.note-slot.on` 小格渲染）；
  - 手动笔记**冲突校验**：若该数字在行/列/宫已存在 → 拒绝并温和提示（红闪），任何情况下不允许保留错误候选；
  - **自动铅笔同步**：普通模式或提示落定某数后，`erasePenInUnit(i,v)` 自动清除同行/列/宫其余格的该候选数；橡皮同时清值与笔记。
  - 笔记不计入提示次数与错误计数，不影响星级；`solver.js` 的 `getCandidates` 为数据基础，无需改动。
- **智能提示 `pickHintCell`**：遍历所有空格，候选越少越优先，填该格**正确解**（`solution[i]`，保证提示内容绝对正确）；但**跳过「正确解当前不可放」的被堵格**（格子的正确解不在当前候选里 = 该格被填错的数堵死）；全部被堵则建议「有格子被填错了，先用橡皮擦掉，再试试提示」。提示消息：「提示：第 r 行第 c 列 填数字 v」；提示落定后同步触发自动铅笔清理。
- **通关 `checkWin`**：全部填满后做**防御性校验**（逐格剔除自身再验 `cellValid`，合法落子规则下必然成立）才结算；提示按钮在盘面无空格时禁用。

## 5. 星级与最佳成绩判定

- **星级 `calcStars(hints, errors)`**（双指标，提示与错误均影响）：

| 条件 | 星级 |
|---|---|
| 提示 0 次 **且** 错误 0 次 | ★★★ |
| 提示 ≤1 次 **且** 错误 ≤3 次 | ★★ |
| 其余（过关即有） | ★ |

  - 用过提示星级**封顶 2★**；错误 >3 次封顶 1★。
- **最佳判定 `betterThan(A, B)`**：**星级高优先，同星级比用时短**；仅当严格更优才覆盖 `store.best[key]`。
- **最近**：`store.recent[key]` 无条件覆盖为本局用时；**历史**：`history` 无条件 push 后滚动保留最近 30 条。
- 结算浮层展示：星级 + 「用时 X 秒 · 错误 N 次 · 提示 N 次」+ 新纪录徽标 + 打卡 + 三按钮（再来一局 / 选难度 / 打卡日历）。

## 6. 持久化（localStorage）

- key：`redtools.shudurumen.v1`（容器内多工具共享存储，必须带工具前缀）。
- 结构：

```js
{
  version: 1,
  best:    { "4": {ms, errors, hints, stars, date}, "6": {...}, "9": {...} },  // 各难度最佳
  recent:  { "4": ms, "6": ms, "9": ms },                                     // 各难度最近用时
  checkin: { dates: ["YYYYMMDD", ...], streak },                              // 打卡
  history: [ {date, level, ms, errors, hints, stars} ]                        // 滚动 30 条
}
```

- 读写全部 try/catch（隐私模式等异常静默降级）；`loadStore()` 校验 `version === 1` 并补全缺失字段（best/recent/checkin/history），history 超 30 条截尾；初始化写入一次。
- **打卡** `doCheckin()`：通关一局 → `dates` 写入今日 YYYYMMDD（去重 + 排序）、滚动 365 天；`calcStreak()` 连续天数**含今天往前推**（今天未打则从昨天起算），跨天断。
- **计时**：从**游戏页渲染开始**（数独为长时任务，按整局计时，`startTimer()` 在 `startGame` 中调用）；`performance.now()` + `setInterval(100ms)` 按差值刷新 `⏱ 07.5`（秒+1 位小数）；通关 `stopTimer()` 定格。

## 8. 合规自检（Chrome 61 / 容器规范）

- JS：ES2017 经典脚本（var + function），无 `?.`/`??`/对象展开/`replaceAll`/module/import；无内联事件/eval/innerHTML 脚本注入（仅渲染文本/图标）；事件全部 `addEventListener`；无 fetch/XHR/Worker/clipboard；localStorage 读写 try/catch。

## 11. 与系列规范的关系

- **系列归属**：`docs/教育工具/教育工具产品矩阵规划.md` §3.4 逻辑思维训练（P1 数独入门）→ `RedTools/series/益智/逻辑思维/` 子系列第 4 款；对标洪恩数独「数独启蒙」方向，适用 K1-3–K4-6（L2–L3）。
- **可复用核心**：计时/成绩/打卡对齐 `RedTools/series/益智/设计文档.md` §4（localStorage key 带工具前缀 + 打卡日历模式，与分类整理/翻牌记忆配对同款）；Chrome 61 / 交互合规对齐 §5；逻辑思维关卡方案对齐 §7（本案走**「运行时程序化出题」变体**：无需一次性转换脚本与 levels.js 数据文件，算法内嵌即出题源）。
- **与同系列的差异**：推箱子/迷宫寻路以求解指标（最少推动数/最短步数）定星级、分类整理以错误次数定星级，本工具改为**提示×错误双指标星级**（0 提示 0 错 3★ / 提示≤1 且错≤3 2★ / 其余 1★，用提示封顶 2★）；输入用底部一排数字条（非屏幕九宫格，低龄友好）；计时从**游戏页渲染开始**（数独为长时整局任务，与分类整理「首次点选开始」不同）；**v1.0 无断局恢复、无候选笔记铅笔模式、无语音、无教学体系、无图标版启蒙**（对标草案的**简化落地**）。
- **与 24 点同思路**：**运行时程序化出题，零题库**——24 点=表达式穷举构造保证可解；数独=回溯终盘 + 挖洞唯一解保证，唯一解在每次挖洞时用 `solveCount(limit=2)` 校验，杜绝无解/多解题。
- **与数独小侦探草案的关系**：算法直接移植 `数独小侦探原型/logic_test.js`（原型已验证），视觉/交互按本工具「逻辑思维·天蓝系 + 数字符号」精简落地；同目录《数独小侦探_双版本设计草案.md》为历史参考，不承担本工具代码。
- **扩展**：难度常量 `LEVELS` 双参数可直接加档（盘面尺寸/目标已知格改数值即可）；`solver.js` 为纯算法模块，`getCandidates` 已预留候选笔记数据基础；后续可加断局恢复（`state` + `pencils` 快照持久化）、教学体系。
