## 2. 目标与原则

1. **P0 优先**：修复断局恢复三态（每日/闯关/导入）来源丢失，零 schema 迁移（旧快照字段缺失用默认值兜底）。
2. **P2 加固**：数据上限 / 导入校验 / 无障碍 / 性能防线 / 文档一致性，全部向后兼容。
3. **红线保持**：`solver.js` 零改动；测试契约（class/文案/emoji）零破坏；localStorage key 不 bump。
4. **验证闭环**：P0 必须有**失败证明修复有效**的回归断言（修复前 R9-R11 会 FAIL）。

## 3. 变更设计

### 3.1 P0 — 断局恢复三态修复（核心）

| 项 | 现状 | 方案 |
|----|------|------|
| `saveCur()` | `store.cur = {level,N,givens,...,origPuzzle,ms,startStamp}` | **补 3 字段**：`createdFrom: state.createdFrom, isDaily: state.isDaily, fromMap: state.fromMap` |
| `restoreCur()` | 只回填盘面/笔记/撤销/计时，来源字段缺失 | **补回填**（旧快照兜底）：`createdFrom = (cur.createdFrom==='import') ? 'import' : 'normal'`；`isDaily = !!cur.isDaily`；`fromMap = (typeof cur.fromMap==='number' && cur.fromMap>=0) ? cur.fromMap : -1` |
| `resumeGame()` | 硬编码 `createdFrom='normal' / isDaily=false / fromMap=-1` | **移除三行覆盖**（restoreCur 已回填；注释说明旧快照兜底语义） |

**修复后行为**（与开局一致）：
- 每日挑战中断→恢复：顶栏「· 每日题」保留；通关记 `store.daily={date,level}` ✓
- 闯关中断→恢复：顶栏「· 关卡 X-Y」保留；通关记 `mapProgress` 含该关 ✓
- 导入局中断→恢复：顶栏「· 导入题」保留；通关不计 best/打卡/成就 ✓

**冒烟扩展**：`smoke_shudu_resume.py` 新增 R9（每日）/R10（闯关）/R11（导入）三态恢复断言——每态验证「顶栏标记保留 + 通关后 store 对应字段写入/不写入」。

### 3.2 P2⑨ — 收藏本 FIFO 上限

`toggleFav` push 后加 `while (store.favorites.length > 50) { store.favorites.shift(); }`（同错题本 50 上限）。

### 3.3 P2⑩ — 导入题最少给定格校验

`parsePuzzleText` 唯一解校验前加：
```
MIN_GIVENS = {4:4, 6:10, 9:17}   // 4×4 生成目标 10 的半程保守线；6×6 目标 21 的半程；9×9 数学下限 17 线索
givens 计数 < MIN_GIVENS[N] → 拒绝：「题目已知格太少（N×N 至少 MIN 个已知数）」
```
**冒烟适配确认**：share 冒烟 G 用例 `genPuzzle(6,21)`（21-25 格 ≥ 10）不受影响；F3 值越界用例在 givens 检查前先触发「0~N」错误，断言顺序不变。

### 3.4 P2⑫ — 铅笔笔记 aria

`buildNoteGrid` 网格容器加 `role="group" aria-label="候选笔记"`（不破坏 `.cell-note`/`.note-slot` 选择器与 `data-v` 属性）。

### 3.5 P2⑧ — 生成器性能防回归脚本

新增 `tests/perf_sudoku_gen.js`（node 直接加载 solver.js，mock `window`）：
- 预热 1 轮 JIT 后测 `genPuzzle(9,33)` ×10 轮：均值 < 500ms、单轮 < 2000ms（防数量级退化）
- `genPuzzle(6,21)` ×20 / `genPuzzle(4,10)` ×20：均值 < 100ms
- 产出非法（无解/长度错）即 FAIL；输出 PASS/FAIL + exit code

### 3.6 P2⑥ — 双模式验证与回写

- 构建验证：`build_all.py --tool 数独思维 --mode offline` + `--mode online` 均须成功（static 工具 online 仅部署目录不入 publish）
- 回写：RedTools README 总表数独思维行补「双模式接入（B 批）」+ 状态列补构建验证

### 3.7 P2⑤ / P2⑪ — 评估后不动（记录决策）

| 项 | 评估结论 | 理由 |
|----|----------|------|
| P2⑤ 旧文档归档 | **保留原位，不归档** | 被 8 个文件 25 处引用（设计文档/生成引擎说明/迭代设计/草稿教材/solver.js 注释/README），`数独小侦探原型/logic_test.js` 是 solver.js 移植来源（功能性引用）；归档产生大量断链 |
| P2⑪ 徽章墙 locked 分支 | **保留不清理** | `SKILLS[].locked` 分支为未来新增技巧（L8+）留扩展位；删除收益小风险中（冒烟不依赖 🔒 徽章计数，但清理需动 DOM 逻辑） |
