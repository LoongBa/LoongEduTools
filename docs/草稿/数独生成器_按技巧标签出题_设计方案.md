# 《数独生成器 —— 按技巧标签出题》设计方案

**版本**：V1.0

**适用场景**：中小学数独教学、分层练习、题库建设、竞赛训练

**核心目标**：根据指定的技巧标签，生成唯一解 9×9 数独题，并保证题目所需技巧与标签匹配。

**关联文档**：《数独小侦探\_双版本设计草案.md》《数独小侦探\_开发方案.md》—— 本生成器即开发方案中 "技巧分层求解器" 的独立展开，题库反哺产品（适龄教学版 L0–L4 / 全功能版自由解题模块 L5–L7）。



***

## 一、项目概述

传统数独生成器通常只按 "简单、一般、困难、挑战" 出题，但教学场景需要更细的粒度：



* "请给我 10 道只用到隐性唯一的题。"

* "生成必须使用 X-Wing 才能解的困难题。"

* "题目最多用到数对，不能出现链。"

* "目标技巧是 XY-Wing，允许使用 L0～L4。"

因此，本生成器以**技巧标签**为核心，支持：



1. **最大技巧等级**：如 maxLevel=L3，表示只用 L0～L3 可解。

2. **必须技巧**：如必须使用 X-Wing。

3. **禁止技巧**：如禁止链和猜测。

4. **目标技巧**：以某技巧为主要训练点。

5. **提示数范围**：如 28～32 个提示。

6. **对称性**：中心对称、非对称。

7. **批量生成**：一次生成 N 道并去重。

## 二、技巧标签体系

### 2.1 技巧阶梯

沿用教学阶段 L0～L7：



| 阶段 | 技巧标签示例    | 代码示例                                               |
| -- | --------- | -------------------------------------------------- |
| L0 | 规则、候选数    | `L0_BASIC`                                         |
| L1 | 唯一余数、隐性唯一 | `L1_NAKED_SINGLE`、`L1_HIDDEN_SINGLE`               |
| L2 | 区块摒除      | `L2_POINTING`、`L2_CLAIMING`                        |
| L3 | 数组        | `L3_NAKED_PAIR`、`L3_HIDDEN_PAIR`、`L3_NAKED_TRIPLE` |
| L4 | 鱼与翼       | `L4_X_WING`、`L4_XY_WING`、`L4_SWORDFISH`            |
| L5 | 高级模式与唯一性  | `L5_UNIQUE_RECTANGLE`、`L5_W_WING`                  |
| L6 | 链与着色      | `L6_X_CHAIN`、`L6_XY_CHAIN`、`L6_AIC`                |
| L7 | 强制链与搜索    | `L7_FORCING_CHAIN`、`L7_GUESS`                      |

### 2.2 标签依赖关系

每个技巧可定义前置依赖，用于教学推荐和允许集合推导：



```
{

&#x20; "code": "L4\_X\_WING",

&#x20; "name": "X-Wing",

&#x20; "level": 4,

&#x20; "dependsOn": \["L0\_BASIC", "L1\_HIDDEN\_SINGLE", "L2\_POINTING"],

&#x20; "description": "两行两列成矩形，排除四角外候选"

}
```

允许集合可以是：



* **阶梯式**：允许到 L4，则 L0～L4 全部允许。

* **精确式**：只允许 `L1_NAKED_SINGLE`、`L3_NAKED_PAIR`。

* **排除式**：允许 L0～L5，但禁止 `L5_UNIQUE_RECTANGLE`。

## 五、核心模块设计

### 5.1 终盘生成器

**方法 A：随机回溯填满**

从空棋盘开始，按行优先顺序填数，每格随机尝试 1～9，冲突回溯。

**方法 B：基准终盘 + 等价变换**

预置若干合法终盘，随机执行：



* 数字置换 1～9；

* 同宫内行交换；

* 同宫内列交换；

* 宫行交换；

* 宫列交换；

* 整体转置。

输出：完整合法终盘 `solution`。

### 5.2 挖洞器

从 `solution` 复制出 `puzzle`，随机选择格子置 0。

每挖一个或一对格子，调用解数计数器验证唯一解。

若多解，则恢复该格。

支持：



* 中心对称挖洞；

* 非对称挖洞；

* 目标提示数范围；

* 优先挖候选数多的位置。

### 5.3 解数计数器



```
countSolutions(puzzle, limit=2)
```

使用回溯搜索，找到 2 个解立即停止。

返回解的数量，用于唯一解验证。

### 5.4 逻辑求解器

这是按技巧标签出题的核心。求解器维护候选数表，按技巧优先级循环应用：



```
while not solved:

&#x20;   for skill in enabledSkillsOrderedByLevel:

&#x20;       if skill.apply(candidates) succeeds:

&#x20;           recordStep(skill, exclusions, placements)

&#x20;           break

&#x20;   else:

&#x20;       return STUCK
```

每个技巧实现为独立规则：



```
class Skill:

&#x20;   code: str

&#x20;   level: int

&#x20;   def apply(self, board) -> SkillResult | None:

&#x20;       ...
```

`SkillResult` 包含：



* 使用的技巧代码；

* 填写的数字；

* 排除的候选；

* 涉及的格、行、列、宫；

* 解释文本。

### 5.5 技巧规则引擎

技巧按等级注册，支持启用 / 禁用：



```
skill\_registry = {

&#x20;   "L1\_NAKED\_SINGLE": NakedSingle(),

&#x20;   "L1\_HIDDEN\_SINGLE": HiddenSingle(),

&#x20;   "L2\_POINTING": Pointing(),

&#x20;   "L3\_NAKED\_PAIR": NakedPair(),

&#x20;   "L4\_X\_WING": XWing(),

&#x20;   ...

}
```

求解时可指定：



```
solve(puzzle, allowedSkills={"L0\_BASIC", "L1\_NAKED\_SINGLE", ...})
```

### 5.6 技巧标签分析

对一道题，分析：



1. **最低必要技巧阶段**：从 L0 开始逐步启用技巧，找到能解出的最低等级 k。

2. **必须技巧**：对目标技巧 T，禁用 T 后重新求解。若不能解，则 T 是必须技巧。

3. **使用技巧统计**：记录每个技巧使用次数、步骤数、分支数。

4. **猜测深度**：若允许 L7，记录回溯节点数和最大分支。

### 5.7 难度评估器



```
score = w1 \* minRequiredLevel

&#x20;     \+ w2 \* stepCount

&#x20;     \+ w3 \* requiredSkillCount

&#x20;     \+ w4 \* guessDepth

&#x20;     \+ w5 \* (81 - givens)

&#x20;     \+ w6 \* averageCandidates
```

按阈值分档：



| 难度 | 条件                                    |
| -- | ------------------------------------- |
| 简单 | minRequiredLevel ≤ 1                  |
| 一般 | minRequiredLevel = 2～3                |
| 困难 | minRequiredLevel = 4～5                |
| 挑战 | minRequiredLevel ≥ 6 或 guessDepth > 0 |

## 六、按技巧标签出题流程

### 6.1 生成参数



```
{

&#x20; "maxLevel": 4,

&#x20; "allowedSkills": \["L0", "L1", "L2", "L3", "L4"],

&#x20; "requiredSkills": \["L4\_X\_WING"],

&#x20; "forbiddenSkills": \["L6", "L7"],

&#x20; "givensRange": \[26, 30],

&#x20; "symmetric": false,

&#x20; "difficulty": "困难",

&#x20; "count": 5,

&#x20; "seed": 12345

}
```

### 6.2 生成算法伪代码



```
function generateByTags(params):

&#x20;   results = \[]

&#x20;   while len(results) < params.count and not timeout:

&#x20;       solution = generateFullGrid(seed)

&#x20;       puzzle = digHoles(solution, params.givensRange, params.symmetric)

&#x20;       if countSolutions(puzzle, 2) != 1:

&#x20;           continue

&#x20;       analysis = analyzePuzzle(puzzle, params.allowedSkills)

&#x20;       if not analysis.solved:

&#x20;           continue

&#x20;       if analysis.minRequiredLevel > params.maxLevel:

&#x20;           continue

&#x20;       if any(skill in analysis.usedSkills for skill in params.forbiddenSkills):

&#x20;           continue

&#x20;       if not all(skill in analysis.requiredSkills for skill in params.requiredSkills):

&#x20;           continue

&#x20;       rating = rateDifficulty(analysis)

&#x20;       if rating.level != params.difficulty:

&#x20;           continue

&#x20;       results.append({

&#x20;           puzzle, solution, analysis, rating

&#x20;       })

&#x20;   return results
```

### 6.3 提高命中率



* 预生成大量终盘，避免重复。

* 挖洞时动态调用逻辑求解器，边挖边评估。

* 对困难 / 挑战题使用离线批量生成，存入题库。

* 使用多线程 / 多进程并行生成。

* 缓存已生成题目，按标签索引。

## 七、数据模型

### 7.1 核心表



```
\-- 题目表

CREATE TABLE puzzles (

&#x20;   id BIGSERIAL PRIMARY KEY,

&#x20;   puzzle\_string CHAR(81) NOT NULL,

&#x20;   solution\_string CHAR(81) NOT NULL,

&#x20;   givens\_count INT NOT NULL,

&#x20;   min\_required\_level INT,

&#x20;   difficulty VARCHAR(20),

&#x20;   step\_count INT,

&#x20;   code VARCHAR(50) PRIMARY KEY,

&#x20;   name VARCHAR(100),

&#x20;   level INT,

&#x20;   depends\_on JSONB,

&#x20;   description TEXT

);

\-- 题目技巧使用表

CREATE TABLE puzzle\_skill\_usage (

&#x20;   puzzle\_id BIGINT REFERENCES puzzles(id),

&#x20;   is\_required BOOLEAN,

);

\-- 生成任务表

CREATE TABLE generation\_jobs (

&#x20;   id BIGSERIAL PRIMARY KEY,

&#x20;   params JSONB,

&#x20;   status VARCHAR(20),

&#x20;   created\_at TIMESTAMP DEFAULT NOW()

```

### 7.2 索引

## 十、性能优化



1. **终盘池**：预生成 1000+ 终盘，随机变换。

2. **增量验证**：挖洞时逐步验证唯一解，避免最后才发现多解。

3. **逻辑求解器缓存**：缓存候选数表，避免重复计算。

4. **并行生成**：多进程生成，任务队列调度。

5. **离线题库**：挑战题提前生成，运行时直接取。

6. **Redis 缓存**：热门标签组合结果缓存。

7. **位运算优化**：候选数用 9 位整数表示，加速排除。

## 十五、总结

本方案以**技巧标签**为核心，构建了一个可教学、可分层、可扩展的数独生成器：



* 用 **L0～L7 技巧阶梯**定义标签；

* 用 **逻辑求解器**分析题目所需技巧；

* 用 **唯一解验证**保证题目合法；

* 用 **难度评估器**综合评分；

* 用 **API 和前端**支持教师配置、学生练习；

* 用 **缓存与离线题库**保证性能。

最终可实现：

> 教师勾选 "L3 数对 + 必须使用显性数对 + 禁止链"，系统生成唯一解、难度匹配、带完整解题步骤的 9×9 数独题。
