## 1. 定位与玩法

**一句话**：迷宫盘面（推箱子关卡），孩子用**指令积木**编排机器人的移动序列
（↑ 前进 / ↰ 左转 / ↱ 右转），点「▶ 执行」后机器人按序列移动（前方有箱子则推箱）。
所有箱子到目标点 = 答对。

**编程教学本质**（与推箱子游戏的根本区别）：
- 推箱子：直接方向键实时控制（表现性玩法）；
- 机器人走迷宫：**先编排指令序列 → 一次性执行 → 观察结果 → 调试修正**（顺序编程思维，
  像 Scratch 的指令序列阶段）。

## 2. 有标准答案论证（合规关键）

| 判定维度 | 机制 |
|---|---|
| 对/错 | 指令序列执行后的盘面 = 所有箱子在目标（`isWon` 程序判定，非表现性分数） |
| 星级 | 指令数 vs 关卡最少推动数（`bestPushes` b 值，≤1.5× = 3★，程序可算） |
| 学习反馈 | 执行失败显示「还有箱子没到目标点，调整指令再试」→ 像调试器定位错误序列 |

> 无生存/分数/时间竞争——纯「编排-执行-验证」循环，编程练习不是游戏。

## 3. 关卡与难度

| 难度 | 关卡区段 | 星级标准 |
|---|---|---|
| 简单 | 第 1-5 关 | 指令数 ≤ 1.5×b = 3★ / ≤ 2.5×b = 2★ / 其余 1★ |
| 普通 | 第 6-10 关 | 同左 |
| 挑战 | 第 11-15 关 | 同左 |

- 关卡数据：复用推箱子 `levels.js`（Microban 155 关全量，本轮开放前 15 关）；
- 每关 b 值（最少推动数）为星级基准（levels.js 预计算）。

## 4. 核心机制

- **解析**：XSB 关卡 → 位集合（walls/goals/boxes/player），复用推箱子解析；
- **执行器**（execStep）：逐条指令——left/right 改朝向（face ±90°），fwd 按朝向移动
  （前方有箱子则推箱，撞墙/越界忽略）；
- **判定**：指令执行完 → `isWon(boxes, goals)`（所有箱子在目标）；
- **指令序列**：可追加/删除（点击序列 chip 删除）/清空/重置盘面。

## 5. 数据与存储

- `LX_SHARED.storage`：`configure({toolName: 'jiqirenzoumi'})` → 键前缀 `redtools.jiqirenzoumi.v1`；
  结构 `{version, best:{easy,normal,hard}, recent, checkin, history}`；
- `calcStreak(dates)` → `LX_SHARED.progress.streak(dates)`。

## 6. 合规

- 有标准答案（目标盘面判定）→ 安全练习区（编程教学，非游戏）；
- 无排行榜/无跨用户对比 → 个人纵向（星级/打卡/最佳）；
- UI 文案「指令/执行/前进/转向/完成练习」编程练习用语；
- 零图片素材（SVG 程序化盘面），包体 0.02 MiB。

## 7. 技术要点

- Chrome 61 基线（ES2017 经典脚本、CSS 无 gap/aspect-ratio/clamp）；
- 双模式脚本顺序 `data.js → lx-shared.js → levels.js → main.js`；
- 构建：`python build_all.py --tool 机器人走迷宫`；
- 复用：levels.js（Microban 155 关）+ XSB 解析 + 推箱判定逻辑。
