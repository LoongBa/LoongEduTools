## 1. 定位与玩法

**一句话**：经典扫雷的数字推理玩法，但**踩雷不判负**——踩到雷标出来继续推理，全部安全格翻开 = 完成练习。

**与经典扫雷的根本区别**（D2 核心改造）：

| 项 | 经典扫雷（🔒 推迟） | 扫雷推理（本工具） |
|---|---|---|
| 踩雷 | 💥 爆炸 + 判负 + 终局 | **标出该雷 + 推理提示，局继续**（可继续翻开其它格） |
| 胜负 | 全部排雷=赢 / 踩雷=输 | **全部安全格翻开 = 完成**（无胜负概念） |
| 文案 | 「踩到雷了/输了/胜利」 | 「完成推理/继续翻开安全格」练习用语 |
| 推理依据 | 无 | 踩雷后显示数字推理提示（几=周围几雷） |
| 星级 | — | 踩雷次数 + 用时（踩雷少=更优） |

## 2. 有标准答案论证（合规）

- **数字推理**：每格数字 = 周围雷数（可程序判定）→ 推理结论确定（哪些格安全/哪些格是雷）；
- **完成判定**：全部安全格翻开（`checkWin` 程序判定）；
- **踩雷不判负**：雷是「已确认的推理依据」而非「失败条件」——弱化「踩雷=输」的胜负机制，
  强化「数字→排除」的逻辑推理（指导原则 §二 🟡 改造路径）。

## 3. 关卡与难度

| 难度 | 盘面 | 雷数 |
|---|---|---|
| 初级 | 9×9 | 10 |
| 中级 | 16×16 | 40 |
| 高级 | 30×16 | 99 |

- 首点 3×3 安全区（首点不踩雷）；标旗模式（触屏/键盘双输入）；
- 完成判定：翻开全部安全格；踩雷次数计入星级展示（非判负）。

## 4. D2 改造点（相对经典扫雷）

1. **存储迁移**：`redtools.minesweeper.v1` → `redtools.saoleituili.v1`（LX_SHARED.storage configure 'saoleituili' + get/set('v1')，双模式接入）；
2. **loseGame 不判负**：`state.over` 不再置 true——标雷 + `hitMines` 记录 + `showMineHint` 推理提示 + `checkWin` 继续判定；
3. **paintCell**：非终局状态显示已踩雷（💣 标出，红底）；
4. **文案**：openWin「完成推理！」+ 踩雷次数展示；openLose「推理未完」；
5. **星级**：踩雷次数 + 用时（新纪录/最佳展示）。

## 5. 数据与存储

- `LX_SHARED.storage`：`configure({toolName: 'saoleituili'})` → 键前缀 `redtools.saoleituili.v1`；
  结构（复用扫雷）：`{games, wins, best, checkin, guard, cur, flagMode, ...}`；
- `calcStreak(dates)` → `LX_SHARED.progress.streak(dates)`（打卡连续天数）。

## 6. 合规

- 数字推理有标准答案 → 安全练习区（推理练习，非「游戏」）；
- 无排行榜/无跨用户对比 → 个人纵向（最佳用时/踩雷次数）；
- UI 文案练习用语（完成推理/继续翻开安全格）；
- 零图片素材（程序化棋盘 + emoji 雷/旗），包体 0.03 MiB。

## 7. 技术要点

- Chrome 61 基线（ES2017 经典脚本）；双模式脚本顺序 `data.js → lx-shared.js → main.js`；
- 构建：`python build_all.py --tool 扫雷推理`；
- 复用：经典扫雷 main.js（1415 行）核心（布雷/数字/翻牌/标旗/防沉迷）副本改造。
