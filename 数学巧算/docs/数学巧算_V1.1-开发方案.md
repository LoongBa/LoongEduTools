## 二、目标与原则

- **目标**：V1.1.0 交付「打印讲义增强」——①**题单固定**：同一讲默认恒定同一套题（seed 由 lesson_id 派生，跨会话稳定），纸张可复练、家长可对照；②**可选题数/难度**：屏上配置面板——每档（基础/提高/挑战）可勾选打/不打 + 题数可调（默认 lesson count）；③**换一组题**：一键重掷 seed 生成新题单；④**恢复默认**一键还原 lesson 配置。
- **原则**：
  - **零引擎改动**（关键约束）：smart_gen.js 18 处 `Math.random()` 直调，逐点改造为 seed 感知 = 引擎全量重回归、高风险。改为**生成期注入**：`generatePractice` 在同步生成窗口内临时覆写 `Math.random` 为播种 PRNG（mulberry32），`finally` 必还原——同步单线程隔离，引擎/其余视图零感知。
  - **确定性 = 纯函数可测**：同一 `(genName, count, seed)` 恒产出同一题单（引擎无外部状态、validate 纯数学，随机仅消费在生成 fn 内）；题序子 seed 设计——第 i 题 seed = `baseSeed + i`，改 count 时前 i 题保持稳定（加题不重洗）。
  - **向后兼容**：`generatePractice` 新增可选 `seed?` 参数；缺省 = V0.6 随机行为完全等价（PracticeView 不受影响）。
  - **可复练优先**：默认 seed 稳定（同讲恒同题单），「换一组题」提供受控变化——纸张复练价值最大化。
  - **复用不重写**：配置面板用现有 ui-kit（Btn/Pill）；打印管线/答案区/防切页样式全部沿用 V0.6。
  - **打印隔离**：配置面板 `print-hidden`（不进纸张）；练习单仅渲染勾选档。
  - **不计 store**（沿用 N3）：不 todaySec/guard/practiced。

## 三、变更设计（逐项）

### 3.1 播种 PRNG + seed 工具（新 · lib/handout.ts）

**方案**（全部收进 `lib/handout.ts`，自包含零 import，engine.mjs 可单测）：

1. **`mulberry32(seed)`**：经典 32 位 PRNG（`Math.imul`，Chrome 28+ 可用，离线合规）：
   ```ts
   function mulberry32(seed: number): () => number {
     let a = seed >>> 0;
     return () => {
       a = (a + 0x6d2b79f5) >>> 0;
       let t = a;
       t = Math.imul(t ^ (t >>> 15), t | 1);
       t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
       return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
     };
   }
   ```
2. **`hashSeed(str): number`**：FNV-1a 32 位字符串散列（同字符串恒同值，作默认 seed）：
   ```ts
   export function hashSeed(str: string): number {
     let h = 2166136261;
     for (let i = 0; i < str.length; i++) {
       h ^= str.charCodeAt(i);
       h = Math.imul(h, 16777619);
     }
     return h >>> 0;
   }
   ```
3. **`generatePractice` 扩展签名**（向后兼容，P1；I4 防御落实）：
   ```ts
   export function generatePractice(
     genName: string,
     count: number,
     engine: HandoutEngine | null,
     seed?: number,   // V1.1 新增：提供 → 确定性题单；缺省 → V0.6 随机行为
   ): HandoutPractice[] {
     if (!engine || !genName || count <= 0) return [];
     // ⚠ 同步窗口约束（I4）：engine.gen 必须纯同步，禁止 async/await/Promise——
     // try/finally 仅保护同步路径；未来引擎若引入异步需改此方案。
     const originalRandom = Math.random;
     // I4 dev 防重入：进入前若已被 mulberry32 覆写 → 调用链重入，告警
     if (originalRandom.toString().indexOf("mulberry32") !== -1) {
       console.warn("[handout] Math.random 已被覆写——疑似 generatePractice 重入，请检查调用链");
     }
     const seeded = typeof seed === "number" && Number.isFinite(seed);
     try {
       for (let i = 0; i < count; i++) {
         if (seeded) Math.random = mulberry32((Math.floor(seed) + i) >>> 0);  // 题序子 seed
         const q = engine.gen(genName);
         if (!q || typeof q.text !== "string" || q.text === "") return [];
         out.push({ text: q.text, answer: q.answer });
       }
       return out;
     } finally {
       Math.random = originalRandom;   // 必还原（B 级约束，中途 return [] 也执行）
     }
   }
   ```
   - 第 i 题 seed = `(floor(seed) + i) >>> 0`：count=5 与 count=3（同 seed）前 3 题一致；不同 i 种子不同 → 题间不重复（引擎本身也有随机度，天然防同题）。
   - `finally` 还原即使中途 `return []`（B2 失败路径）也执行。
   - **N3（Oracle，预存在风险，知悉不采纳）**：`engine.gen` 内部 validate 6 连败时会返回未验证题（text 非空）→ generatePractice 会放行。V0.6 随机模式概率极低（L1 9600 题 0 失败）；V1.1 固定 seed 下若命中会确定性出现，由 §3.4 I3 扩展的真实引擎测试暴露。不给 handout 的 HandoutEngine 接口加可选 `validate` 字段（保持零侵入），记录为已知边界。

**涉及文件**：`lib/handout.ts`（+3 函数/参数）；`engine.mjs` L9 扩展单测（见 §3.4）。

### 3.2 配置面板 + 题单重生成（P2/P3 · HandoutView.tsx）

**现状**：`useState(() => generatePractice(...))` 初始化器一次性生成（L55-65）；三档全打写死（L170）。

**方案**：

1. **配置状态**（默认 = 三档全打 + lesson count，缺失兜底 5/5/3）：
   ```ts
   type LevelConfig = { on: boolean; count: number };
   const [config, setConfig] = useState<Record<Level, LevelConfig>>(() => {
     const out = {} as Record<Level, LevelConfig>;
     for (const lv of ["basic", "advance", "challenge"] as Level[]) {
       out[lv] = { on: true, count: Math.min(10, Math.max(1, lesson?.practice?.[lv]?.count || 5)) };
     }
     return out;
   });
   const [seed, setSeed] = useState<number>(() => hashSeed(String(lessonId)));
   ```
   - 题数范围 1–10（挑战默认 3 在范围内；10 题×3 档 ≈ 30 题 2-3 页 A4，纸张容量合理）。
2. **engineOk 改为普通 const（I1 落实）**：`const engineOk = !!getEngine();`（每次 render 重算，替代 useState 冻结——与响应式 practiceByLevel 保持一致，杜绝"useMemo 生成出题但 engineOk=false 置灰"的自相矛盾）。
3. **生成改为 `useMemo` 响应式**（配置/seed 变化 → 重生成；确定性保证同输入同输出）：
   ```ts
   const practiceByLevel = useMemo<Record<Level, HandoutPractice[]>>(() => {
     const out = {} as Record<Level, HandoutPractice[]>;
     if (!lesson) return out;
     const engine = getEngine();
     for (const lv of ["basic", "advance", "challenge"] as Level[]) {
       out[lv] = config[lv].on
         ? generatePractice(lesson.practice?.[lv]?.gen || "", config[lv].count, engine, seed)
         : [];
     }
     return out;
   }, [lesson, config, seed]);
   ```
   - StrictMode dev 双调无害（seed 确定性纯函数；`Math.random` 覆写在同步窗口内成对还原）。
   - **引擎不可用**：`generatePractice` 返回 `[]`（B2）→ 练习单区警告 + 打印置灰（`engineBroken = !engineOk`）；全档未勾选是合法配置，打印原理/例题版。
4. **屏上配置面板**（`print-hidden`，插在工具条下方）：
   ```
   📐 讲义配置（不进纸张）
   [○/✓ 基础] [− 5 +]   [○/✓ 提高] [− 5 +]   [○/✓ 挑战] [− 3 +]
   [🔄 换一组题] [恢复默认]
   ```
   - 档开关：Btn（lit=开 / ghost=关）→ `setConfig({...c, [lv]: {...c[lv], on: !c[lv].on}})`
   - 题数：`[−]/[+]` 小按钮 → count ±1，边界 1..10 钳制
   - 换一组题：`setSeed((s) => (s + 1) >>> 0)`（受控新题单；再点再换）
   - 恢复默认：重置 config 为 lesson 默认 + seed 复位 `hashSeed(lessonId)`
5. **练习单/答案区渲染三态（I2 落实）**：仅渲染勾选档，且区分"生成失败"：
   - `on && length > 0` → 正常渲染题列；
   - `on && length === 0` → 「⚠ 该组题生成失败，请点「换一组题」」（引导用户换组脱困）；
   - `!on` → 不渲染。
   - 答案区 = 勾选且成功档 items 扁平化。全档无题时提示文案区分：`全档未勾选 → （未勾选练习档，仅打印原理/例题）`；`勾选但全失败 → （练习单生成失败，请点「换一组题」重试）`。
6. **页脚题单组别（N2 采纳）**：`生成日期：{todayStr()} · 题单组别：{seed - hashSeed(String(lessonId)) + 1} · 巧算乐学 V1.1.0`——家长可对上"第 N 组"复练，换组可回溯。

**涉及文件**：`HandoutView.tsx`。

### 3.4 测试与合规

1. **engine.mjs L9 扩展**：
   - **seed 确定性**：用「消费 `Math.random` 的 mock 引擎」（`gen` 返回 `{ text: String(Math.random()) + " =", answer: 1 }`）——同 seed 两次生成文本逐项全等；不同 seed 生成文本至少一项不同（≥3 题）。
   - **题序稳定性**：同 seed，count=5 与 count=3 → 前 3 题全等。
   - **Math.random 还原**：调用前后 `Math.random` 引用同一（`captured === Math.random`）；重入检测告警不误报（单测环境无预覆写 → 不触发 warn）。
   - **真实引擎确定性（I3 落实）**：≥3 个 genName × ≥2 个 seed 各两次全等——覆盖不同随机消费形态：`combo_basic`（纯 ri 驱动）、`sub_property_challenge`（含 `Math.random() < 0.5` 二选一分支，sg_stage3_4）、`fraction_distributive_advance`（分数/小数重试路径）；seed 取 `hashSeed("s4l1")` 与 `hashSeed("s4l1") + 1`；另补"同 genName 不同 seed 至少一项不同"断言防假等。
   - **向后兼容**：缺 seed 行为等价 V0.6（随机路径仍返回 count 题）；`engine null`/`genName 空`/`count ≤ 0` → `[]`（既有断言保留）。
   - 边界：`seed = 0`、`seed` 为小数（floor 处理）、超大 seed（>>> 0 截断）不抛错。
2. **smoke.mjs**：阶段 4 讲义场景扩展——
   - 配置面板渲染（「换一组题」「恢复默认」按钮 + 每档 [−]/[+]）；
   - 默认三档全打断言保留（一、基础题 已断言；补 二、提高题/三、挑战题 存在）；
   - **换一组题**：点击后 `.handout-practice-row` 文本数组与点击前至少一项不同；
   - **关档**：关掉基础档 → 「一、基础题」消失、「二、提高题」仍在；
   - **页脚组别**：含「题单组别」文案；
   - 返回课堂页、打印按钮仍可用（回归）。
3. **合规**：零新依赖/网络/音频；`Math.imul`/位运算 Chrome 28+（离线基线 Chrome 61 兼容）；配置面板 print-hidden 不进纸张。

## 五、风险与决策点

| # | 风险/决策 | 评估 | 处置 |
|---|---|---|---|
| R1 | **Math.random 全局覆写**的副作用面 | 同步单线程 + finally 必还原 + 仅 handout 生成窗口内；React 渲染路径不消费 Math.random；StrictMode 双调成对还原 | 接受；I4 落实——函数头同步约束标注 + dev 防重入检测 + L9 还原断言（引用同一）防回归 |
| R2 | **题单固定的产品语义**（同讲恒同题 vs 按日变题） | "复练同一套"是 R1 明确诉求；换一组题覆盖"想换题"场景 | 默认 hashSeed(lessonId) 恒固定 + 手动换组（决策点 D1） |
| R3 | 引擎 validate 重试（`gen` 内 ≤5 次 fn 重抽） | seed 窗口内确定性 → 重试序列也确定，题单仍稳定 | 接受；I3 真实引擎确定性单测覆盖 |
| R4 | 题数范围导致篇幅超长 | 1–10/档，全开×10 = 30 题 ≈ 2-3 页 A4（答案区独立页已 break-before） | 范围钳制 1..10；档内 break-inside 已有 |
| R5 | 全档未勾选 / 勾选但生成失败 | 全未勾选 = 合法打印原理/例题版；勾选失败需用户引导 | I2 三态渲染：失败显示「⚠ 该组题生成失败，请点「换一组题」」；打印不禁用（引擎 ok 即可） |
| R6 | **预存在**：gen() 6 连败返回未验证题（N3） | V0.6 已存在；L1 9600 题 0 失败概率极低；V1.1 固定 seed 命中则确定性出现 | 知悉不采纳（保持 HandoutEngine 零侵入）；I3 真实引擎测试覆盖到则暴露，届时再议 |
| D1 | 默认 seed = lessonId（恒固定）vs 含日期（每日新题） | 恒固定 = 复练价值最大化；每日新题 = 新鲜感 | **默认 lessonId 恒固定**（用户诉求"题单固定"字面义）；换一组题补新鲜感 |
| D2 | seed 变化粒度 | 换一组题 = seed+1（受控可复现）vs 随机 seed（不可复现） | seed+1：家长可对话式选组（"第一组难了换第二组"），可复现可回退 |
| D3 | 配置是否持久化（localStorage） | 每讲配置各异、打印低频，持久化收益低 | **不持久化**（每次进讲义默认 = lesson 配置；恢复默认按钮兜底） |
| D4 | 题数 stepper 范围 | 1–10 | 钳制 + 语义明确（超出纸张容量无意义） |
| D5 | useMemo 依赖 config 整对象（N4） | 单档变更触发全档重生成 | 毫秒级成本可忽略；分档 memo 复杂度不值，**不采纳**（记录备选） |
