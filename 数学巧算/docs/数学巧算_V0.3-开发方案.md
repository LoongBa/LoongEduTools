## 二、目标与原则

- **目标**：V0.3.0 交付四项——①口算热身模块（复用数学口算 generators.js）；②防沉迷限时（对齐防沉迷通用契约）；③家长报告打印（window.print 零依赖）；④minitool zip 打包 + 发布 SOP（对齐点读陪练 publish 管线）。
- **原则**：
  - **复用不重写**：generators.js 直接内联（零依赖纯 ES5 26KB，已确认 Chrome 61 兼容）；防沉迷契约对齐 RedTools 通用需求 §4；打印对齐数独思维 v1.23；打包对齐 publish_offline.py。
  - **不复制教材/不超纲**：热身题面用口算基础层（10 以内/表内乘除/简单小数），不引入新知识点。
  - **儿童数据最小化**：防沉迷/报告全部本地 localStorage，无网络。
  - **最小化修复，不借机重构**：不重构既有视图/引擎。

## 三、变更设计（逐项）

### 3.1 口算热身模块（P1）

**现状**：无热身入口；PracticeView 直接从 lesson.practice.gen 调 SMART_GENERATORS。
**方案（v0.2 修订：落实 I1/I2/I5、N1/N5/N6）**：
1. **内联 generators.js**：复制 `RedTools/series/学科/数学口算/src/assets/generators.js` → `数学巧算/src/src/assets/kou_gen/kou_gen.js`（保留 `window.KOU_GENERATORS` 命名，与 `SMART_GENERATORS` 共存）。
   - **语法**：实际代码为 ES5 子集（var/function/IIFE/正则），文件头注释标注上界 ES2017；Chrome 61 直接可用，无需降级（I9 措辞订正）。
   - 裁剪：删除未使用的 `ensureDivisible` 私有函数（已确认 0 调用）。
   - 补充：内联知识点元数据为 `window.KOU_META`（**25 条**：g1_*(4)+g2_*(4)+g3_*(5)+g4_*(4)+g5_*(4)+g6_*(4)，来源 `main.js` POINTS 表；I1 订正 24→25）。
2. **main.tsx 注入**：在 smart_gen 系列之后追加 `import "@/assets/kou_gen/kou_gen"`（副作用挂 window；Vite 按依赖图加载，两 IIFE 独立挂 window 可共存——N1 订正"顺序加载"为"副作用 import"）。
3. **入口**：HomeView 新增「口算热身」独立入口卡片（不打断七步课堂流），进入后选档 → 连出 N 题（默认 10）→ 即时反馈 → 结算打卡。
   - 档位 × 知识点池（**按年级段前缀命名 lessonKey，N5 采纳**）：基础=`warmup:g1`（g1_* 一年级）、提高=`warmup:g2`（g2_* 二年级）、挑战=`warmup:g3`（g3_* 三年级，**含 g3_frac**——其 "p/q" 答案键盘 "/" 键可输入，已验证；N4 明确全纳入）。
   - 每档随机 3 个知识点循环出题。
4. **新视图 WarmupView.tsx**：复用 PracticeView 的数字键盘/即时反馈 UI 模式，题面走 `KOU_GENERATORS.gen(type)`。
   - **判题（I5 明确依赖）**：从 `window.SMART_GENERATORS.normalizeInput(input, answer)` 取判题函数（normalizeInput 挂在巧算引擎上；巧算引擎 main.tsx 已先于热身加载，运行时安全）。口算 answer 格式（number / "p/q" / 小数）与 normalizeInput 兼容性已交叉验证通过（String(answer).trim() + toNum 分数解析 + 1e-6 容差）。
   - **TS 声明（I2 落实）**：WarmupView 内 `const w = window as unknown as { KOU_GENERATORS?: {...}; KOU_META?: {...} }` 局部声明（对齐 PracticeView 现有模式），或新增 `global.d.ts`。
5. **防沉迷联动（I3 落实）**：WarmupView 结算时同时累加 `todaySec`（recordPractice 现有逻辑）+ `guard.addPlayed({count: total})` 累加 `playedToday`（每完成 1 题计数由 PracticeView/WarmupView 传 total，语义=N2"按完成题数"）。
6. **MeView stageProgress 兼容（I8 落实）**：stageProgress 遍历 lessons 时**跳过 `warmup:` 前缀 key**，热身前缀不混入阶段进度。

**涉及文件**：新建 `src/assets/kou_gen/kou_gen.js`；`src/src/main.tsx`；`src/src/App.tsx`（状态机加 warmup 态）；新建 `src/src/views/WarmupView.tsx`；`src/src/views/HomeView.tsx`（入口卡）；`src/src/views/MeView.tsx`（stageProgress 跳过 warmup 前缀）。

### 3.2 防沉迷限时（P2）

**现状**：store 仅 `todaySec` 累计，无档位/拦截/自律。
**方案（v0.2 修订：落实 B1 字段名对齐契约 + I3 两段式 + I4 todaySec 关系）**：

1. **store 扩展**（`StoreShape` 增字段，version 1→2 迁移）——**字段名严格对齐防沉迷契约 §4（B1 修订）**：
   ```ts
   guard: {
     minutePref: 5 | 10 | 15,        // 默认 5
     gamesPref: 10 | 20 | 30 | 0,    // 学科类口径=题量档（默认 10，0=不限）；字段名对齐契约（games 前缀统一，语义=题量）
     today: "YYYY-MM-DD",            // ⚠️ 与 store.checkin 同格式（B2 修订：不用契约 YYYYMMDD，避免跨日重置失效）
     playedToday: 0,                 // 今日已完成题量（契约字段名）
     delayMinTimes: 0,               // 时长延迟次数（上限 2，跨日重置）
     delayGamesTimes: 0              // 题量延迟次数（上限 2，跨日重置）
   },
   selfDaily: [],                    // 自律退出天数（YYYY-MM-DD，去重滚动）
   selfStreak: 0,                    // 连续自律天数
   selfLocked: false,                // 今日自律锁
   ```
   - **B2 修订**：guard.today / selfDaily 统一用 `"YYYY-MM-DD"`（与 store.todayStr()/checkin 同格式）。偏离契约字符串格式（契约用 YYYYMMDD）但内部一致，避免 guard.ts 用 store.todayStr() 比较时永不相等→每次加载重置。注释标明偏离原因。
   - **B3 修订**：store.tsx `load()` 现硬编码 `version: 1`（L69），必须重构迁移逻辑——`if (!parsed.guard) 补默认值; version = 2`，参考数学口算 `normalizeStore`（main.js L91-101）模式。写入方案涉及文件。
   - **I4 修订（todaySec 去留，方案 A）**：`todaySec` 保留为展示用累计字段（MeView 显示"今天练了 X"），guard.today/playedToday 独立做跨日重置；`todayReset()` 时**同步清零 todaySec**（修旧数据跨日不归零的潜在 bug）。
2. **逻辑层 lib/guard.ts**（纯函数，无 UI 依赖）——**API 对齐 LX_SHARED.guard 已落地 8 API 契约（I6 修订）**：
   - `setPrefs(guard, {minutePref, gamesPref})` / `startRound()` / `addPlayed({count, nowMs})`（count=本组题数）
   - `checkDue(guard, nowSec, playedToday)` → `{dueTime | dueQ | null}`（返回到点类型；startedAt 由调用方传入，guard 不持久化 cur——对齐契约 V0.8 口径）
   - `extend(guard, kind)`（时长 +5min / 题量 +10，上限 2 次）/ `enough(guard)`（记 selfDaily + 重算 selfStreak + 置 selfLocked）/ `isLocked()` / `streak()`
3. **拦截点——两段式（I3 修订）**：
   - **第一段·到点引导（练习中）**：`checkDue` 返回 dueTime/dueQ 时，弹**非阻塞引导条**「再做完这组就休息哦」（不暂停、不拦截输入，让做完本组）——对齐契约 §3 学科类「到点时先弹'本组完成即休息'引导」。
   - **第二段·组后二选（结算处）**：PracticeView/WarmupView 的 finished 分支，若到点 → 弹延迟/自律二选浮层（「延迟」= extend +5min/+10 题，上限 2 次；「我很自律，今天足够了」= enough → 结算页自律祝贺）——对齐契约 §2.2/§2.4。
   - 自律锁生效后：HomeView/StageView 新练习入口 → 提示「今天已经很自律啦，明天见」（isLocked 拦截）。
   - MeView 增加「防沉迷设置」区（时长档/题量档选择 → setPrefs）。
4. **计时与计数**：
   - PracticeView 已有 ms 计时器 → 结算时累计进 `todaySec`（现有 recordPractice 已累加）+ `guard.addPlayed({count: total})`（total = lesson.practice[level].count 或 WarmupView 默认 10；语义=N2"按完成题数"，完成 1 题 +1 由 total 体现）。
   - startedAt：PracticeView 用 useRef 持有起始 performance.now()，结算时传 `nowMs`（学科类无试错局豁免，startedAt 传 0 亦可——I7 明确）。

**涉及文件**：`src/src/lib/store.tsx`（schema + load() 迁移重构 + 新 API：setPrefs/addPlayed 等经 store 暴露）；新建 `src/src/lib/guard.ts`；`src/src/views/PracticeView.tsx`（到点引导条 + 组后二选浮层）；`src/src/views/WarmupView.tsx`（同上）；`src/src/views/HomeView.tsx`（自律锁拦截）；`src/src/views/MeView.tsx`（防沉迷设置 + 自律天数展示）。

### 3.3 家长报告打印（P3）

**现状**：MeView 有错题/打卡，无报告视图。
**方案（v0.2 修订：落实 I8 家长门槛 + N3 分页 + N4 渲染策略）**：
1. **报告视图 ReportView.tsx**（MeView 新增「家长报告」入口卡片 → 进入独立视图）：
   - **家长门槛（I8 落实）**：入口卡片对齐数学口算「标题 5 秒内连点 5 次」家长验证（或长按 2s），防儿童误触系统打印框；验证通过后进入 ReportView。
   - 今日反馈：完成题量/用时/各档最佳正确率
   - 近 7 天：打卡日/练习秒数/错题数（派生自 checkin/todaySec/lessons）
   - 阶段掌握度：7 阶段 × 完成讲次/总讲次（复用 MeView stageProgress 逻辑，**跳过 warmup: 前缀**）
   - 错题摘要：前 10 条
2. **打印实现**：视图内「🖨️ 导出/打印」按钮 → `window.print()`（对齐数独思维 v1.23，Chrome 61 file:// 可用；沿用其 30ms 延迟保手势上下文）。
   - **渲染策略（N4 采纳）**：ReportView 用**条件渲染**（`{view === 'report' && <ReportView/>}`），print 时 DOM 仅报告内容，避免隐藏元素被打印。
   - **分页（N3 采纳）**：`styles.css` 增 `@media print`——隐藏导航/按钮/非报告区（`display:none`）+ 报告区块 `page-break-after: always` 独占一页。
3. **数据只读**：报告全部派生，不写任何 store 字段（对齐数独思维"只读本地数据"）。

**涉及文件**：新建 `src/src/views/ReportView.tsx`；`src/src/views/MeView.tsx`（入口卡 + 家长门槛）；`src/src/styles.css`（@media print + 分页）。
