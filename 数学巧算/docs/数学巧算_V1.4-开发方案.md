# 数学巧算 V1.4.0 开发方案 · 家长报告增强

> 版本：v0.1（2026-09-29）· 迭代级别：**重要级**（新功能 + store schema v4→v5 跨文件接口变更）
> 流程：方案 v0.1 → Sisyphus 自审 → Oracle 外审 → 修订 v0.2 → 实施 → Sisyphus 审核报告

## 一、背景与目标

家长报告（ReportView，V0.5 家长门槛 + 打印）已含：今日反馈 / 近 7 天 / 阶段掌握度 / 错题摘要 / 薄弱方法 TOP3 / 下周建议 / 原理复述。但存在三块缺口：

| 缺口 | 现状 | 本轮 |
|---|---|---|
| **热身数据完全缺席** | 错题摘要与薄弱方法均排除 warmup（V0.5 I5 决策），六档使用情况、热身错题知识点薄弱（warmupMist 计数）家长完全看不到 | **A 热身面板**（六档分布 + warmupMist 薄弱 TOP3，纯展示） |
| **§2.2 明示「进步曲线」未落地** | store 无按日时间序列（lessons["warmup:gX"].best 只存最佳正确率，非历史） | **B 热身进步曲线**（store 新增 warmupDaily 按日聚合 → 近 14 天正确率 CSS 条形图） |
| **V1.3 重练闭环无统计展示** | ReviewView 答对移出/答错保留已闭环，但报告无"本周重练/掌握"数据 | **C 重练面板**（store 新增 reviewDaily → 近 7 天掌握/重练次数） |

目标：V1.4.0 补齐三块，家长报告成为「巧算课堂 + 口算热身 + 错题重练」三线完整视图。数据全部本地（儿童数据最小化）。

## 二、范围

- **A. 热身面板**（纯展示，零 schema 变更）：
  - 六档使用分布：`store.lessons["warmup:gX"].practiced`（总题数）条形
  - 热身错题知识点薄弱 TOP3：`store.warmupMist` 计数降序取 3，key `"gX:type"` 解析 → KOU_META 中文名（`window.KOU_META` 运行时读，兜底 type id）
- **B. 热身进步曲线**（schema v5）：
  - `store.warmupDaily: Record<date, WarmDayPoint>`，`WarmDayPoint = { total, correct, sec, sessions }`（当日聚合）
  - WarmupView 结算写入（recordWarmupDaily）；ReportView 近 14 天正确率条形图（CSS div，零依赖 Chrome 61 兼容）
  - 滚动上限 60 天（防 localStorage 膨胀）
- **C. 重练面板**（schema v5）：
  - `store.reviewDaily: Record<date, { mastered, retried }>`（掌握=答对移出数、retried=答错次数）
  - ReviewView 结算写入；ReportView 近 7 天 + 累计展示
- 打印兼容：新面板均入 `report-root`（现有 @media print 自动覆盖）

**不做**：历史秒数细分（todaySec 只有今日，练习秒数无历史存储，保持"仅打卡/题量"）；正确率按难度细分；SVG/canvas 图表库（离线零依赖红线）；KOU_META 表迁移（直接 window 读）；近 7 天热身叠加课堂打卡视图改造。

## 三、设计

### 3.1 新增纯逻辑文件 `src/src/lib/report.ts`（engine 可单测，参考 recite.ts/weak.ts 模式）

- `export interface WarmDayPoint { total: number; correct: number; sec: number; sessions: number }`
- `export interface ReviewDayPoint { mastered: number; retried: number }`
- `export function mergeWarmDay(existing: WarmDayPoint | undefined, point: WarmDayPoint): WarmDayPoint` —— 按日聚合（total+、correct+、sec+、sessions+）；**undefined 字段默认 0 防 NaN**（Oracle I5）
- `export function mergeReviewDay(existing: ReviewDayPoint | undefined, point: ReviewDayPoint): ReviewDayPoint`
- `export function pruneDaily(keys: string[], maxDays: number): string[]` —— 滚动裁剪：日期降序（YYYY-MM-DD lexicographic，零填充前提），留最近 maxDays，返回应删除的 key 列表（Oracle N3 否决：两步更易单测）
- `export function buildTrend(daily: Record<string, WarmDayPoint>, days: number, endKey: string): Array<{ key: string; total: number; correct: number; rate: number | null }>` —— **升序输出**（最旧→最新，Oracle I2），长度恰为 `days`；窗口 `[endKey-(days-1), endKey]` 外条目一律剔除；窗口内缺失日插 `{ key, total:0, correct:0, rate:null }` 占位（含当日）

### 3.2 store schema v4 → v5（跨文件接口变更）

`src/src/lib/store.tsx`：

- `StoreShape` 新增：
  - `warmupDaily: Record<string, WarmDayPoint>`（key = YYYY-MM-DD）
  - `reviewDaily: Record<string, ReviewDayPoint>`
- `version` 类型联合 `1 | 2 | 3 | 4 | 5`；`emptyStore()` 补默认 `{}` + `version: 5`
- `load()` **显式补默认**（Oracle I1，同 warmupMist 范式，防旧数据 null 覆盖）：`warmupDaily: parsed.warmupDaily || {}`、`reviewDaily: parsed.reviewDaily || {}` + `version: 5`
- `ProgressApi` 新增：
  - `recordWarmupDaily(point: WarmDayPoint): void`（mergeWarmDay 今日聚合 + pruneDaily 60 天上限）
  - `recordReviewDaily(point: ReviewDayPoint): void`（mergeReviewDay + pruneDaily 60 天）
- **recordPractice / retryMistake 等签名不动**

### 3.3 WarmupView 写入点

结算 effect（现有 `recordPractice` 旁）加 `recordWarmupDaily({ total, correct, sec, sessions: 1 })`：
- 定数：total=quantity、correct=correct、sec=Math.round(ms/1000)
- 计时：total=doneCount、correct=correct、sec=Math.round(ms/1000)
- 两模式统一（V1.2 口径）
- **Oracle N4**：`total/correct/sec` 在 effect 内计算一次，同时传 recordPractice 与 recordWarmupDaily，禁分散重算（防双写漂移）

### 3.4 ReviewView 写入点

- 新增 `retriedCount` state（答错时 +1）
- **新增 `useEffect` 结算写入**（Oracle B1 阻断级）：`useEffect(() => { if (finished) recordReviewDaily({ mastered, retried: retriedCount }); }, [finished])`（同 WarmupView recordPractice 模式，`// eslint-disable react-hooks/exhaustive-deps` 抑制告警）。**禁止在 checkAnswer 的 setTimeout 内联调用**——闭包捕获发起 render 的旧 mastered，队列清空题的 +1 不生效，UI 与存储不一致
- **中途退出不写**（与"不结算"语义一致，D 类决策）

### 3.5 ReportView 展示

- **🏃 口算热身面板**（插在「错题摘要」后）：
  - 六档分布：`WARM_LEVELS` map `store.lessons["warmup:"+lv].practiced` → 每档条形（题数 + 档名）
  - warmupMist 薄弱 TOP3：`store.warmupMist` 降序取 3 → key 拆解 `split(":", 2)`（Oracle N2 防御）→ `window.KOU_META` 查中文名（缺失兜底 type id；array.find 够用，N1 否决 Map）
  - **热身进步曲线**（近 14 天）：`buildTrend(store.warmupDaily, 14, todayKey)` → 条形图（每日正确率 % 高亮 / 无数据灰条 / 题数 title）；CSS 纯 div 实现（`styles.css` 补 `.trend-bar` + `.trend-panel`）
- **🔁 错题重练面板**（插在「下周建议」后）：近 7 天 `reviewDaily` 掌握数/重练次数条形或摘要 + 累计（全表 Σ mastered / Σ retried）
- 空态：无数据 → 引导文案（"做完一组口算热身/重练后在这里看进步"）
- **打印兼容（Oracle I4）**：`.trend-panel { break-inside: auto }`（panel 可分页）+ `.trend-panel .trend-bar { break-inside: avoid }`（单条不分页）；无数据灰条加边框（B&W 可辨识，不只靠色）

### 3.6 测试

- `tests/engine.mjs` 新增 **L13「报告统计纯逻辑」**：
  - `mergeWarmDay`：无既有 → 点本身；有既有 → 四字段聚合；**undefined sec 默认 0**（I5）
  - `mergeReviewDay`：聚合
  - `pruneDaily`：日期降序留最近 N；超限裁剪正确性（60/120 天上限模拟）；**恰 N 条边界（全保留删 0）**；**畸形 date key（"2026-9-5"）行为自洽**（I5）
  - `buildTrend`：补缺失日 rate=null、含当日、长度恰为 days、升序；**窗口外条目剔除**（I5）
- `tests/smoke.mjs` 扩展（家长报告场景）：
  - 家长报告热身面板渲染（六档/薄弱 TOP3/曲线容器）
  - 热身完成一组后 → report warmupDaily 有当日记录（evaluate localStorage）
  - 重练面板渲染（完成一组重练后 reviewDaily 有记录）
  - 打印按钮仍可用（回归）

### 3.7 合规复查

- 无网络引用 / 无 PK 排行 / 儿童数据最小化（warmupDaily/reviewDaily 纯本地滚动）；防沉迷不涉及。

## 七、风险与决策

| # | 风险/决策 | 处置 |
|---|---|---|
| R1 | 曲线用 CSS div 实现：无数据日高度为 0 视觉空白 | 无数据日画灰底占位条（总览连续感）；数据日按 rate 高度 + 题数 title 提示 |
| R2 | warmupMist 仅增不减（V1.2 R3），薄弱 TOP3 可能长期不变 | 展示层标注"累计错题次数"而非"当前薄弱"；配合 V1.4+ schema v5 mistakes.type 联动（AGENTS 待办已有） |
| R3 | warmupDaily/reviewDaily 滚动上限 | **升 120 天**（Oracle I3 改法 b：一学期 ≈ 126-140 天，120 天覆盖整学期；warmupDaily ~4.8KB + reviewDaily ~3.6KB ≈ 8.4KB 可忽略） |
| R4 | window.KOU_META 读不到（引擎加载顺序异常） | 兜底 type id 展示，不崩 |
| R5 | 今日多次热身（多组）合并聚合 | mergeWarmDay 按日累加 total/correct/sec/sessions——一日多组自然累计 |
| R6 | ReviewView 中途退出不写 reviewDaily | 与"中途退出不结算"语义一致；仅队列清空（全部掌握）结算写入 |
