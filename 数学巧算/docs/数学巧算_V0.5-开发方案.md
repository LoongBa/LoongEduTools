## 二、目标与原则

- **目标**：V0.5.0 交付「薄弱方法与建议」——①薄弱方法 TOP 3（按 lessonId 聚合错题数，反查讲次标题）；②下周建议（基于薄弱讲次 + 未完成讲次生成重练清单）；③家长报告'阶段掌握度'下钻薄弱提示（薄弱讲次标红）。不新增视图，纯 ReportView 增强 + 纯逻辑抽取。
- **原则**：
  - **数据驱动零配置**：薄弱判定 = 错题数（wrongCount 聚合），数据全部来自已有 `mistakes` + `lessons`；无需新 store 字段、无迁移。
  - **反查复用 V0.4 模式**：lessonId → STAGES 反查 stage/lesson 标题（与 recite 反查同构，`${s.stage}:${l.lesson_id}` 键）。
  - **只读不写**：统计/建议纯计算（useMemo），不动 store、不清错题（错题清理属未来功能决策，不在本迭代）。
  - **儿童数据最小化**：全部本地计算，家长报告打印不新增个人画像字段。
  - **最小化修复，不借机重构**：不重构 ReportView 现有 5 Panel 结构、不动 store。
  - **建议可执行**：下周建议落到具体讲次（"重练第 4 阶段《结合律配对》基础档"），不给泛泛之谈。

## 三、变更设计（逐项）

### 3.1 薄弱方法统计纯逻辑（P1 · 新建 lib/weak.ts）

**现状**：`mistakes: { key, lessonId, expr, answer, wrongCount }[]`，lessonId 形如 "s4l3"（**raw lesson_id，无 stage 前缀**，PracticeView L149 `lesson?.lesson_id` 写入）或 "warmup:g1"（WarmupView L150）；STAGES 提供 `stage.lessons[].lesson_id/title`。
**方案（v0.2 修订：落实 B1 + I3/I5）**：

1. **新建 `src/lib/weak.ts` 纯逻辑层**（引擎可测，**STAGES 注入不 import**——B1/I3 采纳）：
   ```ts
   export interface WeakLessonRef { stage: string | number; grade: string; title: string; }
   export interface WeakMethod {
     lessonId: string;      // raw lesson_id（"s4l3"）
     stageGrade: string;    // "四年级"（从注入的 index 反查）
     title: string;
     wrongCount: number;
     share: number;         // 该讲错题 / 非 warmup 总错题
     orphan: boolean;       // 反查不到 → 标记（用于调试/空态区分）
   }
   /** 构建 lessonId → 讲次元数据索引（一次遍历，ReportView useMemo 调用一次） */
   export function buildLessonIndex(stages): Map<string, WeakLessonRef>;
   /** 按错题聚合薄弱方法（limit 截断；warmup 排除；并列按 lessonId 字典序稳定） */
   export function topWeakMethods(mistakes, index, limit = 3): WeakMethod[];
   ```
   - **B1（双审独立发现·阻断）**：反查键 = `index.get(mistakes.lessonId)`（`l.lesson_id` 直比），**不是** `${s.stage}:${l.lesson_id}` 复合键——`mistakes.lessonId` 是 raw "s4l3"，复合键 "4:s4l3"（store.lessons 键）是另一套命名，混用必全量落空。recite 反查（ReportView L57）用复合键是对 store.lessons 键，与 mistakes.lessonId 无关。
   - warmup 排除：`mistakes.lessonId.startsWith("warmup:")` 跳过（I5 口径一致：错题摘要计数同样排除）。
   - 排序：错题数降序 → 并列按 lessonId 字典序（稳定输出）。
   - orphan 标记：`index.get()` 无匹配 → `{ orphan: true }` 计入结果（**不跳过**，供空态区分 + 调试），share 分母含 orphan 错题。
2. **engine.mjs L8「weak 纯逻辑」单测**（注入 mock stages/mistakes，I3 落实）：
   - 聚合正确（多 lessonId 求和 / warmup 排除 / 降序 / limit 截断 / 并列字典序）；
   - orphan 标记（mock 一个 index 里不存在的 lessonId）；
   - buildLessonIndex 解析（grade/title/stage 全字段）；
   - share 精度（保留 1 位小数）。

**涉及文件**：新建 `src/src/lib/weak.ts`；`src/tests/engine.mjs`（L8）。

### 3.2 下周建议生成（P2 · weak.ts 内 suggestWeek）

**现状**：无建议逻辑。
**方案**（纯规则生成，不引入 LLM/网络——离线 minitool 硬约束；v0.2 落实 I1/I6）：

```ts
export interface WeekSuggestion {
  kind: "weak" | "incomplete";
  lessonId: string;
  stageGrade: string;
  title: string;
  action: string;   // "重练基础档" / "建议本周学完"
}
export function suggestWeek(mistakes, lessons, stages, limit = 4): WeekSuggestion[]
```

- **来源一（重练薄弱）**：topWeakMethods(mistakes, index, 2) 中 wrongCount ≥ 2 且非 orphan → action "错题较多，建议重练基础档"。
- **来源二（补齐未完成）**：遍历 STAGES（按阶段序 1→2→…→6，**不含"X"拓展**）取 `done === false && practiced === 0`（`store.lessons[`${stageKey}:${lesson_id}`]`）的讲次 → **跨阶段按序取前 2 讲**（I6 明确"最靠前阶段"歧义）；action "建议本周学完，点亮阶段进度"。
  - **I1 修订**：recite-only 讲次（done=false 且 practiced=0 但有 recite）**照常推荐**（复述不置 done、不增 practiced，确属未完成；删除 v0.1 的"不推荐"排除措辞）。
- 合并去重（按 lessonId），kind 优先级 weak > incomplete；来源不足不强凑，返回不足 limit 条（I6）。
- **空态**：无薄弱且无 incomplete → `[]`，UI 显示"本周没有明显薄弱方法，继续按阶段推进即可 🎉"。
- **孤儿处理**：weak 来源含 orphan 错误题 → 在空态文案区分"有错题但未识别到对应讲次"。

**涉及文件**：`src/src/lib/weak.ts`（追加函数）。

### 3.3 ReportView 增强（P1/P2/P3 · 视图接线）

**现状**：ReportView 5 Panel；V0.4 已有 recite 反查模式 + print-truncate 打印截断。
**方案（v0.2 修订：落实 I2/I4/I5 + N1-N4）**：

1. **薄弱方法 Panel「🎯 本周薄弱方法」**（置于错题摘要之后、原理复述之前）：
   - `useMemo(() => buildLessonIndex(STAGES), [])` 一次构建 index；
   - `topWeakMethods(store.mistakes, index, 3)` 渲染 3 行：`{grade}《{title}》` + 错题数 + 比例条（ProgressBar，`share` 值）；
   - 每行右侧 Pill：`错 {n} 题`（n≥3 用 warm 色，否则 secondary）；or​phan 行不展示（课题外，仅调试可见）；
   - **空态两种（I2 采纳）**：`store.mistakes.length === 0` → "还没有错题，方法掌握得很好 💪"；`mistakes 有值但全 orphan` → "暂未识别到对应讲次的错题（{n} 条），建议清空后重新练习"；
   - 点击行 → 打开对应讲次？**V0.5 不做**（N1 采纳：ReportView 是家长门槛进入，跳学生练习流属 mode switch，UX 决策留 V0.6）。
2. **下周建议 Panel「📌 下周建议」**（置于薄弱方法之后）：
   - `suggestWeek(store.mistakes, store.lessons, STAGES, 4)` 渲染清单（📇 图标 + title + action 文案）；
   - 空态文案如上。
3. **阶段掌握度下钻提示（P3）**：**Pill 判定独立计算（I4 采纳）**——不依赖 topWeakMethods 的 top-3 截断，改按 stage 维度聚合：该 stage 任一讲 `wrongCount ≥ 2` 即亮 `· 有薄弱`（warm 色）。与薄弱 Panel 复用同一 index，单独计算每 stage 的薄弱标记。
4. **错题摘要计数口径（I5 采纳）**：标题计数改为排除 warmup 后的 `非 warmup mistakes 数`（与 share 分母一致）。
5. **打印语义（N2 采纳）**：两个新 Panel 数据量 ≤7 行，不做 print-truncate；沿用现有 Panel 样式（break-inside avoid 由 .report-root 规则兜底）。
6. **MeView 入口文案**补「薄弱方法 / 下周建议」。

**涉及文件**：`src/src/views/ReportView.tsx`；`src/src/views/MeView.tsx`（文案）。

## 五、风险与决策点

| # | 风险/决策 | 评估 | 处置 |
|---|---|---|---|
| R1 | "薄弱"仅按错题数判，未加权正确率 | wrongCount 直接反映重复错误；best 正确率含档位差异（challenge 低分≠方法差） | **错题数为主锚**；`share` 比例辅助；不做正确率加权（避免复杂化） |
| R2 | 孤儿 lessonId（stages 无匹配的历史错题） | 数据迁移/手工构造可能产生 | 跳过 + orphanCount 内部计数（不显示给用户） |
| R3 | 建议不落地（无跳转链接） | 纯展示，家长需自行去阶段页找 | V0.5 接受（Minimal）；未来可做"点击建议 → 直达讲次"（涉及跨视图跳转，另立迭代） |
| R4 | 新 Panel 打印撑页 | 数据量 ≤ 7 行，远小于 55+ 讲 recite | 不做 print-truncate；依赖 .report-root break-inside avoid |
| D1 | 建议是否包含 warmup 热身推荐 | 口算热身是基础层，非薄弱方法维度 | **不推荐 warmup**（薄弱=巧算方法讲）；若未来需要可扩展 |
| D2 | suggestWeek 的 incomplete 判定 | done=false 且 practiced=0 | **= "未开始"语义**；recite-only 讲次（复述不置 done、不增 practiced）照常推荐（I1 修订：确属未完成，删除 v0.1"不推荐"排除措辞） |
| D3 | 新 Panel 位置 | 信息层级：总览 → 薄弱 → 建议 → 明细 | 薄弱/建议置于错题摘要之后、原理复述之前（先诊断后行动） |
