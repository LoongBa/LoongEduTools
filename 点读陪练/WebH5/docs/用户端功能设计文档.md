## 1. 产品定位与设计原则

### 1.1 要解决的问题

教材配套 App 通常把「跟读打分」当作核心，孩子被评分牵着走；家长缺少可执行的陪练动作，也不知道孩子卡在哪。本产品把定位放在**每天 15–20 分钟的亲子陪练流程**上：不打分、不排名、不比较，只给孩子一个明确的当日任务和「回哪几张卡再练一次」的补救路径。

### 1.2 硬性设计约束（不可违反）

以下约束已在代码中落地，任何后续改动都必须保持：

1. **不做 PK / 排行榜 / 分数对比**，不出现「击败了 xx% 的同学」这类文案。
2. **全程不使用红色表达失败**。状态色只有：完成（草绿 `--lit`）、提醒（暖黄 `--warm`）、辅助（天蓝 `--sky`）、待办（中性 `--idle`）。自评「需要帮助」用中性灰表达，不用警示色。
3. **孩子读的正文 ≥ 18px**。句卡主句使用 `--text-sentence`（clamp 1.75rem→2.5rem）；最小字号出现在辅助说明（11–13px），那些是给家长看的。
4. **圆角统一 12–16px 量级**，由 `--radius: 0.75rem` 派生（`rounded-2xl` / `rounded-3xl`）。
5. **原创 IP**，不复刻教材角色、不使用教材原版音频/文本；插画为 AI 生成的白底扁平卡通图。
6. **儿童数据最小化**：不采集姓名、生日、头像、麦克风数据外传等任何信息。录音只在内存回放，不落存储、不外传。清空数据入口在「我的」页且必须二次确认。
7. **双版本**：在线互动版 + A4 黑白打印版（五件套），打印版永远走浅色线稿，与屏幕主题解耦。
8. **动效温和可打断**，禁止闪烁催促类动画；`prefers-reduced-motion` 下所有 `anim-*` 关闭。

### 1.3 视觉取向

活泼但克制、学习优先、护眼。整站是手机比例画幅（`max-w-[520px]` 居中，两侧留白），底部四格导航，没有顶栏——页面标题由各页自己的 `PageHead` 承担。

## 4. 核心业务流程

### 4.1 学习节奏模型

```
一册 = 6 个单元（Unit 1–6）
一单元 = 一周 = 5 个陪练日（Day 1–5）+ 周末检验
一天 = 四个环节：开场复习(warm) → 新学(new) → 巩固(drill) → 收尾(wrap)
一环节 = 若干句卡（每单元共 8 张：warm 2 / new 3 / drill 2 / wrap 1）
```

Day 主题句来自 `DAY_TITLES`（`src/data/content.ts:694`）：我们一起做的事 / 把昨天听到的说出来 / 换我来问问题了 / 把句子说得更长一点 / 今天全部串起来。

### 4.2 周次与「今天是 Day 几」的推算

`weekInfo()`（`store.ts:249`）以**周一为一周起点**，内容起始周锚定在 `2026-09-07`：

```
week = max(1, floor((本周一 - 2026-09-07) / 7天) + 1)
dow  = (getDay() + 6) % 7      // 0=周一
isWeekend = dow >= 5           // 周六周日
```

`currentDay`（`store.ts:322`）：在本周内从 Day1 往后找第一个 `finished !== true` 的槽位，若 1–5 全满则返回 `6`（表示进入检验日）。

首页取 `dayNo = Math.min(currentDay, 5)`，所以五天全完成后首页仍显示 Day5 并允许回看。

### 4.3 每日陪练完整流程（`/daily`）

```
进入 /daily
  ├─ todayRecord 已 finished？
  │    └─ 是 → 显示「今天已经打过卡啦」三选面板
  │             [回看今天的句子] → goStage(0)，不再点亮
  │             [重新开始一次]   → 回首页
  │             [先回首页]       → 回首页
  │    └─ 否 ↓
  ├─ dayInWeek = startDay()
  ├─ stageIdx 初始 = 第一个未完成的环节（断点续练）
  ├─ StageBar 展示四环节；仅「已完成」环节可点击回跳（onJump 限制 i < stageIdx）
  ├─ 主体渲染 SentenceCardView（key = card.id 触发 anim-card 入场）
  │    · 点插画区 → 朗读整句；左右滑动 >56px → 上/下一句
  │    · 点句中单词 → 单词点读 + 释义浮起（activeWord 高亮 1.4s）
  │    · [听一听] 正常语速；[慢一点] 切慢速并立即朗读；[按住跟读] 录音
  ├─ advance()
  │    · 未到末句 → cardIdx++
  │    · 到末句   → markStage(dayInWeek, stage)
  │       ├─ 非最后环节 → StarBurst + 620ms 后 goStage(i+1)
  │       └─ 最后环节   → StarBurst，主体换成 WrapCard（今日词汇清单，最多 12 个）
  ├─ [记下今天认识的词，完成打卡] → finishDay(dayInWeek, 本单元全部词) → 跳 /card
  └─ 左上返回键 backHome()
       ├─ 已完成 or 一个环节都没做完 → 直接回首页
       └─ 否则弹遮罩：[先记下已完成部分](markStage 当前环节) / [稍后再说，继续练]
```

底部文案实时显示「{环节名}环节 · 已接触 N 个词」，`touchedWords` 按 `STAGES.indexOf(c.stage) <= stageIdx` 累计去重（`daily.tsx:49`）。低年级模式开启时追加提示「句子显示得更大一些」。

> **实现事实**：`littleKid` 只影响句卡字号（30px/38px），页底提示文案与之对齐为「低年级模式：句子显示得更大一些」。

### 4.4 打卡与词卡点亮规则

`finishDay(dayInWeek, words)`（`store.ts:362`）做四件事：

1. 找到本周同 `dayInWeek` 的记录，没有则新建；
2. `stagesDone` 并集补全为四环节，`finished = true`；
3. `touched[word] = Date.now()`（用于「三天没碰」复习提醒）；
4. `litWords = 去重(旧值 ∪ words)`。

传入的 `words` 是**整个单元的全部句卡词**（`daily.tsx:79`），不是当天环节的片段——即完成一天就把本单元的词一次性收进收藏册。这是有意为之的宽松收集规则（「收集是成就，不是考核」）。

`markStage` 只写 `stagesDone`，不影响 `finished`，也不点亮词卡。

### 4.5 周末检验与小阅兵开放条件

```
open = litDays.length >= 5 || isWeekend
```

不满足时 `/review` 渲染引导态（`review.tsx:44`）：「还差 N 天就能来检验」+ 回首页按钮，不暴露能力条目。

满足后逐条自评，`choose(key)`：
- `rateSkill(skillId, key)` 写入本周记录（同周同 skillId 覆盖旧值）；
- 若 `key === "help"` → 额外调用 `reviewSkills(unitId, {skillId: "help"})`，副作用是把该能力 `remedy.stage` 对应环节的所有句卡词并入 `litWords`（补练也算接触），同时刷新全单元词的 `touched`；
- 面板下方展开补练提示 `remedy.hint` + `[去补练]` → `/daily`；
- 评完第 4 条触发 `StarBurst`。

`allPassed = 四项都是 can 或 almost` → 显示「本周四项都过关啦」+ 打开成长卡 / 打印记录单。

成长卡的草稿态判定：`passed < 4` 时 `isDraft = true`，副标题显示「还差 N 项能力未过关」，并在页尾挂一条去 `/review` 的引导卡。

### 4.6 复习提醒（柔性，不施压）

`dueReview`（`store.ts:442`）：`touched` 中时间戳早于 `now - 3天` 的词。

- 首页：仅当 `dueReview.length > 0` 时出现一条左侧暖黄描边的横幅 → `/words`；
- 词卡页：命中词打「该复习啦」暖黄角标，进度条下方显示「N 张三天没碰了，翻一翻就算复习」，否则显示「最近的词都还热乎着」。

文案一律用「翻一翻就算复习」，不出现「逾期」「未完成」。

## 5. 内容层规格（`src/data/content.ts`）

### 5.1 规模

| 维度 | 数量 |
|---|---|
| 单元 | 6（u1–u6） |
| 句卡 | 每单元 8 张，共 48 张 |
| 词卡 | 每单元 12 个，共 72 个（`TOTAL_WORDS` 由 reduce 算出） |
| 歌曲 | 每单元 1 首，4–6 行 |
| 能力检查 | 每单元 4 项，共 24 项 |

六个单元主题：U1 My Classroom 我们的教室 / U2 My Friends 我的朋友 / U3 My Schoolbag 我的书包 / U4 My Home 我的家 / U5 Food We Like 我们喜欢的食物 / U6 Jobs and Places 职业与场所。

### 5.2 句卡的环节分布（固定配比）

`warm × 2 → new × 3 → drill × 2 → wrap × 1`。ID 规则 `u{单元}-{序号}`，序号与环节顺序一致（如 u1-3/u1-4/u1-5 是 new）。

每张句卡带 `words[]`（句中可单独点读的词 + 中文释义），这些词同时是该单元词卡的来源。

### 5.3 能力检查的补救映射

每个 `SkillCheck` 必带 `remedy: { stage, hint }`。`hint` 要写到具体卡号（如「回到新学第 4 张与巩固第 6、7 张句卡」），因为这条文案会原样出现在小阅兵和成长卡建议里。`stage` 决定 `reviewSkills` 点亮哪些句卡的词。

### 5.4 辅助导出

```ts
STAGES: Stage[]                        // ["warm","new","drill","wrap"]
stageLabel(s: Stage): string           // 环节中文名
cardsByStage(unit, stage): SentenceCard[]
unitOf(id: string): Unit               // 找不到回落 UNITS[0]
interface SentencePart { text: string; clickable: boolean; cn?: string }
splitSentence(en, words?): SentencePart[]
  // 按空白切分并剥标点；words[] 中**不含空格**的词条会回填 cn 释义，
  // 供句卡点读时浮出中文。词组（each other / pencil case）不参与回填，
  // 避免把碎片误标成词组意思。
shuffled<T>(list, seed): T[]           // 固定种子乱序，用于打印连线题右列
DAY_TITLES: string[]                   // 5 条
TOTAL_WORDS: number                    // 72
```

`splitSentence` 用 `en.split(/(\s+)/)` 保留空白片段，`clickable` 由「剥掉 `.,!?;:` 后长度 > 0」决定；命中词典的片段带上 `cn`，句卡点读时会在该词下方浮出中文气泡（`sentence-card.tsx`）。

## 6. 状态与存储（`src/lib/store.ts`）

### 6.1 存储约定

- key：`dianedu.progress.v1`（单 key 存整个 `ProgressState`）
- 读写时机：`useProgress()` 首次挂载 `load()`；每次 `state` 变化在 `useEffect` 中 `save(state)`
- 容错：`load()` / `save()` 均 try/catch，失败时 `storageOk = false`，「我的」页顶部提示「本地存储暂时不可用，内容都能正常看，只是进度不会被记录」
- 向后兼容：`settings: { ...DEFAULT_SETTINGS, ...(parsed.settings ?? {}) }`。**新增设置字段不需要数据迁移**，旧存档自动补默认值；代价是旧存档里已显式写入的布尔值不会被新默认值覆盖（例如老用户仍会保留 `followSystem: false`）
- 数组字段防御：`days` / `skills` / `litWords` 非数组时回落 `[]`，`touched` 非对象时回落 `{}`

### 6.2 `useProgress()` 返回契约

这是全站唯一状态入口，返回类型别名为 `ProgressApi`。

**状态与派生值**

| 名称 | 类型 | 含义 / 算法 |
|---|---|---|
| `state` | `ProgressState` | 原始存档 |
| `unit` | `Unit` | `unitOf(state.unitId)` |
| `week` | `number` | 当前周号 |
| `isWeekend` | `boolean` | 周六/周日 |
| `today` | `string` | 今日 ISO 日期 |
| `currentDay` | `number` | 本周第一个未完成日（1–5，全满为 6） |
| `litDays` | `number[]` | 本周 `finished` 的 dayInWeek 列表 |
| `todayRecord` | `DayRecord \| undefined` | 按 `date === today` 查找 |
| `stats` | 见下 | 汇总统计 |
| `dueReview` | `string[]` | 超 3 天未接触的词 |
| `storageOk` | `boolean` | localStorage 是否可用 |

`stats`：`totalDays`（finished 记录数）、`streak`（从最近一条往前逐日比对期望日期，遇断即停）、`collected`（`litWords.length`）、`totalWords`（常量 72）、`unitsDone`（finished 记录里去重 unitId 数）。

**方法**

| 签名 | 作用 |
|---|---|
| `startDay(): number` | 已有今日记录则沿用其 dayInWeek；否则从 currentDay 起跳过已 finished 槽位，上限 5 |
| `markStage(dayInWeek, stage)` | 建/改记录，`stagesDone` 去重追加；已含该 stage 则不变 |
| `finishDay(dayInWeek, words)` | 见 §4.4 |
| `rateSkill(skillId, rating)` | 同周同 skillId 覆盖 |
| `skillRating(skillId): SelfRating \| undefined` | 只查本周 |
| `reviewSkills(unitId, ratings)` | 刷新全单元 touched；对 help 项点亮 remedy.stage 句卡的词 |
| `setUnit(unitId)` | 切换当前单元 |
| `patchSettings(patch)` | 浅合并设置 |
| `resetAll()` | 回到 `emptyState()`（含设置恢复默认） |

### 6.3 主题体系

> ⚠️ 本节描述**当前代码状态**。用户已提出「取消浅/深二分、整体转深色」的调整方向，该调整暂缓执行；一旦落地，需同步改写本节与 §12。

- `ThemeKey` 七值：浅色 `sprout`(嫩芽黄绿，`:root` 默认) / `matcha`(抹茶豆沙) / `warm`(暖米) / `sky`(天蓝)；深色 `moss`(苔夜黄绿) / `forest`(森林夜绿) / `night`(墨夜)。
- `THEMES[]` 每项：`{ k, t, note, dark?, swatch: [c1,c2,c3] }`，供「我的」页两列色板卡片渲染。
- `isDarkTheme(k)`：读 `dark` 标记。CSS 侧与 canvas 侧的深色判据**统一收敛到这里**（CSS 用 useEffect 同步的 `html.dark` class），禁止再按主题名枚举。
- `systemPrefersDark()`：读 `prefers-color-scheme`，异常时按浅色。
- `resolveTheme(pref, followSystem)`：开关关闭直接返回 pref；开启则按系统偏好查 `DARK_PAIR` / `LIGHT_PAIR`。
- `DARK_PAIR`：sprout→moss, matcha→forest, warm→night, sky→night, 深色自身映射自身。
- `LIGHT_PAIR`：sprout→sprout, matcha→matcha, warm→warm, sky→sky, moss→sprout, forest→matcha, night→warm。
- `DEFAULT_SETTINGS.followSystem = true`（深浅默认跟随系统）。
- 根元素生效逻辑集中在 `useProgress` 的 useEffect（`store.ts:266`）：字号 → `style.fontSize`（large=18px / normal=16px）；主题 → `dataset.theme` + `classList.toggle("dark")`；底色档 → `STANDARD_BG` / `SOFT_BG` 覆盖 `--background`（浅色 soft 为空字符串表示不覆盖；深色语义相反，standard 略提亮、soft 更暗）。开启跟随系统时注册 `matchMedia(...).addEventListener("change", apply)`，cleanup 中移除。
- 预览参数：`?theme=xxx` → `PREVIEW_THEME`，只挂根元素、不落盘、优先级高于跟随系统。用途是让用户「先看效果再决定要不要用这套配色」，也是沙箱截图验收非默认主题的唯一手段。

**防漏机制**：`DARK_PAIR` / `LIGHT_PAIR` / `STANDARD_BG` / `SOFT_BG` 都是 `Record<ThemeKey, …>`。新增 ThemeKey 时 TS 会直接报错要求补齐四处，不要绕过（不要用 `Partial<>` 或 `as` 断言）。

## 7. 语音能力（`src/lib/speech.ts`）

### 7.1 `speak(text, opts?)`

```ts
interface SpeakOptions { slow?: boolean; onEnd?: () => void }
speak(text: string, opts?: SpeakOptions): boolean   // 返回是否真正发声
```

- 语音选择：模块级缓存 `cachedVoices`，过滤 `/^en/i`，优先 `en-US`；监听 `voiceschanged` 刷新（部分浏览器首次调用返回空数组）。
- 参数：`rate` 慢速 0.62 / 正常 0.92，`pitch` 1.05。
- 每次调用先 `cancel()`，保证不会叠音。
- 降级：不支持 `speechSynthesis`、文本为空、或抛异常 → 返回 `false`，由调用方展示文字提示（句卡显示「重音在加粗的音节上…」，词卡/点唱台显示设备不支持说明）。
- `onEnd` 同时挂在 `onend` 和 `onerror` 上，确保高亮状态一定复位。

### 7.2 `useRecorder()`

```ts
{ supported, state: "idle"|"recording"|"ready"|"denied", error, start(), stop(), play(), discard() }
```

- `supported`：`navigator.mediaDevices.getUserMedia` && `"MediaRecorder" in window`。不支持时句卡显示灰色占位「没有麦克风也能完成今天的陪练」，流程不阻塞。
- `start()`：申请权限 → `new MediaRecorder(stream)` → 收集 chunks → `setState("recording")`；失败 → `state="denied"` + `error="没有拿到麦克风权限"`。
- `onstop`：立即停掉所有 track（释放麦克风指示灯）；`blob.size > 1000 && urlRef.current === null` 才生成 objectURL 并置 `ready`，过短视为误触回到 `idle`。
- `play()`：`new Audio(url).play()`，仅内存回放。
- `discard()`：revokeObjectURL + 停 track + 回 idle。句卡在 `card.id` 变化时自动调用（`sentence-card.tsx:44`）。
- 组件卸载 cleanup 调 `cleanup`；`pagehide` 与 `visibilitychange(hidden)` 时若在录制则强制 `stop()`。

> **交互例外说明**：react-design 规范一般要求只用 `onClick`。「按住跟读」是连续手势（press-to-talk），确实需要原始指针序列，因此这里用 `onPointerDown` / `onPointerUp` / `onPointerLeave` 是指南允许的例外，不要改成 click。插画区的左右滑动同理。

## 9. 设计系统与样式契约（`src/styles.css`）

### 9.1 Token 全集

每个主题块（`:root` 与 6 个 `[data-theme]`）必须提供同一套 token，缺项会导致该主题下某处颜色继承自上一层：

```
背景与文字：--background --surface-deep --foreground --muted-text
容器：      --card --card-foreground --popover --popover-foreground
主色：      --primary --primary-foreground --primary-deep
次级面：    --secondary --secondary-foreground --muted --muted-foreground --accent --accent-foreground
描边焦点：  --border --input --ring
状态语义：  --lit --lit-soft --on-lit --warm --warm-soft --sky --sky-soft --idle --idle-foreground
遮罩阴影：  --overlay --shadow-soft --shadow-lift
```

`@theme inline` 把这些映射成 Tailwind utility（`bg-primary`、`text-on-lit`、`bg-lit-soft` 等）。另有 `--radius-sm…3xl`（基于 `--radius: 0.75rem` 派生）、`--text-child/sentence/display`、`--font-sans`。

**组件侧铁律**：只允许 `var(--*)` 与 theme utility，禁止写死色值。唯一豁免是打印线稿（`#111` / `#fff`，必须与屏幕主题无关）和 canvas 兜底色。

### 9.2 跨主题工具类

| 类名 | 用途 | 深色分支 |
|---|---|---|
| `.panel-border` | 卡片描边。浅色半透明（`color-mix` 70% transparent），深色实色——深色下阴影几乎不可见，层级只能靠描边 | `.dark .panel-border` |
| `.ip-plate` | IP 插画是白底生成图，深色主题下垫浅底板（`oklch(0.95 0.02 130)`）维持「圆角白底」观感 | `.dark .ip-plate` |
| `.bg-surface-deep` / `.text-muted-text` / `.text-primary-deep` | 未注册进 `@theme` 的三个补充 utility | — |
| `.shadow-soft` / `.shadow-lift` | 两级阴影 | 值随主题变深 |
| `.tap-target` | `min-height: 48px` 触控面积 | — |
| `.bg-overlay` | 遮罩层底色（引用 `--overlay`） | 值随主题变深 |

**深色判据只能是 `.dark` class**（由 useEffect 同步到 `<html>`）。历史上曾按 `[data-theme="forest"], [data-theme="night"]` 枚举，每加一套深色主题都要回来补选择器，漏一个就出现「深色下描边消失」。

### 9.3 动效

| class | keyframes | 时长 | 用途 |
|---|---|---|---|
| `.anim-pop` | press-pop | 0.24s | 按钮按下反馈（听一听播放中） |
| `.anim-star` | star-rise | 1.5s forwards | `StarBurst` 星星飘散 |
| `.anim-float` | soft-float | 3.6s infinite | 朗读时插画轻微浮动 |
| `.anim-word` | word-hint | 0.42s | 单词点读放大 |
| `.anim-in` | ring-in | 0.42s both | 元素入场上移 |
| `.anim-card` | slide-card-in | 0.32s both | 句卡换页横向滑入（`--slide-from` 可控方向） |

`@media (prefers-reduced-motion: reduce)` 下六者全部 `animation: none !important`。滚动入场另用模板的 `reveal` / `reveal-up` 等 class（`src/lib/reveal-engine.ts`，`main.tsx` 中 `initRevealEngine()` 接线），**严禁手写 IntersectionObserver 或自创 `opacity:0` 等待 JS 显示的类**。

### 9.4 打印约定

`@media print`：`@page { size: A4 portrait; margin: 14mm }`，`html,body` 强制白底，`.no-print` 隐藏，`.print-only` 显示，`.print-sheet` 重置 position/width/shadow/border/padding/margin，`.print-break { break-before: page }`。

打印永远走浅色线稿，与屏幕主题完全解耦——这是深色主题下仍需保证可用的关键设计。查看 A4 预览需用桌面视口（`read-browser-screenshot --h5=false`）。

### 12.3 V0.9.1 会话调整（点唱台 / 成长卡 / 我的 / 听写 / 导航）

> 本会话（V0.9.1）对产品形态做了一轮集中调整，核心目标：**点唱台从"逐句播放"升级为"原创儿歌整曲 + 教材跟读"双形态；成长卡从全局统计改为单元学习态势座舱；"我的"页按家长/孩子分流；新增词汇听写**。以下为已实现的变更记录。

**点唱台（`_layout.jukebox.tsx` + 数据层）**
- 歌曲列表按类型区分：每单元最多两首——**原创歌曲**（`song.kind === "original_song"`，暖色标签 + 🎵 MusicIcon）与**教材跟读**（`textbook_lyrics`，蓝色标签 + 小喇叭 SpeakerIcon）；歌名右侧带 "Unit N" 小标签
- 原创歌曲 = 整曲播放：`song.json` 提供 `audio`（人声轨）/ `instrumental`（伴奏轨）/ `duration` / `lyrics[{start,end}]` → 双 `<Audio>` 并行，进度条（拖动 seek 双轨同步）、当前句高亮（timeupdate 驱动）、点击歌词跳句、上/下一句（seek 到句 start）
- 原创歌曲三态切换（调速区左侧）：**原曲**（人声+伴奏）/ **伴奏**（仅伴奏，卡拉OK）/ **清唱**（仅人声）——`trackMode` state，切换即时改 `muted`
- 教材跟读 = 逐句 TTS 连播：`textbook_lyrics.json`（`lines[{en,zh,audio,chant_id}]` + `chants[]` 分组）+ `textbook/*.mp3`；**无**进度条/三态/听唱按钮（逐句模型）

## 13. 扩展指南

### 13.1 新增一个单元

在 `UNITS` 数组追加一个 `Unit`，严格照抄现有结构：8 张句卡（warm×2 / new×3 / drill×2 / wrap×1）、12 个词、1 首歌、4 项能力。ID 按 §8.1 规则。无需改任何页面——首页、词卡、点唱台、打印、小阅兵全部由数据驱动。

自检清单：
- [ ] 每张句卡的 `words[].text` 尽量能在同单元 `words[]` 中找到对应词条（否则该词永远不会成为独立词卡）
- [ ] 4 项能力的 `remedy.stage` 覆盖至少两个不同环节（否则补练路径过于集中）
- [ ] `remedy.hint` 写到具体卡号
- [ ] 歌词行数 4–6，每行英文 ≤ 8 词（朗读时长控制在跟唱停顿内）

### 13.2 新增一个设置项

1. `Settings` 接口加字段 → `DEFAULT_SETTINGS` 给默认值；
2. 在「我的」页对应 `Section` 内加控件（开关用 `Switch`，档位用 `Segmented`）；
3. 若影响根元素，扩 `useProgress` 的 useEffect 并把新字段加入依赖数组；
4. **不需要写迁移**——`{...DEFAULT_SETTINGS, ...saved}` 自动为旧存档补默认值。

### 13.3 新增一套主题

1. `styles.css` 加 `[data-theme="xxx"]` 块，**§9.1 的 token 全集一个都不能少**；
2. `ThemeKey` 联合类型加值；
3. `THEMES[]` 加一项（含 `note`、`swatch` 三色、深色则 `dark: true`）；
4. 补齐 `DARK_PAIR` / `LIGHT_PAIR` / `STANDARD_BG` / `SOFT_BG` 四处 —— TS 编译会强制你补，不要用断言绕过；
5. 深色分支一律走 `.dark`，**不要新增按主题名枚举的选择器**；
6. 验收：`?theme=xxx` 逐页核对首页 / 天天见 / 词卡 / 成长卡 / 小阅兵 / 我的，重点看描边可见性、IP 底板、`--on-lit` 文字对比、canvas 导出图配色。

### 13.4 新增一个页面

在 `src/routes/` 建 `_layout.xxx.tsx`（`createFileRoute("/_layout/xxx")`），`routeTree.gen.ts` 会在下次 `dev`/`build` 自动更新。若需要进底部导航，改 `_layout.tsx` 的 `NAV` 数组（注意四格 grid 布局，超过 4 个要同时改 `grid-cols-4`）。

自建组件一律**具名导出** `export function Xxx`，紧耦合父子组件写在同一文件（可到 ~320 行），普通文件软上限 ~260 行。

### 13.5 涉及后端的演进方向（当前刻意不做）

如果将来要多设备同步，正确路径是：加载 meoo-cloud 技能 → 建 `progress` 表（一行一设备，字段对齐 `ProgressState`）→ 把 `store.ts` 的 `load`/`save` 换成「本地优先 + 云端异步上行」。**页面层不应感知存储介质变化**，所有读写继续走 `useProgress()`，这是当前抽象留给未来的唯一接缝。

## 附录 B：经验沉淀

- Tailwind v4 下 `getPropertyValue("--primary")` 返回 `oklch(...)` 原始串，Canvas 2D 不一定接受；「临时元素 + `style.color` + `getComputedStyle().color`」让浏览器换算最稳。
- 多主题只覆盖与色相相关的 token，状态色 `--lit` / `--sky` 跨主题保持一致，避免「完成=绿色」的语义被主题改掉。
- 深色主题下阴影几乎不可见，卡片层级要靠实色描边维持；`color-mix` 做浅/深分叉比在组件里写两套 class 干净。
- 「柔和底色 / 标准底色」这类二档设置在深色主题下语义要反过来：standard = 略微提亮的深底，soft = 更暗一档，绝不能复用浅色的提亮逻辑。
- IP 插画是白底生成图，深色主题下不能靠 `bg-card` 承托，需 `.ip-plate` 显式垫浅底板 —— 但这也正是当前深色主题「大面积浅色块刺眼」的来源之一。
- 儿童产品的「复习提醒」要用机会语气（「翻一翻就算复习」）而不是任务语气（「你有 N 个词逾期未复习」）。
