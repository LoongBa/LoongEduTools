## 0. 需求与目标

### 0.1 产品定义

**教材同步的点读陪练工具**——不复制人教版素材（图像/音频），只同步教材单元的话题/词汇/句型/语音骨架，句子、插图、音频全部原创生产（句句自写、图图自绘、音音自产），复用既有点读/热区底层能力，覆盖小学 1-6 年级上下册全部单元。

### 0.2 新增能力（相对现有生产方法论）

| # | 能力 | 说明 |
|---|------|------|
| 1 | **双模式** | 离线 zip（现状，Chrome 61 兼容）+ 在线 Web 版 |
| 2 | **在线认证** | 手机号 + 产品授权口令激活 → 设置密码 → 手机号密码找回；**微信 OAuth 预留** |
| 3 | **内容范围** | 1-6 年级上下册全单元（12 册，远超现有四上 6 单元） |
| 4 | **听写（自听）** | 词/句听写：播放 → 输入/点选 → 判定 → 错题集 |
| 5 | **歌曲跟唱（卡拉OK）** | 伴奏 + 滚动歌词同步 + AI 配音跟唱 |

### 0.3 版权红线（延续，全产品硬约束）

> **产品内不出现教材原句、原图、原音。** 只同步"知识点骨架"（话题/词汇表/句型结构/语音点 = 事实信息）。

⚠️ **卡拉OK 伴奏红线的澄清**：歌曲同样**原创自产**（AI 生成原创曲目或自编），伴奏轨来自**自产歌曲的 instrumental 轨**（生成时即得）或 **demucs 对自产音频分离**。**不采用人教原曲去人声**——"教材音频去人声"仅作为技术做法参考（人声分离技术路线），素材必须自产。

## 1. 总体架构

### 1.1 架构原则：内容 SSOT（单源真值），传输层分叉，表现层独立

```
                    ┌─────────────────────────────────────┐
  内容生产（LLM+人工）──▶│ content/ 内容仓库（SSOT）          │
                    │  content.json + skeleton.json       │
                    │  + audio/（原始 mp3）+ images/        │
                    └──────────┬──────────────────────────┘
                               │
                    ┌──────────┴──────────────────────────┐
                    ▼                                      ▼
         【离线管线】build_framework.py           【在线管线】publish_online.py
         → base64 内联音频+图片                    → JSON/音频/图片 上传 COS
         → 单 HTML + Chrome 61 兼容               → API 索引 + CDN 直引
         → zip → 小红书/自营分发                    → 在线 SPA 消费（现代浏览器）
```

- **共享层**：content.json schema（唯一内容真值）、skeleton.json、原始素材
- **分叉层**：
  - 离线：全部内联、Chrome 61 兼容（小红书 webview + 未知设备）
  - 在线：URL 直引、现代浏览器（Chrome 90+/Safari 14+），可上 Vue/Svelte SPA
- **不做**：离线/在线前端代码复用（表现层独立演进，共享 schema 已够）

### 1.2 内容仓库结构

```
RedTools/content/  （或独立仓 edu-content/）
├── manifest.json               # 全册总目录：grade/volume/unit/version/hash
├── grades/
│   └── G04/V1/
│       ├── manifest.json       # 册级：单元清单 + 骨架索引
│       ├── units/U01/
│       │   ├── content.json    # ★ 单元内容 SSOT（8 模板 + 听写 + 歌曲）
│       │   ├── skeleton.json   # 知识点骨架（词汇/句型/语音清单）
│       │   ├── audio/          # 原始 mp3（非 base64）
│       │   └── images/         # 原始 png（非 base64）
│       └── assets/             # 册级共享（IP 角色、UI 素材）
└── _shared/                    # 跨册共享（小虎一家 IP、音效、字体）
```

- 单元 content.json 带 `version` + `content_hash`；manifest 聚合索引
- 构建按 hash 增量跳过未变更单元
- Git tag 里程碑（`content-v4a-6units` 等）

## 2. 双模式内容管线（一次生产、双端消费）

### 2.1 离线管线（现状复用）

```
content/（U01 content.json + audio + images）
  → build_framework.py（ToolConfig：series/tool/version/book/素材目录）
  → 图片 PIL→WebP 1200w；音频 ffmpeg→base64→audio/<key>.js
  → data.js（window.APP_DATA 含 meta/units/pages/tracks）
  → 图标角标 → zip（index.html 根目录）→ publish/<系列>/
  → 解压测试版（双击即测）
```

保持 Chrome 61 兼容（ES2017 上限、无 flex gap、Web Audio base64 播放）。

### 2.2 在线管线（新增）

```
content/ → publish_online.py（新脚本）
  → 上传 COS：/content/<grade>/<vol>/<unit>/*.json + /audio/*.mp3 + /images/*.png
  → 生成 /api/manifest（册/单元索引 + version + hash）
  → CDN 加速（COS 自带）→ 在线 SPA fetch 消费
```

**在线 SPA**（新建目录 `RedTools/online-app/`）：
- 技术选型：Vue 3 + Vite（或 Svelte——二选一后固定），目标浏览器 Chrome 90+/Safari 14+
- 复用点读/热区/听写/卡拉OK 交互**逻辑**（从离线 JS 移植，非代码复用）
- PWA 可选（Service Worker 缓存内容，支持弱网/部分离线）

### 2.3 数据流约定

| 数据 | 离线 | 在线 |
|------|------|------|
| 内容 JSON | 内联 data.js | API 分发 |
| 音频 | base64（.js 内联） | URL（COS/CDN） |
| 图片 | base64（.js 内联） | URL（COS/CDN） |
| 打卡/成绩 | localStorage | localStorage（登录后可选云同步） |

## 3. 在线认证设计

### 3.1 技术选型：腾讯云 Serverless 全家桶（预算敏感 + 无运维）

| 组件 | 选型 | 免费额度 | 说明 |
|------|------|---------|------|
| 计算 | **腾讯云 SCF（云函数）** | 40万 GB-s/月 | 无服务器，Python/Node |
| 存储 | **COS（对象存储）** | 50GB/月 | 内容分发 + CDN |
| 数据库 | **腾讯云 CloudBase（NoSQL）** | 充足 | 用户/license/打卡 |
| 短信 | **腾讯云短信** | 100 条试用 | 激活/找回验证码 |
| 微信 | 微信开放平台（预留） | — | 后期 OAuth |

> 选腾讯云核心理由：**后期微信 OAuth 必走微信生态**，腾讯云最顺；预算敏感期 CloudBase 免费额度够 MVP。

### 3.2 认证流程

```
【首次激活】（在线，一次性）
  1. 手机号 + 产品授权口令（购买时随货发放）
  2. SCF 校验口令（license 表）+ 校验短信验证码
  3. 设置密码 → 创建用户（phone + password_hash + license 绑定）
  4. 返回 JWT（7 天，存 localStorage）
  5. license ↔ phone 一对一绑定（防转卖）

【日常登录】
  手机号 + 密码 → SCF → JWT（过期需重新登录，简单优先）

【找回密码】（手机号密码找回）
  手机号 → 短信验证码 → 重置密码

【微信 OAuth（预留接口）】
  /auth/wechat 回调 → user 表加 wechat_openid 字段（可空）
  → 登录后绑定（手机号已存在则绑定 openid）
  → 阶段 2 落地，设计上字段/路由已预留
```

### 3.3 离线 zip 防盗版（轻量策略）

- **现实判断**：离线 HTML 的 JS 可破解，强 DRM 投入产出比极低
- **方案**：离线 zip 首启弹**产品授权口令**输入框 → 本地校验（口令 hash 内置，混淆即可）→ localStorage 标记已激活
- **不做**：设备指纹绑定（离线场景易误伤）、每客户单独构建 zip（不可规模化）
- **依靠**：持续更新（新单元/新功能）驱动复购 + 在线版为正版主战场

### 3.4 安全注意

- 口令校验放 SCF（在线）+ 混淆 JS（离线），不同强度
- 短信限频：1 分钟 1 条 / 1 小时 5 条 / 1 天 10 条（SCF 内实现）
- JWT secret 存 SCF 环境变量（不落代码仓库）
- 密码 bcrypt/argon2 哈希（不存明文）

## 4. 内容范围：1-6 年级全册（12 册改造）

### 4.1 规模化测算

| 项 | 值 |
|---|-----|
| 总册数 | 12 册（一上~六下） |
| 总单元 | ~120 单元（每册 6-13 单元不等） |
| 现状单单元 | 1-1.5 人天（内容生产 + 审校） |
| 理论总耗时 | 120-180 人天（单人 5-8 个月） |

### 4.2 管线环节自动化分级（关键：QA 是唯一瓶颈）

| 环节 | 自动化 | 工具 | 人工占比 |
|------|-------|------|---------|
| ① 骨架提取 | 半自动 | OCR 教材 → LLM 起草 → 人工校对 | 40% |
| ② 内容生成（8 模板） | 半自动 | content_drafter.py（LLM 按骨架+模板生成）→ 人工审 | 30% |
| ③ 配图 | **全自动** | 批量生图工具（已有） | 5% 抽检 |
| ④ 配音 | **全自动** | **音频批量生成工具/**（Edge TTS 英式 + Kokoro，LoongMediaTools 通用工具） | 0 |
| ⑤ 组装 | **全自动** | build_framework.py（已有） | 0 |
| ⑥ QA | **纯人工** | 知识点/音频/配图/交互 4 维 checklist | 100% |

> **结论**：配图/配音/组装已全自动（现有基建强），瓶颈 100% 在人工 QA。
> **解法**：① 内容生产用 `content_drafter.py`（LLM 批量起草降人工）；② 按册分批交付、交叉互审。

### 4.3 排期（分批交付）

| 阶段 | 内容 | 备注 |
|------|------|------|
| A（月 1-2）| 四上 U03-U06 补齐 + 四下 | 复用模板最快 |
| B（月 3-4）| 三上 + 三下 | 基础册，配图量大 |
| C（月 5-6）| 五上 + 五下 | 内容复杂度上升 |
| D（月 7-8）| 一上/一下/二上/二下 | 量多但内容简单 |
| E（月 8-9）| 六上 + 六下 | 最难（考试导向），QA 最重 |

## 5. 新功能设计

### 5.1 听写（自听模式）

**两种形态 × 三级分级：**

| 形态 | 低年级（1-2） | 中年级（3-4） | 高年级（5-6） |
|------|-------------|-------------|-------------|
| 字母听写 | ✅ 主形态 | — | — |
| 单词听写 | 多选（选字母/选词） | 自由输入 + 提示 | 自由输入 |
| 句子听写 | — | 选词排序 | 自由输入（标点容错） |

**交互流程：**
```
进入听写 → 选单元 + 形态 + 分级
  → 播放（自动 1 遍，可重播限 3 次）→ 慢/常/快三档（复用 tts rate）
  → 输入/点选 → 判定（大小写/标点/空格容错）
  → 对 → ✓ + 鼓励；错 → 显示答案 + 入错题集
  → 错题集（localStorage，SM-2 简化：错必重出，连对 2 次移出）
  → 结算（沿用打卡/分享/防沉迷通用能力）
```

**技术要点**：
- 音频复用 base64 + Web Audio（现有方案）；判定 `normalizeInput()` 做容错归一
- 错题集独立 key（`dictation_errors`，按 unit+word 索引）
- 听写局数纳入防沉迷（`docs/通用需求-防沉迷自控力.md`）

### 5.2 歌曲跟唱（卡拉OK 模式）

#### 5.2.1 伴奏获取（自产，合规）

| 方案 | 质量 | 成本 | 合规 | 推荐 |
|------|------|------|------|------|
| **A. AI 自产原歌 + 直接取伴奏轨** | 高 | Suno/Udio 订阅 | ✅ 原创 | ✅ 主方案 |
| B. demucs 分离自产歌曲人声 | 中-高 | 免费（本地） | ✅（自产素材） | 备选 |

- **歌曲 = 原创**（Suno/Udio 生成儿歌，输入自写歌词 + 风格 prompt），生成时即得 vocal + instrumental 双轨
- 卡拉OK 播放 instrumental 轨；vocal 轨供示范跟唱
- **红线**：不采用人教原曲，仅复制"该主题/该节奏型"思路（旋律原创）

#### 5.2.2 滚动歌词同步

| 精度 | 格式 | 实现 | Chrome 61 | 推荐 |
|------|------|------|-----------|------|
| **行级高亮** | LRC `[mm:ss.xx] 歌词行` | 定时器 + currentTime | ✅ | MVP ✅ |
| 逐字高亮 | word-timestamp JSON | Whisper 本地对齐 | ✅ | 润色期 |

#### 5.2.3 AI 配音演唱 vs TTS 跟唱

| 方案 | 效果 | 复杂度 | 场景 |
|------|------|--------|------|
| **A. Suno 原歌（人声）+ instrumental 伴奏** | ★★★★★ 演唱级 | 低 | 正式单元歌曲 ✅ |
| B. Edge TTS 节奏化朗读 | ★★ 朗读感 | 极低 | 简单童谣/字母歌兜底 |
| C. DiffSinger 自训练歌声合成 | ★★★★ | 高（需训练） | 不推荐现阶段 |

**MVP**：行级 LRC + 自产 instrumental + 原歌示范；**润色**：逐字高亮 + 在线版实时跟唱打分（Web Audio pitch detection）。

## 8. 待确认决策点（评审后定稿）

1. **内容仓库位置**：独立仓 `edu-content/` vs RedTools 内 `content/` 子目录（倾向独立仓，可独立版本）

3. **CloudBase vs TDSQL-C**：MVP 用 CloudBase（NoSQL 免费），用户量级起来再评估
4. **卡拉OK 首期范围**：MVP 行级 LRC + 自产伴奏；逐字高亮排阶段 2
5. **听写自由输入的 Chrome 61 兼容**：输入框 OK，语音输入（Web Speech API）排在线版
```
