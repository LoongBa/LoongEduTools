# 英语点读陪练 · 在线能力兼容接口设计（前瞻 · 不阻塞现状）

> 定位：为「同一套 React 代码 → 两种构建形态」设计**兼容接口**——离线 zip（现状，纯本地）与在线 dist（Web 部署，可联网、离线可运行）。
> 覆盖三块能力：**在线验证 / 在线更新单元内容 / 提交学习数据**。
> 本文是接口设计（前瞻预留），不要求立即实现；落地分期见 §4。
> 关联文档：`英语点读陪练_产品与架构设计方案.md`（§2 双模式管线、§3 在线认证，本次按单前端双形态修订）、`内容生产SOP_标准操作流程.md`（发布）、`离线发布经验与踩坑记录.md`（平台约束）。

## 0. 关键决策（先说结论）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **单前端双形态**（修订架构文档 §1.1「不做前后端代码复用」） | 本需求要求「共用程序代码，只是资源文件独立」；离线/在线共用 `src/`，构建期 `BUILD_TARGET` 区分 |
| D2 | **内容更新走 RemoteProvider + IndexedDB 缓存**，不引 Service Worker | SW 离线语义与「构建期内联」哲学冲突（探索确认：项目零 SW/PWA 基础）；idb-keyval 轻量、不动 minitool 约束之外任何东西 |
| D3 | **素材 URL 化**：远程 JSON 里 audio/image 直接写完整 `https://` URL | 现有 `fromContent.ts` 的 `absAudio()` 对 `https?://` **原样透传**（探索确认），零改造 |
| D4 | **提交信封最小化**：只上报学习统计（打卡/自评/词数），不采集身份 | 儿童数据最小化红线（store/speech/docs 多处明文）；匿名 `clientId` 本地随机、可随清空删除 |
| D5 | **离线形态零变化**：minitool 容器禁网络（device-capabilities L88/L139），在线能力全部只在线形态激活 | 能力检测见 §3.5 |

## 1. 能力边界（探索实测确认）

| 能力 | 离线 zip（minitool） | 在线 dist（Web） |
|---|---|---|
| 网络（fetch/XHR/WebSocket/EventSource） | ❌ **全禁**（skill 条款原文：网络请求「fetch / XMLHttpRequest、加载外部图片 / 字体 / 媒体等一切联网请求」禁用；扫描清单含 `fetch(` / `new WebSocket(`） | ✅ 可用 |
| 内容数据 | 构建期内联 `catalog.generated.ts` + base64 聚合音频 js | 远程 manifest 索引 + 增量拉取单元 JSON + 素材 URL 直引（COS/CDN） |
| 音频播放 | base64 → `decodeAudioData` 纯内存 | 在线形态可直接 `new Audio(url)`（现代浏览器） |
| 进度存储 | localStorage `dianedu.progress.v1` | 同左 + **可选云提交** |
| 在线验证（授权） | 口令 hash 本地校验 + localStorage 激活标记（§3.3 已设计） | 手机号+口令+短信 → JWT（§3.2 已设计，SCF） |
| 数据提交 | ❌ | ✅ POST `/api/progress`（草案 §3.3） |

**现状基座（可直接利用）**：
- `content.ts: loadCatalog()` = **唯一内容收敛口**（async、`main.tsx` render 前 `await`、4 道「全或无」降级 return、一次性写入 `MANIFEST/UNITS/UNIT_ROWS/TOTAL_WORDS` 四个 let 活绑定）——远程/内联切换可完全藏在函数体内，**UI 组件零感知**。
- `fromContent.ts: contentToUnit / songJsonToSong` = **纯函数**（JSON → Unit/Song），远程 JSON 走同一转换，语义一致，无第二套适配层。
- `absAudio()` 对 `https?://` 原样放行；相对路径仍走 `./units/uXX/` 约定。
- `version.ts: APP_VERSION / DATA_STAMP` 现成常量，可直接进提交信封与内容比对。
- 全 `src/` **零 fetch/XHR/SW/IndexedDB**（仅 localStorage 进度）——在线能力是全新引入，无历史包袱。

## 2. 内容层接口：ContentProvider

### 2.1 核心抽象

```ts
// src/data/content-provider.ts（新增）
interface CatalogSnapshot {
  manifest: Manifest | null;
  units: Record<string, { content: unknown; song: unknown; textbook: unknown }>;
}

interface ContentProvider {
  /** 返回本次内容快照；失败/离线返回 null（由 loadCatalog 级联降级）。永不抛错。 */
  resolve(): Promise<CatalogSnapshot | null>;
  /** 数据更新时间戳（供「内容已更新」比对；null = 不可知） */
  dataStamp?: () => string | null;
}

// 内置 Provider（现状，同步包一层 async）
class InlineProvider implements ContentProvider {
  resolve() { return Promise.resolve(EMBEDDED_CATALOG as unknown as CatalogSnapshot | null); }
}

// 远程 Provider（在线形态；离线形态不注册）
class RemoteProvider implements ContentProvider {
  constructor(opts: { baseUrl: string; cache: ContentCache; })
  async resolve(): Promise<CatalogSnapshot | null> {
    // 1) 拉远程 /api/manifest（含每单元 version/hash）
    // 2) 与缓存 manifest 比对 → 变更/新增单元列表
    // 3) 增量拉取变更单元 { content.json, song.json, textbook_lyrics.json }
    // 4) 写缓存（IndexedDB），返回合并快照
    // 5) 全失败 → null（loadCatalog 回退内联）
  }
}

// 编排（loadCatalog 内，替换现 L831-867 前半段）
const provider = resolveProvider();              // 在线形态=Remote(+Inline 兜底)，离线=Inline
const snap = (await provider?.resolve()) ?? await inline.resolve();
// 后半段 materialize(snap) 复用现有 L837-866 逻辑（contentToUnit/songJsonToSong 遍历）
```

**loadCatalog 改造原则**：保留现有 4 道降级 return 的「全或无」语义，扩展为三级：`远程快照 → 内联快照 → 内置示例`。改动面 = 1 个函数 + 1 个新文件，消费方零感知。

### 2.2 远程内容协议（草案，对齐架构文档 §1.2 的 version/hash 设计）

```
GET /api/manifest            → { schema: "manifest@2", updated_at, units: [{ id, no, version, hash }] }
GET /api/units/<id>/content  → content.json（内容包）
GET /api/units/<id>/song     → { song.json, textbook_lyrics.json }（或分两端点）
```

- **增量依据**：per-unit `hash`（内容包文件哈希）；缓存命中且 hash 相同 → 不重拉
- **内容提示**：`RemoteProvider.dataStamp()` 返回 `updated_at`，与本地 `DATA_STAMP` 比对 → 提示「有新内容」
- 素材（audio/image）在 JSON 里直接写完整 URL（D3），`absAudio` 透传，**无需改 fromContent**
- 音频在线形态：`audioUrl(key)` 对 `https://` 原样返回 → `new Audio(url)`；离线形态走 base64（现状不变）——现有 `audioUrl` 已天然区分

### 2.3 缓存介质（D2）

| 方案 | 结论 |
|---|---|
| IndexedDB（`idb-keyval`，~1KB 零依赖） | ✅ 推荐：轻量、不动 minitool 约束、可存 JSON + 素材 URL 元数据 |
| Service Worker + Cache API | ❌ 不引：与「构建期内联」哲学冲突，且 SW 注册本身在容器内行为不可控 |
| localStorage | ❌ 容量 5MB 上限，内容 JSON 会超 |

## 3. 数据提交与在线验证接口

### 3.1 提交信封（DataSubmit）

```ts
// src/lib/submit.ts（新增；从 _layout.me.tsx exportText 提炼统计口径为单点）
interface SubmitEnvelope {
  schema: "progress.submit@1";
  clientId: string;            // 匿名：localStorage 随机生成（dianedu.clientId，crypto.randomUUID），随清空删除
  submittedAt: string;         // ISO8601 带时区
  appVersion: string;          // 复用 APP_VERSION
  dataStamp: string;           // 复用 DATA_STAMP（服务端可判定「旧数据配新内容」）
  progress: {
    stats: { totalDays; streak; collected; totalWords; unitsDone };   // 复用 useProgress().stats
    days:   { date; week; dayInWeek; stagesDone; finished }[];        // finished 过滤
    skills: { week; skillId; rating }[];                              // 当前/近周
  };
}
```

**存储层最小改造（新增 3 项，不破坏现有 schema 兼容）**：
- `ProgressState.schemaVersion?: 1` —— 表达协议版本（现只有 key 名 `.v1`）
- `ProgressState.lastSubmittedAt?: number` —— 增量提交游标
- `DayRecord` 可选补 `ts?: number`（完成时间戳）——支持增量去重；不做也行（date 粒度够 MVP）

**端点草案**：`POST /api/progress`（SCF，架构文档 §3 技术栈）→ 服务端仅存统计聚合（无身份关联）；响应 `{ ok, lastSubmittedAt }` 回写游标。

**最小化红线**：不采集姓名/生日/设备指纹/录音；`clientId` 纯本地随机、非标识真人；「清空本机进度」时一并删 `clientId` 与缓存（现状 `resetAll` 走 state 覆盖，需补一次 localStorage 清理）。

### 3.2 在线验证接口（两层，预留）

| 层 | 用途 | 接口 |
|---|---|---|
| **内容验证** | 校验内容来源/防篡改 + 触发更新 | manifest 拉取即天然校验（https + 可选签名）；`hash` 比对驱动「有更新」提示 |
| **授权验证** | 正版激活（在线版） | 沿用架构文档 §3.2：`/auth/activate`（口令+短信）`/auth/login`（JWT，7 天，存 localStorage）——前端侧新增 `AuthProvider` 抽象：`token()` / `isActivated()` / `onLogin()`，离线形态回落本地口令 hash 校验（§3.3，现状已设计未实现） |

> 能力自评（skills rating）**不上报判定、不做 PK/排行**——「在线验证」不含成绩评判（标准答案原则：无 PK/排行）。

### 3.3 构建开关与能力检测

```ts
// vite env（define）：import.meta.env.VITE_BUILD_TARGET: "offline" | "online"
//   - offline：RemoteProvider/AuthProvider/submit 模块 tree-shake 掉（不打包进离线 zip）
//   - online：注册 RemoteProvider + SW 可选 + 提交按钮

// 运行时
const isOnlineApp = () =>
  import.meta.env.VITE_BUILD_TARGET === "online" && typeof location !== "undefined" && location.protocol !== "file:";
```

- 离线形态 = 现 `vite build`（`offlineHtmlPlugin/offlineCssPlugin` 合规改造不变）；在线形态 = `pnpm build:online`（`vite build --mode online`，去 offline 插件 + 注入 `VITE_BUILD_TARGET`）
- 在线版离线可运行：内容走 IndexedDB 缓存（首启拉取后离线可用）+ 进度 localStorage（现状）；网络断开时 `RemoteProvider.resolve()` 返回缓存快照（不 null），无需 `navigator.onLine` 特判（fetch 失败自动回落缓存）

### 3.4 服务端接口草案（SCF 部署；manifest/units 可纯静态，progress 走函数）

**三端点总览**（同域 `/api/*`）：

| 端点 | 方法 | 用途 | 实现方 |
|---|---|---|---|
| `/api/manifest` | GET | 目录索引（每单元 version/hash + 全局 updated_at） | `publish_online.py` 生成静态 JSON（可纯 COS 托管） |
| `/api/units/<id>` | GET | 单元内容包 + 点唱台 JSON（素材字段为完整 URL） | 同上 |
| `/api/progress` | POST | 学习统计上报（匿名 clientId） | SCF 云函数 |

**请求/响应示例**：
- `GET /api/manifest` → `{ "schema": "manifest@2", "updated_at": "2026-09-25T10:00:00Z", "grades": [{ "grade_code": "4A", "grade_label": "四年级上", "units": [{ "id": "u01", "no": 1, "title": "...", "cn": "...", "version": "1.0", "hash": "a1b2c3d4" }] }] }`
- `GET /api/units/u01` → `{ "content": {...}, "song": {...}, "textbook": {...} }`（audio/image 字段写完整 `https://` URL，前端 `absAudio` 原样透传）
- `POST /api/progress` 请求体 = §3.1 信封；响应 `{ "ok": true, "lastSubmittedAt": 1727247600000 }`

**SCF 骨架（Python，腾讯云，架构文档 §3 选型）**：
```python
import json, time

def progress_handler(event, context):
    body = json.loads(event.get("body") or "{}")
    record = {
        "clientId": body.get("clientId"),      # 匿名标识，不关联真人
        "submittedAt": body.get("submittedAt"),
        "appVersion": body.get("appVersion"),
        "dataStamp": body.get("dataStamp"),
        "progress": body.get("progress", {}),   # 仅学习统计（打卡/自评/词数）
        "receivedAt": int(time.time() * 1000),
    }
    # TODO: 写入 CloudBase（NoSQL），按 clientId + date 去重/追加；限频 1 次/分钟
    return {"statusCode": 200, "body": json.dumps({"ok": True, "lastSubmittedAt": record["receivedAt"]})}
```

**部署要点**：
- manifest/units 纯静态（COS+CDN），**仅 progress 需函数**；前端 `fetch` 同域相对路径 `/api/...`，无需跨域配置（异域部署时补 CORS）
- 授权验证（口令/短信/JWT）按架构文档 §3.2/§3.4 为**后续里程碑**（P2 只做匿名统计上报）
- 儿童数据最小化：服务端不存身份字段、不做 PK/排行；`clientId` 可随清空丢弃

## 5. 决策点与红线（留给实现时确认）

1. **在线后端是否立即建**：架构文档 §3 选型（腾讯云 SCF/COS/CloudBase）预算友好，但 P1 只依赖静态 COS（manifest+JSON 可纯静态托管），**SCF 仅在 P2 需要**——可先 COS 静态 + 后补函数。
2. **内容仓库**（架构 §1.2 的 `RedTools/content/` 独立仓 + version/hash）：当前未落地（探索确认），P1 的远程 manifest 可由 `publish_online.py`（新脚本，从 `build/uXX/content_package.json` 生成）直接产出，不强制先建独立内容仓。
3. **架构文档修订**：§1.1「不做离线/在线前端代码复用」与本需求冲突，落地 P0 时同步修订为「单前端双形态」；§2.1 离线管线描述（`build_framework.py`/`data.js`）与现状 WebH5 React 不符，一并校正。
4. **红线不变**：儿童数据最小化（不采集身份、录音纯内存、清空二次确认）；minitool 离线容器禁网络（在线能力绝不打包进离线 zip）；无 PK/排行。
