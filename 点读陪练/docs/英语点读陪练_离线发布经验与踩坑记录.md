# 英语点读陪练 · 离线发布经验与踩坑记录

> 小红书小工具（minitool 离线 H5）发布踩坑与既定方案沉淀。后续单元发布直接复用，勿重蹈覆辙。
> 流程侧见 `docs/内容生产SOP_标准操作流程.md` 步骤 9-10；本文只记「为什么这么做 / 踩过的坑 / 既定决策」。

---

## 一、平台硬约束（上传校验 + 容器运行期）

| # | 约束 | 内容 | 影响 |
|---|---|---|---|
| 1 | **文件类型白名单** | zip 内仅允许：`html / css / js / png / jpg / jpeg / gif / webp / svg / woff / woff2 / json` | **不含音频扩展名**——`mp3/wav/ogg` 一出现即被打回「不支持的文件类型」 |
| 2 | **文件数量 ≤200** | zip 总文件数上限 | 素材必须聚合，不能每音频一文件 |
| 3 | **体积门禁** | 单文件 ≤10MB；zip ≤10MiB（skill 建议 ≤2MiB，超了 WARN 不阻塞） | 图片须 WebP 压缩、音频须 base64 文本化 |
| 4 | **容器 CSP** | 脚本必须**外置经典脚本**（禁内联/eval/`type=module`）；音视频**禁 `data:`/`blob:` 来源**（图片可 data:/blob:，媒体不行） | 音频不能伪装 data URI 或 blob URL 播放 |

约束 1+4 的组合拳 = **音频唯一合法形态：base64 文本进 `.js`，运行时 Web Audio 纯内存解码播放**。

---

## 二、方案演进（时间线）

1. **初版**：mp3 直接进 zip → 平台报错 `不支持的文件类型: units/u01/audio/u01_p1_comp001.mp3`。
2. **base64 每音频一 js**：参考已验证包 `RedTools/publish/学科/新英语四上点读1单元.zip`（`window.AUDIO_DATA[key]=base64` + 动态 script 注入 + `decodeAudioData` 播放）→ 类型过关，但 **186 个音频 js + 68 其他 = 254 项，撞「文件数 ≤200」上限**。
3. **聚合 js（最终）**：按 **单元 × 类型** 合并为 6 个 js → **74 项**，双约束同时满足。

## 三、最终方案（既定决策，勿再改）

### 编码：`src/encode_audio_b64.py`
- 扫描 `build/offline/units/<uid>/` 全部 mp3 → 聚合输出 `audio/<uid>-audio.js` / `audio/<uid>-song.js` / `audio/<uid>-textbook.js`（每单元 3 组）
- 组内逐 key：`window.AUDIO_DATA["<key>"] = "<base64>";`
- **编码后删除原 mp3**（白名单要求）
- 集成进 `publish_offline.py` 步骤 7（拆分后、门禁前自动跑）；门禁新增「音频文件残留」复查（残留 exit 2）

### key 规范（前后端必须一致）
key = **相对 `units/` 根的路径去扩展名**：
| 源文件 | key |
|---|---|
| `units/u01/audio/u01_s0_h01.mp3` | `u01/audio/u01_s0_h01` |
| `units/u01/song/song_vocal.mp3` | `u01/song/song_vocal` |
| `units/u01/song/textbook/line_01.mp3` | `u01/song/textbook/line_01` |

前端 `normalizeKey()` 统一三种输入形态（纯文件名 / `./units/…` / `units/…`）；`groupOf()` 由 key 推导聚合组名。

### 运行时播放（`src/lib/audio.ts`）
`ensurePayload(key)` 注入 `./audio/<group>.js` → `window.AUDIO_DATA[key]` 取 base64 → `atob` → `ArrayBuffer` → **`decodeAudioData`（回调式，Chrome 61）** → `AudioBufferSourceNode` 播放（支持 rate、onEnd、onError）。**全程不经过 `<audio>` 元素 / data: / blob:，符合 CSP 约束 4**。
- `speech.ts`：`speakMp3` / `stopAudio` / `setAudioRate` 全部走 buffer 播放（失败回退浏览器 speechSynthesis）
- `jukebox.tsx`：整曲双轨重写为 BufferSource 状态机（Gain 控制三态、轮询进度+歌词高亮、seek/变速/暂停续播保留）

## 四、踩坑清单

| # | 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|---|
| 1 | mp3 直接入包 | 平台打回「不支持的文件类型」 | 白名单无音频扩展名 | base64 文本化（见三） |
| 2 | 每音频一 js | 254 项超 200 上限 | 文件数硬限制 | 按单元×类型聚合 6 个 js |
| 3 | 编码脚本漏建目录 | `publish_offline.py` 步骤 7 抛 `FileNotFoundError: audio/u01-audio.js` | 拆分步骤**全量重建 offline**，`audio/` 目录不存在，聚合版直接 `write_text` 未建目录（旧每文件版靠 `mkdir(parents=True)` 兜住） | `audio_root.mkdir(parents=True, exist_ok=True)`（rmtree 后重建） |
| 4 | 异步解码竞态 | 快速连点「下一句」时旧音频解码完成后仍开播，串台/叠播 | `playMp3Buffer` 异步回调才建 source，`stopAudio` 时旧请求尚未开播、无法打断 | 模块级 `playSeq` 代际令牌：每次发起/停止 `+1`，回调校验 `mySeq === playSeq` 才继续（旧请求静默作废） |
| 5 | WebAudio 变速变调 | 慢速档（0.55x）音高变低 | `AudioBufferSourceNode.playbackRate` 无 `preservesPitch`（原 HTMLAudioElement 有） | **与 Chrome 61 基线行为一致**（Chrome 61 的 Audio 元素本无 preservesPitch），非退化；若儿童跟读变调明显可上调慢速档位（决策待用户） |
| 6 | data:/blob: 媒体被 CSP 拦 | （规避成功，未踩） | 容器 CSP 禁媒体 data:/blob: | 全程 Web Audio 内存播放；录音回放早于本次已走同一路线（`speech.ts useRecorder`） |

## 六、延伸经验

- **白屏缺陷**（早于本次）：离线壳剥 `type="module"` 后入口变同步经典脚本 → `#root` 未解析即 `createRoot` → React #299 白屏。解法：`type="module"` → `defer` + `whenDomReady()` 双保险（已提交 `1975151`，§12.6 有记录）。
- **平台报错是「最小可用信息」**：先按错误处理单文件，实测才暴露下一层限制（类型 → 数量）。发布脚本门禁应**一次覆盖全部已知约束**，避免反复上传试错。
- **参考已验证包价值**：仓库 `RedTools/publish/学科/新英语四上点读1单元.zip` 是同一平台跑通的音频方案（结构、CSP 规避、变速范围），改造前先解包看它。
