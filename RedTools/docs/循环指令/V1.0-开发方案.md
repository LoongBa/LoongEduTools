## 2. 目标与原则

### 2.1 目标

- **玩法**：网格盘面（起点 S + 终点 G），孩子用指令让机器人从 S 走到 G；
  指令含**显式循环块** `🔁 重复 N 次 { 指令... }`（循环体内多条指令、参数 N、挑战档嵌套）。
- **判定**：执行后机器人位置 = 目标格 = 有标准答案（合规安全区）。
- **概念教学**：**循环 = 自动化**（测速转型核心语义：写「重复 N 次」替代手动 N 次重复动作）；
  与走迷宫隐式 chip ×N 的区别 = **显式循环块**（多指令整体重复）。
- **星级**：编写量（循环块=1 条 + 内部指令计 1 不乘 N）vs 最优编写量（生成器模式）→ ≤1.5× 3★。
- **形态**：离线 zip + 双模式；零素材（SVG 程序化盘面）。

### 2.2 原则

1. 有标准答案判定（执行后位置 = 目标格）——合规安全区核心。
2. 显式循环块为 MVP 核心（区别于走迷宫隐式 chip），挑战档支持嵌套。
3. 复用走迷宫移动语义/执行高亮/失败定位/锁定 + 通用模式 + lx-shared。
4. 零素材、Chrome 61 兼容、低龄友好渐进（单层 → 嵌套）。

## 3. 变更设计

### 3.1 玩法与指令模型

**盘面**：网格。简单 6×6 / 普通 8×8 / 挑战 10×10。起点 S（机器人朝右）+ 终点 G（⭐）。

**★ 走廊墙体（oracle 阻断项修复）**：生成器沿轨迹生成**走廊**——轨迹格 = 可行走空地；
**相邻非轨迹格 = 墙体**（把机器人限制在轨迹走廊内，堵死捷径）。这样：
- 最优解 = 沿走廊走（唯一路径），孩子不能抄近道；
- 循环块方案 = 高效编码，展开写 = 低效 → 教学目的（找模式用循环）得以保证；
- 与走迷宫差异：走迷宫固定关卡复用、本工具程序化走廊 + 显式循环块结构。

**三档难度（oracle 修订：表现型展开必须 ≥2★ 上限）**：
- 简单：6×6 · pattern 长 2 · rep 3（展开 6 条 vs 循环 3 条 → 展开 2★、循环 3★）
- 普通：8×8 · pattern 长 3 · rep 3（展开 9 条 vs 循环 4 条 → 展开 2★、循环 3★）
- 挑战：10×10 · pattern 长 4 · rep 3（展开 12 条 vs 循环 5 条 → 展开 2★、循环 3★）
> 参数保证：**展开写必然 ≥ 1.5× optimal**（简单 2.0× / 普通 2.25× / 挑战 2.4×）——孩子必须用循环块才能 3★。

**指令模型**（分层指令树，循环块为显式容器）：

```
程序 = 指令序列（顺序执行）
指令 =
  | 基础指令: { type: 'fwd'|'left'|'right' }        # ⬆ 前进 / ↰ 左转 / ↱ 右转
  | 循环块:   { type: 'loop', rep: N, body: [指令] } # 🔁 重复 N 次 { body }
```

**★ 循环块与走迷宫 chip ×N 的对比（oracle 决策点 1 建议）**：
> 概念卡明确话术：「走迷宫的 ×N 是让**一个动作**做很多遍；循环块是让**一组动作**做很多遍」——
> 走迷宫 = 单指令参数化（隐式），循环指令 = 多指令块重复（显式容器）。

**循环块交互**（块内编辑）：
- 添加循环块：点击 `🔁 循环` 按钮 → 序列中插入空循环块 `🔁 重复 2 次 { }`；
- 块内编辑：点击循环块展开 → 显示块内指令区（可加 前进/左转/右转），块尾 `✓ 完成` 收合；
- N 调节：循环块头单击递增 `2→3→4→5→2`（对齐走迷宫 ×N 参数化语义）；
- **★ MVP 全部单层循环（oracle 决策点 5：嵌套留 V1.1）**：挑战档模式更长（4 条）而非嵌套，避免块内编辑交互状态机复杂度。

**执行语义**：程序展开为线性动作序列（loop 按 rep 展开 body），逐条执行（动画 260ms/步 + 当前指令高亮）；执行中锁定编辑（复用走迷宫 execLock）。

**编码序列到动作**：
- fwd：朝当前方向前进 1 格（走廊 → 非轨迹格 = 撞墙 = 失败定位）；
- left：左转 90°；right：右转 90°；
- 判定：执行完机器人位置 = 目标格 → 过关；否则 `✗ 机器人走到了 (x,y)，目标在 (gx,gy)（还差 M 格）` + 当前位置红标。

### 3.2 关卡生成器（走廊 + 轨迹约束 + simulate 共用）

```
genLevel(diff):
  cfg = {easy:{size:6, patternLen:2, rep:3},
         normal:{size:8, patternLen:3, rep:3},
         hard:{size:10, patternLen:4, rep:3}}[diff]
  loop 上限 200:
    pattern = genPattern(cfg.patternLen)   # 含 ≥1 条 fwd（保证位移），其余 left/right
    steps = []; for i in 0..rep-1: steps += pattern
    # simulate（纯函数，与执行器共用）：从 (1,1) 朝右起步
    sim = simulate(steps, cfg.size, {x:1, y:1}, 0)
    if sim.invalid: continue               # 越界 → 重试
    if sim.selfIntersect: continue          # ★ 轨迹自交 → 重试（oracle 3a 修复）
    # ★ 走廊：轨迹格 = 空地，相邻非轨迹格 = 墙（oracle 阻塞项修复）
    walls = buildCorridor(sim.trace, cfg.size)
    return { grid: walls, trace: sim.trace, start: {x:1,y:1}, startFace: 0,
             goal: sim.trace[last], path: steps, pattern, rep,
             optimal: pattern.length + 1 }
  返回 seedLevel(diff)   # 兜底（对齐 D4 先例）
```

**★ simulate 纯函数（oracle 3d 修复——与执行器共用同一实现）**：

```
simulate(steps, size, start, startFace):
  pos = start; face = startFace; trace = [start]
  for step in steps:
    if step == 'left':  face = (face + 3) % 4
    elif step == 'right': face = (face + 1) % 4
    else:  # fwd
      np = pos + DIRS[face]
      if np 越界 (x<0||x>=size||y<0||y>=size): return {invalid: true}
      pos = np; trace.push(pos)
  # 自交检查（oracle 3a）
  selfIntersect = len(set(trace)) < len(trace)
  return { invalid: false, selfIntersect, trace, end: pos }
```

**最优编写量**：生成器已知 pattern + rep —— **最优 = pattern.length + 1**（循环块 1 条 + 模式指令数）。

### 3.3 判定与反馈

- 执行完位置 = 目标 → 过关（`✓ 完成！机器人到目标啦（N★，指令 M 条 / 最优 K）`）；
- 未达 → `✗ 机器人走到了 (x,y)，目标在 (gx,gy)（还差 M 格）` + 当前位置红标；
- **★ 撞墙失败定位（oracle 4b 修复）**：err class 标在**循环块整体 chip**（红框）+ 文案
  `⛔ 第 K 次循环里的第 M 条指令（前进）撞墙啦`——不定位到块内具体指令 UI 层（嵌套时太深）；
- **★ 循环迭代计数（oracle 4c 建议）**：循环块执行时块头显示 `🔁 第 2/3 次`，块内当前指令高亮——
  让孩子理解「同样的指令在不同位置效果不同」（循环核心概念的可视锚点）；
- 执行中高亮当前展开指令（含循环体内指令）+ 锁定编辑。
