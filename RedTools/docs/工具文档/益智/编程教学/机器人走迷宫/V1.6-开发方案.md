## 1. 背景与目标

### 1.1 背景

编程教学线 D1 走迷宫已完成核心概念闭环：顺序（v1.0）→ 循环（v1.1）→ 条件（v1.3）→ 调试（v1.4）→ 分支（v1.5）。
v1.6 引入**参数化移动**——机器人"一次走 N 格"（直线移动多格），教学编程核心概念**参数（parameter）**：
指令可以带参数，一次表达多次移动。

### 1.2 与 v1.1 rep 循环次数的区别（关键设计，Oracle 核查通过）

| 版本 | 机制 | 语义 | 动画 | 失败语义 |
|---|---|---|---|---|
| v1.1 | `cmd.rep`（chip 点击 1→2→3→4） | **重复执行单步**：指令执行 rep 次，每次独立判断障碍 | 逐步动画（260ms/步） | 每步独立判定，撞墙记失败 |
| **v1.6** | `cmd.steps`（`走 N 步`） | **一次性参数化移动**：直线移动 N 格（参数=距离） | 逐格动画（260ms/步） | 中途撞墙=正常停止；第一步即撞墙=失败 |

**教学定位**：rep 是"循环"概念（重复做同一件事），steps 是"参数"概念（一个指令携带数量参数）。
v1.6 让孩子理解：**不用写 N 条前进，写一条"前进 N 步"即可**——参数化让程序更简洁。
**行为差异即教学点**：`↑×3` 撞墙会失败（每次尝试独立），`➡走3步` 撞墙自动停（像人走路走到墙停）——两者行为不同，正是区分"循环"与"参数"的直观体现。

### 1.3 与兄弟工具对比（Oracle 核查通过）

- **循环指令（D5）**：显式循环块 `🔁 重复 N 次 {组指令}`——一组动作重复 N 遍（循环结构）
- **走迷宫 v1.1**：隐式 chip ×N——单条指令重复 N 遍（循环启蒙）
- **走迷宫 v1.6（本方案）**：`走 N 步`——**单条指令携带距离参数**，一次移动 N 格（参数化，非循环）
- **合并策略编程（D4）**：方向指令 ×N 参数化（`cmd.val` 1→4）——已实现参数化先例，v1.6 复用其交互模式

## 2. 变更设计

### 2.1 新增指令：`➡ 走N步`（CMD_STEPS）

**指令**：`➡ 走N步`（label 动态显示当前参数：`➡ 走3步`）

**数据结构**：
```js
var CMD_STEPS = { id: 'steps', label: '➡ 走N步' };
// state.cmds 中：{ id: 'steps', steps: 1 }   // steps 参数 1..9，无 rep 字段
// 执行期字段：_stepsLeft（剩余格数）/ _stepsMoved（已走格数，失败语义判定用）
```

**交互**（复用 v1.5 chip 点击循环模式 + D4 参数化先例）：
- 点击指令区 `➡ 走N步` 按钮 → 追加 `{id:'steps', steps:1}` 到序列
- 点击序列中 steps chip → 参数递增 1→2→3→…→9→1（9 上限，区别于 rep 的 4 上限）
- ✕ 删除同其他指令
- **steps 无 rep 字段**（与 rep 互斥，Oracle 确认正确：`_loopLeft=1` 天然不叠加）

**执行语义**（Oracle B1/B2/B3 修订）：
1. 逐格移动：每格调用共享 `tryMoveFwd()`，与现有 260ms 步进节奏一致（**逐格动画**，可见推箱过程）
2. 遇障碍（墙/越界/箱推不动）→ 停止（安全行为，同 fwd 撞墙）
3. 失败语义：`_stepsMoved=0`（第一步即撞墙）→ 记 firstFail；已走 ≥1 格后撞墙 → 正常停止不记失败
4. steps 可在 if 分支内使用（editCtx 支持添加，`_execTop` 继承机制不变）

### 2.2 执行器（Oracle B2/B3 修订：共享 tryMoveFwd + 工作队列复用）

**提取共享移动函数**（fwd/steps/block 三指令共用，消除代码重复）：
```js
/* 共享前进一格逻辑：返回 {moved, reason} */
function tryMoveFwd() {
  var pr = state.player % state.w, pc = Math.floor(state.player / state.w);
  var dx = DIRS[state.face][0], dy = DIRS[state.face][1];
  var nr = pr + dx, nc = pc + dy;
  if (nr < 0 || nr >= state.w || nc < 0 || nc >= state.h) { return { moved: false, reason: 'edge' }; }
  var nIdx = nc * state.w + nr;
  if (state.walls[nIdx]) { return { moved: false, reason: 'wall' }; }
  if (state.boxes[nIdx]) {
    var br = nr + dx, bc = nc + dy;
    if (br < 0 || br >= state.w || bc < 0 || bc >= state.h) { return { moved: false, reason: 'box' }; }
    var bIdx = bc * state.w + br;
    if (state.walls[bIdx] || state.boxes[bIdx]) { return { moved: false, reason: 'box' }; }
    delete state.boxes[nIdx]; state.boxes[bIdx] = true;
    state.player = nIdx;
    return { moved: true, reason: 'ok' };
  }
  state.player = nIdx;
  return { moved: true, reason: 'ok' };
}
```

**execStep 改造**：
- fwd 分支：改用 `tryMoveFwd()`，失败时记 firstFail（`reason` 复用 v1.4 分类 wall/edge/box）
- block 分支：**直接调用 `tryMoveFwd()`，行为不变**（tryMoveFwd 已封装"无障碍才动"语义）；block 不记 firstFail（撞墙为预期探测行为，区别 fwd）
- steps 分支（**逐格动画 + 工作队列复用，修复死循环**）：
```js
else if (cmd.id === 'steps') {
  // 初始化执行期字段
  if (cmd._stepsLeft === undefined) { cmd._stepsLeft = cmd.steps || 1; cmd._stepsMoved = 0; }
  var r = tryMoveFwd();
  if (r.moved) { cmd._stepsLeft--; cmd._stepsMoved++; }
  if (r.moved && cmd._stepsLeft > 0) {
    // 仅"移动成功且未走完"才重插入队首 → 逐格动画；撞墙即停（无死循环）
    state.execQueue.splice(state.queueIdx, 0, cmd);
  }
  // 失败语义：第一步即撞墙 → 记失败；中途撞墙（_stepsMoved>0）→ 正常停止
  if (!r.moved && cmd._stepsMoved === 0 && !state.firstFail) {
    state.firstFail = { absStep: state.absStep, cmd: cmd, reason: r.reason };
  }
}
```

**关键点**：
- 死循环修复（Oracle B2）：重插入条件是 `r.moved && _stepsLeft > 0`（撞墙不重插入）
- 失败语义（Oracle B2）：`_stepsMoved === 0` 区分"第一步失败"vs"中途停止"
- resetLoopLeft 扩展（Oracle I1）：增加 `_stepsLeft`/`_stepsMoved` 清理

### 2.3 数据结构适配（Oracle I2/I3）

**addCmd 增加 steps 分支**：
```js
function addCmd(id) {
  if (state.execLock) { return; }
  if (id === 'if') { state.cmds.push({ id: id, then: [], else: [] }); }
  else if (id === 'steps') { state.cmds.push({ id: id, steps: 1 }); }
  else { state.cmds.push({ id: id, rep: 1 }); }
  renderSeq();
}
```
`renderBranchCol` 的 addBtns 同理（else 分支内可添加 steps）。

**renderSeq 适配**：
```js
// lbl:
var lbl = cmd.id === 'fwd' ? '↑' : cmd.id === 'left' ? '↰' : cmd.id === 'right' ? '↱'
  : cmd.id === 'block' ? '🧱' : cmd.id === 'steps' ? '➡' + (cmd.steps || 1) + '步' : '❓if';
var repTxt = (!isIf && cmd.id !== 'steps' && cmd.rep && cmd.rep > 1) ? ('×' + cmd.rep) : '';
```

**chip 点击处理器三分支**：
```js
if (isIf) { openEditCtx(i, cmd); }
else if (cmd.id === 'steps') { cycleSteps(i); }   // 1→9→1
else { cycleRep(i); }
```

**新增 cycleSteps**：
```js
function cycleSteps(i) {
  if (state.execLock) { return; }
  var cmd = state.cmds[i];
  if (!cmd || cmd.id !== 'steps') { return; }
  cmd.steps = ((cmd.steps || 1) % 9) + 1;
  renderSeq();
}
```

### 2.4 关卡设计（Oracle I5：6 类模板，非纯直线走廊）

v1.6 新增 **10 关（176-185）**，6 类模板确保 steps 有不可替代优势：

| # | 模板 | 说明 | steps 优势 |
|---|---|---|---|
| 176-177 | 长直推箱 | 5+ 格直道推箱到目标 | `➡走5步`=1 条 vs `↑×5`=5 条 |
| 178-179 | L 型走廊 | 直道→转→直道 | `➡走3步 ↱ ➡走4步`=3 条 vs 展开 7+ 条 |
| 180-181 | 中途障碍 | 直道中间有墙，steps 撞墙自动停+转向绕行 | steps 撞墙自动停（行为教学点） |
| 182-183 | 多箱直推 | 推箱A 3格→转向→推箱B 2格 | steps 省在长推距 |
| 184 | 路径选择 | 长直线（steps 高效）vs 短弯路（多指令） | 激励参数化选择 |
| 185 | 混合 if+steps | if 分支内用 steps | 综合分支+参数两教学点 |

**关卡设计保证**：展开写（N×fwd 或 rep）≥ 1.5×b（含 steps 最优），否则 steps 无星级优势。

### 2.5 b 值口径（Oracle I4：新关=含 steps 最优编写量，旧关不动）

- **176-185 新关**：`b` = **含 steps 的最优编写量**（一条 steps 计 1 条）
  - 求解器：BFS 枚举 `{id:'steps', steps:N}` 作为单条指令（不展开 N 步），求最短编写量
  - star 阈值：`totalSteps <= b*1.5 → 3★`（与 D5 循环指令一致）
- **1-175 旧关**：`b` 保持 push count 不动，star 逻辑不变（不回归）
- 设计文档补入此口径定义

### 2.6 星级计算

- totalSteps：steps 指令计 **1 条**（`c.rep||1` 对 steps 天然 =1，无需改）——激励用参数化
- b 值：176-185 新关 = 含 steps 最优编写量
- 关卡保证：展开写 ≥ 1.5×b → 用 steps 才 3★（复用 D5 循环指令验证模式，Oracle 确认一致）
