## 2. 发现的问题

### 🔴 重要级（已修复）

**F1 — `_execTop` 跨轮残留导致失败定位错位**

- **位置**：`main.js` execRun（设顶层 `_execTop` 不递归清分支内）+ execIf（`=== undefined` 判断只设一次）+ resetLoopLeft（只清 `_loopLeft` 不清 `_execTop`）
- **问题**：分支内指令的 `_execTop` 由 execIf 按需设置且**只设一次**。执行→失败→重置→编辑指令改变 if 顶层索引→再执行时，分支内残留旧 `_execTop` 不被刷新，`findCmdIndex` 读残留索引跳过引用查找 → 失败定位指向错误指令。
- **触发场景**（Oracle 推演确认可复现）：第 1 轮 if 在索引 1 → 删除前置指令 if 下移到索引 0 → 第 2 轮分支内失败 → errIdx 返回残留的 1（应指向 0）。
- **影响**：失败调试反馈"第 N 条指令"错位，误导孩子；不影响通关判定/星级。
- **修复**（方案 A，1 行）：execIf 无条件覆盖 `branch[i]._execTop = cmd._execTop`（去掉 `=== undefined` 判断）。
- **回归验证**：F1 专项测试 10/10 通过（跨轮残留场景 err 定位正确指向 if 块当前索引）。
