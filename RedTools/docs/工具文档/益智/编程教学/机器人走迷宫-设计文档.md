## 2. 玩法设计

### 2.1 规则

- 迷宫盘面 = 推箱子关卡（Microban I，XSB 格式）：墙、地板、目标点、箱子。
- 孩子用**指令积木**编排机器人的移动序列：`↑ 前进` / `↰ 左转` / `↱ 右转` / `🧱 前方探测`。
- 点「▶ 执行」后机器人按指令序列移动；**前方有箱子则推动**（推箱逻辑同推箱子）。
- 胜利条件：执行完成后**所有箱子都在目标点**（isWon 判定）= 有标准答案。
- 失败不惩罚：执行完箱子未到位 → 提示「还有箱子没到目标点，调整指令再试」。

### 2.2 指令系统（v1.0 → v1.5，编程教学核心概念路线）

| 版本 | 概念 | 指令 | 说明 |
|---|---|---|---|
| v1.0 | 顺序 | ↑ 前进 / ↰ 左转 / ↱ 右转 | 顺序编排 + 观察调试 |
| v1.1 | 循环 | 指令 chip ×2/×3/×4 | 单击 chip 循环次数递增（1→2→3→4→1），循环启蒙 |
| v1.3 | 条件 | 🧱 前方探测 | **探测前方**：前方为墙/箱子/边界 → 条件成立「不前进」；前方空地 → 前进一格（避障守卫） |
| **v1.5** | **分支** | **❓ if前方有墙** | **if/else 条件分支**：前方有墙/箱子/边界 → 执行 then 分支指令组；否则 → 执行 else 分支指令组 |

- **🧱 前方探测（v1.3 新增）**：一个「安全前进/避障」条件指令——机器人先看前方有没有障碍，
  没有才动。孩子用它避免「撞墙/撞箱」，为 if/else 条件分支打基础（单指令级条件判断）。
- **❓ if前方有墙（v1.5 新增）**：**多指令分支结构**——如果前方有障碍（墙/箱/边界），执行
  **then 分支**（一组指令）；否则执行 **else 分支**（另一组指令）。这是编程核心概念「分支结构」
  （if/else）的正式教学，与 v1.3 单指令「条件跳过」构成递进：条件跳过是「成立就不走这一步」，
  分支是「成立走 A 组指令，不成立走 B 组指令」。
- 单条指令可带循环次数（rep），循环在**执行时展开**：指令实际执行 rep 次，动画可见。
- 星级基准 = **实际执行步数**（循环展开后 totalSteps；if 块计 1 条 + 分支内指令数）vs 关卡最优 b。

### 2.3 交互

| 输入 | 说明 |
|---|---|
| 点指令按钮 | 追加指令到序列（右侧序列展示 1.↑ 2.🚧…） |
| 点序列 chip | 循环次数递增（1→2→3→4→1），chip 显示 ×N（if 块除外） |
| **点 if 块 chip** | **v1.5：打开分支编辑区（editCtx），编辑 then/else 两栏指令** |
| 点 chip ✕ | 删除该条指令（if 块需确认） |
| ↺ 清空 | 清空指令序列 |
| ▶ 执行 | 从初始盘面执行全部指令（每步 260ms 动画） |
| ⟲ 重置 | 重置到初始盘面（保留序列） |
| 下一关 › | 通关后出现，进入下一关 |

### 2.4 v1.5 if/else 条件分支教学（新）

**教学定位**（方案 §1.4）：全可见棋盘上 if/else 不是「必要条件」（孩子可预先知道方向），
而是**更高效编程策略**——岔路口关卡中，展开写需要为每个岔路口写多条转弯指令，
用 `❓ if前方有墙` 一个指令块即可让机器人自动按前方状态走对应分支。类比 v1.1 循环指令：
展开写也能解，但循环/分支块更高效（编写量更少 → 星级更高）。

**数据结构**：`{ id:'if', then:[指令对象数组], else:[指令对象数组] }`（无 rep 字段；
if 块是条件分支不是循环，`cycleRep()` 跳过）。

**执行语义**（工作队列模型）：
1. 求值条件：机器人前方（当前 face 方向）越界/墙/箱子 = 有障碍
2. 有障碍 → 执行 `then` 分支内全部指令；无障碍 → 执行 `else` 分支内全部指令
3. 分支内可含：前进/左转/右转（含 rep）/嵌套 if 块（v1.5 限制最多嵌套 2 层）
4. 分支内指令执行时继承父级 if 块的顶层下标（高亮/失败定位回溯到父级 if chip）

**关卡设计**（v1.5 新增 20 关 156-175，全部推箱子 + 岔路口）：
- 每关含 1-2 个「岔路口」：机器人站在岔路口，前方有墙（then 路）vs 前方无障碍（else 路）
- **展开写可解**（不强制用 if），但用 if/else 编写量更少 → 星级更高（激励分支结构）
- 三档渐进：156-165 简单（单岔路）→ 166-172 进阶（双岔/长推）→ 173-175 挑战（嵌套/多箱）
- b 值 = BFS 求解器自动计算的展开解指令数（脚本验证 20/20 可解）

## 4. 技术设计

### 4.1 数据模型

- **关卡数据**：`window.LEVELS = [{g:[XSB行], b:最少推动数|null}]`（levels.js，更名自推箱子，
  Microban I 155 关全量内嵌 + v1.5 新增 20 关（156-175，推箱子岔路口），b 由求解器预计算）。
- **难度区段**（`LEVELS_CFG`）：easy 1-30 / normal 31-80 / hard 81-175（v1.2 由 1-15 全量扩展；v1.5 hard 上限 155→175）。
- **运行时状态**：`state = { level, levelIdx, w, h, walls:{idx:true}, goals:{idx:true}, boxes:{} , player:idx, face:0, cmds:[{id,rep}|{id:'if',then,else}], execQueue:[], queueIdx:0, curTop:-1, MAX_QUEUE:500, execDone, won, ... }`
  - `face` 朝右 0/下 1/左 2/上 3（`DIRS = [[1,0],[0,1],[-1,0],[0,-1]]`）
  - idx = `y*w + x`，walls/goals/boxes 为哈希集对象
  - v1.5：`execQueue` 工作队列 + `queueIdx` 队列位置 + `curTop` 当前执行指令的顶层 chip 下标（高亮）
  - v1.5：if 块指令对象 `{id:'if', then:[], else:[]}`（无 rep；cycleRep 跳过）
- **存储**（V0.4 迁移）：`LX_SHARED.storage.configure({toolName:'jiqirenzoumi'})` → 键 `redtools.jiqirenzoumi.v1`；
  结构 `{ version, best:{easy,normal,hard}, recent:{...}, checkin:{dates,streak}, history:[] }`。

### 4.2 执行器（v1.5 工作队列模型）

```
execRun(): 已执行/已通关/空序列 → return；loadLevelState() 重置盘面
  execQueue = cmds.slice()（浅拷贝，指令对象共享引用）
  顶层指令标记 _execTop = i（分支指令插入时继承父级 if 的顶层下标）
  resetLoopLeft(cmds) 递归清零所有 _loopLeft（含 then/else 分支内指令）
execStep(): queueIdx ≥ execQueue.length → execDone + checkWin()
  execQueue.length > MAX_QUEUE(500) → 自动终止（防 if 无限展开）
  cmd = execQueue[queueIdx]; queueIdx++
  absStep++；curTop = cmd._execTop（分支指令高亮父级 if chip）
  rep-on-cmd：_loopLeft===undefined ? 初始化 rep||1；_loopLeft>0 → splice 回队首（再执行一次）
  按 id 分发：
    left: face=(face+3)%4   right: face=(face+1)%4
    if:   execIf(cmd) — 求值前方障碍 → 选中分支插入队首
    fwd/block: 前向格 (nr,nc)（推箱逻辑同前）
  renderBoardOnly() + renderSeqHighlight() + setTimeout(260ms) 步进

execIf(cmd): 前方越界/墙/箱子 = hasObstacle
  branch = hasObstacle ? cmd.then : cmd.else
  branch 指令继承父级 _execTop → splice.apply(execQueue, [queueIdx, 0].concat(branch))

resetLoopLeft(cmds): 递归遍历 cmds + then/else 分支，全部 _loopLeft = undefined
```

- **废弃递归模型**：v1.4 的 `state.prog` 线性索引与 if 分支插入不兼容，v1.5 改为**可变工作队列**
  （队首弹出 + 分支插入队首，天然支持嵌套 if = 递归插入）。
- **firstFail 追溯**（v1.5）：`firstFail.cmd` 记录**指令对象引用**（非 prog 索引）；
  `checkWin` 用 `findCmdIndex(cmd)` 回溯——顶层指令返回自身下标，分支内指令回溯到父级 if 块
  的顶层下标（错误定位到 if chip）。
- **循环计数修复（v1.3 保持）**：`_loopLeft` 用 `=== undefined` 判初始化（0 = 执行完，不能重置）；
  v1.5 execRun 改 `resetLoopLeft` 递归清零。
- **block 语义落地（v1.3 保持）**：复用 fwd 的方位/边界计算，但**不推箱**——前方有箱视为障碍停步。

### 4.3 渲染

- SVG `board-svg`（viewBox 0 0 w*32 h*32）：墙 rect / 地板 rect / 目标 circle / 箱 rect 双层 / 玩家蓝圆+白眼。
- 执行中每步 `renderBoardOnly()` 重建（≤13×15=195 格，开销可忽略）。

### 4.4 判定/星级

- **胜利**：所有箱子在目标集合（箱数=目标数由关卡保证）。
- **星级**（实际指令步数 vs 最优推动数 b，扁平宽松）：
  - b≠null：steps ≤ b×1.5 → 3★；≤ b×2.5 → 2★；通关 1★
  - b=null（19 关求解超时）：通关 2 星封顶
  - v1.5：if 块计编写量 = 1 + then.length + else.length（用 if 编写量更少 → 星级更高，激励分支）
  - 重复通关仅当星级更高或推进更远才覆盖 best
- **打卡**：通关一关写入今日（去重、365 天滚动）、重算连续天数（对齐 `docs/通用需求-打卡分享记录.md`）。

## 5. 合规自检（Chrome 61 / 容器规范）

- JS：ES2017 经典脚本（var/function），无 `?.`/`??`/对象展开/module/import/内联事件/eval/fetch/XHR/Worker。
- CSS：无 `gap`/`aspect-ratio`/`clamp()`/逻辑属性/`:has`；flex 兼容写法；无外部 URL。
- 资源：SVG 程序化渲染零素材；无 CSP meta（容器管理）。
- 包体：zip ≈ 0.02 MiB（≪ 2 MiB 建议值）。
- 存储：LX_SHARED.storage 本地键，不联网上传；无追踪/无广告/无内购。
