**差异化机会**：
1. **零图片素材**：全部卡片图案由 SVG 代码程序化生成（24 个童趣图标），包体仅 0.03 MiB，

2. **无限新布局**：随机选 N 个图标 × 每图标 2 张卡 → 洗牌布阵 → 每次进游戏都是新布局 ✅

   而非盲目乱翻 ✅
4. **扩展预留**：图标库独立（icons.js `window.ICONS`），后续可换成语、单词卡等主题 ✅

## 2. 玩法规则

1. **开局**：从首页选择难度进入（简单 6 对 / 进阶 8 对 / 挑战 10 对）。
2. **出题**：随机选 N 个图标（24 选 N，不重复）→ 每个图标做 2 张卡 → Fisher-Yates 洗牌布阵。
3. **翻牌**：所有卡片背面朝上；点击翻一张，每次最多翻开 2 张。
4. **配对判定**：
   - 两张图标相同 → 配对成功，绿色边框锁定，保持翻开；
   - 两张图标不同 → 红色边框闪烁约 500ms 后翻回。
5. **步数**：每翻满 2 张计 1 步（无论成功失败），结果页展示，引导减少无效翻牌。
6. **计时**：第一次翻牌时启动计时；全部配对完成结束计时。
7. **结算**：全部配齐即 `finishGame()`，显示用时 + 步数 + 星级 + 打卡。
8. **动画锁定**：配对判定动画期间（`state.busy`）不接受点击，避免连点错乱。

> 设计考量：卡片必须**点满 2 张才判定**，期间其余卡片可翻、可改变主意重翻同一张（防误触），
> 符合低龄儿童的触屏操作习惯；`busy` 锁只在两张不同等待翻回时启用。

## 3. 程序化 SVG 图标库（核心方案）

### 3.1 图标库（icons.js `window.ICONS`，24 个）

| 图标 | id | 图标 | id | 图标 | id |
|---|---|---|---|---|---|
| 太阳 | sun | 云朵 | cloud | 月亮 | moon |
| 星星 | star | 花朵 | flower | 大树 | tree |
| 小鱼 | fish | 帆船 | boat | 苹果 | apple |
| 西瓜 | watermelon | 蝴蝶 | butterfly | 爱心 | heart |
| 雨滴 | raindrop | 雪花 | snow | 气球 | balloon |
| 猫咪 | cat | 蘑菇 | mushroom | 飞机 | plane |
| 彩虹 | rainbow | 蜜蜂 | bee | 雪人 | snowman |
| 皇冠 | crown | 吉他 | guitar | 火箭 | rocket |

- 每个图标：`{ id, label, draw() }`，`draw()` 返回以 (0,0) 为中心的完整 `<svg>` 字符串
  （`viewBox="-20 -20 40 40"`，糖果色填充，童趣扁平风）。
- 形状工具函数（`c/ce/rc/pl/pa/ln/star/starPts`）与 `svgWrap` 为 icons.js 局部函数，
  后续记忆力类工具（图形序列复刻 / 位置记忆）可直接复制扩展。
- 图标以「形状 + 颜色」双重区分，颜色均为高对比糖果色（红 #ff6b6b / 黄 #ffd23f /
  蓝 #5b8def / 紫 #c98aff 等），低龄也容易分辨。

### 3.2 出题引擎（main.js `buildDeck`）

```
洗牌 ICONS → 取前 level 个 → 每个图标 push 2 张卡（{id, iconId, matched:false}）→ 再洗牌 → 布阵
```

- 每次进游戏（含「重新开始」「再来一局」）重新出题，布局不重复。
- `iconSvg(iconId)` 按 id 查 ICONS 并调用 `draw()`，卡片正面 `innerHTML` 渲染。

## 4. 难度与星级

### 4.1 难度定义（main.js `LEVELS` 常量）

| 难度 | label | 对数 | 网格 | 卡片宽 | 3★ 阈值（threeMs） | 2★ 阈值（twoMs） |
|---|---|---|---|---|---|---|
| 简单 | 简单 · 6 对 | 6 | 4 列 × 3 行 | 25% | ≤25000ms（25 秒） | ≤50000ms（50 秒） |
| 进阶 | 进阶 · 8 对 | 8 | 4 列 × 4 行 | 25% | ≤45000ms（45 秒） | ≤90000ms（90 秒） |
| 挑战 | 挑战 · 10 对 | 10 | 5 列 × 4 行 | 20% | ≤75000ms（75 秒） | ≤150000ms（150 秒） |

### 4.2 星级评级

| 难度 | 3★ | 2★ | 1★ |
|------|------|------|------|
| 简单（6 对） | ≤25 秒 | ≤50 秒 | 其余 |
| 进阶（8 对） | ≤45 秒 | ≤90 秒 | 其余 |
| 挑战（10 对） | ≤75 秒 | ≤150 秒 | 其余 |

> ⚠️ 星级阈值为需求草案参考值，待真机实测后按真实分布校准。

`calcStars(level, ms)`：`ms <= threeMs` → 3★；`ms <= twoMs` → 2★；否则 1★。

## 5. 页面/视图结构

```
首页 viewHome（3 个难度卡片 + 各难度最佳成绩/未挑战 + 底栏导航 成绩/打卡/首页）
  │ 点击难度卡片
  ▼
游戏页 startGame（顶部 返回|难度|计时|已配对 / 卡片网格 / 步数 / 重新开始）
  │ 全部配对完成 → finishGame（延迟 350ms）
  ▼
结果浮层 showResult（完成 / 大号用时 / 用时·步数·配对统计 / 星级 / 新纪录横幅 / 再来一局 / 返回首页）

底栏导航：成绩 viewHistory（最近 30 次，时间倒序） │ 打卡 viewCheckin（本月日历 + 连续天数）
```

- **顶栏（app-header）**：`renderHeader(title)` 渲染图标 + 标题 + 版本号（来自 `APP.meta.version`）。
- **首页 `viewHome`**：标题「选择难度」+ 提示「翻开卡片，找出相同的图案，全部配对过关！」；
  3 个难度卡片（`diff-card`），每张含难度按钮 + 该难度最佳成绩（`最佳 x.x 秒`，未玩过显示「未挑战」）。
- **游戏页 `startGame`**：
  - 顶部状态栏：`‹ 返回` | `难度label`（如「简单 · 6 对」）| `⏱ 00.0` | `配对 0/6`（绿色）；
  - 卡片网格 `memory-grid grid-<对数>`：flex-wrap 铺排，卡片为**正方形**（宽度百分比 +
    同值 `padding-bottom`，相对同一容器宽度）；
  - 状态行 `game-status`：`步数 0`（居中）；
  - 底部「重新开始」按钮（重新出题再来，步数/配对/计时清零）。
  - 游戏页**不渲染底栏导航**（顶部返回 + 底部重新开始，避免误触退出）。
- **结果浮层 `showResult`**：全屏半透明遮罩 + 白色卡片，含「完成！」、大号用时、
  用时/步数/配对统计、星级、新纪录时「🎉 新纪录！」、以及「再来一局」「返回首页」；
  `finishGame` 延迟 350ms 后展示，让最后一对配对的绿色锁定先被看到。
- **成绩页 `viewHistory`**：无记录时提示「暂无成绩，先来一局吧！」；否则按时间倒序列出
  最近 N 次（难度 / 日期·步数 / 用时 / 星级）。
- **打卡页 `viewCheckin`**：本月日历（已打卡日高亮点亮 + 今日紫色描边）+ 连续打卡天数
  （≥7 天显示 🎉）；打卡由完成游戏自动触发，本页仅展示。

### 5.1 状态模型（main.js `state`）

```js
{
  level: 6,          // 当前难度 6 / 8 / 10（对数）
  cards: [],         // 卡片列表 [{id, iconId, matched}]（buildDeck 生成）
  flipped: [],       // 当前翻开卡片的 id（最多 2 个）
  pairs: 0,          // 已配对对数
  moves: 0,          // 步数（每翻满 2 张计 1）
  busy: false,       // 配对判定动画中（两张不同等待翻回），锁定点击
  started: false,    // 是否已开始计时（首次翻牌置 true）
  finished: false,   // 是否已结算
  startMs: 0,        // 开始计时时间戳（performance.now()）
  elapsed: 0,        // 结算用时 ms
  timerId: null      // setInterval 句柄
}
```

另维护 `cardEls[]`（按 card.id 索引的 DOM 元素，翻牌/配对/翻回时改 className）。

## 6. 成绩持久化（localStorage key `redtools.memorypair.v1`）

```js
{
  version: 1,
  best:   { "6": {ms, date}, "8": null, "10": null },  // 各难度最佳（ms 更小覆盖）
  recent: { "6": ms, "8": 0, "10": 0 },                // 各难度最近成绩
  checkin: { dates: ["YYYYMMDD"], streak },            // 打卡日期（滚动 365 天）+ 连续天数
  history: [ {date, level, ms, moves, stars} ]          // 滚动 30 条，最新在前
}
```

- 读写均包 try/catch：`loadStore` 解析失败或首次打开返回默认结构；`saveStore` 写入失败静默。
- 启动时先 `loadStore()` 再 `saveStore()`（初始化写入，建立默认结构）。
- **最佳成绩**：`msRound = Math.round(elapsed)`；`best[level]` 为空或 `msRound < best.ms` 时
  覆盖为 `{ms, date}` 并标记新纪录（结果浮层显示「🎉 新纪录！」）。
- **最近成绩**：`recent[level]` 直接覆盖为本局用时。
- **历史**：`history.unshift(...)` 最新在前，`while (length > 30) pop()` 滚动保留 30 条；
  每条含 `moves` 字段（记录本局步数，便于回顾策略质量）。

### 6.1 打卡逻辑（与学科系列/舒尔特方格一致）

- 完成一局即自动打卡：`todayStr()` 生成 YYYYMMDD，不在 `dates` 则 push，然后 `sort()`；
  `while (dates.length > 365) dates.shift()` 滚动保留 365 天。
- 连续天数 `calcStreak(dates)`：从日期列表末尾向前回推，**含今天**往前数连续天数，
  跨天即断（缺一天 streak 归零）；结果写入 `checkin.streak`，打卡页渲染时实时重算。
- 打卡无手动入口，本工具「完成一局」即点亮今日。

## 7. 关键实现点

### 7.1 翻牌与配对（`onCardTap` / `compareCards`）

- `state.finished` / `state.busy` 时忽略点击；已配对（`card.matched`）或已翻开
  （`state.flipped` 中含该 id）的卡忽略。
- 首次翻牌 → `started=true` + `startMs=performance.now()` + `startTimer()`。
- 翻满 2 张 → `moves++` + `compareCards()`：
  - 图标相同 → 两卡 `matched=true` + `.matched` 类（绿色边框锁定）+ `pairs++` + 清空 flipped；
    `pairs >= level` → `finishGame()`；
  - 图标不同 → `busy=true` + `.miss` 类（红色边框），500ms 后移除 `.flipped`/`.miss` 类、
    清空 flipped、`busy=false`。

### 7.2 卡片 3D 翻转（style.css）

- `.card`：`perspective: 600px`（-webkit- 双写）；
- `.card-inner`：`transform-style: preserve-3d` + `transition: transform 0.3s`；
- `.card-face`：绝对定位撑满 + `backface-visibility: hidden`；背面（`.card-back`）紫色渐变 +
  白色问号；正面（`.card-front`）白底图标，预置 `rotateY(180deg)`；
- `.card.flipped .card-inner` → `rotateY(180deg)`，露出正面。
- 卡片间距不用 flex gap：内层 `.card-inner` 相对卡片内缩 4px（left/top/right/bottom），
  白色网格背景形成间隔。

### 7.3 正方形卡片网格

- 卡片 `width: 25%`（挑战 `20%`）+ `padding-bottom` 同值百分比——两者相对**同一容器宽度**，
  卡片天然正方形且按列数精确铺满（4 列 / 5 列），无换算误差；
- `.memory-grid` 用 flex-wrap（-webkit- 前缀双写），子项 `min-width:0` 防溢出。

### 7.4 计时与安全区（同舒尔特方格）

- `performance.now()` 实算差值 + `setInterval(100ms)` 刷新（后台回来计时仍准）；
- `syncAppHeight()` 写 `--app-height`，`env(safe-area-inset-*)` + `@supports` 双兜底。

## 8. Chrome 61 / 合规约束

| 类别 | 约束 | 本工具做法 |
|---|---|---|
| JS 语法 | ES2017 上限经典脚本 | `var` + `function` 风格，无 `?.` `??` 对象展开 `replaceAll`；无 `type="module"`/import/export |
| 事件 | 全部 `addEventListener` | 卡片点击逐个绑定（闭包保留 idx）；无内联事件 / eval |
| 网络 | 零网络请求 | 无 fetch/XHR/Worker/外部资源；无 audio；SVG 全代码生成（`http://www.w3.org/2000/svg` 仅为命名空间标识符，非网络请求） |
| 图片 | 无图片素材 | 除构建生成的 `assets/icon.png` 外，一切图形 SVG 代码生成；zip 内无额外图片文件 |
| CSS 语法 | Chrome 61 兼容层 | 无 flex `gap`/`aspect-ratio`/`clamp`/`inset`/逻辑属性/`:has`/`@container`/`dvh`；3D 翻转 `-webkit-` 前缀双写；Flex 子项设 `min-width:0` |
| 动画 | 温和反馈（光敏安全） | 翻转 0.3s、配对失败红框 0.5s，无强频闪 |
| 触控 | 触摸友好 | 卡片 hit area ≥48px（6 对下约 100px 宽）；按钮 min-height 48px |

静态工具：`datasource='static'`，无 book/图片/音频素材，无单元概念。

`tools.py` 登记：

```python
ToolConfig(
    series="益智", tool="翻牌记忆配对",
    subgroup="记忆力",            # → series/益智/记忆力/翻牌记忆配对/

```

```
src/（index.html + assets/）──► copy_static ──► dist/益智/翻牌记忆配对/

        ├─► make_static_icon（icon_base.png 母版 + 角标「翻牌记忆配对」
```
