## 2. 玩法规则

1. **开局**：从首页选择难度进入（简单 2×2 / 进阶 3×3 / 挑战 4×4）。
2. **出题**：随机取一个场景 → 按 N×N 切块 → Fisher-Yates 洗牌打乱；
   若洗牌后恰好已还原则重新洗（guard ≤ 100）。
3. **点选与交换**：点一块碎片 → 紫色高亮选中；点另一块 → 交换位置（步数 +1）；
   点已选中的同一块 → 取消选中（防误触）。
4. **归位判定**：每块 `curRow === row && curCol === col` 即归位，顶部显示「归位 x/N」；
   全部归位即 `isSolved()` → `finishGame()`。
5. **计时**：第一次点选时启动计时；全部归位结束计时。
6. **结算**：全部归位即 `finishGame()`，显示用时 + 步数 + 归位 n/n + 星级 + 打卡。
7. **完成反馈**：全部碎片加 `.solved` 绿色边框闪烁 400ms → 350ms 后弹出结算浮层。

> 设计考量：交换玩法不要求按住拖动，两块互换即可逐步还原，符合低龄儿童的触屏操作习惯；
> 步数只做策略引导指标（先观察参照图再动手），不影响星级；参照图与目标画面一一对应，
> 练的正是"这块该回到哪个位置"的空间方位感。

## 3. 程序化 SVG 场景切块（核心方案）

### 3.1 场景库（scenes.js `window.SCENES`，8 个 400×400 正方形场景）

| 场景 | id | 元素数 | 场景 | id | 元素数 |
|---|---|---|---|---|---|
| 海边 | ocean | 9 | 农场 | farm | 9 |
| 森林 | forest | 8 | 海底 | undersea | 9 |
| 太空 | space | 9 | 冬日 | winter | 9 |
| 花园 | garden | 8 | 城堡 | castle | 8 |

- 每个场景：`{ id, name, w, h, bg, elements }`，`w/h` 均为 400（正方形视口）；
  `bg` 为背景 SVG 字符串（全视口坐标，含渐变 defs）；`elements` 为 6~9 个元素，铺满画面、互不重叠。
- 每个元素：`{ id, x, y, s, draw }`，`x/y` 为元素中心（视口坐标）、`s` 为缩放；
  `draw(opt)` 返回以 (0,0) 为中心的内层 SVG 字符串，由渲染层套 `<g transform>` 定位。
- 形状工具函数（`c/cc/ce/rc/pl/pa/ln/star/starPts/cloudDraw`）为 scenes.js 局部函数，
  后续空间感知类工具（找不同差异场景 / 旋转配对）可直接复制扩展。
- 元素以「形状 + 颜色」双重区分，糖果色高对比（红 #ff5b5b / 黄 #ffd23f / 蓝 #4a90c4 等），
  切块后局部画面也容易辨认。

### 3.2 切块与出题引擎（main.js `buildPieces`）

```
生成 N×N 碎片 {id, row, col}（row/col 为目标行列）→ Fisher-Yates 洗牌 →
若 isSolvedArr 恰好已还原则重洗（guard≤100）→ 按数组索引重算 curRow/curCol
```

- 数组索引 = 当前槽位；`row/col` = 目标位置（场景中的行列），`curRow/curCol` = 当前位置。
- 每次进游戏（含「重新开始」「再来一局」）重新随机场景 + 重新洗牌，布局不重复。
- `pieceSvg(p)`：碎片 `<svg viewBox="x y w h">` 内嵌**完整场景 SVG**
  （`sceneContent` = 背景 + 各元素 `<g transform>`），viewBox 取该块「目标行列」区域，
  由浏览器裁剪显示局部；**归位即恢复完整画面**。
- 参照图 `fullSceneSvg(scene)`：`viewBox="0 0 400 400"` 内嵌完整场景内容。

## 4. 难度与星级

### 4.1 难度定义（main.js `LEVELS` 常量）

| 难度 | label | 块数 | 网格 | 3★ 阈值（threeMs） | 2★ 阈值（twoMs） |
|---|---|---|---|---|---|
| 简单 | 简单 · 2×2 | 4 | 2×2 | ≤25000ms（25 秒） | ≤60000ms（60 秒） |
| 进阶 | 进阶 · 3×3 | 9 | 3×3 | ≤90000ms（90 秒） | ≤180000ms（180 秒） |
| 挑战 | 挑战 · 4×4 | 16 | 4×4 | ≤240000ms（240 秒） | ≤480000ms（480 秒） |

- 难度档位与学段对应：2×2 → L1 preK；3×3 → L2 K1-3；4×4 → L3 K4-6（从少块到多块）。

### 4.2 星级评级

| 难度 | 3★ | 2★ | 1★ |
|------|------|------|------|
| 简单（2×2） | ≤25 秒 | ≤60 秒 | 其余 |
| 进阶（3×3） | ≤90 秒 | ≤180 秒 | 其余 |
| 挑战（4×4） | ≤240 秒 | ≤480 秒 | 其余 |

> ⚠️ 星级阈值为需求草案参考值，待真机实测后按真实分布校准。

`calcStars(level, ms)`：`ms <= threeMs` → 3★；`ms <= twoMs` → 2★；否则 1★。

## 5. 页面/视图结构

```
首页 viewHome（3 个难度卡片 + 各难度最佳成绩/未挑战 + 底栏导航 成绩/打卡/首页）
  │ 点击难度卡片
  ▼
游戏页 startGame（顶部 返回|难度|计时|归位 x/N / 参照图区 / 拼图网格 / 步数 / 重新开始）
  │ 全部归位 → finishGame（延迟 350ms）
  ▼
结果浮层 showResult（完成！ / 大号用时 / 用时·步数·归位 n/n / 星级 / 新纪录横幅 / 再来一局 / 返回首页）

底栏导航：成绩 viewHistory（最近 30 次，时间倒序） │ 打卡 viewCheckin（本月日历 + 连续天数）
```

- **顶栏（app-header）**：`renderHeader(title)` 渲染图标 + 标题 + 版本号（来自 `APP.meta.version`）。
- **首页 `viewHome`**：标题「选择难度」+ 提示「点选两块拼图交换位置，拼出完整图片！」；
  3 个难度卡片（`diff-card`），每张含难度按钮 + 该难度最佳成绩（`最佳 x.x 秒`，未玩过显示「未挑战」）。
- **游戏页 `startGame`**：
  - 顶部状态栏：`‹ 返回` | `难度label`（如「简单 · 2×2」）| `⏱ 00.0` | `归位 0/N`（绿色）；
  - 参照图区 `renderRef()`：完整图缩略 90px（2×2/3×3 常显；4×4 默认 `.hide` 隐藏 +
    「看原图」按钮 → `ref-overlay` 大图浮层 3 秒自动关闭，点击浮层也可关）；
  - 拼图网格 `puzzle-grid grid-<n>`：flex-wrap 铺排，碎片为**正方形**（宽度百分比 +
    同值 `padding-bottom`，2×2→50%、3×3→33.33%、4×4→25%）；
  - 状态行 `game-status`：`步数 0`（居中）；
  - 底部「重新开始」按钮（重新随机场景出题再来，步数/计时/归位清零）。
  - 游戏页**不渲染底栏导航**（顶部返回 + 底部重新开始，避免误触退出）。
- **结果浮层 `showResult`**：全屏半透明遮罩 + 白色卡片，含「完成！」、大号用时、
  用时/步数/归位 n/n 统计、星级、新纪录时「🎉 新纪录！」、以及「再来一局」「返回首页」；
  `finishGame` 延迟 350ms 后展示，让全部碎片的绿色归位闪烁先被看到。
- **成绩页 `viewHistory`**：无记录时提示「暂无成绩，先来一局吧！」；否则按时间倒序列出
  最近 N 次（难度 / 日期·步数 / 用时 / 星级）。
- **打卡页 `viewCheckin`**：本月日历（已打卡日高亮点亮 + 今日蓝色描边）+ 连续打卡天数
  （≥7 天显示 🎉）；打卡由完成游戏自动触发，本页仅展示。

### 5.1 状态模型（main.js `state`）

```js
{
  level: 2,          // 当前难度 2 / 3 / 4
  scene: null,       // 当前场景对象（SCENES 随机取一个）
  sceneHtml: '',     // 场景内容 SVG 字符串（bg + 各元素）
  pieces: [],        // 碎片列表 [{id, row, col, curRow, curCol}]，数组索引=当前槽位
  selected: -1,      // 当前选中槽位索引，-1 表示未选中
  moves: 0,          // 步数（每次交换 +1）
  started: false,    // 是否已开始计时（首次点选置 true）
  finished: false,   // 是否已结算
  startMs: 0,        // 开始计时时间戳（performance.now()）
  elapsed: 0,        // 结算用时 ms
  timerId: null,     // setInterval 句柄
  refTimer: null     // 参照大图浮层 setTimeout 句柄
}
```

另维护 `pieceEls[]` / `pieceSvgEls[]`（按槽位索引的碎片 DOM 元素与内层 `<svg>`，
选中/交换/归位时改 className 与 viewBox）。

## 6. 成绩持久化（localStorage key `redtools.jiandanpintu.v1`）

```js
{
  version: 1,
  best:   { "2": {ms, date}, "3": null, "4": null },  // 各难度最佳（ms 更小覆盖）
  recent: { "2": ms, "3": 0, "4": 0 },                // 各难度最近成绩
  checkin: { dates: ["YYYYMMDD"], streak },           // 打卡日期（滚动 365 天）+ 连续天数
  history: [ {date, level, ms, moves, stars} ]         // 滚动 30 条，最新在前
}
```

- 读写均包 try/catch：`loadStore` 解析失败或首次打开返回默认结构；`saveStore` 写入失败静默。
- 启动时先 `loadStore()` 再 `saveStore()`（初始化写入，建立默认结构）。
- **最佳成绩**：`msRound = Math.round(elapsed)`；`best[level]` 为空或 `msRound < best.ms` 时
  覆盖为 `{ms, date}` 并标记新纪录（结果浮层显示「🎉 新纪录！」）。
- **最近成绩**：`recent[level]` 直接覆盖为本局用时。
- **历史**：`history.unshift(...)` 最新在前，`while (length > 30) pop()` 滚动保留 30 条；
  每条含 `moves` 字段（记录本局步数，便于回顾"先想再换"的策略质量）。

### 6.1 打卡逻辑（与学科系列/舒尔特方格一致）

- 完成一局即自动打卡：`todayStr()` 生成 YYYYMMDD，不在 `dates` 则 push，然后 `sort()`；
  `while (dates.length > 365) dates.shift()` 滚动保留 365 天。
- 连续天数 `calcStreak(dates)`：从日期列表末尾向前回推，**含今天**往前数连续天数，
  跨天即断（缺一天 streak 归零）；结果写入 `checkin.streak`，打卡页渲染时实时重算。
- 打卡无手动入口，本工具「完成一局」即点亮今日。

## 7. 关键实现点

### 7.1 点选与交换（`onPieceTap` / `swapSlots` / `isSolved`）

- `state.finished` 时忽略点击。
- 首次点选 → `started=true` + `startMs=performance.now()` + `startTimer()`。
- `selected === -1` → 选中该块，加 `.selected` 类（紫色描边）；
  `selected === slot` → 取消选中（防误触）；
  否则 → 交换：先移除旧选中高亮，`swapSlots(a, slot)` + `moves++` +
  `updateMoves()` + `updateSolved()`；随后 `isSolved()` 为真 → `finishGame()`。
- `swapSlots(a, b)`：交换 `state.pieces[a]` / `state.pieces[b]` 数组元素 →
  按新槽位重算两块的 `curRow/curCol` → `updatePieceSvg(a/b)` 只 `setAttribute('viewBox', ...)`，
  **不重建 DOM**（性能关键：交换仅改两个 svg 属性）。
- `isSolved()`：逐块判断 `curRow === row && curCol === col`，全真即归位。

### 7.2 程序化 SVG 切块（`pieceSvg`）

- 碎片 viewBox = 该块**目标行列**区域：`x = col*size`、`y = row*size`、`wh = size`，
  其中 `size = scene.w / n`；内嵌完整场景 SVG，浏览器裁剪显示局部。
- 归位判定与 viewBox 目标区域一致，**归位即恢复完整画面**，天然自洽。
- SVG 场景经 `innerHTML` 插入允许（容器 CSP 无碍；`xmlns` 仅为命名空间标识符，非网络请求）。

### 7.3 正方形碎片网格

- 碎片 `width` + `padding-bottom` 同为网格宽度百分比（2→50%、3→33.33%、4→25%）——
  两者相对**同一容器宽度**，碎片天然正方形且按列数精确铺满，无换算误差；
- `.puzzle-grid` 用 flex-wrap（-webkit- 前缀双写），子项 `min-width:0` 防溢出；
- 块间缝隙不用 flex gap：内层 `.piece-inner` 相对碎片内缩 4px（left/top/right/bottom）。

### 7.4 计时与安全区（同舒尔特方格）

- `performance.now()` 实算差值 + `setInterval(100ms)` 刷新（后台回来计时仍准）；
- `syncAppHeight()` 写 `--app-height`，`env(safe-area-inset-*)` + `@supports` 双兜底。

### 7.5 完成反馈动画

- 全部归位时每块加 `.solved` 类：绿色描边（#12b76a）+ `solvedFlash` 0.4s ease-out
  光晕闪烁一次；`finishGame` 延迟 350ms 展示结果浮层，先看到完整画面 + 归位反馈。

## 8. Chrome 61 / 合规约束

| 类别 | 约束 | 本工具做法 |
|---|---|---|
| JS 语法 | ES2017 上限经典脚本 | `var` + `function` 风格，无 `?.` `??` 对象展开 `replaceAll`；无 `type="module"`/import/export |
| 事件 | 全部 `addEventListener` | 碎片点击逐个绑定（闭包保留 slot）；无内联事件 / eval |
| 网络 | 零网络请求 | 无 fetch/XHR/Worker/外部资源；无 audio（未用 Web Audio）；SVG 全代码生成（`http://www.w3.org/2000/svg` 仅为命名空间标识符，非网络请求） |
| 图片 | 无图片素材 | 除构建生成的 `assets/icon.png` 外，一切图形 SVG 代码生成；zip 内无额外图片文件 |
| CSS 语法 | Chrome 61 兼容层 | 无 flex `gap`/`aspect-ratio`/`clamp`/`inset`/逻辑属性/`:has`/`@container`/`dvh`；渐变 `-webkit-` 前缀双写；Flex 子项设 `min-width:0` |
| 动画 | 温和反馈（光敏安全） | 归位绿色闪烁 0.4s 一次，无强频闪 |
| 触控 | 触摸友好 | 碎片 hit area 大（2×2 下约半屏宽）；按钮 min-height 48px（难度卡 56px） |
