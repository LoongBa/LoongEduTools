## 1. 定位

| 项 | 说明 |
|---|---|
| 能力维度 | 空间感知（形状拼合、旋转与方位、局部-整体认知） |
| 目标用户 | 3–10 岁（L1 preK / L2 K1-3 / L3 K4-6） |

## 2. 玩法设计

### 2.1 板块

- 7 块经典七巧板，SVG 程序化渲染（零图片素材）：
  2 大三角 + 1 中三角 + 2 小三角 + 1 正方形 + 1 平行四边形，
  每块填充色（橙/粉/蓝/紫/青/黄/绿）+ 白描边，选中时蓝色高亮 + 阴影。
- 形状数据集中在 `src/assets/tangram.js`（`window.TAN.shapes`），
  顶点以参考点（几何质心）为原点，渲染 `<g transform="translate(x,y) rotate(rot) scale(scale)">`。

### 2.2 图案库（12 款，三档各 4）

每款 = 7 块「目标位 + 旋转角」（`window.TAN.puzzles` 的 `targets`）+ 整体剪影（`outline`），
数据经**几何校验**（7 块两两无重叠 + 采样并集覆盖 outline ≥ 98.9%）：

| 档位 | 图案 |
|---|---|
| 简单（L1 分块占位） | 正方形 / 小房子 / 小鱼 / 小碗 |
| 进阶（L2 整体剪影） | 箭头 / 大鹅 / 小猫 / 小狗 |
| 挑战（L3 缩略参考） | 天鹅 / 火箭 / 海豚 / 大象 |

> 数据源：OMerkel/Tangram（MIT，(c) 2019 Oliver Merkel）经典图案库，
> 由 `build_tangram.py`（本工具目录）解析 `data/challenges.js` + `data/hmi.js` 生成：
> 每块绝对位置 = SVG transform（translate+rotate 45° 步进），统一缩放到 320×320 游戏区（长边 280）。
> 生成时自动校验：非 45° 倍数旋转角图案剔除、7 块无重叠、覆盖 ≥ 95% 才收录。

### 2.3 难度分档（目标提示递减）

| 档位 | 学段 | 目标提示 |
|---|---|---|
| 简单 | L1 preK | SVG 内显示**分块占位轮廓**（每块目标位蓝色虚线描边，一目了然） |
| 进阶 | L2 K1-3 | 只显示**整体图案剪影**（outline 半透明填充） |
| 挑战 | L3 K4-6 | 游戏区无提示，顶部**缩略参考图**（outline 小图） |

### 2.4 交互

- **拖拽**：pointer 事件（pointerdown/move/up，Chrome 61 支持），拖起块提到最上层；
  命中检测 = 逆 transform（scale→rotate→translate）+ 点在多边形内（射线法）
- **旋转**：点选块后点「↻ 旋转」按钮，每次 +45°（经典七巧板块只旋转不翻转）
- **磁吸吸附**：块参考点距目标 < 24px 且角度差（mod 45）< 22.5° → 自动对齐目标位并锁定（placed）；
  移出容差自动解锁
- **提示**：💡 高亮第一块未归位块的目标位置（黄色脉冲 1.5s），封顶 2 次/局
- **重置**：7 块回到初始散落位（底部条带），计时/提示计数归零
- **完成判定**：7 块全部 placed → 结算

### 2.5 闭环

- 计时（顶部实时 mm:ss，interval 250ms）+ 提示次数
- 星级：0 提示 3★ / 提示 1-2 次 2★
- 打卡：完成即记入 `redtools.tangram.v1`（localStorage）：
  `best[图案名]`（最快用时 + 星级 + 提示数）、`done[图案名]`、总完成数、
  `checkin`（打卡日期 + 连续天数）、`history`（滚动 30 条）
- 结算页：星级 + 用时 + 提示次数 + 本图案最佳 + 连续打卡 + 三按钮（再来一局/下一个图案/返回首页）
- 首页图案卡片带「✓ 已完成」标记 + 各图案最佳成绩；底部导航：成绩 / 打卡 / 首页

## 3. 技术实现

### 3.1 文件

```
series/益智/空间感知/七巧板/
├── build_tangram.py        # 数据解析器：OMerkel 数据 → tangram.js（开发期，可复算/扩图案）
├── data/
│   ├── challenges.js       # 数据源（OMerkel/Tangram MIT，勿改）
│   └── hmi.js              # 7 块基准形状定义（数据源）
└── src/
    ├── index.html          # 页面骨架（data.js → tangram.js → main.js）
    └── assets/
        ├── tangram.js      # 7 块形状 + 12 款图案数据（window.TAN，自动生成）
        ├── main.js         # 游戏逻辑（首页/游戏/结算 + SVG 渲染 + 拖拽/旋转/吸附）
        ├── style.css       # 天蓝主题样式
        └── icon_base.png   # 图标母版（构建期加角标）
```

### 3.2 数据坐标系

- 数据统一缩放到 320×320 游戏区（图案长边 280 居中），`puzzles[].scale` 为每款缩放因子
- 渲染块 = `translate(x,y) rotate(rot) scale(scale)` + 本地顶点（质心为原点）
- `targets[key]` = {x, y, rot}：块参考点目标位（rot 为 45° 倍数，0-315）
- `outline` = 整体剪影（多段多边形，已缩放）

### 3.3 Chrome 61 兼容

- JS：经典脚本 IIFE、ES2017（无 module/eval/?. 可选链）、事件全 addEventListener、
  PointerEvent 能力使用（含 pointercancel）
- SVG：`<polygon>` + `transform` + `vector-effect="non-scaling-stroke"`（Chrome 61 支持）
- CSS：无 flex gap / aspect-ratio / clamp / :has / @container / dvh；间距用 margin；
  安全区 env(safe-area-inset-*)；动画 ≤ 400ms（提示脉冲 500ms 温和）
- 数据：纯 JSON 对象，无外部引用

### 3.4 合规与测试

- 离线 zip：零图片素材（图标除外）、无网络请求、无 fetch/XHR/Worker
- 审计 PASS（6 files 0 warning）；合规自查 0 禁止项（innerHTML 仅注入内部生成的 SVG 字符串）
- 冒烟：Playwright file:// 与 http:// 双协议 **64/64 通过**
  （数据完整性/首页 12 卡/进游戏/7 块渲染/钩子磁吸/结算/localStorage/提示封顶/旋转/重置/
   真实指针拖拽吸附/成绩页/打卡日历/无 JS 错误）
- 视觉质检：首页布局美观、三档分组完整、简单档分块占位 + 7 彩色块正常（multimodal-looker）
- ⚠️ Chrome 61 / Android 8.1 WebView 真机未实测（如实标记）

## 4. 已知限制与后续

- 图案数据源为 OMerkel 经典库（MIT），12 款已覆盖三档；扩图案 = 在 `build_tangram.py`
  SELECT 追加 + 重跑（自动校验 45° 兼容 + 无重叠 + 覆盖）
- 拼图区 320×320 固定；图案长边 280，底部散落条带与图案可能轻微叠放（未放置块半透明可辨）

- ⚠️ Chrome 61 / Android 8.1 / 真机 WebView 未实测时如实标记，不宣称真机通过
