## 2. 玩法规则

1. **开局**：从首页选择难度进入。N×N 方格内随机排列数字 1~N²（3×3=9、4×4=16、5×5=25）。
2. **顺序点击**：按 1→2→…→N² 的顺序点击数字，顶部提示「下一个：N」。
3. **计时**：点中 1（`state.next === 1` 且未开始）时启动计时，记录 `startMs = performance.now()`，
   `setInterval(100ms)` 按 `performance.now() - startMs` 差值刷新显示；点中 N² 结束计时。
4. **点错**：点击非当前目标数字，该格红色闪烁约 400ms（miss 类）+ 错误计数 +1，**不结束、不重置**。
5. **点对**：该格绿色高亮约 300ms（hit 类）；非最后一格时更新「下一个」提示。
6. **结算**：点中 N² 即 `finishGame()`，停止计时并计算用时。

**洗牌算法**（`shuffleNums(n)`）：Fisher-Yates 原地洗牌，先填充 1..n 再逐位随机交换，
保证全排列等概率；每次进游戏（含「重新开始」「再来一局」）重新洗牌。

> 后台标签页说明：`setInterval` 在后台会被浏览器节流，显示刷新可能暂停，但最终用时始终
> 以 `performance.now() - startMs` 实算，切后台回来计时依旧准确。

## 3. 难度与星级

### 3.1 难度定义（main.js `SIZES` 常量）

| 难度 | label | 数字个数 | 3★ 阈值（threeMs） | 2★ 阈值（twoMs） |
|---|---|---|---|---|
| 3×3 | 3×3 入门 | 9 | ≤15000ms（15 秒） | ≤30000ms（30 秒） |
| 4×4 | 4×4 进阶 | 16 | ≤35000ms（35 秒） | ≤60000ms（60 秒） |
| 5×5 | 5×5 挑战 | 25 | ≤60000ms（60 秒） | ≤100000ms（100 秒） |

### 3.2 星级评级

| 难度 | 3★ | 2★ | 1★ |
|------|------|------|------|
| 3×3 | ≤15 秒 | ≤30 秒 | 其余 |
| 4×4 | ≤35 秒 | ≤60 秒 | 其余 |
| 5×5 | ≤60 秒 | ≤100 秒 | 其余 |

`calcStars(size, ms)`：`ms <= threeMs` → 3★；`ms <= twoMs` → 2★；否则 1★。

## 4. 页面/视图结构

```
首页 viewHome（3 个难度卡片 + 各难度最佳成绩/未挑战 + 底栏导航 成绩/打卡/首页）
  │ 点击难度卡片
  ▼
游戏页 startGame + renderGame（顶部状态栏一行 / 正方形网格 / 底部 重新开始）
  │ 点中 N² → finishGame（延迟 350ms）
  ▼
结果浮层 showResult（完成 / 大号用时 / 用时·错误统计 / 星级 / 新纪录横幅 / 再来一局 / 返回首页）

底栏导航：成绩 viewHistory（最近 30 次，时间倒序） │ 打卡 viewCheckin（本月日历 + 连续天数）
```

- **顶栏（app-header）**：`renderHeader(title)` 渲染图标 + 标题 + 版本号（来自 `APP.meta.version`）。
  首页显示工具名「舒尔特方格」；游戏页显示当前难度名。
- **首页 `viewHome`**：标题「选择难度」+ 提示「按顺序点击 1 → N²，越快越好」；3 个难度卡片
  （`diff-card`），每张含难度按钮 + 该难度最佳成绩（`最佳 x.x 秒`，未玩过显示「未挑战」）。
- **游戏页 `startGame` + `renderGame`**：`startGame` 重置全部状态并洗牌；`renderGame` 渲染：
  - 顶部状态栏一行：`‹ 返回` | 难度名 | `⏱ 00.0` 计时 | `错误 N` | `下一个：N`；
  - 正方形网格（`shulte-grid grid-{size}`，`grid-cell` 内嵌 `<button class="cell-btn">`）；
  - 底部「重新开始」按钮（重新洗牌再来）。
  - 游戏页**不渲染底栏导航**（顶部返回 + 底部重新开始，避免误触退出）。
- **结果浮层 `showResult`**：全屏半透明遮罩 + 白色卡片，含「完成！」、大号用时、
  用时/错误统计、星级、新纪录时「🎉 新纪录！」、以及「再来一局」「返回首页」两个按钮；
  `finishGame` 延迟 350ms 后展示，让最后一次点击的绿色高亮先被看到。
- **成绩页 `viewHistory`**：无记录时提示「暂无成绩，先来一局吧！」；否则按时间倒序列出
  最近 N 次（难度 / 日期·错误次数 / 用时 / 星级）。
- **打卡页 `viewCheckin`**：本月日历（已打卡日高亮点亮 + 今日蓝色描边）+ 连续打卡天数
  （≥7 天显示 🎉）；打卡由完成游戏自动触发，本页仅展示。

### 4.1 状态模型（main.js `state`）

```js
{
  size: 0,         // 当前难度 3 / 4 / 5
  nums: [],        // 洗牌后的数字序列，长度 size*size
  next: 1,         // 当前目标数字
  errors: 0,       // 错误次数
  started: false,  // 是否已开始计时（点中 1 置 true）
  finished: false, // 是否已结算
  startMs: 0,      // 开始计时时间戳（performance.now()）
  elapsed: 0,      // 结算用时 ms
  timerId: null    // setInterval 句柄
}
```

## 5. 成绩持久化（localStorage key `redtools.shulte.v1`）

```js
{
  version: 1,
  best:   { "3": {ms, date}, "4": null, "5": null },  // 各难度最佳（ms 更小覆盖）
  recent: { "3": ms, "4": 0, "5": 0 },                // 各难度最近成绩
  checkin: { dates: ["YYYYMMDD"], streak },           // 打卡日期（滚动 365 天）+ 连续天数
  history: [ {date, size, ms, errors, stars} ]        // 滚动 30 条，最新在前
}
```

- 读写均包 try/catch：`loadStore` 解析失败或首次打开返回默认结构；`saveStore` 写入失败静默。
- 启动时先 `loadStore()` 再 `saveStore()`（初始化写入，建立默认结构）。
- **最佳成绩**：`msRound = Math.round(elapsed)`；`best[size]` 为空或 `msRound < best.ms` 时
  覆盖为 `{ms, date}` 并标记新纪录（结果浮层显示「🎉 新纪录！」）。
- **最近成绩**：`recent[size]` 直接覆盖为本局用时。
- **历史**：`history.unshift(...)` 最新在前，`while (length > 30) pop()` 滚动保留 30 条。

### 5.1 打卡逻辑（与学科系列数学口算一致）

- 完成一局即自动打卡：`todayStr()` 生成 YYYYMMDD，不在 `dates` 则 push，然后 `sort()`；
  `while (dates.length > 365) dates.shift()` 滚动保留 365 天。
- 连续天数 `calcStreak(dates)`：从日期列表末尾向前回推，**含今天**往前数连续天数，
  跨天即断（缺一天 streak 归零）；结果写入 `checkin.streak`，打卡页渲染时实时重算。
- 打卡无手动入口，本工具「完成一局」即点亮今日。

## 6. 关键实现点

### 6.1 正方形网格

- `.shulte-grid`：`position:relative; width:100%; height:0; padding-bottom:100%`，
  用 padding-bottom 百分比撑出与宽度相等的正方形，兼容 Chrome 61（无 aspect-ratio）。
- `.grid-cell`：绝对定位，`left = (idx % size * 100 / size)%`、
  `top = Math.floor(idx / size) * 100 / size%`；`padding:4px` 提供格子间距（不用 flex gap）。
- 内嵌 `<button class="cell-btn">`（width/height 100%）保证点击区大且语义正确：
  320px 宽屏下 view 水平 padding 16×2，网格宽 288px，5×5 每格 57.6px，
  按钮 49.6px ≈ 49px ≥ 48px 触控下限。

### 6.2 数字字号（按难度随屏自适应）

| 难度 | 字号（vw） | ≥400px 封顶 |
|---|---|---|
| 3×3 | 16vw | 64px |
| 4×4 | 12vw | 48px |
| 5×5 | 9vw | 36px |

`@media (min-width: 400px)` 下用固定 px 封顶，避免平板/桌面字号过大。

### 6.3 点击判定 `onCellTap(btn, num)`

- `state.finished` 时直接忽略（结算后不再响应）。
- `num === state.next`（正确）：
  - `btn.className = 'cell-btn hit'`（绿色高亮，CSS 动画 0.3s），300ms 后移除高亮类；
  - 首次（`!state.started`，即 next===1）启动计时：`startMs = performance.now()` + `startTimer()`；
  - `done = state.next >= size * size` **在自增前判定**，随后 `next += 1`；
    `done` 为真直接 `finishGame()`（点中 N² 即结算），否则 `updateNext()` 刷新提示。
- 否则（错误）：`btn.className = 'cell-btn miss'`（红色闪烁，CSS 动画 0.4s），`errors += 1`、
  `updateErrors()`，400ms 后移除 miss 类；不中断、不重置。

### 6.4 结果浮层

- `.result-overlay`：`position:fixed` 全屏半透明遮罩 + `.result-box` 白色卡片
  （完成/大号用时/用时·错误统计/星级/新纪录横幅/再来一局/返回首页），`appendChild` 到 `document.body`；
- `closeOverlay(overlay)` 从父节点移除；「再来一局」同难度重开，「返回首页」回 `viewHome`。

### 6.5 安全区与高度适配

- `syncAppHeight()`：用 `window.innerHeight` 写 `--app-height` CSS 变量，`resize` 时同步，
  覆盖 100vh 在移动端地址栏伸缩时的高度误差（`body` 用 `height: calc(var(--app-height, 100vh))`）。
- 顶栏/底栏用 `--safe-area-inset-top/bottom` + `env(safe-area-inset-*, 0px)` 双兜底
  （`@supports` 增强），适配刘海屏与底部横条。

## 7. Chrome 61 / 合规约束

| 类别 | 约束 | 本工具做法 |
|---|---|---|
| JS 语法 | ES2017 上限经典脚本 | `var` + `function` 风格，无 `?.` `??` 对象展开 `replaceAll`；无 `type="module"`/import/export；无箭头函数 |
| 事件 | 全部 `addEventListener` | 无内联事件 / eval / `onclick` 属性 |
| 网络 | 零网络请求 | 无 fetch/XHR/Worker/外部资源；无 audio（无音效设计） |
| CSS 语法 | Chrome 61 兼容层 | 无 flex `gap`/`aspect-ratio`/`clamp`/`inset`/逻辑属性/`:has`/`@container`/`dvh`；格子间距用 cell padding；Flex 子项设 `min-width:0` |
| 动画 | 温和反馈（光敏安全） | hit 0.3s 轻微放大（最大 1.06）、miss 0.4s 透明度淡出，无强频闪 |
| 图标 | 打包图标 | `assets/icon.png`（构建时母版 + 角标「舒尔特方格」生成） |

```python
ToolConfig(
    series="益智", tool="舒尔特方格",

```
src/（index.html + assets/）──► copy_static ──► dist/益智/舒尔特方格/
