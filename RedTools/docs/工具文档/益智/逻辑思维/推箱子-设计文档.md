## 2. 玩法设计

### 2.1 规则（经典 Sokoban）

- 网格地图由墙、地板、目标点（黄圆）、箱子、玩家组成。
- 玩家每次移动一格（上/下/左/右），不能穿墙、不能穿过箱子。
- 玩家紧邻箱子并朝箱子方向移动时**推动**该箱子一格；一次只能推一个，**不能拉**。
- 箱子不能推到墙、另一个箱子或地图外。
- 胜利条件：**所有箱子都推到目标点上**（箱子数 == 目标数，关卡保证）。
- 死锁：箱子被推到角落或贴死墙边则无法解出，可「重开」或「撤销」。

### 2.2 操作

| 输入 | 说明 |
|---|---|
| 触屏滑动 | 棋盘上滑动手势（阈值 24px，水平/垂直占优判定，防误触） |
| 键盘 | 方向键 ←↑↓→ 或 WASD；**Z 撤销 / R 重开** |
| 方向按钮 | 十字 D-pad（▲◀▼▶，56px hit area，PC 模拟器/无键盘兜底） |
| 功能按钮 | 「↺ 撤销」无限步回退（栈上限 500）；「↻ 重开」重置本关 |

### 2.3 反馈

- **动画**（温和，光敏合规）：通关浮层弹性入场（cardIn 250ms）+ 星级弹出（starPop 350ms）。
- **音效**（Web Audio `OscillatorNode` 合成，零音频文件）：
  移动（低频轻响）/ 推箱（低沉三角波）/ 箱子入坑（清脆）/ 推不动（闷响）/ 胜利（上行琶音）。
  首次用户手势创建 `AudioContext`，播放异常静默降级。
- **视觉区分**：墙灰蓝立体块、箱子木棕圆角块、**箱子在目标=完成绿**、玩家蓝色圆（两只白眼）、目标黄色圆点。

## 4. 技术设计

### 4.1 数据模型

- **关卡**：`window.LEVELS = [ {g:[XSB行...], b:最少推动数|null}, ... ]`（levels.js，155 关全量内嵌）。
- **运行时状态**：`state = { level, w, h, walls:{idx:true}, goals:{idx:true}, boxes:{idx:true}, player:idx, moves, pushes, won, undoStack }`。
  idx = `y*w + x`；walls/goals/boxes 用对象做哈希集（O(1) 查找，避开 JS 位运算 32 位限制）。

### 4.2 移动与推箱（核心算法）

```
tryMove(dir):   # dir 0左 1上 2右 3下（D-pad/键盘/滑动统一入口）
  nIdx = 玩家向 dir 移动一格
  if nIdx 是墙 → 忽略
  if nIdx 有箱子：
    bIdx = 箱子再向 dir 一格
    if bIdx 是墙/箱子/越界 → 推不动（sndBlock），忽略
    推：boxes 更新；pushes++；若入目标 sndGoal 否则 sndPush
  else：玩家移动（sndWalk）
  moves++；pushUndo()；paint()；saveCur()；胜利判定
```

- **方向映射**（idx = y*w+x，pr = idx%w 为列 x，pc = floor(idx/w) 为行 y）：
  `LEFT: 列-1` / `UP: 行-1` / `RIGHT: 列+1` / `DOWN: 行+1`
  （⚠️ 踩坑：初版 DR/DC 增量写反导致"左"实际视觉上移，冒烟 D 段通关注入解法时暴露，已修复）
- **撤销**：`undoStack` 每步前快照 `{player, boxes, moves, pushes}`，无限回退（上限 500 防内存膨胀）；空栈点击安全。
- **无效移动**（撞墙/推不动/越界）不记步、不压栈。
- **胜利判定**：所有箱子位都在目标集合（箱数==目标数已由关卡保证）。

### 4.3 渲染

- 棋盘容器 `padding-bottom = h/w*100%` → 宽高比 = 关卡 w:h，**格子为正方形**（每格 `100/w% × 100/h%` 绝对定位）。
- 每次渲染重建全部 cell（≤ 关 36 的 5×15=75 格 / 前 60 关最大 12×8=96 格，开销可忽略）。
- 目标点/玩家眼睛用 `::before/::after` 伪元素绘制；箱子在目标时隐藏目标点（`.boxgoal`）。

### 4.4 关卡数据（方案 A：一次性转换脚本）

| 项 | 内容 |
|---|---|
| 数据源 | **Microban I by David W. Skinner**（155 关），来源 kbarni/sokoban.koplugin 仓库 levels/Microban.txt（镜像 sneezingtiger.com） |
| 许可 | "freely distributed provided they remain properly credited"（免费分发，保留署名，非商业）；工具内选关页底部已署名 |
| 转换脚本 | `series/益智/逻辑思维/推箱子/convert_levels.py`：解析 XSB（`; N` 分隔）→ 逐关校验（合法字符/单人/箱数==目标数）→ **BFS 求解器**算最少推动数 → 生成 levels.js |
| 求解器 | 状态 = (箱子位掩码, 玩家位)，位运算 flood-fill 玩家可达区；**角落死锁剪枝**（sound：相邻两正交方向皆墙且不在目标）；每关超时 20s |
| 求解结果 | 136/155 关求得最优推动数；**前 60 关全部求解成功**（最优 1~59 推，难度渐进）；19 关超时（8+ 箱大关，全在开放范围外，`b:null` 前端降级为通关 2 星封顶） |
| 体积 | levels.js 全量 155 关 ≈ 20 KB；zip 包体 0.02 MiB（≪ 2 MiB 建议值） |
| 开放策略 | `OPEN_LEVELS = 60`（main.js 常量）：数据全量内嵌，**当前仅开放前 60 关**；扩关只改常量，无需重新生成数据 |

### 4.5 持久化（localStorage）

- key：`redtools.tuixiangzi.v1`（容器内多工具共享存储，必须带工具前缀）。
- 结构：`{ version, unlocked:1, solved:{N:{moves,pushes,stars,date}}, checkin:{dates,streak}, cur:{level,player,boxes,moves,pushes} }`。
- **解锁**：通关第 N 关 → `unlocked = max(unlocked, N+1)`（≤ OPEN_LEVELS）；选关页锁定 🔒。
- **星级**（按最优推动数，儿童宽松档）：
  - 3 星：`pushes ≤ ceil(best × 1.5)`；2 星：`pushes ≤ ceil(best × 2.5)`；1 星：通关
  - `best` 为 null（求解超时关）：通关 2 星封顶
  - 重复通关仅当星级更高才覆盖记录
- **打卡**：通关一关 → `dates` 写入今日（去重、滚动 365 天）、重算连续天数（对齐 `docs/通用需求-打卡分享记录.md`）。
- **断局恢复**：每次有效移动后 `store.cur` 快照；重新打开自动恢复到上次的关卡与步数；通关后清空 cur。

### 4.6 音效（Web Audio 合成）

```js
tone(freq, dur, type, vol, delay)   // OscillatorNode + GainNode 包络
sndWalk: sine 200Hz 50ms    sndPush: triangle 140Hz 70ms
sndGoal: triangle 523Hz 90ms  sndBlock: square 90Hz 80ms
sndWin:  523/659/784/1047 上行琶音
```

`AudioContext` 懒创建 + 用户手势 `resume()`；全部 try/catch 降级。

## 5. 合规自检（Chrome 61 / 容器规范）

- JS：ES2017 经典脚本（var + function），无 `?.`/`??`/对象展开/module/import；无内联事件/eval/innerHTML；
  keydown 用 `keyCode`；触屏用 `touches/changedTouches`；无 fetch/XHR/Worker/clipboard。
- CSS：无 `gap`/`aspect-ratio`/`clamp()`/逻辑属性/`:has`；flex 三重前缀；动画双写 `@-webkit-keyframes` + `@keyframes`；
  棋盘比例用 `padding-bottom` 百分比（非 aspect-ratio）；安全区 env() 兜底。
- 资源：全部内联/本包；无外部 URL；无 CSP meta（容器管理）；音频零文件（Oscillator 合成）。
- 包体：构建产物 0.02 MiB（≪ 2 MiB 建议值）。
