## 2. 原型 bug 根因分析与修复（本工具的核心设计依据）

> 用户明确反馈原型存在两个 bug：**画面一直抖动**、**画出来的物体不会掉落**。
> 本工具从根因入手重新设计，而非在原型上打补丁。

### 2.1 Bug1「画面一直抖动」—— 渲染层每帧随机数

**根因（代码实证）**：原型渲染管线在**每一帧**调用 `Math.random()`：
- `drawGround()`：地面 5 条蜡笔线 × 26 个顶点每帧 ±1.2px 随机抖动；
- `drawCrayonPoly()`：所有地形与自绘刚体每帧 ±1.4px 抖动；
- `drawBall()` / `drawStar()`：球/星描边每帧 ±0.6~0.7px 抖动。

静态场景实测帧间像素变化 **0.35%**（本应为 0）——整个画面持续"呼吸式"微抖。

**对策（零每帧随机）**：
| 渲染对象 | 新方案 |
|---|---|
| 纸张/地面/地形 | **离屏静态层**：进关时一次性烘焙到离屏 canvas，帧循环整块 `drawImage` |
| 自绘刚体 | **创建时烘焙 sprite**：蜡笔抖动纹理（3 填充+2 描边）在笔画生成瞬间一次性绘制，帧循环按 `body.position/angle` 贴图 |
| 球/星 | 预烘焙 sprite；星仅做**确定性 sin 呼吸动画**（平滑动画 ≠ 随机抖动） |
| 预览笔迹 | 纯色粗线，无随机 |

修复后静态场景帧间像素差 **0.000%**（实测）。

### 2.2 Bug2「物体不会掉落」—— 三个叠加根因

**根因 A：重力标称过弱 + 球平衡在三角台顶点**
- 原型 `engine.gravity.y=1, scale=0.001` → 实测球初始下落速度仅约 300 px/s（远弱于真实感）；
- 球初始放在三角台**正顶点**上（对称平衡点），力学上可永远静止 → 球根本不滚。

**对策**：重力 `scale=0.002`（约 2000 px/s²，下落干脆）；球一律放在三角台**右坡面**上（有 10~50px 落差自动落坡），绝不放在平衡点。

**根因 B：画在球/地形上被"挤压锁死"**
- 原型笔画重叠时无处理，摩擦 0.9 + 弱重力 → 笔画与球互相顶住僵死（实测笔画画在球上方 2 秒不动）。

**对策**：自绘刚体创建即**静态**（见 §3.1，画完即固化）——从根本上消除挤压锁死；世界在玩家画完第一笔后才启动（见 §3.2），球有充足时间等待搭建。

**根因 C：球出界/高速穿透/梁体在支点打滑**
- 原型 60Hz 单步进：球速 800px/s 时 13px/帧 > 板厚 12px → **高速穿透**（球直接穿过木板）；
- 长梁搭在平台边缘（刀锋接触）→ 被球一撞即滑移/倾覆。

**对策**：物理 **120Hz 子步进**（`STEP=1000/120`，防穿透）；自绘刚体静态化（无支点滑动问题）；solve 斜坡起点"接"在落点平台右边缘、顶面与台面齐平（无缝过渡，无落差撞击）。

### 2.3 与原型的「一模一样」边界声明

原版为 C++/Box2D 桌面程序，浏览器无法逐字节复刻。本工具与原型同用 **Matter.js**（Box2D 同族），
手感参数集中可调（`physics.js` 顶部常量），后续可平滑切换 Planck.js（Box2D 官方 JS 直译）。

## 3. 技术设计

### 3.1 自绘刚体：创建即静态（画完即固化）

```
原始点集(指针采样, 每≥4px 一点)
  │ RDP 简化(ε=5px) —— 控点数、防抖动
  ▼
简化折线
  │ 加粗(半宽6px, miter≤2.2) 生成双侧轮廓多边形
  ▼
厚轮廓多边形
  │ poly-decomp 凸分解 + Matter.fromVertices(flagInternal=true)
  ▼
复合刚体（凹形笔画焊接为一个刚体）
  │ 创建即 setStatic(true) ← 关键：静态=零滑动/零倾覆/零挤压锁死
  ▼
烘焙蜡笔 sprite（一次性）→ 加入世界
```

- **密度 0.008**（静态下质量仅作语义保留，便于后续切换动态）；
- 面积 <150px² 或点数 <3 → 丢弃并提示"再画长一点"；
- 上限 30 个自绘刚体，超出自动淘汰最早的（防性能劣化）；
- 撤销/擦除/重置：从世界移除对应刚体（静态体可正常移除）。

### 3.2 世界冻结：画完第一笔才启动物理

关卡加载后**物理世界冻结**（`worldStarted=false`，主循环跳过 `Engine.update`）：
- 玩家可从容观察地形、规划并画出第一笔；
- 第一笔完成 → `worldStarted=true` → 物理启动（同时**清零累积时间**，防止冻结期补帧导致球瞬移）；
- 之后球从三角台滚下，沿玩家搭建的斜坡/桥滑向星星。

设计价值：**消除时间压力**（低龄友好），同时保证解法可复现（搭建先于滚动）。

### 3.3 物理参数表（`physics.js` 顶部常量，集中可调）

| 对象 | 密度 | 摩擦 | 弹性 | 备注 |
|---|---|---|---|---|
| 自绘刚体（静态） | 0.008 | 0.3 | 0.05 | 静态固化，球在其上滚动 |
| 红色小球 | 0.003（L4/L9/L10 加重 0.006~0.012） | 0.02 | 0.03 | 滚动顺滑、微弹 |
| 三角台/平台（静态地形） | — | 0.3 | 0 | 缓坡 30~33°（球出口水平速度最大化） |
| 地面 | — | 0.6 | 0 | 比平台"涩"——长距离必须借斜坡 |
| 轻纸箱（动态） | 0.0001 | 0.05~0.1 | 0 | 极轻，可被球撞开（L4/L9/L10） |

- 重力：`gravity.y=1, scale=0.002`（约 2000 px/s²）；
- 求解器：`positionIterations=10, velocityIterations=8`（堆叠稳定）；
- 步进：**120Hz 子步进**（`STEP=1000/120`）——高速小球不穿透 12px 薄板；
- 世界：1000×600（100px=1m 语义）。

### 3.4 渲染架构（零每帧随机，见 §2.1）

```
进关：bakeStaticLayer()  ← 纸张纹理+地形+地面一次性烘焙
   └─ bakeBall()/bakeStar()  ← 球/星 sprite 一次性烘焙
画一笔：bakeDrawnSprite(body)  ← 蜡笔抖动纹理一次性烘焙
每帧 render()：
   drawImage(staticLayer) → 各自绘刚体 sprite(按 position/angle) → 预览笔迹 → 球 → 星(确定性 sin 呼吸) → 粒子
```

### 3.5 关卡数据（`levels.js`，10 关渐进）

| 关 | 名称 | 难度 | 教学点 | 参考解法（solve，自动验证用） |
|---|---|---|---|---|
| 1 | 滑向星星 | ★ | 画斜坡让球从台面滑到星 | 1 条长斜坡 |
| 2 | 搭一座桥 | ★ | 跨深沟搭桥（下坡桥） | 1 条桥 |
| 3 | 两级跳板 | ★★ | 两段斜坡接力 | 2 条坡 |
| 4 | 撞开纸箱 | ★★ | 加速冲开轻纸箱 | 1 条坡 + 1 箱 |
| 5 | 斜坡接力 | ★★ | 三段斜坡逐级下滑 | 3 条坡 |
| 6 | 斜坡着陆 | ★★ | 高台斜坡滑到目标平台 | 1 条坡 |
| 7 | 两段桥 | ★★★ | 中柱两段桥（先下后上） | 2 条桥 |
| 8 | 高速冲坡 | ★★★ | 长陡坡冲刺最远距离 | 1 条长坡 |
| 9 | 穿越纸箱阵 | ★★★ | 连续撞开两排纸箱 | 1 条坡 + 2 箱 |
| 10 | 终极挑战 | ★★★ | 三级斜坡 + 双平台 + 纸箱综合 | 3 条坡 + 2 箱 |

**关卡几何铁律（10 关全部自动解法验证通过的稳定架构）**：
1. 三角台 30~33° 缓坡（球出口水平速度最大化）；
2. 每个三角台配「落点平台」（顶面=台底边），斜坡起点**接在平台右边缘**、顶面与台面齐平（无缝过渡，零落差撞击）；
3. 全程**下坡**：落点平台(480) → 各级平台(505~540) → 地面(560)；
4. 每关带 `solve` 参考解法（多条笔画），供自动化冒烟逐关通关验证。

### 3.6 成绩/打卡（localStorage，复用益智通用核心）

```js
localStorage['redtools.wuli.v1'] = {
  version: 1,
  best:    { "1": 3, ... },        // 每关最佳星级
  checkin: { dates: ["20260919"], streak },  // 打卡（完成任意一关点亮今日）
  history: [ {date, level, stars, strokes, ms} ]  // 滚动 30 条
}
```

- **星级**：通关时画面残留笔画数 ≤2 → ★★★；≤4 → ★★；>4 → ★（引导"用最少的笔画"规划）；
- 首页关卡卡片显示每关最佳星级；底部「🔥 连续打卡 N 天」。

## 6. 测试与验证

- **自动化冒烟**（Playwright + 本地 chromium，file:// 与 http:// 双协议）：
  - 首页 10 卡片 / 标题 / 打卡显示；
  - **10 关参考解法逐关通关**（画 solve → 轮询过关浮层，每关 ≤25s）；
  - **无抖动**：静态场景左半区帧间像素差 <0.01%（实测 0.000%）；
  - **自绘刚体固化**：笔画画完 Δ位置 <1px（实测 0.000px）；
  - **球受重力**：世界启动后球 y 位移 >50px（470→544）；
  - 橡皮擦模式 / 撤销 / 重置 / 调色板 / 无 JS 错误。
- **视觉质检**：多模态看板（`look_at` / multimodal-looker）核对首页布局、关卡画面球/星/地形渲染（曾抓出"球/星未渲染"缺陷并修复）。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 静态刚体"画在空中不落"（与原版"画什么掉什么"的差异） | 玩家预期落差 | 关卡地形确保球始终需要斜坡引导；提示文案强调"画一笔变成木板"；后续可切换动态+冻结机制（见 §8） |
| 世界冻结机制 | 玩家想先看球滚再画 | 冻结只到第一笔，且提示文字说明；后续可加"启动"按钮 |
| 多段 solve 时机 | 第二笔未画完球已滚过 | 冻结只到第一笔；solve 测试快速连画；玩家重画成本低（撤销/重置） |
| 高速穿透 | 球穿过薄板 | 120Hz 子步进 + 板厚 12px；实测 L8 球速 900px/s 无穿透 |
