## 2. 目标与原则

**目标**：本轮后——
1. 构建期校验覆盖书页完整性（页码连续/零 track/图片对齐），缺页缺图进 `--strict`
2. 工作台任务面板日志流式可见、热区保存即时回传刷新、审核按单元推进并自动衔接下一单元
3. `--strict` 附加体积门禁（subprocess 调 audit_artifact）；新增合规自查脚本（白名单 + Csp 禁项 + 产品红线禁词）
4. 校验/审核缓存文件写入加锁，消除并发竞态

**原则**：
1. **校验默认不破坏构建**：书页完整性沿用 WARN 默认 + `--strict` 硬失败（与 hz/audio 同桶收集）
2. **审计放打包后**：审计入口在 `build_all.py` 层（拿到 zip_path 后），`build_framework.py` 零改动时序
3. **subprocess 优先**（审计/合规均以 CLI 子进程调用）：audit_artifact 只返回字符串，import 后仍需解析；避免 `.skill/` 进主流程 sys.path；与 `_api_rebuild` 样板同构
4. **消息总线统一**：工作台 → 前端用 window.postMessage 事件协议（`redraw_sent` 既有 + 新增 `hotzone_saved` / `unit_review_done`）
5. 本轮为开发支撑迭代，`tools.py` 英语点读版本不变
6. **合规脚本本轮先独立跑通 + 接工作台一键审计**，不并入 `--strict`（避免首次跑真实产物出红、且需先校准阈值），作为发布门禁下一步

## 3. 变更设计

### 3.1 P1-P4：书页完整性校验（`validate_page_completeness`）

**新函数**（`build_framework.py`，与 V1.3.1 两个校验函数并列）：
```python
def validate_page_completeness(book: dict, unit: dict, start: int, end: int,
                               img_dir: Path, redrawn_img_dir: Path | None = None) -> dict:
    """校验单元书页完整性。
    返回 {missing_pages: [page_no], zero_track_pages: [page_no],
          redrawn_missing_imgs: [page_no], both_missing_imgs: [page_no],
          total_pages: int, ok: bool}
    - missing_pages:     range(start,end) 中 book["bookpage"] 缺 page_no 的集合
        （必须对 book 判：unit["pages"] 已被 L220-222 continue 过滤，无法反推）
    - zero_track_pages:  unit["pages"] 中 len(tracks)==0 的页
    - redrawn_missing:   重绘目录缺 Page_{page_no:03d}.png（原版可兜底 → WARN 级）
    - both_missing:      重绘与原版皆缺（→ ERROR 级语义，strict 必触发）
    """
```
- 图片存在性：**分别判两目录**（Oracle B1：不能用 `(redrawn_img_dir or img_dir)` 只查一个目录，须与 `convert_images` L280-285 回退顺序一致）：
  ```python
  redr_ok = bool(redrawn_img_dir and (redrawn_img_dir / f"Page_{pno:03d}.png").exists())
  orig_ok = bool(img_dir and (img_dir / f"Page_{pno:03d}.png").exists())
  if not redr_ok and not orig_ok: both_missing.append(pno)          # 双缺 → ERROR 级
  elif redrawn_img_dir and not redr_ok and orig_ok: redrawn_missing.append(pno)  # 原版兜底 → WARN 级
  ```
- **调用点**：`build_tool` L903-916 校验块，`validate_hotzones` 之后：
  ```python
  comp = validate_page_completeness(book, unit, start, end, cfg.img_dir, cfg.redrawn_img_dir)
  if comp["missing_pages"] or comp["both_missing_imgs"] or comp["zero_track_pages"]:
      log(f"⚠️ 书页完整性: {len(comp['missing_pages'])} 缺页, {len(comp['zero_track_pages'])} 零track(可能为扉页), {len(comp['both_missing_imgs'])} 双缺图")
      validation_issues.append(f"书页完整性 {len(missing)+len(zero)+len(both)} 项")
  ```
- **P3 修复（Oracle B2：不改 convert_images）**：`both_missing` 已精确捕获 convert_images（L287-289）会 `continue` 跳过的页（两目录皆缺）——**both_missing 即 P3 的 strict 桶入口**，无需修改 convert_images 签名/提升 validation_issues（它还导致模块级函数 L273 引用 build_tool 局部变量 L870 的顺序问题）。convert_images 的 `log(WARN)` 保留为信息性日志。
- **P4 修复**：`build_framework.py` `main()` argparse 补 `--strict`（与 build_all.py 同语义，透传 build_tool）

**工作台集成（P1-P4 收口）**：
- `hotzone_serve.py` `_handle_status` 每单元 `validation` 增 `page_issues`：**实时计算**（复用 `validate_page_completeness`，读 book + 两个目录 stat，成本可忽略）
- `workbench/index.html` 单元卡片校验 badge 增 `📄 缺页 N`/`🖼️ 缺图 N`（红/橙分级）
- `_handle_status` 读 JSON 相关加 `FILE_LOCK` 包住 read（Oracle S4，与 L1 同一把锁，消除半写读异常隐患）

**涉及文件**：`build_framework.py`、`build_all.py`、`hotzone_serve.py`、`workbench/index.html`

### 3.2 W1：任务面板日志流式输出

**后端** `hotzone_serve.py`：
- 队列项增 `logs: list[str]`（含字段：`task/page/unit/book/status/.../logs`）
- `redraw_worker`（L90-117）`subprocess.run` 改 `subprocess.Popen`，**带 deadline 超时 kill（Oracle B3）**：
  ```python
  proc = subprocess.Popen(cmd, stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
                          text=True, encoding="utf-8")
  deadline = time.time() + 600
  for line in proc.stdout:
      if time.time() > deadline:                       # 子进程挂起（无输出）防护
          task["logs"].append("[timeout] 子进程超时，强制终止")
          proc.kill()
          break
      task["logs"].append(f"[{fmt_time}] {line.rstrip()}")
      if len(task["logs"]) > 500: task["logs"] = task["logs"][-500:]
  rc = proc.wait(timeout=10)                            # kill 后 wait 快速返回
  ```
  stderr 并入 stdout（`stderr=STDOUT`），失败信息仍可入 error（取日志尾部）。**删除 `task is None` 死代码（Oracle S3）**——worker 持 dict 引用，`_api_tasks_clear`（L536-541）只移除 done/failed 不移除 running，`task` 不会变 None；若未来要支持取消则改 `task["cancelled"]` 标志。
- `/api/tasks` 响应含 tasks 的 `logs`（每任务截尾 200 行为限，控制 payload）
- 说明：`TASK_QUEUE` 为内存态（重启即丢）——日志随队列同生命周期，本轮不持久化（单用户本地工具可接受，见风险表）
- `redraw.py` 若当前输出粒度不足（只头尾 print），补逐页进度 print（验证时实测决定）

**前端** `workbench/index.html`：
- 任务面板日志区：`refreshTasks()` 全量重写改**增量 append**——记录每个任务已渲染的 logs 行数 `lastLogLen[id]`，仅渲染新增行 + 自动滚动到底部（保留 5s 轮询，模拟流式观感，不做真 SSE——见风险表）
- 失败任务展开显示 `error` 摘要 + 日志尾部

**涉及文件**：`hotzone_serve.py`、`workbench/index.html`、（视实测）`redraw.py`

### 3.5 A1-A4：审计接入 `--strict` + 合规自查脚本

**A1/A2：审计接入（方案 B：build_all.py 层，零改 build_framework 时序）**：
```python
# build_all.py（L130 之后）
zip_path = build_tool(cfg, u, args.pages, mode=args.mode, strict=args.strict)
if args.strict and zip_path and str(zip_path).endswith(".zip"):   # offline 产物
    cmd = [sys.executable, str(REDTOOLS_skill/"scripts/audit_artifact.py"), str(zip_path)]
    proc = subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8", timeout=60)
    if proc.returncode != 0:
        detail = (proc.stdout + (proc.stderr or ""))[-600:]        # Oracle S6：stdout+stderr 兜底
        raise SystemExit(f"体积/文本门禁审计失败 rc={proc.returncode}: {detail}")
    # rc==0 即使 WARN 也不中断（与 audit_artifact 语义一致：warnings 不影响 rc）
```
- 失败落入既有 `except SystemExit` → 计 failed 继续批量、最后汇总 rc
- online 模式 `zip_path` 为部署目录 → 本轮跳过（审计语义面向发布 zip）
- 阈值沿用 audit_artifact 模块级常量（zip>10MiB ERROR / >2MiB WARN / 单文本>2MiB / 合计>5MiB）

**A3/A4：合规自查脚本（新建 `RedTools/scripts/compliance_check.py`，Oracle S1：避免 tools/ 与 tools.py 混淆）**：
```python
"""合规自查：CLI python compliance_check.py <dir|zip>
规则源：.skill/minitool-zip-builder/references/zip-artifact-spec.md
1. 扩展名白名单 §2：.html/.css/.js/.png/.jpg/.jpeg/.gif/.webp/.svg/.woff/.woff2/.json
   （zip 内任何其他扩展名 → ERROR）
2. Csp 禁项 §3（仅扫文本文件内容）：
   禁内联 <script>、onclick=、javascript:、eval(/new Function、WASM、
   外部域名引用(http/https url 非白名单域)、iframe/object → ERROR
3. 产品红线禁词（AGENTS.md §1）：排行榜 / 云存档 / 多人互动 / PK / 排名
   → ERROR（离线包红线）
返回码：0=通过（仅警告）/ 1=违规 / 2=用法错误；stdout 前缀 ERROR:/WARN:/PASS:/FAILED:
（与 audit_artifact 输出约定一致，便于统一解析）
"""
```
- 位置权衡：audit_artifact.py 位于 `.skill/`（skill 包解压产物 = 规范包），**不改它**；合规脚本放 `RedTools/scripts/`（新增子目录，与 build 体系同级，避免与根下 tools.py 注册表混淆）
- 白名单规则非硬编码：脚本可 `--whitelist-file references/zip-artifact-spec.md` 可选引用，默认内置常量（本轮内置 + 注释引用权威文件）
- **CSP 禁项边界（Oracle B-阻塞：不 flag style=）**：spec §3 明确**允许**内联 `style="..."`；内容扫描**只禁脚本相关内联**（`<script>...`、`onclick=`、`javascript:`、`eval(`、`new Function(`、WASM、外部域名引用、iframe/object），**不得**对 `style=` 报违规
- **性能（Oracle S2）**：audio/*.js 为多 MB base64（`window.AUDIO_DATA[...]`），内容扫描限定 `.html`/`.css` 或跳过 >2MiB 文件（白名单扩展名检查仍做，只跳内容扫描）：
  ```python
  TEXT_SCAN_SUFFIXES = {".html", ".css"}   # 内容扫描只做 html/css（.js 的 audio 体积大且无 inline 风险）
  TEXT_SCAN_MAX_SIZE = 2 * 1024 * 1024     # >2MiB 跳过内容扫描，仅做扩展名白名单
  ```
- 产品红线禁词（排行榜/云存档/多人互动/PK/排名）扫描限定 .html/.js 文本，报告标注行号供人工复核（接受注释类 false positive：如「不使用排行榜」也会命中，标注供人工放行）

### 3.6 L1：校验/审核缓存并发加锁
