## 2. 目标与原则

1. L1：误传册名 → 友好报错（`❌ 未知册: X，可用: [...]`）+ 返回码 1
2. L2：红线扫描**跳过注释文本**（.js 的 `//` 行注释 + `/* */` 块注释；.html 的 `<!-- -->`），只扫有效代码文本——注释类 false positive 归零，真实违规不受影响
3. **行号保持**：注释替换为空白字符（保留 `\n`），命中位置行号与原文一致
4. 不改扫描范围（仍扫 .html/.js）、不改其他规则、不引入依赖

### 3.2 L2：compliance_check.py 注释跳过

**新 helper**（模块级）：
```python
def strip_comments(text: str) -> str:
    """把注释内容替换为空白（保留换行 → 行号不变），仅用于红线禁词扫描。
    - .js 风格：// 行注释、/* */ 块注释
    - .html 风格：<!-- --> 块注释
    """
    # 先处理字符串字面量？——不：字符串里的"排行榜"若为 UI 文案正是红线目标，必须保留。
    # 只替换注释。简单状态机或正则组合：
    out = re.sub(r"/\*.*?\*/", lambda m: _blank(m.group(0)), text, flags=re.S)   # 块注释
    out = re.sub(r"//[^\n]*", lambda m: _blank(m.group(0)), out)                  # 行注释
    out = re.sub(r"<!--.*?-->", lambda m: _blank(m.group(0)), out, flags=re.S)   # html 注释
    return out

def _blank(s: str) -> str:
    """s 内非换行字符替换为空格（保行号）。"""
    return "".join("\n" if ch == "\n" else " " for ch in s)
```
- `scan_redline` 开头：`text = strip_comments(text)`（audio 段跳过在前）
- ⚠️ **边界**：`.js` 字符串内 `//` 如 URL `"https://x"` 会被误判为行注释开头 → 其后的代码被吞。缓解：仅对**命中位置在注释区间外**的禁词判定——改为收集注释区间（非替换），命中 `m.start()` 落在任何注释区间内则跳过：
  ```python
  def comment_ranges(text) -> list[tuple[int,int]]:  # 合并的注释区间
  ```
  实现更严谨（区间收集 + 命中点判含），替代"替换法"避免 URL `//` 误吞。

**决定**：采用**区间收集法**（比替换法稳）：
```python
RE_BLOCK = re.compile(r"/\*.*?\*/", re.S)
RE_LINE = re.compile(r"//[^\n]*")
RE_HTML = re.compile(r"<!--.*?-->", re.S)

def comment_ranges(text: str) -> list[tuple[int, int]]:
    spans = []
    for pat in (RE_BLOCK, RE_LINE, RE_HTML):
        spans += [(m.start(), m.end()) for m in pat.finditer(text)]
    spans.sort()
    return spans

def in_ranges(spans, pos) -> bool:
    for s, e in spans:
        if s <= pos < e:
            return True
        if s > pos:
            break
    return False
```
- `scan_redline`：`spans = comment_ranges(text)`；每个命中 `m.start()` → `if in_ranges(spans, m.start()): continue`（跳过注释内禁词）；禁词词本身（REDLINE_WORDS/REDLINE_PATTERNS）不变
- ⚠️ 已知残留：`.js` 字符串内 `"//"` 字面量（如 URL）产生的"假注释区间"会让**其后的**真实禁词被跳过——单文件本地工具可接受；若后续需精确可引入字符串解析（本轮不做）
