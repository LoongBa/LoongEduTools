## 3. Oracle 实施复核结论（摘要）

**发现 1 个关键隐患 + 1 个 R3 偏差，已修复**：
1. 🔴 **status/validate 未加载校正文件**（`hz` 传的是元数据 `{file, updated_at}` 而非内容 → `build_unit_data` 静默忽略校正 → hz_issues 校验的是**原始坐标**，deleted tracks 未过滤）→ **已修复**：加载 `hz_data` 传给 build_unit_data
2. 🟠 **缓存 staleness 未实现**（R3 要求 mtime 失效键）→ **已修复**：validate 写入 mtime 键（book/hotzone/audio），status 比对判 stale → null

**确认无问题**：validate_hotzones 规则顺序（inverted 优先于 zero_area，right==left 归 inverted 与 docstring 一致）；`_strip_internal` 递归 strip 安全（当前 schema 仅 `_from_correction` 以 `_` 开头）；status 性能可接受（纯 dict/float 运算 sub-100ms）；`_api_validate` 音频目录与 build 口径一致（三场景全匹配）；--strict per-unit SystemExit 机制与方案 collect-then-fail 功能等价（无需改动）。
