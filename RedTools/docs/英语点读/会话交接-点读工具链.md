## 4. 重要决策与经验（勿忘）

1. **校验默认 WARN 不破坏构建**，`--strict` 可选硬失败（collect-then-fail 一次看全）
2. **book.json 完整性判定对 book 判**（build_unit_data 静默 continue 过滤缺页，unit 无法反推）
3. **审计放 zip 打包后**（strict 失败点在 package_zip 前）；online 返回目录跳过审计（.zip 后缀判断）
4. **subprocess 优先**（审计/合规均 CLI 子进程调用，不 import audit_artifact，避免 .skill 进 sys.path）
5. **消息总线**：postMessage 三事件（redraw_sent 既有 + hotzone_saved + unit_review_done）；数据权威源=服务端
6. **worker 日志防挂起**：必须 Popen + 线程读 queue + deadline kill（纯 `for line in proc.stdout` 会永久阻塞零输出子进程）
7. **FILE_LOCK 与 TASK_LOCK 不嵌套**（无死锁面）；并发 validate 已验证无丢失更新
8. **模板→报告传播**：改 quality_review_template.html 必须重跑 gen_qa_reports.py 全量（qa_reports 不入库）
9. **并行会话活跃时只提交不 push**；push/tag 需用户明确同意（§6A）；精确 git add + diff --cached 复核
10. **版本策略**：开发支撑迭代不改 tools.py 版本（保持 v1.3.0）；功能级增量打 tag（v1.3.2/v1.3.3）
