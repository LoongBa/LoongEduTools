## 2. 目标与原则

**目标**：本轮后——
1. 文档与实际功能一致（修 3 处过时 + 统一版本号到 v1.3.0）
2. 构建期自动校验热区坐标合法性 + 音频覆盖，异常即警告/失败
3. 工作台单元卡片展示校验状态（坐标异常数 / 音频缺失数），可一键重新校验

**原则**：
1. **校验默认不破坏构建**：坐标异常/音频缺失默认 WARN（不中断），新增 `--strict` 可选硬失败——保持既有构建兼容
2. **单一校验源**：校验逻辑集中在 `build_framework.py` 新增模块（`validate_hotzones` / `validate_audio_coverage`），构建期与工作台共用
3. 文档修复如实描述现状，不夸大
4. 本轮不改点读产物包版本（v1.3.0 保持，发布等音频产物重建另行确认）

### 3.5 V1：热区坐标合法性校验（`validate_hotzones`）

**新函数**（`build_framework.py` 新增，供构建期 + 工作台共用；Oracle R1：只校验最终产物坐标，不重复 page/track 遍历）：
```python
def validate_hotzones(unit: dict) -> list[dict]:
    """校验单元最终产物（post-correction）热区坐标合法性。
    unit = build_unit_data() 返回值（已是校正后坐标）。
    返回异常列表: [{page, track, kind, detail, from_correction}]
    kind: out_of_range(超出[0,1]) / inverted(right<=left 或 bottom<=top) /
          zero_area(面积<1e-6) / corrupt(非数值)
    from_correction: True=该坐标来自热区校正覆盖（便于编辑器定位上游）
    """
```
- 规则：left/top/right/bottom 均在 [0,1]；right>left；bottom>top；面积>1e-6；数值可解析
- **调用点**：`build_tool`（unit 构建完成后、convert_images 前）——`build_unit_data` 保持纯函数
- 构建期汇总 WARN（列出 top N 条 + 计数）；`--strict` 时异常>0 → SystemExit（R4 见 §3.8）

### 3.6 V2：音频覆盖校验（`validate_audio_coverage`）

**Oracle R2：必须复用 `find_source_audio` + 抽取回退目录解析**——先抽公共 helper：
```python
def _resolve_audio_dirs(audio_dir: Path) -> tuple[Path, Path | None]:
    """主音频目录 + 回退目录（_重读音频素材 → 同级 _音频素材/单句音频 兜底）。
    convert_audio 与 validate_audio_coverage 共用，避免口径分叉。"""
```
- `convert_audio` 改为调用 `_resolve_audio_dirs`（行为不变）
- 新增 `validate_audio_coverage(unit: dict, audio_dir: Path) -> dict`：
  ```python
  """返回 {total_tracks, missing_audio: [{page, track, key}], ok: bool}"""
  # 内部对每个 track 调 find_source_audio(primary, page_no, t, fallback) 判存在性，
  # 不重新实现 glob 匹配（与构建实际解析完全一致）
  ```
- 构建期：`convert_audio` 前调用，WARN 汇总「本单元 N/M 缺音频」；`--strict` 硬失败
- **`build_manifest` 口径对齐（Oracle 指出）**：manifest 现仅扫 `_音频素材`，与构建「重读优先+音频素材兜底」口径不同。本轮在编辑器 UI/文档注明「清单=原版音频；构建=重读优先」，并让工作台 badge 与构建口径一致（走 `_resolve_audio_dirs`）

### 3.7 V3：工作台校验状态集成（Oracle R3：按成本分层 + 缓存）

**服务端** `hotzone_serve.py`：
- `_handle_status` 每单元附 `validation`：
  - `hz_issues: N` —— **自动计算**（纯坐标校验，成本可忽略，复用 `validate_hotzones`）
  - `audio_missing: N | null` —— **按需计算**（涉及大量 glob，不自动跑；`null`=未校验）
- 新增 `POST /api/validate {book, unit?}`：跑音频校验 → 写模块级缓存 + 落 `_重绘图片素材/校验记录.json`
- 缓存失效键 = `(书数据.json mtime, max 热区校正 mtime, _重读音频素材 mtime, _音频素材 mtime)`，任一变化则 `audio_missing` 标 stale

**前端** `workbench/index.html`：
- 单元卡片校验 badge：`⚠️ 热区 N`（橙）、`🔇 缺音频 N`（红，点击触发 `/api/validate`）
- 卡片边框：有校验问题 → 橙/红边（与 hasfail/has-hz 并存）
- 发布摘要行加校验计数；`audio_missing: null` 显示「🔇 未校验（点击校验）」

**涉及文件**：`build_framework.py`、`hotzone_serve.py`、`workbench/index.html`

### 3.8 `--strict` 管线（Oracle R4）

- `build_tool` 增 `strict: bool = False` 参数
- `build_all.py` 增 `--strict` flag，透传 build_tool
- **多单元构建（--units 0,1,2）collect-then-fail**：收集全部单元 issue 后统一 SystemExit（打印每单元 top N + 总数），一次看全
- 单一 `--strict` 即对 hz+audio 同时硬失败（不细分，避免过度设计）

## 7. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 校验 WARN 影响既有构建输出 | 产物差异 | 校验只加日志不改产物；build 回归对比验证 |
| 工作台 validation 依赖 build_framework 函数 | 服务端 import 耦合 | sys.path 已注入；ImportError 兜底（缺依赖时跳过校验） |
| 文档大改引入新错误 | 误导 | 修订后 grep 断言 + 人工核对关键表述 |
| 四上真实数据可能暴露既有坐标异常 | 校验告警多 | 校验结果如实展示（这正是价值）；不硬失败 |
