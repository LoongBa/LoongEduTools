## 2. 目标与原则

**目标**：本轮迭代后——
1. 工作台 11 册任意单元「🧪 测试」都能正确解析产物路径（无产物时给出明确提示）
2. 从工作台点「📋 审核」直接定位到对应单元，不用手动翻
3. 单元寻址**单一口径**：服务端为权威源，前端零重复逻辑
4. 发布闭环（提材/重建）失败信息可诊断

**原则**：
1. **服务端为单元元数据权威源**：`/api/status` 返回每单元 `app_name`。**前缀由服务端 BOOK_MAP 的 grade/vol 派生（`新英语{grade[0]}{vol[0]}点读`），unit_no 解析复用 build_framework 抽取的 `resolve_unit_no()` 公共函数**——两边各管各的、零漂移。
2. 保持 file:// 直开与 http 服务器模式双兼容（质检报告 matURL 已有基础）。
3. 不改点读产物包（本轮纯开发支撑工具，产物发布等重读音频完成后另行确认）。`resolve_unit_no` 抽取属纯重构（提取+委托调用），不改变任何产物命名行为。
4. 修复最小化：聚焦清单 7 项，不借机重构。

## 3. 变更设计

### 3.1 P0-A：测试链接动态化（app_name 服务端下发）

**现状**：`workbench/index.html` L223 硬编码 `新英语四上点读${no}单元_解压测试版`。

**方案（Oracle 修订：不复用 resolve_app_name 整体）**：
1. `build_framework.py`：从 `resolve_app_name` 中**抽取 `resolve_unit_no(book, unit_index) -> str` 公共函数**（Unit N→N / Revision→复习 / Appendix N→附录N / else→unit_index+1）；`resolve_app_name` 改为委托调用它（行为零变化）。
2. `hotzone_serve.py` `_handle_status()`：每单元计算 app_name 加入响应
   - 前缀：`f"新英语{grade[0]}{vol[0]}点读"`（BOOK_MAP 派生的 grade/vol，非硬编码）
   - unit_no：`from build_framework import resolve_unit_no`
   - `units[i].app_name = f"新英语{grade[0]}{vol[0]}点读{unit_no}单元"`
3. `workbench/index.html`：
   - `switchView('test')` 改用 `u.app_name`（不再 `unitNoOf(u)` 拼接）
   - 测试路径：`../../publish/学科/${u.app_name}_解压测试版/index.html`（相对路径，publish 由 /redtools/ 服务）
   - **存在性探测**：`fetch(url, {method:'HEAD', cache:'no-store'})` 探测 **`<app_name>_解压测试版/index.html`**（实际启动目标，非目录）——失败时提示「该册尚未构建解压测试版（先 🔨 重建单元）」而非开空白页

**涉及文件**：`build_framework.py`、`hotzone_serve.py`、`workbench/index.html`

### 3.2 P0-B：审核视图单元定位（?unit=N 锚点）

**现状**：`workbench/index.html` L217 `frame.src = ../qa_reports/${bookKey}.html` 无单元参数；报告模板 `currentUnit=0` 固定初值。

**方案（Oracle 修订：补 L773 openReview 冲突）**：
1. `quality_review_template.html`：初始化时解析 `location.search` 的 `unit` 参数
   - `?unit=N`（单元下标）→ 初始化 `currentUnit=N`，`render()` 后定位到单元
   - **关键：模板 L773 `if(reviewList.length) openReview(0)` 会立即进全屏覆盖定位** → 修订为：`?unit` 存在时，`openReview` 定位到**该单元首张重绘页**（`reviewList.findIndex(p => p.page >= u.start && p.page < u.end)`，找不到回退 0）；无 `?unit`（file:// 直开）保持现状
2. `workbench/index.html`：审核视图 src 改为 `../qa_reports/${bookKey}.html?unit=${curUnit}`

**涉及文件**：`quality_review_template.html`、`workbench/index.html`

### 3.3 P1-C：统一单元寻址口径

**现状**：前端 `unitNo()`（L121-128）与 `build_framework.resolve_app_name`（L78-108）重复实现；测试链接用标题解析、rebuild 用下标。

**方案**：
1. 测试链接一律用服务端下发的 `u.app_name`（3.1 完成）
2. `unitNo()` 保留仅作**卡片展示**用途（如标题无 Unit N 时的角标数字），不再参与路径拼装
3. `switchView('test')` 校验：`u.app_name` 为空/缺失时给提示，不 window.open

**涉及文件**：`workbench/index.html`

### 3.4 P1-D：status 页数按实际 bookpage 计数（防御）

**现状**：`hotzone_serve.py` L225 `end = pages_max + 1`，L251 `pages = max(0, end - start)`——页码差口径。

**方案（Oracle 修订：int 健壮化）**：`pages` 改为「bookpage 中 page_no ∈ [start, end) 的实际页数」：
```python
actual = sum(1 for p in bookdata.get("bookpage", []) if start <= int(p.get("page_no") or 0) < end)
units.append({..., "pages": actual, ...})
```
（四上当前数据结果不变：Unit1 12 页 … Appendix4 2 页；缺页/末单元边界自动正确）

**涉及文件**：`hotzone_serve.py`

### 3.5 P2-E：rebuild 失败日志展示

**现状**：`workbench/index.html` L246-257 失败时仅单行错误（`j.tail` 虽拼入但不可读）。

**方案**：
- `doRebuild` 失败时 `pubStatus` 显示错误行 + 追加「📋 查看日志」toggle，展开 `<pre>` 显示 `j.tail`（滚动 300px 高）
- 成功时显示发布状态行（现状保留）

**涉及文件**：`workbench/index.html`（+ 少量 CSS）

### 3.6 P2-F：promote 备份保留多版

**现状**：`hotzone_serve.py` L392 `shutil.copy2(dst, backup_dir / f"Page_{page:03d}_v_prev.png")`。

**方案（Oracle 修订：时间戳防碰撞）**：备份名带**日期+时间戳**：
```python
ts = datetime.datetime.now().strftime("%Y%m%d_%H%M%S")
shutil.copy2(dst, backup_dir / f"Page_{page:03d}_v_{ts}.png")
```
（保留每次提材前一版，不覆盖、跨日不冲突）

**涉及文件**：`hotzone_serve.py`

### 3.7 P0-G：修复 `import time` 缺失（Oracle 新增）

**现状**：`redraw_worker()` L92 `time.sleep(1)` 但顶部无 `import time` → worker 首循环 NameError 死亡，队列瘫痪。

**方案**：`hotzone_serve.py` import 块补 `import time`。验证：入队 1 任务 → 状态 60s 内从 queued 转 done/failed（冒烟新增断言）。

**涉及文件**：`hotzone_serve.py`
