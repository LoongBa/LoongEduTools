# 通用需求：小工具打卡 / 成绩记录 / 分享

> **通用能力规范**（跨工具复用），非某一具体工具需求。适用于学科/游戏类小工具
> （数学口算、舒尔特方格、翻牌记忆配对等）的激励与传播闭环。
> 状态：**需求记录（Demo 级）**，可进入设计/开发。
> 关联：数学口算 `docs/工具文档/学科/数学口算-设计文档.md` F6/F9（每日打卡，P0）为本需求的先行实现，
> 本需求为其通用化沉淀 + 补齐「成绩记录」「分享」两块。
> 更新：2026-09-17

---

## 1. 定位与范围

| 项 | 说明 |
|---|---|
| 通用能力 | **打卡记录**（localStorage）/ **成绩记录**（最高分/最近成绩/进步曲线）/ **分享**（打卡卡片图 + 一键复制文案） |
| 本期形态 | 小红书小工具（离线 zip + H5，纯前端，不联网） |
| 未来扩展 | **微信 / 抖音内运行的 H5**（对接 OAuth 认证、平台分享接口）——本期先预留接口抽象，见 §6 |
| 核心价值 | **「打卡有成就感 + 一键生成分享素材」**，让家长愿意主动发笔记/朋友圈传播 |

## 2. 核心功能

### 2.1 打卡记录（P0）

- **每日打卡**：打开小工具自动记录当天使用，生成连续打卡天数。
- **历史记录**：展示最近 7 天 / 30 天打卡日历，高亮已打卡的天（小圆点日历）。
- **本地存储**：全部数据存 localStorage，无需联网。

### 2.2 成绩记录（P2）

- **最高分**：记录历史最好成绩（最快用时 / 最高分数，按工具定义指标）。
- **最近 10 次成绩**：按时间倒序列出。
- **进步曲线**：简单 SVG 折线图，展示最近 10 次成绩变化趋势（不引图表库）。

### 2.3 分享功能（P1）

- **生成打卡卡片**：
  - 尺寸 **1080×1920**（竖版，适配小红书笔记）。
  - 内容：连续打卡天数 + 今日成绩 + 鼓励语 + 小工具名称 / 作者。
  - 风格：简洁、可爱、暖色调，适合家长发朋友圈 / 小红书。
- **一键复制文案**：自动生成分享文案，例：

  > "今天是连续打卡第 7 天！孩子做舒尔特方格只用了 15 秒，比昨天快了 2 秒！专注力训练效果太明显了～# 专注力 #舒尔特方格 #小学生"

- **保存图片**：用户长按保存打卡卡片，手动发布笔记。

## 3. 交互流程

```
打开小工具 → 主界面（游戏/练习）
    ↓
完成一次练习 → 弹出结算页
    ↓
结算页显示：本次成绩 + 历史最好 + 连续打卡天数
    ↓
底部两个按钮：
    【再来一次】  【分享打卡】
    ↓
点【分享打卡】 → 生成打卡卡片预览
    ↓
预览页显示：
    - 打卡卡片大图
    - 自动复制的文案提示"已复制，去小红书粘贴发布吧"
    - 【保存图片】按钮
```

## 4. UI 要求

- 所有界面简洁，**一屏看完**，无复杂导航。
- 打卡日历用**小圆点**表示，打了卡的天高亮。
- 进步曲线用**简单 SVG** 画，不依赖图表库。
- 分享卡片设计适合小红书风格（暖色调、可爱字体）。
- 遵循系列基线（Chrome 61 / Android 8.1）：按钮 hit area ≥48×48px、反馈动画温和、无强闪烁。

## 5. 技术约束（离线 zip 版，本期）

- 纯前端，所有数据存 **localStorage**，不联网、不调用任何 API。
- 分享功能：**canvas 生成图片 + 复制文案到剪贴板**。
- 包体 ≤ 10 MiB（实际纯前端无媒体场景按系列规范 **≤ 2 MiB**；卡片为运行时 canvas 绘制，不占包体）。

### 5.1 localStorage 设计（与数学口算 v2 schema 对齐）

> 多工具共存关键：容器内（同一域名 WebView / 同源 H5）localStorage 是**共享**的，
> 所有 key 必须带工具命名空间前缀：`<toolId>_<key>`（如 `math_arith_checkin`）。

```js
{
  version: 1,                          // ★ 版本字段 + 迁移函数（v1→v2）
  checkin: { dates: ["YYYYMMDD"], streak, longestStreak },  // 打卡
  records: { best: {...}, recent10: [ /* 按时间倒序，滚动维护 */ ] },  // 成绩
  // 各工具自有数据（错题本等）由工具自行扩展，key 统一带工具前缀
}
```

- 打卡：`dates` 存已打卡日期字符串，连续天数由 dates 回溯计算（跨天/缺天正确）。
- 成绩：`recent10` 上限 10 条 FIFO；`best` 按工具定义的指标（用时越小越好 / 分数越大越好）更新。

### 5.2 复制文案（Chrome 61 兼容，关键）

- **基线无 `navigator.clipboard`**（66+ 才有）→ 用 **`document.execCommand('copy')` + 隐藏 `<textarea>`** 方案。
- 必须在**用户手势内**调用（点击【分享打卡】按钮时即复制）。
- **保底**：复制失败时展示文案全文，提示手动长按选择复制（iOS 微信 WKWebView 等场景兜底）。

### 5.3 卡片生成与保存

- **生成**：离屏 `<canvas>`（1080×1920）绘制卡片 → `toDataURL('image/png')` / `toBlob`。
- **保存**：
  - 移动端：提示**长按图片保存**（H5 无法静默写入相册，微信 JS-SDK `saveImageToPhotosAlbum` 属未来 H5 版能力，见 §6）。
  - 桌面/部分安卓：`<a download>` 触发下载。
- 卡片文案（打卡天数/今日成绩/鼓励语）由工具传入，通用模板渲染。

### 5.4 合规自查（系列规范）

- 无 `fetch`/XHR/Worker/定位/`window.open`、无外部 `http(s)://` 引用（剪贴板/下载均用本地 API）。
- JS：ES2017 经典脚本；CSS：Chrome 61 基线（禁 gap/aspect-ratio/clamp 等）。
- 发布前跑 `audit_artifact.py` + 冒烟测试（file:// 与 http:// 双协议）。

## 6. 未来扩展：微信 / 抖音内 H5（预留接口）

> 本期离线 zip **不实现**以下能力，但代码层预留抽象，避免日后返工。

| 能力 | 离线 zip 版（本期） | 微信 H5 | 抖音 H5 |
|---|---|---|---|
| 存储 | localStorage（工具前缀命名空间） | 同左；注意公众号环境第三方 Cookie/分区存储差异 | 同左 |
| 认证 | 无 | 微信 OAuth 网页授权（**需后端签名**，公众号服务号资质） | 抖音开放平台 OAuth（需后端 + 应用资质） |
| 分享 | 卡片图长按保存 + 文案复制 | 微信 JS-SDK `wx.updateAppMessageShareData` / `wx.saveImageToPhotosAlbum`（需 JS-SDK + 后端签名） | 抖音 JS SDK / Web Share API 能力探测 |
| 通用分享探测 | — | `navigator.share` 存在则优先（可分享文字/文件），否则降级复制+长按 | 同左 |

**代码层预留建议**：
1. **能力探测封装**：`getShareCapability()` 返回 `{ webShare: bool, wxSdk: bool, copy: bool, saveAlbum: bool }`，各分享入口按能力分支。
2. **分享文案生成纯函数**：输入（打卡天数/今日成绩/工具名/标签）→ 输出文案字符串，H5 版可复用同一函数拼 `wx.updateAppMessageShareData` 的 title/desc。
3. **卡片渲染抽离**：canvas 绘制逻辑与 DOM 解耦，H5 版可复用生成图传给平台分享接口。
4. **认证预留**：入口处预留 `auth` 抽象（离线版恒为匿名模式），不绑定任何平台 API。
