# 通用需求：防沉迷与自控力

> **通用能力规范**（跨工具复用）：每个小游戏都带"自控力/防沉迷"设置——开局前可设时长与
> 今日局数，到点提醒选择「延迟」或「我很自律，今天足够了」，结算页提供「分享/自律」出口。
> 状态：**需求记录（设计已定稿）**，扫雷（v1.0.1）为首批落地，其余工具按本文档对齐。
> 关联：`docs/通用需求-打卡分享记录.md`（打卡/成绩/分享 schema，本文档的结算三选与分享复用其 §2/§5）。

## 1. 定位与设计思想

| 项 | 说明 |
|---|---|
| 通用能力 | **防沉迷/自控力训练**：开局前设置 → 到点提醒 → 延迟/自律二选 → 结算三选（再来/分享/自律） |
| 本期形态 | 小红书小工具（离线 zip + H5，纯前端，数据全部 localStorage） |
| 核心设计思想 | **不断网不锁屏的"软提醒 + 成就感"**：小游戏不能强制关闭（无法技术锁死），
  且"我家孩子很自律"的**成就记录**正是家长发笔记传播的卖点——防沉迷本身就是传播素材 |
| 目标用户 | 小学生（被约束对象）+ 家长（设置者/见证者） |
| 伪需求排除 | ❌ 不做法定时的硬停机/人脸验证（离线小工具无后台、无意义）；❌ 不做家长端远程管理
  （超出本期形态）；✅ 做"自律天数"成就 + 分享卡片里的自律徽标 |

**一句话设计**：让孩子在开始前自己选"今天玩多久/玩几局"，到时间了由他自己决定「延迟」还是
「我很自律，今天足够了」——把防沉迷变成**自控力训练**，而不是家长单方面限制。

## 2. 通用规则（所有小游戏默认继承）

### 2.1 开局前设置（guard）

- **单局时长档位**：5 / 10 / 15 分钟（默认 **5**），记忆上次选择（`minutePref`）。
- **今日局数上限**：3 / 5 / 10 局 / 不限（默认 **5**），记忆上次选择（`gamesPref`，0=不限）。
- **入口**：信息条附近「⏱」设置条（展开两个选择行），每次新局前可见可改；设置即时生效并持久化。
- **试错局豁免**：失败且用时 < **10 秒**的局视为"试探性操作"，**不计入今日局数**；
  胜利或用时 ≥ 10 秒的失败才算一局（`startedAt` 判定，防止孩子反复闪电开局刷局数）。
- **跨日重置**：`today` 变化时清零 `playedToday / delayMinTimes / delayGamesTimes`。

### 2.2 到点提醒（guard 弹窗）

触发条件（满足任一，游戏**暂停**，计时停走、棋盘输入忽略）：

| 触发 | 判定 |
|---|---|
| 单局时长到点 | `state.time >= minutePref * 60` |
| 今日局数到点 | `guard.playedToday >= gamesPref`（gamesPref>0 时） |

弹窗两选：

| 按钮 | 行为 |
|---|---|
| **延迟** | 时长 → 本局再 +5 分钟；局数 → 今日上限再 +2 局；**每类延迟上限 2 次**（`delayMinTimes / delayGamesTimes` 计数，达上限后到点不再提供延迟，仅剩自律） |
| **我很自律，今天足够了** | `selfDaily` 记今日 + 重算 `selfStreak` → 结束本局（清 cur、锁今日 `selfLocked`）→ 显示自律祝贺弹窗 |

### 2.3 自律锁（selfLocked）

- 点「我很自律」后：**今日不再接受新局**（难度 tab / 新游戏按钮 → 提示"今天已经很自律啦，明天见"）。
- 明日 `today` 变化自动解锁。
- 结算页 / 设置条的「自律」按钮也在局内任一时点可用（主动结束今日）。

### 2.4 结算三选（胜利 / 失败 / 自律退出后）

```
🎉/💥 结算弹层
├── 再来一局      （仅自律锁未生效时）
├── 分享打卡      （1080×1920 卡片 + 文案，见通用需求-打卡分享记录.md §2.3/§5）
└── 我很自律，今天足够了
```

- 分享卡片增加「今日自律 X 天」徽标（激励传播）。
- 自律退出不分胜负，仍记录"今日自律天数"成就。

## 3. 不同类型小游戏的差异

> 防沉迷按工具类型自然适配——**核心思想一致，档位口径与触发时机按玩法微调**。

| 维度 | 经典游戏类（扫雷/2048/俄罗斯方块） | 学科练习类（口算/乘法口诀/点读） | 益智关卡类（舒尔特/找不同/拼图） |
|---|---|---|---|
| 时长档位 | 5/10/15 分钟（默认 5） | 5/10/15 分钟（默认 5） | 5/10/15 分钟（默认 5） |
| 局数档位 | 3/5/10/不限（默认 5） | 无"局"概念 → 用**组/题量**：10/20/30题/不限（默认 10） | 3/5/10/不限（默认 5） |
| 试错局豁免 | ✅ 失败且 <10s 不计（如点错雷） | ✅ 答错不算"完成"，按**完成题数**计数，无试错概念 | ✅ 未完成关卡不计；完成才 +1 |
| 到点后 | 暂停弹窗（延迟/自律） | 到点时先弹"本组完成即休息"引导，完成本组后再弹二选 | 到点弹"完成本关再休息"二选 |
| 结算三选 | ✅ 再有/分享/自律 | ✅（再来一组/分享/自律） | ✅（再来一关/分享/自律） |
| 自律锁 | ✅ 统一 | ✅ 统一 | ✅ 统一 |
| 备注 | 扫雷为**首批落地**，全部规则照 §2 实现 | 计数口径改为题量，触发时机延后到组间 | 计数口径按关卡完成 |

> **实现约定**：`guard` schema（§4）各工具完全一致；差异仅在"局"的计数来源与档位文案。

## 4. localStorage schema（统一）

> 对齐 `docs/通用需求-打卡分享记录.md` §5.1 的 `<toolId>_<key>` 命名空间，`guard` 字段各工具一致。

```js
{
  version: 2,                          // ⬆ 引入 guard 后升到 2（v1 数据迁移：补 guard/selfDaily 默认值）
  // ...既有：best / games / wins / checkin（见通用需求-打卡分享记录.md）
  guard: {
    minutePref: 5,                     // 单局时长档位（5/10/15）
    gamesPref: 5,                      // 今日局数档位（3/5/10 或 0=不限；学科类为题量档位）
    today: "YYYYMMDD",                 // 当前计数日（跨日重置判断）
    playedToday: 0,                    // 今日已计局数（学科类=已完成题量；益智类=已完成关卡数）
    delayMinTimes: 0,                  // 单局时长延迟次数（上限 2，跨日重置）
    delayGamesTimes: 0                 // 局数延迟次数（上限 2，跨日重置）
  },
  selfDaily: ["YYYYMMDD"],             // 自律退出天数（去重、滚动 365）
  selfStreak: 0,                       // 连续自律天数（calcStreak 同打卡逻辑）
  selfLocked: false,                   // 今日是否已自律锁定（跨日自动复位）
  cur: { ..., startedAt: 0 }           // 增加 startedAt（首点毫秒时间戳，试错局判定）
}
```

**迁移规则**：读旧 store（无 `guard`）时补齐默认值并写回；无副作用。

## 5. 合规与边界

- 纯前端，无网络/无 API；所有防沉迷数据 localStorage。
- 弹窗文案温和正向（"休息一下，明天更棒"），避免焦虑话术。
- 延迟上限 2 次后**仅剩自律出口**（强制按钮只此一个，但**不强行结束游戏**——保持"提醒式"，
  不产生"被锁死"的对抗感；真正约束靠自律成就带来的正向反馈）。
- Chrome 61 基线：无新 API；canvas 分享卡片与剪贴板方案复用打卡分享文档 §5.2/§5.3。
