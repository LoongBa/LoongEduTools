# 重绘图片审核 + 热区修正 — 需求与设计方案

> 版本：v0.1（草案）| 日期：2026-09-20 | 状态：待评审
> 目标：基于**服务器模式**，把「重绘图片审核」与「热区修正」整合到**一个统一界面**，
> 带年级/册次/单元汇总入口，数据统一保存在**各册重绘目录**（`_重绘图片素材/`）。

---

## 1. 背景与现状问题

英语点读重绘流程已拆分出多个工具，但使用分散、入口混乱：

| 现状工具 | 职责 | 问题 |
|---|---|---|
| `qa_reports/*.html`（质检报告） | 人工对比原图/重绘，标记通过/需重绘/画框 | file:// 直开可用，但与热区编辑分离；审核结论需导出 JSON 再手动同步 |
| `hotzone_editor/`（热区校正） | 拖动/缩放热区、保存校正 | 与审核分离；数据保存依赖浏览器下载或服务器 POST |
| `redraw.py` / `tasks/`（重绘脚本） | AI 重绘 | 与审核/热区无界面联动 |
| `hotzone_serve.py` / `hotzone_prepare.py` | 服务器 / 本地数据包加载 | 双模式并存，增加心智负担 |
| `apply_qa_review.py` / `promote_redraws.py` / `gen_qa_reports.py` | 审核应用 / 提材 / 报告生成 | 命令行为主，无统一入口 |

**核心痛点**：
1. 审核与热区修正分属两个界面，切换成本高；同一页既要点读又要调热区时来回跳。
2. 数据分散：审核记录在 `qa_reviews.json`，热区校正在 `热区校正_*.json`，图片在 `_重绘图片素材/`，无统一视图。
3. 发布前无法直观确认「某单元图片/热区/审核是否最新」。
4. 临时文件/生成物散落，清理靠人工。

---

## 2. 目标与原则

**目标**：一个服务器模式下的统一工作台，覆盖「重绘 → 审核 → 修正热区 → 提材 → 构建 → 发布确认」全流程。

**原则**（用户确认的 7 条 + 补充）：
1. 数据：原始数据复制到各册**重绘目录**（`_重绘图片素材/`）作为后续数据，与原始数据断开。
2. 图片审核：需重绘页重新审核，通过即更新数据并**记录时间**。
3. 热区数据：修改过的不丢失，**记录时间**（`exported_at` / 文件 mtime）。
4. 分单元审核、绘制热区。
5. 发布时间标记：版本与图片更新时间、热区更新时间**分离为独立小字标记**（仅时间，不标注含义）。
6. 发布状态：构建时输出「版本 / 图片是否最新 / 热区是否最新」。
7. 审核界面：左右两张图、中间操作区；审核后自动下一张；「跳过已通过」默认勾选；单元完成自动衔接，本册结束询问返回。
8. 审核时支持**矩形标记**（原图/重绘画框 + 原因 + 备注），供重绘重点纠正。
9. **服务器模式为唯一主模式**：统一界面由服务提供，自动加载素材；本地数据包模式降级为离线备选。
10. 数据统一存各册重绘目录：`book.json` 副本、`热区校正_*.json`、审核记录。

## 3. 功能需求

### 3.1 统一工作台（服务器模式）

- 服务入口：`hotzone_serve.py`（或更名 `redtools_workbench.py`）一键启动，浏览器打开统一界面。
- 统一界面（单页应用）：
  - **汇总入口**（首页）：年级 → 册次 → 单元 三级导航，显示每单元的：
    - 重绘进度（已重绘/总数）、审核进度（通过/需重绘/待审）、热区校正状态（有无校正文件、最后更新时间）
    - 测试链接（解压测试版直达）
  - **单元工作台**（点入某单元后）：同一界面内两个视图切换：
    - **审核视图**：左右原图/重绘 + 中间操作区（✅同意过审 / ❌需重绘 / 原因勾选 / 备注 / 矩形标记 / 自动下一张 / 跳过已通过 / 单元衔接）
    - **热区视图**：当前页点读热区编辑（拖动/缩放/删除/播放验证/坐标面板），并排显示原图对照
  - 两视图可**同页快速切换**（如审核发现问题 → 一键切到热区视图微调 → 切回审核继续）。

### 3.2 数据存储（统一在各册重绘目录）

```
F:\_教材素材\...\<年级>\<册>\_重绘图片素材\
├── book.json                          # 原始 book.json 副本（编辑基准，与原始断开）
├── _hotzone_manifest.json             # 音频清单（服务器/数据包加载用）
├── 热区校正_<单元标题>.json            # 热区修正数据（每单元一个，覆盖同名=更新）
├── review_<单元标题>.json  (或统一 qa_reviews.json)  # 审核记录（页级：pass/issues/marks/reason/时间）
└── Page_*.png                         # 重绘图片（审核通过后提材至此）
```

- 审核记录建议**每册一份** `review.json`（随册存放，避免全局文件）：
  ```json
  { "book": "四年级_上册", "updated_at": "...",
    "reviews": { "21": {"pass": false, "issues": ["blurry"], "marks": [...], "reason": "...", "reviewed_at": "..."} } }
  ```
- 时间记录：审核 `reviewed_at`、热区 `exported_at`、文件 mtime，均进入「发布状态」检查。

### 3.3 数据流

```
原始 book.json ──► 复制副本 → _重绘图片素材/book.json（脱离原始）
原始图片 ──► AI 重绘（redraw.py）→ tasks/output → 审核视图人工审核
审核通过 ──► 提材 → _重绘图片素材/Page_*.png（记录时间）
审核需重绘 ──► 带 marks/reason 重新重绘 → 再审核（循环）
热区修正 ──► 热区视图 → 保存 → _重绘图片素材/热区校正_*.json（覆盖更新，记录时间）
构建 ──► build_all.py（自动读重绘目录副本 + 校正文件）→ zip + 发布状态检查
发布确认 ──► 版本 / 图片时间 / 热区时间 独立标记 + 是否最新
```

### 3.4 服务端接口（hotzone_serve.py 扩展）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/redtools/工作台/index.html` | GET | 统一工作台页面 |
| `/<年级>/<册>/...` | GET | 素材静态服务（图片/音频/副本） |
| `/api/unit` | GET | 单元元数据（页/轨道/重绘状态/审核状态/热区状态） |
| `/api/status` | GET | 全册状态汇总（进度/时间/最新性） | ✅ |
| `/api/save_hotzone` | POST | 保存热区校正 → 重绘目录（覆盖更新） | ✅ |
| `/api/save_review` | POST | 保存审核记录 → qa_reviews.json + 重生成报告 | ✅ |
| `/api/promote` | POST | 提材（审核通过页 → 重绘目录） | ✅ |
| `/api/rebuild` | POST | 重建单元 zip（build_all.py，返回发布状态） | ✅ |

### 3.5 发布状态（已有基础，纳入工作台展示）

- 构建输出：`发布状态: 版本 1.2.0 | 图片 07:53 | 热区 08:44 | 构建 08:45`
- 工作台每单元展示：图片是否最新（素材 mtime vs 构建时间）、热区是否最新、审核进度。

## 4. 设计方案

### 4.1 架构

```
┌────────────────────────────────────────────────┐
│  统一工作台（服务器模式单页应用）                  │
│  ├── 汇总首页（年级→册→单元，进度/状态/时间）      │
│  └── 单元工作台                                  │
│      ├── 审核视图（左右图+中间操作+矩形标记+自动下张）│
│      └── 热区视图（点读热区编辑+原图对照）         │
└──────────────────┬─────────────────────────────┘
                   │ HTTP (GET 素材 / POST api)
┌──────────────────▼─────────────────────────────┐
│  hotzone_serve.py（本地 HTTP 服务）               │
│  ├── 静态：/redtools/*（工作台+工具） /<册>/*（素材）│
│  └── API：save_hotzone / save_review / promote   │
│       / rebuild / status / apply_review          │
└──────────────────┬─────────────────────────────┘
                   │ 读写
┌──────────────────▼─────────────────────────────┐
│  各册重绘目录 _重绘图片素材/（book 副本/校正/审核/图）│
│  重绘工具/（脚本：redraw/apply/promote/build）    │
└────────────────────────────────────────────────┘
```

### 4.2 界面布局（单元工作台）

```
┌ 顶栏：返回汇总 | 年级·册·单元 | 版本/图片/热区时间小字 ┐
├────────────────────────────────────────────────┤
│  视图切换：[审核] [热区]                          │
├────────────────────────────────────────────────┤
│  审核视图：                                       │
│  ┌─原图─┬─操作区─┬─重绘─┐                        │
│  │      │ 状态/进度 │     │                        │
│  │      │ ◀ 下一页 ▶  │     │                        │
│  │      │ ✅同意 ❌需重绘│     │                        │
│  │      │ 原因/备注    │     │                        │
│  │      │ 📍标记 跳过已通过 │     │                        │
│  └──────┴───────┴─────┘                        │
│  热区视图：                                       │
│  ┌─重绘(可编辑热区)─┬─原图对照─┬─句子列表/坐标─┐     │
└────────────────────────────────────────────────┘
```

### 4.3 关键实现点

- **共用一套审核状态**：审核视图与热区视图共享 `S[pageKey]`（pass/issues/marks/reason），热区视图编辑后审核状态不受影响。
- **矩形标记**（已实现于质检模板）复用：坐标按原图 natural 尺寸存储，重绘侧按坐标区域重点纠正。
- **自动下一张/跳过已通过/单元衔接**（已实现）复用。
- **数据保存**：服务器模式 POST 保存（覆盖同名=更新，带确认）；构建侧两处扫描（册根 + 重绘目录）保持兼容。
- **提材**：审核通过页自动从任务 output 复制到重绘目录（promote_redraws.py，册前缀防串）。
- **发布状态**：`data_source_times()`（图片/热区最新 mtime）+ 构建日志（已实现），工作台以 `/api/status` 展示。

| M2 | 统一工作台：汇总入口（年级/册/单元 + 进度/热区/审核状态）+ `/api/status` | ✅ 已完成（2026-09-20） |
