## 2. 目标与原则

### 2.1 目标

- **玩法**：给定初始盘面（确定性）+ 目标数字，孩子编排**方向指令序列**（⬅➡⬆⬇，可参数化 ×N）
  → ▶ 执行 → 程序判定最终盘面是否合出目标数字。
- **判定**：最终盘面含 ≥ 目标数字的块 = 有标准答案（合规安全区）。
- **概念教学**：顺序（方向序列）+ **策略规划**（多步合并路径预判）——编程教学线「策略型」第 3 种。
- **星级**：指令条数 vs **BFS 最短指令数**（确定性状态空间可搜）→ ≤1.5× 3★ / ≤2.5× 2★。
- **形态**：离线 zip 静态 + 双模式；零素材（CSS 数字块风格复用 2048）。

### 2.2 原则

1. 有标准答案判定（最终盘面含目标值）——合规安全区核心。
2. **确定性执行**：去掉 randomTile，移动后不插新块（与 2048 原版关键区别，程序可判）。
3. **BFS 最优解**：确定性状态空间有限（4^d），BFS visited 去重可算最短指令数（星级基准）。
4. 生成器必有解：随机初始盘面 → BFS 验证可达目标 → 不可达重试。
5. 复用 2048 slideLine/applyMove 合并逻辑 + 通用模式 + lx-shared；零素材、Chrome 61 兼容。

## 3. 变更设计

### 3.1 玩法与指令模型

**盘面**：小盘面。简单 3×3（目标 8）/ 普通 4×4（目标 16）/ 挑战 4×4（目标 32）。

**★ 难度数值（oracle 数学匹配修正 v0.2）**：target 是「2 原子」需求——32=2⁵ 需 16 原子、16 需 8、8 需 4。
初始块值 ∈ {2,4}，故 **initBlocks 必须保证最差情况（全 2）sum ≥ target 原子**：
- 简单：3×3 · target 8（4 原子）· **initBlocks=4**（全 2 = 4 原子 ✅）· maxSteps 5
- 普通：4×4 · target 16（8 原子）· **initBlocks=6**（全 2 = 6 < 8 → 但仍可能靠生成 4 块凑够；**生成器另加 sum≥target 硬约束保证**）· maxSteps 7
- 挑战：4×4 · target 32（16 原子）· **initBlocks=9**（全 2 = 9 < 16 → **同样靠 sum≥target 硬约束**）· maxSteps 9

> **硬约束**：生成器放置 initBlocks 个块（值 ∈ {2,4}）后，**校验 Σ块值 ≥ target**（不满足则整盘重随机）——
> 因 2048 合并值恒为 2 的幂、block 原子量即其数值本身，sum ≥ target 是**可达的必要条件**（oracle 致命项修复）。
> 配合 BFS 可达验证（充分条件），保证 100% 有解。

**指令集**（方向序列，可参数化）：

| 指令 | 语义 | 参数化 |
|---|---|---|
| ⬅ 左移 | 整盘向左滑（2048 合并语义，每块每轮只合一次） | chip ×N = 连续左移 N 次 |
| ➡ 右移 | 整盘向右滑 | 同上 |
| ⬆ 上移 | 整盘向上滑 | 同上 |
| ⬇ 下移 | 整盘向下滑 | 同上 |

**执行语义**：逐条指令应用 `applyMovePure(grid, dir)`（确定性、无新块）；动画逐步展示（每步 300ms，合并 pop 高亮）。

**边界/无变化语义**：某方向移动无变化（changed=false）→ **计 1 条指令** + 盘面闪烁 + 友好文案「⬅ 这边没有块可以移动哦」（oracle UX 建议），星级按总指令条数计（与 BFS 最优解口径数学一致——BFS optimal 是严格下界，oracle 确认）。

### 3.2 确定性核心（复用 2048 合并逻辑 → 纯函数改造）

- **复用算法**：`slideLine`（一维滑移合并，每块每轮只合一次）——2048 已实现（main.js:157-181）；
- **★ 纯函数改造（oracle 阻断项）**：2048 原版 `applyMove(dir)` 直接 **in-place 修改 `state.grid`**（main.js:182-205），且 `slideLine` 内 `state.score +=` 累加。BFS 需要不可变快照，**必须改造为纯函数版**：
  ```
  applyMovePure(grid, size, dir) → { newGrid, changed }
  ```
  - BFS 与执行器**共用同一 applyMovePure**（单一实现防不一致，对齐方块排列指令 dropRowFor 先例）；
  - slideLine 去掉 score 累加，返回 {out, merged}；
  - `idxAt`（main.js:151）/ `gridSame`（main.js:77）硬编码 SIZE=4 → **参数化 size**（支持 3×3/4×4）；
- **判定目标**：`isWon(grid, target)` = `max(grid) >= target`（2048 原 `isWon` 硬编码 2048 → 参数化；「≥」比「恰好」更合适——合出更大是超额完成不惩罚，oracle PASS）。
- **反馈强化**：达成时若 `max(grid) > target`，文案含「🎉 合出了 N，超过目标 M！」正向强化（oracle 建议）。

### 3.3 关卡生成器（随机盘面 + sum 硬约束 + BFS 必达验证 + seed 兜底）

```
genLevel(diff):
  cfg = {easy:{size:3, target:8,  maxSteps:5,  initBlocks:4},
         normal:{size:4, target:16, maxSteps:7,  initBlocks:6},
         hard:{size:4, target:32, maxSteps:9, initBlocks:9}}[diff]
  loop 上限 200:
    grid = 空盘
    随机放置 initBlocks 个块（值 ∈ {2, 4}，位置不重叠）
    if sum(grid) < cfg.target: continue      # ★ 原子量硬约束（oracle 致命项修复）
    shortest = bfsShortest(grid, cfg.target, cfg.maxSteps)
    if shortest >= 1:                        # 解长 1..maxSteps（0 = 初始含目标，排除）
      返回 {grid, target, optimal: shortest}
  返回 seedLevel(diff)                        # ★ seed 兜底（oracle 阻断项：教学工具永不卡死）
```

**seed 兜底盘面**（每难度 2 组手工设计有解盘面，生成失败时轮换使用）：
- easy seed：`[2,2,2,2]` 排一行 → 左移×2 = 8（optimal 2）；
- normal seed：`[2,2,2,2, 4,4]`（4×4 两行）→ 构造 16；
- hard seed：`[4,4,4,4, 4,4,4,4, 2,2]`（4×4 三行 8×4 + 2×2）→ 构造 32。

**BFS 最短指令数**（纯函数 + visited + 无变化剪枝）：

```
bfsShortest(startGrid, target, maxDepth):
  if max(startGrid) >= target: return 0       # ★ 入口防御（oracle 建议，BFS 自守）
  queue = [{grid: startGrid, depth: 0}]; visited = {key(startGrid)}
  while queue:
    cur = dequeue
    for dir in 0..3:
      res = applyMovePure(cur.grid, size, dir)   # 纯函数
      if !res.changed: continue                  # 无变化剪枝（不算步数，口径一致）
      if max(res.newGrid) >= target: return cur.depth + 1
      if cur.depth + 1 < maxDepth and !visited.has(key(res.newGrid)):
        visited.add; enqueue
  return -1
```

- **性能基准（oracle 建议）**：验证计划 §4 补「批量 100 关/难度测 BFS P99 耗时 < 50ms」；
- **风险缓解**：`>50ms 降级`——仅验证可达、用生成时缓存 optimal 作星级基准（不重新求最优）。

### 3.4 判定与反馈

- 全部指令执行完 → 盘面含 ≥ 目标 → 过关（星级/打卡/下一关）；
- 未达成 → 反馈当前最大值：`✗ 最大只有 N，还没合出 M（还差一点！调整指令再试）`；
- 达成但超额 → `✓ 完成！合出了 N（目标 M）🎉`（oracle 正向强化建议）；
- 无变化步 → 盘面闪烁 + `⬅ 这边没有块可以移动哦`（oracle UX 建议）；
- 执行中高亮当前指令 chip（复用走迷宫 exec 高亮）+ 指令锁定（防编辑）；
- 目标数字常驻显示（顶栏/盘面角标）；合并规则概念卡（「两个相同数字相撞，合成一个双倍」oracle 建议）。

### 3.5 页面结构

```
首页（三难度卡 + best/星）
关卡页：顶栏（‹ 返回 / 难度 / 目标：合出 X / ⏱ 计时）
        盘面（CSS grid 数字块，2048 米黄配色 + 目标数字角标）
        指令区（⬅➡⬆⬇ 按钮 + 序列 chips 参数化 ×N + ▶ 执行 / ↺ 清空 / ⟲ 重置）
        反馈条（执行中高亮 / 达成 / 未达成-当前最大值 / 无变化提示）
        结算（星级 / 打卡 / 下一关 ›）
```
