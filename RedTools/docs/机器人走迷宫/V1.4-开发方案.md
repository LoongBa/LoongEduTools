## 1. 背景与现状问题

| 编号 | 优先级 | 问题 | 代码位置 |
|---|---|---|---|
| P1 | 高 | **失败无定位**：执行失败（箱子未到位）仅显示「✗ 还有箱子没到目标点，调整指令再试」——孩子不知道是**第几条指令错了、错在哪一步**（撞墙/推不动/绕远），调试闭环缺失 | `execStep()`（main.js L433-488）、`checkWin()`（L490-501） |
| P2 | 中 | **执行过程无轨迹**：260ms 步进动画能看到机器人动，但**指令序列无当前执行位置指示**——长序列下孩子跟不上「机器人正在执行第几条」 | `renderSeq()`（L364-391）静态渲染，执行时不变 |
| P3 | 低 | **差箱量无提示**：失败时不知道**还差几个箱子没到位**（目标感弱） | `checkWin()` L499 |

> 立项评估 §3.2 明确承诺「执行失败显示定位错误指令（像调试器）」为学习反馈三要素之一（对/错判定 ✔ 已有、星级 ✔ 已有、**错误定位 ✘ 缺失**）。

## 2. 目标与原则

**目标**：V1.4 补齐「编排 → 执行 → 观察 → **调试**」闭环的学习反馈——
1. 执行中在指令序列**高亮当前正在执行的指令**（可视化轨迹跟踪）；
2. 执行失败定位**首个出错指令**（撞墙/推不动 + 展开步数提示，像调试器断点）；
3. 失败时提示**还差几个箱子**到位（目标差距反馈）。

**原则**：
- 最小化修改：只动 main.js 执行器 + style.css 高亮样式，**不改关卡数据/判定规则/存储结构**；
- 保持 ES2017 / Chrome 61 兼容（class 名操作、无新 API）；
- 不改变星级/打卡/结算逻辑（学习反馈增强，非玩法变更）；
- 失败定位只提示「第一个」错误（调试器语义：先解决最早问题）。

## 3. 变更设计

### 3.1 P1 + P2：执行追踪与指令高亮（main.js `execStep` / `renderSeq`）

**现状**：`execStep()` 每步移动后 `setTimeout(execStep, 260)`；`renderSeq()` 静态渲染 chip（无执行态样式）。

**方案（v0.2 修订：砍 stepLog、加执行锁定、简化文案）**：
1. `state` 新增执行追踪字段（仅执行期使用，不入库）：
   ```js
   firstFail: null,     // 首个失败：{absStep, prog, cmdId, reason}（wall|box|edge）
   absStep: 0,          // 展开步计数（循环指令按 rep 展开的绝对步数）
   execLock: false      // 执行中锁定标志（防执行期间改序列）
   ```
   （v0.2 砍弃 v0.1 的 `stepLog[]` 全量日志——仅为失败定位不需要历史轨迹；`done` 态也砍，非过度设计）
2. **执行锁定**（v0.2 新增，自审发现）：`execRun()` 置 `state.execLock = true`，`checkWin()` 结束置 `false`；
   `addCmd()` / `removeCmd()` / `cycleRep()` / 清空按钮入口判断 `execLock` 时 return（防执行中改序列导致高亮/定位错位）；
   对应按钮加 `disabled` 态（CSS `[disabled]{opacity:.5}`）。
3. `execStep()` 每条指令执行前：`state.absStep += 1`；实际移动类指令（fwd）**未移动**（前方墙/箱推不动/越界）时
   记 `state.firstFail = {absStep, prog, cmdId, reason}`——只记首个：
   ```js
   if (!ok && !state.firstFail) { state.firstFail = {absStep: state.absStep, prog: state.prog, cmdId: cmd.id, reason: reason}; }
   ```
   left/right 从不失败；**block 永不报错**（前方有障碍是条件成立，非错误，见 §8 默认决议）。
4. 执行中渲染：当前指令 chip 加 `exec` 类——`execStep()` 内 `renderSeqHighlight()`（新增独立函数）：
   遍历 seq-box 内 `.cmd-chip`，第 `state.prog` 个加 `exec`、其余移除（**只改 classList，不重建 seq-box，事件不丢**）；
   执行完成（`checkWin`）时清全部 `exec`。
5. 执行完成反馈文案：
   - `state.firstFail` 存在 → 该指令 chip 加 `err` 类 + 反馈文案
     「✗ 第 M 条指令 ⬆ 卡住了：前方是墙/推不动箱子」——**用「第 M 条指令」定位**（M = prog+1，孩子跟着序列数数即知），
     absStep 仅内部分析用、不进文案（v0.2 简化：避免「第 N 步 × 第 M 条」双概念混淆）；
   - 无 firstFail 但箱子未到位 → 差箱提示（见 3.2）。
6. `execRun()` / 重置按钮入口置 `state.firstFail = null; state.absStep = 0`（状态清理防残留）。

### 3.2 P3：差箱提示（main.js `checkWin`）

**现状**：失败统一文案。

**方案**：`checkWin()` 失败分支末尾追加差箱统计——
```js
var left = 0; for (var k in state.boxes) { if (hasOwn(state.boxes,k) && !state.goals[k]) left++; }
// 反馈文案：'✗ 还差 ' + left + ' 个箱子到目标点，调整指令再试'
// firstFail 存在时优先展示定位信息：'✗ 第 M 条指令卡住了（前方墙/推不动），还差 N 个箱子'
```
执行中锁定与状态清理（v0.2）：
- `execRun()` 入口：`state.execLock = true; state.firstFail = null; state.absStep = 0;`
- `checkWin()` 完成分支：`state.execLock = false;` 清所有 `.exec` class
- `addCmd/removeCmd/cycleRep/清空/重置` 入口：`if (state.execLock) return;` + 按钮 `disabled` 态

### 3.3 视觉设计（style.css）

新增 2 个 class（Chrome 61 兼容写法）+ 1 个禁用态：

| class | 用途 | 样式 |
|---|---|---|
| `.cmd-chip.exec` | 执行中当前指令 | 白底蓝字 + 蓝边 + 轻微放大/阴影（动画节奏 260ms 同频） |
| `.cmd-chip.err` | 失败定位指令 | 红底白字 + 红框 + ❗ 前缀（断点语义） |
| `[disabled]` | 执行中禁用的指令按钮 | `opacity:.5` 灰显（cmd-add / chip / 清空） |

> v0.2 砍弃 `done` 态（执行过轨迹灰显）——视觉噪音，低龄认知负担，非核心。仅 `exec`（蓝）高亮 + `err`（红）定位。

## 8. 默认决议（实施前置确认项，有异议可复议）

1. **block 永不报错**：失败定位仅针对 fwd「试图移动但未动」（前方墙/箱推不动/越界）；block 前方有障碍是**条件成立**（探测到障碍），不视为错误——避免把避障指令的预期行为误报为 bug（教学正确性优先）。
2. **不实现 done 态**：只高亮当前 exec，不做执行过轨迹灰显（视觉噪音，低龄认知负担）。
3. **首个失败即停**：失败定位停在第 1 个错误指令（调试器断点语义），文案提示「先改掉这一点」。
4. **firstFail/absStep/execLock 为执行期内存字段**，不入库、不持久化（存储结构零变更）。
5. **执行锁定**：执行期间（execLock）禁用指令编辑（addCmd/removeCmd/cycleRep/清空），防执行中改序列导致状态错位。
