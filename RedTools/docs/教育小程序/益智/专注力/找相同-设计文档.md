## 2. 玩法设计

### 2.1 规则

- 每局多轮（按难度）。每轮：顶部显示**目标图案**（大卡），下方 M 张**候选卡**——其中**恰好 1 张与目标完全一致**，其余 M−1 张为「带一种小差异」的干扰项。
- 点击候选卡：选对（与目标一致）→ 绿色确认 + 进入下一轮；选错 → 红闪 400ms + 错误计数 +1（**不换题，可重试**）。
- 全部轮次完成即过关。
- **价值**：孩子要先记住/比对目标特征（颜色、大小、局部部件），再逐张排除干扰项——训练抗干扰与细节分辨。

### 2.2 操作

| 输入 | 说明 |
|---|---|
| 点候选卡 | 正确 → 绿闪进下一轮；错误 → 红闪 + 错误 +1，卡可继续点 |
| 底栏按钮 | 「返回难度」回难度页；「重新开始」同难度重抽一局 |
| 顶栏按钮 | 「← 返回」回难度页 |

### 2.3 反馈

- **正确**：候选卡绿色确认（`okFlash 300ms`）+ 轻音效 → 350ms 后渲染下一轮（目标与候选全部换新）。
- **错误**：候选卡红闪（`wrongFlash 400ms`，背景 `#ffe9e6 → #ffd5d0 → 白`）+ 低音效 + 底栏 `❌ N` 计数更新；卡留在原处可再次尝试。
- **音效**（Web Audio `OscillatorNode` 合成，零音频文件）：正确清脆 / 错误低沉 / 胜利上行琶音；首次用户手势创建 `AudioContext`，异常静默降级。

## 4. 技术设计

### 4.1 数据模型

- **难度常量 `LEVELS`**：

| key | 难度 | 轮数 | 候选数 M | 干扰明显度 |
|---|---|---|---|---|
| '1' | 简单 | 5 | 3 | 明显：palette 对比色改色 / scale 1.4·0.7 / 变体；无位移 |
| '2' | 普通 | 6 | 4 | 中等：近似色 ±18~28% / scale 1.25·0.8 / 位移 10~16px |
| '3' | 困难 | 8 | 5 | 细微：近似色 ±5~13% / scale ±0.08~0.13 / 位移 5~9px |

- **运行时状态**：`state = { level, round, totalRounds, candidates: [{params, isTarget, op}], answerIndex, correct, errors, won, startMs, ms, timerId }`。

### 4.2 元素库（elements.js，73 元素零素材）

- `window.SCENES`（8 场景）+ 平铺池 `window.ELEMENTS`（73 个元素），**移植自找不同 scenes.js**（表格化：元素 draw 以 (0,0) 为中心的内层 SVG，支持 `draw({fill, variant})` 参数化 + `palette`/`variantMax` 元数据）。
- 每局抽元素**本局内不重复**（池 73 ≫ 轮数上限 8，充裕）。

### 4.3 出题引擎（目标 + 干扰项）

```
newRound():
  e = pickRoundElement()                # 池内随机、本局不重复
  targetP = { fill:e.fill, variant:0, s:1, dx:0, dy:0 }
  candidates = [{ params: targetP, isTarget:true }]
  + buildDistractors(e, level, M-1)     # M-1 个干扰项
  整体 Fisher-Yates 洗牌 → answerIndex = isTarget 下标
```

- **差异操作 `DIFF_OPS`**（4 种，难度控制强度）：

| op | 简单 '1' | 普通 '2' | 困难 '3' |
|---|---|---|---|
| recolor | palette 对比色（必不同于主色） | 50% palette 对比色 / 50% 近似色 ±18~28% | 近似色 ±5~13%（相似色调） |
| scale | 1.4 / 0.7（大） | 1.25 / 0.8（中） | ±0.08~0.13（微调） |
| variant | 切换变体（variantMax>0 才有此 op） | 同左 | 同左 |
| move | 无（难度 1 不用位移） | 10~16px | 5~9px |

- **干扰项唯一性（渲染签名去重）**：`makeSig(e, p) = elementCardSvg(e, p)`（渲染后的 SVG 字符串）作为去重键——同时保证干扰项**视觉上**确实与目标不同、彼此不同。
- **兜底**：改色幅度递增重试（理论上不触发，73 元素池各难度远足够）。

### 4.4 ⚠️ 修复记录：参数签名 → 渲染签名（v1.0 视觉质检发现）

- **问题**：初版用「渲染参数签名」（`fill|variant|s|dx_dy` 字符串）去重干扰项。但**部分元素的 `draw()` 忽略 `fill`/`variant` 参数**（图形硬编码颜色）→ recolor/variant 干扰项**渲染结果与目标完全一致** → 出现「看着一模一样、点它却判错」的假干扰项（真实游戏缺陷，视觉质检 + 冒烟随机捕获）。
- **修复**：去重键改为**渲染后的 SVG 字符串**（`elementCardSvg(e, p)`），凡渲染与目标/已有干扰项相同者一律重试（guard 40→60 + fallback 兜底）；scale/move 必然改变 outerHTML transform，保证任意元素最终都能生成有效干扰项。
- **验证**：修复后 30 局 × 5 轮 = **150 轮扫描 0 重复、答案唯一**（`verify_zxt_fix.py`）。

### 4.5 交互与判定

- 候选卡点击：`onCardTap(idx)` —— 判 `candidates[idx].isTarget`：正确 → 绿闪 + `correct++` → 350ms 后 `newRound()`；错误 → 红闪 400ms + `errors++` + 更新底栏计数。
- 最后一轮正确 → `onWin()`：计时定格、星级、存档、打卡、结算浮层。

### 4.6 计时

- `startTimer()`：`state.startMs = performance.now()`，`setInterval(100ms)` 差值刷新 `'⏱ ' + fmtTime(ms)`（秒 + 1 位小数，如 `⏱ 07.5`）。
- 进入游戏页即开始计时（整局计时，同数独入门/因果排序）。
- v1.0 无断局恢复（中途退出回难度页，重新进重抽新局）。

### 4.7 星级与最佳成绩

- **星级**（按错误次数）：★★★ 错误 0 次；★★ 错误 ≤2 次；★ 其余（过关即有）。
- **最佳判定** `betterThan`：星级高优先，同星级比用时短；仅严格更优才覆盖。
- **最近/历史**：`recent` 无条件覆盖、`history` 滚动保留最近 30 条。

### 4.8 持久化（localStorage）

- key：`redtools.zhaoxiangtong.v1`（工具前缀，容器内多工具共享存储）。
- 结构：

```js
{
  version: 1,
  best:    { "1": {ms, errors, stars, date}, "2": {...}, "3": {...} },  // 各难度最佳
  recent:  { "1": ms, "2": ms, "3": ms },                               // 各难度最近用时
  checkin: { dates: ["YYYYMMDD", ...], streak },                        // 打卡
  history: [ {date, level, ms, errors, stars} ]                         // 滚动 30 条
}
```

- 读写全部 try/catch（隐私模式等异常静默降级）；`loadStore()` 校验 `version === 1` 并补全缺失字段。
- **打卡** `doCheckin()`：过关一局 → 今日 YYYYMMDD 去重 + 排序 + 滚动 365 天；`calcStreak()` 连续天数**含今天往前推**，跨天断。

### 4.9 音效（Web Audio 合成）

```js
sndCorrect: triangle 523Hz 0.09s    // 找对（清脆）
sndWrong:   square   150Hz 0.12s    // 点错（低沉）
sndWin:     523/659/784/1047 上行琶音（sine，间隔 0.12s）
```

`AudioContext`（含 `webkitAudioContext` 兜底）懒创建 + 用户手势 `resume()`；全部 try/catch 降级。

### 4.10 视图结构

- 三个视图 + 一个浮层：**难度选择页** / **游戏页** / **打卡日历页**；**结算浮层**（`🎉 全找对啦！` + 星级 + 统计 + 打卡 + 三按钮：再来一局 / 选难度 / 打卡日历）。
- 每次切视图 `clearNode` 全量重建 DOM；候选卡正方形网格用 `width` + `padding-bottom` 百分比（3 张 33.33% 单行 / 4 张 50% 两行 / 5 张 33.33% 两行）。
- 打卡日历：7 列网格（`14.28%`），done 橙色 `#ff9c1a`、today 蓝色描边、`streak-info` 连续天数（≥7 天 🎉），与系列同款。

- 包体：构建产物 0.03 MiB（≪ 2 MiB 建议值）。

## 8. 与系列规范的关系

- **系列归属**：`教育工具产品矩阵规划.md` §4.1 专注力训练（P1 找相同）→ `series/益智/专注力/` 子系列第 2 款；适用 preK–K1-3（L1–L2）。
- **可复用核心**：计时/成绩/打卡对齐 `series/益智/设计文档.md` §4；Chrome 61 / 交互合规对齐 §5；**元素库与差异变换对齐 §6（找不同 pattern）**——8 场景 73 元素 `draw({fill,variant})` 参数化直接复用。
- **与找不同的关系（逆玩法）**：找不同 = 两图比对找差异（观察力，元素作用于场景）；找相同 = 目标 vs 多候选找唯一一致（专注力抗干扰，元素独立成卡）。差异变换池由找不同 5 种裁剪为 4 种——**hide 移除原因**：单图案卡片中隐藏一个部件对低龄区分度差且易误判，改由 variant（整体替换部件）承担。
- **与同系列差异**：无提示功能（找同性质无"给答案"诉求，错误可重试不惩罚）；星级仅按错误数（用时用于同星比较）。
- **扩展**：`ELEMENTS` 元素池可增补（新增场景/元素即扩充题库）；难度档可加轮数/候选数；后续可加「计时挑战」模式或提示（高亮与目标差异最小的候选）。
