## 2. 玩法设计

### 2.1 规则

- 从难度池随机取一条**步数匹配的因果/时间序列**，把步骤卡片打乱。
- 目标：按因果/时间先后顺序把卡片全部排好（`cards[i].stepIdx === i`，数组槽位 = 正确步序）。
- 交互：**点选一张卡片（橙色高亮）→ 点另一张 → 交换位置**；点已选中的卡片取消选中。
- 全部归位即过关；**排序类无「错动作」**：任何交换都被接受，不会像分类整理/数独那样报错，**步数即操作质量**（交换次数越少越好）。
- 每局序列随机抽取 + 洗牌，孩子不会背顺序。

### 2.2 操作

| 输入 | 说明 |
|---|---|
| 点卡片（无选中） | 选中该卡（橙色高亮 + 轻音效） |
| 点已选中卡片 | 取消选中 |
| 点另一张卡片 | 交换两张位置（重渲染 SVG + 280ms 弹跳动画 + 步数 +1 + 轻音效） |
| 💡 提示 | 高亮第一张错位卡片 1.2s（温和脉冲，**不自动归位**）；提示次数 +1（星级封顶 2★） |
| 重新开始 | 同难度重抽一局（重新取序列 + 重新洗牌） |
| 返回难度 | 回难度选择页 |

### 2.3 反馈

- **选中**：卡片橙色高亮；**交换**：两张卡 280ms 弹跳动画（`swap-anim`）+ 轻音效。
- **提示**：第一张错位卡 1.2s 温和脉冲（`hinting`），只「告诉你看哪张」，不代做。
- **通关**：全部卡片绿色边框闪烁 400ms（`solved`）+ 确认音 + 胜利上行琶音，350ms 后弹结算浮层「🎉 排好啦！」。
- **音效**（Web Audio `OscillatorNode` 合成，零音频文件）：点选（520Hz 0.05s triangle）/ 交换与提示（660→990 双音）/ 胜利（523/659/784/1047 上行琶音，同分类整理/迷宫寻路）。首次用户手势创建 `AudioContext`，播放异常静默降级。

## 3. 难度与序列库

### 3.1 三档难度（按卡片步数 N）

| key | 难度 | 步数 N | 序列池（随机取 1） | 3★ 步数上限（2N−1） | 2★ 步数上限（3N） |
|-----|------|-------|-------------------|---------------------|-------------------|
| '3' | 简单 | 3 | 昼夜三部曲 / 花开三部曲 | 5 | 9 |
| '4' | 普通 | 4 | 晨起流程 / 蝴蝶成长 / 做蛋糕 / 青蛙成长 | 7 | 12 |
| '5' | 困难 | 5 | 植物生长 / 洗手流程 | 9 | 15 |

- 序列池按难度硬编码在 `main.js` 的 `SEQ_POOL`（`'3'`→daycycle/bloom、`'4'`→morning/butterfly/cake/frog、`'5'`→plant/wash）；`pickSequence` 池未命中时按 `steps.length` 全库兜底。

### 3.2 序列库设计（causals.js，`window.CAUSALS`）

8 条「因果/时间」序列，共 **32 张步骤卡**，全部程序化 SVG 生成、零图片素材。每条序列 = `{ id, name, steps: [drawFn, ...] }`，`steps` 数组顺序即正确因果顺序（`steps[0]` 最先发生）。

| id | 序列 | 步数 | 各步内容（steps[0] → 最后） |
|----|------|------|------------------------------|
| daycycle | 昼夜三部曲 | 3 | 日出（粉霞 + 刚冒出地平线的半轮朝阳）→ 正午（蓝天 + 高挂太阳 + 云朵）→ 日落（橘红天空 + 低垂夕阳 + 深色剪影） |
| bloom | 花开三部曲 | 3 | 花苞（闭合绿苞未开）→ 半开（花瓣尖从苞里探出）→ 盛开（六片花瓣全开 + 花心 + 叶子） |
| morning | 晨起流程 | 4 | 起床（从床上坐起）→ 洗漱（洗手台前刷牙）→ 早餐（鸡蛋牛奶面包）→ 出门（背小书包走向门口） |
| butterfly | 蝴蝶成长 | 4 | 虫卵（叶上一团白卵）→ 毛毛虫（趴叶啃食）→ 蛹（挂在枝上）→ 蝴蝶（展翅彩色蝴蝶） |
| cake | 做蛋糕 | 4 | 搅拌面糊（打蛋盆）→ 烤箱烘烤（发红光）→ 裱奶油装饰 → 完成（两层蛋糕 + 草莓 + 樱桃） |
| frog | 青蛙成长 | 4 | 蛙卵（水里一团）→ 小蝌蚪 → 长腿蝌蚪（长出后腿）→ 青蛙（绿色坐好） |
| plant | 植物生长 | 5 | 播种（往土里撒种子）→ 发芽（小苗钻出）→ 长叶（长高叶多）→ 开花（粉色六瓣）→ 结果（红红苹果） |
| wash | 洗手流程 | 5 | 开水（拧开水龙头流水）→ 打肥皂（手心搓肥皂出泡沫）→ 搓手（用力搓满手泡泡）→ 冲水（水流冲净泡泡）→ 擦干（毛巾擦小手） |

- **程序化 SVG 卡片**：每张卡 `viewBox="-65 -65 130 130"`，内容以 (0,0) 为中心，糖果色童趣扁平风；由 `sky/greenHill/cloud/sunRays/kidHead/kidBody` 等共享场景配件 + 序列专属 drawFn 拼装，`w()` 包装为完整 `<svg>`；卡片间用明显「因果递进」视觉差区分。
- **cc 圆心圆 vs c 原点圆命名约定**：形状工具中 `cc(cx, cy, r, f)` 是**四参圆心圆**（显式指定圆心坐标），`c(r, f)` 是**原点圆**（圆心固定在 (0,0)）。**修复记录（v1.0 视觉质检发现）**：`kidHead` 曾误用原点圆 `c(9, color)` 画头部，导致头部偏到卡片原点；已修为四参圆心圆 `cc(x, y, 9, color)`；`wash` 序列「擦干」卡的 `cc` 多参缺陷同步修复。此后新卡片统一遵循「有坐标需求用 `cc`，中心对称装饰用 `c`」。
- **因果递进是卡片设计核心**：同一条序列内每张卡必须有肉眼可辨的「状态推进」（花苞→盛开、日出→正午→日落、蛙卵→蝌蚪→青蛙），跨序列不重复图形；视觉质检按此标准逐卡校验。

### 3.3 出题引擎

```
pickSequence(lv):          # 难度池随机取 1 条（SEQ_POOL 硬编码），池未命中按 steps.length 全库兜底
buildCards(seq):           # n 张 { stepIdx: 0..n-1 } → Fisher-Yates 洗牌
                           # 防「恰好还原」：isSortedArr 为真则重洗，guard ≤ 100
```

| 方法 | 职责 |
|------|------|
| `pickSequence(lv)` | 按难度池随机取序列；池未命中则全库按步数兜底 |
| `buildCards(seq)` | 生成 `[{stepIdx}]` 数组 + 洗牌；**防「恰好还原」重洗**（`isSortedArr` 为真则重洗，guard≤100） |
| `isSolved()` | 全遍历 `cards[i].stepIdx === i`（数组槽位 = 正确步序） |
| `firstMisplaced()` | 第一张错位卡片槽位（-1 表示全部归位），提示选卡依据 |

## 4. 交互与判定

- **选中/取消/交换 `onCardTap(slot)`**：取胜状态忽略 → 无选中则选中（`selected` 橙色高亮 + 轻音效）→ 点同一张取消选中 → 点另一张执行交换。
- **交换 `swapSlots(a, b)`**：换数组 → `updateCardSvg` 重渲染两张卡（`innerHTML` 重新注入对应 drawFn 生成的 SVG）→ 280ms 弹跳动画（`swap-anim`）→ 轻音效 → 步数 +1 → `updateStatus` → `isSolved()` 为真则 `finishGame()`。
- **归位判定 `isSolved`**：`cards[i].stepIdx === i`（槽位 i 上放的卡片目标步序号等于 i）；全部成立才结算。
- **无对错反馈**：排序类没有「错动作」，任何交换都被接受；步数即操作质量（星级依据）。
- **通关 `finishGame`**：全卡绿色边框闪烁 400ms（`solved`）+ 确认/胜利音效，350ms 后弹结算浮层；提示按钮禁用。

## 5. 提示与星级

### 5.1 提示（不代做）

- `useHint()`：找第一张错位卡片（`firstMisplaced`）→ 该卡 1.2s 温和脉冲高亮（`hinting` class）→ 提示次数 +1 → 双音确认音效。
- **只告诉你看哪张，不自动归位**；用一次提示星级封顶 2★。

### 5.2 星级（= f(提示, 步数)）

| 条件 | 星级 |
|---|---|
| 提示 0 次 **且** 步数 ≤ N×2−1（3→5、4→7、5→9） | ★★★ |
| 提示 ≤1 次 **且** 步数 ≤ N×3（3→9、4→12、5→15） | ★★ |
| 其余（过关即有） | ★ |

- 用过提示星级**封顶 2★**。
- **最佳判定 `betterThan(starsA, msA, starsB, msB)`**：**星级高优先，同星级比用时短**；仅严格更优才覆盖 `store.best[key]`。
- **最近**：`store.recent[key]` 无条件覆盖为本局用时；**历史**：`history` 无条件 push 后滚动保留最近 30 条。
- 结算浮层展示：星级 + 「用时 X 秒 · 步数 N 次 · 提示 N 次」+ ✅ 今日已打卡 + 新纪录徽标 + 三按钮（再来一局 / 选难度 / 📅 打卡日历）。

## 6. 持久化（localStorage）

- key：`redtools.yinguopaixu.v1`（容器内多工具共享存储，必须带工具前缀）。
- 结构：

```js
{
  version: 1,
  best:    { "3": {ms, moves, hints, stars, date}, "4": {...}, "5": {...} },  // 各难度最佳
  recent:  { "3": ms, "4": ms, "5": ms },                                     // 各难度最近用时
  checkin: { dates: ["YYYYMMDD", ...], streak },                              // 打卡
  history: [ {date, level, ms, moves, hints, stars} ]                         // 滚动 30 条
}
```

- 读写全部 try/catch（隐私模式等异常静默降级）；`loadStore()` 校验 `version === 1` 并补全缺失字段（best/recent/checkin/history），history 超 30 条截尾；初始化写入一次。
- **打卡** `doCheckin()`：通关一局 → `dates` 写入今日 YYYYMMDD（去重 + 排序）、滚动 365 天；`calcStreak()` 连续天数**含今天往前推**（今天未打则从昨天起算），跨天断。
- **计时**：从**游戏页渲染开始**（`startTimer()` 在 `startGame` 中调用，整局计时）；`performance.now()` + `setInterval(100ms)` 按差值刷新 `⏱ 07.5`（秒 + 1 位小数）；通关 `stopTimer()` 定格。

## 8. 合规自检（Chrome 61 / 容器规范）

- 触控/光敏：按钮 hit area ≥48px；动画温和（交换 280ms / 归位 400ms / 浮层 ≤250ms / 提示脉冲 1.2s 低振幅），无频闪。
- 资源：全部内联/本包；无外部 URL；无 CSP meta（容器管理）；序列卡程序化 SVG + 音效 Oscillator 合成 → **零图片零音频零数据文件**。
- 包体：构建产物 0.02 MiB（≪ 2 MiB 建议值）。

## 11. 与系列规范的关系

- **系列归属**：`教育工具产品矩阵规划.md` §3.4 逻辑思维训练（P2 因果排序）→ `series/益智/逻辑思维/` 子系列第 5 款；对标小象「因果关系排序」方向，适用 K1-3–K4-6（L2–L3）。
- **可复用核心**：计时/成绩/打卡对齐 `series/益智/设计文档.md` §4（localStorage key 带工具前缀 + 打卡日历模式，与数独思维/分类整理同款）；Chrome 61 / 交互合规对齐 §5。
- **与同系列的差异**：推箱子/迷宫寻路以求解指标（最少推动数/最短步数）定星级、分类整理以错误次数、数独思维以提示×错误，本工具改为**提示×步数双指标星级**（0 提示且步数 ≤2N−1 → 3★）；**排序类无「错动作」**（任何交换被接受，无错误计数，步数即操作质量）；计时从**游戏页渲染开始**（整局任务，同数独思维）；难度以**卡片步数**区分（3/4/5 步）而非盘面尺寸。
- **交互复用简单拼图**：点选两张交换（选中高亮 / 点同张取消）、数组槽位 = 目标位归位判定、Fisher-Yates 洗牌 + **防「恰好还原」重洗（guard≤100）** 均沿用 `series/益智/空间感知/简单拼图` 的交换模式。
- **程序化 SVG 新变体**：系列 §8 记忆力图标库（viewBox 40×40 单图标）、§9 空间感知场景切块（viewBox 裁剪）之后，本工具是「**程序化 SVG 步骤卡片**」新变体：整卡即一条序列的一步（viewBox 130×130 居中），8 序列共享场景配件函数（sky/cloud/sunRays/kidHead 等），序列库独立成 `causals.js`，后续可整体扩展新序列。
- **逻辑思维子系列至此 6 款全部完成**（2026-09-19）：迷宫寻路 / 分类整理 / 数独思维 / 推箱子 / 因果排序 / 蜡笔物理，待建清单清空（产品矩阵 §4.4 全部交付）。
- **扩展**：`SEQ_POOL` 加序列 id 即可扩档；`causals.js` 新增 `{id, name, steps}` 即新增序列；后续可加断局恢复（`state` 快照持久化）、拖拽排序（交互升级）、更多生活/自然序列。
