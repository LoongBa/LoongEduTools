## 1. 背景与目标

### 1.1 背景与现状

合并策略编程 v1.0 已完成「**解题**」路径：程序化生成器（随机盘面 + sum≥target 硬约束 + BFS 必达验证 + seed 兜底）+ 孩子编方向指令序列（⬅➡⬆⬇ 参数化 ×N）→ 最终盘面 ≥ 目标判定 + BFS 最短指令数星级。

**缺口**：与方块排列 v1.1→v1.2 同构——只有「解给定关卡」单向路径，缺**创作闭环**。孩子无法**自己设计初始盘面与目标**让程序/自己来解。设计文档 §8 明确候选「关卡编辑器」（创作闭环）。

### 1.2 教学定位（与方块排列 v1.2 对齐）

| 角色 | 方块排列 v1.2 | 合并策略 v1.1 |
|---|---|---|
| 解题 | 画目标图案 → 可拼校验 → 保存/挑战 | 摆初始数字块 + 选目标 → 可解校验 → 保存/挑战 |
| 教学价值 | 理解「图案能否由四格骨牌落拼出」→ 落定物理 | 理解「初始块值与目标的关系」→ **原子量/合并路径**（sum≥目标 只是必要条件，BFS 才是充分判定） |

- 角色反转：设计盘面时必须理解「2 和 2 相撞 = 4，4 和 4 = 8…（原子量翻倍）」「块数越多越容易合出大数，但指令也未必更短」「sum≥目标 不够——块的位置/合并路径决定了是否可达」→ 比解题更深的确定性状态推理
- 与方块排列 v1.2 同构：编辑器产出 → 校验（可解）→ 本地保存 → 进入同一练习/判定/星级流程
- 合规：自建关卡**本地存储、不入 publish**（同方块排列 v1.2 N1——custom 不对外分发）；无 PK/排行榜/云存档

### 1.3 目标

|---|---|

## 2. 变更设计

### 2.1 数据模型：自定义关卡库

**存储**：`LX_SHARED.storage`（工具已 `configure({toolName:'hebing'})` → 键前缀 `redtools.hebing.`）：
```js
// storage.set('customLevels', arr) → 实际键 'redtools.hebing.customLevels'（customLevels 是独立集合，非 store 的 'v1' 键，无 .v1. 段）
// value: [{ id, name, cells, size, target, optimal, createdAt, solved }, ...]
```
> ⚠️ 勿硬编码完整键名（绕过 storage 前缀约定 + 不被清除覆盖）。统一 `LX_SHARED.storage.set('customLevels', arr)` / `get('customLevels')`。

| 字段 | 说明 |
|---|---|
| id | 唯一（`Date.now() + '-' + Math.random().toString(36).slice(2,5)`，防毫秒碰撞——走迷宫 v1.9 N4） |
| name | 关卡名（默认「我的关卡 N」，≤12 字） |
| cells | 初始块数组 `[{idx, val}, ...]`（idx = y*4 + x，val ∈ {2,4}） |
| size | 固定 **4**（编辑器 4×4，对齐 normal/hard 盘面；easy 3×3 不开放——MVP 固定 4×4） |
| target | 目标数字 8/16/32（保存时确定） |
| optimal | **bfsShortest(grid, 4, target, 18)**（保存时算出；可达则 ≥1，不可达不保存） |
| createdAt | 创建时间戳 |
| solved | 是否已用指令通关过（「已解」徽章） |

**上限**：最多 **20 关**（超限提示删旧关）；**块数 ≤ 9**（对齐 hard initBlocks=9，BFS 状态空间与 v1.0 生成器同量级——P99 <0.5ms 实测基线）；**块值仅 2/4**（对齐生成器取值域，原子量语义一致）。

**存取函数**（同方块排列 v1.2 签名）：
| 函数 | 签名 | 说明 |
|---|---|---|
| loadCustomLevels | `() → Array` | IIFE 顶部 `var customLevels = loadCustomLevels()`；无数据 `[]` |
| saveCustomLevels | `(arr) → void` | `storage.set('customLevels', arr)` |
| addCustomLevel | `(cells, target, optimal, name) → id` | 校验通过后构造对象 push + save；超 20 提示 |
| removeCustomLevel | `(id) → void` | confirm 后按 id 过滤 + save |
| markCustomSolved | `(idx) → void` | `customLevels[idx].solved = true; saveCustomLevels(customLevels)` |

### 2.3 编辑器视图（viewEditor）

**布局**（独立视图）：
```
┌──────────────────────────────────┐
│ [‹ 返回] 🛠 盘面编辑器 ⏱ 4×4      │
│ 名称: [________]（≤12字）          │
│ 目标: [8] [16] [32]  ← 三选一     │
│ ┌────────────────────────────┐ │
│ │  4×4 网格（点格循环摆块）     │ │  ← 中央网格
│ └────────────────────────────┘ │
│ 工具: [🔢 2] [🔢 4] [🧹 橡皮]     │  ← 先选值再点格（或点格循环 空→2→4→空）
│ 校验: [✓ 检查可解]  [💾 保存]  [↺ 清空]  │
└──────────────────────────────────┘
```

**绘制交互**：
- 每格 `editCells[y*4+x] = 0 | 2 | 4`（0 = 空）；**点格循环**：空 → 2 → 4 → 空（单击即可，低龄友好——不需先选工具再点）
- 另提供「🔢 2 / 🔢 4 / 🧹 橡皮」工具按钮 = 点格**直接写入**该值（连续涂多格用：`pointerdown` + `pointermove` + `setPointerCapture`，Chrome 55+ 基线内）
- 预览渲染：2 → 米黄小方块、4 → 深色块（复用 TILE_CLS 配色，所见 = 练习时盘面样子）
- **模型转换**（Oracle 复核 N-3）：编辑器 `editCells[y*4+x]`（位置索引数组）↔ 存储 `cells = [{idx, val}]`（对象数组）——保存时非零格 → `{idx, val}` 过滤；编辑载入时 cells → editCells 填充（startCustom line 142-143 已示范 cells → grid，编辑器需逆向）

**可解性校验（✓ 检查可解）**——核心新逻辑（**复用 v1.0 bfsShortest，零新算法**）：

| 检查项 | 规则 |
|---|---|
| 块数 | `cells.length ≥ 1` 且 `≤ 9`（「最多 9 个数字块」）；值仅 2/4 |
| **原子量硬约束** | `sum(cells) ≥ target`（v1.0 oracle v0.2 确立的必要条件；不满足直接提示「数字加起来不够目标」） |
| **可解性** | `bfsShortest(grid, 4, target, 18) ≥ 1`（**精确充分判定**——2048 合并确定性无随机新块，BFS 即完备；maxDepth 18 = Oracle I1 修订：custom 盘面非生成器产出（生成器保证 ≤9 步必达），target=32 + 9 块散布极端盘面合并链 4→8→16→32 可能需 13-18 步，12 步不够；4×4 状态空间有限 + nodeCap 20 万兜底防爆） |

> **为什么 D4 比 D3 简单**：方块排列需 checkSolvable 两阶段（落定物理顺序相关、覆盖剪枝不完备）；合并策略的合并过程**无落定物理**（applyMovePure 纯函数 + BFS 已精确建模）——BFS 可达 = 孩子存在合法指令解，且返回的 `optimal` 即**真实最优步数**（非任意参考解）。这是 D4 custom 能上真实星级的根本前提（见 §2.4）。

**BFS 性能与兜底**（Oracle I2/N3 修订）：
- v1.0 实测：3 难度生成器 BFS P99 < 0.5ms（easy 0.1 / normal 0.2 / hard 0.5，maxSteps ≤ 9）——custom 块数 ≤ 9、maxDepth 18、4×4 固定 → 同量级，**实施时补测 custom 量级 P99**（N3）
- **nodeCap 20 万**（bfsShortest 增加可选 `nodeCap` 参数，默认不启用、custom 校验时传 200000）→ **超限返回 -2**（Oracle I2：返回值三态区分）
- **校验三态语义**：

| bfsShortest 返回值 | 语义 | 校验文案 |
|---|---|---|
| `opt >= 1` | 可解（最优步数已知） | 「✓ 可解！最优 N 步」→ 可保存 |
| `opt === -1` | maxDepth 内无解（真不可解或需更多步） | 「**18 步内未找到解**，试试少放几块或改小目标」（Oracle I1：非绝对「不可解」） |
| `opt === -2` | nodeCap 超限 | 「暂不确定，试试**减少块数**或改小目标」（非假阴性，与方块排列 v1.2 一致；Oracle 复核 I-3：编辑器 4×4 固定不可缩小盘面） |

**保存**：
- 校验通过才可保存（「✓ 可解！保存成功」）；未校验/不可解/暂不确定 → 提示先检查
- 保存 → addCustomLevel → 返回关卡库列表

### 2.4 自定义关卡练习（startCustom）

**进入**：关卡库列表点 [▶ 挑战] → `startCustom(idx)`（复刻 startGame 完整启动序列）：
```js
function startCustom(idx) {
  state.finished = false;                     // Oracle I3：与 startGame 对齐
  state.execLock = false; state.execDone = false; state.won = false;
  state.cmds = []; state.totalCmds = 0;
  state.level = 'custom'; state.customIdx = idx;
  state.size = 4;                             // Oracle N2：统一 state.size（守卫用）
  var cl = customLevels[idx];
  var grid = new Array(16).fill(0);
  for (var i = 0; i < cl.cells.length; i++) { grid[cl.cells[i].idx] = cl.cells[i].val; }
  state.initGrid = grid; state.grid = grid.slice();
  state.target = cl.target; state.optimal = cl.optimal;
  renderGame(); state.startMs = Date.now(); startTimer();
}
```

**星级：真实 BFS 最优基准**（与 v1.0 同公式）：
- `total ≤ optimal * 1.5 → 3★`；`≤ optimal * 2.5 → 2★`；其余 1★
- optimal 保存时由 bfsShortest 精确算出（确定性执行 + 最优可达）→ 3★ 可达成（**优于方块排列 v1.2 的 2★ 兜底**——D3 是因 refPieces 是任意合法解非最优解；D4 的 bfsShortest 即最优解，无此限制）
- 教学激励：孩子挑战「用 ≤ 最优的指令数合出目标」——理解 BFS 最优 vs 自己编排的差距

**custom 模式守卫清单**（Oracle v0.2 修订：N2 state.size 统一后精简为 7 处——renderBoardOnly/execStep 不再直接读 LEVELS_CFG）：

> **N2 统一口径**：startGame/startCustom 均设 `state.size`（内置关 = `LEVELS_CFG[level].size`，custom = 4），renderBoardOnly/execStep 统一读 `state.size`——消除两处 LEVELS_CFG 守卫点，降低遗漏风险。
> ⚠️ 实施注（Oracle 复核 N-1/N-2）：v1.0 `startGame`（L359-373）**同步补** `state.size = LEVELS_CFG[level].size;`（不展示代码，防漏改）；v1.0 `state` 对象（L66-79）补 `size: 4` 初始属性（与 target: 8 同级，对齐默认档）。

|---|---|---|
| renderGame 顶栏 | `LEVELS_CFG[state.level].label` | `state.level === 'custom' ? customLevels[state.customIdx].name : LEVELS_CFG[state.level].label` |
| renderBoardOnly/execStep | `LEVELS_CFG[state.level].size` | **改读 `state.size`**（startGame/startCustom 统一设置，N2） |

## 4. 验证计划

### 4.1 单元测试（Node 独立脚本，与前端同一实现源）

| 测试项 | 断言 |
|---|---|
| 空盘面 | 0 块 → 拦截「先摆数字块」 |
| 块数上限 | 10 块 → 拦截「最多 9 个数字块」 |
| 值域 | 出现非 2/4 → 拦截（UI 层不产生，防御性） |
| **原子量硬约束** | 2×2（sum=4）目标 8 → 拦截「数字加起来不够」 |
| 单块可解 | [4] 目标 8 不可解（单块无法翻倍）→ 拦截；[2,2] 目标 4 → 可解（左移=4） |
| 简单可解 | [2,2,2,2] 一行 目标 8 → 可解 optimal=2 |
| **不可解样例** | 4 块分四角（无相邻）目标 8 → sum=8 但不可解 → 拦截（教学点：sum 够不等于可达） |
| 普通可达 | [2,2,2,2,4,4] 目标 16 → 可解（v1.0 seed normal 同构） |
| 挑战可达 | 三行 8×4 + 2×2 目标 32 → 可解（v1.0 seed hard 同构） |
| **BFS 最优与 v1.0 一致** | 对 v1.0 seed 三盘面：bfsShortest(…,18) 结果 ≥ 原 maxSteps 口径结果（深度扩展不破坏既有判定） |
| **nodeCap -2（Oracle I2 + 复核 I-4）** | ① 确定性测试：bfsShortest(grid, 4, target, 18, **10**) → 返回 -2（低 nodeCap 强制触发，验证 -2 返回路径 + 文案）；② 极端盘面（9 块全 4 + 目标 32 高散布局）→ 不误触 -2（常规量级）；常规盘面必返回精确值 |
| **maxDepth 三态（Oracle I1）** | 校验逻辑区分：`opt>=1` 可解 / `opt===-1` 不可解（18 步内无解）/ `opt===-2` 暂不确定——三态文案各就位 |
| **custom BFS 性能（Oracle N3）** | 随机 custom 盘面 200 轮：bfsShortest(grid,4,target,18) P99 实测（期望 ≪50ms；与 v1.0 0.5ms 同量级上报） |
| 生成器互逆 | genLevel 随机 100 关：custom 校验逻辑（sum+bfsShortest(…,18)）→ 全可解（生成即解） |
| optimal 回放 | custom 保存后：按 optimal 步 BFS 解逐步执行（applyMovePure）→ 必达 target |
