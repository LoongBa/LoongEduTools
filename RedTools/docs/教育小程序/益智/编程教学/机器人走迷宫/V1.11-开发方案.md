## 1. 背景与目标

### 1.1 背景

v1.10 完成自定义指令块（抽象/封装）：孩子把重复动作段封装成命名块，主序列引用复用。
**缺口**：块是"固定动作段"——同一块每次调用动作完全相同。真实函数（Scratch My Blocks 带输入）
支持**参数化**：同一块，调用时传入不同参数，动作不同（如「前进 N 步」块，传 2 走 2 格、传 5 走 5 格）。
编程教学最高阶抽象 = **函数参数**（同一函数不同输入 → 不同行为）。

### 1.2 教学定位

- v1.10 抽象：**命名复用**（✓ 已验证：把重复段打包，主序列精简）
- **v1.11 参数化**：**同块不同参数 → 不同行为**（函数签名/参数的启蒙）——"一个块，N 种用法"
- 教学价值：孩子发现「距离不同但路径模式相同」的动作段可以**共用一块**（只差数字）——
  比 v1.10 更进一步：不只省"重复写"，还能省"重复建块"
- 类比：v1.6 steps（➡N步）= 指令级参数；v1.11 块参数 = **块级参数**（参数注入块体）

### 1.3 与既有能力关系

| 能力 | 现状（v1.10） | v1.11 |
|---|---|---|
| 块定义 | body 仅基础指令（含 steps 固定参数） | + 块可声明"带 1 个参数（走 N 步）"；body 内 steps 可参数化（steps:null） |
| 块调用 | `{id:'call', bid, name}` 无参数 | + `param:N`（N=1..9，默认 3）；chip 显示 `🧩块名(3)` |
| 执行 | execCall 展开 body | 展开时把 call.param 注入 body 参数化 steps 的**运行时值**（不改块库） |
| 星级 | call 计 1 + body 一次（I-1） | 保持；参数化 steps 计 1（同基础 steps） |
| N-3 遗留 | 游戏中「管理块」→ 块库 → 仅返回首页（丢游戏现场） | + 块库「返回游戏」按钮（来源记忆 blockListReturn） |

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **函数参数化**：同块不同参数不同行为；识别"距离不同但模式相同"的动作段共用一块 |
| 玩法 | 块编辑器可开「🔢 带参数」→ body 内 steps 变 `➡N步(N)`（参数版）；调用时 chip 显示 `🧩名(N)`，点击 1→9 调参 |
| 合规 | 本地存储（同 v1.10）、无 PK/云同步；参数化 = 编程概念教学 |
| 范围 | 0 新关卡（块是元能力）；**每块 ≤1 个参数**（低龄，参数化 steps 仅 1 处）；不影响 v1.10 无参数块 |

## 2. 变更设计

### 2.1 数据模型扩展（customBlocks）

```js
// 块对象（v1.11 扩展）：{ id, name, body, createdAt }   // ★ hasParam 不存储（B2 派生）
// body 内参数化 steps：{ id:'steps', steps:null }（steps=null 表示"运行时取调用参数"）
// call 指令（v1.11 扩展）：{ id:'call', bid, name, param: N }（param 仅当目标块含参数化 steps 时有意义）
```

- **hasParam 派生（B2 采纳，Oracle 修订）**：`blockHasParam(id) = getCustomBlock(id).body.some(c => c.id==='steps' && c.steps===null)`——
  **单一数据源**（body 状态决定块是否带参数），删除参数化 steps 自然失效，无失同步可能；不存字段
  顺带简化 add/update 签名与编辑器载入初始化
- **backward compat**：旧块（body 无 steps:null）→ 派生 false（无参数）；call 无 param → 无参数调用，
  与 v1.10 完全一致——**零迁移** ✅
- **参数上限**：`param: 1..9`（对齐 steps 参数 1-9；默认 3——中间值好观感）

**存取函数**：复用 v1.10 五函数（add/update/remove/get/load/save 不变，仅 body 加 steps:null 标记）。
新增 `blockHasParam(id)`（派生函数）。

### 2.2 块编辑器扩展（viewBlockEdit）

**布局新增**（名称行下）：
```
┌──────────────────────────────────┐
│ 名字: [______]（≤6字）            │
│ [🔢 带参数：走 N 步]  ← toggle（开启后 body 第一条 steps 变参数版） │
│ ┌── body 指令区 ──────────────┐ │
│ │ [1.↑ 2.➡N步(N) 3.↰]        │ │  ← 参数版 steps chip 显示 (N)
│ │ [+↑][+↰][+↱][+🧱][+➡N步]    │ │
│ └─────────────────────────────┘ │
│   [💾 保存]  [↺ 清空]  [‹ 取消]  │
└──────────────────────────────────┘
```

**交互**：
- `[🔢 带参数：走 N 步]` toggle（checkbox 按钮样式 active 态）：开 → `editBlockHasParam = true` +
  **自动把 body 第一条 steps 设为 `steps:null`**（若无 steps → 提示「先加一条 ➡N步」并保持 off）；
  关 → 参数化 steps 恢复固定（`steps:null` 的恢复为 `steps:1`）
- **toggle 状态从 body 派生**（B2）：编辑器载入已有块时 `editBlockHasParam = body.some(c => c.steps === null)`；
  **删除参数化 steps → toggle 自动 off**（其余参数化 steps 若有多处，全部恢复固定 steps:1；N1 多处参数化为后续增强）
- **body 参数化 steps chip**：`2.➡N步(N)`（区别于固定 `➡走3步`）；点击**不调参**（参数由调用方决定）——
  **I3：4 处 cycleSteps（块编辑 body/主序列/loop body/if 分支）加 `if (cmd.steps === null) return;` guard**（参数版 no-op，防 null→1 破坏标记）
- 保存：body 含 steps:null 即带参数（无需 hasParam 字段）；update/add 走现有函数

### 2.3 块选择面板 + 序列 chip（参数显示与调参）

**块选择面板**（renderBlockPicker）：
- 有参数块条目名显示 `🧩块名(N)`（N=默认 3）；body 预览参数版显示 `➡N步(N)`（I3：L1268 预览加 null 分支）
- 点击追加：`{id:'call', bid, name, param: blockHasParam(b.id) ? 3 : undefined}`（无参数块 param 不设）

**序列 call chip**（renderSeq）：
- 渲染：`🧩块名(N)`（有参数块显示参数；无参数块仅 `🧩块名`）
- **点击行为分流**（关键新交互）：
  - 有参数块：点击 → `cycleCallParam(i)`（参数 3→4→…→9→1→…→2→3 循环，对齐 cycleSteps 1-9）
  - 无参数块：点击 → viewBlockEditFromGame（v1.10 保留）
- 参数版 chip 视觉：`(N)` 用浅紫小字（`.call-param`），与块名区分——参数可调视觉暗示（N2 定义/调用显示分离为后续增强）

**cycleCallParam**：
```js
function cycleCallParam(i) {
  if (state.execLock) { return; }
  var cmd = state.cmds[i];
  if (!cmd || cmd.id !== 'call') { return; }
  if (!blockHasParam(cmd.bid)) { viewBlockEditFromGame(cmd.bid); return; }  // 无参数块走编辑
  cmd.param = ((cmd.param || 3) % 9) + 1;   // 3→4→…→9→1→…→2→3（1-9 循环）
  renderSeq();
}
```

### 2.4 执行器（execCall param 注入）

**核心洞察**：execCall 已把 body 对象数组 splice 进队列。参数化 steps 需要**运行时值**
（= call.param），但不能污染块库（body 是共享引用，多次调用不同参数需各自独立）。

```js
function execCall(cmd) {
  var def = getCustomBlock(cmd.bid);
  if (!def || !def.body || !def.body.length) { return; }
  // I-2 防递归校验（保持不变）
  ...
  resetLoopLeft(def.body);
  // v1.11：参数注入——为 body 生成"运行时副本"（参数化 steps 填 param，其余指令浅拷贝）
  var runBody;
  if (blockHasParam(cmd.bid)) {
    runBody = def.body.map(function (c) {
      var nc = { id: c.id };
      if (c.rep !== undefined) { nc.rep = c.rep; }
      if (c.id === 'steps') { nc.steps = (c.steps === null) ? (cmd.param || 3) : c.steps; }
      else if (c.steps !== undefined) { nc.steps = c.steps; }
      return nc;
    });
  } else {
    runBody = def.body;   // 无参数块：直接共享引用（v1.10 行为不变）
  }
  for (var i = 0; i < runBody.length; i++) { runBody[i]._execTop = cmd._execTop; }
  state.execQueue.splice.apply(state.execQueue, [state.queueIdx, 0].concat(runBody));
}
```

- **为何需运行时副本**：同一参数块被不同 call 以不同 param 调用——若直接改共享 body 的 steps，
  第一次展开 steps=2 执行，第二次展开前重置又 steps=5→共享对象被污染（且 execStep 的
  `_stepsLeft/_stepsMoved` 就近写在对象上，副本隔离更安全）。**map 浅拷贝 + 参数化赋新值**
  = 每 call 独立运行时指令对象（body ≤8 条，开销可忽略）
- **无参数块走原路径**（直接共享引用）→ 零回归
- **I2（Oracle 修订）**：`resetLoopLeft(def.body)` 对参数块是空操作（副本全新无执行期字段），
  对非参数块**必需**（B1 修复防跨 call 残留）——保留统一调用 + 注释说明（防后人误读）
- **副本 _execTop 设置正确性（Oracle 确认）**：execStep L1705 读 `cmd._execTop`，副本上设置即生效

**execStep steps 分支兼容**：参数化 steps 展开后就是普通 `{id:'steps', steps:N}`（N=param），
现有 steps 逐格动画/撞墙停逻辑**零改动** ✅。

### 2.5 totalSteps（星级口径，I1 采纳——统一走 totalSteps(bd.body)）

```js
} else if (c.id === 'call') {
  n += 1;
  if (!seenBlockIds[c.bid]) {
    seenBlockIds[c.bid] = true;
    var bd = getCustomBlock(c.bid);
    if (bd) { n += totalSteps(bd.body); }   // ★ 参数块/非参数块统一（I1 Oracle 修订）
  }
}
```

**I1 依据（Oracle 确认）**：`totalSteps` L1869 `else` 分支 `n += (c.rep || 1)` 已对 steps（含
`steps:null`）计 1（steps 无 rep → `undefined||1`=1）；body 仅基础指令（BLOCK_BODY_CMDS，
无 if/loop/call），`totalSteps(bd.body)` 与参数块手动计**逐项等价**（steps→1 / fwd→rep / 其他→1）
——无需 if(blockHasParam) 手动计分支，消除双路径 divergence 风险。

**激励论证**（同动作段不同距离场景，Oracle 确认 K≥2 成立）：
- 块「走N步再左转」body=[参数steps, left]，调用 2 次不同参数（2 和 5）：
  - 块写：2 call = `2×1 + body一次(1+1)` = 4 条
  - 展开写：steps2 + left + steps5 + left = 4 条——持平
  - 3 次调用（2/3/4）：块 = 3 + 2 = 5；展开 = 6 条 → 块优 ✅
- **关键**：参数块的价值 = 块计数不随参数数增长（body 仅计一次）；≥3 次调用复用显著优
- **N3 教学引导（Oracle 建议）**：K=1（纯 steps:null 单条参数块）无激励（1 call+1 body=2 vs 直接 steps=3 计 1）——
  文档/设计引导孩子做「走N步+转」类**多指令参数块**（K≥2 才有复用价值）

|---|---|

## 7. 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 参数注入污染块库（共享引用） | 中 | execCall 参数块走**运行时副本**（map 浅拷贝 + 参数化赋新值），块库 body 永不被写参数值；无参数块保持共享引用（v1.10 行为不变） |
| **hasParam 与 body 失同步（删除参数化 steps）** | **中** | **B2 修订：hasParam 派生（body.some(c.steps===null)），不存储字段——单一数据源，删除自然失效** |
| **blockListReturn 串扰（逃逸路径）** | **中** | **B1 修订：viewHome() 开头统一设 'home'（覆盖页头 home/首页卡片/任意逃逸）；mgrBtn 设 'game'；无 stale 可能** |
| 参数化 steps 点击破坏标记（null→1） | 低 | **I3 修订：4 处 cycleSteps 加 `if (steps===null) return;` guard** |
| 参数版显示误导（null 显示 1 步） | 低 | **I3 修订：2 处标签（块编辑 body chip/面板预览）加 null 分支显示 `➡N步(N)`** |
| 参数块星级激励不足（K=1 单条参数块无激励） | 低 | N3 教学引导：文档/设计引导「走N步+转」多指令参数块（K≥2 复用价值）；面板默认参数 3 + 调用次数无上限 |
| 参数范围误用（param=9 一步推太远） | 低 | 对齐 steps 1-9 上限（既有限制）；执行撞墙自动停（安全行为） |
| 旧块（无 steps:null）行为 | 低 | 派生 blockHasParam=false；call 无 param → 无参数路径完全一致；**零迁移** |
| click 分流混淆（参数 vs 编辑） | 低 | 参数块 chip 显示 `(N)` 视觉暗示；无参数块路径不变；文档说明 |
| totalSteps 双路径 divergence | 低 | **I1 修订：统一 `n += totalSteps(bd.body)`（Oracle 确认与手动计逐项等价），删手动分支** |
