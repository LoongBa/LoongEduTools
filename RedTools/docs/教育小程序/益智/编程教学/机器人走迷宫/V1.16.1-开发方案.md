## 1. 背景与目标

### 1.1 背景

v1.15（块体含 if）起块内 if 分支可放参数化 steps（`?₁`），v1.16（块内控制流嵌套）参数化 steps 可深至
if→loop→body。但**编辑态参数 toggle 的派生与批量操作函数不递归 if 分支**（v1.15 既有缺口，v1.16 放大）：

| 函数 | 递归 loop.body | 递归 if 分支 | 问题 |
|---|---|---|---|
| `scanParamSteps`（L104，执行派生） | ✅ | ✅ | 标准参照——递归已对齐 |
| `hasParamInBody`（L947） | ✅ | ❌ | `editBlockHasParam`（toggle UI）= false 而执行派生有参数 → UI 不一致 |
| `toggleStepsInArr`（L993） | ✅ | ❌ | toggle 批量操作漏覆盖分支内 steps |
| `hasStepsInArr`（L1001） | ✅ | ❌ | toggle ON 前置检查漏分支内 steps → 误报「先加一条 ➡N步」 |
| `toggleBlockHasParam`（L965） | ✅ | ❌ | OFF 恢复固定漏分支 / ON 检查+操作漏分支 |

**具体场景**：
- 块 `[if(then=[steps:null], else=[])]` → 执行派生参数（blockHasParam=true）但 toggle 显示 off（editBlockHasParam=false）
- 点 toggle ON → 只参数化顶层/loop.body steps，分支内 `?₁` 不变 → 操作后 UI 与实际仍不一致
- 点 toggle OFF → 分支内 `?₁` 不恢复固定 → 无法关闭
- toggle ON 前置检查（hasStepsInArr）→ 仅分支有 steps 时误报「先加一条 ➡N步」

### 1.2 目标

将 4 个 toggle 相关函数递归 if 分支，**完全对齐 scanParamSteps 的递归模式**（顶层 + loop.body + if.then/else），
消除编辑态 UI/批量操作与执行派生的不一致。无功能变更、无执行路径改动。

| 项 | 说明 |
|---|---|
| 范围 | 仅 4 个函数递归补 if 分支（每处 +2~3 行） |
| 不改 | execCall/cloneBlockBody/scanParamSteps/星级/存储/数据结构——执行路径零改动 |
| 版本 | **v1.16.1**（patch：bug fix——修复既有缺口，非新功能） |

## 2. 变更设计

### 2.1 `hasParamInBody`（编辑态参数派生，对齐 scanParamSteps）

```js
function hasParamInBody(arr) {
  for (var pi = 0; pi < arr.length; pi++) {
    var c = arr[pi];
    if (c.id === 'steps' && c.steps === null) { return true; }
    if (c.id === 'loop' && c.body && c.body.length && hasParamInBody(c.body)) { return true; }
    if (c.id === 'if') {   // v1.16.1：补 if 分支递归（I1 对齐 scanParamSteps）
      if (c.then && c.then.length && hasParamInBody(c.then)) { return true; }
      if (c.else && c.else.length && hasParamInBody(c.else)) { return true; }
    }
  }
  return false;
}
```

**效果**：`editBlockHasParam` 派生与 `blockParamCount`（scanParamSteps）一致——块 `[if(then=[steps:null])]` 保存后
再编辑，toggle 正确显示 on。

### 2.2 `toggleStepsInArr`（数组批量参数化/恢复固定，补 if 递归）

```js
function toggleStepsInArr(arr, toParam) {
  for (var i = 0; i < arr.length; i++) {
    if (arr[i].id === 'steps') {
      if (toParam && arr[i].steps !== null) { arr[i].steps = null; }
      else if (!toParam && arr[i].steps === null) { arr[i].steps = 1; if (arr[i].paramIdx !== undefined) { delete arr[i].paramIdx; } }
    } else if (arr[i].id === 'loop' && arr[i].body) { toggleStepsInArr(arr[i].body, toParam); }
    else if (arr[i].id === 'if') {   // v1.16.1：补 if 分支递归
      if (arr[i].then) { toggleStepsInArr(arr[i].then, toParam); }
      if (arr[i].else) { toggleStepsInArr(arr[i].else, toParam); }
    }
  }
}
```

### 2.3 `hasStepsInArr`（toggle ON 前置检查，补 if 递归）

```js
function hasStepsInArr(arr) {
  for (var i = 0; i < arr.length; i++) {
    if (arr[i].id === 'steps') { return true; }
    if (arr[i].id === 'loop' && arr[i].body && hasStepsInArr(arr[i].body)) { return true; }
    if (arr[i].id === 'if') {   // v1.16.1：补 if 分支递归
      if (arr[i].then && hasStepsInArr(arr[i].then)) { return true; }
      if (arr[i].else && hasStepsInArr(arr[i].else)) { return true; }
    }
  }
  return false;
}
```

### 2.4 `toggleBlockHasParam`（toggle 主循环，补 if 分支处理）

**OFF 分支**（原本 L968-973）：补 `else if (c.id==='if') → toggleStepsInArr(then/else, false)`：

```js
for (var i = 0; i < editBlockBody.length; i++) {
  if (editBlockBody[i].id === 'steps' && editBlockBody[i].steps === null) {
    editBlockBody[i].steps = 1;
    if (editBlockBody[i].paramIdx !== undefined) { delete editBlockBody[i].paramIdx; }
  } else if (editBlockBody[i].id === 'loop' && editBlockBody[i].body) { toggleStepsInArr(editBlockBody[i].body, false); }
  else if (editBlockBody[i].id === 'if') {   // v1.16.1
    if (editBlockBody[i].then) { toggleStepsInArr(editBlockBody[i].then, false); }
    if (editBlockBody[i].else) { toggleStepsInArr(editBlockBody[i].else, false); }
  }
}
```

**ON 分支 x2**（hasSteps 检查 L979-982 + 批量操作 L984-987）：补 if 处理：

```js
// hasSteps 检查：补 if 分支（hasStepsInArr 已递归 if——2.3 改后自动覆盖）
for (var j = 0; j < editBlockBody.length; j++) {
  if (editBlockBody[j].id === 'steps') { hasSteps = true; break; }
  if (editBlockBody[j].id === 'loop' && hasStepsInArr(editBlockBody[j].body)) { hasSteps = true; break; }
  if (editBlockBody[j].id === 'if' && ((editBlockBody[j].then && hasStepsInArr(editBlockBody[j].then)) ||
      (editBlockBody[j].else && hasStepsInArr(editBlockBody[j].else)))) { hasSteps = true; break; }   // v1.16.1
}

// 批量操作：补 if 分支（toggleStepsInArr 已递归 if——2.2 改后自动覆盖）
for (var k = 0; k < editBlockBody.length; k++) {
  if (editBlockBody[k].id === 'steps' && editBlockBody[k].steps !== null) { editBlockBody[k].steps = null; }
  else if (editBlockBody[k].id === 'loop' && editBlockBody[k].body) { toggleStepsInArr(editBlockBody[k].body, true); }
  else if (editBlockBody[k].id === 'if') {   // v1.16.1
    if (editBlockBody[k].then) { toggleStepsInArr(editBlockBody[k].then, true); }
    if (editBlockBody[k].else) { toggleStepsInArr(editBlockBody[k].else, true); }
  }
}
```

（注：ON 分支的 hasSteps 检查与批量操作均可简化为复用 hasStepsInArr/toggleStepsInArr 的递归，但因主循环逐元素
遍历 editBlockBody 顶层，if 元素需显式进入分支——保持现有结构 + 每处 +2 行，改动最小）

### 2.5 保留语义

- **I2 幂等保持**（v1.13）：ON 仅「未参数化 steps」→ 槽#0（已参数化含槽#1 保持不变）——分支内递归沿用
