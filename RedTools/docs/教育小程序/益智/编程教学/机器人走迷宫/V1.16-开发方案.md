## 1. 背景与目标

### 1.1 背景

v1.15 完成块体含 if（决策 A 单层：**if.then/else 仅基础指令 + 参数化 steps，不含 if/loop/call**——
分支添加行复用 `BLOCK_BODY_LOOP_CMDS`）。但**块内 if 分支仍不能放循环**——
「前方有墙则循环 N 次转向」这类**条件 × 循环复合动作**：

- 主序列已验证（v1.5+）：if 分支可嵌 loop（`loopDepth` 守卫 ≤2）——「有墙 → 绕行 N 步」关卡解法常见
- 块体场景仍缺：孩子想封装「遇墙绕行」块（`if 墙 → 循环 {转向 + 前进}`）会被添加行约束拦住

设计文档 §9 明确下一候选（最后一块块能力强化）：**块内控制流嵌套（if 内嵌 loop / 条件×循环）**。

**缺口**：块内 if 分支添加行 = `BLOCK_BODY_LOOP_CMDS`（基础 + 参数化 steps，无 loop）→ 条件内嵌循环无法在块内表达。

### 1.2 教学定位

| 版本 | 能力 | 教学价值 |
|---|---|---|
| v1.14 | 块体含 loop | 循环藏在块里（抽象 × 循环） |
| v1.15 | 块体含 if | 决策藏在块里（抽象 × 条件） |
| **v1.16** | **if 分支内嵌 loop** | **条件 × 循环嵌套**：真实函数体内「if 内含循环」——经典复合逻辑（扫雷式绕行、往返清扫、边界避障） |

- 教学叙事：主序列已验证「有墙绕行」（if+loop 组合，v1.5-v1.8）；v1.16 把这个**复合模式封进块**——
  孩子写「避开障碍」块 = `if 墙 → 🔁 循环 {↰ ↑}`，调用方只看 🧩名
- 与参数 × 条件嵌套叠加：分支内 loop.body 可含参数化 steps（`?₁`）→「有墙 → 走 `?₁` 步 × 循环」三维抽象

### 1.3 与既有能力关系（约束矩阵现状 → 目标）

**现状（v1.15 决策 A 单层）**：

| 位置 | 允许指令 |
|---|---|
| 块 body 顶层 | 基础 + loop + if |
| 块内 loop.body | 基础 + 参数化 steps（不含 if/loop/call） |
| 块内 if.then/else | 基础 + 参数化 steps（**不含 if/loop/call——决策 A**） |

**目标（v1.16 放开分支内 loop，其余保持）**：

| 位置 | 允许指令 | 变化 |
|---|---|---|
| 块 body 顶层 | 基础 + loop + if | — |
| 块内 loop.body | 基础 + 参数化 steps（不含 if/loop/call） | **保持单层** |
| 块内 if.then/else | 基础 + 参数化 steps + **loop**（不含 if/call） | **放开 loop** |

**边界决策**：分支内仅放开 loop（`BLOCK_BODY_BRANCH_CMDS = 基础 + 参数化 steps + loop`）；
分支内**仍禁 if/call**（防 if 嵌套 + 防递归——与 v1.15 保持）；分支内 loop 的 body 仍按 loop.body 规则
（不嵌 if/loop/call——**双层嵌套即封顶**：if → loop → 基础，孩子沿 v1.14/v1.15 线性路径学会，无第三层负担）。

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **条件 × 循环嵌套**：if 分支内可放循环（复合模式封装）；循环 body 仍线性（双层封顶） |
| 玩法 | 块内 if 编辑态分支添加行出现 🔁 循环 → 添加后进 loop 编辑态（次数调参 + body 编辑）→ 返回回 if 编辑态（来源记忆） |
| 合规 | 本地存储（同前）、无 PK/云同步；条件×循环 = 编程概念教学 |
| 范围 | 0 新关；不改主序列任何逻辑；存量块零迁移零回归；**块内 if 分支仍不嵌 if/call** |

## 2. 变更设计

### 2.1 数据模型（零迁移）

```js
// 块 body 指令新增用法：{ id:'if', then:[ {id:'fwd'}, {id:'loop', rep:2-9, body:[基础 ± 参数化 steps]} ], else:[...] }
//   嵌套约束：if.then/else 不嵌 if/call（编辑器不提供入口 + 保存校验 + 执行防御）
//             分支内 loop.body 不嵌 if/loop/call（loop 单层规则不变）
//   存储结构不变（customBlocks 数组透传，loop 是 if.then 内的子对象）
```

- backward compat：存量块（分支无 loop）→ 一切行为 v1.15 不变；新增能力仅向前
- **派生递归已覆盖（零改动）**：`scanParamSteps` 递归 if 分支 + loop.body（v1.14 防御性实现）→
  分支内 loop.body 的参数化 steps 自动计入 `blockParamCount` ✅
- **深拷贝已覆盖（零改动）**：`cloneBlockBody(paramCmd)` 统一递归入口——if.then/else → 每元素再走 loop 分支
  （`c.id==='loop' → body 递归拷贝 + 参数注入`）→ 分支内 loop 自动深拷贝 ✅
- **执行器已覆盖（零改动）**：`execCall` 副本路径用同一 `cloneBlockBody(def.body, cmd)`；
  共享引用路径（无参数块）execIf `splice.apply(展开)` 插入 branch（含 loop 对象）→ execStep 遇 loop → execLoop
  （resetLoopLeft + _execTop 继承已递归）✅
- **防递归已覆盖（零改动）**：`hasCallInBlock` 递归 if 分支 + loop.body（v1.14 I4）✅
- **重置已覆盖（零改动）**：`resetLoopLeft` 递归 if 分支 + loop.body ✅
- **星级已覆盖（零改动）**：`totalSteps` 递归 if（1+then+else）+ loop（1+body）✅
- **面板预览已覆盖（零改动）**：`pickerPreviewSpan` if 分支 buildBranch 内递归调用 → 分支内 loop 自动走 `.pv-loop` 摘要 ✅
  （仅需更新注释「单层约束下无嵌套」表述）

### 2.2 块编辑器扩展（核心改动 1：分支添加行放开 loop）

```js
// v1.15：var BLOCK_BODY_LOOP_CMDS = [CMD_FWD, CMD_L, CMD_R, CMD_BLOCK, CMD_STEPS];  // loop.body 添加行
// v1.16 新增：if 分支添加行 = 基础 + 参数化 steps + loop（不含 if/call——分支不嵌 if）
var BLOCK_BODY_BRANCH_CMDS = [CMD_FWD, CMD_L, CMD_R, CMD_BLOCK, CMD_STEPS, CMD_LOOP];
```

- `renderBlockBranchInBlock`（v1.15，L862）添加行 `BLOCK_BODY_LOOP_CMDS` → **换 `BLOCK_BODY_BRANCH_CMDS`**
- `addBlockBodyCmd`（v1.14 已有 loop 分支：`{ id:'loop', rep:2, body:[] }`）→ 分支添加行传 `arr`（then/else）
  走同一逻辑 ✅ 零改动
- **loop.body 添加行不变**（`BLOCK_BODY_LOOP_CMDS` 保持——loop 单层，不嵌控制流）

### 2.3 编辑态往返（核心改动 2：来源记忆——返回回 if 编辑态）

**B1/B2（Oracle 修订——返回/删除两处完整逻辑）**：

**现状问题**：块内 loop 编辑态（v1.14）返回按钮固定「‹ 返回块体」。分支内 loop 若复用同一编辑态，
返回会跳回块体顶层——丢失 if 上下文（需重新点 if chip 进分支）。

**方案：来源记忆（最小化，不改双状态结构）**

```js
// v1.16：loop 编辑态来源（null=从块体顶层进入；ifCmd 对象=从 if 分支进入）
var editBlockLoopFrom = null;
```

- **进入时记录（顺序关键）**：`renderBlockBodyChip` loop 点击分支（当前 L820-827）：
  ```
  editBlockLoopFrom = editBlockIfTarget;   // v1.16：必须在清空前捕获来源（Oracle 确认顺序）
  editBlockLoopTarget = cmd;
  editBlockIfTarget = null;                // v1.15 B1：双状态互斥（清空 if 编辑态）
  ```
  - 块体顶层进入时 editBlockIfTarget 为 null → from=null；if 分支内进入时非 null → from=该 if 对象
- **返回时恢复（B1 Oracle 修订——始终清 loopTarget）**：renderBlockEdit loop 分支「‹ 返回块体」按钮（L633）：
  ```js
  backBtn.addEventListener('click', function () {
    editBlockLoopTarget = null;   // B1：始终清（原方案漏清——renderBlockEdit L587 先查 loopTarget 会再进 loop 编辑态，核心功能失效）
    if (editBlockLoopFrom) { editBlockIfTarget = editBlockLoopFrom; editBlockLoopFrom = null; }   // 恢复 if 编辑态（双栏重渲染）
    renderBlockEdit();
  });
  ```
  - from 非 null → 恢复 if 编辑态（loop 编辑的对象就在分支数组内，位置保留）
  - from null → 原 v1.14 行为（回块体）
- **删除此循环按钮（B2 Oracle 修订——双路径定位 + from 恢复，完整 6 步）**：
  `editBlockLoopFrom` 存的是 if 对象引用；进入 loop 编辑态时 editBlockIfTarget 已被互斥清空——
  **必须用 editBlockLoopFrom（非 editBlockIfTarget，否则 null.then TypeError）**：
  ```js
  delBtn.addEventListener('click', function () {
    var removed = false;
    // ① 双路径定位：先扫 editBlockLoopFrom 的 then/else（by 引用 ===），未命中回退 editBlockBody 顶层
    if (editBlockLoopFrom) {
      var ifCmd = editBlockLoopFrom;
      for (var di = 0; di < (ifCmd.then||[]).length; di++) { if (ifCmd.then[di] === lp) { ifCmd.then.splice(di,1); removed = true; break; } }
      if (!removed) for (var di2 = 0; di2 < (ifCmd.else||[]).length; di2++) { if (ifCmd.else[di2] === lp) { ifCmd.else.splice(di2,1); removed = true; break; } }
    }
    if (!removed) { for (var di3 = 0; di3 < editBlockBody.length; di3++) { if (editBlockBody[di3] === lp) { editBlockBody.splice(di3,1); break; } } }
    // ② 清 loop 编辑态 + ③④ 恢复 if 编辑态（from 非 null）+ 清 from
    editBlockLoopTarget = null;
    if (editBlockLoopFrom) { editBlockIfTarget = editBlockLoopFrom; editBlockLoopFrom = null; }
    // ⑤ 参数派生刷新 ⑥ 重渲染
    editBlockHasParam = hasEditBodyParam();
    renderBlockEdit();
  });
  ```
  - 引用相等性：lp = editBlockLoopTarget 指向具体 loop 对象，=== 匹配唯一（多分支同名 loop 是不同对象，正确移除目标）
- **I2（Oracle）— if chip 进 if 编辑态强制重置来源**：L829-836 if chip click handler
  （设 `editBlockIfTarget = cmd; editBlockLoopTarget = null;`）应加 `editBlockLoopFrom = null;`（防御跨操作残留）
- **viewBlockEdit（L560-561）重置链**：补 `editBlockLoopFrom = null;`（进块编辑器全重置）
- **互斥保持**：进入 loop 编辑态仍清 `editBlockIfTarget = null`（双状态互斥）+ 设 `suppressChipClickUntil = 0`；

**三态往返流（Oracle 验证）**：
```
1. 块体 → 点 if chip → if 编辑态（ifTarget=ifCmd, loopTarget=null, from=null）
2. if 编辑态 → 点分支内 loop chip → loop 编辑态（loopTarget=loopCmd, ifTarget=null, from=ifCmd）
3. loop 编辑态 → 返回/删除 → if 编辑态（ifTarget=ifCmd, loopTarget=null, from=null）← B1/B2 修复后成立
4. if 编辑态 → 返回 → 块体（ifTarget=null）
```

### 2.4 嵌套校验（核心改动 3：hasIllegalNested 放宽分支 loop）

**现状（v1.15 修复版，L1020-1043）**：
- `hasIllegalNested`: loop.body 查 loop/if/call（顶层）；if.then/else 查 `hasForbiddenNested`（loop/if/call 全禁）
- `hasForbiddenNested(arr)`: 数组内查 loop/if/call

**v1.16 目标**：if 分支允许 loop，禁 if/call；分支内 loop 的 body 仍按 loop.body 规则（不嵌 if/loop/call）。

```js
// v1.16：分支数组顶层禁 if/call（loop 允许）；分支内 loop 的 body 递归校验（不嵌 if/loop/call）
function hasForbiddenNested(arr) {   // 语义调整：分支顶层禁 if/call + loop.body 递归（v1.15 全禁 → v1.16 放开 loop）
  for (var i = 0; i < arr.length; i++) {
    var c = arr[i];
    if (c.id === 'if' || c.id === 'call') { return true; }
    if (c.id === 'loop') {
      if (!c.body) { continue; }
      for (var j = 0; j < c.body.length; j++) {
        if (c.body[j].id === 'loop' || c.body[j].id === 'if' || c.body[j].id === 'call') { return true; }   // loop.body 单层校验
      }
    }
  }
  return false;
}
```

- 双重保险（v1.15 延续）：`doSaveBlock` 保存校验（hasIllegalNested）+ `hasCallInBlock` 执行时（已递归）✅
- 正常编辑入口已隔离（添加行不含 if/call）——校验仅兜底异常数据

### 2.5 既有缺口说明（I1 Oracle——hasParamInBody 等不递归 if 分支，归遗留）
