## 1. 背景与目标

### 1.1 背景

v1.10 自定义指令块以来（v1.10-1.13 四轮），块能力演进：抽象（命名复用）→ 块参数（单参）→ 参数贯穿（多参共享）→ 混合态/多参数数组（每步独立参数）——**参数维度已闭环**。但块体指令集仍被**决策 B** 限制：仅基础指令 fwd/left/right/block/steps（v1.10 设计，防递归 + 低龄线性），**不含 if/loop/call**。

设计文档 §9 明确下一候选：**块体含 loop（不含 if/call，控制流抽象渐进）**——孩子把带循环的动作段封装成命名块（如「走 N 步 ×3 次」「绕障碍转圈」），抽象 × 循环组合（Scratch 自定义块内嵌循环等价）。

**缺口**：块体内不能放 🔁 循环块 → 「走三步→转→重复」类模式必须每次展开写（无法封装）。同时 V1.13 审核报告 N2 遗留：面板预览中固定/参数/循环无视觉区分（纯文本），低龄难辨「哪步可调」。

### 1.2 教学定位

- v1.7 主序列 🔁 循环：**循环 = 自动化**（一组指令重复 N 次）
- v1.10-v1.13 块能力：**抽象 = 命名复用 + 参数化**
- **v1.14 组合**：**循环 × 抽象**——「把循环封装成块，调用时还能调参数」：
  ① 块体含 loop：「走 N 步×M 次」类**模式单元**封装成块（循环藏在块里，调用方只看到 🧩名）；
  ② **参数 × 循环嵌套**：loop body 内放参数化 steps（`?₁`）→ 块「走 ?₁ 步 ×3 次」调用传 2 走 2×3、传 5 走 5×3——**循环次数 + 步数双维度抽象**
- 教学价值：孩子理解「块可以包含控制结构」——抽象不仅封"直线段"，还能封"带流程的动作段"（真实函数体内含循环）

### 1.3 与既有能力关系

| 项 | v1.13 | v1.14 |
|---|---|---|
| 块体指令集 | fwd/left/right/block/steps（决策 B） | **+ loop（单层，不含 if/嵌套 loop/call）** |
| blockHasParam/blockParamCount 派生 | 仅扫顶层 body（steps:null） | **递归 loop.body**（loop.body 内参数化 steps 也计入——B1 Oracle 修订） |
| 执行 | execCall 参数块副本 / 无参块共享引用 | **needsCopy = blockHasParam（递归版）**——参数块副本含 loop.body 递归拷贝 + 参数注入递归；无参无参化块共享引用（v1.10 零回归） |
| 星级 totalSteps | call 1+body 一次；loop 递归 | **零改动**（totalSteps 已递归 loop.body） |
| 块编辑器 | 单栏 body chips | + 🔁 添加按钮 + 块内 loop 编辑（展开式）+ loop.body 参数化 steps |
| 面板预览 | 纯文本 join（固定/参数无视觉区分） | **span 拼接视觉标记**（N2：固定灰/参数紫/loop 灰框） |
| 防递归 | I-2：body 含 call 终止 | **扩展**：hasCallInBlock 递归 loop.body/if.body/if.alt（I4） |

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **循环 × 抽象组合**：块可含控制结构（循环藏在块内）；参数×循环双维度（走 ?₁ 步 ×N 次） |

## 2. 变更设计

### 2.1 数据模型（块 body 扩展，向后兼容零迁移）

```js
// 块 body 新增指令：{ id:'loop', rep: 2-9（对齐主序列 loop 2-9）, body: [...] }
//   loop.body 指令集 = 基础指令（fwd/left/right/block/steps 含参数化 steps:null+paramIdx）
//   单层约束：loop.body 不嵌 loop/if/call（编辑器入口不提供 + 保存校验兜底，I2）
// call/星级/存储结构不变（loop 是其 body 子对象，customBlocks 数组透传）
```

- **backward compat**：存量块 body 无 loop → 一切行为 v1.13 不变（零迁移；新编辑器能力仅向前）
- **派生函数递归化（B1 Oracle 修订——关键）**：v1.13 blockHasParam/blockParamCount 仅扫顶层 body。
  **v1.14 块内含 loop 后，loop.body 内也可能有参数化 steps（steps:null）**——派生必须递归：
  ```js
  // blockParamCount 递归版（顶层 + loop.body 递归，I3 undefined→0 / I4 clamp 2 逻辑不变）
  function scanParams(arr, counter) {   // counter: {maxIdx:0, hasNull:false}
    for (var i = 0; i < arr.length; i++) {
      var c = arr[i];
      if (c.id === 'steps' && c.steps === null) { counter.hasNull = true; counter.maxIdx = Math.max(counter.maxIdx, c.paramIdx || 0); }
      else if (c.id === 'loop' && c.body && c.body.length) { scanParams(c.body, counter); }
    }
  }
  ```
  **理由（B1）**：若 loop.body 内 steps:null 未计入派生 → blockHasParam=false → execCall 走共享引用 →
  参数化 steps 不被解析 → 执行 null 崩溃。**派生递归 + needsCopy=blockHasParam（递归版）** 闭环。
- **blockHasLoop 派生**：`body.some(c => c.id==='loop')`（仅顶层判断，loop 不嵌套）——文档/教学用，非执行判定
- **上限**：loop.body 指令数 ≤ MAX_BODY（8）；loop rep 2-9

### 2.2 块编辑器扩展（🔁 添加 + 块内 loop 编辑）

**添加行**（renderBlockEdit addRow）：`BLOCK_BODY_CMDS` 增加 `CMD_LOOP`（🔁循环）→ 添加 `{id:'loop', rep:2, body:[]}`
（MAX_BODY 计数不变——loop 计 1 条顶层指令，loop.body 内部指令另计 ≤8）。

**块内 loop 编辑（展开式，独立于主序列 editCtx——块编辑器是独立视图）**：
- loop chip 渲染：`N.🔁×M`（浅灰底 `.loopb`，对齐主序列 loop chip 视觉）+ 右上 ✕（删除整个 loop）
- **点击 loop chip → 块编辑器切换为「loop 编辑态」**：
  ```
  🧩 编辑块：<块名>  →  🔁 重复 M 次（− 次数 / + 次数，2-9）
  [1.↑ 2.➡?₁步 3.↰]        ← loop.body 指令 chips（复用 renderBlockBodyChip 同款：固定 steps 单击调数/参数化单击切槽位/长按固定⇌参数）
  [+↑][+↰][+↱][+🧱][+➡N步]   ← 添加行（基础指令 + 参数化 steps 入口；不含 if/loop/call——单层约束 I2 入口隔离）
  [‹ 返回块体]  [✕ 删除此循环]
  ```
- **状态**：`editBlockLoopTarget = null | loop 对象引用`（renderBlockEdit 分支渲染；返回块体置 null 重渲染）
- **loop.body chips 复用 renderBlockBodyChip**（循环遍历 loop.body；i 为 loop.body 内下标）——长按/槽位/去抖复用
- **次数调参**：复用主序列 loop rep 调参逻辑（2-9 步进）
- **I1 修订（去抖标志隔离）**：进入 loop 编辑态时显式 `suppressChipClickUntil = 0`（防块体编辑残留去抖吞掉
  loop.body 首次单击）；loop.body 参数化 steps 的 paramIdx 指向**顶层块参数槽位**（loop 无独立参数，
  renderBlockBodyChip 参数源统一从顶层块上下文取，不因 loop 编辑态切换）

**深拷贝（B3 Oracle 修订——统一递归逐字段复制）**：viewBlockEdit 深拷贝**递归 loop.body**，
对每条指令（含 loop.body 内）逐字段复制 id/rep/steps/paramIdx——不做顶层/loop.body 特殊区分：
```js
function cloneBlockBody(arr) {   // 统一递归（顶层 body / loop.body 同用）
  return (arr || []).map(function (c) {
    var nc = { id: c.id };
    if (c.rep !== undefined) { nc.rep = c.rep; }
    if (c.steps !== undefined) { nc.steps = c.steps; }
    if (c.paramIdx !== undefined) { nc.paramIdx = c.paramIdx; }
    if (c.id === 'loop') { nc.body = cloneBlockBody(c.body); }   // 递归 loop.body（B3）
    return nc;
  });
}
```
（blockNameTaken/update/save 无需特殊处理——update/save 整体替换 def.body，缓冲区已深拷贝 ✅ Oracle 确认）

### 2.3 执行器（execCall 参数注入递归）— B1/B2 修订

**B1 修订（Oracle——撤销 `_loopLeft` 污染推理，needsCopy 收窄）**：
v0.1 称「含 loop 块无条件副本（防 _loopLeft 跨 call 污染）」——**推理错误**：顺序队列执行器
同一指令对象不可能同时在队中出现两次（无递归/无并发；第一次 call body 完全出队消费后才触发第二次 call；
execStep 每次执行 `cmd._loopLeft = cmd.rep || 1` 重新初始化）→ **不存在 _loopLeft 跨 call 污染**。

**副本的真正必要性 = 参数注入**（loop.body 内 steps:null 需按 call 参数解析，shared body 会被污染或丢失解析）：
```js
function execCall(cmd) {
  ...
  // B1 修订：needsCopy = blockHasParam（递归版——loop.body 内参数化 steps 也计入）
  // 无参数无参数化块 → 共享引用（v1.10 零回归保持，含 loop 但无参数化 steps 的块走共享）
  if (blockHasParam(cmd.bid)) {
    runBody = def.body.map(function (c) {
      if (c.id === 'loop') {
        var nl = { id: 'loop', rep: c.rep, body: (c.body || []).map(function (b2) {
          var nb = { id: b2.id };
          if (b2.rep !== undefined) { nb.rep = b2.rep; }
          if (b2.steps !== undefined) { nb.steps = resolveStep(cmd, b2); }   // B2：拷贝时同步解析
          if (b2.paramIdx !== undefined && b2.steps !== null) { nb.paramIdx = b2.paramIdx; }
          return nb;
        }) };
        return nl;
      }
      ...（现有单层指令复制 + resolveStep）
    });
  } else {
    runBody = def.body;   // 共享引用（v1.10 零回归）
  }
  ...
}
```
- **B2（Oracle）**：resolveStep 提取为**独立函数**（B2 槽位回退链 `params[slot] → (slot===0? param||3 : 3)`），
  execCall 对顶层 body 与 loop.body 统一调用——**参数解析集中于 execCall**，execLoop 保持「只管插队 +
  resetLoopLeft」的纯粹职责（主序列 loop/块内 loop 共用 execLoop，不感知块参数）
- **B1 前提验证（§4.2 #2）**：确认 execStep 对共享 body steps:null 的解析路径——由于派生递归后
  任何含 steps:null 的块（含 loop.body）必走副本，共享引用路径**永不含 steps:null** → 解析变异问题
  天然规避（共享块无参数化，无需解析）✅
- **I-2 防递归扩展（I4 Oracle）**：`hasCallInBlock` 递归检查 loop.body / if.body / if.alt
  （块体无 if 但异常数据可能混入——防御性，与 v1.10 I-2「异常数据终止」定位一致）
- **execCall 的 resetLoopLeft**：副本全新无执行期字段（I2 空操作注释沿用）；共享引用路径保留（无参块必需）

### 2.4 星级 totalSteps（零改动确认 + 激励示例表 I3）

totalSteps 已递归 loop（`c.id==='loop' → n += 1 + totalSteps(c.body)`）✅ 块体 loop 自动计入；
call 计 1 + body 一次（seenBlockIds）不乘参数数/循环数 ✅；loop.body 参数化 steps 经 `c.rep||1` 计 1 ✅。

**I3 激励示例表**（「走 3 步 ×2 次」模式，教学引导 N3 类比数据支撑）：

| 写法 | totalSteps | 实际执行步数 | 激励 |
|---|---|---|---|
| 块内直接 6×fwd | 1(call) + 6 = 7 | 6 | baseline |
| 块内 loop rep:2 body:[fwd×3] | 1(call) + 1(loop) + 3 = 5 | 6 | ✓ 块优（5 < 7） |
| 块内 loop rep:6 body:[fwd] | 1(call) + 1(loop) + 1 = 3 | 6 | ✓ 显著优（3 < 7） |

- 教学目标 = **循环 = 自动化**（v1.7 主序列同款激励：写少 → 星级高），块内 loop 延续此口径
- **阈值检查**：现有星级阈值按关内 best b 定，loop 块 totalSteps 更低 → 更易 3★（偏宽松）。
  教学初期**可接受偏松**（鼓励孩子用循环抽象）；如后续出现「全关用 loop 无脑 3★」再评估收紧（N1 记录）

### 2.5 面板预览视觉标记（N2 收尾）

**现状**：renderBlockPicker 预览 `b.body.map(...).join(' ')` 纯文本——固定 `➡2步` / 参数 `➡?₁步` /
loop `🔁×2` 无视觉区分（V1.13 审核报告 N2）。

**v1.14 设计**：预览从纯文本改为 **span 拼接**（每指令一个 span，CSS 类区分）——
| 指令类型 | 预览 span | class |
|---|---|---|
| 固定 steps | `➡2步` | `.pv-steps`（灰底） |
| 参数化 steps | `➡?₁步` / `➡?₂步` | `.pv-param`（浅紫底，同参数主题） |
| fwd/left/right/block | `↑`/`↰`/`↱`/`🧱` | `.pv-base`（无底） |
| loop | `🔁×2{...}`（body 摘要同规则） | `.pv-loop`（浅灰框） |
- 实现：renderBlockPicker 预览 map 返回 span 元素（appendChild + 空格分隔）；loop 预览递归 body 摘要
  （≤3 条截断 + `…` 防溢出——N2 兼容：span/className/textContent/appendChild 均 DOM Core L1，Chrome 1+ ✅）

### 2.6 范围与边界

- 0 新关；不改主序列 loop/if/call 任何逻辑；不改关卡/结算/存储
- **单层约束（I2）**：**编辑器入口隔离为主**（loop.body 添加行仅基础指令 + 参数化 steps——用户无创建嵌套入口）
  **+ 保存校验兜底**（doSaveBlock 校验 loop.body 不含 loop/if/call，异常数据拒绝保存 + 提示）
  + 执行层 hasCallInBlock 防御（I4，异常数据终止）——三层
- **存量块**：body 无 loop → 共享引用路径不变（v1.13 已验证回归）
- **Chrome 61**：无新 API（复用现有 makeEl/appendChild/addEventListener）
