## 1. 背景与目标

### 1.1 背景

走迷宫已完成编程核心概念六块闭环：顺序（v1.0）→ 循环（v1.1 隐式 chip ×N）→ 条件（v1.3）→ 调试（v1.4）→ 分支（v1.5 if）→ 参数化（v1.6 steps）。
v1.7 引入**显式循环块**（`🔁 重复 N 次 {组指令}`）——一组动作重复做（区别于 v1.1 单动作 ×N），
且**循环块内可嵌 if/steps/前进**——教学编程核心的**控制结构组合**（循环 + 分支 + 参数叠加）。

### 1.2 与既有机制的关系

| 机制 | 版本 | 语义 | 与 v1.7 关系 |
|---|---|---|---|
| `cmd.rep`（chip ×N） | v1.1 | 单条指令重复 N 遍（隐式循环启蒙） | **保留**（单动作循环） |
| `🔁 循环块`（显式） | **v1.7** | **一组指令**重复 N 次（显式循环块，结构教学） | **新增**（组动作循环） |
| `❓ if前方有墙` | v1.5 | 条件分支 | **循环块内可嵌**（组合） |
| `➡ 走N步` | v1.6 | 参数化移动 | **循环块内可嵌**（组合） |

**教学定位**（对齐 D5 循环指令）：
- v1.1 `×N` = 一个动作重复做（重复 = 机械复制）
- v1.7 `🔁 循环块` = **一组动作**重复做（循环 = 自动化/抽象）
- **循环块内嵌 if/steps** = 控制结构组合（循环里判断、循环里参数化）——编程进阶核心

### 1.3 与 D5「循环指令」的区别

D5 是**独立工具**专训循环（走廊 + 显式循环块 + 编写量星级），body 仅含简单动作（无 if/steps）。
走迷宫 v1.7 是**在走迷宫内**引入循环块并支持**内嵌 if/steps**（组合控制结构），
教学进阶是"循环块内嵌分支/参数"——D5 未覆盖组合场景。

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **显式循环块** + **控制结构组合**（循环内嵌 if/steps/前进） |
| 玩法 | `🔁 循环` 指令：点击后循环次数 2→3→4→5→2（区别 rep 的 1→4）；块内可加指令（editCtx 模式） |
| 合规 | 有标准答案（循环次数确定 → 执行确定 → 盘面判定），合规安全区 |
| 合规红线 | 不引入 PK/排行榜；循环块是编程教学（自动化思想），非"爽快"玩法 |

## 2. 变更设计

### 2.1 新增指令：`🔁 循环`（CMD_LOOP）

**指令**：`🔁 循环`（label 动态显示：`🔁 ×3`）

**数据结构**：
```js
var CMD_LOOP = { id: 'loop', label: '🔁循环' };
// state.cmds 中：{ id:'loop', rep:2, body:[指令对象数组] }
// body 内可含：fwd/left/right/block/steps/if（v1.7 组合控制结构）
// body 内禁 loop（MVP 单层，D5 同款限制）；body 内 if 可嵌套 ≤2 层（同 v1.5）
```

**交互**（复用 v1.5 editCtx 模式 + D5 循环块编辑）：
- 点击指令区 `🔁循环` 按钮 → 追加 `{id:'loop', rep:2, body:[]}` 到序列（不自动展开）
- 点击序列 loop chip → **打开循环编辑区**（editCtx 扩展：单栏 body 编辑 + 次数调参）
- 编辑区内：循环次数调参（2→3→4→5→2）+ body 指令增删（可加 ↑/↰/↱/🧱/➡N步/❓if）
- body 内 if 点开 → 再展开嵌套 if 编辑（同 v1.5，if 深度 ≤2）
- ✕ 删除同其他指令（loop 需确认）

**循环次数**：rep 字段（2→3→4→5→2，起始 2——1 次无意义，D5 同款）

### 2.2 执行器扩展（Oracle B1/I3 修订：复用 rep-on-cmd + 轮间状态重置）

**设计决策（Oracle 确认）**：loop 轮数**复用现有 rep-on-cmd 机制**（`_loopLeft` 处理，execStep 开头对 loop 已正确回插 rep 次），
execLoop 只负责**插入 body**（不碰 `_loopLeft`，职责单一）。删除 v0.1 第一版（自管 `_loopLeft` 双重递减）。

**execStep 分发**（rep 块之后）：
```js
else if (cmd.id === 'loop') {
  execLoop(cmd);   // 仅插入 body（轮数已由 rep-on-cmd 处理）
}
```

**execLoop（含 Oracle B1 修复：轮间状态重置 + I-new 修复：_execTop 无条件覆盖）**：
```js
/* v1.7 显式循环块：body 指令插入队首（轮数由 rep-on-cmd 处理） */
function execLoop(cmd) {
  if (!cmd.body || !cmd.body.length) { return; }
  // B1 修复：轮间重置 body 执行期状态（共享引用反复入队会残留 _loopLeft/_stepsLeft，
  // 若不清除，第 2 轮起 body 内 rep>1 的 fwd 只走 1 次、steps 只走 1 格）
  resetLoopLeft(cmd.body);
  // body 指令继承父级 loop 的顶层下标（高亮/失败定位）
  // I-new 修复：无条件覆盖（与 execIf F1 一致）——防跨轮残留旧 _execTop
  // （execRun 仅重置顶层 cmds 的 _execTop，不触及 loop.body 内指令，
  //   若用户在两次运行间编辑改变 loop 顶层索引，条件赋值会跳过更新 → 失败定位错位）
  for (var i = 0; i < cmd.body.length; i++) {
    cmd.body[i]._execTop = cmd._execTop;
  }
  state.execQueue.splice.apply(state.execQueue,
    [state.queueIdx, 0].concat(cmd.body));
}
```

**resetLoopLeft 扩展（Oracle B1 依赖）**：
```js
function resetLoopLeft(cmds) {
  for (var i = 0; i < cmds.length; i++) {
    var c = cmds[i];
    c._loopLeft = undefined;
    c._stepsLeft = undefined;
    c._stepsMoved = undefined;
    if (c.id === 'if') {
      if (c.then && c.then.length) { resetLoopLeft(c.then); }
      if (c.else && c.else.length) { resetLoopLeft(c.else); }
    } else if (c.id === 'loop' && c.body) {
      resetLoopLeft(c.body);   // ← 新增：递归 loop.body
    }
  }
}
```

**队列状态推演（loop rep=2, body=[fwd×3]，带 B1 修复）**：
- 轮 1：execLoop 重置 body → fwd._loopLeft=undefined。插入 fwd@queueIdx。rep-on-cmd：undef→3→2 回插、2→1 回插、1→0 不回插 → fwd 执行 3 次 ✓
- 轮 2：execLoop **重置 body** → fwd._loopLeft=undefined（清轮 1 残留）。插入 fwd。rep-on-cmd：undef→3→2→1→0 → fwd 执行 3 次 ✓
- **修复生效**：body=[fwd×3] 或 [steps走3步] 每轮都完整执行

### 2.3 editCtx 扩展（Oracle I2/I5 修订：type 字段 + if 深度守卫）

**editStack 栈帧扩展**：`{ type:'if'|'loop', topIdx, cmd }`（对齐现有 editStack 数组结构）：
- type='if' → 双栏 then/else 编辑（现有逻辑不变）
- type='loop' → 单栏 body 编辑 + 循环次数调参（新增）

**if 深度守卫（Oracle I2 修订）**：现有 `editStack.length >= 2` 限制 if 嵌套 2 层——但 v1.7 下 loop 是 level 0，
body 内 if 进 level 1 即被拦。守卫改为**按 if 类型计数**：
```js
function ifDepth() {
  var n = 0;
  editStack.forEach(function (e) { if (e.cmd && e.cmd.id === 'if') { n += 1; } });
  return n;
}
// openNestedEditCtx / renderBranchCol 的 +if 按钮内：
if (ifDepth() >= 2) { /* ⚠ 分支嵌套最多 2 层 */ return; }
```
这样 loop(0)→if(1)→if(2) 才会被拦，body 内 if 可嵌套 2 层（与 v1.5 顶层 if 等价）。

**loop 编辑区渲染**（renderEditCtx 扩展）：
```
🔁 循环 ×N — 循环编辑
[次数: − 3 +]（或点击 chip 递增 2→3→4→5→2）
[body 指令 chips：1.↑ 2.➡走3步 3.❓if]
[+↑][+↰][+↱][+🧱][+➡N步][+❓if]
[关闭]
```
- body 内 if chip 点开 → openNestedEditCtx（栈 +if 帧，ifDepth 守卫）
- body 内步骤 chip 点 → cycleSteps；普通 chip 点 → cycleRep；✕ 删除

### 2.5 星级计算（Oracle I4 修订：递归口径）

**totalSteps 扩展**：
```js
function totalSteps(cmds) {
  var n = 0;
  cmds.forEach(function (c) {
    if (c.id === 'if') {
      n += 1;
      n += (c.then ? totalSteps(c.then) : 0) + (c.else ? totalSteps(c.else) : 0);
    } else if (c.id === 'loop') {
      n += 1 + (c.body ? totalSteps(c.body) : 0);   // 递归 body（body 内 if 同口径 1+then+else）
    } else {
      n += (c.rep || 1);
    }
  });
  return n;
}
```
> ⚠️ 注意：v1.5 的 totalSteps 对 if 用 `c.then.length`（不递归），v1.7 改为**递归 totalSteps**——
> 等价条件：then/else 内命令 rep 均为 1（或无 rep）时 `1+length == 1+递归 length`（等价）。
> 若 then/else 内存在 rep>1 命令（如 then=[fwd×3]：v1.5 计 1，v1.7 计 3），值会变化——
> 需回归确认 v1.5 关卡星级无漂移（v1.5 分支内大概率无 rep>1，§4.1 回归覆盖）。

**星级**：186-195 新关 b = 含循环块最优编写量；`totalSteps <= b*1.5 → 3★`（展开写 ≥1.5×b 封顶 2★，激励循环块）。

## 5. 风险与对策（Oracle S 级补全）
