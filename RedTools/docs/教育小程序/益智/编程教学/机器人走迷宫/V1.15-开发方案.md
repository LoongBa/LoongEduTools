## 1. 背景与目标

### 1.1 背景

v1.14 完成块体含 loop（决策 B 部分放开：块 body 可含 🔁 循环）。但**块体仍不含 if 条件分支**——
主序列的 `❓ if前方有墙`（v1.5 成熟：then/else 双栏 + 嵌套 ≤2 层 + execIf 求值）无法被封装进块。
设计文档 §9 明确下一候选：**块体含 if（条件抽象渐进）**——孩子把「前方有障碍 → 转向」类**决策段**封装成命名块。

**缺口**：块内不能放 `❓ if` → 「探测+分支」逻辑无法复用（每关重复写）。Scratch 自定义块内嵌条件块是
常见模式（如「避开障碍」块：if 墙 → 转方向）。v1.14 已把基础铺好（scanParamSteps/hasCallInBlock 已递归 if，
v1.15 仅需：块编辑器 if 支持 + 块内 if 编辑态 + execCall if 分支拷贝注入 + 嵌套边界）。

### 1.2 教学定位

- v1.5 主序列 if：**条件分支 = 决策**（前方探测 → then/else 二选一）
- v1.14 块体含 loop：**循环 × 抽象组合**（循环藏在块里）
- **v1.15 块体含 if**：**条件 × 抽象组合**——「探测+决策」段封装成块（决策藏在块里，调用方只看 🧩名）：
  ① 块内 if：「避开障碍」块 = if 墙 → 转向（决策逻辑复用）；
  ② **参数 × 条件嵌套**：if 分支内放参数化 steps（`?₁`）→ 块「前方有墙则走 ?₁ 步绕开」调用传 2 走 2 格——
  **条件 + 参数双维度抽象**
- 教学价值：孩子理解「块可以包含决策结构」——抽象不仅封"直线段/循环段"，还能封"带判断的动作段"
  （真实函数体内含 if）

### 1.3 与既有能力关系

| 项 | v1.14 | v1.15 |
|---|---|---|
| 块体指令集 | 基础 + loop（单层） | **基础 + loop + if（顶层）** |
| 块内 if 编辑 | — | **双栏 then/else（复用 .block-edit-row/.block-edit-col 布局 + renderBlockBodyChip 三态交互）** |
| if 分支内指令 | — | **基础指令 + 参数化 steps（不含 if/loop/call——决策 A）** |
| execCall | loop.body 递归拷贝 + 参数注入 | **+ if 分支递归拷贝 + 参数注入**（resolveStep 统一，I2 路径 1） |
| scanParamSteps | 递归顶层 + loop.body + if（防御性已有） | **零改动**（已递归 if 分支——v1.14 铺路） |
| hasCallInBlock | 递归 loop.body + if | **零改动**（已递归 if——v1.14 铺路） |
| 星级 totalSteps | 已递归 if（1+then+else） | **零改动** |
| 块内 loop | loop.body 仅基础（不含 if——v1.14 单层） | **保持**（loop.body 不嵌 if；if 分支不嵌 loop——对称约束） |

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **条件 × 抽象**：块可含决策结构（探测藏在块内）；参数×条件嵌套（前方有墙则走 ?₁ 步） |
| 玩法 | 块编辑器可加 ❓ if → 点击进入块内 if 编辑（then/else 双栏 + 参数化 steps）；块内 if 分支不嵌 if/loop/call（低龄线性） |
| 合规 | 本地存储（同前）、无 PK/云同步；条件+抽象 = 编程概念教学 |
| 范围 | 0 新关；**块内 if 单层**（if 分支不嵌 if/loop/call，决策 B 精神延续）；不改主序列 if/loop 任何逻辑；存量块零迁移零回归 |

## 2. 变更设计

### 2.1 数据模型（块 body 扩展，向后兼容零迁移）

```js
// 块 body 新增指令：{ id:'if', then:[基础指令 ± 参数化 steps], else:[同] }
//   单层约束：if.then/if.else 不嵌 if/loop/call（编辑器不提供入口 + 保存校验 + 执行防御——I2 三层同 v1.14）
//   块内 loop.body 仍不嵌 if（v1.14 单层保持）；块内 if 分支不嵌 loop（对称约束——决策 A）
// call/星级/存储结构不变（if 是 body 子对象，customBlocks 数组透传）
```

- **backward compat**：存量块 body 无 if → 一切行为 v1.14 不变（零迁移；新编辑器能力仅向前）
- **派生递归**：scanParamSteps **已递归 if.then/if.else**（v1.14 防御性实现）→ blockHasParam 自动覆盖 if 分支内参数化 steps ✅ 零改动
- **防递归**：hasCallInBlock **已递归 if 分支**（v1.14 I4）→ 块内 if 分支含 call（异常数据）终止 ✅ 零改动

### 2.2 块编辑器扩展（❓ 添加 + 块内 if 编辑态）— B1 修订：双状态，不泛化

**B1（Oracle 修订——双状态替代泛化）**：v0.1 拟将 `editBlockLoopTarget` 泛化为 `editBlockEditTarget = {type,cmd}`。
**修订：保留 `editBlockLoopTarget`（v1.14 已发布 tag 零改动）+ 新增 `editBlockIfTarget`**——
- 双状态互斥天然（同一时刻只编辑一个块内控制流）；互斥保证 = 进入一方时清空另一方（`editBlockLoopTarget = editBlockIfTarget = null` 统一在 viewBlockEdit 重置 + 进入 if 编辑态清 loopTarget / 反之）
- renderBlockEdit 新增 if 分支（`if (editBlockIfTarget) { renderBlockEditIf(); return; }`），**不触碰 loop 分支**（v1.14 逻辑零改动）
- 设置点分两处（loop chip 设 loopTarget；if chip 设 ifTarget）——回归风险最小（已发布 tag 稳定性优先）
- I1 去抖重置：进入任一编辑态均 `suppressChipClickUntil = 0`（双状态各清一次，机械安全）

**添加行**（renderBlockEdit addRow）：`BLOCK_BODY_CMDS` 增加 `CMD_IF`（❓if墙）→ 添加 `{id:'if', then:[], else:[]}`

**块内 if 编辑态**：
- if chip 渲染：`N.❓if`（紫色 `.if`，对齐主序列 if chip 视觉）+ 右上 ✕（删除整个 if）
- **点击 if chip → 块内「if 编辑态」**（renderBlockEditIf 分支）：
  ```
  🧩 编辑块：<块名>  →  ❓ if前方有墙 — 分支编辑
  ┌── ✅ then（有墙） ───┐  ┌── ❌ else（无墙） ──┐
  │ [1.↑ 2.➡?₁步]      │  │ [1.↰]             │
  │ [+↑][+↰][+↱][+🧱][+➡N步] │  │ [+↑][+↰][+↱][+🧱][+➡N步] │   ← 添加行 = BLOCK_BODY_LOOP_CMDS 复用（I2 入口隔离）
  └────────────────────┘  └───────────────────┘
  [‹ 返回块体]  [✕ 删除此 if]
  ```
- **双栏渲染**：新增 `renderBlockBranchInBlock(type, label, arr)`——复刻主序列 renderBranchCol 布局
  （双列 .block-edit-row + 每列 .block-edit-col + chips + 添加行），**不引入新 class**（I1 Oracle）；
  目标数组 = `editBlockIfTarget.then` / `.else`；chips 复用 renderBlockBodyChip（三态交互，参数化 ?₁ 可放 if 分支内）
- **添加行复用 BLOCK_BODY_LOOP_CMDS**（基础 + 参数化 steps，不含 if/loop/call——I2 入口隔离），不新定义（I1）
- **I1 去抖隔离**：进入 if 编辑态显式 `suppressChipClickUntil = 0`

**深拷贝（B3 Oracle 修订——统一入口）**：cloneBlockBody 补 if 分支递归；**cloneBranchWithParams 为其子函数**（处理 then/else 拷贝 + resolveStep 注入），调用关系图：
```
execCall → cloneBlockBody（副本路径统一入口）
            ├── loop.body 递归（v1.14）
            └── if.then/else → cloneBranchWithParams（v1.15 新增：逐字段拷贝 + steps:null → resolveStep）
viewBlockEdit 深拷贝 → cloneBlockBody（无参数注入——resolveStep 仅执行期）
```
```js
function cloneBlockBody(arr, paramCmd) {   // paramCmd: 执行期传 cmd（参数注入）；编辑器深拷贝传 null
  return (arr || []).map(function (c) {
    var nc = { id: c.id };
    if (c.rep !== undefined) { nc.rep = c.rep; }
    if (c.steps !== undefined) { nc.steps = paramCmd ? resolveStep(paramCmd, c) : c.steps; }
    if (c.paramIdx !== undefined) { nc.paramIdx = c.paramIdx; }
    if (c.id === 'loop') { nc.body = cloneBlockBody(c.body, paramCmd); }
    if (c.id === 'if') { nc.then = cloneBlockBody(c.then, paramCmd); nc.else = cloneBlockBody(c.else, paramCmd); }   // v1.15
    return nc;
  });
}
// cloneBranchWithParams 已并入 cloneBlockBody（paramCmd 参数统一处理顶层/loop.body/if 分支）——B3 Oracle 统一入口
```

### 2.3 执行器（execCall if 分支递归拷贝 + 参数注入）— B2/B3/B4 修订

**B2（Oracle——共享引用安全 + execIf 展开方式验证）**：
逐帧分析（块 A = `{if, then:[fwd], else:[left]}` 无参数化，主序列 `[call A, call A]`）：
| 帧 | 队列 | 动作 | 污染检查 |
|----|------|------|----------|
| 0 | [call A, call A] | execCall A, needsCopy=false, body 共享展开 | if 对象共享引用进队列 |
| 1 | [if, call A] | execIf 探测→选 then, `unshift(...then)` | **then 数组未被修改**（展开插入元素） |
| 2 | [fwd, call A] | execTop fwd 纯动作 | 不写 _execTop/_loopLeft 到指令对象 |
| 3 | [call A] | execCall A 第二次, body 共享展开 | if 再次共享引用 |
| 4 | [if] | execIf→选 else, `unshift(...else)` | else 数组未被修改 |
| 5 | [left] | execTop left 纯动作 | 不写状态 |
**结论**：共享引用路径安全——前提 execIf 采用 `unshift(...branch)` 展开插入元素（**验证缺口 #1**：冒烟确认不修改原数组）；then/else 仅基础指令（单层约束保证）。

```js
// execCall（v1.15 扩展——B3 统一入口）：
if (blockHasParam(cmd.bid)) {
  runBody = cloneBlockBody(def.body, cmd);   // paramCmd = cmd：顶层/loop.body/if 分支统一参数注入
} else {
  runBody = def.body;   // 无参数无参数化块：共享引用（v1.10/v1.14 B1 确认顺序队列无污染）
}
```
- **执行路径零改动**：块内 if 展开进 execQueue 后由 execStep `cmd.id === 'if' → execIf(cmd)` 处理（v1.5 既有）✅
- **needsCopy 判定**：blockHasParam（递归版已含 if 分支）——if 分支含参数化 steps 的块走副本 ✅
- **固定值保护**：resolveStep 已含「steps !== null 原样」判断（v1.14 修正）✅
- **resetLoopLeft**：已递归 if.then/if.else（v1.5 既有）✅

**B4（Oracle——ifDepth 交互说明）**：块内 if 展开进队列后走 execIf，**ifDepth 正常累加（宏展开语义）**——
场景「主序列 ifDepth=2（满嵌套）→ call 含 if 的块 → execIf ifDepth=3」：上限=2 时**会被 execIf 拦截**（合理防御，
非新增关卡限制——「0 新关」承诺不含执行时嵌套深度防御）。验证缺口 #3（ifDepth 交互测试）+ 教学引导提示。

### 2.4 星级 totalSteps（零改动确认）

totalSteps 已递归 if（`c.id==='if' → n += 1 + totalSteps(then) + totalSteps(else)`）✅ 块体 if 自动计入；
call 计 1 + body 一次（seenBlockIds）✅；if 分支参数化 steps 经 `c.rep||1` 计 1 ✅。
**激励（I4）**：块内含 if = call 计 1 + body 一次（if 计 1 + 两分支指令数）——复用价值与 loop 块一致
（≥2 次调用优）；教学引导「重复出现的探测+决策模式（如避开障碍）才值得封装成块」。

### 2.5 嵌套边界决策（方案 A——Oracle 确认）

**现状约束矩阵**（主序列）：loop.body 可嵌 if/loop（loopDepth ≤2）；if 分支禁 loop（可嵌 if，ifDepth ≤2）

**v1.15 块内约束（对称简化）**：

| 位置 | 允许指令 | 说明 |
|---|---|---|
| 块 body 顶层 | 基础 + loop + **if** | v1.14 + v1.15 |
| 块内 loop.body | 基础 + 参数化 steps | v1.14 保持（不嵌 if/loop/call） |
| 块内 if.then/else | 基础 + 参数化 steps | **v1.15 新增**（不嵌 if/loop/call） |

**方案 A（Oracle 确认合理）**：块内 if 分支仅基础 + 参数化 steps——决策 B 精神延续（块 = 线性+单层控制）；
与主序列「if 分支禁 loop」约束对称；约束不一致本身是设计决策（块 = 封装复用单元，单层最简 + 低龄线性）。
**双重保险**：hasIllegalNested 扩展 if 分支（保存时）+ hasCallInBlock 递归 if（v1.14 I4，执行时）。

### 2.6 面板预览 if 摘要（I3 确认——单层无递归）

- `.pv-if` 紫底 + `{then…|else…}` 包裹；then/else 内 chips 复用 v1.14 N2 样式（.pv-steps 灰 / .pv-param 紫）——
  单层约束下无嵌套，无需递归；截断规则同 v1.14（超长省略号）

### 2.7 范围与边界

- 0 新关；不改主序列 if/loop 任何逻辑（execIf/ifDepth/renderBranchCol/editStack 均不动——仅块编辑器新增 if 入口 + 块内编辑态）
- **存量块**：body 无 if → 共享引用/副本路径不变（v1.14 已验证回归）
- **Chrome 61**：无新 API（复用 makeEl/appendChild/addEventListener）

|---|---|---|
| 块内 if 编辑态与主序列 editCtx 混淆（双栏实现误伤） | 中 | 块内 if 独立视图（editBlockIfTarget 双状态，editBlockLoopTarget 零改动）+ 复用 .block-edit-row/.block-edit-col——不触碰主序列 editCtx（editStack/renderEditCtx 保持） |

| **B4 ifDepth 超限（主序列满嵌套 + call 含 if 块）** | 中 | 宏展开语义下正常累加（合理防御）；缺口 #3 交互测试确认行为 + 教学引导提示 |

| 深拷贝漏 if 分支（编辑即污染块库） | 中 | cloneBlockBody 补 then/else 递归（B3 统一入口）+ 单元验证 |
