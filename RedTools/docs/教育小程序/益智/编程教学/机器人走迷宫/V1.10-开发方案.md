## 1. 背景与目标

### 1.1 背景

走迷宫已闭环：解题（内置关卡）→ 出题（v1.9 关卡编辑器）双路径。指令系统现有 7 种指令
（fwd/left/right/block/steps/if/loop），覆盖顺序→循环→条件→调试→分支→参数化→循环块→嵌套循环。
**缺口**：孩子只能**用固定指令**编排，不能**创造自己的指令**。编程教学最高阶能力之一 = 抽象
（把一段常用动作封装成有名字的块，之后像单条指令一样引用复用——函数/子程序/自制积木
（Scratch My Blocks）的启蒙形态）。

### 1.2 教学定位

- 既有指令：**系统给的积木**（顺序/循环/条件/分支/参数化/循环块/嵌套）
- **v1.10：孩子自造的积木**（🧩 自定义指令块）——把一段指令序列命名保存，之后序列里一条
  `🧩块名` 即代表整段执行（**抽象/封装**：一次定义、多次复用；Scratch「制作新积木」）
- 教学价值：孩子必须**识别重复模式** → **提炼封装** → **命名复用**——与"把解法写一遍"
  相比，抽象后主序列大幅精简（这正是函数/子程序的本质动机）
- 类比：v1.7 循环块是"重复执行一段"（自动化）；v1.10 自定义块是"一段动作命名后到处用"（复用）
  ——差异教学点：循环强调**次数**，自定义块强调**命名与复用**（抽屉里的一件工具）

### 1.3 与既有能力关系

| 能力 | 现状 | v1.10 |
|---|---|---|
| 指令系统 | 7 种固定指令 | + `🧩块名` 自定义块引用（指令对象 `{id:'call', bid, name}`） |
| 编辑器 | v1.9 关卡编辑器（盘面编辑） | + **块编辑器**（指令序列编辑：名称 + body 指令） |
| 存储 | customLevels（关卡库） | + **customBlocks**（块库，同 storage 模式） |
| 执行器 | execQueue 工作队列（loop/if 分支插入） | 执行器**零改动设计**：call 展开 = execLoop 同构（查块库 body → 插入队首） |
| 编写量 | totalSteps（loop 计 1+body 不乘 rep） | call 计 **1 条/次引用**（块 body 不计入——定义成本，非本关编写量） |
| 星级 | 关卡 b 值 vs totalSteps | **0 新关**：块改写任意关卡都降低 totalSteps → 3★ 更容易（抽象激励天然成立）；关卡数据/b 值全不动 |

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | **程序抽象/封装**：识别重复动作段 → 封装为命名块 → 主序列引用复用（函数启蒙） |
| 玩法 | 首页「🧩 我的块」卡片 → 块库（新建/编辑/删除）→ 练习页 cmd-bar「🧩块」按钮选择追加引用 |
| 合规 | 块库本地存储（同 customLevels 先例）、无 PK/云同步、无分享传播；抽象 = 编程概念教学 |
| 范围 | **不加新关卡**（205 关已全量；块是元能力，任何关卡可用）；**不加块嵌套**（禁 call-in-block，防递归+低龄认知） |

## 2. 变更设计

### 2.1 数据模型：自定义块库

**存储**（完全对齐 v1.9 customLevels 先例）：
```js
// LX_SHARED.storage.set('customBlocks', arr) → localStorage 键 'redtools.jiqirenzoumi.customBlocks'（无 .v1. 段）
// value: [{ id, name, body: [指令对象数组], createdAt }, ...]
```

| 字段 | 说明 |
|---|---|
| id | 唯一：`Date.now() + '-' + Math.random().toString(36).slice(2,5)`（v1.9 同款防碰撞） |
| name | 块名（默认「我的块 N」，**≤6 字**——低龄短名、chip 显示紧凑） |
| body | **基础指令数组**：fwd/left/right/block/steps（含 rep 循环次数 / steps 参数）——**不含 if/loop/call**（见 §2.2 决策） |
| createdAt | 创建时间戳 |

**上限**：块数量 ≤ **8 个**（低龄心智槽位，够用不臃肿）；块 body ≤ **8 条指令**（防"整关塞一块"星级虚高，也符合抽象粒度——复杂动作拆多块）。

**名称约束**（N-1 采纳）：块名**非空 + 唯一**（重名提示「这个名字已有块啦」），≤6 字；
保存校验在 addCustomBlock/updateCustomBlock 统一做（重名校验发生在**编辑块自身时先排除自身**）。

**存取函数**（对齐 v1.9）：
| 函数 | 签名 | 说明 |
|---|---|---|
| loadCustomBlocks | `() → Array` | IIFE 顶部加载；无数据 `[]` |
| saveCustomBlocks | `(arr) → void` | `storage.set('customBlocks', arr)` |
| addCustomBlock | `(name, body) → id` | 构造对象 push + save；超 8 提示 |
| removeCustomBlock | `(id) → void` | confirm 后按 id 过滤 + save |
| updateCustomBlock | `(id, name, body) → void` | 编辑保存（引用自动生效——函数定义更新，调用点用最新 body） |
| getCustomBlock | `(id) → obj\|null` | 执行器查块定义（bid → body） |

### 2.2 块体指令集决策（关键）

**块 body 仅允许基础指令**：fwd / left / right / block / steps（含 rep 循环次数、steps 参数 N）：

| 选项 | 方案 | 决策 |
|---|---|---|
| A | body 允许全部 7 指令（含 if/loop） | ❌ 与顶层/loop 嵌套编辑交错，editStack 复杂度爆炸；块编辑器需复用 if/loop 分支编辑 UI |
| B | **body 仅基础指令（本方案）** | ✅ **采纳**：块 = 顺序动作段封装（抽象启蒙核心）；控制结构已在顶层/loop/if 中教学过，不重复；块编辑器 = 单栏 chips + 添加按钮（复用 renderLoopBody 的 chips 区 UI 风格） |
| C | body 允许基础 + call（嵌套块） | ❌ 递归/间接递归风险、认知负担大，MVP 不做（后续版本候选） |

- **禁 call-in-block**（B 隐含）：无递归可能 → 执行器无需环检测（MAX_QUEUE 500 兜底已有）
- **唯一循环来源**：基础指令本身的 rep 循环次数（×2/×3/×4，同主序列 chip 交互）——块内可含"重复动作"，块外引用重复展开

│ │ [1.↑ 2.↰ 3.➡走3步]          │ │  ← chips（点击循环次数/参数递增/✕删除）
│ │ [+↑][+↰][+↱][+🧱][+➡N步]     │ │  ← 仅基础指令按钮

**交互**：
- 名称 input（maxLength=6）；body 指令 chips 复用 renderSeq chip 样式（点击 cycleRep/cycleSteps、✕ 删除）
- 添加按钮仅 5 个基础指令（[+↑][+↰][+↱][+🧱][+➡N步]）——无 if/loop/块（§2.2 决策 B）
- **编辑器锁定**（I-4 采纳）：进入 viewBlockEdit 时 `setCmdLocked(true)` 锁主编辑器（防孩子在编辑块 body 时误操作主序列/其它视图控件），退出（保存/取消/返回）时解锁；对齐既有 editStack 进入锁定的先例
- [💾 保存]：body 非空 + 名称非空且唯一才可保存（body 空提示「先加几条指令」；重名提示「这个名字已有块啦」）；保存 → `updateCustomBlock`/`addCustomBlock` → 返回块库
- [↺ 清空]：confirm 后清空 body（对齐编辑器）

### 2.5 练习页：块引用

**cmd-bar 新增按钮**：`[🧩块]`（追加在 7 按钮后 → 8 按钮，layout 复用 flex-wrap 两行）：
- 点击 → 内联块选择面板（插入 cmd-bar 下方）：
  - 无块：提示「先去首页 🧩 我的块 建一个块」
  - 有块：每个块一个按钮 `🧩块名` → 点击追加 `state.cmds.push({id:'call', bid, name})` 并关面板
  - **body 预览**（N-2 采纳）：面板块条目下方显示 body chips 缩略（如「前进×2 / 左转」），强化「封装可见」教学，帮孩子识别块用途
- 面板含「🧩 管理块」链接 → viewBlockList（低龄直达）

**序列 chip 渲染**（renderSeq 扩展，I-3 采纳）：
- call chip：`N.🧩块名`（紫色系 `.call` class，与 loop 绿/if 橙区分）
- **name 来源**：渲染时**查块库取最新 name**（`getCustomBlock(bid)`），不依赖存储的 name 副本；块已删除 → 灰显 + 「块已删除」标记（N-3 采纳）但仍显示存储的 name 作降级
- **删除**：✕ 角标删除同其他指令（删除 call 不影响块定义）
- **点击**：进入 `viewBlockEdit(bid)` 编辑该块（孩子点指令直接改块定义，强化「引用↔定义」关联）

**引用与块库的耦合**：
- 块被删除 → 序列中残留 call：渲染灰显（N-3）+ 执行时 `getCustomBlock(bid)` 为 null → 反馈「🧩 块「名」已删除」并终止（不崩溃）
- 块被编辑 → 已插入 call 自动用最新 body（引用存 bid，执行时查最新定义）
- 保存成功的块数据**跨关卡可用**（块库全局，非关卡绑定——正是"抽屉工具"教学意图）

### 2.6 执行器（call 展开 = execLoop 同构，零状态改动）

**核心洞察**：v1.7 execLoop 已有完整"body 展开 + 插入队首 + 继承 _execTop + 轮间 resetLoopLeft"模式。
自定义块引用的执行 = **按 bid 查块库取出 body 后走同一路径**：

```js
/* v1.10 自定义块引用：同 execLoop 结构，body 来自块库（getCustomBlock(bid)） */
function execCall(cmd) {
  var def = getCustomBlock(cmd.bid);
  if (!def || !def.body || !def.body.length) {        // 块被删/空 → 外部已有反馈，无 body 直接返回
    return;
  }
  // I-2 采纳：防递归爆栈——块定义 body 含 call（数据被篡改/导入异常数据）→ 反馈终止
  for (var k = 0; k < def.body.length; k++) {
    if (def.body[k].id === 'call') {
      var fbI = document.getElementById('game-feedback');
      if (fbI) { fbI.textContent = '⚠ 块「' + (def.name || '?') + '」定义异常（含嵌套引用），已停止'; fbI.className = 'game-feedback miss'; }
      state.execLock = false; stopTimer(); clearExecHighlight(); state.execDone = true;
      return;
    }
  }
  resetLoopLeft(def.body);                             // B1 同款：展开前清 body 执行期状态（共享引用污染防 bug）
  for (var i = 0; i < def.body.length; i++) {
    def.body[i]._execTop = cmd._execTop;               // I-new 同款：无条件继承父级 call 顶层下标（高亮/失败定位）
  }
  state.execQueue.splice.apply(state.execQueue,
    [state.queueIdx, 0].concat(def.body));
}
```

**execStep 分发**（I-2 采纳，防递归 + 删除块兜底在 execCall 内统一处理，无需外层校验）：
```js
} else if (cmd.id === 'call') {
  var defCall = getCustomBlock(cmd.bid);
  if (!defCall) {
    // 块已删除：反馈 + 终止（防 null 崩溃）
    state.execDone = true;
    var fbD = document.getElementById('game-feedback');
    if (fbD) { fbD.textContent = '🧩 块「' + (cmd.name || '?') + '」已删除，先移除这条指令吧'; fbD.className = 'game-feedback miss'; }
    state.execLock = false; stopTimer(); clearExecHighlight();
    return;
  }
  execCall(cmd);
}
```

**分支/编辑守卫**：
- **call 不可入 if 分支/loop body**（块是顶层工具指令）：renderBranchCol/renderLoopBody 添加按钮**不含 [🧩块]**——仅顶层 cmd-bar 提供（低龄简化：块引用只出现在主序列；与 v1.8「if 分支内禁 loop」反向前例对称）
- **加载守卫（I-2 补充，v1.11 可缓）**：execCall 已校验 body 无 call（防递归爆栈，本版必做）；customLevels 导入含 call-in-loop 的深度校验推迟到 v1.11（execCall 兜底已保证不崩溃——call 在 loop body 会"正常工作"重复展开，非崩溃，仅违背教学设计，风险低）
- 执行锁定：setCmdLocked 已锁 .cmd-add/.cmd-chip → 块选择面板按钮加 `.cmd-add` 类自动被锁

**resetLoopLeft(cmds)**：call 指令自身无 body 字段（body 在块库）→ 现有递归不碰块库对象；块库 body 的
执行期残留由 execCall 展开前 resetLoopLeft 清理（同 execLoop B1）——**完全复用，无需改 resetLoopLeft**。

### 2.7 编写量 totalSteps（星级口径，I-1 采纳修订）

```js
var seenBlockIds = {};                 // v1.10：本关已计数的块 bid 集合（body 仅计一次）
...
} else if (c.id === 'call') {
  n += 1;                              // 每次引用计 1 条（调用开销）
  if (!seenBlockIds[c.bid]) {          // body 仅计一次（同 loop 不乘 rep 的编写量口径）
    seenBlockIds[c.bid] = true;
    var bd = getCustomBlock(c.bid);
    if (bd) { n += totalSteps(bd.body); }
  }
}
```

**激励论证（I-1 修订：与 loop 同构——call 计 1 + body 计一次，不乘调用次数）**：
- 单次 call：`1 + body`，比直接写多 1 开销 → **单块封装无收益**（防「整关塞一块」刷分）
- 多次 call 同块：`N + body`（body 只计一次）→ 复用有收益：3 call(body 8 fwd) = 11，直接写 = 24
- 例：某动作段 3 条指令出现 3 次 → 直接写 9 条；封装成块 → `3 + 3 = 6` 条 → 3★ 门槛下降（抽象激励成立，但不会像"body 零计"那样压到 3）
- **防星级虚高闸**：单次 call 不比直接写少（+1 开销）→ 无法靠"把解法塞一块再引用 1 次"刷分；复用收益随调用次数线性增长（真实抽象收益）
- 关卡 b 值/数据**零改动**：块改写 = 同解法不同表达，totalSteps 随复用度下降 → 3★ 更容易（教学意图：抽象使编写量减少，正当激励）

### 2.8 清除数据覆盖（对齐 v1.9 B5；N-3/N-6 采纳）

viewParent「清除所有数据」：`storage.remove('v1')` + `storage.remove('customLevels')` **+ 追加 `storage.remove('customBlocks')`**。
- **语义明确**（N-6）：清除块库后，**已保存关卡（customLevels）中的 call 引用保留**（用户可能只想清块库不清关卡/成绩）——残留 call 走 N-3 灰显 + 执行反馈兜底
- 若后续需要「清空所有（含关卡中的 call）」，单独提供入口，不混入「清除数据」

| 测试项 | 断言 |
|---|---|

| 双 call 不同块 | callA(3) + callB(2) = 1+3+1+2 = 7 |

## 7. 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 块 body 共享引用执行期污染（多 call/重复执行） | 中 | execCall 展开前 `resetLoopLeft(def.body)`（B1 同款）；引用存 bid 执行查最新定义（无陈旧 body） |
| **星级虚高（整关塞一块刷 3★）** | **中** | **I-1 修订：call 计 1 + body 计一次——单次 call 比直接写多 1 开销（单块封装无收益），复用收益随调用次数线性增长（真实抽象）**；块 body ≤8 条进一步限制单块粒度 |
| **块定义含 call 递归爆栈** | **低** | **I-2 修订：execCall 入口校验 def.body 无 call，发现即「定义异常」反馈终止**（数据篡改场景兜底） |
| 块被删除残留引用崩溃 | 低 | 渲染灰显（N-3）+ execStep 查库兜底反馈终止；删除前 confirm |
| 低龄命名困难/混淆 | 低 | 默认名「我的块 N」+ ≤6 字短名 + **非空/唯一校验（N-1）** |
| 重名块混淆 | 低 | 保存时重名校验（编辑自身排除） |
| 与 v1.9 编辑器职责混淆 | 低 | 首页独立卡片 + 块库独立视图；盘面编辑器（v1.9）与指令块编辑器（v1.10）入口/视图分离 |
| call 进 if/loop body 复杂度 | 低 | 范围限制：块引用仅顶层 cmd-bar（renderBranchCol/renderLoopBody 不含 [🧩块]）；执行器 call-in-loop 兜底不崩溃（v1.11 可加深层加载校验） |
| 块编辑器误操作主序列 | 低 | **I-4 修订：进入 viewBlockEdit setCmdLocked(true)，退出解锁** |
