## 1. 背景与目标

### 1.1 背景

v1.11 块参数实现「带 1 个数字参数的块」（Scratch 带输入积木进阶）。Oracle v1.11 审核记录 2 项后续增强：
- **N1 多处参数化**：方案限制「每块 ≤1 处 steps 参数化」（编辑器第一条），但**执行层 execCall 运行时副本已支持所有 `steps:null` 填同一 param**——仅编辑器未放开。放开后「走 N 步 → 右转 → 走 N 步」类**拐角/方形模式**可一个参数块表达，参数复用教学价值更高。
- **N2 定义/调用显示分离**：Scratch 先例——块**定义**用占位符（`walk [n] steps`），**调用**填具体值（`walk 3`）。v1.11 定义态显示 `➡N步(N)`（N 既是占位又像具体值，略混）。

### 1.2 教学定位

- v1.11 块参数：**同块不同参数 → 不同行为**（已闭环）
- **v1.12 增强**：① **参数在块内多处生效**（一个 N，块内多处「走 N 步」——参数贯穿动作段）；
  ② **定义/调用语义分离**（定义时 ? 占位 = "这里由调用决定"，调用时具体数字 = 实际行为）
- 教学价值：孩子理解「参数 = 块内可替换的一处名字」——不只一处行为，而是**整段动作的变量**（Scratch 参数变量的直观化）

### 1.3 与既有能力关系

| 项 | v1.11 | v1.12 |
|---|---|---|
| 参数化 steps 数量 | 编辑器仅第 1 条（执行层已支持多处） | **全部 steps 参数化**（toggle 开 → 所有 steps 变 steps:null） |
| 定义态显示 | `➡N步(N)` | **`➡?步`**（? 占位符，N2） |
| 调用态显示 | `🧩名(3)` | 不变（具体数字） |
| 面板预览 | `➡N步` | **`➡?步`**（N2） |
| 执行 | execCall 副本 steps:null→param | **零改动**（已支持全部参数化） |
| 星级 | totalSteps 统一（I1） | **零改动** |

### 1.4 目标

| 项 | 说明 |
|---|---|
| 教学目标 | 参数 = 块内可替换的变量（多处生效）；定义（抽象）vs 调用（具体）语义分离 |
| 玩法 | toggle 开 → 块内所有 steps 变 `➡?步`；定义态 ? 占位、调用态具体数字 |
| 合规 | 本地存储（同前）、无 PK/云同步；参数化 = 编程概念教学 |
| 范围 | 0 新关；无执行器/星级改动（N1 执行层已就绪，N2 纯显示）；不影响 v1.10/v1.11 已存数据（steps:null 语义不变） |

## 2. 变更设计

### 2.1 N1 多处参数化（编辑器放开）

**现状**（v1.11）：toggle 开 → 仅第一条 steps 参数化（`break` at L663）。

**v1.12 设计**：toggle 开 → **所有 steps 参数化**（全部 `steps:null`）；toggle 关 → 全部恢复固定 `steps:1`。

```js
function toggleBlockHasParam() {
  if (editBlockHasParam) {
    // 关：全部参数化 steps（steps:null）恢复固定 steps:1
    for (var i = 0; i < editBlockBody.length; i++) {
      if (editBlockBody[i].id === 'steps' && editBlockBody[i].steps === null) {
        editBlockBody[i].steps = 1;
      }
    }
    editBlockHasParam = false;
    return null;
  } else {
    // 开：需要 body 有 steps；全部参数化
    var hasSteps = false;
    for (var j = 0; j < editBlockBody.length; j++) {
      if (editBlockBody[j].id === 'steps') { hasSteps = true; break; }
    }
    if (!hasSteps) { return '😅 先加一条 ➡N步，才能带参数'; }
    for (var k = 0; k < editBlockBody.length; k++) {
      if (editBlockBody[k].id === 'steps') { editBlockBody[k].steps = null; }   // v1.12：全部参数化
    }
    editBlockHasParam = true;
    return null;
  }
}
```

**语义**：一个块一个参数 N，块内**所有** steps 都走 N 步——「走 N 步再转再走 N 步」= 一个块完成方形/拐角动作。执行层 execCall 副本已将所有 steps:null 填同一 cmd.param（Oracle v1.11 已确认）→ **零执行改动**。

**addBlockBodyCmd**：参数态下新增 steps 直接 `steps:null`（v1.11 已实现 `editBlockHasParam ? null : 1` ✅ 无需改）。

**blockHasParam 派生**（B2）不变：`body.some(steps===null)`——全部或部分参数化都判定为参数块 ✅。

### 2.2 N2 定义/调用显示分离

**显示矩阵**（v1.12）：

| 场景 | v1.11 | v1.12 | 说明 |
|---|---|---|---|
| 块编辑器 body 参数版 steps | `2.➡N步(N)` | **`2.➡?步`** | 定义态 ? 占位（抽象：这里由调用决定） |
| 块选择面板预览 | `➡N步` | **`➡?步`** | 同上 |
| 参数块 call chip | `🧩走N左转(3)` | **`🧩走N左转(3)`**（不变） | 调用态具体数字 |
| 展开执行 | steps:N | 不变 | 具体行为 |

- **? 占位符视觉**：`➡?步` 中 `?` 用浅紫色（同参数主题色），强化"待填"语义（CSS class `.param-q`）
- **修改点**：
  - `renderBlockBodyChip` L611：`lbl = '➡?步'`（原 `➡N步(N)`）
  - `renderBlockPicker` 预览 L1372：`c.steps === null ? '➡?步'`（原 `➡N步`）
  - hint 文案 L553：「块里「➡?步」的距离由调用时传入（1-9）」（原 `➡N步(N)`）
- **无 JS/执行/星级改动**（纯显示文案）

### 2.3 交互细节确认

- **toggle 文案**：`🔢 带参数：走 N 步`（不变；hint 同步说明"块里所有 ➡?步 都走同一个 N"）
- **参数版 steps 点击**：no-op（v1.11 I3 guard 保留；? 占位不可直接调参，参数由调用方决定）
- **cycleCallParam**：不变（调用态调参）
- **旧数据**：v1.11 已存参数块（body 含 1 处 steps:null）→ 显示 `➡?步`（显示升级，数据不迁移）；
  其余步骤未参数化 → 固定显示 ➡走N步；toggle 再开关一次即全部参数化（用户主动）

### 2.4 范围与边界

- 0 新关；执行器/星级/存储零改动（纯编辑器 + 显示）
- N1 放开后「一处参数化 + 其余固定」混合态：toggle 关会全部恢复固定（符合「参数 = 全部或全不」简化语义）；
  如需混合（部分 steps 参数化部分固定）→ 后续迭代（当前低龄 MVP 全参数化更直觉）
- toggle 开→关→开：第一次开全部参数化，关全部恢复，再开再全部参数化——状态一致，无残留
