## 1. 背景与目标

### 1.1 背景与现状

循环指令 v1.0 已完成「**显式循环块（单层）**」教学：走廊盘面（轨迹格空地 + 相邻非轨迹格墙，堵死捷径）+ 机器人 S→G + `🔁 重复 N 次 {组指令}`（MVP 单层）+ **编写量星级**（循环块 1 条 + 内部指令计 1 不乘 N）+ 骨架 pattern（fwd×k + right 螺旋）生成器。

**缺口**：与走迷宫 v1.7→v1.8 同构——循环块 body 内**禁 loop**（MVP 单层）。v1.1 放开此限制：**循环块内可再嵌循环块**（嵌套循环）——编程核心的**嵌套结构**（循环套循环 = 二维重复）。

### 1.2 教学定位（与走迷宫 v1.8 对齐）

| 概念 | 走迷宫 v1.8 | 循环指令 v1.1 |
|---|---|---|
| v1.7 / v1.0 | `🔁×N {组指令}` = 一组动作重复 N 次（循环 = 自动化） | 同（显式循环块） |
| **v1.8 / v1.1** | `🔁×M {🔁×N {指令}}` = 内层循环完整 N 次 × 外层 M 轮（**嵌套循环 = 二维自动化**） | 同 |
| 教学价值 | 嵌套结构：外层每轮执行一次内层完整 N 次 | 同（类比乘法表 / 网格清扫） |

- 与走迷宫 v1.8 的区别：走迷宫 196-205 是**新增固定关卡**（b=嵌套解 totalSteps）；循环指令是**程序化生成**（无 levels.js）——v1.1 通过**升级骨架 patternLen + 重定义 optimal 为嵌套解常量 4** 实现激励（避免引入固定关卡破坏生成器架构）

## 2. 变更设计

### 2.0 ★ 核心数学口径（Oracle B1 修复——v0.1 缺陷回顾）

> **v0.1 缺陷（Oracle B1）**：方案全程把 `patternLen` 当「fwd 数 k」，但 `genPattern(len)` 实际产生 `[fwd×(len-1), right]`（**fwd 数 = patternLen − 1**，v1.0 注释 `[F,F,R]`/`[F,F,F,R]` 可证）。连锁错误：
> - 单层循环写量被高估 1（声称 7/9，实际 6/8）→ **normal 单层 6 ≤ 1.5×4=6 → 仍 3★，激励失效**；
> - 嵌套解示例 `🔁×5{fwd}` 产生 5 fwd 但走廊仅 4 fwd 段 → **机器人撞墙**；
> - 几何推演 F^5/F^7 基于错误前提。

**v0.2 修复**：`normal.patternLen: 4→6`、`hard.patternLen: 5→8`（非 5/7）。改后全部自洽（下方 §2.4 表为唯一权威数值）：

| 档 | patternLen | fwd 数（=patternLen−1） | 单层循环写量 | 嵌套写量 | 内层 rep | 几何 |
|---|---|---|---|---|---|---|
| easy | 3（不变） | 2 | 4 | 4 | 2 | F²→x=3≤6 ✓ |
| **normal** | **6** | **5** | **7** | 4 | **5** | F⁵→x=6≤8 ✓ |
| **hard** | **8** | **7** | **9** | 4 | **7** | F⁷→x=8≤10 ✓ |

- **optimal 口径**：三档统一 = **4**（嵌套解写量常量，genLevel `optimal: cfg.patternLen + 1` 改为常量 `4`——不再是 patternLen+1）
- 3★ 阈值 `total ≤ 4×1.5 = 6`：easy 单层 4≤6 → 3★（保留教学）；normal 单层 7>6 → 2★；hard 单层 9>6 → 2★；嵌套 4≤6 → 3★ ✅
- easy patternLen=3 不变 → v1.0 回归零影响（生成盘面/单层解写量全同）
- 生成器代码（genPattern/genLevel/simulate/noNear/verifyUniquePath）**零改动**——仅 LEVELS_CFG 数值变化，gate 自动校验新盘面

### 2.1 嵌套循环 UI：body 内嵌 loop + loopDepth 守卫 + 两层编辑上下文

**现状**（v1.0）：`addBodyCmd` 顶部 `if (id === 'loop') { return; }`（body 内禁 loop）；`editCtx = { loopIdx: -1 }`（单层扁平编辑上下文）。

**v1.1 变更**：

**(a) addBodyCmd 放开 loop + loopDepth 守卫 + 内外层目标分支**（Oracle v0.2 复核 I1-new：addBodyCmd 与 cycleLoopRep/removeBodyCmd 同需内外层分支——innerIdx≥0 时目标 = 内层 loop，否则 = 外层 loop）：
```js
function addBodyCmd(id) {
  if (state.execLock) { return; }
  if (editCtx.loopIdx < 0) { return; }
  var outer = state.cmds[editCtx.loopIdx];
  if (!outer || outer.type !== 'loop') { return; }
  var loop;
  if (editCtx.innerIdx >= 0) {                 // 内层编辑态 → 目标 = 内层 loop
    loop = outer.body[editCtx.innerIdx];
    if (!loop || loop.type !== 'loop') { return; }
  } else {                                     // 外层编辑态 → 目标 = 外层 loop
    loop = outer;
  }
  if (id === 'loop') {
    if (loopDepth() >= 2) {                    // 嵌套 ≤2 层守卫
      var fb = document.getElementById('game-feedback');
      if (fb) { fb.textContent = '⚠ 循环嵌套最多 2 层'; fb.className = 'game-feedback miss'; }
      return;
    }
    loop.body.push({ type: 'loop', rep: 2, body: [] });   // N1：默认 rep=2（hard 需点 5 次到 7，UX 可接受）
  } else {
    loop.body.push({ type: id });
  }
  renderSeq();
}

/* v1.1：当前嵌套深度 = 正在编辑外层循环(loopIdx≥0 ? 1 : 0) + 已展开内层循环(innerIdx>=0 ? 1 : 0) */
function loopDepth() {
  return (editCtx.loopIdx >= 0 ? 1 : 0) + (editCtx.innerIdx >= 0 ? 1 : 0);
}
```

**(b) 两层编辑上下文**（editCtx 扩展，Oracle v0.2 复核确认足够/更简单——两索引 vs 走迷宫 editStack 栈：≤2 层固定深度下两索引更简单，无需通用栈）：
```js
var editCtx = { loopIdx: -1, innerIdx: -1 };   // -1 = 顶层/未展开
// loopIdx >= 0 = 正在编辑第 loopIdx 条顶层循环块（外）的 body
// innerIdx >= 0 = 正在编辑 cmds[loopIdx].body[innerIdx] 内层循环块的 body（仅 loopIdx>=0 时有意义）
```
- 外层循环编辑区内：body chip 若是 loop → 渲染 `🔁×N` 绿色小 chip（`.loopb` 类）+ 点击 → `editCtx.innerIdx = b` → 展开**内层编辑区**（面包屑「🔁 内层循环 · 重复 N 次」+ 重复次数按钮 + body chips + [⬆][↰][↱] 加动作 + [✓ 完成]）
- 内层编辑区「✓ 完成」→ `innerIdx = -1` → 回到外层编辑区；外层「✓ 完成」→ `loopIdx = -1` → 回到顶层
- 内层编辑区的加动作按钮**不含 🔁**（深度 2 已封顶，按钮隐藏简化 UI）

**(c) renderBlockEdit 两层适配**（Oracle I3 伪代码）：

### 2.2 执行器：嵌套循环（递归展开 + 递归失败定位）

**现状**（v1.0）：execRun 手工双层循环扁平化（只处理单层），失败定位 `locateFailStep` 只算一层。

**v1.1 变更**：

**(a) 递归扁平化**（嵌套天然支持）：
```js
function flattenCmds(list, out) {
  for (var i = 0; i < list.length; i++) {
    var c = list[i];
    if (c.type === 'loop') {
      for (var r = 0; r < (c.rep || 2); r++) { flattenCmds(c.body, out); }
    } else { out.push(c.type); }
  }
  return out;
}
// execRun：state.execSteps = flattenCmds(state.cmds, [])
```

**(b) 撞墙失败定位递归**（`第 a 次外层循环里的第 b 次内层循环里的第 c 条指令`）：
```js
// flattenCount(body) = body 完全展开步数（递归：loop → rep × flattenCount(body)；叶 → 1）
function flattenCount(list) {
  var n = 0;
  for (var i = 0; i < list.length; i++) {
    var c = list[i];
    if (c.type === 'loop') { n += (c.rep || 2) * flattenCount(c.body); }
    else { n += 1; }
  }
  return n;
}
// 递归定位：返回「第 a 次外层循环里的第 b 次内层循环里的第 c 条指令」路径描述
// Oracle v0.2 复核 N2-new：prefix 拼接「次循环里的 」→「次循环里的」去掉尾空格，保持与 v1.0「第 K 次循环里的第 M 条指令」格式一致
function locateFailStep(stepIdx, list, prefix) {
  var offset = 0;
  for (var i = 0; i < list.length; i++) {
    var c = list[i];
    if (c.type === 'loop') {
      var total = (c.rep || 2) * flattenCount(c.body);
      if (stepIdx >= offset && stepIdx < offset + total) {
        var rel = stepIdx - offset;
        var iter = Math.floor(rel / flattenCount(c.body)) + 1;
        return locateFailStep(rel % flattenCount(c.body), c.body, prefix + '第 ' + iter + ' 次循环里的');
      }
      offset += total;
    } else {
      if (stepIdx === offset) { return prefix + '第 ' + (i + 1) + ' 条指令（' + dirName(c.type) + '）'; }
      offset += 1;
    }
  }
  return prefix + '某条指令';
}
// Oracle I2：dirName helper（v1.0 硬编码「⬆ 前进」的 bug 一并修复——撞墙定位现在能区分左右转）
function dirName(t) {
  return t === 'fwd' ? '⬆ 前进' : (t === 'left' ? '↰ 左转' : (t === 'right' ? '↱ 右转' : '指令'));
}
// checkWin 调用：locateFailStep(state.firstFail.step - 1, state.cmds, '')
```

**(c) totalCmds 递归**（编写量 = 写的块数，不乘 rep——v1.0 语义自然扩展）：
```js
function countCmds(list) {
  var n = 0;
  for (var i = 0; i < list.length; i++) {
    var c = list[i];
    if (c.type === 'loop') { n += 1 + countCmds(c.body); }
    else { n += 1; }
  }
  return n;
}
// 例：🔁×2 {🔁×2 {fwd}} → 1 + (1 + 1) = 3（外层 1 + 内层 1 + fwd 1，不乘 rep）
// 例：🔁×3 {🔁×5 {fwd} right}（normal 嵌套解）→ 1 + (1 + 1 + 1) = 4
```

### 2.3 循环块 rep 上限：2-5 → 2-9

**现状**（v1.0）：`cycleLoopRep` 循环 2→3→4→5→2（上限 5）。
**v1.1 变更**：循环 2→3→4→5→6→7→8→9→2（上限 9）——normal/hard 嵌套解内层 rep 需 5/7（§2.4），必须放开。
- **存量回归安全**：v1.0 各档 optimal = patternLen+1（单层循环解，rep 固定 3），rep 上限放开不改变任何既有最优/激励
- 顶层 loop 与内层 loop 共用同一 cycleLoopRep（上限 9）

**cycleLoopRep 内外层分支**（Oracle I1）：
```js
function cycleLoopRep() {
  if (state.execLock) { return; }
  var loop;
  if (editCtx.innerIdx >= 0) {            // 内层编辑态 → 操作内层 loop
    if (editCtx.loopIdx < 0) { return; }
    var outer = state.cmds[editCtx.loopIdx];
    if (!outer || outer.type !== 'loop') { return; }
    loop = outer.body[editCtx.innerIdx];
  } else if (editCtx.loopIdx >= 0) {      // 外层编辑态 → 操作外层 loop（v1.0 行为）
    loop = state.cmds[editCtx.loopIdx];
  } else { return; }
  if (!loop || loop.type !== 'loop') { return; }
  loop.rep = ((loop.rep || 2) - 1) % 8 + 2;  // 2→3→4→5→6→7→8→9→2
  renderSeq();
}
```

**removeBodyCmd 内外层分支**（Oracle I1——两层操作目标显式）：
```js
function removeBodyCmd(i) {
  if (state.execLock) { return; }
  if (editCtx.loopIdx < 0) { return; }
  var outer = state.cmds[editCtx.loopIdx];
  if (!outer || outer.type !== 'loop') { return; }
  if (editCtx.innerIdx >= 0) {
    // 内层编辑态：splice 内层 loop 的 body
    var inner = outer.body[editCtx.innerIdx];
    if (!inner) { return; }
    inner.body.splice(i, 1);
  } else {
    // 外层编辑态：splice 外层 loop 的 body；若删的是正在编辑的内层 loop → innerIdx 校正回退
    outer.body.splice(i, 1);
    if (editCtx.innerIdx === i) { editCtx.innerIdx = -1; }
    else if (editCtx.innerIdx > i) { editCtx.innerIdx -= 1; }
  }
  renderSeq();
}
```

### 2.4 难度升级 + optimal 口径（★ 核心变更，v0.2 权威数值）

**嵌套解写量 = 4**（`🔁×3 {🔁×k {fwd} right}` = 外层 1 + 内层(1+1) + right 1，恒定与 k 无关；k = fwd 数 = patternLen−1）。
**单层循环解写量 = 1 + patternLen**（body = 整条 pattern）。

**v0.2 三档表（B1 修复后唯一权威）**：

| 档 | 盘面 | patternLen | fwd 数 | rep | optimal | 单层循环写量 | 展开写量 | 星级 |
|---|---|---|---|---|---|---|---|---|
| 简单 | 6×6 | 3（不变） | 2 | 3 | 4（嵌套解） | 4 | 9 | 单层 4 ≤ 1.5×4=6 → **3★**（保留 v1.0 教学）；嵌套 4 → 3★ |
| 普通 | 8×8 | 4 → **6** | 5 | 3 | 4（嵌套解） | 7 | **18** | 单层 7 > 6 → **2★**；嵌套 4 → **3★** ✅ |
| 挑战 | 10×10 | 5 → **8** | 7 | 3 | 4（嵌套解） | 9 | **24** | 单层 9 > 6 → **2★**；嵌套 4 → **3★** ✅ |

> Oracle v0.2 复核 N1-new：展开写量 = patternLen × rep（6×3=18 / 8×3=24，v0.1 残留 15/21 是旧 patternLen 5/7 的错值，已更正）。

- **optimal 口径变更**：三档 optimal 统一重定义为**嵌套解写量常量 4**（genLevel `optimal: cfg.patternLen + 1` → 改常量 `4`）
- easy 保留 k=3：单层循环仍 3★（v1.0 教学目标「学会循环块」不丢失）；normal/hard 递进「单层不够 → 要嵌套」
- **几何校验**（Oracle v0.2 复核逐格验证，生成器 gate 自动校验；术语统一——N3-new：patternLen 直接用档名标注，不用「k」避免与 §2.0 fwd 数混淆）：
  - normal（patternLen=6，fwd 数 5）：F^5 → x=6 ≤ 8 ✓；L 形走廊（row1 x1-6 / col6 y1-6 / row6 x1-6）非连续轨迹格 Manhattan 距离 ≥2，无 4 邻接 → noNear ✓；verifyUniquePath 唯一路径 ✓
  - hard（patternLen=8，fwd 数 7）：F^7 → x=8, y=8 ≤ 10 ✓；同构 L 形走廊 noNear ✓
  - easy（patternLen=3，fwd 数 2）：F^2 → x=3 ≤ 6 ✓（v1.0 已验证）
- **seed 兜底**（genLevel 内置直线走廊，optimal 2）：生成失败兜底不强制嵌套（罕见，教学工具永不卡死）——**删除 seedLevel 死代码**（Oracle N2：v1.0 seedLevel 函数是死代码，genLevel 已有内置直线兜底，删除防混淆）

function openBlockEdit(idx) {
