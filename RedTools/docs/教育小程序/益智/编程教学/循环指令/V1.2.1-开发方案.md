## 2. 变更设计（全部小改，零架构影响）

### 2.1 撤销到中间格（UX 改进，核心变更）

**现状**（v1.2）：`onEditCellClick` 中「点在 trace 内的格」→ 一律拦截「这条路绕回自己了」；`undoEdit` 仅 pop 末端一格。

**v1.2.1 变更**：
```js
// onEditCellClick 中（优先级 ①→④）：
// ① 点在 trace 内（除末端）→ 回退到该格
// ② 点在末端 → 无操作（防误触）
// ③ 点相邻格 → append（末端生长）
// ④ 其余 → 「要从上一格接着画」
if (inTrace) {
  if (idx === trace.length - 1) { return; }          // ② 点末端 = 无操作（防误触）
  // ★ v1.2.1：① 点在 trace 中间格 → 回退到该格（删除其后所有格）
  state.editTrace = trace.slice(0, idx + 1);          // 保留 0..idx，丢弃 idx+1..end
  showEditMsg('已回退到第 ' + (idx + 1) + ' 格');
  renderEditBoard();
  return;
}
// ③④ 点 trace 外格：邻接 append / 否则提示（原「绕回自己」拦截已删除——Oracle N-4）
```

> **交互语义决策**：原「点已画格 = 绕回自己（拦截）」与「点中间格 = 回退」冲突。取「**回退优先**」：点任何已画格（除末端）= 回退到该处（删除其后所有格）——低龄直觉「点到哪、回到哪」，且天然解决长路径误画。
>
> **防自交说明（Oracle N-4 措辞澄清）**：本模型结构性保证的是**重复格预防**（回退优先 → append 永不接收已在 trace 中的格 → trace 恒为简单路径、无重复顶点）；**近路捷径（走廊折回自身附近，墙堵不住抄近道）不被结构性保证，仍由保存时 `noNear`/`verifyUniquePath`（L1057/L1059，v1.2 既有，零改动）拦截**。旧「这条路绕回自己了」文案不再触发（原触发场景 = 点已画格 = 现回退语义），整串删除（Oracle N-4）。

**边界**：
- 点末端（最后格）→ 无操作（防误触清空）
- 点起点 (1,1) → 回退到起点（trace = [起点]）
- 🧹 撤销末端按钮保留（逐格回退快捷方式）

| 风险 | 等级 | 缓解 |
|---|---|---|
| **回退语义误解**（点已画格 = 回退 vs 绕回拦截） | 低 | 防自交由生长模型结构性保证（末端邻接 append 不可能产生分支）；点末端 = 无操作防误触；冒烟「点中间格回退」断言 |

| patch 范围蔓延 | 低 | 严格限定 3 处代码 + 1 处文档 + 1 处使用文档 |
