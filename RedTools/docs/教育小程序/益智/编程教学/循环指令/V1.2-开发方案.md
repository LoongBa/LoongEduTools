## 1. 背景与目标

### 1.1 背景与现状

循环指令 v1.0/v1.1 已完成「**解题**」路径：程序化生成器（走廊骨架 pattern 螺旋 + simulate 无自交 + noNear 无近路 + verifyUniquePath 唯一路径 + seed 兜底）+ 孩子编循环块/嵌套循环指令 → 机器人走到 ⭐ 判定 + 编写量星级（optimal=4 嵌套解常量）。

**缺口**：与走迷宫 v1.9 / 方块排列 v1.2 / 合并策略 v1.1 同构——只有「解给定关卡」单向路径，缺**创作闭环**。孩子无法**自己设计走廊**让程序/自己来解。

### 1.2 教学定位（与系列关卡编辑器对齐）

| 角色 | 走迷宫 v1.9 | 方块排列 v1.2 | 合并策略 v1.1 | 循环指令 v1.2 |
|---|---|---|---|---|
| 解题 | 设计盘面 → 可解校验 → 挑战 | 画图案 → 可拼校验 → 挑战 | 摆数字块 → 可解校验 → 挑战 | **画走廊 → 唯一路径校验 → 挑战** |
| 教学价值 | 理解「能否推到目标」 | 理解「能否落拼出」 | 理解「原子量/可达性」 | **理解「走廊结构」→ 唯一路径/无近路（为什么只有一条路、为什么必须循环）** |

- 角色反转：设计走廊时必须理解「轨迹格 4 邻接连续 = 一条路」「非连续步不得相邻（否则有近路捷径）」「路径必须唯一」→ 比解题更深的走廊结构理解
- 与系列同构：编辑器产出 → 校验（唯一路径）→ 本地保存 → 进入同一练习/判定/星级流程
- 合规：自建关卡**本地存储、不入 publish**；无 PK/排行榜/云存档

### 1.3 目标

| 项 | 说明 |
|---|---|
| 玩法变化 | 首页新增「🛠 自建关卡」入口 → 关卡库（列表/新建/编辑/删除）→ 编辑器（10×10 网格末端生长画路径）→ 唯一路径校验（**复用现成 noNear/verifyUniquePath，零新算法**）→ 保存 → 从列表挑战自建关 |

| 保留 | 练习/判定/执行器/星级/打卡/存储/双模式全复用；生成器/嵌套循环/verifyUniquePath/noNear/simulate/buildCorridor **零改动** |
| 范围 | 0 新内置关；**新增 customLevels 数据层 + custom 练习专属路径**（2★ 兜底）；存量进度兼容 |

## 2. 变更设计

### 2.1 数据模型：自定义关卡库

**存储**：`LX_SHARED.storage`（工具已 `configure({toolName:'xunhuan'})` → 键前缀 `redtools.xunhuan.`）：
```js
// storage.set('customLevels', arr) → 实际键 'redtools.xunhuan.customLevels'（customLevels 是独立集合，非 store 的 'v1' 键，无 .v1. 段）
// value: [{ id, name, trace, gridW, gridH, goal, createdAt, solved }, ...]
```
> ⚠️ 勿硬编码完整键名。统一 `LX_SHARED.storage.set('customLevels', arr)` / `get('customLevels')`。

| 字段 | 说明 |
|---|---|
| id | 唯一（`Date.now() + '-' + Math.random().toString(36).slice(2,5)`，防毫秒碰撞） |
| name | 关卡名（默认「我的走廊 N」，≤12 字） |
| trace | 轨迹格数组 `[{x, y}, ...]`（**Oracle B1 修复：对象数组与 noNear/buildCorridor/verifyUniquePath 函数签名一致**——三函数均访问 `trace[i].x/.y`；从起点 (1,1) 起连续 4 邻接路径） |
| gridW/gridH | **固定 10**（编辑器 10×10 画布；trace 从 (1,1) 出发，10×10 内足够画螺旋/蛇形） |
| goal | `{x, y}` = **trace 末端元素**（`trace[trace.length-1]`，天然对象——Oracle B1） |
| createdAt | 创建时间戳 |
| solved | 是否已用指令通关过（「已解」徽章） |

**上限**：最多 **20 关**（超限提示删旧关）；**trace 长度 ≥ 4 且 ≤ 64**（「至少走 4 格才有意思；最多 64 格（10×10 画布上限）」——对齐生成器「轨迹覆盖 ≥ 4 格」）。

**存取函数**（同 D4 v1.1 签名；Oracle I4 修订：loadCustomLevels 加 Array.isArray 防御）：
| 函数 | 签名 | 说明 |
|---|---|---|
| loadCustomLevels | `() → Array` | IIFE 顶部 `var customLevels = loadCustomLevels()`；`var r = LX_SHARED.storage.get('customLevels'); return Array.isArray(r) ? r : [];`（防损坏 JSON/旧版本残留） |
| saveCustomLevels | `(arr) → void` | `storage.set('customLevels', arr)` |
| addCustomLevel | `(trace, name) → id` | 校验通过后构造对象（goal = trace 末端）push + save；超 20 提示 |
| updateCustomLevel | `(idx, trace, name) → void` | **Oracle I2：编辑已有关保存 = 覆盖同 id**（改 trace/name/goal，保留 id/createdAt；solved 重置 false）；低龄心智「改了就是改了」 |
| removeCustomLevel | `(id) → void` | confirm 后按 id 过滤 + save |
| markCustomSolved | `(idx) → void` | `customLevels[idx].solved = true; saveCustomLevels(customLevels)` |

### 2.3 编辑器视图（viewEditor）

**布局**（独立视图）：
```
┌──────────────────────────────────┐
│ [‹ 返回] 🛠 走廊编辑器 ⏱ 10×10    │
│ 名称: [________]（≤12字）          │
│ ┌────────────────────────────┐ │
│ │  10×10 网格（画走廊路径）    │ │  ← 中央网格（起点 S 固定 (1,1)）
│ └────────────────────────────┘ │
│ 工具: [✏ 画路径] [🧹 撤销末端]  [↺ 清空] │
│ 校验: [✓ 检查路径]  [💾 保存]          │
└──────────────────────────────────┘
```

**绘制交互——末端生长模型**（最稳健，天然防断链/自交；Oracle 决策点 2 确认合理）：
- 起点 **固定 (1,1) 朝右**（对齐生成器语义；编辑器自动画上 S 标记）
- **画路径**：点某格 → 若该格与当前路径**末端 4 邻接** → append `{x, y}` 对象到 trace（Oracle B1：对象格式）；否则拦截「要从上一格接着画」（不能跳格/另起炉灶）
- **防自交**：点已在 trace 中的格 → 拦截「这条路绕回自己了」
- **撤销末端**（🧹）：删除 trace 最后一格（回退一步）
- **↺ 清空**：trace 重置为 [起点]
- 预览渲染：trace 格 = 走廊空地色（复用 #f0f2f5 + 轨迹小圆点）+ 起点 S 蓝标 + 末端 ⭐ 预览；非轨迹格 = 空白底

**唯一路径校验（✓ 检查路径）——核心新逻辑（全部复用现成纯函数，零新算法；Oracle B1 修复后签名一致）**：
- **签名**（Oracle N8）：`checkCorridor(trace) → {ok: Boolean, msg: String}`——trace 为 `[{x,y},...]` 对象数组（Oracle B1）；msg 分级提示（通过「✓ 唯一路径！可以保存」/ 失败原因）
- **viewEditor 入参**（Oracle N7）：`viewEditor(idx)`——idx=-1 新建 / ≥0 编辑已有（存 `state.editIdx`）；关卡库列表 [✏ 编辑] 传该关数组下标，[+ 新建关卡] 传 -1

| 检查项 | 规则 | 复用函数 |
|---|---|---|
| 长度 | `trace.length ≥ 4`（「至少走 4 格」）且 `≤ 64`（10×10 画布上限） | — |
| 越界 | 每格 x,y ∈ [1,10]（画时已拦，防御性再查） | — |
| **连续性**（Oracle N6 采纳） | 每相邻 trace 元素 4 邻接（末端生长保证；防御性兜底，断链时精准提示「路径有断开」而非误报「不止一条路」） | — |
| **无近路** | `noNear(trace, 10)`——任意非连续步轨迹格不得 4 邻接（**走廊无捷径前提**） | **现成 `noNear`** |
| **唯一路径** | `verifyUniquePath(trace, buildCorridor(trace, 10), 10, {x:1, y:1}, goal)`（Oracle B1：`{1,1}` → `{x:1,y:1}`；Oracle N1：verifyUniquePath 实际不消费 walls 参数——buildCorridor 结果供 startCustom 建墙用，与生成器 genLevel L217 用法一致） | **现成 `verifyUniquePath` + `buildCorridor`** |

> **为什么零新算法**：生成器已经用同一对函数校验程序生成的走廊（noNear 无近路 + verifyUniquePath 唯一路径）——编辑器产出只需喂同一校验器。**生成器与编辑器共用同一「走廊合法性」判定 = 单一实现防不一致**（对齐 simulate 纯函数先例）。

**校验结果**：
- 通过 → 「✓ 唯一路径！可以保存」（显示路径格数；Oracle N5：若 trace ≥ 40 格补「路径较长，执行约 X 秒」提示）
- 不通过 → 分级提示：长度不足「至少走 4 格」/ 连续性「路径有断开」（Oracle N6）/ 近路「这条路离太近，会抄近道」（引导孩子理解无近路）/ 唯一路径失败「不止一条路能到终点」（rare——noNear 通过后 BFS 唯一性应自动成立，防御性提示）

**保存**（Oracle I2 明确语义）：
- 校验通过才可保存（「✓ 保存成功」）；未校验/不通过 → 提示先检查
- **新建**（editIdx = -1）→ `addCustomLevel(trace, name)`（goal = trace 末端）
- **编辑已有**（editIdx ≥ 0）→ `updateCustomLevel(editIdx, trace, name)`——**覆盖同 id**（保留 id/createdAt，重置 solved=false；低龄心智「改了就是改了」）
- 保存 → 返回关卡库列表

### 2.4 自定义关卡练习（startCustom）

**进入**：关卡库列表点 [▶ 挑战] → `startCustom(idx)`（复刻 startGame 完整启动序列）：
```js
function startCustom(idx) {
  stopTimer();                             // 防重复 interval（⟲ 重置重载路径）
  state.finished = false;
  state.execLock = false; state.execDone = false; state.won = false;
  state.cmds = []; state.totalCmds = 0; state.firstFail = null;
  editCtx.loopIdx = -1; editCtx.innerIdx = -1;
  state.level = 'custom'; state.customIdx = idx;
  var cl = customLevels[idx];
  state.gridW = state.gridH = cl.gridW;    // 固定 10
  state.trace = cl.trace;                  // [{x,y},...]（Oracle B1：对象数组）
  state.walls = buildCorridor(cl.trace, cl.gridW);   // ★ 现成：轨迹格相邻非轨迹格 = 墙
  state.start = { x: 1, y: 1 }; state.startFace = 0;
  state.goal = cl.goal;                    // {x,y} = trace 末端（Oracle B1）
  state.optimal = 0;                       // ★ Oracle I1-refine：显式重置 0（非"不设"——state 跨关残留，
                                           //   先玩内置关再进 custom 时 optimal 仍为 4，安全信号会失效；
                                           //   重置 0 使遗漏 early return 时星级显式 1★（测试必捕获））
  state.curPos = { x: 1, y: 1 }; state.curFace = 0;
  renderGame(); state.startMs = Date.now(); startTimer();
}
```

**星级：2★ 兜底**（与走迷宫 v1.9 custom b=null / 方块排列 v1.2 一致）：
- `finishLevel` custom 分支：`stars = 2` 写死（不走 optimal 公式）——自建走廊的**最优循环解不可简单算**（需要 pattern 分解识别，远超编辑器校验范畴）；通关即 2★ + `markCustomSolved` + history push `{level:'custom', customName}`
- 反馈文案 `（2★，自建关卡）`；不写 store.best/recent（防污染三档统计）
- 教学激励：自建关强调「用循环块/嵌套循环让机器人走到终点」而非拼星级

**custom 模式守卫清单**（D5 执行器天然安全——execStep 读 state.gridW/gridH/walls 而非 LEVELS_CFG，故守卫点少于 D4）：

| 位置 | v1.1 现状 | v1.2 custom 守卫 |
|---|---|---|
| renderGame 顶栏 | `LEVELS_CFG[state.level].label + ' · 让机器人到 ⭐'` | `state.level === 'custom' ? customLevels[state.customIdx].name : LEVELS_CFG[state.level].label` |
| finishLevel | 写 store.best/recent + optimal 公式星级 | **custom 分支**（Oracle I1 修订）：不写 best/recent；`stars = 2`；`markCustomSolved(state.customIdx)`；history push `{level:'custom', customName, stars: 2, cmds}`；**设反馈 `（2★，自建关卡）` 后 return——不进入 L916-929 optimal 公式代码**（消除「反馈同格式」矛盾）；不访问 state.optimal |
| nextLevel | 同难度再来 | 顶部 `if (state.level === 'custom') { viewCustomList(); return; }` |
| ⟲ 重置 | 就地重置 | **天然安全（Oracle N2）**：⟲ 按钮就地清指令复位，不读 LEVELS_CFG/不调 genLevel——custom 同内置关行为，无需特殊守卫 |
| viewParent history | `LEVELS_CFG[h.level] ? label : h.level` | `h.level === 'custom' ? ('自建关卡·' + h.customName) : ...` |
| 清除所有数据 | `storage.remove('v1')` | **追加 `storage.remove('customLevels')`**（+ `customLevels = []` 内存同步） |
| **viewCustomList** | —（新视图） | 顶部 `stopTimer()` |
| startGame | — | **补 `editCtx.loopIdx = -1; editCtx.innerIdx = -1;`**（与 startCustom/nextLevel 对齐，防两层编辑残留——现有 renderBlockEdit/addBodyCmd 防御性自愈但脆弱，显式重置更稳） |

> 执行器（execRun/execStep）读 state.gridW/gridH/walls/goal——startCustom 已全部设置，**天然无 LEVELS_CFG 依赖**（D5 v1.1 起 gridW/gridH 存 state 而非读 cfg，D4 的 size 守卫在此不需要）。
