## 2. 玩法设计

### 2.1 核心玩法

1. 给定**目标布局**（K 个四格骨牌堆成的图案，橙色半透明叠加在盘面上）；
2. **v1.1 多块整体编排**：孩子为**全部 K 块**每块编排指令（块 tab 切换编辑）：`↻ 旋转`（×1/×2/×3）/ `⬅ 左移` / `➡ 右移`（参数化 N 格）/ `⬇ 落下`；
3. 点「▶ 执行」→ 按块顺序统一执行（动画逐步：每块旋转 → 移动 → 落下 → 落定 → 下一块，不中断）→ 全部 K 块落定；
4. 程序**逐格比对**最终网格 vs 目标网格 → 一致 = 答对（统一判定）。

> **v1.1 教学升级**（v1.0 单块试错式 → v1.1 整体规划式）：孩子需**提前规划**——先想好所有块怎么放（参照目标图案与已规划块落位），编完整套指令，一次执行看结果。「程序 = 完整的指令序列」心智（提前规划/批量化）。

> **v1.2 创作闭环**（关卡编辑器）：孩子**自己画目标图案**（10×10 网格涂色）→ **可拼校验**（两阶段：分割枚举 + 落定验证，与生成器同一落定物理）→ 保存到关卡库 → 从首页/列表**挑战自建关**（2★ 兜底）。角色反转：设计图案时理解「方块从上往下落」「四格骨牌 7 型 × 4 旋转」——比解题更深的构建结构理解（对齐走迷宫 v1.9 出题教学）。

### 2.2 判定（有标准答案）

| 判定维度 | 机制 |
|---|---|
| 对/错 | 最终网格 vs 目标网格逐格比对（程序可判定，非表现性分数） |
| 逐块即时反馈 | 每块落定后检查「已放但不在目标中的多余格」→ 「这一块有 N 格放偏了（红色标记）」 |
| 星级 | 指令条数（参数化语义：旋转 1 条/移动 1 条/落下 1 条）vs 最优解（≤1.5× = 3★，≤2.5× = 2★） |

### 2.3 指令与执行语义

- **指令固定三段**：旋转 → 移动 → 落下（不可重排，低龄认知负担低）；
- **参数化 chip**：旋转 chip 单击递增 1→2→3→1（转 N 次）；移动 chip 递增 1→2→…→max→1（移 N 格，max=W-1）；
- **边界语义**：移动超出棋盘 → 截断到边界（不判非法）+ 块闪烁「到边了」提示；
- **执行锁定**：执行中禁用指令编辑（防错位）。

### 2.4 三档难度

| 档 | 盘面 | 块数 | 骨牌型 |
|---|---|---|---|
| 简单 | 6×6 | 2 | 6 型（排除 O 型，旋转无变化易困惑） |
| 普通 | 8×8 | 4 | 7 型 |
| 挑战 | 10×10 | 6 | 7 型 |

## 3. 关卡生成器（程序化，必有解）

- 随机取 (type, rot, col) → `dropRowFor()` 模拟落下堆叠（与执行器**共用同一函数**，单一实现防不一致；v1.2 参数化为 `dropRowForW(type,rot,col,placed,gridW,gridH)`，现有 `dropRowFor` 委托——编辑器 checkSolvable 复用同一物理）；
- 目标布局 = 生成过程落定结果（**必有解**：生成即执行）；最优解 = Σ((rot?1:0) + (col≠mid?1:0) + 1)；
- col 生成事前约束 `rand(W - pieceWidth + 1)` 不越界；重试上限 500；
- 生成器专项验证 600/600（3 难度 × 200 轮：必有解/最优解公式/不越界/排除 O 型全过）。

## 3A. 关卡编辑器（v1.2，创作闭环）

- **入口**：首页「🛠 自建关卡 (N)」→ 关卡库（列表/新建/编辑/删除/挑战）→ 编辑器；
- **编辑器**：10×10 网格单层涂格（画格/橡皮，pointer 拖动，画格 = 橙色半透明同目标叠加色）；名称 ≤12 字；校验/保存/清空；
- **可拼校验 `checkSolvable`（两阶段）**：阶段 1 分割枚举（纯覆盖 DFS——target 的 K 块分割，最左上未覆盖格必被某块覆盖，occupied⊆target 剪枝，与顺序无关完备）；阶段 2 落定验证（贪心从底到顶——块 row+1 处与已放格交集或触底即可放，精确匹配 dropRowFor「停在首个重叠行上一行」语义；无可放块且未放完 = 该分割不可拼，继续找下一分割）；节点上限 20 万 → 「暂不确定」；
- **约束检查**：格数 4 的倍数 / ≥4 / ≤24（6 块上限）；悬空图案（上格无下支撑）不可拼（落定物理教学点）；
- **数据**：`customLevels`（`redtools.fangkuai.customLevels`，无 .v1. 段）上限 20 关；存 cells（trim 后坐标）+ gridW/gridH + **refPieces**（阶段 2 验证通过的合法放序——custom 关卡 pieces 骨架/块 tab UI，不强制）；
- **练习**：`startCustom(idx)` 复用 v1.1 完整编辑 UI（块 tab = refPieces K 块）；星级 **2★ 兜底**（无 optimal，refPieces 是任意合法解非最优）；不写 store.best/recent；通关 markCustomSolved（「已解」徽章）；「再来一题」回关卡库；重新生成不适用（重载同关）；清除数据随 customLevels 一并删除。

## 4. 复用与双模式

- **复用**：俄罗斯方块 `SHAPES`（7 型 × 4 旋转态几何）+ 机器人走迷宫 UI/持久化/星级模式；
- **持久化**：`LX_SHARED.storage.configure({toolName:'fangkuai'})` → `redtools.fangkuai.v1`；
- **双模式**：offline（zip → publish）+ online（部署目录），index.html 在 data.js 后注入 lx-shared.js。

## 5. 合规自检（Chrome 61 / 容器规范）

- JS：经典脚本（无 module/import/export）、ES2017 内（无 `?.` `??` 对象展开）、事件全部 addEventListener；
- CSS：无 flex gap / aspect-ratio / clamp / 逻辑属性 / :has；Flex 子项 min-width:0；
- CSP：无 fetch/XHR/Worker/定位/剪贴板/window.open、无外部 http(s) 引用、无内联事件；
- 命名：无「游戏/闯关/胜利/得分」字样（合规自查 PASS）；
- 数据最小化：仅关卡进度/星级/打卡，纯离线。
