## 2. 玩法设计

### 2.1 规则

- 迷宫盘面 = 推箱子关卡（Microban I，XSB 格式）：墙、地板、目标点、箱子。
- 孩子用**指令积木**编排机器人的移动序列：`↑ 前进` / `↰ 左转` / `↱ 右转` / `🧱 前方探测`。
- 点「▶ 执行」后机器人按指令序列移动；**前方有箱子则推动**（推箱逻辑同推箱子）。
- 胜利条件：执行完成后**所有箱子都在目标点**（isWon 判定）= 有标准答案。
- 失败不惩罚：执行完箱子未到位 → 提示「还有箱子没到目标点，调整指令再试」。

### 2.2 指令系统（v1.0 → v1.5，编程教学核心概念路线）

| 版本 | 概念 | 指令 | 说明 |
|---|---|---|---|
| v1.0 | 顺序 | ↑ 前进 / ↰ 左转 / ↱ 右转 | 顺序编排 + 观察调试 |
| v1.1 | 循环 | 指令 chip ×2/×3/×4 | 单击 chip 循环次数递增（1→2→3→4→1），循环启蒙 |
| v1.3 | 条件 | 🧱 前方探测 | **探测前方**：前方为墙/箱子/边界 → 条件成立「不前进」；前方空地 → 前进一格（避障守卫） |
| v1.5 | 分支 | **❓ if前方有墙** | **if/else 条件分支**：前方有墙/箱子/边界 → 执行 then 分支指令组；否则 → 执行 else 分支指令组 |
| v1.6 | 参数化 | **➡ 走N步** | **参数化移动**：一次直线移动 N 格（N=1..9 参数），区别于 rep 的重复单步 |
| v1.7 | 循环块 | **🔁 循环** | **显式循环块**：一组指令重复 N 次（循环=自动化），块内可嵌 if/steps（控制结构组合） |
| **v1.8** | **嵌套循环** | **🔁 内嵌 🔁** | **嵌套循环**：循环块内嵌循环块（二维重复/嵌套结构，循环套循环） |
| **v1.10** | **抽象/封装** | **🧩 我的块** | **自定义指令块**：孩子把自己的一段指令序列封装成命名块，主序列一条 `🧩块名` 引用即执行（函数/子程序启蒙，Scratch My Blocks） |
| **v1.11** | **块参数** | **🔢 带参数** | **函数参数化**：块 body 含参数化 steps（`➡N步(N)`，距离由调用方传入 1-9）——同一块不同参数不同行为（Scratch 带输入积木进阶） |
| **v1.12** | **参数贯穿** | **🔢 带参数（增强）** | **N1 多处参数化**：一个参数 N 贯穿块内所有 steps（方形/拐角模式）+ **N2 显示分离**（定义态 `➡?步` 占位 / 调用态具体数字） |

- **🧱 前方探测（v1.3 新增）**：一个「安全前进/避障」条件指令——机器人先看前方有没有障碍，
  没有才动。孩子用它避免「撞墙/撞箱」，为 if/else 条件分支打基础（单指令级条件判断）。
- **❓ if前方有墙（v1.5 新增）**：**多指令分支结构**——如果前方有障碍（墙/箱/边界），执行
  **then 分支**（一组指令）；否则执行 **else 分支**（另一组指令）。这是编程核心概念「分支结构」
  （if/else）的正式教学，与 v1.3 单指令「条件跳过」构成递进：条件跳过是「成立就不走这一步」，
  分支是「成立走 A 组指令，不成立走 B 组指令」。
- 单条指令可带循环次数（rep），循环在**执行时展开**：指令实际执行 rep 次，动画可见。
- 星级基准 = **实际执行步数**（循环展开后 totalSteps；if 块计 1 条 + 分支内指令数）vs 关卡最优 b。

### 2.4 v1.5 if/else 条件分支教学（新）

**教学定位**（方案 §1.4）：全可见棋盘上 if/else 不是「必要条件」（孩子可预先知道方向），
而是**更高效编程策略**——岔路口关卡中，展开写需要为每个岔路口写多条转弯指令，
用 `❓ if前方有墙` 一个指令块即可让机器人自动按前方状态走对应分支。类比 v1.1 循环指令：
展开写也能解，但循环/分支块更高效（编写量更少 → 星级更高）。

**数据结构**：`{ id:'if', then:[指令对象数组], else:[指令对象数组] }`（无 rep 字段；
if 块是条件分支不是循环，`cycleRep()` 跳过）。

**执行语义**（工作队列模型）：
1. 求值条件：机器人前方（当前 face 方向）越界/墙/箱子 = 有障碍
2. 有障碍 → 执行 `then` 分支内全部指令；无障碍 → 执行 `else` 分支内全部指令
3. 分支内可含：前进/左转/右转（含 rep）/嵌套 if 块（v1.5 限制最多嵌套 2 层）
4. 分支内指令执行时继承父级 if 块的顶层下标（高亮/失败定位回溯到父级 if chip）

**关卡设计**（v1.5 新增 20 关 156-175，全部推箱子 + 岔路口）：
- 每关含 1-2 个「岔路口」：机器人站在岔路口，前方有墙（then 路）vs 前方无障碍（else 路）
- **展开写可解**（不强制用 if），但用 if/else 编写量更少 → 星级更高（激励分支结构）
- 三档渐进：156-165 简单（单岔路）→ 166-172 进阶（双岔/长推）→ 173-175 挑战（嵌套/多箱）
- b 值 = BFS 求解器自动计算的展开解指令数（脚本验证 20/20 可解）

### 2.5 v1.6 参数化移动教学（新）

**教学定位**（方案 v1.6 §1.2）：参数化 = 指令携带数量参数，一次表达多次移动。
与 v1.1 rep（循环）区别：rep 是"重复执行单步"（每次独立判断），steps 是"一次直线移动 N 格"（参数=距离）。
**行为差异即教学点**：`↑×3` 撞墙会失败（每次尝试独立），`➡走3步` 撞墙自动停（像人走路走到墙停）——
两者行为不同，正是区分"循环"与"参数"的直观体现。

**数据结构**：`{ id:'steps', steps:1 }`（参数 1..9，**无 rep 字段**——steps 与 rep 互斥，
`_loopLeft=1` 天然不叠加）。执行期字段 `_stepsLeft`/`_stepsMoved`。

**交互**（复用 v1.5 chip 点击循环模式 + D4 参数化先例）：
- 点击指令区 `➡N步` 按钮 → 追加 steps 指令
- 点击序列 steps chip → 参数递增 1→2→3→…→9→1（9 上限，区别于 rep 的 4 上限）
- ✕ 删除同其他指令

**执行语义**（逐格动画，工作队列复用）：
1. 每格调用共享 `tryMoveFwd()`，与现有 260ms 步进节奏一致（**逐格动画**，可见推箱过程）
2. 遇障碍（墙/越界/箱推不动）→ 停止（安全行为，同 fwd 撞墙）
3. 失败语义：`_stepsMoved=0`（第一步即撞墙）→ 记 firstFail；已走 ≥1 格后撞墙 → 正常停止不记失败
4. steps 可在 if 分支内使用（editCtx 支持添加，`_execTop` 继承机制不变）

**共享移动函数**（v1.6 重构）：`tryMoveFwd()` 返回 `{moved, reason}`，fwd/steps 共用；
block（前方探测）保留原内联逻辑（不推箱，前方有箱视为障碍）。消除 fwd/steps 移动逻辑重复。

**关卡设计**（v1.6 新增 10 关 176-185，6 类模板）：
- 长直推箱（176-177/179）→ L 型走廊（178）→ 中途障碍（180-181）→ 多箱直推（182-183）
  → 路径选择（184）→ 混合 if+steps（185）
- 每类保证：展开写（N×fwd 或 rep）≥ 1.5×b → 用 steps 才 3★（激励参数化）
- **b 值口径**（v1.6）：176-185 新关 `b` = **含 steps 的最优编写量**（一条 steps 计 1 条，
  BFS 枚举 `{id:'steps', steps:N}` 为单条指令）；1-175 旧关 `b` 保持 push count 不动（不回归）

**星级**：totalSteps 中 steps 计 1 条（`c.rep||1` 对 steps 天然 =1）；新关 `steps <= b*1.5 → 3★`。

### 2.6 v1.7 循环块教学（新）

**教学定位**（方案 v1.7 §1.2）：显式循环块 = **一组动作**重复做（循环=自动化），
区别于 v1.1 `×N` 单动作重复（重复=机械复制）。**循环块内可嵌 if/steps** = 控制结构组合
（循环+分支+参数叠加）——编程进阶核心。

**与 D5「循环指令」区别**：D5 独立工具专训循环（body 仅简单动作）；走迷宫 v1.7 支持
**循环块内嵌 if/steps**（组合控制结构），教学进阶是"循环里判断、循环里参数化"。

**数据结构**：`{ id:'loop', rep:2, body:[指令对象数组] }`
- body 内可含：fwd/left/right/block/steps/if（组合）
- body 内禁 loop（MVP 单层，D5 同款）；body 内 if 可嵌套 ≤2 层（同 v1.5）
- 循环次数 rep 2→3→4→5→2（起始 2，1 次无意义）

**执行语义**（工作队列复用）：
1. loop 轮数**复用 rep-on-cmd**（`_loopLeft` 处理，execStep 开头对 loop 已正确回插 rep 次）
2. `execLoop` 只插入 body 到队首（不碰 `_loopLeft`，职责单一）
3. **B1 修复**：execLoop 每轮 `resetLoopLeft(cmd.body)` 清 body 执行期状态（共享引用残留防 bug）
4. **I-new 修复**：body 指令 `_execTop` 无条件覆盖（与 execIf F1 一致，防跨轮残留）

**关卡设计**（v1.7 新增 10 关 186-195，循环块专关）：
- 直线重复（186-187）→ 旋转重复（188-189）→ 循环+steps（190-191）→ 循环+if（192-193）→ 综合（194-195）
- 每类保证：展开写 ≥ 1.5×b → 用循环块才 3★（激励循环）
- **b 值口径**（v1.7）：186-195 新关 `b` = BFS 展开解长度（循环块编写量 < b → 3★）；
  1-185 旧关不动

**星级**：totalSteps 中 loop 计 `1 + totalSteps(body)`（递归，body 内 if 同口径 1+then+else）；
新关 `totalSteps <= b*1.5 → 3★`。

### 2.7 v1.8 嵌套循环教学（新）

**教学定位**（方案 v1.8 §1.2）：嵌套循环 = **循环套循环**（二维重复/嵌套结构）。
v1.7 `🔁×N {组指令}` = 一组动作重复 N 次（循环=自动化）；v1.8 `🔁×M {🔁×N {指令}}` =
一组动作重复 N 次，整套再重复 M 次（**嵌套循环**=二维自动化）。
教学价值：外层循环每轮执行一次内层循环的完整 N 次（类比乘法表/网格清扫）。

**范围限制**（Oracle I3）：**仅支持 loop-in-loop**（循环体内直接嵌循环）。
**loop-in-if-branch 不支持**——if 的 then/else 编辑区（renderBranchCol）不提供 🔁 按钮。

**数据结构**：`{ id:'loop', rep:N, body:[{id:'loop', rep:M, body:[...]}] }`（body 内嵌 loop，≤2 层）

**执行语义**（工作队列天然支持，Oracle 推演验证）：
1. 外层 loop 每轮 execLoop 插入内层 loop → 内层 loop 完整执行 rep 次 → 外层下一轮
2. **B1 递归覆盖内层 _loopLeft**：execLoop 的 `resetLoopLeft(cmd.body)` 递归清内层 loop._loopLeft
   （Oracle 逐步推演：loop×2{loop×2{fwd}} → fwd 执行 4 次 ✅）
3. **I-new _execTop 继承**：内层 loop._execTop = 外层 loop._execTop（无条件覆盖）
4. **MAX_QUEUE 安全**：2 层嵌套峰值 queue ~10-15，远低于 500

**editCtx 嵌套编辑**（Oracle I2）：
- renderLoopBody 添加按钮加 CMD_LOOP + `loopDepth()` 守卫（编辑栈 loop 帧数 ≤2）
- body 内 loop chip：lbl 显示 `🔁×N`（绿色 `.loopb`），click → openNestedEditCtx（打开内层编辑区）
- 内层编辑区有「返回上层」按钮（goBackEditCtx）
- loopDepth 与 ifDepth 独立计数（loop 帧不计 ifDepth，if 帧不计 loopDepth）

**关卡设计**（v1.8 新增 10 关 196-205，嵌套循环专关；v1.8.1 按 Oracle 审核 F1-F5 重做 2D 盘面）：
- 方向多样（右推/左转上推/右转下推）+ 结构多样（纯嵌套 fwd / 嵌套+steps / 概念教学关）：
  196 右推6格 `🔁×2{🔁×3{fwd}}` → 197 左转上推6格 → 198 右推6格 `🔁×3{🔁×2{fwd}}` → 199 右转下推6格 → 200 嵌套+steps → 201 左转上推 steps → 202 概念教学关（最小嵌套，豁免激励）→ 203 右转下推 steps → 204 右转下推8格 → 205 左转上推8格
- **2D 教学**（Oracle F3/F5 修复）：目标唯一且远离箱 → **单条 fwd 不可解**；转向（left/right）引入二维推箱路径；10 关盘面全部去重（F1/F2）
- **b 值口径**（Oracle B1 修订）：196-205 新关 `b` = **嵌套解 totalSteps**（非 BFS 展开长度）！
  展开写 totalSteps > 1.5×b → 2★；嵌套写 = b → 3★（激励成立）
- 202 属**概念教学关**（最小嵌套演示，不强求星级激励；其余 9 关展开/嵌套比 ≥1.75 激励成立）

**星级**：totalSteps 中嵌套 loop 递归计（`🔁×2{🔁×2{fwd}}` = 3）；新关 `totalSteps <= b*1.5 → 3★`。

### 2.8 v1.9 关卡编辑器（新）

**教学定位**（方案 v1.9 §1.2）：八块概念全部「解题」单向路径 → v1.9 补**创作闭环**（出题能力）：孩子**自己设计关卡**（墙/箱/目标/玩家）→ 可解性校验 → 本地保存 → 从首页进入自建关挑战。设计关卡须理解「箱子能否被推到目标」——比解题更深的盘面结构理解。

### 2.9 v1.10 自定义指令块（新）

**教学定位**（方案 v1.10 §1.2）：既有 7 种指令 = 系统给的积木；v1.10 = **孩子自造的积木**

### 4.2 执行器（v1.8 工作队列模型 + 共享移动函数 + 循环块/嵌套循环）

```
execRun(): 已执行/已通关/空序列 → return；loadLevelState() 重置盘面
  execQueue = cmds.slice()（浅拷贝，指令对象共享引用）
  顶层指令标记 _execTop = i（分支指令插入时继承父级 if/loop 的顶层下标）
  resetLoopLeft(cmds) 递归清零 _loopLeft + v1.6 _stepsLeft/_stepsMoved（含 then/else 分支 + loop.body）
execStep(): queueIdx ≥ execQueue.length → execDone + checkWin()
  execQueue.length > MAX_QUEUE(500) → 自动终止（防 if/steps/loop 无限展开）
  cmd = execQueue[queueIdx]; queueIdx++
  absStep++；curTop = cmd._execTop（分支指令高亮父级 if/loop chip）
  rep-on-cmd：_loopLeft===undefined ? 初始化 rep||1；_loopLeft>0 → splice 回队首（再执行一次）
    （steps 无 rep → _loopLeft=1 → no-op；loop 的 rep 即轮数 → 复用此机制）
  按 id 分发：
    left: face=(face+3)%4   right: face=(face+1)%4
    if:   execIf(cmd) — 求值前方障碍 → 选中分支插入队首
    loop: execLoop(cmd) — 轮数已由 rep-on-cmd 处理，只插入 body
    steps: 逐格动画（工作队列复用）：tryMoveFwd() 走 1 格，_stepsLeft--/_stepsMoved++
          仅"移动成功且未走完"才 splice 回队首（撞墙即停，无死循环）
          _stepsMoved=0 第一步撞墙 → 记 firstFail；中途撞墙 → 正常停止
    fwd:   tryMoveFwd() — 失败记 firstFail（reason 分类 wall/edge/box）
    block: 保留原内联逻辑（只在前方空地前进，不推箱；不记 firstFail）
  renderBoardOnly() + renderSeqHighlight() + setTimeout(260ms) 步进

tryMoveFwd(): 共享前进一格，返回 {moved, reason:'ok'|'wall'|'edge'|'box'}
  越界→edge；墙→wall；箱→可推则推（推箱同推箱子）否则 box；空地→前进
  fwd/steps 共用；block 不用（不推箱语义）

execIf(cmd): 前方越界/墙/箱子 = hasObstacle
  branch = hasObstacle ? cmd.then : cmd.else
  branch 指令无条件继承父级 _execTop（F1 修复：防跨轮残留）→ splice.apply(execQueue, [queueIdx, 0].concat(branch))

  B1 修复：resetLoopLeft(def.body) 展开前清执行期状态（共享引用防污染；I2：参数块副本全新为空操作，非参数块必需）
  body 指令无条件继承父级 _execTop（I-new，与 F1 一致）→ splice.apply(execQueue, [queueIdx, 0].concat(body))
  execStep call 分支：getCustomBlock(bid) 不存在（块已删）→ 反馈「块已删除」+ 终止（不崩溃）
  v1.11 参数注入：blockHasParam(bid) 时生成运行时副本（map 浅拷贝 + steps:null 填 call.param）——
    同一参数块不同 call 不同 param 互不污染（块库 body 永不被写参数值）；无参数块保持共享引用

execLoop(cmd): v1.7/v1.8 显式循环块
  B1 修复：resetLoopLeft(cmd.body) 轮间重置（共享引用残留防 bug：body 内 rep>1/steps/嵌套 loop 每轮完整执行）
  body 指令无条件继承父级 _execTop（I-new 修复，与 F1 一致）→ splice.apply(execQueue, [queueIdx, 0].concat(body))
  v1.8 嵌套：body 内嵌 loop 由内层 execLoop 处理（外层每轮插入内层，内层完整执行 rep 次）
  loopDepth()：编辑栈中 loop 帧数（≤2，嵌套循环深度守卫）

resetLoopLeft(cmds): 递归遍历 cmds + then/else 分支 + loop.body（含嵌套 loop），清 _loopLeft/_stepsLeft/_stepsMoved
```

  - v1.5 if 块计编写量 = 1 + then.length + else.length
  - **v1.6 新关 176-185**：b = **含 steps 的最优编写量**（一条 steps 计 1 条）；steps 指令计 1 条
    （`c.rep||1` 天然 =1）→ 展开写 ≥1.5×b 封顶 2★，用 steps 才 3★（激励参数化）
  - **v1.7 新关 186-195**：b = BFS 展开解长度；loop 计 `1 + totalSteps(body)`（递归，body 内 if 同口径）
    → 展开写 ≥1.5×b 封顶 2★，用循环块才 3★（激励循环）
  - **v1.10 块引用全局口径**：call 计 `1 + body 一次`（seenBlockIds 按 bid 去重，body 不乘调用次数；
    单次 call 比直接写多 1 开销防单块刷分，多次复用 N+body 有收益）；0 新关（b 值/数据零改动）
  - **v1.11 参数块同口径（I1 统一）**：参数块/非参数块统一 `n += totalSteps(bd.body)`（steps:null 经
    `c.rep||1` 计 1）；K≥2 参数块 3+ 调用复用优（块 5 vs 展开 6）；K=1 纯单条参数块无激励（N3 引导多指令块）
  - b=null（19 关求解超时）：通关 2 星封顶
  - 重复通关仅当星级更高或推进更远才覆盖 best
- **打卡**：通关一关写入今日（去重、365 天滚动）、重算连续天数（对齐 `docs/通用需求-打卡分享记录.md`）。
