## 1. 背景与目标

### 1.1 背景与现状

方块排列指令 v1.0 = **单块编排**（逐块试错式）：
- 一次只编**当前块**（state.curIdx 指向）的指令（rot/left/right/drop）
- 点 ▶ 执行 → 当前块按指令落定 → 立即检查差格 → 清空 cmds → 编下一块
- 孩子逐块「编 → 执行 → 看反馈 → 改」，每块独立循环，无需全局预判
- 星级 = Σ每块指令数 vs 最优解（生成器 = 顺序落定，参考解即生成时 rot/col）

**缺口**：无法**整体规划**——孩子不能先想好所有块怎么放，再一次性编写完整指令序列执行。
教学上，「程序 = 完整的指令序列（先规划、后执行）」是核心心智，v1.0 的逐块试错式弱化了这一点。
设计文档 §9 明确候选「多块整体编排」。

### 1.2 教学定位

| 版本 | 玩法模式 | 教学价值 |
|---|---|---|
| v1.0 | 单块编排（编一块→执行→下一块） | 顺序 + 旋转 + 参数化移动（试错式反馈） |
| **v1.1** | **多块整体编排（全部编完→统一执行）** | **提前规划 / 批量化**：「程序 = 完整的指令序列」——先想好 K 块怎么放（参照目标图案与已规划块的落位），编完整套指令，一次执行看结果 |

- 与走迷宫「先编完整指令再执行」对齐（走迷宫就是整体编排——方块排列 v1.0 反而偏试错）
- 目标图案在盘面半透明叠加——整体规划的「参照物」已具备；孩子需预判每块与目标/已规划块的重叠
- 失败后仍可定位（差格红框 + 逐块核对第几块放偏）

### 1.3 目标

| 项 | 说明 |
|---|---|
| 玩法变化 | 指令编辑区改为**全部 K 块的指令序列**（块 tab 切换各块指令）；▶ 执行 = 按块顺序统一执行全部 |
| 教学 | 提前规划：先想好所有块怎么放（对齐目标/避免重叠），完整编写，一次执行 |
| 保留 | 旋转/参数化移动语义、生成器（顺序落定）、差格红框定位、星级口径、存储/打卡/双模式 |
| 范围 | 0 新关；不改生成器/落定物理；**指令序列数据结构重构**（cmds → blockCmds[K]）；存量进度兼容 |

## 2. 变更设计

### 2.1 数据模型（核心：cmds → blockCmds）

```js
// v1.0：state.cmds = [当前块指令 {id, val}]（编完一块清空）
// v1.1：state.blockCmds = [[块0指令], [块1指令], ..., [块K-1指令]]（每块独立序列，整体编辑）
//       state.curEditIdx = 当前编辑的块下标（tab 切换）；执行时按块顺序消费
// 兼容：cmdCounts 不再需要（Σ blockCmds[i].length 即时可算——星级用）
// 存储：不持久化指令（同 v1.0）——仅关卡进度/星级/打卡
```

- **新增 state.curEditIdx**（编辑态当前块，0..pieces.length-1；startGame 重置 0）
- **新增 state.blockCmds**（数组数组）：startGame/nextLevel/resetBtn 重置为 `pieces.map(function(){ return []; })`
- **移除 state.cmdCounts**（star: `total = Σ blockCmds[i].length`，空块计 0）；无引用残留（grep 断言验证）
- **cmds 语义** → `blockCmds[curEditIdx]`（编辑/渲染）；执行时按 curIdx 顺序取（N-1 引用清单见 §4.1）

### 2.2 编辑器 UI（块 tab + 整体指令区）

```
┌─────────────────────────────────────────────┐
│ 目标：把方块排成橙色图案                      │
│ [第1块 ▮▮▮] [第2块 ▯] [第3块 ▯] … ─块 tab 切换│
│ 盘面（半透明目标 + 已落块 + 差格红框）        │
│ 当前块预览 + 指令序列（当前 tab 的块）        │
│ [↻旋转][⬅左移][➡右移][⬇落下]                │
│ [▶ 执行] [⟲ 重置] [再来一题 ›]               │
└─────────────────────────────────────────────┘
```

- **块 tab 行**（新增，`.block-tabs`）：每块一个 tab（`第N块` + 类型色块小图标），当前编辑块高亮
  - 点击 tab → `state.curEditIdx = N` → renderSeq/预览刷新
  - 执行中（execLock）禁用 tab（防错位）——**I-3 Oracle：setCmdLocked 选择器扩展加 `.block-tab`**
- **指令序列**：编辑 `blockCmds[curEditIdx]`（当前 tab 块的序列）——chip 交互同 v1.0（cycleParam/removeCmd）
- **添加行/清空**：作用于 blockCmds[curEditIdx]
- **预览（I-3 Oracle：curIdx → curEditIdx）**：编辑态（state.cur 为 null）预览取 `pieces[curEditIdx]`（替代
  v1.0 的 `pieces[curIdx]`——tab 切换时预览换块）；执行态（state.cur 存在）显示执行快照（不变）
- **进度指示**：编辑态顶栏「已编 X/K 块指令」（X = 有指令的块数，非强制）；执行态「执行中 N/K」

### 2.3 执行器（按块顺序统一消费）— I-1/I-2/I-4 Oracle 修订：完整状态机

**execRun 入口（I-2/I-4 Oracle 修订——守卫重设计 + 执行态重置）**：

```js
// v1.1（I-2）：入口守卫——全空提示，非静默 return；首块空不阻塞（endBlock 原位落定续跑）
function execRun() {
  var total = 0;
  for (var bi = 0; bi < state.blockCmds.length; bi++) { total += state.blockCmds[bi].length; }
  if (total === 0) {
    var fb0 = document.getElementById('game-feedback');
    if (fb0) { fb0.textContent = '😅 先给至少一块编指令，再点执行！'; fb0.className = 'game-feedback miss'; }
    return;
  }
  if (state.execLock || state.execDone || state.won) { return; }
  // v1.1（I-4）：全量执行前置重置——curIdx=0 + placed=[]（一次性全量执行，防重玩残留）
  state.curIdx = 0;
  state.placed = [];
  state.execLock = true;
  state.diffCells = null;
  setCmdLocked(true);
  // 第 0 块执行快照
  var pc = state.pieces[0];
  state.cur = { type: pc.type, rot: 0, col: Math.floor(state.gridW / 2), cells: null };
  state.cmdProg = 0;
  execCmdStep();
}
```

**execCmdStep 改造（I-1 Oracle 修订——endBlock 提取 + 块间续跑状态机）**：

```js
// v1.1：从当前块 blockCmds[curIdx] 逐条执行；本块指令耗尽 → endBlock 落定 → 续下一块
function execCmdStep() {
  var cmdsThis = state.blockCmds[state.curIdx] || [];
  if (state.cmdProg >= cmdsThis.length) { endBlock(); return; }   // 本块完成（含空块：0>=0 直接落定）
  var cmd = cmdsThis[state.cmdProg];
  state.cmdProg += 1;
  var cur = state.cur;
  if (cmd.id === 'rot') { cur.rot = (cur.rot + cmd.val) % 4; renderPreview(); setTimeout(execCmdStep, 300); }
  else if (cmd.id === 'left') { cur.col -= cmd.val; if (cur.col < 0) { cur.col = 0; flashEdge(); } renderBoardOnly(); renderPreview(); setTimeout(execCmdStep, 300); }
  else if (cmd.id === 'right') { var info = pieceInfo(cur.type, cur.rot); var maxCol = state.gridW - info.w; cur.col += cmd.val; if (cur.col > maxCol) { cur.col = maxCol; flashEdge(); } renderBoardOnly(); renderPreview(); setTimeout(execCmdStep, 300); }
  else if (cmd.id === 'drop') {
    var pc2 = state.pieces[state.curIdx];
    var placedCells = [];
    for (var p2 = 0; p2 < state.placed.length; p2++) { placedCells.push({ cells: state.placed[p2].cells }); }
    var row2 = dropRowFor(cur.type, cur.rot, cur.col, placedCells);
    cur.row = row2 < 0 ? 0 : row2;
    cur.cells = absCells(cur.type, cur.rot, cur.col, cur.row);
    setTimeout(execCmdStep, 300);
  }
}
// v1.1（I-1 Oracle）：块结束状态机——落定 + 续下一块（或统一判定）
//   关键 6 处变更（对照 v1.0 L580-584）：
//   ① 删 cmdCounts.push（cmdCounts 移除，星级改 Σ blockCmds）② 删 execLock=false（多块续跑保持锁定）
//   ③ 删 setCmdLocked(false)（保持 UI 锁定防切 tab）④ 删 cmds=[]（blockCmds 持久）
//   ⑤ 新增 state.cur 重建（下一块快照）⑥ 新增 setTimeout 续跑
function endBlock() {
  var cur = state.cur;
  var pc = state.pieces[state.curIdx];
  var placedCells = [];
  for (var p = 0; p < state.placed.length; p++) { placedCells.push({ cells: state.placed[p].cells }); }
  var row = dropRowFor(cur.type, cur.rot, cur.col, placedCells);
  if (row < 0) { row = 0; }
  cur.row = row;
  cur.cells = absCells(cur.type, cur.rot, cur.col, row);
  state.placed.push({ type: cur.type, rot: cur.rot, col: cur.col, row: row, cells: cur.cells });
  state.curIdx += 1;
  renderBoardOnly();
  var prog = document.getElementById('game-prog');
  if (prog) { prog.textContent = LEVELS_CFG[state.level].label + ' · 执行中 ' + state.curIdx + '/' + state.pieces.length + ' 块'; }
  if (state.curIdx >= state.pieces.length) {
    state.execDone = true;
    state.execLock = false;
    setCmdLocked(false);
    checkWin();
  } else {
    // 逐块差格即时提示（N 级保留——不中断执行）
    var excess = calcExcessCells();
    var fb = document.getElementById('game-feedback');
    if (excess && excess.length > 0) {
      state.diffCells = excess;
      if (fb) { fb.textContent = '块 ' + state.curIdx + ' 已落定（有 ' + excess.length + ' 格放偏，执行完再调整）'; fb.className = 'game-feedback miss'; }
      renderBoardOnly();
    } else if (fb) { fb.textContent = '第 ' + state.curIdx + ' 块落定，继续执行…'; fb.className = 'game-feedback ok'; }
    // ⑤⑥ 下一块执行快照重建 + 短延迟续跑（空块也走此路径——原位落定，300ms 视觉过渡）
    var pcN = state.pieces[state.curIdx];
    state.cur = { type: pcN.type, rot: 0, col: Math.floor(state.gridW / 2), cells: null };
    state.cmdProg = 0;
    renderPreview();
    setTimeout(execCmdStep, 300);
  }
}
```

**空块语义（决策 B，I-2 Oracle 确认）**：`endBlock` 在 `cmdProg(0) >= blockCmds[i].length(0)` 时立即触发——
空块落**初始位置**（rot 0 + 中位 col），与生成器「生成即落定」语义一致（不编 = 原位落，差格红框提示放偏，
教学合理）；加 300ms 延迟（N-2 采纳）避免视觉跳跃。
**块间差格即时提示**：保留每块落定后的 excess 检查（红框 + 提示），但**不中断执行**（整体编排语义：
一次跑完看结果）；最终 checkWin 统一判定。

### 2.4 判定 / 星级 / 重置

- **checkWin 零改动**：最终网格 vs 目标逐格比对（placed 累积全程）✅
- **星级**：`total = Σ blockCmds[i].length`（空块 = 0）vs `state.optimal`（生成器最优解不变）；
  ≤1.5× = 3★ / ≤2.5× = 2★（同 v1.0 口径）
- **⟲ 重置**：清空全部 blockCmds（`blockCmds = pieces.map(() => [])`）+ 重生成关卡（同 v1.0 语义）
- **再来一题**：nextLevel 重置 blockCmds

### 2.5 范围与边界

- 0 新关；生成器/落定物理（dropRowFor/absCells）零改动
- **存量进度兼容**：store 结构不变（best/recent/history/checkin）；关卡重开即走新 UI（无持久指令）
- **Chrome 61**：无新 API（复用 makeEl/addEventListener/SVG）
- **合规**：本地存储/无 PK/无云同步（同 v1.0）
