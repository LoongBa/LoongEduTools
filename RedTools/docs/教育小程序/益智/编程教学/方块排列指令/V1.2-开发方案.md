## 1. 背景与目标

### 1.1 背景与现状

方块排列指令 v1.0/v1.1 已完成「**解题**」路径：程序化生成器（随机 (type, rot, col) → dropRowFor 顺序落定 → 必有解）+ 孩子编指令（旋转/参数化移动/落下）→ 布局比对判定。v1.1 多块整体编排后，孩子已经历「顺序→旋转→参数化移动→多块规划」完整解题练习链。

**缺口**：与走迷宫 v1.9 前同样的问题——只有「解给定关卡」单向路径，缺**创作闭环**。孩子无法**自己设计目标图案**让程序/自己来解。设计文档 §9 明确候选「关卡编辑器」（创作闭环）。

### 1.2 教学定位（与走迷宫 v1.9 对齐）

| 角色 | 走迷宫 v1.9 | 方块排列 v1.2 |
|---|---|---|
| 1-8 块 / v1.0-1.1 | 解题（给定盘面 → 写指令） | 解题（给定目标图案 → 编指令） |
| **v1.9 / v1.2** | **出题**（设计盘面 → 校验可解 → 保存/挑战） | **出题**（画目标图案 → 校验可拼 → 保存/挑战） |
| 教学价值 | 理解「箱子能否推到目标」→ 盘面结构 | **理解「图案能否由四格骨牌落拼出」→ 落定物理 + 骨骼形状** |

- 角色反转：设计图案时必须理解「方块是**从上往下落**的（叠放/悬空约束）」「四格骨牌只有 7 种型 × 4 旋转」→ 比解题更深的构建结构理解
- 与走迷宫 v1.9 同构：编辑器产出 → 校验（可解）→ 本地保存 → 进入同一练习/判定/星级流程
- 合规：自建关卡**本地存储、不入 publish**（同走迷宫 v1.9 N1——custom 不对外分发，可解性校验是 UX 保障非合规硬要求）；无 PK/排行榜/云存档

## 2. 变更设计

### 2.1 数据模型：自定义关卡库

**存储**：`LX_SHARED.storage`（工具已 `configure({toolName:'fangkuai'})` → 键前缀 `redtools.fangkuai.`）：
```js
// storage.set('customLevels', arr) → 实际键 'redtools.fangkuai.customLevels'（customLevels 是独立集合，非 store 的 'v1' 键，无 .v1. 段）
// value: [{ id, name, cells, gridW, gridH, refPieces, createdAt, solved }, ...]
```
> ⚠️ 勿硬编码完整键名（绕过 storage 前缀约定 + 不被清除覆盖）。统一 `LX_SHARED.storage.set('customLevels', arr)` / `get('customLevels')`。

| 字段 | 说明 |
|---|---|
| id | 唯一（`Date.now() + '-' + Math.random().toString(36).slice(2,5)`，防毫秒碰撞——走迷宫 v1.9 N4） |
| name | 关卡名（默认「我的图案 N」，≤12 字） |
| cells | 目标格子索引数组（`y*gridW + x`；保存时按 trim 后 gridW 编码） |
| gridW/gridH | 图案边界（保存时**裁剪**：全空行/全空列去除 → 最小盘面；trim 后图案最低行 = 地面行，落定物理自洽） |
| refPieces | 参考解（阶段 2 验证通过的合法序列 `[{type, rot, col, row}, ...]`，K = cells/4 个）——custom 关卡 pieces 骨架（块 tab UI），不展示/不强制 |
| createdAt | 创建时间戳 |
| solved | 是否已用指令通关过（「已解」徽章） |

**上限**：最多 **20 关**（超限提示删旧关）；**每个图案 ≤ 24 格**（6 块 × 4 格/块，超出提示「最多 6 个方块（24 格）」——两阶段搜索上限保障）。

**存取函数**（同走迷宫 v1.9 签名）：
| 函数 | 签名 | 说明 |
|---|---|---|
| loadCustomLevels | `() → Array` | IIFE 顶部 `var customLevels = loadCustomLevels()`（与 store 同加载）；无数据 `[]` |
| saveCustomLevels | `(arr) → void` | `storage.set('customLevels', arr)` |
| addCustomLevel | `(cells, gridW, gridH, refPieces, name) → id` | 校验通过后构造对象 push + save；超 20 提示 |
| removeCustomLevel | `(id) → void` | confirm 后按 id 过滤 + save |
| markCustomSolved | `(idx) → void` | `customLevels[idx].solved = true; saveCustomLevels(customLevels)` |

**绘制交互**（单层涂格模型，简化走迷宫 v1.9 I1 分层模型）：
- 每格 `editCells[y*10+x]` 布尔（画/空）
- 工具按钮选画笔（画格/橡皮）；`pointerdown` + `pointermove` + `setPointerCapture`（Chrome 55+ 支持，Chrome 61 基线内）

**可拼性校验（✓ 检查可拼）**——核心新算法（**v0.2 两阶段，Oracle B1 修复**）：

| 检查项 | 规则 |
|---|---|
| 格子数 | `cells % 4 === 0`（「格子数要是 4 的倍数（每个方块占 4 格）」）；`cells ≥ 4`；`cells ≤ 24`（「最多 6 个方块=24 格」） |
| **可拼性** | **`checkSolvable(gridW, gridH, targetSet, K)`——两阶段：分割枚举 + 落定验证**（见下） |

**`checkSolvable` 设计（v0.2 重构，修复 v0.1 B1 剪枝不完备）**：

> **v0.1 缺陷回顾（Oracle B1）**：v0.1 用「最左上未覆盖格必须被**下一块**覆盖」剪枝——这在**纯覆盖**（顺序无关）时正确，但**顺序落定**（dropRowFor 物理，顺序相关）下不完备：覆盖行 0 的块必须先有垫块才可能落定到高处，空盘面直接落必触底（row = gridH - h > 0）。gridH > 4 时（easy 6×6 / normal 8×8 / hard 10×10）任何块都无法空盘面覆盖行 0 → **生成器产出的全部图案都会判 false，生成器互逆测试 100/100 全失败**。「最底左格」变体递归第二步同样有垫块漏解。根因：把「覆盖剪枝」错误地用在了「必须落定」的约束上。

**v0.2 两阶段（正确性论证）**：
- **阶段 1：分割枚举（纯覆盖 DFS——顺序无关）**：找 target 的 K 块分割（每块 = 7 型 × 4 旋转 × 平移位置，覆盖 target 且互不重叠）。
  - 「最左上未覆盖格 c **必须被某块覆盖**」剪枝：**此时顺序无关（纯覆盖），剪枝完备**——对每个候选块的 4 格中任一格对齐 c 且其余格 ⊆ target 枚举；
  - 剪枝：`occupied ⊆ target`（强剪枝）+ 深度 ≤ K
- **阶段 2：落定验证（贪心从底到顶——顺序相关）**：对阶段 1 找到的每个分割，验证是否存在放置顺序使每块 dropRowFor 落定到其分割位置。
  - **精确判定**：块 X（type/rot/col），目标 row r：`dropRowFor(X, placed) == r` ⟺ 「X 在 r 处与 placed 无重叠（分割保证）」∧「X 在 r+1 处与 placed 有交集 **或** X 在 r+1 处触底（r+1+h > gridH）」（dropRowFor 停在首个重叠行的上一行）；
  - **贪心从底到顶**：每步任取「紧邻下方已放 或 触底」的未放块放置——**可放性单调**（放置块只增加他人下方支撑、低块不遮挡高块下落路径）→ 存在顺序时贪心必成功；无可放块且未放完 = 该分割不可拼；
  - 阶段 2 失败 → 阶段 1 继续找下一分割（**不是直接 false**）
- **节点上限 20 万**（阶段 1 DFS + 阶段 2 验证共同计数）→ 超限返回「暂不确定」（提示「试试缩小或改一改图案」，非假阴性）
- **正确性**：阶段 1 完备（纯覆盖剪枝正确：c 必被某块覆盖）+ 阶段 2 精确匹配 dropRowFor 物理（首个重叠行语义）→ 返回 true 的图案存在孩子可写的合法指令解（refPieces 即序列）；生成器产出的图案阶段 1 必找到分割（生成过程即分割）、阶段 2 必通过（生成顺序即放序）→ **生成器互逆全 true**
- **性能**：阶段 1 纯覆盖 DFS 候选 = 7 型 × 4 rot × ≤6 对齐 ≈ 168/步 + occupied⊆target 强剪枝；K ≤ 6、target ≤ 24 格 → 常规毫秒级；节点上限兜底

**落定物理参数化（Oracle I4 + v0.2 复核 I1 修复）**：checkSolvable 在编辑器上下文调用（state 可能是 10×10 编辑画布，非 trim 后尺寸）→ 抽两个纯函数：
- `absCellsW(type, rot, col, row, gridW)`（**gridW 显式传入**——v0.2 复核 I1：absCells L172 硬依赖 `state.gridW`，若只参数化 dropRowForW 而 absCells 仍读 state.gridW，checkSolvable 会用错尺寸算格子索引）；现有 `absCells` 委托 `absCellsW(..., state.gridW)`
- `dropRowForW(type, rot, col, placed, gridW, gridH)`；现有 `dropRowFor` 委托 `dropRowForW(..., state.gridW, state.gridH)`
- 单一实现防不一致：生成器/执行器/checkSolvable 共用同一对纯函数，checkSolvable 传 trim 后校验尺寸

**保存**：
- 校验通过才可保存（「✓ 可拼！保存成功」）；未校验/不可拼/暂不确定 → 提示先检查
- 保存时 trim：去掉全空行/全空列 → 得 gridW/gridH + 重编码 cells；refPieces 同步按 trim 后坐标生成（阶段 2 验证即已按该尺寸）
- 保存 → addCustomLevel → 返回关卡库列表

### 2.4 自定义关卡练习（startCustom）

**进入**：关卡库列表点 [▶ 挑战] → `startCustom(idx)`（复刻 startGame 完整启动序列）：
```js
function startCustom(idx) {
  state.execLock = false; state.execDone = false; state.won = false;
  state.placed = []; state.curIdx = 0; state.curEditIdx = 0;
  state.cur = null;                               // v0.2（Oracle I3）：重置执行预览，防 renderPreview 残留
  state.diffCells = null;                         // v0.2：同步 resetBtn/startGame 语义
  if (state.stepTimer) { clearTimeout(state.stepTimer); state.stepTimer = null; }
  state.level = 'custom'; state.customIdx = idx;
  var cl = customLevels[idx];
  state.gridW = cl.gridW; state.gridH = cl.gridH;
  state.targetCells = {}; for (var i = 0; i < cl.cells.length; i++) { state.targetCells[cl.cells[i]] = true; }
  state.pieces = cl.refPieces.map(function (rp) {
    return { type: rp.type, rot: rp.rot, col: rp.col, row: rp.row, cells: null };
  });                                  // 参考解作 pieces 骨架（块 tab/预览）；cells 由执行时计算
  state.blockCmds = state.pieces.map(function () { return []; });
  renderGame(); state.startMs = Date.now(); startTimer();
}
```

**refPieces 机制要点**（V1.1 依赖 pieces 的关键点）：
- `renderGame`/`renderBlockTabs`（块 tab 数 + ✓ 标记）/`countEditedBlocks`/`renderPreview`（编辑态预览 spec）都读 `state.pieces` → refPieces 补齐后 custom 获得**完整 v1.1 编辑 UI**（块 tab 切换/预览/各块序列）：K 块 tab 对应 refPieces 每块 type
- **不展示/不强制参考解**：检查 = 网格比对（孩子爱怎么写怎么写）；refPieces 仅是「有解存在」证明 + UI 骨架（Oracle I-审查注：refPieces 锁定块型序列，孩子只能用该块型组合——v1.1 内置关同样固定 pieces，体验一致；同一图案若有多个分割解，refPieces 取阶段 1 找到的第一个，孩子仍可自由编指令）
- 执行器零改动：execRun 按 blockCmds 顺序落定（dropRowFor 运行时计算 row）——refPieces 的 row 字段仅预览占位
- **星级**：custom 2★ 兜底（Oracle N1 确认：refPieces 是任意合法解非最优解，不宜作最优指令数基准——与走迷宫 custom b=null 一致）

**custom 模式守卫清单**（v0.2 补全——Oracle I1/I2 修订：3 处增补，共 10 处）：

| 位置 | 现状（v1.1） | v1.2 custom 守卫 |
|---|---|---|
| renderGame 顶栏 L441 | `LEVELS_CFG[state.level].label` | `state.level === 'custom' ? customLevels[state.customIdx].name : LEVELS_CFG[state.level].label` |
| **renderBlockTabs L374（v0.2 补，Oracle I1）** | `LEVELS_CFG[state.level].label`（进度文案） | custom 时 `customLevels[state.customIdx].name` |

### 2.6 合规与数据边界

- 自建关卡**本地存储**（`LX_SHARED.storage` 键 `customLevels` → localStorage `redtools.fangkuai.customLevels`），不联网、无云同步（符合离线 zip 约束）

- **「清除所有数据」覆盖**（走迷宫 v1.9 B5 教训）：viewParent 清除除 `storage.remove('v1')` 外，**追加 `storage.remove('customLevels')`**，确保自建关卡随数据清除一并删除
- 编辑器无排行/无分享传播（合规红线）

## 4. 验证计划

### 4.1 checkSolvable 专项（Node 独立脚本，与前端同一实现源）

| 测试项 | 断言 |
|---|---|
| 空图案 | 0 格 → 拦截「格子数要是 4 的倍数」 |
| 非 4 倍数 | 10 格 → 拦截 |
| 超上限 | 28 格 → 拦截「最多 6 个方块」 |
| 单 I 型 | 4 格横条 → 可拼 true |
| 单 O 型 | 2×2 方块 → 可拼 true |
| 两个水平 I 叠放 | 8 格（两行各 4，第二块落第一块上）→ 可拼 |
| **叠放高层（B1 回归）** | 3 层水平 I 叠放（12 格，gridH=3）→ **可拼 true**（v0.1 最左上格剪枝会误判 false——覆盖行 0 的块需垫块） |
| **gridH>4 高层（B1 回归）** | 6×6 盘 2 块叠放（下层 I 竖 + 上层横 I）→ 可拼 true（v0.1 剪枝判 false 的典型生成器场景） |
| 悬空图案 | 上格有下格空（如 L 型倒悬）→ **不可拼 false**（落定物理约束——教学点） |
| 无法拼成骨牌的图案 | 4 格竖条旁错位一格 → 阶段 1 无分割 → false |
| **分割存在但落定不成立** | 图案 = 两个错位 O 型（A: col=0 row=0 目标上方 / B: col=2 触底）——阶段 1 可分割但 A@row=0 下方无支撑阶段 2 不可行 → false（Oracle v0.2 复核 N3：具体样例如上） |
| 生成器互逆 | genLevel 随机 100 关（三难度混跑）：checkSolvable(其 targetCells) → **全 true**（生成即解=两阶段自洽） |
| 性能 | 24 格随机图案 → 节点数 < 20 万（不假阴性）；构造极端图案 → 超限返回「暂不确定」 |
| refPieces 回放 | checkSolvable 返回解 → 用 dropRowForW 顺序落定 → 占格 == targetCells |
