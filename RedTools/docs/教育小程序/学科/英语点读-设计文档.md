| 数据 | 来源 | 说明 |

### 2.1 book.json 关键结构

- `bookpage[]`：每页一条，核心字段 `page_no` 与 `track_info[]`。
- `track_info[]`：点读热区，字段映射到前端如下：

| book.json 字段 | 前端字段 | 说明 |
|------|------|------|
| `track_text` | `text` | 英文文本 |
| `track_genre` | `cn` | 中文栏目（如「第一单元 在家帮忙」） |
| `track_left/top/right/bottom` | 同名 | 热区坐标，**0~1 归一化**，原点页面图左上角、y 轴向下 |
| `track_duration` | `duration` | 音频时长（秒） |
| `track_index` | `track_index` | 句序号（构建时不可缺失，缺失会中断构建） |

- `bookaudio_v3[]`：单元目录，`title` 形如 `"Unit 1 Helping at home"`，`page_no` 为单元起始页。

### 2.2 单元范围推断

`resolve_unit_pages()`：单元起始页取 `bookaudio_v3[i].page_no`，结束页取下一个单元
`page_no`（末单元取 `bookpage` 末尾 +1）。Unit 1 因此自动收敛为页 2-13，无需手写页码。

## 3. 构建管线

入口：`python build_all.py --tool 英语点读 --units 0`（`build_framework.build_tool` 实现）。

```
book.json
  ├─(2) resolve_unit_pages ──► 页码范围（bookaudio_v3 推断）
  ├─(3) build_unit_data   ──► 提取 pages/tracks（校验 track_index）
  ├─(4) convert_images    ──► PIL → images/page_NNN.webp（1200w, q78, method 6, RGB）
  ├─(5) convert_audio     ──► ffmpeg → base64 → audio/<key>.js（window.AUDIO_DATA）
  ├─(6) make_icon         ──► icon_base.png 母版 + 自动角标 → assets/icon.png(128px) + publish(1024px)
  ├─(7) write_data_js     ──► data.js（window.APP_DATA）
  └─(8) package_zip       ──► <app_name>.zip → publish/学科/（index.html 在 zip 根目录）
```

各步要点：

1. **copy_static**：复制 `src/` 的 index.html + assets/，剔除 `icon_base.png`（母版不入包）。
2. **(3) build_unit_data**：audio key 生成规则 `p{page_no:03d}_{track_index:02d}`；
   坐标保留 4 位小数；`subtitle` 取首页第一条中文（`track_genre`）。
3. **(4) 图片**：PIL 打开 PNG，宽超 1200 则等比缩放（LANCZOS），转 RGB 存 WebP（quality 78, method 6）；
   素材缺失时 WARN 跳过。
4. **(5) 音频**：`ffmpeg -ac 1 -ar 24000 -b:a 48k -map_metadata -1 -f mp3 pipe` 压缩，
   输出 base64 **纯 payload** 写入 `audio/<key>.js`（无 `data:` 前缀）；缺失音频生成空 payload 并 WARN。
5. **(6) 图标**：`badge_text()` 从 bookname + 单元 title 生成角标（如「四上 Unit01」），
   母版居中裁方 + 底部圆角半透明条叠加文字 → 128px 入包供页面 favicon/顶栏，1024px 到 `publish/` 供上传。
6. **app_name**：`resolve_app_name()` 按模板动态命名（`Unit N` → `{unit_no}=N`、
   `Revision` → `复习`、`Appendix N` → `附录N`），用于 zip/图标文件名。
7. **zip**：`package_zip` 以 dist 目录为根，相对路径入包（index.html 在根目录，非套一层目录）。

发布门禁：审计 `python .skill/minitool-zip-builder/scripts/audit_artifact.py <dist|zip>`、
合规自查（grep 禁止项 + 扩展名白名单）、Playwright 冒烟（file:// 与 http:// 双协议）。

## 4. 前端数据结构（window.APP_DATA）

由 `write_data_js()` 生成，`index.html` 首个脚本加载：

```js
window.APP_DATA = {
  meta: {
    name: "新英语四上点读1单元",
    version: "1.1", series: "学科", tool: "英语点读",
    book: "英语（PEP） 四年级 上册",
    bookid: "newpep_4s", bookid_3rd: "1212001401255",
    unit_index: 0
  },
  units: [{
    id: "newpep_4s-u1",
    title: "Unit 1 Helping at home",
    subtitle: "第一单元 在家帮忙",
    pages: [{
      no: 2,
      image: "images/page_002.webp",
      tracks: [{
        text: "Unit 1 Helping at home",
        cn: "第一单元 在家帮忙",
        audio: "p002_01",            // 对应 audio/p002_01.js
        left: 0.0773, top: 0.0479,   // 0~1 归一化热区坐标
        right: 0.8536, bottom: 0.2396,
        duration: 4.41,
        track_index: 1
      }]
    }]
  }]
};
```

约定：
- `page.image` → `images/page_NNN.webp`（构建产物）；`track.audio` → `audio/<key>.js`。
- 坐标契约：**热区一律 0~1 归一化存储，渲染层转像素/百分比**（点读模式用
  `left/top × 100% toFixed(2)` 定位虚线框）。见系列文档 §2.2、README §3.1。

## 5. 音频方案（关键决策，勿改）

约束链：平台 zip 白名单**不含任何音频格式** + 容器 CSP **禁止 `<audio>/<video>` 使用
`data:`/`blob:` 媒体源** → 音频无法以 mp3/wav 入包、也无法用 `new Audio(dataUri)` 播放。
唯一合规路：

- **打包**：每个 track 音频 `ffmpeg 48kbps mono 24kHz` 压缩 → base64 纯 payload →
  独立 `audio/<key>.js`（`window.AUDIO_DATA["p002_01"]="<base64>"`，无 `data:` 前缀）。
- **播放**：运行时 `AudioContext.decodeAudioData(ArrayBuffer)` 内存解码 →
  `createBufferSource` → `start(0)`。全程不经 `<audio>` 元素 / data: URI / 网络请求。
- **预加载**：`preloadPageAudios(page)` 在渲染页面时动态创建本页全部音频
  `<script src="./audio/<key>.js">`（async），点读零延迟；翻页自动补载新页。
- **兜底**：`playAudio` 取 payload 为空时动态补拉一次脚本（onload 重试、onerror 结束回调）。
- **解码缓存**：`bufferCache[key]` 按 audio key 缓存 AudioBuffer，避免同句重复解码。
- **体积真相**：base64 膨胀约 33%，但 zip 对 base64 文本压缩率高（实测 42%），净增≈0。

## 6. 功能设计（以 main.js 为准）

### 6.1 页面骨架（index.html）

`header#app-header`（顶栏 + 模式切换）→ `main#page-view`（课本页）→ `footer#app-footer`
（字幕 + 顺序控制 + 翻页）；脚本顺序 `data.js` → `assets/main.js`。无内联脚本/事件。

### 6.2 状态模型

```js
mode = 'tap' | 'seq'          // 点读 / 顺序（默认 'tap'）
seq  = { running, index, pageNo, paused, offset, playCount,
         repeat, rate, autoNext }
currentUnit / currentPage / currentHotspot / currentSource / audioCtx / bufferCache
```

持久化：`localStorage` 键 `redtools.mode`、`redtools.seq`；容器禁用时 try/catch 降级默认。

### 6.3 双模式总览

| 模式 | 交互 | 高亮 |
|------|------|------|
| 点读（tap） | 点击课本虚线框 → 播该句 + 字幕 | 热区实线蓝底 `is-playing` |
| 顺序（seq） | 整页按 track 连播，控制条操作 | 当前句热区高亮跟随 |

切换：`stopAll()` → 更新 `mode` → `saveMode()` → `render()` 重建三个区块。

### 6.4 点读模式

- 热区渲染：`page.tracks` 中坐标合法的项生成 `.hotspot` 虚线框（`spot.title=track.text`）。
- 点击：`playTrack()` → `stopPlayback()` 停旧句 → 框高亮 + `currentHotspot` 记录 → 刷新字幕 →
  `playAudio()`。字幕区默认文案「点击课文区域试听」。
- 顺序播放中点击热区：先 `stopAll()`、切回点读模式并保存，再播该句（见 §7 坑位）。

### 6.5 顺序模式控制条（两行）

- **行 1**：`‹ 上一条` / `▶ 播放`（播放中变 `⏸ 暂停`、暂停中变 `▶ 继续`）/ `下一条 ›` / 进度
  （未播放「共 x 句」，播放中「第 x / y 句」）。
- **行 2**：`重复`（×1 ↔ ×2，开时高亮）/ `速度`（四档循环）/ `自动连播`（开/关）/ `重听本页`。

播放流程：

1. `startSequence()`：无 track 直接返回；`index=0`，更新进度，`playSeqNext()`。
2. `playSeqNext()`：守卫 `running && pageNo===currentPage && mode==='seq'`；到末尾走
   `finishSequence()`。每句先 `stopSourceOnly()` + `clearAllHotspots()` 清旧高亮，再高亮本句并播放。
3. 句播完回调：校验 `currentSource` 与守卫条件；`repeat ×2` 时（`playCount<1`）本句重播一遍，
   否则 `index+=1` 进下一句。
4. 上一条/下一条：`stopSourceOnly()` + 指针移动后直接从头播目标句（同句内从头，不做秒级续播）。
5. 暂停/继续：暂停用 `currentSource.stop()`（当前句中断）；继续从**当前句开头**重播
   （`offset` 精度简化，代码注释明示）。
6. 变速：`cycleSpeed()` 在 `[0.75, 1, 1.25, 1.5]` 循环，写入 `src.playbackRate.value`；
   **音高随速度变化是 WebAudio 原生行为**，非缺陷。
7. 空页：顺序模式控制条显示「本页无可播放内容」，播放按钮无效。

边界：第一句时「上一条」、末句时「下一条」置灰（`is-disabled` 仅视觉，点击仍有效且重播当前句）；
翻页按钮则用原生 `disabled`，真不可点。

### 6.6 自动连播（finishSequence）

本页播完（`seq.index ≥ tracks.length`）：

| 条件 | 行为 |
|------|------|
| `autoNext` 开 且 非末页 | `currentPage+=1` → `render()` → 自动 `startSequence()` 继续 |
| 已到末页 | `flashCaption('已播放到最后一页')`（2 秒后恢复字幕） |
| 否则 | `flashCaption('本页播放完毕，可翻页继续')` |

`flashCaption` 临时替换字幕区文本 2s 后 `refreshCaption()` 恢复。

### 6.7 翻页

- 按钮：`封面` / `‹` / `第 x / y 页` / `›` / `末页`；边界页禁用首尾按钮。
- 触屏滑动：`pointerdown/pointerup` 采集，满足「水平位移 >48px、`|dx|>|dy|×1.5`（水平占优）、
  500ms 内」→ 左滑翻下一页、右滑翻上一页；越界停在封面/末页。
- 任何翻页都先 `stopAll()`（顺带停止顺序播放）。

### 6.8 顶栏与单元切换

- 图标 + 工具名 + 版本小字（`header-ver`，显示 `v1.3.0`，便于调测辨认产物）。
- `units.length > 1` 时提供单元 tab；点击 `stopAll()` → 切单元 → 回到第 0 页 → `render()`。

### 6.9 设置记忆

| 设置 | 键 | 内容 |
|------|------|------|
| 模式 | `redtools.mode` | `'tap' | 'seq'` |
| 顺序选项 | `redtools.seq` | JSON `{repeat, rate, autoNext}` |

写入时机：切模式 `saveMode()`；重复/速度/自动连播变更 `saveSeqOptions()`。读取时校验类型，
非法值忽略保留默认；localStorage 不可用时静默降级（try/catch 包裹，见代码注释）。

## 7. 关键坑位（已踩过，勿重复）

系列文档 §3.1 为本工具实战沉淀，原文收录：

1. `decodeAudioData` 结果按 audio key 缓存（`bufferCache`），避免每句重复解码。
2. `source.stop()` 会触发 `onended` 回调 → 回调须校验 `currentSource === src` 防止误推进。
3. 顺序播放自动切句/手动切换都须 `clearAllHotspots()` 清旧高亮（仅 `clearHotspot()` 不够，
   后者只清单个当前热区）。
4. `window.AUDIO_DATA` 是动态 `<script>` 注入后新建的对象，读取须每次实时查
   `(window.AUDIO_DATA || {})[key]`，不能缓存初始引用（初始可能是空对象）。
5. `new Audio(dataUri)` 会被 CSP 拦截，播放一律走 Web Audio。
6. 顺序播放中点热区：切回点读模式并播该句（交互打断设计，见 §6.4）。

补充实现注意：

- `ensureAudioCtx()` 惰性创建，`ctx.state === 'suspended'` 时先 `resume()`（自动化播放策略场景）。
- `syncAppHeight()` 随 resize 维护 `--app-height` 变量，配合容器注入的 safe-area 变量做全高布局。
- 页面图 `pointer-events: none`，交互全部落在热区层上，避免图片层拦截点击。

## 8. Chrome 61 基线约束

- **JS**：经典脚本（无 `type="module"`/import/export）、不超 ES2017（无 `?.` `??` 对象展开
  `String.replaceAll`）、事件全部 `addEventListener`、无 eval/内联事件。
- **CSS**：无 flex `gap` / `aspect-ratio` / `clamp()` / 逻辑属性 / `:has` / `@container` / `dvh`；
  Flex 子项设 `min-width:0`；安全区用 `env(safe-area-inset-*)` + 容器变量双重兜底；
  增强特性放 `@supports` 能力检测层。
- **合规自检**：无 `fetch`/XHR/Worker/定位/剪贴板/`window.open`、无外部 `http(s)://` 引用、
  无 `<base>`/`<iframe>`/自建 CSP meta。
