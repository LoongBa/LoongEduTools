# 批量生图工具 — 设计方案

> 版本：v1.0 | 日期：2026-09-19 | 状态：待 Oracle 审阅

## 1. 设计目标

构建一个**通用的批量 AI 生图执行引擎**，解决以下核心问题：

| 问题 | 解决方案 |
|------|----------|
| 单 API Key 额度有限 | 多 Key 轮换 + 冷却周期自动恢复 |
| 批量任务中断需从头跑 | 断点续跑（done.json 记录完成状态） |
| 并发控制不灵活 | 自动匹配可用 Key 数 / 手动指定 |
| 重绘工具与引擎耦合 | 插件化 Provider 架构，重绘作为特例 |
| API Key 分散管理 | keys.json 公共配置，所有工具共享 |

## 2. 架构设计

### 2.1 分层架构

```
+-----------------------------------------------------+
|                   CLI 层 (batch_cli.py)              |
|   统一入口：run / list / status / create / clear     |
+-----------------------------------------------------+
|                 执行引擎层 (batch_engine.py)          |
|   并发调度 + 状态管理 + 断点续跑 + 重试逻辑            |
+-----------------------------------------------------+
|                Provider 层 (providers/)               |
|   +-------------+  +-------------+  +-------------+ |
|   |  sensenova  |  |   openai    |  |   custom    | |
|   +-------------+  +-------------+  +-------------+ |
+-----------------------------------------------------+
|               Key 管理层 (key_manager.py)             |
|   多 Provider 支持 + 轮换调度 + 冷却周期 + 并发安全    |
+-----------------------------------------------------+
```

### 2.2 核心模块职责

| 模块 | 职责 | 关键接口 |
|------|------|----------|
| `batch_cli.py` | CLI 统一入口 | `main()` |
| `batch_engine.py` | 执行引擎 | `execute_task()`, `run_single_job()` |
| `batch_redraw.py` | 重绘特例 | `create_redraw_task()`, `create_from_book_json()` |
| `key_manager.py` | Key 管理 | `KeyManager.register_provider()`, `get_next_key()`, `mark_exhausted()` |
| `providers/base.py` | 抽象基类 | `BaseProvider.generate()`, `Job`, `JobResult` |
| `providers/sensenova.py` | SenseNova | `SenseNovaProvider` |

## 3. 数据流

### 3.1 任务执行流程

```
用户创建任务
    |
    v
batch_cli.py create --> 生成 jobs.json
    |
    v
batch_cli.py run --> execute_task()
    |
    +---> load_task_config()     # 读取 config.json
    +---> load_jobs()            # 读取 jobs.json
    +---> KeyManager             # 加载 keys.json, 注册 Provider
    +---> resolve_concurrency()  # 计算并发数
    |
    v
ThreadPoolExecutor(max_workers=N)
    |
    +---> run_single_job() x N   # 并发执行
    |       |
    |       +---> km.get_next_key()    # 获取可用 Key
    |       +---> provider.generate()  # 调用 API
    |       |       |
    |       |       +-- QuotaExhaustedError --> mark_exhausted() --> 换 Key 重试
    |       |       +-- RetryableError --> 等待 backoff 后重试
    |       |       +-- 成功 --> save_done_id()
    |       |
    |       +---> 失败计数 --> 达到 max_retries 则放弃
    |
    v
输出汇总报告
```

### 3.2 Key 轮换状态机

```
             +--------------+
             |   可用状态    |
             |  (exhausted  |
             |   = false)   |
             +------+-------+
                    | get_next_key()
                    v
             +--------------+
             |   使用中      |
             |  (当前 Key)   |
             +------+-------+
                    | 额度用完
                    v
             +--------------+
             |   冷却中      |
             |  (exhausted  |
             |   = true)    |
             |  started_at  |<-- 周期起点
             +------+-------+
                    | elapsed >= cycle_seconds
                    v
             +--------------+
             | 自动重新激活  |
             | (清除记录)    |
             +------+-------+
                    |
                    +---> 回到 "可用状态"
```

### 3.3 断点续跑机制

```
jobs.json:
  [ {id: "p1", ...}, {id: "p2", ...}, {id: "p3", ...} ]

done.json:
  ["p1", "p3"]  <-- 已完成

--resume 模式:
  过滤: jobs - done = [{id: "p2", ...}]
  只执行剩余任务
```

## 4. 关键设计决策

### 4.1 为什么用 done.json 而非改写 jobs.json？

| 方案 | 优点 | 缺点 |
|------|------|------|
| 改写 jobs.json | 简单 | 不可逆，无法 --force 重跑 |
| done.json 独立记录 | 可逆，支持 --force 清除 | 多一个文件 |

选择 done.json，因为批量任务常需要「重跑失败项」或「全量重跑」。

### 4.2 为什么 Key 冷却用 started_at 而非 exhausted_at？

旧版重绘工具的设计：周期起点 = 首次使用时刻（started_at），而非用完时刻。
这样多个 Key 的恢复时间均匀分布，避免同时恢复同时用完。

### 4.3 并发数 auto 的计算逻辑

```
auto = count(available_keys)
     = total_keys - count(exhausted_keys_in_cooldown)
```

当所有 Key 都在冷却中，auto = 1（至少 1 个线程等待恢复）。

### 4.4 Provider 插件化

- 新增 Provider 只需继承 `BaseProvider` + 实现 `generate()`
- 异常体系：`QuotaExhaustedError`（换 Key）/ `RetryableError`（重试）/ `FatalError`（放弃）
- keys.json 支持多 Provider 同时配置

## 5. JSON 任务格式

### 5.1 jobs.json

```json
[
  {
    "id": "page_002",
    "prompt": "将这张图片重绘为卡通风格...",
    "input_image": "input/Page_002.png",
    "output_path": "output/Page_002_redrawn.png",
    "params": { "size": "auto" }
  }
]
```

### 5.2 config.json

```json
{
  "task_name": "pep4s_u01",
  "provider": "sensenova",
  "model": "sensenova-u1.5-lite",
  "size": "auto",
  "concurrency": "auto",
  "retry": {
    "max_attempts": 3,
    "backoff_seconds": 5
  }
}
```

### 5.3 keys.json

```json
{
  "sensenova": {
    "keys": ["sk-xxx", "sk-yyy", "sk-zzz"],
    "cycle_seconds": 18000
  },
  "openai": {
    "keys": ["sk-abc"],
    "cycle_seconds": 3600
  }
}
```

## 6. 与旧版重绘工具的关系

| 对比项 | 旧版 redraw.py | 新版批量生图工具 |
|--------|----------------|------------------|
| 架构 | 单体脚本 | 分层架构 |
| Key 管理 | 内嵌 | 独立模块，公共 keys.json |
| 并发 | --parallel 手动指定 | auto 自动匹配 |
| 断点续跑 | 不支持 | done.json + --resume |
| Provider | 仅 SenseNova | 插件化，可扩展 |
| 任务格式 | 目录结构 | JSON 文件 |
| 重绘特例 | 全功能内置 | 调用通用引擎 |

**推荐**：新任务使用批量生图工具，旧重绘工具保留兼容但不再维护。
