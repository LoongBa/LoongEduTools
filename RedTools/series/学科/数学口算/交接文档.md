## 二、未完成 — P0（发布前必须完成）

### 2.1 validate() 反推校验是占位桩

**位置**：`generators.js` L389-395

```js
function validate(q) {
  var t = q.text;
  var a = q.answer;
  // 校验函数：按题型反向验算（生成器内部已保证，这里做兜底断言）
  return true;  // ← 始终返回 true，未实际校验
}
```

**问题**：Oracle P0 要求"每个生成器配反推校验函数，生成后用数学运算反向验算答案，校验失败则重新生成"。当前 validate() 是空壳。

**修复方案**：为每个生成器类型实现反推逻辑，例如：
- `g1_20add`：验证 `text` 中两个加数之和 === `answer`
- `g2_div`：验证 `text` 中被除数 ÷ 除数 === `answer`
- `g3_frac`：验证通分后加减结果约分 === `answer`
- `g6_pct`：验证百分数/小数/分数互化等价

可复用 `checkAnswer()` (main.js L274-290) 的 `toNum()` 逻辑做等价比较。

**位置**：`generators.js` L207-219

```js
// g4_big 生成：
return { type: 'g4_big', text: num + ' = ? 万', answer: w };
```

**问题**：题面是 `45678 = ? 万`，答案是整数 `4`（万）。用户输入 `4` 时，`checkAnswer()` 的 `toNum("4") === toNum(4)` 应该成立。**但需验证**：`q.answer` 是数字类型还是字符串？如果 `q.answer = 4`（数字），`String(4) === "4"` 正确；如果 `q.answer = "4"`（字符串），也正确。**实测确认即可**。
