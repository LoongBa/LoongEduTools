## 1. 通用约束（所有学科系列工具必须遵守）

来源：`RedTools/.skill/minitool-zip-builder/`（小红书小工具平台规范）。

| 约束 | 内容 |
|------|------|
| zip 白名单 | 仅 `jpg css gif svg png js jpeg json html woff2 webp woff`，**无音频格式** |
| CSP | `<audio>/<video>` 禁 `data:`/`blob:` 媒体；脚本禁内联/eval/module |
| 离线 | 所有资源打包在内，不联网 |
| 基线 | JS: ES2017 / Chrome 61；CSS: Chrome 61 基线 + 能力检测增强 |
| 体积 | zip ≤ 10 MiB（建议 ≤ 2 MiB） |

## 2. 数据驱动架构（可复用核心）

### 2.1 数据流

```
book.json（或等价数据源）
  └─► build_framework.py（公共构建）
        ├─ 图片: PIL → WebP（1200w, q78）
        ├─ 音频: ffmpeg 48k mono → base64 → audio/<key>.js（window.AUDIO_DATA）
        ├─ 图标: icon_base.png 母版 + 自动叠加角标 → 128px(入包) + 1024px(上传)
        └─ data.js: window.APP_DATA = {meta, units:[{pages:[{tracks:[...]}]}]}
```

### 2.2 前端数据结构（点读类工具通用）

```js
window.APP_DATA = {
  meta: { name, version, series, tool, book, unit_index },
  units: [{
    id, title, subtitle,
    pages: [{
      no, image,                       // image: "images/page_002.webp"
      tracks: [{
        text, cn, audio,               // audio: "p002_01"（对应 audio/p002_01.js）
        left, top, right, bottom,      // 0~1 归一化热区坐标
        duration, track_index
      }]
    }]
  }]
}
```

### 2.3 音频方案（关键决策，勿改）

平台白名单无音频格式 + CSP 禁 data:/blob: 媒体 → **唯一合规路**：

- 音频经 ffmpeg 压缩（48kbps mono 24kHz）→ base64 纯 payload → 独立 `.js` 文件
  （`window.AUDIO_DATA["p002_01"] = "<base64>"`，**不带 data: URI 前缀**）
- 运行时 `AudioContext.decodeAudioData(ArrayBuffer)` 内存解码 → `createBufferSource` 播放，
  全程不经过 `<audio>` 元素 / data: URI / 网络。
- 预加载：渲染页面时动态注入本页全部音频 js（`<script src="./audio/<key>.js">`），点读零延迟。
- 体积真相：base64 膨胀 33%，但 zip 对 base64 文本压缩率高（实测 42%），净增≈0。

## 3. 点读工具功能模式（英语点读 v1.1 已实现）

| 功能 | 实现要点 |
|------|---------|
| 点读模式 | 热区虚线框标识可点区域；点击播单句 + 高亮 + 字幕 |
| 顺序模式 | 整页按 track 自动连播；上一条/下一条/重听本页/重播当前句/暂停继续/进度 |
| 重复 ×2 | 每条播两遍再进下一条（`seq.playCount`） |
| 变速四档 | 0.75 / 1 / 1.25 / 1.5（`src.playbackRate.value`，音高随变是 WebAudio 原生行为） |
| 自动连播 | 本页播完自动翻下一页继续；末页提示；可开关 |
| 翻页 | 封面/‹/页码/›/末页 + 触屏滑动（阈值 48px、水平占优、500ms 内） |
| 记忆 | 模式/重复/变速/自动连播持久化 localStorage（容器禁用时降级） |

### 3.1 前端关键坑位（已踩过，勿重复）

- `decodeAudioData` 结果按 audio key 缓存（`bufferCache`），避免每句重复解码。
- `source.stop()` 会触发 `onended` 回调 → 回调须校验 `currentSource === src` 防止误推进。
- 顺序播放自动切句/手动切换都须 `clearAllHotspots()` 清旧高亮（仅 `clearHotspot()` 不够）。
- `window.AUDIO_DATA` 是动态 script 注入后新建的对象，读取须每次实时查
  `(window.AUDIO_DATA || {})[key]`，不能缓存初始引用（初始为空对象）。
- `new Audio(dataUri)` 会被 CSP 拦截；播放一律走 Web Audio。

## 4. 构建与发布流程

```bash
# 构建（产出 dist/<系列>/<工具>/ + publish/<系列>/）
python build_all.py --tool 英语点读

# 审计（体积/文本门禁）
python .skill/minitool-zip-builder/scripts/audit_artifact.py dist/学科/英语点读
python .skill/minitool-zip-builder/scripts/audit_artifact.py publish/学科/新英语四上点读1单元.zip

# 合规自查（grep 禁止项）+ 冒烟测试（Playwright，见 RedTools/README.md §6.5）
```

发布产物（publish/学科/ 下平铺）：
- `<工具名>.zip`（附 SHA-256 记录）
- `<工具名>-图标(1024).png`（小红书上传要求 1024×1024）
- `发布文案.txt`（标题/正文/标签，人工维护）
- `<工具名>_解压测试版/`（双击 index.html 即测）

## 5. 新工具接入步骤（如数学口算）

1. 确定数据源（数学口算需自备题库数据，结构对齐 `window.APP_DATA`）。
2. `series/学科/<新工具>/src/`：index.html + assets/（main.js/style.css/icon_base.png 母版）。
   - 复制英语点读的 src 作为起点，按工具差异裁剪。
3. `tools.py` 登记 `ToolConfig`（series/tool/version/book/素材目录/app_name）。
4. 若构建管线有差异（如口算无音频、需生成题目 json）→ 扩展 `build_framework.py`。
5. 跑 `build_all.py --tool <新工具>` → 审计 → 冒烟 → 更新进度清单。
