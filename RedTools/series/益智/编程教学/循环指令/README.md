## 1. 需求草案

### 1.1 背景与问题

| 编号 | 优先级 | 问题 | 现状 |
|------|:---:|------|------|
| D5-1 | 高 | 反应力「点击反应测试 / 手速挑战」🔒 推迟（测速类纯分数、无标准答案 = 游戏红线） | `series/益智/反应力/{点击反应测试,手速挑战}/` 源码保留、不宣传不迭代 |
| D5-2 | 高 | 编程教学线 3 款（走迷宫移动型/方块排列构建型/合并策略策略型）缺**循环结构专训** | 走迷宫 v1.1 隐式循环（chip ×N 单指令）；无**显式循环块**（多指令重复） |
| D5-3 | 中 | 测速「重复点击」语义 → 编程「重复执行」概念天然映射（循环 = 点击的自动化） | 立项评估 §2 映射表：反应测速 → 循环指令编程 |

### 1.2 目标

- **玩法**：网格盘面（起点 S + 目标 G），孩子用指令让机器人从 S 走到 G；指令含**显式循环块**
  `🔁 重复 N 次 { 指令... }`（可参数 N、内部可放多条指令）→ ▶ 执行 → 机器人沿路径到 G = 答对。
- **判定**：执行后机器人位置 = 目标格（有标准答案，合规安全区）。
- **概念教学**：**循环 = 自动化**（测速转型核心：不用手点 100 次，写「重复 100 次」一条）——
  区别于走迷宫隐式 chip ×N 的**显式循环块**（循环体内多条指令、一次编写重复执行）。
- **星级**：**编写量**（孩子添加的指令条目：循环块 = 1 条 + 内部指令每条计 1，不乘 N）vs
  **最优编写量**（生成器模式的最小编写量——孩子找到重复模式才能压缩）→ ≤1.5× 3★。
- **形态**：离线 zip 静态 + 双模式；零素材（SVG 程序化盘面）。

### 1.3 玩法细节（MVP 草案）

1. **盘面**：网格（简单 6×6 / 普通 8×8 / 挑战 10×10），起点 S（机器人朝右）+ 终点 G（⭐）；
2. **指令区**：
   - 基础：`⬆ 前进`（1 格）/ `↰ 左转` / `↱ 右转`（复用走迷宫移动语义）；
   - **循环块**：`🔁 重复 N 次 { }`——点开进入块内编辑，可添加基础指令；块头 N 可调
     （单击递增 2→3→4→…）；挑战档支持**块内再套循环**（嵌套）；
3. **执行**：循环块展开执行（动画逐步，每步 260ms），当前指令高亮（复用走迷宫 exec 高亮）；
4. **判定**：执行完机器人 = 目标格 → 过关；否则差格提示（「还差 M 步到目标」+ 当前位置红标对齐走迷宫 v1.4）；
5. **星级**：编写量（循环块算 1、内部指令计 1 不乘 N）vs 最优（生成器模式可算）；
6. **关卡生成**：随机模式单元（2-4 条动作，含转向）→ 重复 K 次（2-4）→ 展开成路径 →
   模拟走位验证不越界 → 盘面 = 路径；**最优编写量 = 模式单元指令数 + 循环块 1**（找到模式即最优）。

### 1.4 范围（MVP）

- 指令：前进/左转/右转 + 循环块（单层；挑战档嵌套）+ ▶ 执行 / ↺ 清空 / ⟲ 重置；
- 三档：简单（单层循环 · 模式 2 条 ×2 次）/ 普通（单层 · 模式 3 条 ×2-3 次）/ 挑战（嵌套 · 2 层）；
- 判定：终点位置 + 差格提示 + 星级（编写量）+ 打卡/best/recent；
- 双模式（LX_SHARED.storage，键 `redtools.xunhuan.v1`）。

### 1.5 非目标（MVP 不做）

- 不做 0 判定点的手速/反应计时（那是游戏残留）；
- 不做 if/else 分支、参数化移动（走 N 步）——聚焦循环结构本身；
- 不做障碍/推箱（走迷宫已覆盖移动挑战）——D5 是**纯循环模式识别**练习。
