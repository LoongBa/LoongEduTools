## 1. 需求草案

### 1.1 背景与问题

| 编号 | 优先级 | 问题 | 现状 |
|------|:---:|------|------|
| D4-1 | 高 | 经典游戏类「2048」🔒 推迟（版号政策：生存式合并分数 = 表现性玩法） | 源码保留、不宣传不迭代（`series/经典游戏/2048/`） |
| D4-2 | 高 | 编程教学线已有移动型（走迷宫）+ 构建型（方块排列），缺**策略型**（多步规划合并） | 系列 README §规划：转型候选含「合并策略编程（2048）」 |
| D4-3 | 中 | 2048 原生**随机新块**（randomTile）→ 无法程序判定；解空间大 → 星级判定复杂 | 需「确定性执行 + BFS 最短指令数」改造 |

### 1.2 目标

- **玩法**：给定初始盘面（确定性，无随机新块）+ 目标数字（如 32），孩子编排**方向指令序列**
  （⬅➡⬆⬇，可参数化 ×N）→ ▶ 执行 → 程序判定最终盘面是否合出目标数字。
- **判定**：最终盘面含 ≥ 目标数字的块 = 有标准答案（合规安全区核心）。
- **概念教学**：顺序（方向序列）+ **策略规划**（提前想好几步合并路径）+ 空间推理——
  编程教学线第 3 种「策略型」，比移动型/构建型更强调多步规划。
- **星级**：指令条数 vs **BFS 最短指令数**（程序可算：确定性状态空间有限，4^d 深度可搜）→ ≤1.5× 3★。
- **形态**：离线 zip 静态工具 + 双模式；零素材（复用 2048 数字块视觉风格）。

### 1.3 玩法细节（MVP 草案）

1. **盘面**：小盘面（简单 3×3 / 普通+挑战 4×4）；初始放少量低值块（2/4）；
2. **目标**：右上角显示「目标：合出 X」（简单 8 / 普通 16 / 挑战 32）；
3. **指令**：方向按钮（⬅ 左 / ➡ 右 / ⬆ 上 / ⬇ 下）逐条加入序列，**chip 参数化 ×N**（复用循环 chip 语义：⬅×2 = 连续左移 2 次）；
4. **执行**：逐条方向指令应用（动画逐步，合并高亮）→ 无随机新块（确定性，与 2048 原版关键区别）；
5. **判定**：执行完 → 盘面含 ≥ 目标 = 过关；否则提示当前最大值（「最大只有 16，还差一点」）；
6. **生成器**：随机生成初始盘面 → **BFS 验证可达目标** + 算最短指令数 → 不可达则重试（重试上限）；
7. **最优解**：BFS（visited 去重，深度 ≤9，4×4 状态空间可搜）。

### 1.4 范围（MVP）

- 指令：⬅➡⬆⬇（参数化 ×1-×4）+ ▶ 执行 / ↺ 清空 / ⟲ 重置；
- 三档：简单（3×3 · 目标 8 · ≤5 步）/ 普通（4×4 · 目标 16 · ≤7 步）/ 挑战（4×4 · 目标 32 · ≤9 步）；
- 判定：最终盘面含 ≥ 目标 + BFS 星级 + 当前最大值反馈；
- 打卡/成绩/best/recent（复用通用模式）；双模式（LX_SHARED.storage，键 `redtools.hebing.v1`）。

### 1.5 非目标（MVP 不做）

- 不做随机新块/生存式分数/「2048 达成胜利」（那是游戏残留）；
- 不做玩家双向控制（滑动手势/按键）——纯指令编程；
- 不做 if/else/循环嵌套（本工具聚焦「策略规划顺序」）。
