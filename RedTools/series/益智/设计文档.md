## 1. 通用约束（所有益智系列工具必须遵守）

|------|------|

## 2. 系列结构：子系列分组

益智类按能力维度分组，三级结构：`series/益智/<能力子系列>/<工具>/`。

```
series/益智/
├── README.md            # 系列说明 + 子系列/工具清单
├── 设计文档.md           # 本文件：系列设计规范
└── 专注力/              # 子系列示例（能力维度）
    ├── README.md        # 子系列说明 + 工具清单
    └── 舒尔特方格/       # 工具（src/ + README.md；文档见 docs/工具文档/益智/专注力/）
```

**构建框架支持**：`build_framework.ToolConfig` 新增 `subgroup` 字段
（如 `subgroup="专注力"`），`tool_dir` 自动解析为 `series/<系列>/<subgroup>/<工具>/`；
`dist/` 与 `publish/` 保持系列内平铺（`dist/益智/`、`publish/益智/`），文件名区分工具。
学科等无子系列工具不受影响（`subgroup=None` 时路径与原来一致）。

## 3. 静态工具构建模式（益智类通用）

益智类工具无教材数据源（无 book.json/图片素材/音频），统一走**静态工具**管线：

```
src/（index.html + assets/）──► copy_static（复制 + 剔除 icon_base.png）
                              ├─► write_static_data_js（生成 data.js，仅 meta）
                              ├─► make_static_icon（母版 + 角标「工具名」→ 128px 入包 + 1024px 到 publish/）
                              └─► package_zip → publish/<系列>/<工具名>.zip
```

- `tools.py` 登记：`ToolConfig(series="益智", subgroup="专注力", tool="舒尔特方格",
  version="1.0", datasource="static", app_name="舒尔特方格")`
- 前端数据：`window.APP_DATA = { meta: { name, version, series, tool, ... }, units: [] }`
  （静态工具 units 为空，渲染不依赖它）
- 构建/审计命令：
  ```bash
  python build_all.py --tool 舒尔特方格
  python .skill/minitool-zip-builder/scripts/audit_artifact.py dist/益智/舒尔特方格
  ```

## 4. 可复用核心：计时 + 成绩 + 打卡

益智类训练工具普遍需要「计时成绩 + 激励」闭环，以下模式已在舒尔特方格落地，可直接复用：

### 4.1 计时
- `performance.now()` 记录起点，`setInterval(100ms)` 按差值刷新显示（后台回来计时仍准）
- 显示格式：秒 + 1 位小数（`⏱ 07.5`）

### 4.2 成绩持久化（localStorage）
```js
{
  version: 1,
  best:    { "3": {ms, date}, ... },   // 各难度最佳（指标更优则覆盖）
  recent:  { "3": ms, ... },           // 各难度最近
  checkin: { dates: ["YYYYMMDD"], streak },  // 打卡
  history: [ {date, size, ms, errors, stars} ]  // 滚动 30 条
}
```

### 4.3 打卡（与学科系列一致）
- 完成一次训练即点亮今日：`dates` push 今日 YYYYMMDD（去重 + 排序）、滚动 365 天
- 连续天数 `calcStreak`：含今天往前推、跨天断
- 打卡日历页：本月日历火苗 + 「连续打卡 N 天」（≥7 天 🎉）

## 5. Chrome 61 / 交互合规要点（益智类通用）

- **JS**：ES2017 上限经典脚本（var + function 风格，无 `?.` `??` 对象展开 `replaceAll`、
  module/import/export）、事件全部 `addEventListener`、无 eval/内联事件、无 fetch/XHR/Worker
- **CSS**：无 `gap`（间距用 padding/margin 实现，如正方形网格用 `padding-bottom:100%` +
  绝对定位格子）、无 `aspect-ratio`/`clamp()`/`inset`/逻辑属性/`:has`/`@container`/`dvh`；
  Flex 子项设 `min-width:0`；安全区用 `env(safe-area-inset-*)` + `--app-height` 变量
- **触控**：按钮 hit area ≥48×48px；动画温和（正确绿 300ms / 错误红 400ms，无频闪）
- **适配**：手机竖屏为主，PC 打开居中且内容 max-width 约 480px

## 6. 观察力子系列：程序化关卡生成（无图片方案）

> 观察力类工具（找不同 P0 / 找相同 P1 / 细节搜索 P2 / 错误在哪里 P2）共用本方案：
> **关卡由 SVG 元素树程序化生成，零图片素材、零版权风险、包体极小（建议 <0.5 MiB）**。
> 首个落地：找不同（益智/观察力，已立项）。

### 6.1 核心模型

- **场景** = 背景（天空/海边/森林…）+ 元素列表；每个元素是一段**可参数化 SVG 模板**
  （位置/颜色/大小/旋转/变体 均可参数）
- **关卡** = 场景定义 + 差异描述（选哪些元素、应用什么变换）
- **出题** = 随机选 N 个元素 × 随机差异变换 → 每次进游戏都是新关卡，孩子不会背答案

### 6.2 差异变换原子操作（5 种）

| # | 操作 | 示例 | 明显度控制（难度） |
|---|------|------|-----------|
| 1 | 改色 | 红苹果→绿苹果 | 色差大小（相近色=难 / 对比色=易） |
| 2 | 变位 | 太阳左上→右上 | 位移距离 |
| 3 | 缩放/旋转 | 云变大、风向标转向 | 比例 / 角度 |
| 4 | 隐藏 | 左图有鱼、右图没有 | 固定明显 |
| 5 | 替换变体 | 西瓜条纹→纯色 | 变体相似度 |

### 6.3 渲染与合规

- 左右两图共用**同一 SVG 树**，右图按差异描述改属性渲染 → 无需存两张图，包体≈代码体积
- SVG 在 zip 白名单内（`svg` ✅）；无外部引用、无网络、无 `<audio>`；Chrome 61 支持 SVG+DOM 操作
- 反馈标记（打勾/红叉）用叠加 SVG 层或 CSS 绝对定位实现，动画 ≤400ms 无频闪

### 6.4 与通用核心的关系

- 计时/成绩/打卡直接复用 §4（舒尔特方格已落地）
- 新增资产 `scenes.js`（场景元素库）放工具 `src/assets/`，后续观察力工具复制扩展
- 首版场景规模：8~10 个场景 × 每场景 8~10 个元素起步，童趣扁平风，可无限扩展

## 7. 逻辑思维子系列：关卡数据方案（推箱子已落地）

> 逻辑思维类工具（推箱子 P2 / 数独入门 P1 / 迷宫寻路 P1 / 分类整理 P1 / 因果排序 P2）
> 共用本方案：**关卡数据采用「一次性转换脚本 + 静态 JS 内嵌」**（方案 A，构建框架零改动）。
> 首个落地：推箱子（益智/逻辑思维，v1.0）。

### 7.1 数据管线

```
外部关卡源（XSB 文本） ──► convert_levels.py ──► src/assets/levels.js
     （一次性脚本：解析 + 校验 + 求解最优指标）     （随 copy_static 原样入包）
```

- **数据格式**：XSB（推箱子事实标准，`#`墙 `@`玩家 `+`玩家在目标 `$`箱 `*`箱在目标 `.`目标 空格地板）。
- **源数据**：Microban I by David W. Skinner（155 关），免费分发、保留署名、非商业；选关页底部署名。
- **求解器**：BFS 求最少推动数（状态 = 箱子位掩码 + 玩家位；位运算 flood-fill 可达区；
  **角落死锁剪枝**——相邻两正交方向皆墙且不在目标，sound；注意 `(up&&down)/(left&&right)` 是竖井/横巷**非**死锁，曾误剪导致大量关卡误判不可解）。
- **开放策略**：数据全量内嵌（155 关 ≈ 20 KB），`OPEN_LEVELS` 常量控制开放数量（当前 60），扩关零改动。
- **星级基准**：最优推动数（构建期求解），3 星 ≤1.5× / 2 星 ≤2.5×；求解超时关卡 `b:null` 前端降级（通关 2 星封顶）。

### 7.2 与通用核心的关系

- 成绩/打卡/断局恢复直接复用 §4（localStorage，key 带工具前缀）。
- 新增资产 `levels.js`（关卡数据）放工具 `src/assets/`，转换脚本保留在工具目录（可复算/扩关）。
- 未来多工具共享关卡库（如数独题库）可升级为 `RedTools/_shared/` + 构建期 `datasource` 扩展（向后兼容）。

## 8. 记忆力子系列：程序化 SVG 图标库（翻牌记忆配对已落地）

> 记忆力类工具（翻牌记忆配对 P0 / 数字记忆 P0 / 图形序列复刻 P1 / 位置记忆 P1）
> 共用本方案：**卡片/元素图案由 SVG 代码程序化生成（零图片素材、零版权风险、包体极小）**。
> 首个落地：翻牌记忆配对（益智/记忆力，v1.0，包体 0.03 MiB）。

### 8.1 核心模型

- **图标库** = 一组 SVG draw 函数（`icons.js` 内 `window.ICONS`），每个图标返回以 (0,0) 为中心
  的完整 `<svg>` 字符串（`viewBox="-20 -20 40 40"`，糖果色填充，童趣扁平风）
- **出题** = 随机选 N 个图标 × 每图标 2 张卡 → Fisher-Yates 洗牌布阵 → 每次进游戏都是新布局
- **渲染** = 卡片正面 `innerHTML` 直接插入 `draw()` 返回的 SVG → 无图片文件、包体≈代码体积
- **扩展** = 图标库独立成文件，后续可整体替换主题（成语/单词卡等）

### 8.2 卡片 3D 翻转（CSS，Chrome 61 兼容）

- `.card`：`perspective: 600px`；`.card-inner`：`transform-style: preserve-3d` +
  `transition: transform 0.3s`；`.card-face`：绝对定位撑满 + `backface-visibility: hidden`
- 背面紫色渐变 + 问号；正面白底图标预置 `rotateY(180deg)`；`.card.flipped .card-inner` → `rotateY(180deg)`
- 全部属性 `-webkit-` 前缀双写（Chrome 61 需前缀）；正方形卡片用 `width` + 同值 `padding-bottom`
  百分比（相对同一容器宽度）精确铺排，间距用内层 inset（无 flex gap）

### 8.3 与通用核心的关系

- 计时/成绩/打卡直接复用 §4（localStorage，key 带工具前缀）；新增「步数」指标
  （每翻满 2 张计 1 步）引导先记再翻
- 形状工具函数（`c/ce/rc/pl/pa/ln/star/starPts`）与 `svgWrap` 为 icons.js 局部函数，随文件复制

## 9. 空间感知子系列：程序化 SVG 场景切块（简单拼图已落地）

> 空间感知类工具（简单拼图 P0 / 七巧板 P1 / 华容道 P2 / 旋转拼图 P2）
> 共用本方案：**完整场景图由 SVG 代码程序化生成（零图片素材），切块渲染走 viewBox 裁剪**。
> 首个落地：简单拼图（益智/空间感知，v1.0，包体 0.02 MiB）。
### 9.1 核心模型

- **场景库** = `scenes.js` 内 `window.SCENES`：8 个正方形 400×400 童趣场景
  （海边/森林/太空/花园/农场/海底/冬日/城堡），每场景 6~9 个元素；
  结构 `{ id, name, w, h, bg, elements }`，`bg` 为全视口背景 SVG（含渐变 defs），
  元素 `{ id, x, y, s, draw }`，`draw(opt)` 返回以 (0,0) 为中心的内层 SVG
- **切块** = 碎片 `<svg viewBox="x y w h">`（x/y = 该块「目标行列」区域）内嵌**完整场景内容**
  （`sceneContent` = bg + 各元素 `<g transform>`），浏览器 viewBox 裁剪显示局部
- **出题** = 随机场景 + N×N 切块 + Fisher-Yates 洗牌 + **防「恰好还原」重洗**（guard≤100）
- **交换** = 点选两块（紫色描边高亮）交换数组槽位 + 重算 `curRow/curCol` +
  仅 `setAttribute('viewBox')` 更新两个 svg（不重建 DOM，性能优）
- **归位判定** = 每块 `curRow===row && curCol===col`；全部归位 → 绿色边框闪烁 400ms →
  350ms 后结算浮层（用时 + 步数 + 归位 n/n + 星级 + 新纪录 + 打卡）
- **扩展** = 场景库独立成文件，后续七巧板/旋转拼图可直接复制扩展（换图形模板即可）

### 9.2 正方形碎片网格（CSS，Chrome 61 兼容）

- 与 §8.2 同款：正方形碎片用 `width` + 同值 `padding-bottom` 百分比
  （2×2→50%、3×3→33.33%、4×4→25%），`flex-wrap` + `-webkit-` 前缀双写，间距用内层 inset（无 flex gap）
- 选中态紫色描边（`outline` 不影响布局）；完成态绿色边框 + `solvedFlash 0.4s ease-out` 闪烁（≤400ms 光敏安全）

### 9.3 参照图辅助（降龄设计）

- 完整图 90px 缩略常显（2×2/3×3，降低低龄认知负荷）；4×4 默认隐藏缩略 +
  「看原图」按钮 → 大图浮层 3 秒自动关闭（点击也可关）
- 引导「先看参照图规划目标位置，再点选交换」——步数指标量化策略质量

### 9.4 与通用核心的关系

- 计时/成绩/打卡直接复用 §4（localStorage，key 带工具前缀）；新增「步数」指标
- 场景生成函数（`sceneContent/elementSvg`）与形状工具为 scenes.js/main.js 局部函数，随文件复制
- 无音效（与找不同一致）；主题色天蓝系（`#e8f4ff` 背景 / `#4aa8ff` 主色），区别于记忆紫

## 9b. 华容道：角色 SVG 库 + 关卡 BFS 求解（已落地）

> 华容道（空间感知 P2）落地两套可复用资产，供旋转拼图等后续复用：

### 9b.1 角色 SVG 库（characters.js）

- **程序化 Q 版角色**：7 个 draw 函数（曹操/关羽/张飞/赵云/马超/黄忠/小兵），返回以 (0,0) 为中心
  的 `<svg viewBox="-50 -50 100 100">`，滑块内撑满自适应。
- **高头饰角色**（冕冠/银盔红缨/紫金冠雉翎）用 tall viewBox `-50 -70 100 120`
  （顶部留 20 单位防头饰裁切——曾踩坑：头饰顶到 -64 被 SVG 画布裁掉，质检发现后修复）。
- 通用部件函数（head/roundEye/slantEye/brow/blush/smile/mouthLine/body/bodySoldier）
  保证 7 角色风格统一；差异化靠 肤色/头饰/胡须/袍色 组合（白脸曹操黑须红袍 vs 红脸关羽
  绿巾绿袍 vs 黑脸张飞豹眼络腮胡 vs 银盔赵云 vs 紫金冠马超 vs 白须黄忠 vs 蓝巾小兵）。

### 9b.2 关卡数据管线（build_levels.py → levels.js）

- 盘面 4×5、出口底部中央（曹操 2×2 左上抵达 (3,1) 即胜）；棋子固定尺寸
  （曹操 2×2 / 关羽 2×1 / 四将 1×2 / 小兵 1×1）。
- **BFS 最少步数**：单格步进口径（点箭头一次=1 步）+ **同型归一化剪枝**
  （四将位置排序 + 四兵位置排序 → 消除 4!×4! 状态爆炸，每关 ~2.4 万态秒级求解）。
- **星级基准**：3 星 ≤1.5×b / 2 星 ≤2.5×b（b=最少步数）；超时关卡 b=null 通关 2 星封顶。
- 交互：点选棋子 → 紫色方向箭头（▲▼◀▶）移动一格 + 滑动手势；不可移动棋子抖动反馈。
- 复用到旋转拼图等滑块类：换盘面/棋子尺寸/出口即可，BFS 脚本与角色库原样复制。

6. 更新进度清单（`RedTools/README.md`）+ 系列/子系列 README + 本文件（如结构变化）。
